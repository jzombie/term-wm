# Plan: `term-session` Gateway (multi-channel supervisor + CLI administration + Windows daemonization)

## Goal

Replace the one-process-per-channel architecture with a **single gateway daemon** that hosts every channel in one process, add a CLI for listing/killing channels and connected sockets (identified by server-assigned conn id + connect time + physical size + hostname), and make Windows auto-background the daemon like Unix does. All functionality tested.

Design decisions (per user):

- Single **gateway socket** with method-level routing (no per-channel sockets, no per-channel server processes).
- **Session-kill vs socket-kill are separate, unambiguous operations.**
- No env-var-based identity — identity is a **server-assigned `conn_id`**; channel binding is server-side and authoritative (a client can only reach the channel it attached to).
- Legacy single-channel `--server` mode is **replaced entirely**.

## 1. Wire protocol (`crates/term-session-muxio-service-definitions`)

### `src/methods.rs`

Existing pattern: each method implements `RpcMethodPrebuffered` with private bitcode encode structs (`SpawnRequest`/`SpawnResponse`, etc.).

| Method | Input | Output | Notes |
|---|---|---|---|
| `Attach` (new) | `(channel: String, hostname: String)` | `conn_id: usize` | Binds the connection to `channel`, records `hostname` + server-side `connected_at`. Identity is server-assigned; **not** client-suppliable. |
| `Spawn` (changed) | `(cmd: Option<Vec<String>>, cols, rows)` | `(id, cols, rows)` | **No channel in payload** — routed via the connection's bound channel (rejected if `Unattached`). **Idempotent/re-entrant**: existing live session → ignore `cmd`, apply `cols/rows` as implicit resize, return existing id; exited session or none → respawn (non-empty `cmd` overwrites the stored template, else template reused). |
| `ResizePty` (changed) | `(id, cols, rows)` | `(cols, rows)` | Routed via bound channel. |
| `CloseSession` (changed) | `(id)` | `()` | Routed via bound channel. |
| `WriteInput` (changed) | `(id, data)` | `()` | Routed via bound channel. |
| `ListSessions` → **`ListChannels`** (replaced) | `()` | `Vec<ChannelInfo>` | `ChannelInfo { name, session: Option<SessionInfo>, clients: Vec<ClientInfo> }`; `SessionInfo { id, cols, rows, exited, exit_code, title }`; `ClientInfo { conn_id, hostname, connected_at_unix: u64, cols, rows }` |
| `KillChannel` (new) | `(channel: String)` | `()` | Kills the channel's **session only** and force-detaches **all** of its sockets (authoritative server-side eviction: `conns.write()` → snapshot targets → drop guard → `channel.lock()` to shutdown each output stream, fail pending RPCs, evict each `ConnEntry` and channel `clients` entry). **Terminates the entire PTY process group, not just the session leader** (SIGTERM → escalate SIGKILL to `-pgid`; see §2). Channel stays registered; next attach respawns. |
| `KillClient` (new) | `(channel: String, conn_id: usize)` | `()` | Force-detaches **one socket**: removes from channel client/subscriber maps, ends its output stream, fails its pending RPCs, evicts its `ConnEntry`. |
| `ShutdownGateway` (new) | `()` | `()` | Stops the daemon (needed by tests + `term-session stop`). **Acts as a responsible process supervisor:** atomic `is_shutting_down` seal, then **snapshot-and-release** teardown — collect the active `ChannelState` set under a brief `channels.write()`, release it, and off-lock execute the full process-group termination (SIGTERM→SIGKILL escalation / `TerminateJobObject`) per channel. The handler returns `()` immediately; a detached task sleeps ≥50 ms for the transport to flush the response, then fires the exit oneshot. The daemon does **not** exit until every child tree is terminated and the `()` response is drained; no lock is held across the awaits. |
| `OnPtyResized`, `STREAM_INPUT`, `SUBSCRIBE_OUTPUT`, `PushOutput` | unchanged | | Streams route via the connection's bound channel. |

New `bitcode`-serializable types: `ChannelInfo`, `SessionInfo`, `ClientInfo` (timestamps as `u64` unix seconds; never `SystemTime` directly). New muxio error ids: `RPC_ERROR_UNATTACHED` (any RPC/stream on an unbound connection) and `RPC_ERROR_SHUTTING_DOWN` (any RPC/stream after shutdown begins).

### `src/channel.rs`

Add `pub fn gateway_channel_name() -> ChannelName`, **static and deterministic** — a fully reproducible, upstream-independent logical name. Resolution order:
1. `TERM_WM_GATEWAY` env var — **runtime-only** isolation override (injected by the test harness, CLI `--gateway`, or an operator), resolved at the moment of execution via `std::env::var("TERM_WM_GATEWAY")`;
2. else the static default `term-wm/<user>/gateway` where `<user>` is the current OS user — from `$USER`/`getpwuid` (Unix) or `USERNAME` env (Windows);
3. reject a bare/shared literal (e.g. `term-wm/__gateway__`) unless explicitly requested via `--gateway`/env.

**No build-time entropy — the compiled artifact is 100% deterministic.** There is **no `build.rs` RNG**, no `env!("...")`-injected hash, and no compile-time token. The logical IP name is derived only from platform user identity + the static literal, so identical source compiles to an identical binary (reproducible-build/SLSA compatible) and an upgraded binary probes the **same** endpoint as the running daemon (no orphaned-daemon black holes across `cargo install`/package updates). Protocol versioning, if ever needed, appends a predictably-changing literal (e.g. `term-wm/<user>/gateway-v1`), never randomness.

**Test isolation is the test harness's job — not the binary's.** `gateway_channel_name()` stays agnostic to suite mechanics; the harness generates a UUID per suite and injects it into every client/daemon subprocess via `std::process::Command::env("TERM_WM_GATEWAY", uuid)`. (A compile-time token would fail anyway: Cargo caches `build.rs` output, so two runs of unchanged `cargo test` reuse the same baked token and collide.)

**Binding is `muxio`'s responsibility — no manual IPC pathing.** The daemon only computes the logical `gateway_channel_name()` and hands it to `muxio` (`probe_ipc_endpoint` / `RpcIpcServer`). All OS-specific physical socket resolution, directory creation/scoping, permission/SDDL enforcement, and collision avoidance are `muxio`'s transport domain. The application layer must not `lstat`-validate, `chmod`, `umask`, `DirBuilder`, or otherwise hand-build filesystem paths. The static logical name above is purely the identity; the physical path stays entirely inside `muxio`.

## 2. Server (`crates/term-session-server`)

Refactor `src/session_server.rs` (currently a single flat `run_server` at `:158` holding `ServerState` at `:54`). Restructure around a gateway. Two-tier coordination to avoid a global I/O hot-spot mutex:

```
ServerState
├── conns: RwLock<HashMap<usize, ConnEntry>>          // routing table (read-mostly)
└── channels: Arc<RwLock<HashMap<ChannelName, Arc<Mutex<ChannelState>>>>>
```

- `ConnEntry { handle: RpcIpcConnectionContextHandle, state: ConnState, hostname, connected_at, cols, rows }`.
  - `conns` is a read-mostly routing map protected by `RwLock` (or `scc`/`dashmap`).
- **Strict non-nested lock ordering (kills the AB-BA deadlock):** the gateway **never holds two locks at once**. Both the `conns` map and each `ChannelState` are resolved-and-dropped in a strict sequence:
  1. resolve: take `conns.read()`, look up `(channel_id, Arc<ChannelState>)`, compute whatever must be, then **drop** the `conns` guard;
  2. acquire: then take `channel.lock()` and do the work.
  The ordering is always `conns → channel`, never `channel → conns`. Stream handlers resolve the channel id, drop `conns.read()`, and only then lock the channel — so I/O never concurrently holds `conns.read()` while another task holds `channel` awaiting `conns.write()`.
  - `KillChannel`/`KillClient`: `conns.write()` → snapshot the target `ConnEntry`s (and their channel ids) → **release** `conns` → then `channel.lock()` to finalize the PTY, close subscriber streams, and drop those client ids from the channel's `clients` map. No lock is shared between the two phases.
  - As a belt-and-suspenders fallback, deferred GC: a dead conn's own disconnect/eviction path removes its `ConnEntry` from `conns` (idempotent), so even a missed handler cannot wedge the table.
- `state: ConnState` modeled as an explicit state machine:
  ```rust
  enum ConnState {
      Unattached,                        // connected but not yet bound
      Attached(ChannelName),             // bound to a channel via Attach
  }
  ```
  Any `Spawn`/`ResizePty`/`WriteInput`/`CloseSession`/stream request arriving from an `Unattached` connection is rejected at the protocol layer with an explicit `RPC_ERROR_UNATTACHED` error (new muxio error id + client-facing message). `Attach` is the only transition that binds a connection.
- `ChannelState` = today's `ServerState` fields (`session`, `clients: HashMap<conn_id, ClientEntry>`, `subscribers`, `notify`, plus `cmd: Vec<String>` template for respawns, `input_tx`/`input_rx`). Each channel is independently `Mutex`-locked.
- Handler routing: prebuffered/stream handlers resolve `conn_id → conns` (id lookup only), fetch the channel's `Arc<Mutex<ChannelState>>`, drop the routing guard, then operate solely on the per-channel lock. High-throughput streams (STREAM_INPUT/SUBSCRIBE_OUTPUT) hold only the per-channel lock; other channels proceed concurrently.
- **Channel garbage collection (prevents unbounded `channels` growth) with tombstone re-verification (kills the split-brain race).** A channel is eligible for reaping when it has **zero connected clients AND its session has exited** (or never existed). To stop an in-flight `Attach` from resurrecting a channel that a concurrent GC is removing:
  - `ChannelState` carries an `is_reaped: bool` flag (starts `false`).
  - GC runs together with the map removal under a single `channels.write()` **and** re-locks the `ChannelState` inside that critical section to re-verify `clients.is_empty()` before deleting — after confirmed, set `is_reaped = true`, then `remove(channel)` from the map, then release. This guarantees the Arc is unreachable from the map before it's finalized.
  - Every `Attach`/`Spawn` that retrieved an `Arc<ChannelState>` from `channels.read()` must **lock that channel** and check `is_reaped`. If `is_reaped`, drop the stale Arc and **acquire `channels.write()` with a second map lookup inside the critical section (safe double-checked locking)**: re-`get()` the channel name — if the map now holds a non-reaped `ChannelState` (inserted by a racing thread between the read and the write lock), bind to **that** instance; only if the map is absent or still holds the reaped Arc may it instantiate and insert a fresh `ChannelState`. This makes reattachment convergent: a client can never bind to an orphaned instance, and concurrent attaches to the same name always resolve to the single canonical entry (no blind overwrite of a racing thread's fresh channel).
  - **Teardown (output-polling task / disconnect handler) MUST drop the per-channel `MutexGuard` entirely before requesting `channels.write()`** — strict re-entrant ordering, no AB-BA: the initiating handler evaluates `clients.is_empty() && session-exited` under the channel lock, then **`drop(guard)`**, then acquires `channels.write()`. It never holds `channel.lock()` while waiting on `channels` (that would deadlock against an `Attach` holding `channels.read()` and awaiting `channel.lock()`). This every GC/detach path bounds the table for scripting clients that mint unique channels.
- **`Spawn` is idempotent + re-entrant.** `Spawn` full decision matrix on a connection's bound channel:
  - no session or session `exited` **=> respawn**: `cmd` payload if `Some(non-empty)` **overwrites** the stored `cmd` template and is used for the new PTY; `None`/empty falls back to the existing template → respawn → return new id/geometry;
  - session exists & `!exited` **=> reuse**: ignore the incoming `cmd`, apply `cols`/`rows` as an implicit resize, return the existing id (mirrors current behavior at `session_server.rs:210-226`).
  Concurrent `Spawn`s serialize on the per-channel lock; a later `Spawn` can never silently override a live PTY's command.
- **`KillChannel` is authoritative — no client cooperation.** It (a) **kills the session's entire process group** (not just the session leader), (b) finalizes subscriber streams, (c) **force-evicts every bound socket** from `conns` and the channel's `clients` map, shutting down each client's output stream and failing its pending RPCs (same cleanup `KillClient` uses). **Every per-conn output task is explicitly cancelled, not just its map entry dropped** — see cancellation below.
- **Process-group termination (no orphaned jobs), fully asynchronous (no reactor stall).** The session leader is already launched in its own process group/session (portable-pty spawn; exposed via `process_group_leader()` at `pty.rs:373`), but `kill_child()` at `pty.rs:448` only `child.kill()`s the single pid and would orphan grandchildren. Rework session teardown to signal the **process group, not the pid**, without blocking the Tokio RPC handler:
  1. the `KillChannel` handler performs the immediate, non-blocking `SIGTERM` to `-pgid` (and unlocks / returns right away — no `thread::sleep`, no `select!` wait while holding any lock);
  2. it `tokio::spawn`s a **detached task** whose only job is `tokio::time::sleep(SIGKILL_GRACE)` (a `const`, non-blocking timer) then sends `SIGKILL` to `-pgid` for stragglers. The RPC handler and `ChannelState` lock are released before this task runs, so sibling channels keep servicing I/O during the grace window.
  On Windows, the process tree is managed **natively via a Win32 Job Object — no `taskkill`/shell-out**, and assignment is **race-free via `CREATE_SUSPENDED`**: create the job first (`CreateJobObjectW(NULL, NULL)`, `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`), then spawn the child a **single time** with **`CREATE_SUSPENDED`** (`0x00000004`) set in `creation_flags`, extract its raw process handle, `AssignProcessToJobObject(job, child)`, then `ResumeThread` on the child's primary thread handle. There is **no second spawn / re-spawn phase** — `CREATE_SUSPENDED` is only a bit passed to `CreateProcess`; resumption is thread-execution control (`ResumeThread`), never process re-instantiation. This closes the escape window where a pre-contained child could spawn unmanaged background processes. `KillChannel` calls `TerminateJobObject(job, exit_code)` (dispatched on a spawned task, not awaited inline).
- **Explicit async-task cancellation (no dangling CG tasks).** The per-connection output loop (`SUBSCRIBE_OUTPUT` push task that polls PTY output → `respond`) and the input writer task are each governed by a `CancellationToken` (`tokio_util::sync::CancellationToken`) stashed in `ConnEntry`/`ClientEntry`. During kill/evict, the gateway calls `token.cancel()` **synchronously in the kill operation** so the task's next `tokio::select!`/await point aborts it and the subscriber `respond` sender is dropped. Because the output worker drives the PTY render loop, cancellation is coordinated with `ChannelState` output-polling such that a killed conn's finalizer runs before the next broadcast — no detached task survives the evicted `conn_id`.
- **One** `RpcIpcServer`, **one** endpoint, **one** connection-event loop. Disconnect (or transport-level close) removes conn from `conns` + prunes the channel's client/subscriber maps + `recalculate_pty_size` + geometry broadcast (existing logic, moved into `ChannelState` as in `ServerState` at `:107`/`:141`).
- `Session::spawn` keeps setting `TERM_WM_CHANNEL` (informational only — never used for identity).
- Replace `run_server(config)` / `SessionServerConfig` with `run_gateway(gateway: ChannelName)`. **Channels are created lazily on first `Attach`/`Spawn`.** Handlers that arrive without a bound channel are rejected via the `Unattached` state.
- `ShutdownGateway` handler runs an **atomic shutdown seal**, then snapshot-and-release teardown (never holding a lock across `.await` — a `RwLockWriteGuard` spanning a `.await` is `!Send` and stalls the reactor): (1) set `is_shutting_down` (an `AtomicBool` in `ServerState`) to `true` with `Ordering::SeqCst` **before** the teardown window opens; (2) briefly acquire `channels.write()`, drain/collect the `Arc<ChannelState>` set into a snapshot, then immediately drop the lock; (3) iterate off-lock, issuing per-channel process-group `SIGTERM` and `tokio::spawn`ing the `SIGKILL` escalation tasks; (4) `.await` the joined escalation handles so every child tree ends; (5) return `()` to the caller **immediately** and let a detached task end `run_gateway` (see below).
  - **Shutdown exit signal is deferred — never triggered from inside the RPC handler** (that would tear down the muxio transport before the `ShutdownGateway` response frame is flushed, making the client see a generic reset instead of a clean success). The handler instead `tokio::spawn`s a detached task that `sleep`s ≥50 ms (a named `const`, `SHUTDOWN_FLUSH_GRACE_MS`, reusing the flush-grace pattern already used for session-exit in `session_server.rs:545`) to allow the transport to drain the `()` response, and only then fires the exit oneshot that ends `run_gateway`. The RPC handler returns immediately.
  - **Every incoming RPC/stream handler (`Attach`, `Spawn`, `ResizePty`, `WriteInput`, …) checks `is_shutting_down` as its first step**; if `true`, it immediately rejects with a new `RPC_ERROR_SHUTTING_DOWN` error id. Because the seal is set before the lock is dropped, no new `ChannelState`/PTY can be spawned during the asynchronous grace period — the snapshot covers every channel that can exist, and nothing minted mid-teardown is orphaned. Concurrent disconnects stay free since no global lock is held across the await.

## 3. Client (`crates/term-session-client`)

- `run_session(socket: &str, channel: &ChannelName, cmd: &[String], cols, rows)`:
  1. connect to gateway; register `OnPtyResized` (unchanged);
  2. `Attach::call((channel, hostname))` → conn_id (before any session RPC, so stream routing works);
  3. `Spawn::call((Some(cmd) if non-empty else None, cols, rows))` → session id + geometry (replaces the current hardcoded `Spawn::call(client,(None,term_cols,term_rows))` at `lib.rs:276` and its inline `term_cols/term_rows` read);
  4. open `SUBSCRIBE_OUTPUT` / `STREAM_INPUT` streams (calls unchanged; routed by bound channel);
  5. rest of the TUI loop unchanged.
- `remote_pane.rs`: `ResizePty`/`CloseSession` payloads unchanged (id-based); no edits needed beyond signature compatibility.
- `Attach` hostname from `hostname` crate (already a workspace dep) or env.
- Client must surface `RPC_ERROR_UNATTACHED`/`RPC_ERROR_SHUTTING_DOWN`/other gateway errors from `Spawn`/streams as clear messages rather than a hang.
- **ABI/transport fault interception (Layer 4, no silent panic):** the client's initial gateway connect + `Spawn` handshake must explicitly match `muxio` transport and `bitcode` deserialization errors. On a decode/transport parse fault (e.g. an upgraded client against a legacy daemon on the same socket, or wrong frame shape), the client prints a strictly formatted diagnostic to stderr — e.g. `FATAL: Protocol ABI mismatch. A legacy daemon is occupying the IPC socket. Manually terminate the daemon process before continuing.` — and exits with a non-zero exit code. No bare panic or silent drop.

## 5. Windows daemonization (`src/auto_spawn.rs`)

Replace `creation_flags(0x08000000)` at `auto_spawn.rs:52` with named consts (per AGENTS.md magic-strings rule):

```rust
const CREATE_NEW_PROCESS_GROUP: u32 = 0x00000200;
const DETACHED_PROCESS: u32 = 0x00000008;
cmd.creation_flags(CREATE_NEW_PROCESS_GROUP | DETACHED_PROCESS);
```

`DETACHED_PROCESS` gives the child no console, so the parent console's `CTRL_CLOSE_EVENT` never reaches it (CREATE_NO_WINDOW is ignored when DETACHED_PROCESS is set). **It does not disinherit standard handles** — without explicit redirection, wrappers/CI/SSH runners hang waiting for the daemon's inherited `stdin`/`stdout`/`stderr` pipes to close. Therefore each handle must be mapped to `NUL` (`Stdio::null()`), applied cross-platform at `auto_spawn.rs:28-30`, and on Windows the process is additionally started with `inherit_handles(false)` (`.inherit_handles(false)` via `std::os::windows::process::CommandExt`) so no launch-terminal handles leak into the daemon. Add a `--daemon-selfcheck <marker-path>` flag (test-only): the daemon writes `windows-no-console` (via `GetConsoleProcessList == 0`) or `unix-session-leader` (`getsid(0) == getpid()`) to the marker after binding.

**Binary/daemon tests:** create `crates/term-session/tests/` (does not exist yet; `CARGO_BIN_EXE_term-session` is only made available in a crate's own integration-test target). A shared harness helper generates a UUIDv4 per test and injects it into **every** spawned client/daemon `Command` via `.env("TERM_WM_GATEWAY", uuid)`, so tests are isolated by runtime env only:

- spawn real `--daemon --daemon-selfcheck <marker>` → assert detachment proof per platform; unique `TERM_WM_GATEWAY` per test (harness-injected);
- **bind arbitration:** two concurrent auto-spawns against the same runtime `TERM_WM_GATEWAY` converge to a single daemon (no duplicate daemon / no `EADDRINUSE` loop); the loser connects to the winner;
- daemon survives **all clients disconnecting** (re-probe after drop);
- daemon **survives its parent's death**: spawn `term-session attach --channel x -- mock echo` as a subprocess (it auto-spawns the daemon), pipe `hello\n` in, verify echoed output, then terminate the subprocess — the daemon it spawned must still be reachable and the session still alive;
- **ABI mismatch diagnostic:** point a client at a socket owned by a mismatched/legacy frame responder (simulate corrupting the handshake) and assert the client prints the formatted `FATAL: Protocol ABI mismatch…` stderr diagnostic and exits non-zero (no panic, no silent drop);
- clean up each daemon via `ShutdownGateway`/`child.kill()`.

## Notes

- `ListChannels` CLI output: plain-text table by default, `--json` for scripting.
- Gateway name is overridable via `--gateway` / `TERM_WM_GATEWAY` for explicit isolation.
- The default gateway name is the **deterministic static value** `term-wm/<user>/gateway` (no build-time entropy, reproducible-build/SLSA compatible, upgrade-safe — a new binary probes the same endpoint as the running daemon). Test isolation is achieved by the harness injecting a unique `TERM_WM_GATEWAY` per suite into the spawned client/daemon subprocesses.
- Identification of peers uses server-assigned `conn_id` + server-side `connected_at` + physical size + hostname; the conn_id is authoritative and immutable — the bindable channel is derived from it only.
- `ChannelState` must own `cmd`, `input_tx`/`input_rx`, `clients`, `subscribers`, `session`, and its `Notify`. `recalculate_pty_size` + `notify_clients` move into `impl ChannelState` unchanged.
- On child exit, the per-channel output-polling task finalizes subscribers and **clears the session** instead of exiting the daemon.
- Routing never holds the global lock during I/O: only a `conns` read-lookup, then the per-channel `Mutex`. Cross-channel throughput is independent.
- Server remains authoritative on teardown: `KillChannel`/`KillClient`/disconnect all actively evict `ConnEntry`, cancel their per-conn output/input tasks, and sockets — nothing relies on a client disconnecting gracefully.
- Channel reaping is tombstone-safe (`is_reaped` + re-lock inside `channels.write()`), so a concurrent `Attach` cannot split-brain a channel into two disjoint instances.
