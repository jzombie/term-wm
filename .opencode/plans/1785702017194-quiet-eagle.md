# Plan: Fix startup window orientation (no side-by-side in tall/narrow terminals)

## Root cause (verified in current reverted code)

`open_window` (mod.rs:433-441) → `tile_window_key` (drag.rs:430-476) runs at app
startup while `self.managed_area` is still `Rect {0,0,0,0}` (no frame rendered yet).

- Window 1: `managed_layout == None` → line 471 bakes `Some(TilingLayout::new(leaf))`.
- Window 2: `insert_window_balanced(key, 0x0)` → 80x24 landscape fallback → picks
  `InsertPosition::Right` → a `Horizontal` split is permanently baked into the tree.
- First real frame later calls `register_managed_layout(real_area)` which only
  **projects** the existing tree (layout.rs:416-); it never rebuilds topology.
- Result: side-by-side split locked in even on tall/narrow (35x100) viewports.

## The fix (4 surgical edits + 1 new test)

### 1. Defer in `tile_window_key` — `crates/term-wm-core/src/window/window_manager/drag.rs:430`

Move `clear_floating_rect` **above** the new 0x0 guard, then early-return:

```rust
pub(super) fn tile_window_key(&mut self, key: WindowKey) -> bool {
    use crate::layout::LayoutNode;

    // Capture floating rect center BEFORE clearing it
    let floating_info = self
        .floating_rect(key)
        .map(|spec| spec.resolve(self.managed_area))
        .map(|r| r.center());

    self.clear_floating_rect(key);

    if self.managed_area.width == 0 || self.managed_area.height == 0 {
        // Viewport not measured yet (pre-first-render startup): defer layout
        // construction. register_managed_layout builds the tree on frame 1
        // from the mapped windows against the real area.
        self.focus_window_key(key);
        return true;
    }

    // ... existing body unchanged (layout_contains/remove, insert, etc.)
```

- `clear_floating_rect` runs in BOTH paths (this is the current behavior at drag.rs:439):
  a window being tiled stops being floating even when deferred, so the lazy build's
  `!w.is_floating()` predicate sees it correctly.
- `floating_info` is still captured before clearing (unchanged) and simply goes unused
  on the deferred path.
- `return true` preserves the tiled contract; `focus_window_key` preserves focus.
- `open_window` also calls `focus_window_key` itself (mod.rs:439) — redundant but harmless.

### 2. Lazy build in `register_managed_layout` — `crates/term-wm-core/src/window/window_manager/layout.rs`

Insert immediately after `self.managed_area = managed_area;` (line 392):

```rust
if self.managed_layout.is_none()
    && self.managed_area.width > 0
    && self.managed_area.height > 0
{
    let mut tiled: Vec<WindowKey> = self
        .windows
        .iter()
        .filter(|(_, w)| w.state() == WindowState::Mapped && !w.is_floating())
        .map(|(k, _)| k)
        .collect();
    tiled.sort_by_key(|k| self.windows.get(*k).map_or(0, Window::creation_order));
    if let Some(first) = tiled.first().copied() {
        let mut layout = TilingLayout::new(LayoutNode::leaf(first));
        for key in tiled.iter().skip(1) {
            layout.insert_window_balanced(*key, self.managed_area);
        }
        self.managed_layout = Some(layout);
    }
}
```

- Runs exactly once (guarded by `managed_layout.is_none()`), on the first real frame,
  after `managed_area` holds the true viewport → correct orientation via
  `insert_window_balanced`'s aspect-ratio logic.
- No new imports needed: `LayoutNode`, `TilingLayout`, `InsertPosition`, `WindowState`
  are already imported in layout.rs (lines 10, 13); `Window::creation_order` exists
  (entry.rs:209).
- **Filter is strictly `Mapped && !is_floating`.** This avoids pulling dormant
  `Realized` windows (created but never mapped) into the tree. The tiling-intent signal
  is explicit: a window is eligible only if the caller Mapped it (the real `open_window`
  flow does exactly this before calling `tile_window_key`, mod.rs:435).

### 3. Seed test fixtures — `crates/term-wm-core/src/window/window_manager/layout.rs`

Both `make_wm()` helpers (lines 908 and 1262). After constructing the WM, seed the area
so unit tests that tile directly keep tiling immediately:

```rust
wm.managed_area = Rect { x: 0, y: 0, width: 80, height: 24 };
```

This keeps `single_leaf_minimization_nullifies_layout` (layout.rs:981) and all other
core unit tests that call `tile_window_key` on a `make_wm` WM passing, since their
`managed_area` is now non-zero.

### 4. New regression test — `crates/term-wm-core/src/window/window_manager/layout.rs` (tests module)

`startup_two_windows_stack_vertically_on_tall_area`:
1. Construct an **unseeded** WM via `WindowManager::with_config` (NOT `make_wm`).
2. `create_window` x2, `transition_window` both to `Mapped`.
3. Assert `managed_layout.is_none()`.
4. Assert `tile_window(k0)` returns `true` but `managed_layout` stays `None` (deferred).
5. `register_managed_layout(Rect { x: 0, y: 0, width: 35, height: 100 })`.
6. Assert layout is `Some`, both keys contained.
7. Compute regions: assert both share `x == 0` and `width == 35`, and differ in `y`
   (`r0.y < r1.y`) → proves vertical stacking on tall/narrow startup.

### 5. Align integration test with `Mapped` lifecycle — `tests/integration_tiling.rs:1218`

In `tile_single_window_on_empty_workspace_occupies_full_screen`, the window must be
explicitly Mapped before tiling (it currently relies on a `Realized` window being
picked up by the layout, which the strict filter no longer does). Add one line between
`create_window` and `tile_window`:

```rust
let k0 = wm.create_window(NoopComponent);
wm.transition_window(k0, term_wm_core::window::WindowState::Mapped);
assert!(wm.tile_window(k0));
wm.register_managed_layout(AREA);
```

The import path is already used at line 1869 of the same file.

### No other changes needed

- `close_all_windows_then_tile_new_does_not_phantom` (line 1176) renders before tiling
  (`advance_frame`), so its WM already has a non-zero area — unaffected.
- `tile_window_key_respects_quadrant` (mod.rs:6684), the two maximized-open tests
  (mod.rs:4032, 4101): all call `register_managed_layout(80x24)` before `tile_window_key`
  → non-zero area → unaffected.
- No other test files (integration_basic, integration_new_window_focus, overlay_dismissal,
  panic_debug_log, integration_layout_resize) tile directly; they drive full frames.
- No `pending_tile`, flags, or state-machine changes. No `set_managed_area`, no seeding
  in `from_wm`, no changes to term_wm_app.rs, entry.rs, or tiling.rs.
