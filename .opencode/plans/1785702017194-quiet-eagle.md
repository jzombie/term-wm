# Plan: `term-session` Gateway (multi-channel supervisor + CLI administration + Windows daemonization)

## Goal

Replace the one-process-per-channel architecture with a **single gateway daemon** that hosts every channel in one process, add a CLI for listing/killing channels and connected sockets (identified by server-assigned conn id + connect time + physical size + hostname), and make Windows auto-background the daemon like Unix does. All functionality tested.

Design decisions (per user):

- Single **gateway socket** with method-level routing (no per-channel sockets, no per-channel server processes).
- **Session-kill vs socket-kill are separate, unambiguous operations.**
- No env-var-based identity — identity is a **server-assigned `conn_id`**; channel binding is server-side and authoritative (a client can only reach the channel it attached to).
- Legacy single-channel `--server` mode is **replaced entirely**.

## 1. Wire protocol (`crates/term-session-muxio-service-definitions`)

### `src/methods.rs`

Existing pattern: each method implements `RpcMethodPrebuffered` with private bitcode encode structs (`SpawnRequest`/`SpawnResponse`, etc.).

| Method | Input | Output | Notes |
|---|---|---|---|
| `Attach` (new) | `(channel: String, hostname: String)` | `conn_id: usize` | Binds the connection to `channel`, records `hostname` + server-side `connected_at`. Identity is server-assigned; **not** client-suppliable. |
| `Spawn` (changed) | `(cmd: Option<Vec<String>>, cols, rows)` | `(id, cols, rows)` | **No channel in payload** — routed via the connection's bound channel (rejected if `Unattached`). **Idempotent/re-entrant**: existing live session → ignore `cmd`, apply `cols/rows` as implicit resize, return existing id; exited session or none → respawn (non-empty `cmd` overwrites the stored template, else template reused). |
| `ResizePty` (changed) | `(id, cols, rows)` | `(cols, rows)` | Routed via bound channel. |
| `CloseSession` (changed) | `(id)` | `()` | Routed via bound channel. |
| `WriteInput` (changed) | `(id, data)` | `()` | Routed via bound channel. |
| `ListSessions` → **`ListChannels`** (replaced) | `()` | `ListChannelsResponse { gateway_pid: u64, socket: String, channels: Vec<ChannelInfo> }` | `ChannelInfo { name, created_at_unix, session: Option<SessionInfo>, clients: Vec<ClientInfo> }`; `SessionInfo { id, cols, rows, exited, exit_code, title }`; `ClientInfo { conn_id, hostname, connected_at_unix: u64, cols, rows }`. Response carries the daemon's PID + bound socket for the CLI header (§2b). |
| `KillChannel` (new) | `(channel: String)` | `()` | Kills the channel's **session only** and force-detaches **all** of its sockets (authoritative server-side eviction: `conns.write()` → snapshot targets → drop guard → `channel.lock()` to shutdown each output stream, fail pending RPCs, evict each `ConnEntry` and channel `clients` entry). **Terminates the entire PTY process group, not just the session leader** (SIGTERM → escalate SIGKILL to `-pgid`; see §2). Channel stays registered; next attach respawns. |
| `KillClient` (new) | `(channel: String, conn_id: usize)` | `()` | Force-detaches **one socket**: removes from channel client/subscriber maps, ends its output stream, fails its pending RPCs, evicts its `ConnEntry`. |
| `ShutdownGateway` (new) | `()` | `()` | Stops the daemon (needed by tests + `term-session stop`). **Acts as a responsible process supervisor:** atomic `is_shutting_down` seal, then **snapshot-and-release** teardown — collect the active `ChannelState` set under a brief `channels.write()`, release it, and off-lock execute the full process-group termination (SIGTERM→SIGKILL escalation / `TerminateJobObject`) per channel. The handler returns `()` immediately; a detached task sleeps ≥50 ms for the transport to flush the response, then fires the exit oneshot. The daemon does **not** exit until every child tree is terminated and the `()` response is drained; no lock is held across the awaits. |
| `OnPtyResized`, `STREAM_INPUT`, `SUBSCRIBE_OUTPUT`, `PushOutput` | unchanged | | Streams route via the connection's bound channel. |

New `bitcode`-serializable types: `ChannelInfo`, `SessionInfo`, `ClientInfo` (timestamps as `u64` unix seconds; never `SystemTime` directly). New muxio error ids: `RPC_ERROR_UNATTACHED` (any RPC/stream on an unbound connection) and `RPC_ERROR_SHUTTING_DOWN` (any RPC/stream after shutdown begins).

### `src/channel.rs`

Add `pub fn gateway_channel_name() -> ChannelName`, **static and deterministic** — a fully reproducible, upstream-independent logical name. Resolution order:
1. `TERM_WM_GATEWAY` env var — **runtime-only** isolation override (injected by the test harness, CLI `--gateway`, or an operator), resolved at the moment of execution via `std::env::var("TERM_WM_GATEWAY")`;
2. else the static default `term-wm/<user>/gateway` where `<user>` is the current OS user — from `$USER`/`getpwuid` (Unix) or `USERNAME` env (Windows);
3. reject a bare/shared literal (e.g. `term-wm/__gateway__`) unless explicitly requested via `--gateway`/env.

**No build-time entropy — the compiled artifact is 100% deterministic.** There is **no `build.rs` RNG**, no `env!("...")`-injected hash, and no compile-time token. The logical IP name is derived only from platform user identity + the static literal, so identical source compiles to an identical binary (reproducible-build/SLSA compatible) and an upgraded binary probes the **same** endpoint as the running daemon (no orphaned-daemon black holes across `cargo install`/package updates). Protocol versioning, if ever needed, appends a predictably-changing literal (e.g. `term-wm/<user>/gateway-v1`), never randomness.

**Test isolation is the test harness's job — not the binary's.** `gateway_channel_name()` stays agnostic to suite mechanics; the harness generates a UUID per suite and injects it into every client/daemon subprocess via `std::process::Command::env("TERM_WM_GATEWAY", uuid)`. (A compile-time token would fail anyway: Cargo caches `build.rs` output, so two runs of unchanged `cargo test` reuse the same baked token and collide.)

**Binding is `muxio`'s responsibility — no manual IPC pathing.** The daemon only computes the logical `gateway_channel_name()` and hands it to `muxio` (`probe_ipc_endpoint` / `RpcIpcServer`). All OS-specific physical socket resolution, directory creation/scoping, permission/SDDL enforcement, and collision avoidance are `muxio`'s transport domain. The application layer must not `lstat`-validate, `chmod`, `umask`, `DirBuilder`, or otherwise hand-build filesystem paths. The static logical name above is purely the identity; the physical path stays entirely inside `muxio`.

## 2. Server (`crates/term-session-server`)

Refactor `src/session_server.rs` (currently a single flat `run_server` at `:158` holding `ServerState` at `:54`). Restructure around a gateway. Two-tier coordination to avoid a global I/O hot-spot mutex:

```
ServerState
├── conns: RwLock<HashMap<usize, ConnEntry>>          // routing table (read-mostly)
└── channels: Arc<RwLock<HashMap<ChannelName, Arc<Mutex<ChannelState>>>>>
```

- `ConnEntry { handle: RpcIpcConnectionContextHandle, state: ConnState, hostname, connected_at, cols, rows }`.
  - `conns` is a read-mostly routing map protected by `RwLock` (or `scc`/`dashmap`).
- **Strict non-nested lock ordering (kills the AB-BA deadlock):** the gateway **never holds two locks at once**. Both the `conns` map and each `ChannelState` are resolved-and-dropped in a strict sequence:
  1. resolve: take `conns.read()`, look up `(channel_id, Arc<ChannelState>)`, compute whatever must be, then **drop** the `conns` guard;
  2. acquire: then take `channel.lock()` and do the work.
  The ordering is always `conns → channel`, never `channel → conns`. Stream handlers resolve the channel id, drop `conns.read()`, and only then lock the channel — so I/O never concurrently holds `conns.read()` while another task holds `channel` awaiting `conns.write()`.
  - `KillChannel`/`KillClient`: `conns.write()` → snapshot the target `ConnEntry`s (and their channel ids) → **release** `conns` → then `channel.lock()` to finalize the PTY, close subscriber streams, and drop those client ids from the channel's `clients` map. No lock is shared between the two phases.
  - As a belt-and-suspenders fallback, deferred GC: a dead conn's own disconnect/eviction path removes its `ConnEntry` from `conns` (idempotent), so even a missed handler cannot wedge the table.
- `state: ConnState` modeled as an explicit state machine:
  ```rust
  enum ConnState {
      Unattached,                        // connected but not yet bound
      Attached(ChannelName),             // bound to a channel via Attach
  }
  ```
  Any `Spawn`/`ResizePty`/`WriteInput`/`CloseSession`/stream request arriving from an `Unattached` connection is rejected at the protocol layer with an explicit `RPC_ERROR_UNATTACHED` error (new muxio error id + client-facing message). `Attach` is the only transition that binds a connection.
- `ChannelState` = today's `ServerState` fields (`session`, `clients: HashMap<conn_id, ClientEntry>`, `subscribers`, `notify`, plus `cmd: Vec<String>` template for respawns, `input_tx`/`input_rx`). Each channel is independently `Mutex`-locked.
- Handler routing: prebuffered/stream handlers resolve `conn_id → conns` (id lookup only), fetch the channel's `Arc<Mutex<ChannelState>>`, drop the routing guard, then operate solely on the per-channel lock. High-throughput streams (STREAM_INPUT/SUBSCRIBE_OUTPUT) hold only the per-channel lock; other channels proceed concurrently.
- **Channel garbage collection (prevents unbounded `channels` growth) with tombstone re-verification (kills the split-brain race).** A channel is eligible for reaping when it has **zero connected clients AND its session has exited** (or never existed). To stop an in-flight `Attach` from resurrecting a channel that a concurrent GC is removing:
  - `ChannelState` carries an `is_reaped: bool` flag (starts `false`).
  - GC runs together with the map removal under a single `channels.write()` **and** re-locks the `ChannelState` inside that critical section to re-verify `clients.is_empty()` before deleting — after confirmed, set `is_reaped = true`, then `remove(channel)` from the map, then release. This guarantees the Arc is unreachable from the map before it's finalized.
  - Every `Attach`/`Spawn` that retrieved an `Arc<ChannelState>` from `channels.read()` must **lock that channel** and check `is_reaped`. If `is_reaped`, drop the stale Arc and **acquire `channels.write()` with a second map lookup inside the critical section (safe double-checked locking)**: re-`get()` the channel name — if the map now holds a non-reaped `ChannelState` (inserted by a racing thread between the read and the write lock), bind to **that** instance; only if the map is absent or still holds the reaped Arc may it instantiate and insert a fresh `ChannelState`. This makes reattachment convergent: a client can never bind to an orphaned instance, and concurrent attaches to the same name always resolve to the single canonical entry (no blind overwrite of a racing thread's fresh channel).
  - **Teardown (output-polling task / disconnect handler) MUST drop the per-channel `MutexGuard` entirely before requesting `channels.write()`** — strict re-entrant ordering, no AB-BA: the initiating handler evaluates `clients.is_empty() && session-exited` under the channel lock, then **`drop(guard)`**, then acquires `channels.write()`. It never holds `channel.lock()` while waiting on `channels` (that would deadlock against an `Attach` holding `channels.read()` and awaiting `channel.lock()`). This every GC/detach path bounds the table for scripting clients that mint unique channels.
- **`Spawn` is idempotent + re-entrant.** `Spawn` full decision matrix on a connection's bound channel:
  - no session or session `exited` **=> respawn**: `cmd` payload if `Some(non-empty)` **overwrites** the stored `cmd` template and is used for the new PTY; `None`/empty falls back to the existing template → respawn → return new id/geometry;
  - session exists & `!exited` **=> reuse**: ignore the incoming `cmd`, apply `cols`/`rows` as an implicit resize, return the existing id (mirrors current behavior at `session_server.rs:210-226`).
  Concurrent `Spawn`s serialize on the per-channel lock; a later `Spawn` can never silently override a live PTY's command.
- **`KillChannel` is authoritative — no client cooperation.** It (a) **signals the session's entire process group** via `pty.signal_process_group(SIGTERM)` and arms the exited-checked `SIGKILL` escalation (not just the session leader), (b) finalizes subscriber streams, (c) **force-evicts every bound socket** from `conns` and the channel's `clients` map, shutting down each client's output stream and failing its pending RPCs (same cleanup `KillClient` uses). **Every per-conn output task is explicitly cancelled, not just its map entry dropped** — see cancellation below.
- **Process-group termination — mechanism (pty) vs. policy (daemon), fully asynchronous.** The session leader is already launched in its own process group/session (portable-pty spawn via `setsid`; pgid exposed by the master's `process_group_leader()` at `pty.rs:373`), but `kill_child()` at `pty.rs:448` only `child.kill()`s the single pid and would orphan grandchildren. Layering:
  - **PTY engine = mechanism only, strictly non-blocking.** Add `pub fn signal_process_group(&self, signal: i32) -> PtyResult<()>` to `Pty` that translates to a single `libc::kill(-pgid, signal)` and returns immediately (Unix). **No temporal waits, no escalation, no `std::thread::sleep`, no `kill_tree`** — the engine never dictates grace periods or orchestrates multi-stage teardown. On Windows the pty still exposes the existing single-process `kill_child()` (Job-Object containment is a spawn-time concern; see below).
  - **Daemon = policy owner.** `KillChannel` / `ShutdownGateway` in `session_server.rs` own the full escalation sequence:
    1. handler (non-blocking) calls `pty.signal_process_group(SIGTERM)`, marks the session `kill_pending = true`, and **returns immediately** (no `thread::sleep`, no wait while holding any lock);
    2. `tokio::spawn`s a **detached escalation task** that `await`s `tokio::time::sleep(SIGKILL_GRACE)` (a `const`, non-blocking timer), then re-checks the session state: if the output-polling task has already set `exited` (session reaped during grace), the task **aborts instantly** — no blind `SIGKILL` (avoids the PID-reuse race where the kernel recycled the pgid); only if the session is still alive does it `pty.signal_process_group(SIGKILL)`.
    3. The RPC handler and `ChannelState` lock are released before the escalation task runs, so sibling channels keep servicing I/O during the grace window.
  On Windows, the process tree is managed **natively via a Win32 Job Object — no `taskkill`/shell-out**, and assignment is **race-free via `CREATE_SUSPENDED`**: create the job first (`CreateJobObjectW(NULL, NULL)`, `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`), then spawn the child a **single time** with **`CREATE_SUSPENDED`** (`0x00000004`) set in `creation_flags`, extract its raw process handle, `AssignProcessToJobObject(job, child)`, then `ResumeThread` on the child's primary thread handle. There is **no second spawn / re-spawn phase** — `CREATE_SUSPENDED` is only a bit passed to `CreateProcess`; resumption is thread-execution control (`ResumeThread`), never process re-instantiation. `KillChannel` calls `TerminateJobObject(job, exit_code)` (dispatched on a spawned task, not awaited inline).
- **Explicit async-task cancellation (no dangling CG tasks).** The per-connection output loop (`SUBSCRIBE_OUTPUT` push task that polls PTY output → `respond`) and the input writer task are each governed by a `CancellationToken` (`tokio_util::sync::CancellationToken`) stashed in `ConnEntry`/`ClientEntry`. During kill/evict, the gateway calls `token.cancel()` **synchronously in the kill operation** so the task's next `tokio::select!`/await point aborts it and the subscriber `respond` sender is dropped. Because the output worker drives the PTY render loop, cancellation is coordinated with `ChannelState` output-polling such that a killed conn's finalizer runs before the next broadcast — no detached task survives the evicted `conn_id`.
- **One** `RpcIpcServer`, **one** endpoint, **one** connection-event loop. Disconnect (or transport-level close) removes conn from `conns` + prunes the channel's client/subscriber maps + `recalculate_pty_size` + geometry broadcast (existing logic, moved into `ChannelState` as in `ServerState` at `:107`/`:141`).
- `Session::spawn` keeps setting `TERM_WM_CHANNEL` (informational only — never used for identity).
- Replace `run_server(config)` / `SessionServerConfig` with `run_gateway(gateway: ChannelName)`. **Channels are created lazily on first `Attach`/`Spawn`.** Handlers that arrive without a bound channel are rejected via the `Unattached` state.
- `ShutdownGateway` handler runs an **atomic shutdown seal**, then snapshot-and-release teardown (never holding a lock across `.await` — a `RwLockWriteGuard` spanning a `.await` is `!Send` and stalls the reactor): (1) set `is_shutting_down` (an `AtomicBool` in `ServerState`) to `true` with `Ordering::SeqCst` **before** the teardown window opens; (2) briefly acquire `channels.write()`, drain/collect the `Arc<ChannelState>` set into a snapshot, then immediately drop the lock; (3) iterate off-lock, issuing per-channel `pty.signal_process_group(SIGTERM)` (non-blocking) and `tokio::spawn`ing the exited-checked `SIGKILL` escalation tasks; (4) `.await` the joined escalation handles so every child tree ends; (5) return `()` to the caller **immediately** and let a detached task end `run_gateway` (see below).
  - **Shutdown exit signal is deferred — never triggered from inside the RPC handler** (that would tear down the muxio transport before the `ShutdownGateway` response frame is flushed, making the client see a generic reset instead of a clean success). The handler instead `tokio::spawn`s a detached task that `sleep`s ≥50 ms (a named `const`, `SHUTDOWN_FLUSH_GRACE_MS`, reusing the flush-grace pattern already used for session-exit in `session_server.rs:545`) to allow the transport to drain the `()` response, and only then fires the exit oneshot that ends `run_gateway`. The RPC handler returns immediately.
  - **Every incoming RPC/stream handler (`Attach`, `Spawn`, `ResizePty`, `WriteInput`, …) checks `is_shutting_down` as its first step**; if `true`, it immediately rejects with a new `RPC_ERROR_SHUTTING_DOWN` error id. Because the seal is set before the lock is dropped, no new `ChannelState`/PTY can be spawned during the asynchronous grace period — the snapshot covers every channel that can exist, and nothing minted mid-teardown is orphaned. Concurrent disconnects stay free since no global lock is held across the await.

## 2a. Amendment: daemon idle-exit (session-driven + attached-client-aware, never client-driven)

**Semantics:** the gateway must **never** shut down merely because no clients are connected — a live session persists across client disconnects (that is the multiplexer guarantee the daemon tests assert). It also must **never** shut down while a client is mid-initialization (has `Attach`ed but not yet `Spawn`ed). Teardown may only proceed when **zero live sessions AND zero attached clients** exist.

Exit rule — the predicate is `(live_sessions == 0) ∧ (attached_clients == 0)`:

$$\text{should\_exit} = (\text{no channel has a live non-exited session}) \;\land\; (\text{no conn is in } \texttt{ConnState::Attached})$$

- The daemon stays up while **any** channel holds a live session, even with **zero** connected clients (re-probe after a full disconnect must still find it; session must survive).
- The daemon also stays up while **any** connection is `Attached` to a channel — even if that channel's `session` is currently `None` (the client has attached but not yet issued `Spawn`). Checking only PTY state would race an in-flight `Attach→Spawn` sequence: a session exiting elsewhere would observe `session: None` on the freshly-attached channel, conclude zero work remains, seal the gateway, and reject the pending `Spawn` with `RPC_ERROR_SHUTTING_DOWN`. The `Attached`-conn check closes that window.
- When the **last** live session ends AND no conn remains `Attached`, the gateway initiates the **same snapshot-and-release shutdown as `ShutdownGateway`** (seal, signal any remaining process groups, spawn the exited-checked `SIGKILL` escalations, await them, then the deferred ≥50 ms flush-grace oneshot that ends `run_gateway`). Reuse the shared shutdown helper rather than duplicating teardown.
- An idle **channel** (zero clients + exited session) is reaped by the existing tombstone GC; the daemon-level check runs after a reap: if the `channels` map holds no live session **and** `conns` holds no `Attached` conn, exit. Channels created but never spawned (no session) do not count as "live", but a conn `Attached` to such a channel **does** hold the daemon open.

Implementation notes (`crates/term-session-server/src/session_server.rs`):
- Extract the `ShutdownGateway` teardown body into a shared `async fn shutdown_gateway(state: &SharedState)` that: seals, snapshots, signals process groups, spawns+awaits escalations, then fires the deferred oneshot. `ShutdownGateway` RPC and the idle-exit path both call it.
- The per-channel output-polling task, after clearing an exited session and reaping the channel, checks `state.channels` (read lock) for any remaining live session **and** `state.conns` (read lock) for any `ConnState::Attached(_)`; if none of either, invoke the shared shutdown. Both checks run under brief read locks and are dropped before any `.await`.
- Guard against double-fire: the oneshot is `Mutex<Option<Sender>>` (already taken-once); both triggers are idempotent under the `is_shutting_down` seal.
- `run_gateway` currently returns 0 on `shutdown_rx`; the idle-exit path uses the same signal, so `--daemon` and `term-session stop` both exit cleanly.

Tests:
- integration: after a session's child exits (e.g. `mock exit 0`) and its channel is reaped, the gateway **task ends** (`run_gateway` returns) — verified by the spawned gateway task completing, not by an RPC (the endpoint is gone).
- integration: a session that **outlives all clients** keeps the daemon alive — spawn a long-lived `sleep` session, drop all clients, assert the gateway is still reachable (existing `session_reconnect`/daemon-test coverage), then `ShutdownGateway`.
- integration: **an in-flight attach holds the daemon open** — attach a client to a fresh channel, drop it (or let a sibling session exit) while the client has attached but NOT yet spawned; the gateway must stay up (its `Attached` conn blocks idle-exit). Then `Spawn` succeeds, and only after the client detaches and the session ends does the daemon exit.
- daemon binary test: `attach --channel x -- mock exit 0`; once the session exits, the client detaches, and the channel reaps, the daemon process exits on its own (no `stop` needed) — poll for process termination.

## 2b. Amendment: daemon process visibility (rename + PID in `list`)

**Problem:** every `term-session` process is the same binary. With a single gateway plus several clients (`attach`, `list`, embedded panes), `ps`/`top`/`htop`/Task Manager show several identical `term-session` entries, and it is ambiguous which PID is the daemon versus which are interactive clients.

Three concrete measures make the server process unmistakable:

### 1. Rename the daemon process at startup

When running as `--daemon`, the process title / thread name is mutated so process managers display `term-session-daemon` (or `term-session-d`) instead of generic `term-session`.

Implementation by platform (new `set_daemon_process_name()` called from `run_daemon_mode` in `crates/term-session/src/main.rs`):
- **Linux:** `libc::prctl(libc::PR_SET_NAME, name.as_ptr() as usize, 0, 0, 0)` with `name = "term-session-d"` (comm name is capped at 15 bytes). Visible in `ps -comm`, `top`, `htop`.
- **macOS:** `libc::pthread_setname_np(name.as_ptr())` with `name = "term-session-daemon"`. Visible in Activity Monitor / `ps`.
- **Windows:** `SetThreadDescription(GetCurrentThread(), wide)` with `"term-session-daemon"` (UTF-16). Visible in the Description column of Process Explorer / Process Hacker.
- Guard each behind `#[cfg(...)]`; on non-matching platforms it is a no-op. Keep it a best-effort call (ignore errors) — it is cosmetic and must never affect functionality. NOTE: `pthread_setname_np`/`SetThreadDescription` affect the calling thread only; the daemon's main thread is where it is called, which is sufficient for process-manager display.

### 2. Document flag-based identification

Process managers that show full argv distinguish the roles (documented in README / `--help`):
- `term-session --daemon` → **server daemon**
- `term-session attach --channel dev` → **client** attached to `dev`
- `term-session list` → **admin CLI call**

Quick Unix lookup: `pgrep -f "term-session --daemon"` or `ps aux | grep "[t]erm-session --daemon"`.

### 3. Expose the gateway PID in `list`

Include the daemon's `pid` in the `ListChannels` RPC response so `term-session list` can print it in the header:

```text
Gateway Daemon PID: 18492 | Socket: term-wm/jzombie/gateway

CHANNEL    SESSION    GEOMETRY    CLIENTS    CONNECTED
dev        1          120x40      2          2026-08-02 16:30:00
prod       1          80x24       1          2026-08-02 16:31:12
```

Wire changes:
- `crates/term-session-muxio-service-definitions`: add `ListChannelsResponse { gateway_pid: u64, socket: String, channels: Vec<ChannelInfo> }` (replaces the bare `Vec<ChannelInfo>`), so the CLI can render the header from one call.
- `crates/term-session-server/src/session_server.rs`: `ListChannels` handler fills `gateway_pid` from `std::process::id()` and `socket` from the gateway name it bound.
- `crates/term-session/src/main.rs`: `list` prints the header (`Gateway Daemon PID: <pid> | Socket: <name>`) above the existing vertical list; `--json` gains top-level `gateway_pid`/`socket` fields (keyed per call, not per channel).

Tests:
- integration: `ListChannels` returns a nonzero `gateway_pid` equal to the current process id (the test gateway runs in-process) and the bound socket name.
- CLI (manual / daemon binary test): `term-session list` header shows the daemon PID; optional assertion that `pgrep -f "term-session --daemon"` matches that PID on Unix.
- daemon binary test: after `--daemon` starts, assert the process is renamed — verify via `process::Command` inspection of the process comm/name per platform (Linux: `/proc/<pid>/comm` == `term-session-d`; macOS: skip or best-effort; Windows: `QueryFullProcessImageName`/thread description best-effort), or at minimum assert the daemon still functions after renaming (no functional regression).

## 3. Client (`crates/term-session-client`)

- `run_session(socket: &str, channel: &ChannelName, cmd: &[String], cols, rows)`:
  1. connect to gateway; register `OnPtyResized` (unchanged);
  2. `Attach::call((channel, hostname))` → conn_id (before any session RPC, so stream routing works);
  3. `Spawn::call((Some(cmd) if non-empty else None, cols, rows))` → session id + geometry (replaces the current hardcoded `Spawn::call(client,(None,term_cols,term_rows))` at `lib.rs:276` and its inline `term_cols/term_rows` read);
  4. open `SUBSCRIBE_OUTPUT` / `STREAM_INPUT` streams (calls unchanged; routed by bound channel);
  5. rest of the TUI loop unchanged.
- `remote_pane.rs`: `ResizePty`/`CloseSession` payloads unchanged (id-based); no edits needed beyond signature compatibility.
- `Attach` hostname from `hostname` crate (already a workspace dep) or env.
- Client must surface `RPC_ERROR_UNATTACHED`/`RPC_ERROR_SHUTTING_DOWN`/other gateway errors from `Spawn`/streams as clear messages rather than a hang.
- **ABI/transport fault interception (Layer 4, no silent panic):** the client's initial gateway connect + `Spawn` handshake must explicitly match `muxio` transport and `bitcode` deserialization errors. On a decode/transport parse fault (e.g. an upgraded client against a legacy daemon on the same socket, or wrong frame shape), the client prints a strictly formatted diagnostic to stderr — e.g. `FATAL: Protocol ABI mismatch. A legacy daemon is occupying the IPC socket. Manually terminate the daemon process before continuing.` — and exits with a non-zero exit code. No bare panic or silent drop.

## 5. Windows daemonization (`src/auto_spawn.rs`)

Replace `creation_flags(0x08000000)` at `auto_spawn.rs:52` with named consts (per AGENTS.md magic-strings rule):

```rust
const CREATE_NEW_PROCESS_GROUP: u32 = 0x00000200;
const DETACHED_PROCESS: u32 = 0x00000008;
cmd.creation_flags(CREATE_NEW_PROCESS_GROUP | DETACHED_PROCESS);
```

`DETACHED_PROCESS` gives the child no console, so the parent console's `CTRL_CLOSE_EVENT` never reaches it (CREATE_NO_WINDOW is ignored when DETACHED_PROCESS is set). **It does not disinherit standard handles** — without explicit redirection, wrappers/CI/SSH runners hang waiting for the daemon's inherited `stdin`/`stdout`/`stderr` pipes to close. Therefore each handle must be mapped to `NUL` (`Stdio::null()`), applied cross-platform at `auto_spawn.rs:28-30`, and on Windows the process is additionally started with `inherit_handles(false)` (`.inherit_handles(false)` via `std::os::windows::process::CommandExt`) so no launch-terminal handles leak into the daemon. Add a `--daemon-selfcheck <marker-path>` flag (test-only): the daemon writes `windows-no-console` (via `GetConsoleProcessList == 0`) or `unix-session-leader` (`getsid(0) == getpid()`) to the marker after binding.

## Notes

- `ListChannels` CLI output: vertical list by default (channel block + per-client lines). Header shows `Gateway Daemon PID` + socket name (§2b).
- `kill` is unambiguous: `--kill-session <channel>` (or bare `kill <channel>`) ends the session; `--kill-client <channel> CLIENT_ID` detaches one client by its `conn_id`. There is no `--self` CLI form (out-of-band `--self` would evict the transient admin wrapper, not the target; in-band leave is the client closing its socket). `list` shows each client's `conn_id` (the CLIENT_ID) alongside its OS `pid`, so the operator can kill exactly the client they see.
- Gateway name is overridable via `--gateway` / `TERM_WM_GATEWAY` for explicit isolation.
- The default gateway name is the **deterministic static value** `term-wm/<user>/gateway` (no build-time entropy, reproducible-build/SLSA compatible, upgrade-safe — a new binary probes the same endpoint as the running daemon). Test isolation is achieved by the harness injecting a unique `TERM_WM_GATEWAY` per suite into the spawned client/daemon subprocesses.
- Identification of peers uses server-assigned `conn_id` + server-side `connected_at` + physical size + hostname; the conn_id is authoritative and immutable — the bindable channel is derived from it only.
- `ChannelState` must own `cmd`, `input_tx`/`input_rx`, `clients`, `subscribers`, `session`, and its `Notify`. `recalculate_pty_size` + `notify_clients` move into `impl ChannelState` unchanged.
- On child exit, the per-channel output-polling task finalizes subscribers and **clears the session**; it does not exit the daemon per-session — but when the **last** live session clears (no other channel holds a live session), the gateway triggers the shared session-driven shutdown (see §2a amendment). The daemon never exits merely because clients disconnected.
- Routing never holds the global lock during I/O: only a `conns` read-lookup, then the per-channel `Mutex`. Cross-channel throughput is independent.
- Server remains authoritative on teardown: `KillChannel`/`KillClient`/disconnect all actively evict `ConnEntry`, cancel their per-conn output/input tasks, and sockets — nothing relies on a client disconnecting gracefully.
- Channel reaping is tombstone-safe (`is_reaped` + re-lock inside `channels.write()`), so a concurrent `Attach` cannot split-brain a channel into two disjoint instances.
- **Mechanism vs. policy (process teardown):** the PTY engine exposes only non-blocking primitives — `signal_process_group(signal)` (a single `kill(-pgid, signal)`) and the existing `kill_child()` — and never sleeps, waits, or escalates. All multi-stage escalation (SIGTERM → grace → exited-checked SIGKILL), grace timers, and `kill_pending`/`exited` arbitration live in the daemon supervisor (`session_server.rs`). The escalation aborts if the session exited during grace (PID-reuse safety).
- **Daemon visibility:** the daemon renames its process/thread (`term-session-daemon`/`term-session-d`) via platform APIs at `--daemon` startup, and `list` prints the gateway PID + socket name in its header (§2b) so the server process is never ambiguous against CLI clients.

## §2d. Post-release CLI hardening (bare-help, creation-order listing, `stop --force`)

Three user-facing behavior changes on top of the released gateway:

### 1. Bare `term-session` shows help — `attach` removed, `--channel` + trailing `[CMD]...` via `--`

**Problem:** `main.rs` `None => attach(...)` made a bare `term-session` auto-spawn the daemon and attach. The user wants: a bare run shows the help menu (exit 2, clap missing-argument convention) and never auto-connects; the `attach` subcommand is confusing and redundant, so it is **removed**; the command is passed as **trailing positional args after `--`** (POSIX end-of-options — like `sudo --`, `cargo run --`, `time -p --`), NOT a `--command` flag, so system commands never collide with term-session's own subcommands; and **no `-c` short flag exists** (`--channel` is long-only).

## §2g. Balanced tiling: reweight splits by descendant leaf count

**Problem:** `TilingLayout::insert_window_balanced` (`crates/term-wm-core/src/layout/tiling.rs:124`) splits the largest leaf with hardcoded `weights: [1,1]` and nothing rebalances, so a BSP tree's shallow leaves hog space — `-n 3` yields **½ + ¼ + ¼** (one large, two tiny), and `-n 4` yields ½ + ¼ + ⅛ + ⅛. The existing `LayoutNode::normalize_weights` (layout-engine/tiling.rs:607) sets every split to `[1,1,…]` and does NOT fix this (it preserves the depth imbalance).

**Fix — leaf-count weighting (Option 1, equalize on every insert):** set every internal split's child weights to the number of descendant leaves, so each leaf gets exactly `1/N` regardless of tree depth. For `[W1 | Split[W2,W3]]` → root weights `[1,2]`, inner `[1,1]` → W1=W2=W3=⅓.

**Layout engine (`crates/term-wm-layout-engine/src/tiling.rs`):** add a post-order reweight method on `LayoutNode<Id>`. `weights` is assigned **directly** (not via `zip`), because `LayoutNode::split`/`split_resizable` (lines 93, 102) initialize `weights: Vec::new()`, so `zip` would silently write nothing; the total uses **saturating** arithmetic:
```rust
/// Reweight every Split to its children's descendant leaf counts, so all
/// leaves occupy an equal share of the parent area. Returns this subtree's
/// leaf count.
pub fn reweight_by_leaf_count(&mut self) -> u16 {
    match self {
        LayoutNode::Leaf(_) | LayoutNode::Void(_) => 1,
        LayoutNode::Split {
            children, weights, ..
        } => {
            let counts: Vec<u16> = children
                .iter_mut()
                .map(|c| c.reweight_by_leaf_count())
                .collect();
            let total = counts.iter().fold(0u16, |acc, &x| acc.saturating_add(x));
            *weights = counts;
            total
        }
    }
}
```
(`split_rects_weighted` normalizes by weight sum, so the weights are directly proportional leaf counts.)

**Core (`crates/term-wm-core/src/layout/tiling.rs`):**
- **SEV-1 fix — uninitialized-area fallback + unbiased direction guard.** Startup inserts run before the first render pass, so `insert_window_balanced` receives `managed_area` = `Rect{0,0,0,0}`; with a 0×0 area the old `width/2 < MIN_TILE_WIDTH` guard is always true, forcing `InsertPosition::Bottom` for every window → a purely vertical 1D tree (all windows stacked as thin strips). Fix at the entry of `insert_window_balanced`:
  ```rust
  let area = if area.width == 0 || area.height == 0 {
      Rect { x: 0, y: 0, width: crate::constants::DEFAULT_FLOAT_WIDTH,
             height: crate::constants::DEFAULT_FLOAT_HEIGHT }
  } else { area };
  ```
  and replace the biased `if … else if …` guard with an explicit pair match:
  ```rust
  let can_split_h = largest_rect.width / 2 >= crate::constants::MIN_TILE_WIDTH;
  let can_split_v = largest_rect.height / 2 >= crate::constants::MIN_TILE_HEIGHT;
  let pos = match (can_split_h, can_split_v) {
      (true, false) => InsertPosition::Right,
      (false, true) => InsertPosition::Bottom,
      _ => { /* visual aspect ratio, as before */ }
  };
  ```
- `insert_window_balanced`: call `self.root.reweight_by_leaf_count()` at the end after every branch (void-fill, `split_root`, normal `insert_leaf`). Fixes startup and interactive new-window tiling.
- `remove_window` (line 248): call `self.root.reweight_by_leaf_count()` after `remove_leaf`/`cleanup_after_removal`/`clear_leaf`, so closing a window rebalances the remaining leaves (currently they keep stale pre-removal weights).

**Tests:**
- Layout engine: build the `[leaf | split(leaf, leaf)]` tree, `reweight_by_leaf_count`, assert via `regions(area)` that all three leaves have equal area (the ½+¼+¼ case → ⅓ each). Also `[leaf | split(leaf | split(leaf, leaf))]` (4 leaves) → all ¼.
- Core: `insert_window_balanced` for N windows → every region equal for N = 1, 2, 3, 4.
- Core: **asymmetric removal rebalance** — build a 4-window equal tree, `remove_window` one leaf, assert the remaining 3 leaves are each ⅓.
- Core: **SEV-1 quadrant grid** — `TilingLayout::new_void()`, insert 4 windows with a `0×0` area, then project onto `80×24`: assert exactly 2 distinct column `x`s and 2 distinct row `y`s, each region 40 wide × 12 tall (a true 2×2 grid, not a vertical strip stack).

**Docs/CHANGELOG:** note balanced-by-default tiling on new windows and on window close (startup and interactive).

## §2f. `term-wm` multi-window command support (repeatable `--run`)

**Problem:** `term-wm -n 3 -- ls -la` was parsed as `cmds=["ls","-la"]` and the old code opened **one window per token** (README bug: `ls` in window 1, `-la` in window 2). The positional is now ONE command; add a repeatable `--run`/`-r` flag so distinct commands can fill multiple windows.

**CLI (`src/main.rs`):**
- `Cli` gains `run_cmds: Vec<String>` — `#[arg(short = 'r', long = "run", value_name = "CMD", action = clap::ArgAction::Append)]` (each occurrence = one window command).
- Positional `cmds` stays `num_args = 0.., trailing_var_arg = true, allow_hyphen_values = true`, but is interpreted as **one** command (joined with spaces) appended **after** the `--run` commands (matches the confirmed Window 1/2/3 ordering: `-r vim -r htop -- git log --oneline` → windows vim, htop, git-log).
- `main()`:
  ```rust
  let mut commands = cli.run_cmds;
  if !cli.cmds.is_empty() {
      commands.push(cli.cmds.join(" "));
  }
  let total = if commands.is_empty() {
      cli.count.unwrap_or(2).max(1)
  } else {
      commands.len().max(cli.count.unwrap_or(0)).max(1)
  };
  ```

**Window allocation (`App::new_with`):** one window per command (shell + `command_to_send`), then default shells to fill `total`. `commands` is owned by value — **consume it** with `into_iter()` (no `.clone()` per element):
```rust
let mut used = 0;
for cmd in commands {
    let cb = default_shell_command();
    if let Err(e) = app.spawn_terminal_with_command(cb, Some(cmd)) {
        tracing::error!("Window spawn error: {}", e);
    }
    used += 1;
}
for _ in used..num_windows {
    if let Err(e) = app.wm_new_window() {
        tracing::error!("Window spawn error: {}", e);
    }
}
```

**Help text:** update `cmds` ("one command for a window, from the whole argv after `--`") and add `run_cmds` doc.

**README (`README.md` lines ~41-51):** keep `-n 3 -- ls -la`; add `-r, --run <CMD>` to the options list and multi-command examples:
```
cargo run --release -- -r "vim -l" -r "htop"                 # 2 windows, one command each
cargo run --release -- -n 4 -r "vim -l" -r "htop" -- git log --oneline  # 4 windows: 3 commands + 1 default shell
```

**Tests:** extract two pure helpers in `src/main.rs` and unit-test them:
- `fn build_commands(run_cmds: Vec<String>, positional: Vec<String>) -> Vec<String>` — `run_cmds` ++ `[positional.join(" ")]` when positional non-empty.
- `fn total_windows(count: Option<usize>, commands: &[String]) -> usize` — when non-empty, `commands.len().max(count.unwrap_or(0))` (no trailing `.max(1)`, since `commands.len() >= 1`); when empty, `count.unwrap_or(2).max(1)`.
- Cases: `-n 3 -- ls -la` → 1 command, 3 windows; **`-n 0` with no commands → 1** (clamped); **`-n 0` with 2 `--run` → 2** (commands take precedence); `-n 1` with 2 `--run` → 2; **joined positional containing spaces/hyphens (`git log --oneline`) stays one command**; empty → default 2.
