# Plan: Different color for mouse cursor representation (#253)

Note: the code-review snapshot referenced #259 (snap preview outline) and a stale changelog —
#259 is already **closed** (PR #260) and **already implemented** in this repo
(`render_ghost_preview`, draw_plan_renderer.rs:1807-1871, renders outline-only) and already
documented under `## [0.9.27-alpha]` (CHANGELOG.md:11). No #259 work remains; this plan is
scoped to #253 plus its changelog entry.

## Goal
The mouse cursor overlay is currently rendered as an inverted cell (`Modifier::REVERSED`).
Per issue #253, render it as a solid colored block instead — **blue by default**, and
user-configurable via the `Theme` struct (the codebase's only configuration mechanism).

Scope note: the issue says "ultimately user-configurable". There is no file/CLI config
infrastructure in this repo (`WmConfig`/`Theme` are built in Rust code only, defaulting to
`NOIR`). Making the cursor color configurable = adding theme fields that a programmatic
custom `Theme` can override. Full end-user config files are out of scope and would require
new config infrastructure.

This change targets the **mouse** cursor (`render_cursor_overlay`), NOT the terminal text
block cursor (`terminal.rs` `render_screen`), which is a separate feature.

## Design
The cursor overlay must:
- Paint the hovered cell with `cursor_bg` (blue) background + `cursor_fg` (white) glyph.
- **Preserve** the cell's existing modifiers (BOLD/DIM/ITALIC…) and its glyph — mutate
  fg/bg only via `cell.set_fg()` / `cell.set_bg()`, never `cell.set_style(Style::default()…)`
  which would strip modifiers.
- Follow the theme's semantic-role architecture: register `FgColor::CursorFg` /
  `BgColor::CursorBg` so `Theme::fg()`/`Theme::bg()` resolve them and the exhaustive WCAG
  test audits them.

## Changes

### 1. `crates/term-wm-core/src/theme.rs`
- Add `CursorFg` to `enum FgColor` (~line 65) and `CursorBg` to `enum BgColor` (~line 87).
- Add two fields to `struct Theme` (near `selection_bg`/`selection_fg`, ~line 143):
  ```rust
  /// Background of the mouse-cursor block overlay.
  pub cursor_bg: Color,
  /// Foreground (glyph tint) of the mouse-cursor block overlay.
  pub cursor_fg: Color,
  ```
- Add blue defaults to the `NOIR` const (~line 247, after selection):
  ```rust
  // Mouse cursor overlay (blue per #253)
  cursor_bg: Color::Rgb(0, 90, 200),
  cursor_fg: Color::Rgb(255, 255, 255),
  ```
  (≈6.4:1 contrast — passes WCAG AA.)
- Wire the new roles into the accessors:
  - `Theme::fg()`: `FgColor::CursorFg => self.cursor_fg`
  - `Theme::bg()`: `BgColor::CursorBg => self.cursor_bg`
- **`PHYSICALLY_IMPOSSIBLE` additions** (required so `exhaustive_fg_times_bg()` passes):
  the cursor overlay always sets fg+bg together, so cursor colors are never mixed with any
  other role. Add a grouped comment block + every cross-pair:
  - `(CursorFg, X)` for every `BgColor` X except `CursorBg` and the Profile* bgs (13 entries —
    Profile* are already skipped by the test's `matches!` guard at theme.rs:570). Justification:
    "never combined — cursor fg only on cursor bg".
  - `(Y, CursorBg)` for every `FgColor` Y except `CursorFg` (19 entries). Justification:
    "never combined — cursor bg only carries cursor fg".
  This leaves exactly one evaluated cursor pair — `(CursorFg, CursorBg)` — which passes 3:1.
  No ad-hoc contrast test is added; the exhaustive matrix covers it.
