# Fix: Arrow Keys Blocked in Embedded Man Pages / git log

## Root Cause

The `ScrollViewComponent` in `ScrollKeyMode::Full` intercepts bare Up/Down arrow keys for native scrollbar navigation (mapped to `TermWmAction::ScrollUp`/`ScrollDown`). This breaks standard terminal behavior where arrow keys should **always** be forwarded to the PTY child process.

Additionally, mouse scroll wheel routing lacks proper heuristics (alternate screen detection, mouse tracking, custom margins) to decide whether to scroll the native scrollbar or forward events to the terminal.

## Design (per user guidance)

| Input | Routing |
|-------|---------|
| Keyboard arrow keys (Up/Down/Left/Right) | Always → PTY child process |
| Keyboard PageUp/PageDown/Home/End | ScrollViewComponent (native scrollbar) |
| Keyboard Shift+Up/Down | Native scrollback navigation (modifier-based) |
| Mouse scroll wheel | Heuristic: alternate screen / mouse tracking / margins → PTY or native scrollbar |

## Changes

### 1. `crates/term-wm-ui-components/src/scroll_view.rs` — Remove arrow key interception

- In `on_key`: Remove the `is_full && kb.matches(ScrollUp/ScrollDown, key)` branch entirely
- Arrow keys (Up/Down/Left/Right) always fall through to `self.content.borrow_mut().handle_events()`
- Keep PageUp/PageDown/Home/End interception (correct in all modes)
- Update `ScrollKeyMode::Full` tests: `scroll_view_full_mode_intercepts_all_scroll_keys` → split into tests for page keys still intercepted, arrow keys passed through
- Update `scroll_view_pagination_mode_passes_up_down` — rename to reflect arrow keys pass in ALL modes

### 2. `crates/term-wm-core/src/keybindings.rs` — Rebind ScrollUp/ScrollDown

- Change `ScrollUp` default binding from `(KeyCode::Up, NONE)` → `(KeyCode::Up, SHIFT)` (or remove entirely)
- Change `ScrollDown` default binding from `(KeyCode::Down, NONE)` → `(KeyCode::Down, SHIFT)`
- Update any tests in keybindings.rs that reference these defaults

### 3. Mouse scroll heuristic (`scroll_view.rs:on_mouse` + `terminal.rs`)

- The alternate screen check already exists in `TerminalComponent::handle_events` (line 125: `!self.pane.borrow_mut().alternate_screen()`)
- No code change needed for mouse heuristics at this time — they already work correctly via `direct_mode`
- The `TerminalComponent::render_screen` already uses `pane.alternate_screen()` to suppress scroll sync (line 539, 596)

### 4. `src/main.rs` — Verify default mode (no change needed)

- Terminal is already created with `ScrollKeyMode::PaginationOnly` (line 195)
- After removing arrow interception from `Full` mode, this setting is still correct
