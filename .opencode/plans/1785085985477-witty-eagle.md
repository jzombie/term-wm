# Fix: Arrow Keys Blocked in Embedded Man Pages / git log

## Root Cause

Two independent problems:

1. **Keyboard arrow keys intercepted**: `ScrollViewComponent` in `ScrollKeyMode::Full` intercepts bare Up/Down (bound to `ScrollUp`/`ScrollDown`) for native scrollbar. Arrow keys must **always** be forwarded to the PTY child — standard terminal behavior.

2. **No passive state tracker for PTY byte stream**: Mouse scroll routing relies on ad-hoc `direct_mode` flag and `alternate_screen()` calls through vt100 parser. These lack a unified deterministic state machine to detect alternate screen, mouse tracking, or custom margins.

## Design

### Input Routing Table

| Input | Routing |
|-------|---------|
| Keyboard arrow keys (Up/Down/Left/Right) | Always → PTY child process (never intercepted) |
| Keyboard PageUp/PageDown/Home/End | ScrollViewComponent (native scrollbar) |
| Keyboard Shift+Up/Down | Native scrollback navigation (modifier-based) |
| Mouse scroll wheel | Query `Pane::requires_app_routing()` → PTY or native scrollbar |

### PtyStateTracker — Passive ANSI State Machine

A `vte::Perform` implementor that absorbs escaped bytes and updates internal booleans. No callbacks, no side effects.

**Tracked states:**
- `is_alt_screen_active` — set by `\e[?1049h` / `\e[?1047h` / `\e[?47h`
- `mouse_tracking_mode` — decoded from DECSET 1000/1002/1003
- `is_sgr_mouse_active` — set by `\e[?1006h`
- `is_alt_scroll_mode_active` — set by `\e[?1007h`
- `has_custom_margins` — set by `DECSTBM (\e[r)` when margins ≠ full height

**Decision:** `requires_app_routing() = is_alt_screen_active || mouse_tracking_mode != None || has_custom_margins`

    pub fn new(terminal_height: u16) -> Self;

### 5. `crates/term-wm-pty-engine/src/pty.rs` — Wire byte channel + tracker

**Channel** (reads from ParserReadLoopArgs → Pty):
- Add `tracker_tx: crossbeam_channel::Sender<Vec<u8>>` to `ParserReadLoopArgs`
- Add `tracker_rx: crossbeam_channel::Receiver<Vec<u8>>` + `PtyStateTracker` to `Pty`
- Reader thread: after each `reader.read(&mut buf)` → `tracker_tx.send(buf[..n].to_vec())`
- Channel capacity: 64 (bounded backpressure; if main thread falls behind, older batches are dropped — eventual consistency is fine for state heuristics)

**State processing** (`Pty::requires_app_routing`):
- Drain `tracker_rx` via `try_recv()` in a loop
- Feed each batch through `vte::Parser::advance_bytes(&mut tracker, &bytes)`
- Return `tracker.requires_app_routing()`
- Called from main thread only (via `Pane` trait) — no locks needed

**Resize propagation** (`Pty::resize`):
- After `parser.screen().set_size(...)`, call `self.tracker.resize(new_rows)`

## Concurrency Model

```
Reader Thread                          Main Thread
─────────────                          ───────────
reader.read(&mut buf)                  event loop:
  → shared_parser.lock().process()       → mouse scroll event
  → tracker_tx.send(buf[..n])              → comp.handle_events()
    (bounded channel, 64 cap)                → pane.requires_app_routing()
                                                → drain tracker_rx
                                                → vte::Parser::advance_bytes(&mut tracker)
                                                → tracker.requires_app_routing()
```

- Tracker is **never** mutated on the reader thread (only bytes are sent via channel)
- Tracker is **only** mutated on the main thread, in `requires_app_routing()`, which drains the channel
- No locks needed on the tracker (single-threaded access)
- Channel bounds memory: if main thread lags, old batches are dropped (eventual consistency is sufficient for state heuristics)
- The vt100 parser (existing) remains on the reader thread — unchanged
