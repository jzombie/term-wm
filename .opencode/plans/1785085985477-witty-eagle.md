# Fix: Arrow Keys Blocked in Embedded Man Pages / git log

## Root Cause

Two independent problems:

1. **Keyboard arrow keys intercepted**: `ScrollViewComponent` in `ScrollKeyMode::Full` intercepts bare Up/Down (bound to `ScrollUp`/`ScrollDown`) for native scrollbar. Arrow keys must **always** be forwarded to the PTY child — standard terminal behavior.

2. **No unified state tracker for PTY byte stream**: Mouse scroll routing currently relies on a `direct_mode` flag and ad-hoc `alternate_screen()` calls embedded in render/event code. There's no passive state machine that observes the PTY byte stream to detect alternate screen, mouse tracking, or custom margins — which are the correct heuristics for mouse scroll routing.

## Design

### Input Routing Table

| Input | Routing |
|-------|---------|
| Keyboard arrow keys (Up/Down/Left/Right) | Always → PTY child process |
| Keyboard PageUp/PageDown/Home/End | ScrollViewComponent (native scrollbar) |
| Keyboard Shift+Up/Down | Native scrollback navigation (modifier-based) |
| Mouse scroll wheel | Query `PtyStateTracker::requires_app_routing()` → PTY or native scrollbar |

### PtyStateTracker (new)

A passive `vte::Perform` implementor that absorbs PTY byte stream output and updates internal booleans. No callbacks, no side effects — purely synchronous, deterministic state queryable on demand.

**Tracked states:**
- `is_alt_screen_active` — set by `\e[?1049h` / `\e[?1047h` / `\e[?47h` sequences
- `mouse_tracking_mode` — decoded from DECSET 1000/1002/1003
- `is_sgr_mouse_active` — set by `\e[?1006h`
- `is_alt_scroll_mode_active` — set by `\e[?1007h`
- `has_custom_margins` — set by `DECSTBM (\e[r)` when margins ≠ full terminal height

**Unified decision:** `requires_app_routing() = is_alt_screen_active || mouse_tracking_mode != None || has_custom_margins`

## Changes

### 1. New file: `crates/term-wm-core/src/pty_state_tracker.rs`

Create `PtyStateTracker` struct implementing `vte::Perform` (the `vte` crate is already a dependency — confirmed via `vt100` and `vte` in `Cargo.toml`).

Fields: `is_alt_screen_active`, `mouse_tracking_mode`, `is_sgr_mouse_active`, `is_alt_scroll_mode_active`, `has_custom_margins`, `terminal_height`.

Implement `requires_app_routing()` accessor per the decision matrix above.

### 2. `crates/term-wm-pty-engine/src/` — Wire PtyStateTracker into PTY read path

- Add `PtyStateTracker` as a field in the `Pane` trait or concrete PTY handler
- Every time bytes are read from the child PTY, feed them through a `vte::Parser` into `PtyStateTracker`
- Expose `tracker()` accessor on `Pane` so the UI layer can query state

### 3. `crates/term-wm-ui-components/src/scroll_view.rs` — Remove arrow key interception

- In `on_key`: Remove the `is_full && kb.matches(ScrollUp/ScrollDown, key)` branch entirely
- Arrow keys (Up/Down/Left/Right) always fall through to `self.content.borrow_mut().handle_events()`
- Keep PageUp/PageDown/Home/End interception (correct in all modes)
- Update `ScrollKeyMode::Full` tests: `scroll_view_full_mode_intercepts_all_scroll_keys` → arrow keys now pass through
- Update `scroll_view_pagination_mode_passes_up_down` — rename to reflect arrow keys pass in ALL modes

### 4. `crates/term-wm-core/src/keybindings.rs` — Rebind ScrollUp/ScrollDown

- Change `ScrollUp` default from `(KeyCode::Up, NONE)` → `(KeyCode::Up, SHIFT)`
- Change `ScrollDown` default from `(KeyCode::Down, NONE)` → `(KeyCode::Down, SHIFT)`
- Update any tests referencing these defaults

### 5. `crates/term-wm-ui-components/src/terminal.rs` — Use PtyStateTracker for mouse routing

- Replace `!self.pane.borrow_mut().alternate_screen()` check (line 125) with `tracker.requires_app_routing()` call
- In `handle_events` for mouse scroll: query `tracker.requires_app_routing()` instead of checking `direct_mode` to decide whether to intercept or forward

### 6. `src/main.rs` — No change needed

- Terminal already created with `ScrollKeyMode::PaginationOnly` (line 195)
- `PtyStateTracker` integration happens inside the crate layers
