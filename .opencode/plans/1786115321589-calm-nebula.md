# Horizontal scrollbar: use a bottom-half-block thumb (▄)

## Question / answer
The horizontal scrollbar currently renders with ratatui's `DOUBLE_HORIZONTAL`
default set: **thumb `█` (full block), track `═`, begin `◄`, end `►`** (see
`render_scrollbar_oriented`, `crates/term-wm-ui-components/src/scroll_view.rs:153-170`,
driven from `ScrollViewComponent::render` at line 563 with
`ScrollbarOrientation::HorizontalBottom`).

Yes — a **lower-half-block thumb (`▄`)** would look better for this
bottom-anchored scrollbar: the thumb hugs the bottom edge of the viewport
(reads as a grounded "slider on a rail" instead of a heavy full-height bar),
and the track `═` remains visible through the top half of the thumb cell. This
is a common, subtle TUI scrollbar pattern.

## Change
`crates/term-wm-ui-components/src/scroll_view.rs`
1. Add module-level const near the top:
   `const HORIZONTAL_SCROLLBAR_THUMB: &str = "▄";`
2. In `render_scrollbar_oriented`, pick the thumb symbol by orientation:
   - `ScrollbarOrientation::HorizontalBottom | ScrollbarOrientation::HorizontalTop`
     → `Scrollbar::new(orientation).thumb_symbol(HORIZONTAL_SCROLLBAR_THUMB)`
   - otherwise (vertical) → `Scrollbar::new(orientation)` unchanged
   Keep default track `═` / begin `◄` / end `►`.

## Tests
- New unit test in `scroll_view.rs` `#[cfg(test)]` module: render a horizontal
  scrollbar (`render_scrollbar_oriented` with `HorizontalBottom`, total > view)
  into a 1-row `Buffer` and assert the thumb column contains `▄` and a track
  column contains `═`.
- Existing tests unaffected (verified): `markdown_viewer.rs::scrollbar_does_not_overlay_text`
  only asserts a non-space glyph exists; no insta snapshots pin scrollbar glyphs;
  `terminal.rs` / `text_renderer.rs` scrollbar tests exercise drag math, not glyphs.

## Out of scope
- Vertical scrollbar thumb (would analogously be a right-half block `▌`); only
  change horizontal per request. Mention to user as optional follow-up.
