# Top panel strip: chevron spacing + scroll-thumb dragging

## Problems (user)
1. **Chevrons get buried** — there's no horizontal space between the window
   entries and the `◀`/`▶` indicators; they butt against each other.
2. **Dragging doesn't feel like dragging** — the dragged entry currently jumps
   to the target gap and gets a `REVERSED` highlight. The user wants the window
   title to act like a **scroll thumb**: keep its NORMAL styling and glide with
   the cursor as you drag.

## Design

### A. Chevron gap
`crates/term-wm-sys-ui-components/src/wm_top_panel/window_strip.rs`:
- Add `const CHEVRON_GAP: u16 = 1;`.
- When overflow: `scroll_viewport_width = max_entries_width.saturating_sub(left + right + 2*CHEVRON_GAP)`
  and `entries_start_x = strip_rect.x + left_indicator_width + CHEVRON_GAP`.
- Chevrons stay at the strip edges (`rect.x`, `rect.x + width - 1`), so the first
  entry is `CHEVRON_GAP` right of `◀` and the last entry is `CHEVRON_GAP` left of `▶`.

### B. Scroll-thumb dragging (title glides with the cursor)
Same file:
- **State:** re-add `drag_cursor_col: Option<i32>`; add `drag_grab_col: i32`
  (the offset from the pressed entry's left edge to the press column); re-add
  `drop_index: Option<usize>` (drop-bar target). Keep `drag_moved`.
- **Press on an entry:** set `drag_source`, `drag_moved = false`,
  `drag_grab_col = column as i32 - hit_rect.x`, `drop_index = None`.
- **Drag:** set `drag_cursor_col = column`, `drag_moved = true`; edge-pan as today;
  compute `insert_index` (reduced-space, existing `target_index`) and store
  `drop_index = Some(insert_index)`. Return `Consumed` (NO live dispatch).
- **Release:** dispatch `ReorderWindow { key: drag_source, index: drop_index }`
  ONCE (if `drag_moved` and the index differs from the source's current index),
  then clear state.
- **Render during an active drag** (`drag_source` + `drag_moved`):
  - Skip the dragged key in the normal entry loop (so it isn't rendered twice).
  - Compute the ghost's X in `i32` with a clamp that can never receive `max < min`:
    ```rust
    let vp_start = entries_start_x as i32;
    let max_thumb_x = (vp_start + scroll_viewport_width as i32 - width as i32).max(vp_start);
    let thumb_x = (drag_cursor_col - drag_grab_col).clamp(vp_start, max_thumb_x);
    ```
  - **Absolute viewport clipping:** slice the ghost label with the SAME
    `slice_by_columns` viewport-intersection math as static entries —
    `vp_x = thumb_x - vp_start`;
    `visible = min(scroll_viewport_width, vp_x + width) - max(0, vp_x)`;
    slice `slice_by_columns(&chunk, max(0, -vp_x) as usize, visible as usize)` and draw at
    `entries_start_x + max(0, vp_x)` — so the ghost NEVER bleeds over the `▶` chevron
    or the tiling indicator, exactly like static entries.
  - **Highest Z-order:** draw the ghost AND the `DROP_INDICATOR` bar only AFTER the
    static entry loop finishes, so the floating title rides above all static
    entries (nothing overdraws it).
  - Ghost uses its NORMAL style (`focused`/unfocused from `focus_current`) — no
    `REVERSED`/highlight.

This is the "icon in a panel" / scroll-thumb feel: the title stays under your
cursor (grab offset preserved), keeps its styling, and snaps into place on release.

## Tests (`crates/term-wm-sys-ui-components/src/wm_top_panel/mod.rs`)
- **Chevron gap:** when overflow, `p.strip.entries_start_x == strip_rect.x + left + CHEVRON_GAP`,
  and the right chevron column is `CHEVRON_GAP` past the last entry's end.
- **Ghost follows cursor:** press an entry, drag to a column, render; assert the
  dragged title's rendered cells sit at `clamp(cursor - grab)` (buffer
  inspection) and it appears only once (not duplicated in the normal loop).
- **Commit on release:** update `drag_live_reorders_to_front` → `Drag` now returns
  `Consumed`; `Release` returns `Action(ReorderWindow { key, index })`.
  Update `drag_off_right_edge_clamps_to_end` → same Release path.
- `plain_click_does_not_emit_reorder` and the capture-contract test stay valid.
