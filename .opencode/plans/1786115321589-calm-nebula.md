# Add monocle + tiling/float actions to the default command-palette allow-list

## Goal
`new_custom` / `new_with_config` currently install a fixed 5-action
command-palette allow-list:
`CloseMenu`, `ToggleMouseCapture`, `ToggleClipboardMode`,
`ToggleWindowSelection`, `ExitUi`.

Add the two "View group" actions so the default standalone app can manage
window modes from the palette:
- `ToggleMonocle` (monocle mode, menu icon "▢")
- `ToggleTiling` (View: Float/Tile Windows, menu icon "⊞")

These are the exact actions the Command Palette's View group uses
(`crates/term-wm-core/src/window/window_manager/command_palette.rs:226-248`),
and `runner.rs:98-99` already dispatches both to
`wm.toggle_monocle()` / `wm.toggle_tiling()`. `DEFAULT_SUPPORTED_MENU_ACTIONS`
(term-wm-core constants.rs:19-20) already contains both — this change brings
the standalone allow-list in line with the full default set for these two.

## Changes — `src/term_wm_app.rs`

### 1. Default allow-list in `new_with_config` (lines 130-136)
Add the two variants to the `vec![...]` passed to `new_with_actions`:
`ToggleMonocle`, `ToggleTiling`. New list (7 actions):
`CloseMenu`, `ToggleMouseCapture`, `ToggleClipboardMode`,
`ToggleWindowSelection`, `ExitUi`, `ToggleMonocle`, `ToggleTiling`.

### 2. Staged doc comment (lines 58-62)
Update the "fixed, restricted command-palette allow-list" sentence to include
`ToggleMonocle` and `ToggleTiling`, so the doc stays accurate after the
previous validation. Keep the `new_with_actions` escape-hatch sentence.

### 3. Test `new_custom_limits_supported_menu_actions` (lines 524-537)
Update the expected slice to the new 7-action list. This keeps the guard that
`new_custom` exposes exactly its allow-list (not the full
`DEFAULT_SUPPORTED_MENU_ACTIONS` set, which additionally contains
`NewWindow`, `ToggleDebugWindow`, `ToggleSystemPanel`, `Help`).
