# Rename "New Window" → "New Terminal" (real, default-but-removable action)

## Intent (confirmed with user)
- Rename the concept `NewWindow` → `NewTerminal` everywhere (action variant, host
  trait method, user-facing labels, internal stable ids, test data).
- It must be a **real** action: clicking it spawns a new terminal window. Today
  `TermWmApp` (the `new_custom` path) does NOT override `WindowManagerHost::wm_new_window`,
  so it falls back to the trait's no-op default (`runner.rs:31-33`). The binary
  (main.rs) is the only app that actually spawns.
- Any other app built on `new_custom`/`new_with_config` gets `NewTerminal` in the
  command palette **by default** (added to the default allow-list), and can remove
  it via `new_with_actions`.

## Part B — TermWmApp provides a real `wm_new_terminal` (monotonic titles)

`src/term_wm_app.rs`:
- Add a monotonic sequence counter to the struct: `terminal_counter: usize` (init `0`
  in `from_wm`). Window counts are non-monotonic (closing a window decrements the
  count → title collisions), so titles must come from a never-decreasing counter.
- Add `use term_wm_ui_components::default_shell_command;` — the fn lives in
  `term-wm-ui-components/src/terminal.rs:795` (NOT main.rs) and is glob re-exported
  at the crate root; an explicit import removes any module-resolution ambiguity.
- Add `const NEW_TERMINAL_SCROLLBACK: usize = 2000;` (named const per AGENTS.md).
- In the `impl WindowManagerHost for TermWmApp<C>` block, override:
```rust
fn wm_new_terminal(&mut self) -> std::io::Result<()> {
    self.terminal_counter += 1;
    self.spawn_terminal_window(
        default_shell_command(),
        NEW_TERMINAL_SCROLLBACK,
        None,
        format!("Terminal {}", self.terminal_counter),
    )?;
    Ok(())
}
```
No feature gate needed — `spawn_terminal_window` / `default_shell_command` are
always available in term-wm.

`src/main.rs`: `App::wm_new_window` → `wm_new_terminal`, and **delegate** to the
`TermWmApp` implementation using **fully-qualified trait syntax** (avoids any trait
method-resolution ambiguity inside `impl WindowManagerHost for App`):
```rust
fn wm_new_terminal(&mut self) -> std::io::Result<()> {
    <TermWmApp<NoopComponent> as term_wm::runner::WindowManagerHost<
        AppRootComponent<NoopComponent>,
        LayerComponent,
        OverlayComponent,
    >>::wm_new_terminal(&mut self.inner)
}
```
This centralizes spawning in the facade (fixes the same pre-existing title-collision
bug in main.rs and removes the duplicate spawn logic). Consequence (single source of
truth): **the binary's interactive terminal titles change from "Shell {n}" →
"Terminal {n}"** — recorded in the CHANGELOG. `spawn_terminal_with_command` (used
for `--run` windows) is untouched.

## Part C — Default allow-list (8 actions), single source of truth

**Correction to review SEV-2:** the standalone list is *intentionally* a restricted
subset of `DEFAULT_SUPPORTED_MENU_ACTIONS` (guarded by
`new_custom_limits_supported_menu_actions`; dual_image must stay limited). So it
must NOT simply reference `DEFAULT_SUPPORTED_MENU_ACTIONS`. The valid DRY fix is a
named const for the standalone default set:

- In `src/term_wm_app.rs`, module scope:
```rust
const DEFAULT_STANDALONE_MENU_ACTIONS: &[TermWmAction] = &[
    TermWmAction::CloseMenu,
    TermWmAction::ToggleMouseCapture,
    TermWmAction::ToggleClipboardMode,
    TermWmAction::ToggleWindowSelection,
    TermWmAction::ExitUi,
    TermWmAction::ToggleMonocle,
    TermWmAction::ToggleTiling,
    TermWmAction::NewTerminal,
];
```
- `new_with_config`'s hardcoded `vec![...]` becomes
  `Self::new_with_actions(app_ctx, config, DEFAULT_STANDALONE_MENU_ACTIONS.to_vec())`.
  Note: there is exactly ONE hardcoded vec, in `new_with_config`;
  `new_custom` delegates through it (`new_custom` → `new_with_config` →
  `new_with_actions`), and `new_with_actions` takes `actions` as a parameter — so
  applying the const in `new_with_config` covers `new_custom` and `new_with_config`
  both. No inline action arrays remain in any constructor.
- Update the "Choosing a constructor" doc allow-list enumeration (lines ~58-62).
- Update test `new_custom_limits_supported_menu_actions` (8 actions).
