# Fix: top-panel list item disappears on mouse-down before dragging

## Problem (user)
Mouse-down on a top-panel window entry makes it disappear until the pointer starts
moving.

## Root cause (verified)
In `WindowStrip::render` (`crates/term-wm-sys-ui-components/src/wm_top_panel/window_strip.rs:243`):
```rust
if Some(key) == self.drag_source {
    continue; // drawn as a ghost after the loop
}
```
On `handle_press` (line 444-447) `drag_source` is set AND `drag_moved = false` (the
drag isn't armed until the cursor moves). So the entry is skipped from the normal
loop, but the ghost is only drawn when `self.drag_moved` is true (line 299). Between
Press and the first Drag there is a frame where the item is neither in the normal
loop nor rendered as a ghost → it disappears.

## Fix (one line)
`window_strip.rs:243` — only treat the entry as "being dragged" (skip it) once the
cursor has actually moved:
```rust
if Some(key) == self.drag_source && self.drag_moved {
    continue;
}
```
- Press (drag_moved = false) → the entry renders at its normal position.
- First Drag (drag_moved = true) → the entry is skipped and the gliding ghost is
  drawn. No disappearance gap.

## Tests (`crates/term-wm-sys-ui-components/src/wm_top_panel/mod.rs`)
- **`pressed_entry_stays_visible_before_drag`** (regression): press an entry (no
  Drag), render → the entry's text still appears at its normal position (the normal
  loop renders it; no ghost needed). Then send a Drag, render → the ghost appears at
  the cursor column and the entry is not duplicated in the normal loop.
- Existing drag/ghost tests (`drag_ghost_renders_at_cursor_and_not_duplicated`,
  `drag_ghost_then_release_reorders_to_front`) must still pass.
