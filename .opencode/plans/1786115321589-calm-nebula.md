# Plan: Modularize input handling — contain crossterm behind console/adapter

## Goal (user)
- More modularized mouse/input handling; stop duplicating it across crates.
- Long-term: swapable backend — a non-crossterm backend (mobile-targeting) can implement `EventSource`+`RenderTarget`.
- Resolve the two TODOs added on `feat/mobile-targeting--draft`:
  - `src/unified_event_source.rs:442` — "shouldn't set crossterm directly; should call console_event_source"

## Target layering
- `term-wm-crossterm-adapter` = ALL crossterm knowledge: translation (`try_translate_event`) + NEW canonical `set_mouse_capture`.
- `term-wm-console` = SOLE runtime crossterm boundary: owns input reading (sync `ConsoleEventSource` + NEW dumb-conduit `BackgroundConsoleReader`), delegates crossterm specifics to the adapter.
- Root `UnifiedEventSource` = pure multiplexer, crossterm-free; it is the SINGLE consumer that owns normalization + power-profile bookkeeping; delegates capture + reading to the console crate.
- `term-wm-core` unchanged (already crossterm-free; traits are the swapable-backend seams).

## Normalization ownership (invariant — from review)
`KeyboardNormalizer` is stateful (tracks drag/mouse-button holds). It must be applied EXACTLY ONCE, by the single active consumer:
- `ConsoleEventSource` path (standalone/embedded): normalizes in its own `read_internal` (it is the consumer).
- `UnifiedEventSource` + `BackgroundConsoleReader` path (binary): the reader sends RAW translated events (no normalization); `UnifiedEventSource` normalizes with its OWN existing `self.normalizer` when it drains/reads the channel.
`BackgroundConsoleReader` must carry NO normalization and NO state — it is a pure transport.

### 4. NEW `crates/term-wm-console/src/background_console_reader.rs`
A DUMB CONDUIT (per review — no `EventSource` impl, no state): the only place a background thread reads crossterm. It translates via the adapter and forwards RAW translated core `Event`s on a bounded channel. **No** normalizer, `event_queue`, `last_event_at`, `pending_work`, or `max_sleep_duration` — the consumer owns all bookkeeping. `Send`.

Thread loop (mirrors current root thread at unified_event_source.rs:106-130):
```rust
loop {
    if thread_shutdown.load(Ordering::Acquire) { break; }
    if crossterm::event::poll(CROSSTERM_POLL_INTERVAL /* 100ms, named const */).unwrap_or(false) {
        match crossterm::event::read() {
            Ok(evt) => if let Some(core_evt) = term_wm_crossterm_adapter::try_translate_event(evt)
                && tx.send(core_evt).is_err() { break; }   // NO normalize here
            Err(_) => break,
        }
    }
}
```

API (strictly restricted):
- `pub fn new() -> io::Result<Self>` — spawns thread named `"crossterm-input"`, `bounded(CONSOLE_EVENT_CHANNEL_CAPACITY = 256)`.
- `#[doc(hidden)] pub fn from_receiver(rx: Receiver<Event>, handle: JoinHandle<()>, shutdown: Arc<AtomicBool>) -> Self` — test/embedder seam (cross-crate, so not `#[cfg(test)]`).
- `pub fn receiver(&self) -> Receiver<Event>` — for the multiplexer's `select!`.
- `pub fn set_mouse_capture(&self, enabled: bool) -> io::Result<()>` — delegates to `term_wm_crossterm_adapter::set_mouse_capture`.
- `Drop` sets shutdown flag (detached thread; 100ms poll keeps it responsive — same as today).
- Tests: minimal — only the `from_receiver`/`receiver()` wiring and `set_mouse_capture` delegation (channel-injection, no-op thread handle). Translation coverage lives in the adapter; drain/normalize logic lives in UnifiedEventSource tests.

## Risks / notes
- `select!` borrows its receiver expressions for the whole block, so ALWAYS clone `self.rx`/`self.console_rx` to locals before the macro (O(1) Arc bump) — passing `self.rx` directly and mutating `self` in arms risks `cannot borrow *self as mutable` expansion errors.
- Disconnected console channel → busy-loop hazard → `console_alive` flag flips on `Err` and poll uses the original single-channel fallback (same as today's dead-input-thread behavior).
- `after(remaining)` must be created per iteration with current clamped `remaining`; zero-timeout poll guard `remaining > ZERO` avoids timer allocation in the drain loop.
- Two crossterm readers are mutually exclusive at runtime (binary uses `BackgroundConsoleReader` via `UnifiedEventSource`; standalone `TermWmApp::run` uses `ConsoleEventSource`). Document on `BackgroundConsoleReader`.
- Normalization is applied exactly once, by the active consumer (`ConsoleEventSource` in the standalone path; `UnifiedEventSource` in the binary path). `BackgroundConsoleReader` never normalizes.
- `ConsoleRenderTarget::exit()` DisableMouseCapture left unchanged (test-sensitive, different mechanism/backend).
