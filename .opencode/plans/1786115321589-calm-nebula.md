# Plan: Fix long-line paste "types over" in editors — DECAWM in `term-wm-vt100`

## Task
Bug (user-verified): paste a line WIDER than the terminal into pico/nano; editing it "types over"
stale cells. Only long lines (horizontal scroll). Preexisting in the base vt100 emulator.

## Root cause (verified)
`term-wm-vt100` does not implement **DECAWM (`ESC[?7h/l`)** — `decset`/`decrst`
(screen.rs:1145-1219) have no param-7 arm, so autowrap is always ON. Editors horizontally
scrolling a long line disable wrap and manage their own columns; with wrap forced on, a char at
the right margin wraps the virtual cursor down a row, desyncing it from the editor → text appears
"typed over."

## Approach — TEMPORARY DEV WIRING ONLY, NO VENDORING (user directive)
- **Do NOT vendor the crate.** The user patches the `term-wm-vt100` fork and publishes it
  manually under a new version.
- **Temporary `[patch.crates-io]` for local development only** in root `Cargo.toml`:
  ```toml
  [patch.crates-io]
  term-wm-vt100 = { path = "crates/term-wm-vt100" }
  ```
  - Exists only while the patched fork is being developed locally.
  - **Never committed** (a committed path-patch to a missing dir breaks every clean clone/CI).
  - Once the user publishes: bump `[workspace.dependencies] term-wm-vt100` to the new version and
    DELETE the `[patch]`. That is the permanent, committed solution.

## DECAWM implementation spec (crate-side; user publishes)

### 1. State tracking (`Screen`)
- Add `decuwm: bool` (default `true`). `DECSET 7` → true; `DECRST 7` → false.

### 2. Clamp cursor on `DECRST 7` (review)
Pending wrap is encoded as `cursor.col == size.cols`. On `DECRST 7`, clamp it so the cursor is
never out of bounds while wrap is disabled:
```rust
7 => {
    self.decuwm = false;
    if self.cursor.col >= self.size.cols {
        self.cursor.col = self.size.cols.saturating_sub(1);
    }
}
```

### 3. Character placement (`text()`) — rigid margin when wrap off
- `decuwm == true` (default): preserve existing xterm deferred-wrap behavior unchanged.
- `decuwm == false`:
  - If `cursor.col >= size.cols`, clamp `cursor.col = size.cols - 1`.
  - Write the cell at `cursor.col`.
  - Increment `cursor.col` by 1 only if `cursor.col < size.cols - 1`.
  - If `cursor.col == size.cols - 1`, leave it there. Do NOT set `cursor.col = size.cols`.
  - Skip the `col_wrap` row-advance entirely. Subsequent chars overwrite column W-1 until an
    explicit move (`CUP`, `CUF`, `CR`, `LF`).

### 4. `EL 0` (`ESC[0K`) at pending wrap (review)
When `cursor.col == size.cols` (pending wrap), the current erase range `size.cols..size.cols` is
empty and leaves column W-1 stale. In the `EL` handler, if `cursor.col >= size.cols`, first clamp
`cursor.col = size.cols - 1`, THEN compute the erase bounds, so column W-1 is cleared. Also clear
any pending-wrap state.

## Regression suite (crate-side; the fork currently ships no tests)
- **`decawn_off_clamps_to_right_margin`**: 80-col, `ESC[?7l`, write 85 chars → `cursor.row == 0`,
  `cursor.col == 79`, pending wrap false, row 1 empty, cell (0,79) == 85th char.
- **`decawn_toggle_resets_pending_wrap`**: write 80 chars with wrap on (pending wrap) →
  `ESC[?7l` → pending wrap false, cursor clamped to 79, next char overwrites cell 79.
- **`long_line_horizontal_scroll_simulation`**: replay `ESC[?7l` → `CUP` → write to margin →
  `ESC[0K` → `ESC[?7h`; assert no characters spill to adjacent rows.
- **`el_clears_last_column_in_pending_wrap_state`** (review): with `cursor.col == size.cols`, send
  `ESC[0K`; assert cell `size.cols - 1` is cleared and pending wrap is cleared.

## Add pty-engine regression test for DECAWM (repo-side guard)
The DECAWM tests live in the fork's own suite, which `cargo test --workspace` does NOT run. Add a repo-side regression test in `crates/term-wm-pty-engine/` so the emulator the workspace builds against is verified to honor `ESC[?7l` (autowrap off).

- Location: `crates/term-wm-pty-engine/src/pty.rs`, `#[cfg(test)] mod tests`.
- Test through the PRODUCTION ingestion path (no subprocess): reuse the existing
  `make_parser_test_args()` helper + `parser_read_loop`, feeding `\x1b[?7l` + 85 chars on the
  fixed 24×80 parser. This guards DECAWM AND the reader→parser delivery:
  ```rust
  #[test]
  fn parser_read_loop_decawn_off_does_not_wrap() {
      let mut args = make_parser_test_args();
      let mut payload = Vec::new();
      payload.extend_from_slice(b"\x1b[?7l");
      payload.extend_from_slice(&[b'x'; 85]);
      args.reader = Box::new(std::io::Cursor::new(payload));
      let shared = Arc::clone(&args.shared_parser);
      parser_read_loop(args);

      let screen = shared.lock().unwrap().screen().clone();
      assert_eq!(
          screen.cursor_position(),
          (0, 79),
          "DECAWM off must clamp the cursor to the right margin"
      );
      assert_eq!(
          screen.cell(0, 79).unwrap().contents(),
          "x",
          "the 85th char must overwrite the margin cell, not wrap"
      );
      assert!(
          (0..80).all(|c| screen.cell(1, c).is_none_or(|cell| cell.contents().is_empty())),
          "row 1 must remain empty (no wrap)"
      );
  }
  ```
- FAILS if the emulator lacks DECAWM (`ESC[?7l` ignored → chars wrap to row 1 → assertions
  fail), so it protects the integration point regardless of fork/published crate source.
- Uses only existing helpers (`make_parser_test_args`, `parser_read_loop`, `Cursor`) — fully
  deterministic, no subprocess, no timing.
