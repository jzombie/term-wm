# Fix: Command Palette doesn't close when clicking a window (regression)

## Problem (user)
Regression from the earlier chevron fix: with the Command Palette open, clicking a
window no longer closes it.

## Root cause (verified)
My `palette_stays_open` logic (runner.rs, palette outside-click barrier) keeps the
palette open when `handled && !produced_action`. But `handle_outside_click` returns
`true` ("handled") for THREE different cases:
1. Top-panel chevron scroll — `ComponentOwner::Layer` returns `Consumed`, no action
   (the case I wanted to keep open).
2. Clicking a window body — `ComponentOwner::Window` calls `focus_app_window(key)`
   (mod.rs:2479-2481) and returns `true` with NO queued action.
3. Clicking window chrome (resize/drag/buttons) — `ComponentOwner::Chrome` focuses
   (mod.rs:2465-2477) and returns `true` with NO queued action.

So cases 2/3 are `handled && !produced_action` → `palette_stays_open == true` → the
palette stays open. The boolean return can't distinguish a chrome scroll from a
window focus.

## Fix — report what `handle_outside_click` did (minimal churn)
`crates/term-wm-core/src/window/window_manager/mod.rs`:
- Add `pub enum OutsideClickResult { Ignored, LayerConsumed, Focused, ActionQueued }`
  with `pub fn is_handled(&self) -> bool`. (`LayerConsumed` = a `ComponentOwner::Layer`
  or `Overlay` consumed the event with no action — e.g. a top-panel chevron scroll.
  Named `LayerConsumed` to avoid confusion with `ComponentOwner::Chrome`, which maps
  to `Focused`.)
- Extract the body of `handle_outside_click` into
  `pub fn handle_outside_click_precise(...) -> OutsideClickResult`:
  - Layer/Overlay `Action` → push action, `ActionQueued`.
  - Layer/Overlay `Consumed` → `LayerConsumed` (top-panel chevron scroll).
  - Layer/Overlay `Ignored` → continue scanning.
  - `Chrome`/`Window` → focus the window, `Focused`.
  - nothing handled → `Ignored`.
- `handle_outside_click(...) -> bool` becomes `handle_outside_click_precise(...).is_handled()` —
  unchanged behavior for all existing callers (help barrier, overlay_dismissal tests,
  the 11 window_manager tests).

`crates/term-wm-core/src/runner.rs` (palette outside-click barrier):
- Use `handle_outside_click_precise`; close the palette UNLESS the result is
  `LayerConsumed`:
  ```rust
  let result = app.wm().handle_outside_click_precise(...);
  if result == OutsideClickResult::Ignored {
      app.wm().handle_mouse_focus_click(...);
  }
  drain_action_queue(app, &mut actions);
  if !matches!(result, OutsideClickResult::LayerConsumed) {
      app.wm().close_command_palette();
  }
  ```
- **Ordering note (kept drain-then-close):** the palette closes AFTER draining
  actions, per the existing comment ("Process panel/overlay actions BEFORE closing
  the palette so the OpenCommandPalette toggle behavior works correctly"). Closing
  BEFORE draining would break the toggle: the runner's `OpenCommandPalette` handler
  reopens the palette when `command_menu_visible()` is already false, so a menu-button
  click would close-then-reopen instead of toggling closed. Drain-then-close makes the
  toggle action take effect first, and `close_command_palette()` is then a no-op.
- Remove the now-unneeded `palette_stays_open` helper and its two unit tests.

Effect:
- Top-panel chevron → `LayerConsumed` → palette stays open, list scrolls. ✓
- Click a window / window chrome → `Focused` → palette closes + window focuses. ✓ (fixes the regression)
- Menu button / tiling label → `ActionQueued` → action drains (toggle closes palette), then close is a no-op. ✓
- Genuine outside click → `Ignored` → focus-under-cursor + close. ✓
