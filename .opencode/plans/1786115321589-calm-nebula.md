# Monocle: chevron clicks must not close the Command Palette

## Problem (user)
In Monocle mode, clicking a `◀`/`▶` chevron on the top-panel window strip
immediately closes the Command Palette instead of scrolling the list.

## Root cause (verified)
The runner's Command Palette outside-click barrier
(`crates/term-wm-core/src/runner.rs:548-582`):
1. When the palette is visible and a mouse Press lands outside
   `command_palette_bounds()`, it calls `handle_outside_click(...)`.
2. `handle_outside_click` dispatches to the top-panel layer FIRST
   (`window_manager/mod.rs:2436-2451`); the chevron scrolls the strip and returns
   `EventResult::Consumed`, so `handle_outside_click` returns `true` (handled).
3. But runner.rs:573 then **unconditionally** calls `close_command_palette()` —
   even though the panel consumed the click. So the palette closes despite the
   chevron being handled.

In non-monocle this is masked because the palette's `command_palette_bounds()`
typically includes the top row, so the click goes to the palette directly; in
monocle the chevron is outside the palette dialog → the outside-click path runs.

## Fix (minimal — per user: only no-action chrome clicks keep the palette open)
`crates/term-wm-core/src/runner.rs` (~548-582): only close the palette on a
genuine outside click or when an action was produced; leave it open when a chrome
layer consumed the click WITHOUT producing an action (the chevron case).

Restructure:
```rust
let handled = app.wm().handle_outside_click(
    mouse_evt.column,
    mouse_evt.row,
    &evt,
    &mut actions,
    palette_key,
);
let produced_action = !actions.is_empty();
if !handled {
    // Genuine outside click — activate the window under the cursor.
    app.wm().handle_mouse_focus_click(mouse_evt.column, mouse_evt.row);
}
drain_action_queue(app, &mut actions);
// Close the palette UNLESS a chrome layer consumed the click with no action
// (e.g. chevron scroll) — that keeps the palette open and the list scrolls.
// A produced action (FocusWindow / ToggleTiling) closes it as before, and the
// OpenCommandPalette action toggles it closed via its own dispatch.
if !(handled && !produced_action) {
    app.wm().close_command_palette();
}
update_selection_snapshot(app);
return flush_state_changes(app, driver, ControlFlow::Continue, false, None);
```

Effect:
- **Chevron click** → panel `Consumed`, no action → palette stays open, list scrolls (requested).
- Menu button → `OpenCommandPalette` action → drained → toggles palette closed (unchanged).
- Window-entry / tiling-label click → action produced → palette closes (unchanged).
- Genuine outside click (window/empty) → `handled=false` → focus window + close (unchanged).
