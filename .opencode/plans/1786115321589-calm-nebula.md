# Fix: unfiltered keybinding hints in bottom panel during Monocle + Command Palette

## Root cause (verified)
Two independent code paths push keybinding hints into `WmBottomPanelComponent`:

1. **Filtered (correct):** `WindowManager::register_managed_layout`
   (`crates/term-wm-core/src/window/window_manager/layout.rs:276-320`) derives an
   `ActionLayer` from `self.input_mode` and calls
   `keybindings().bottom_hints_for_layer(MAX_BOTTOM_HINTS, layer)`. With the
   Command Palette open, `input_mode == CommandPalette` → only palette-layer
   actions are shown.
2. **Unfiltered (bug):** `render_overlays` in
   `crates/term-wm-console/src/draw_plan_renderer.rs:844-861` (monocle-cramped
   branch) calls `wm.keybindings().bottom_hints(MAX_BOTTOM_HINTS)` — no layer
   filter — and **overwrites** the filtered hints via `SetKeybindingHints` right
   before drawing the overlay bottom row.

Why it only shows in monocle: in cramped monocle the normal bottom panel slot
claims zero height (`layout.rs:324-357`), so the only visible bottom row is the
overlay drawn by `render_overlays`. Non-monocle never enters the line-788 branch,
so the filtered hints survive.

`bottom_hints()` → `bottom_hints_filtered(max, None)` (no layer check);
`bottom_hints_for_layer(max, layer)` filters by `TermWmAction::layer()`.

## Fix (amended per review): eradicate the render-phase mutation
`register_managed_layout` already pushes the correct layer-filtered hints every
frame — in every mode, including cramped monocle (it runs before `render_overlays`,
and pushes hints regardless of the panel's claimed height). The secondary
`SetKeybindingHints` dispatch in `render_overlays` is therefore redundant AND
destructive (it clobbers the filtered set with the unfiltered one). The rendering
pipeline must stay read-only: it should only call `render()` on state established
during the layout phase.

### 1. `crates/term-wm-core/src/window/window_manager/layout.rs`
Add `pub fn bottom_panel_hints(&self) -> Vec<(TermWmAction, Vec<String>)>` in the
`impl<C,L,O> WindowManager` block (near `register_managed_layout`):
- `match self.hint_visibility { HintVisibility::Always => ..., _ => Vec::new() }`
- when `Always`:
  - if `self.config.wm_command_menu_enabled`: derive layer from `self.input_mode`
    (`CommandPalette → ActionLayer::CommandPalette`, `Help → ActionLayer::Help`,
    else `Global`) → `self.keybindings().bottom_hints_for_layer(crate::constants::MAX_BOTTOM_HINTS, layer)`
  - else → `self.keybindings().bottom_hints(crate::constants::MAX_BOTTOM_HINTS)`

Replace the entire `match self.hint_visibility { ... }` block in
`register_managed_layout` (lines 278-320) with:
```rust
let hints = self.bottom_panel_hints();
if let Some(p) = self.get_semantic_component_mut(super::layer_manager::ComponentTag::BottomPanel) {
    p.process_action(&crate::components::ComponentAction::SetKeybindingHints(hints));
}
```
(Behavior identical; just delegates. This is the ONLY production call site for
`bottom_panel_hints()` — the render pipeline must not use it.)

### 2. `crates/term-wm-console/src/draw_plan_renderer.rs` — DELETE the mutation
In `render_overlays`, monocle-cramped bottom-panel branch (lines 851-860), remove
the hint retrieval and the `SetKeybindingHints` dispatch entirely. The component's
hints were already set correctly by `register_managed_layout`. The branch becomes:
```rust
let mut bottom_hb = HitboxRegistry::new();
if let Some(p) = wm.get_semantic_component_mut(ComponentTag::BottomPanel) {
    let ctx = ComponentContext::new(false).with_screen_area(bottom_area);
    p.render(backend, bottom_area, &ctx, &mut bottom_hb);
}
wm.hitbox_registry_mut().merge(bottom_hb);
```
This restores unidirectional flow: layout phase mutates state, render phase reads
it.

## Tests
### Unit test for `bottom_panel_hints` (layout.rs `#[cfg(test)]`, `NoopComponent`)
- Default (`input_mode` Passthrough): contains Global action
  `OpenCommandPalette`, and is non-empty.
- After `open_command_palette_overlay(...)`: excludes `OpenCommandPalette`,
  contains a `CommandPalette`-layer action (e.g. `FocusNext`).
- `set_hint_visibility(OnDemand)` → empty vec.
- `wm_command_menu_enabled = false` (via config) → unfiltered set still includes
  `OpenCommandPalette`.

### Render-level test (draw_plan_renderer.rs `#[cfg(test)]`)
Regression guard for the render-phase mutation. Using the existing `make_wm()`
helper: build a WM, enter cramped monocle (`update_monocle_mode(width < threshold)`
with `monocle_mode = On`), open the command palette
(`open_command_palette_overlay`), call `register_managed_layout(area)` then
`render_overlays(backend, wm)`, and assert via the existing
`WmBottomPanelComponent::keybinding_hints()` getter that the stored hints are the
CommandPalette-layer filtered set (i.e. render_overlays did NOT clobber them).
Before the fix this test fails (hints contain `OpenCommandPalette`/Global actions);
after the fix it passes.
