# Extract a reusable `TabBarComponent<K>` + refactor the top panel to use it

## Goal
Move the top panel's core tab logic (horizontal scroll, chevron overflow, drag-to-
reorder ghost, edge-panning, auto-scroll-to-active, hit-testing, close buttons) out
of the window-manager-specific `WindowStrip` into a reusable, generic UI component in
`term-wm-ui-components`, then make the top panel embed it (no duplicated logic).

## Naming
`TabBarComponent` → file `tab_bar.rs` (per AGENTS.md, no "component" in filename).
"TabBar" is the idiomatic term for a horizontal row of draggable/closable tabs
(browsers, IDEs), clearer than "tab strip".

## New component: `crates/term-wm-ui-components/src/tab_bar.rs`
Move the logic from `wm_top_panel/window_strip.rs`, generalized and enriched:
```rust
pub struct TabItem<K> {
    pub key: K,
    pub label: String,
    pub closable: bool,          // render a ✕ close affordance; disabled otherwise
    pub style_override: Option<Style>, // per-tab style; None → theme default
}

pub enum TabBarEvent<K> {
    Select(K),
    Close(K),                                    // ✕ clicked on a closable tab
    Reorder { key: K, target_index: usize },
}

struct DragState<K> {
    source: K,
    cursor_col: i32,
    grab_col: i32,
    drop_index: usize,
    moved: bool,
}

pub struct TabBarComponent<K> {
    items: Vec<TabItem<K>>,
    active_key: Option<K>,       // the selected / focused tab
    h_scroll: u16,
    drag_state: Option<DragState<K>>,
    // render geometry (entries_start_x, scroll_viewport_width, max_scroll,
    // entry_geometry, left/right_indicator_rect, item_hits, rect) and auto-scroll
    // guards (last_auto_focus, last_auto_viewport, last_focused_logical_bounds)
}
```
- Bounds: `K: Copy + PartialEq + Eq + Hash + std::fmt::Debug` (stable identity across
  async closes/reorders — not fragile indices).
- **Implements the shared `Component<Msg>` trait** (same one as `ToggleListComponent`,
  `ListComponent`, etc.), parameterized by its own event type:
  ```rust
  impl<K: ...> Component<TabBarEvent<K>> for TabBarComponent<K> { ... }
  ```
  - `render(&mut self, backend, area: LayoutRect, ctx: &ComponentContext, registry)`:
    uses `ctx.config().theme` and the `area` the host hands it (the bar's slot);
    registers no hitboxes of its own (the embedding panel owns the whole-panel
    hitbox), so `registry` is ignored.
  - `handle_events(&mut self, event, ctx) -> EventResult<TabBarEvent<K>>`: self-routes
    the mouse — chevron press → `Consumed` (scroll), close-glyph press → `Action(Close(K))`,
    tab press → `Action(Select(K))`, drag → edge-pan + ghost state, release →
    `Action(Reorder{..})` or `Consumed`, wheel/`ScrollLeft/Right` → scroll → `Consumed`,
    empty press → `Ignored`. Internally dispatches to private
    `handle_press/handle_drag/handle_release/handle_scroll` helpers.
  - `hitbox_id()`/`query()` use the trait defaults (the panel owns routing).
- Public API: `new()`, `begin_frame()`, `clear_drag_state()`,
  `set_items(Vec<TabItem<K>>)`, `set_active(Option<K>)`, `active() -> Option<K>`,
  `items() -> &[TabItem<K>]`, and `hit_test(col,row) -> Option<K>` (the panel's
  `hit_test_window` delegates here).

### Close-glyph correctness (review amendments)
- `const CLOSE_BUTTON_WIDTH: u16 = 2;` (the `" ✕"` affordance). Phase 1 entry width uses
  **visual display columns** (`unicode_width::UnicodeWidthStr::width`, not byte/char
  length) so CJK/multi-byte labels project correctly:
  `entry_width = item.label.width() as u16 + ENTRY_PADDING + (if item.closable { CLOSE_BUTTON_WIDTH } else { 0 })`.
  (`truncate_with_ellipsis` and `slice_by_columns` are already width-aware.) Phase 2
  renders the close glyph at the right end of closable entries; the glyph's sub-rect
  is the rightmost `CLOSE_BUTTON_WIDTH` columns of the entry rect.
- `handle_press` order (never arm a drag from the close button): chevron first, then
  **close-glyph hit** (clear `drag_state`, return `Action(Close(K))`), then **tab body**
  (arm `drag_state` with `grab_col` from the tab rect, return `Action(Select(K))`),
  else `Ignored`.
- `set_active(&mut self, key: Option<K>)` — supports clearing active when no tabs /
  focus moved away.

Export from `crates/term-wm-ui-components/src/lib.rs`:
`pub mod tab_bar;` + `pub use tab_bar::{TabBarComponent, TabBarEvent, TabItem};`.

## Refactor the top panel: `crates/term-wm-sys-ui-components/src/wm_top_panel/`
`mod.rs`:
- Delete `mod window_strip;` and its `use`; delete `wm_top_panel/window_strip.rs`.
- Change `strip: WindowStrip` → `bar: TabBarComponent<WindowKey>`.
- `render_contents`: build `Vec<TabItem<WindowKey>>` from `display_order` +
  `window_labels`, setting `closable: wm.is_closable(key)` and `style_override: None`,
  then `bar.set_items(items); bar.set_active(focus);` (`focus` is already
  `Option<WindowKey>` — do NOT wrap it) and render via the trait:
  `bar.render(backend, bar_rect, &panel_ctx, &mut registry)`.
- `handle_events` routing (menu → bar → tiling): for the bar portion call the trait
  `bar.handle_events(event, ctx)` and a small `map_bar(res)` converts
  `EventResult<TabBarEvent<WindowKey>>` → `EventResult<TermWmAction>`:
  `Select(k) → FocusWindow(k)`, `Close(k) → CloseWindow(k)`, `Reorder{key,index} →
  ReorderWindow{key,index}`, `Consumed/Ignored` pass through.
- `hit_test_window` → `bar.hit_test(col,row)`.
- `begin_frame()` → `bar.begin_frame()`; inactive render → `bar.clear_drag_state()`.

## Tests
**Move all bar-behavior tests from `wm_top_panel/mod.rs` into `tab_bar.rs`**
(where `pub(crate)` internals are accessible), adapted to the generic API with
`K = usize` (or a small `#[derive(Debug,Clone,Copy,PartialEq,Eq,Hash)] TestKey(u32)`)
and exercised through the **`Component<TabBarEvent<K>>` trait** (`render` with a
`ComponentContext`, `handle_events` with `Event`s):
`hit_test`, `overflow_clamps_scroll_and_shows_indicators`,
`scroll_events_adjust_h_scroll`, `drag_ghost_then_release_reorders_to_front`,
`plain_click_does_not_emit_reorder`, `drag_off_right_edge_clamps_to_end`,
`drag_ghost_renders_at_cursor_and_not_duplicated`,
`pressed_entry_stays_visible_before_drag`, `chevrons_have_gap_from_entries`,
`chevrons_do_not_overlap_tiling_indicator` (bar half),
`reorder_moves_focused_off_screen_then_auto_scrolls_back`,
`manual_scroll_persists_until_focus_changes`, plus new `Select`/`Close`/close-glyph
tests (close press must NOT arm a drag; closable entries are wider by
`CLOSE_BUTTON_WIDTH`).

**Keep in `wm_top_panel/mod.rs`** the panel-level tests (menu, tiling, process_action,
layout, visibility, hit_test_area, render_*, capture contract, empty-press) plus a
couple of panel integration tests that route through `p.handle_events` and compute
press coordinates from known layout (menu width + gap + entry widths) WITHOUT poking
bar internals: press an entry → `FocusWindow`, drag+release → `ReorderWindow`.
Remove tests that poked the old `WindowStrip` internals (they now live in tab_bar.rs).

## Verification

```bash
cargo test -p term-wm-ui-components tab_bar
cargo test -p term-wm-sys-ui-components wm_top_panel
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test
```
Manual: `cargo run` → top panel behaves as before (scroll/chevrons/drag-reorder,
plus a per-tab ✕ that closes closable windows); a host app can embed
`TabBarComponent<ItsKey>` directly.
