# Fix: Connected user list only shows current workspace users on focus change

## Root Cause

When the command palette is open and a focus change occurs (e.g., clicking a different window), `focus_window_key()` in `focus.rs:76` rebuilds the menu items but passes an **empty** `all_users_by_ws` map:

```rust
let empty_users = std::collections::BTreeMap::new();
let items = self.wm_menu_items(
    &self.cached_workspaces,
    &self.current_workspace,
    &self.project_tasks,
    &empty_users,  // <-- BUG: empty map
);
```

The `wm_menu_items()` method in `command_palette.rs:271-280` uses this map to display users under each workspace. When empty, it falls back to `self.user_registry` only for the **current workspace**. Users in other workspaces disappear.

This explains the symptom: with two users in different workspaces, only one user (the current workspace's user via `user_registry` fallback) appears after any focus change while the palette is open.

## Fix

Mirror the existing pattern used for `cached_workspaces`, `current_workspace`, and `project_tasks` — cache `all_users_by_ws` on `WindowManager` so `focus.rs` can use it.

### Changes

**1. `crates/term-wm-core/src/window/window_manager/mod.rs`**

Add field after `project_tasks` (line 437):
```rust
pub all_users_by_ws: std::collections::BTreeMap<String, Vec<crate::user_registry::UserEntry>>,
```

Initialize in constructor (line 957, after `project_tasks: Vec::new()`):
```rust
all_users_by_ws: std::collections::BTreeMap::new(),
```

**2. `crates/term-wm-core/src/window/window_manager/focus.rs`**

Replace lines 76-82:
```rust
let empty_users = std::collections::BTreeMap::new();
let items = self.wm_menu_items(
    &self.cached_workspaces,
    &self.current_workspace,
    &self.project_tasks,
    &empty_users,
);
```
With:
```rust
let items = self.wm_menu_items(
    &self.cached_workspaces,
    &self.current_workspace,
    &self.project_tasks,
    &self.all_users_by_ws,
);
```

**3. `src/term_wm_app.rs`**

In `open_command_palette()`, add the sync inside the existing `#[cfg(feature = "session-persistence")]` block (line 870):
```rust
#[cfg(feature = "session-persistence")]
{
    self.wm.cached_workspaces = self.cached_workspaces.clone();
    self.wm.current_workspace = self.current_workspace.clone();
    self.wm.all_users_by_ws = self.all_users_by_ws.clone();
}
```

### Test Updates

- `mod.rs:6731`, `6809`, and other test sites that call `wm_menu_items` with `&std::collections::BTreeMap::new()` — no changes needed (they use local maps directly).
- Existing test `wm_menu_items_user_registry_fallback_nested` at line 900 validates the fallback behavior with an empty map, which remains correct.
