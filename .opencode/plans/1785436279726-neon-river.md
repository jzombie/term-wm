# Plan: Fix Outdated Documentation (README.md & help.md)

## Problem Summary

Both `README.md` and `crates/term-wm-sys-ui-components/assets/help.md` contain descriptions of features that do not match the actual codebase. These discrepancies confuse users and mislead contributors.

---

## Issues Identified

### Issue 1: README.md — `Esc` as Super Key (Lines 34–52)

**What it says:** The README extensively documents `Esc` as a context-aware modifier:
- Tap `Esc` once → enters "WM Mode" with overlay
- Double-tap `Esc` → routes single `Esc` to child window
- Direct mode inverts double-`Esc` behavior

**What the code actually does:**
- The default "super" key is `Ctrl+A` (bound to `TermWmAction::OpenCommandPalette`) — defined in `crates/term-wm-core/src/keybindings.rs:88`
- There is NO double-`Esc` logic in the runner or anywhere else
- `Esc` is only used as a hardcoded default for `CloseHelp` and `ConfirmCancel` actions
- The command palette is opened by matching `OpenCommandPalette` keybinding (`Ctrl+A`), not `Esc`
- `super_passthrough_window` duration exists in `WmConfig` but is not consumed by any runtime logic

**Fix:** Rewrite the "No-Conflict Philosophy" section to describe the actual `Ctrl+A`-based command palette system, not the non-existent `Esc`-based overlay mode.

### Issue 2: README.md & help.md — `[D]` Header Button for Direct Mode

**README line 40:** "Per-window **direct mode** (toggled via the `[D]` header button)"
**help.md lines 32–33:** "Per-window `direct mode` (toggled via the `[D]` header button)"

**What the code actually does:**
- There is NO `[D]` header button — `ChromeTarget::ToggleDirectModeButton` is commented out in `crates/term-wm-core/src/chrome/target.rs:19`
- Direct mode is entirely **automatic** — driven by `DirectInputTracker` in `crates/term-wm-pty-engine/src/pty_state_tracker.rs`
- It activates when a terminal app uses: alt screen, mouse tracking, or custom margins
- It is NOT user-toggleable via any UI button

**Fix:** Update both documents to describe the automatic direct mode behavior, remove references to the `[D]` button.

### Issue 3: README.md — `WmConfig::embedded()` (Lines 64–65)

**What it says:** "WmConfig::embedded() — Minimal mode: no floating window management features..."

**What the code actually does:**
- `WmConfig` has `standalone()` and `minimal()` constructors, NOT `embedded()`
- `minimal()` is defined in `crates/term-wm-core/src/wm_config.rs:146`
- `TermWmApp::embedded()` exists in `src/term_wm_app.rs:419` — it's on `TermWmApp`, not `WmConfig`

**Fix:** Change `WmConfig::embedded()` to `WmConfig::minimal()` and clarify which API level it belongs to.

### Issue 4: README.md — Direct Mode Behavior Description (Lines 44–51)

The table describing direct mode (`Esc` behavior, double-`Esc` inversion) is entirely fictional — no such logic exists in the codebase. The whole section needs to be replaced with an accurate description.

## Detailed Changes

### README.md

Replace lines 34–52 (the entire "No-Conflict Philosophy" section and keybinding table) with:

1. Default super key is `Ctrl+A` (configurable via `KeyBindings`)
2. Press `Ctrl+A` to open the Command Palette overlay
3. While palette is open: `Tab`/`Shift+Tab` cycles windows, `Enter` activates item, `Ctrl+A` sends the key to the focused window
4. Direct mode is **automatic** — enabled when terminal apps use alt screen / mouse tracking / custom margins
5. In direct mode, all keys pass through unfiltered; `Ctrl+A` still opens the palette

**Keep the general "Retro-Modern" philosophy intact** — the motivation is still valid, just the implementation details are wrong.

### help.md

Replace lines 30–33 about `[D]` header button and double-`Esc`:

1. Describe automatic direct mode (triggered by alt-screen, mouse tracking, custom margins)
2. Remove reference to `[D]` header button
3. Remove reference to inverted double-`Esc` behavior in direct mode

The rest of help.md already works correctly at runtime because `%SUPER%`, `%FOCUS_NEXT%`, `%FOCUS_PREV%` etc. are dynamically resolved from the actual keybindings.
