# Plan: Eliminate Allocation Hotspots in term-session-client and term-session-server

## Problem Summary

The ~8ms main loops in `term-session-client` and `term-session-server` contain
severe allocation hotspots that fire even on **idle** frames (no screen change,
no user input).  The two most impactful fixes gate all heap work behind a
dirty-bit check, and the third reuses a parser instead of re-allocating it.

---

## Fix 1 — `drain_pushes()` returns `bool` (P0)

**File:** `crates/term-session-client/src/remote_pane.rs:47–61`

Current signature: `pub fn drain_pushes(&mut self) { … }` (returns unit).

Change it to return `true` if at least one `Vec<u8>` chunk was received and
fed into the parser, `false` otherwise.  This is a 2-line change:

```rust

    let mut updated = false;
    loop { … }
    updated
}
```

## Fix 2 — Gate `contents_formatted()` on dirty bit (P0)

**File:** `crates/term-session-client/src/lib.rs:267–279`, `554–576`

Current behaviour: every 8 ms tick unconditionally calls
`parser.screen().contents_formatted()`, allocating a `Vec<u8>` that is
immediately thrown away when the screen is static.

Change the main-loop logic so that `drain_pushes()` **is** the `has_new_data`
check, and `contents_formatted()` is only called when data actually arrived:

```rust
// BEFORE
pane.drain_pushes();
let current_content = { parser.screen().contents_formatted() };
let has_new_data = prev_content.as_deref() != Some(&current_content);

// AFTER — gated on dirty bit
let has_new_data = pane.drain_pushes();
```

Then inside `if has_new_data || prev_content.is_none() { … }`:
- Lock the parser and call `contents_formatted()` once.
- Compute diff / store `prev_content` as before.
- The `if !has_new_data && !had_input { sleep }` pacing block still works
  because `has_new_data` is now the `bool` returned by `drain_pushes()`.

The initial-wait loop (lines 236–245) and the initial-render block (lines
256–263) are unchanged — they run once at startup.

## Fix 3 — Reuse `prev_parser` instead of allocating every diff (P0)

**File:** `crates/term-session-client/src/lib.rs:561–565`

Current: every frame that needs a diff allocates a fresh `vt100::Parser`:
```rust
let mut prev_parser = vt100::Parser::new(rows, cols, 0);
prev_parser.process(prev);
```

Fix: hoist a persistent `Option<vt100::Parser>` outside the loop, and reuse
it by sending the RIS escape sequence (`\x1bc`) which resets the parser
in-place, then process the previous formatted content into it.

**Critical:** After a terminal resize, `prev_parser` retains pre-resize
dimensions.  Feeding `(h, w)`-sized formatted content into a stale-dimension
parser would desync grid bounds, corrupting `contents_diff` output.  Call
`parser.screen_mut().set_size(rows, cols)` before RIS to synchronize:

```rust
// Outside loop:
let mut prev_parser: Option<vt100::Parser> = None;

// Inside diff block:
Some(prev) => {
    let parser = prev_parser.get_or_insert_with(|| {
        vt100::Parser::new(rows, cols, 0)
    });
    // Synchronise dimensions in case of terminal resize
    parser.screen_mut().set_size(rows, cols);
    parser.process(b"\x1bc");   // RIS: reset parser attributes and screen
    parser.process(prev);        // re-construct previous screen
    screen.contents_diff(parser.screen())
}
```

The RIS escape is a single byte that is O(rows × cols) cheaper than
allocating a new `Parser` (which internally allocates grid rows +
scrollback deque on the heap).

## Fix 5 — Server: Replace 8ms interval with `tokio::sync::Notify` (P0)

**File:** `crates/term-session-server/src/session_server.rs` and `crates/term-session-server/src/session.rs`

### Problem

The server spawns a tokio task that ticks every 8ms (`tokio::time::interval(8ms)`),
locks the shared state, and checks for PTY output — even when the terminal
has been completely idle for hours.  This is a 125 Hz unconditional wakeup.

### Root cause

No mechanism exists to **park** the polling task until the PTY actually produces
output.  The `Pty` background reader thread already sets an edge-triggered
`dirty: Arc<AtomicBool>` flag on new byte arrivals, and already fires a
`status_cb(PtyStatus::Wakeup)` callback on the false→true edge — but the
session server never registers a callback, so this signal is lost.

### Fix

1. **Attach a `tokio::sync::Notify` to the PTY's `status_cb`** so that the
   background reader thread can wake up the polling task when bytes arrive.
2. **Remove the 8ms interval.**  Replace with `notify.notified().await` which
   blocks the tokio task indefinitely until the reader actually produces output.
3. **Handle the no-subscriber case** by calling `session.sync_screen()` to
   clear the dirty flag (otherwise the reader thread parks on I/O burst budget).
4. **Add a `set_status_callback` passthrough to `Session`** so the server can
   register the notify without reaching into the `Pty` field.
5. **Store `notify` in `ServerState`** and provide `ServerState::set_session()`
   that always attaches the callback — this ensures re-spawned sessions via
   the `Spawn` RPC endpoint also get notified.

### Code changes

**`session.rs`** — add passthrough:
```rust
impl Session {
    // ... existing methods ...
    pub fn set_status_callback(&mut self, cb: Option<Box<dyn Fn(PtyStatus) + Send + Sync>>) {
        self.pty.set_status_callback(cb);
    }
}
```

**`session_server.rs`** — store `notify` in `ServerState` and encapsulate
session assignment to guarantee the callback is always attached:
```rust
use term_wm_pty_engine::PtyStatus;

struct ServerState {
    session: Option<Session>,
    clients: Vec<ClientEntry>,
    subscribers: Vec<SubscriberEntry>,
    notify: Arc<tokio::sync::Notify>,
}

impl ServerState {
    fn new(notify: Arc<tokio::sync::Notify>) -> Self {
        Self {
            session: None,
            clients: Vec::new(),
            subscribers: Vec::new(),
            notify,
        }
    }

    /// Replace the current session and attach the Notify callback
    /// so the background polling task is woken on PTY output.
    fn set_session(&mut self, mut session: Session) {
        let n = self.notify.clone();
        session.set_status_callback(Some(Box::new(move |status| {
            if matches!(status, PtyStatus::Wakeup | PtyStatus::Exited) {
                n.notify_one();
            }
        })));
        self.session = Some(session);
        // Prime notify to process initial startup output generated
        // before the callback was registered.
        self.notify.notify_one();
    }
}
```

Replace all direct `guard.session = Some(session)` assignments with
`guard.set_session(session)` — in `run_server` and the `Spawn` RPC handler.

Replace the interval polling loop with `notify.notified().await`:
```rust
// Before (old interval loop):
//   let mut interval = tokio::time::interval(Duration::from_millis(8));
//   loop {
//       interval.tick().await;
//       let mut guard = st.lock().await;
//       ...

// After (event-driven):
tokio::spawn(async move {
    loop {
        // Block until PTY produces output — 0 wakeups when idle
        notify.notified().await;

        let mut guard = st.lock().await;
        // ... rest of the loop is the same ...
        if guard.subscribers.is_empty() {
            if let Some(session) = guard.session.as_mut() {
                session.sync_screen();  // clears dirty, releases reader
            }
            continue;
        }
        let Some(session) = guard.session.as_mut() else { break; };
        let raw = session.read_output();
        let exited = session.check_exited();
        if !raw.is_empty() {
            for sub in &guard.subscribers {
                sub.respond.respond(raw.clone(), false);
            }
        }
        if exited { /* ... same as before ... */ }
    }
});
```

### Why this works (no race condition)

`tokio::sync::Notify` stores **one permit**.  If `notify_one()` is called while
nobody is waiting, the permit is remembered and the next `notified().await`
returns immediately.  So the sequence:

1. Reader sets dirty → `status_cb` → `notify_one()`
2. `notified().await` returns
3. `session.read_output()` → `pty.screen()` clears dirty
4. Reader writes more bytes → sets dirty → `notify_one()`
5. Between step 3 and `notified().await`: permit is stored
6. Next `notified().await` returns immediately

This is correct.  No edge-triggered wakeup loss.

## Fix 6 — Client: Replace 4ms poll with event-driven blocking (P0)

**Files:** `crates/term-session-client/src/lib.rs`, `crates/term-session-client/src/remote_pane.rs`

### Problem

The main loop in `run_session` calls `crossterm_event::poll(4ms)` on every
iteration.  Even when idle, this epoll/kqueue syscall fires 125 times/second.
Combined with the 8ms sleep, the thread is continually cycling between
4ms poll + 4ms sleep — never truly parked.

### Root cause

Two event sources (crossterm user input and muxio PTY output) have no shared
notification mechanism.  The loop polls each independently with short timers.

### Fix: unified crossbeam channel multiplex

Replace the two independent polling paths with a single `crossbeam_channel`
multiplex that blocks until **either** user input or PTY output arrives.

1. **Background crossterm input thread** — calls `crossterm::event::poll(50ms)`
   (not blocking `read()`) and checks `input_tx.is_disconnected()` on timeout
   so the thread can exit promptly when `run_session` terminates.  
   Thread is parked by the OS for up to 50ms when idle; on keypress it wakes
   immediately via epoll/kqueue.

2. **Convert `push_rx` to crossbeam** — the tokio background task that reads
   muxio IPC chunks sends PTY output bytes to a crossbeam channel instead of a
   tokio channel.  `RemotePane::push_rx` changes type accordingly.

3. **Main loop blocks on `crossbeam_channel::select!`** — zero CPU wakeups
   when both input and PTY output are idle.

4. **SIGINT** is handled via the existing atomic flag — checked after wakeup.

5. **Connection health** is checked after wakeup (no periodic check needed —
   the muxio layer will signal disconnection via channel closure).

### Code changes

**`remote_pane.rs`** — replace `push_rx` type and update `drain_pushes`:
```rust
// OLD:
//   push_rx: mpsc::UnboundedReceiver<Vec<u8>>,
//
// NEW:

// ...

pub fn drain_pushes(&mut self) -> bool {
    let mut updated = false;
    loop {
        match self.push_rx.try_recv() {
            Ok(data) => {
                let mut parser = self.parser.lock().unwrap();
                parser.process(&data);
                updated = true;
            }
            Err(TryRecvError::Disconnected) => {
                self.exited.set(true);
                break;
            }
            Err(TryRecvError::Empty) => break,
        }
    }
    updated
}
```

```rust
                    pixel_width: 0,
                    pixel_height: 0,
                };
                prev_content = None;
                let _ = pane.resize(size);
            }
            Event::Paste(text) => {
                let mut wrapped = Vec::with_capacity(text.len() + 12);
                wrapped.extend_from_slice(b"\x1b[200~");
                wrapped.extend_from_slice(text.as_bytes());
                wrapped.extend_from_slice(b"\x1b[201~");
                let _ = pane.write_bytes(&wrapped);
            }
            _ => {}
        }
    }

    // Connection health — check after wakeup
    if !client.is_connected() {
        return Err(io::Error::other("connection to session server lost"));
    }

    // Diff-based render (same as current code)
    if has_new_data || prev_content.is_none() {
        let parser = pane.shared_parser();
        let parser = parser.lock().unwrap();
        let screen = parser.screen();
        let (rows, cols) = screen.size();
        let diff = match &prev_content {
            Some(prev) => {
                let p = prev_parser.get_or_insert_with(|| {
                    vt100::Parser::new(rows, cols, 0)
                });
                p.screen_mut().set_size(rows, cols);
                p.process(b"\x1bc");
                p.process(prev);
                screen.contents_diff(p.screen())
            }
            None => screen.contents_formatted(),
        };
        if !diff.is_empty() {
            out.write_all(&diff)?;
            out.flush()?;
        }
        prev_content = Some(screen.contents_formatted());
    }

    // Exit check
    if pane.has_exited() {
        return Ok(());
    }
}
```

### Important detail: `select!` is fair

`crossbeam_channel::select!` fairly chooses between ready channels.  If both
input and PTY output arrive simultaneously, either may be picked first.
The `drain_pushes()` call after the select catches any additional PTY data.

### `crossbeam_channel` dependency

Add `crossbeam-channel = "0.5"` to `term-session-client/Cargo.toml`.
