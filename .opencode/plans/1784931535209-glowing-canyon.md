# Plan: Eliminate Allocation Hotspots in term-session-client and term-session-server

## Problem Summary

The ~8ms main loops in `term-session-client` and `term-session-server` contain
severe allocation hotspots that fire even on **idle** frames (no screen change,
no user input).  The two most impactful fixes gate all heap work behind a
dirty-bit check, and the third reuses a parser instead of re-allocating it.

---

## Fix 1 — `drain_pushes()` returns `bool` (P0)

**File:** `crates/term-session-client/src/remote_pane.rs:47–61`

Current signature: `pub fn drain_pushes(&mut self) { … }` (returns unit).

Change it to return `true` if at least one `Vec<u8>` chunk was received and
fed into the parser, `false` otherwise.  This is a 2-line change:

```rust
pub fn drain_pushes(&mut self) -> bool {
    let mut updated = false;
    loop { … }
    updated
}
```

## Fix 2 — Gate `contents_formatted()` on dirty bit (P0)

**File:** `crates/term-session-client/src/lib.rs:267–279`, `554–576`

Current behaviour: every 8 ms tick unconditionally calls
`parser.screen().contents_formatted()`, allocating a `Vec<u8>` that is
immediately thrown away when the screen is static.

Change the main-loop logic so that `drain_pushes()` **is** the `has_new_data`
check, and `contents_formatted()` is only called when data actually arrived:

```rust
// BEFORE
pane.drain_pushes();
let current_content = { parser.screen().contents_formatted() };
let has_new_data = prev_content.as_deref() != Some(&current_content);

// AFTER — gated on dirty bit
let has_new_data = pane.drain_pushes();
```

Then inside `if has_new_data || prev_content.is_none() { … }`:
- Lock the parser and call `contents_formatted()` once.
- Compute diff / store `prev_content` as before.
- The `if !has_new_data && !had_input { sleep }` pacing block still works
  because `has_new_data` is now the `bool` returned by `drain_pushes()`.

The initial-wait loop (lines 236–245) and the initial-render block (lines
256–263) are unchanged — they run once at startup.

## Fix 3 — Reuse `prev_parser` instead of allocating every diff (P0)

**File:** `crates/term-session-client/src/lib.rs:561–565`

Current: every frame that needs a diff allocates a fresh `vt100::Parser`:
```rust
let mut prev_parser = vt100::Parser::new(rows, cols, 0);
prev_parser.process(prev);
```

Fix: hoist a persistent `Option<vt100::Parser>` outside the loop, and reuse
it by sending the RIS escape sequence (`\x1bc`) which resets the parser
in-place, then process the previous formatted content into it:

```rust
// Outside loop:
let mut prev_parser: Option<vt100::Parser> = None;

// Inside diff block:
Some(prev) => {
    let parser = prev_parser.get_or_insert_with(|| {
        // rows/cols from the main parser's screen
        vt100::Parser::new(rows, cols, 0)
    });
    parser.process(b"\x1bc");   // RIS: reset to initial state
    parser.process(prev);        // re-construct previous screen
    screen.contents_diff(parser.screen())
}
```

The RIS escape is a single byte that is O(rows × cols) cheaper than
allocating a new `Parser` (which internally allocates grid rows +
scrollback deque on the heap).

## Fix 4 — Pre-allocate paste wrapper buffer (P2)

**File:** `crates/term-session-client/src/lib.rs:541–544`

```rust
// BEFORE
let mut wrapped = b"\x1b[200~".to_vec();
wrapped.extend_from_slice(text.as_bytes());
wrapped.extend_from_slice(b"\x1b[201~");

// AFTER
let mut wrapped = Vec::with_capacity(text.len() + 12);
wrapped.extend_from_slice(b"\x1b[200~");
wrapped.extend_from_slice(text.as_bytes());
wrapped.extend_from_slice(b"\x1b[201~");
```

## Changes NOT pursued

| Candidate | Reason skipped |
|-----------|----------------|
| Server `raw.clone()` per subscriber (session_server.rs:322) | `StreamResponder::respond()` takes `Vec<u8>` (from upstream `muxio`). Cannot share via `Arc<[u8]>` without changing the muxio crate. Out of scope. |
| `push_frame.rs` `String::from_utf8_lossy().into_owned()` | Title changes are infrequent (once per shell prompt). Negligible impact. |
| `input_writer` `data.to_vec()` per keystroke | Keystrokes are user-driven, not in the 8 ms hot loop. Frequencies are human-scale (~Hz). |

## Files Modified

1. `crates/term-session-client/src/remote_pane.rs` — Fix 1 (return bool)
2. `crates/term-session-client/src/lib.rs` — Fix 2, Fix 3, Fix 4

## Verification

```bash
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test
```

The changes are purely mechanical (return type change, loop restructure, hoist
+ RIS reuse).  No behavioural change is expected — the resulting bytes written
to stdout are identical for every valid sequence of events.
