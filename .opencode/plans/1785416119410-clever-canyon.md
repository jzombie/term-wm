# Remove "locked" functionality from term-resize-indicator

## Summary
The `term-resize-indicator` crate has a lock-to-size feature (`Mode::Locked` + `--size` CLI arg + `toggle_lock` on `l`/`L` key). Remove it entirely, leaving only the interactive resize overlay.

## Files to modify

### `crates/term-resize-indicator/src/lib.rs`
- Remove `Mode` enum entirely
- Simplify `App` to just `{ live_size: Size }`
- Remove `initial_lock: Option<Size>` parameter from `run()` — start always in interactive mode
- Remove `toggle_lock()` function
- Remove `l`/`L` key handling in `run_loop`
- Remove `locked` param from `draw_overlay()`, remove `[LOCKED]` label suffix
- Remove unused imports (`Modifier`? — check, it's still used for `BOLD`)

### `crates/term-resize-indicator/src/main.rs`
- Remove `--size` CLI arg
- Remove `parse_size()` and its tests
- Use `#[command(version, about)]` instead of the hardcoded `about = "..."` string — clap will read `version` and `description` from `Cargo.toml` automatically
- Since `Args` is now empty, replace `Args::parse()` with a simpler `Cli::parse()` or remove the `Args` struct entirely and use `clap::Command::new(...)` — either way, the version/about comes from the `Cargo.toml` `description` field
- Update `run()` call to not pass initial_lock

### `crates/term-resize-indicator/Cargo.toml`
- Update `description` to remove "with lock-to-size capability"

## Verification
- `cargo check -p term-resize-indicator` compiles cleanly
- `cargo test -p term-resize-indicator` passes
- `cargo clippy -p term-resize-indicator -- -D warnings` passes
- Manual: `cargo run -p term-resize-indicator` shows the overlay without lock features

## No downstream impact
Only the workspace `Cargo.toml` references this crate (no other crate depends on it).
