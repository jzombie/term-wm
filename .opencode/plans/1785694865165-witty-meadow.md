# Replace File-Backed Clipboard Temp Store with In-Memory Shared Store

## Goal
Remove the file-backed (temp-file) clipboard store from `term-wm` and replace it with a process-shared in-memory buffer as Tier‑1 fallback. Keep the proven 3‑tier pipeline: **shared RAM buffer → `arboard` → OSC 52** (OSC 52 last so the host terminal owns the system clipboard on X11). Eliminates all disk I/O, secret-leak surfaces, and file-permission/race logic.

## Confirmed Design Decisions (from user)
- **Tier‑1 store = process-global shared buffer** (`Arc<RwLock<Option<String>>>`) so copy in a PTY reader thread's handle is immediately readable by the WM's separate paste handle in headless/SSH mode (full round-trip parity with the old session-scoped `/tmp` file, zero disk).
- **`get()` persists** the in-memory value until the next `set()` (NOT consume-on-read).
- **Leaner `ClipboardConfig`**: only `osc52_limit` + `osc52_enabled`.

## Deviation from sketch (preserve proven behavior)
The user proposed a `#[derive(Clone)] Clipboard` with lazy per-call `arboard`. We instead **keep the long-lived `Option<arboard::Clipboard>` handle and `&mut self` methods**, because:
- The module explicitly documents that a long-lived arboard handle is required to avoid the macOS pasteboard teardown-before-flush bug (`clipboard.rs:154-156`).
- `arboard::Clipboard` is `!Clone`.
- Sharing across threads is achieved through the shared `Arc` buffer (all `Clipboard::new()` instances auto-share one global), not through cloning `Clipboard`. This preserves existing call sites (WM `clipboard_mut()`, `PasteClipboard` in `runner.rs:120`, PTY reader loop in `pty.rs:612`) unchanged.

## Files

### `crates/term-wm-pty-engine/src/clipboard.rs` (primary)
**Remove:**
- Fields `temp_store_enabled`, `temp_path`; config field `cache_path`.
- Constructors `with_temp_path`, `headless_with_temp_path`.
- Helpers `write_temp_store`, `read_temp_store`, `default_temp_path`, `ensure_clipboard_store_dir`, `write_clipboard_temp`, `read_clipboard_temp`.
- Consts `ENV_XDG_RUNTIME_DIR`, `CLIPBOARD_CACHE_FILENAME`, `APP_TEMP_DIR_PREFIX`.
- Import `use std::path::{Path, PathBuf};` (keep `std::io::Write`).
- All `#[cfg(unix)] libc` file-permission code and imports.
- Tests tied to the file store.

**Add:**
- Global default shared buffer:
  ```rust
  fn default_shared_buffer() -> Arc<RwLock<Option<String>>> {
      static BUF: std::sync::OnceLock<Arc<RwLock<Option<String>>>> = OnceLock::new();
      BUF.get_or_init(|| Arc::new(RwLock::new(None))).clone()
  }
  ```
- `use std::sync::{Arc, OnceLock, RwLock};`
- `ClipboardConfig { osc52_enabled: bool, osc52_limit: usize }` (`#[non_exhaustive]`), `Default` = `(true, DEFAULT_MAX_OSC52_BYTES)`.
- `Clipboard { arboard: Option<arboard::Clipboard>, shared: Arc<RwLock<Option<String>>>, osc52_enabled: bool, osc52_limit: usize, #[cfg(test)] pub osc52_output: Vec<u8> }`.
- Constructor `with_shared_buffer(Arc<RwLock<Option<String>>>)` (public — enables the shared-buffer test seam and cross-thread injection).
- `with_config`: starts arboard `ok()`, uses `config` flags, `shared: default_shared_buffer()`.

**Rewire methods:**
- `set(&mut self, text: &str)`:
  1. Tier 1 — write `Some(text)` into `*self.shared.write()`.
  2. Tier 2 — `write_system_clipboard(&mut self.arboard, text)` (unchanged).
  3. Tier 3 — emit OSC 52 **only if `self.osc52_enabled`** via `set_via_osc52_with_writer` (unchanged capture-on-test logic).
- `get(&mut self) -> Result<String, ClipboardError>`:
  1. Try `read_system_clipboard(&mut self.arboard)` → `Ok(Some)` returns.
  2. Fall back to in-memory: `self.shared.read().ok().and_then(|g| g.clone())`; `Some` returns, `None`/lock-error → `Err(NotAvailable)`.
- Keep `truncate_for_osc52`, OSC 52 extraction helpers, `format_osc52_bytes`, `set_via_osc52_with_writer`, `Osc52Extractor` unchanged.

**Update module doc header** (`//!` lines 1‑51) to describe the 3‑tier in-memory/arboard/OSC 2 pipeline and the shared-buffer rationale (per AGENTS.md comment-preservation rule: update, don't delete).
