# Plan: Update docs for session persistence, workspaces & new CLI flags

## Goal

Bring user-facing documentation in line with the latest changelog content. The
`[Unreleased]` section introduces: a self-contained `term-wm` binary that embeds a
background session daemon, a workspace abstraction (`<workspace>/main` channels,
`-w/--workspace`, "New Workspace" / "Switch to Workspace: <name>" / "Detach Viewer"
palette entries), new CLI flags (`--no-session-persistence`, `--no-wm`,
`--stop-daemon`, `--list-channels`, `-f/--force`), an environment-scoped gateway
(`term-wm/<env>/<user>/gateway`, `TERM_WM_ENV`), and a new `term-wm-config` crate.
The previous release (0.9.28-alpha) also added `--scrollback` (default 2000),
which is missing from the README.

User decisions: full scope (incl. COMPATIBILITY review + new term-wm-config README),
a dedicated README section, and include `--scrollback`.

## Files to change

### 1. `README.md` (repo root)

**a. Usage → "Options" list (lines ~46-50).** Add the missing flags to the existing
bullet list, keeping style. Proposed additions:

- `-w, --workspace <NAME>` — workspace to open (default `default`); each workspace is
  an independent window-manager session with its own daemon channel (`<workspace>/main`).
- `--scrollback <N>` — scrollback buffer size per terminal window (default 2000).
- `--no-session-persistence` — disable session-persistence behavior at runtime
  (workspaces, gateway, daemon modes); only effective when the `session-persistence`
  feature is compiled in (it is by default). Equivalent to `TERM_WM_NO_SESSION_PERSISTENCE=1`.
- `--no-wm` — run without the window manager (headless session client mode).
- `--stop-daemon` — stop the running background session daemon.
- `--list-channels` — list channels/sessions/clients and exit.
- `-f, --force` — force `--stop-daemon` even with live sessions.

Note near the options that `-n`, `-r`, `--scrollback`, `-w` only take effect on new
sessions (matches the CLI help text "Only takes effect on new sessions").

**b. Quick Start (lines ~36-52).** Add one sentence: on first launch `term-wm`
auto-spawns a detached background session daemon so workspaces and sessions persist
across disconnects; manage it with `--list-channels` / `--stop-daemon`, and pick a
workspace with `-w`.

**c. New section "Workspaces & Session Persistence".** Place after the "Features"
list (before "The No-Conflict Philosophy"), or link from the Features bullet. Content:

- `term-wm` is now a self-contained binary embedding both the window manager and a
  background session daemon (gateway). On first launch a detached daemon is spawned
  automatically; sessions survive terminal/SSH disconnects.
- Each named workspace maps to a daemon channel `<workspace>/main` with its own PTY
  session and window-manager instance. Select at launch with `-w/--workspace`
  (default `default`).
- Switching is seamless: the Command Palette offers **New Workspace**, **Switch to
  Workspace: <name>**, and **Detach Viewer** — switching rebinds the viewer to the
  target workspace's channel without restarting the process; **Detach Viewer**
  disconnects the current viewer's IPC connection without terminating its processes.
- The gateway is scoped by environment: socket `term-wm/<env>/<user>/gateway`, where
  `<env>` defaults to `dev` in debug builds and `prod` in release. `TERM_WM_ENV=dev|prod|test`
  overrides it, so a development build can never attach to a production daemon's
  sessions; `TERM_WM_GATEWAY` overrides the socket wholesale. Both `term-wm --help`
  and `term-session --help` print the resolved `Persistence gateway:` as a footer.
- Terminate or inspect: `--stop-daemon` / `--list-channels` / `-f`.

**d. Features bullet "Detachable Sessions (via term-session)" (lines ~141).** Rewrite
to reflect built-in persistence: "**Session persistence & workspaces (built in):**
`term-wm` now embeds a background session daemon and auto-spawns it on first launch,
so workspaces and their sessions persist across disconnects. The companion
[`term-session`](https://crates.io/crates/term-session) daemon remains available for
standalone, layout-agnostic multiplexing." Reference the new section.

**e. Architecture crate table (lines ~102-111).** Add a row:

session protocol (Muxio), workspaces, sizing, benchmarks".

**f. New "Environment variables" subsection** (compact table, near Options or the new
workspaces section):

| Variable | Purpose | Default |
|---|---|---|
| `TERM_WM_ENV` | Gateway environment scope (`dev`/`prod`/`test`) | `dev` (debug) / `prod` (release) |
| `TERM_WM_GATEWAY` | Full gateway socket override | `term-wm/<env>/<user>/gateway` |
| `TERM_WM_CHANNEL` | Session channel override (for `term-session`) | `default/main` |
| `TERM_WM_NO_SESSION_PERSISTENCE` | Disable persistence behavior at runtime | unset (enabled) |
| `TERM_WM_TRACE_ESC` | File path to dump raw PTY→emulator bytes (debug) | off |
