# Plan: Integrate modular workflow for `copy git diff` (#312)

## Goal

Automate copying git diffs to the clipboard via Command Palette tasks, extensibly:

1. Expose the wm executable as a tasks.json string replacement: `{wm.exe}`
2. Add `--util <UTIL>` to the term-wm binary, routed to an internal `copy` utility that mirrors `term-copy` exactly (shared implementation)
3. Add project-local `.term-wm/tasks.json` entries piping `git diff` into it (platform-gated); they surface in the Command Palette automatically (no palette code changes needed)

**User decisions (binding):** `--util <UTIL>` clap ValueEnum (extensible); copy mechanics shared with `term-copy` via one library function; placeholder named `{wm.exe}`; both Unix `sh -c` and Windows PowerShell platform-gated task entries.

## Step 1: Extract shared copy core into `term-clipboard`

**File: `crates/term-clipboard/src/copy.rs` (new)**, re-exported from `src/lib.rs` (`pub mod copy;` + re-export, matching how `clipboard.rs` is exposed).

Move the ingestion logic out of `crates/term-clipboard/src/bin/term-copy.rs` (lines 41-66) into a library function parameterized by program label so both binaries share byte-identical mechanics. **Return type is `i32`** (not `std::process::ExitCode`, which cannot convert back to an integer) so `src/util.rs` can feed `std::process::exit(i32)` directly:

```rust
pub const COPY_NO_INPUT_MSG: &str = "error: no input; pass a FILE argument or pipe stdin";
pub const COPY_EXIT_SUCCESS: i32 = 0;
pub const COPY_EXIT_FAILURE: i32 = 1;

/// Shared core: FILE argument or piped stdin -> Clipboard (all backends).
/// Prints "<label>: {e}" on failure; returns process exit code.
pub fn run_copy_util(file: Option<PathBuf>, label: &str) -> i32
```

Behavior preserved exactly: TTY-stdin guard fails fast with the no-input message; `Some(path)` -> `Clipboard::set_from_path`; else `Clipboard::set_from_reader(stdin)`; errors print `"{label}: {e}"` to stderr and return `COPY_EXIT_FAILURE`. `term-copy` bin becomes `fn main() { std::process::exit(term_clipboard::run_copy_util(Cli::parse().file, "term-copy")) }`; `term-wm --util copy` calls it with label `"term-wm"`.

Add unit tests in `copy.rs`: reader-based copy asserts content landed in the in-memory shared backend (`default_shared_buffer()`, clipboard.rs:161); file branch via `tempfile` (already a dev-dep); no-input error variant. **Add `serial_test` as a dev-dependency of `term-clipboard`** and annotate every test that touches `default_shared_buffer()` with `#[serial]`: the shared buffer is process-global, and `cargo test` runs tests concurrently, so unsynchronized write/assert pairs would flake (the lock makes access memory-safe but not assertion-atomic across tests). This matches the existing `#[serial]` convention used elsewhere in the workspace.

## Step 2: Add `--util` flag and dispatch (root crate)

**File: `Cargo.toml`**: promote `term-clipboard` from `[dev-dependencies]` (line 202) to `[dependencies]` (workspace dep already defined at line 104). Not optional, so `--util` works in all feature combinations.

**File: `src/cli.rs`**:

```rust
/// Built-in utility commands runnable via `--util`.
#[derive(clap::ValueEnum, Clone, Debug)]
pub enum UtilAction { Copy }

// In struct Cli:
/// Run a built-in utility, then exit. Positional args after `--` forward to
/// the utility (e.g. optional FILE for `copy`).
#[arg(long = "util", value_name = "UTIL")]
pub util: Option<UtilAction>,
```

Utility arguments ride the **existing** `cmds` trailing-var-arg positional (cli.rs:39-40): in util mode, `cmds` IS the utility argv (`[]` = stdin mode, `[path]` = file mode, `>1` = usage error). This avoids adding a second positional that would clash with `trailing_var_arg`. Safe because util dispatch early-exits before `build_commands`/`total_windows` are ever called.

**File: `src/util.rs` (new)**: `pub fn run_util(action: UtilAction, args: &[String]) -> i32` (exit-code return, following the `run_cli_tasks` / `spawn_resolved_task` pattern in cli.rs:249-281). Routes `UtilAction::Copy` to `term_clipboard::run_copy_util(...)` and returns its `i32` unchanged. Arg-count validation: 0 -> stdin, 1 -> file, otherwise stderr usage line + return 1. Register module in `src/lib.rs`.

**File: `src/main.rs`**: insert into the "0a" local-operations block (around line 78, next to `list_tasks`/`tasks`), before any daemon/session code:

```rust
if let Some(util) = cli.util {
    std::process::exit(util::run_util(util, &cli.cmds));
}
```

Works regardless of `session-persistence` feature (unconditional dep).

## Step 4: Project-local tasks.json entries

**File: `.term-wm/tasks.json`**: append two entries after the existing cargo tasks (same `"dev: "` label style, `environments: ["dev"]`). The exe path is passed via the task's `env` block and referenced as an environment variable inside the shell script, so the substituted path NEVER appears inside quoted shell text:

```jsonc
{
    "label": "dev: Copy Git Diff",
    "command": "sh",
    "args": ["-c", "git diff | \"$TERM_WM_EXE\" --util copy"],
    "env": { "TERM_WM_EXE": "{wm.exe}" },
    "platforms": ["linux", "macos"]
},
{
    "label": "dev: Copy Git Diff",
    "command": "powershell",
    "args": ["-NoProfile", "-Command", "git diff | & $env:TERM_WM_EXE --util copy"],
    "env": { "TERM_WM_EXE": "{wm.exe}" },
    "platforms": ["windows"]
}
```

Why this shape:
- Tasks run as direct argv children with no shell wrapping (docs/tasks.md:196-200), so piping requires `sh -c` / PowerShell.
- Env-var indirection sidesteps all quoting hazards: `resolve_task` substitutes `{wm.exe}` in `env` values (project_tasks.rs:254-258), and the shell expands the variable at runtime. Paths containing apostrophes, spaces, or other metacharacters work unmodified. Inline substitution inside single-quoted script text (`'{wm.exe}'`) would break for paths containing `'` and is deliberately NOT used; escaping inside `substitute_vars` is the wrong layer because it also feeds `cwd` and non-shell `env` values where POSIX/PowerShell escape syntax cannot be correct simultaneously.
- Each `args` element is substituted but NOT re-tokenized, so even direct use keeps space-containing paths intact.
- `visible_on_platform` accepts these strings (case-insensitive match against `std::env::consts::OS`, `darwin` alias for `macos`). Identical labels are safe because the platform gates are disjoint.
- **Verify the UI spawner applies per-task env**: read `command_builder_for_task` (src/term_wm_app.rs:876-891) fully and confirm `ResolvedTask.env` lands on the `CommandBuilder`; the CLI path already applies it (`spawn_resolved_task`, cli.rs:249-256). If the UI path drops env, fix it as part of this step (both entry points must behave identically).

No palette changes: `wm_menu_items` renders every discovered task verbatim; `refresh_project_tasks` reloads tasks.json on every palette open.
