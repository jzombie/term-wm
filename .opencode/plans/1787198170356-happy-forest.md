# Plan: Show All Connected Users Grouped by Workspace in Command Palette (Corrected)

## Context
Palette currently shows only flat `Connected Users (N)` for `current_workspace` via `UserRegistry` (`crates/term-wm-core/src/user_registry.rs:20`) and `refresh_user_cache()` (`src/term_wm_app.rs:337`) which queries `ListUsers(session/{current})`. User wants all workspaces with workspace annotation.

- `ListChannels` (`methods.rs:336`, `server.rs:1280`) already returns all `ChannelInfo{ name, clients: Vec<ClientInfo> }` where `ClientInfo` superset of `UserInfo`; workspace = `ChannelName::parse_workspace(&ch.name)`.
- `wm_menu_items(workspaces: &[String], ...)` (`command_palette.rs:106`) builds `MenuDisplayItem::Item(MenuItem{label: Cow<'static,str>, icon: Option<&'static str>, action: TermWmAction, disabled: bool})`. Palette filtered in `TermWmApp::open_command_palette` (`term_wm_app.rs:802`) against `supported_menu_actions` — informational rows must use `action: CloseMenu` with `disabled:true`.
- Current wrapper `App::open_command_palette` (`src/main.rs:679`) does two sync refreshes; adding a second `list_channels()` would double blocking IPC (OS thread + Tokio runtime) on UI thread.

## Decision
Single IPC pass: unify workspace + global user collection in one `list_channels()` call, direct-assign to `WindowManager`, no duplicate `TermWmApp` map/clone.

### 2. `src/term_wm_app.rs` — unify `refresh_workspace_cache()`
Delete `refresh_all_users_cache()`. Replace body of `refresh_workspace_cache()` with single-pass extraction:
```rust
#[cfg(feature = "session-persistence")]
pub fn refresh_workspace_cache(&mut self) {
    if !term_wm_config::runtime::session_persistence_enabled() { return; }
    match term_session::list_channels() {
        Ok(resp) => {
            let mut workspaces = std::collections::HashSet::new();
            let mut users_by_ws: std::collections::BTreeMap<String, Vec<term_wm_core::user_registry::UserEntry>> = std::collections::BTreeMap::new();
            for ch in resp.channels {
                let ws = term_session::ChannelName::parse_workspace(&ch.name).to_string();
                workspaces.insert(ws.clone());
                for c in ch.clients {
                    users_by_ws.entry(ws.clone()).or_default().push(term_wm_core::user_registry::UserEntry {
                        conn_id: c.conn_id, user: c.user, hostname: c.hostname, ssh_ip: c.ssh_ip,
                    });
                }
            }
            for v in users_by_ws.values_mut() { v.sort_by(|a,b| a.user.cmp(&b.user).then_with(|| a.hostname.cmp(&b.hostname))); }
            self.cached_workspaces = workspaces.into_iter().collect();
            self.cached_workspaces.sort();
            self.wm.all_workspaces_users = users_by_ws;
        }
        Err(e) => tracing::debug!("Failed to refresh workspace/user cache: {e}"),
    }
}
```
No `all_users_by_workspace` field on `TermWmApp`; no clone. Direct assign to `wm`.

Keep `refresh_user_cache()` for fallback if needed but palette no longer requires it.

## Follow-up: Should Palette Be Event-Based? (User Q: Avoid Sphaghettification)

**Short answer:** Yes for live presence toasts, **no need for palette global list** — build-on-open is the right trade-off. The current “global `all_workspaces_users` in `WindowManager`” *is* sphaghettification (acknowledged by `wm_menu_items` TODO at `command_palette.rs:105` and `AGENTS.md` view! guidance). The fix is to keep core dumb and app-owned.

**How events already work:**
- Server `OnUserConnected/OnUserDisconnected` (`session_server.rs:700`) → client `main.rs:341` `register_prebuffered` → `pty_wakeup_tx` → `UnifiedEvent::UserConnected` (`unified_event_source.rs:44`) → `drain_pending()` → `EventSource::take_user_connected()` (`event_source.rs:96`) → `runner.rs:449` unconditional per-frame `wm.user_registry.upsert/remove + push_notification` + tick. This is event-based and correct for ephemeral toasts — no polling.
- Global workspace/user list is **also** available via same channel if you added `UserCacheInvalidated` broadcast on every `Spawn`/`evict_conn`, but palette is only visible ~2s and not hot. Polling at open via single `list_channels()` (blocking IPC, ~1-2ms) is cheaper than holding a subscribed mirror and wiring dirty-flag invalidation through `WindowManager`.

**Current sphaghettification (explore #3) and why build-on-open still leaks:**
- `WindowManager` (`mod.rs:407,410,432`) holds `user_registry`, `all_workspaces_users`, `cached_workspaces`, `current_workspace`, `project_tasks` — all `#[cfg(session-persistence)]` with empty defaults, cloned from `TermWmApp` (`term_wm_app.rs:136,299,333`) just so `wm_menu_items` can render without borrowing `App`. Duplicate source of truth, clone on every palette open.
- `AGENTS.md:137-168` and `view!` macro are explicit: `view!` is dumb, ephemeral per-frame, stateful components are `app-owned and injected by reference ({ &mut self.x })`. Core must recompute from `ctx.screen_area()` each frame, not cache app session state.

**Recommended lean fix (no philosophy change, just move ownership):**

1. **Keep build-on-open, but make state app-owned + pass-by-args (no WM field).**  
   - Keep authoritative `BTreeMap<String, Vec<UserEntry>>` only in `TermWmApp` (not in `WindowManager`).  
   - Change `wm_menu_items(&self, workspaces: &[String], current_workspace: &str, project_tasks: &[ProjectTaskConfig], all_users_by_ws: &BTreeMap<String,Vec<UserEntry>>)` — add 4th arg.  
   - `refresh_workspace_cache()` (`term_wm_app.rs:303`) populates `self.all_users_by_ws` (new field on `TermWmApp`) from single `list_channels()` pass; `open_command_palette()` passes `&self.all_users_by_ws` straight to `wm_menu_items`. `WindowManager` stores *nothing* except transient `user_registry` for toasts (which itself could later be app-owned). Removes `#[cfg] pub all_workspaces_users` field entirely.

2. **If you later want live palette while open (event-based):** don’t poll — extend the existing fan-in:
   - Server: already broadcasts per-workspace `OnUserConnected` to that workspace’s `internal_wm_caller`; to get global view you’d need either (a) broadcast to all `internal_wm_caller`s, or (b) client subscribes to `ListChannels` changes via a new `OnChannelListChanged` event.
   - Client: `UnifiedEvent::AllUsersChanged(BTreeMap<...>)` → `runner.rs` unconditional drain → `app.all_users_by_ws = map` → `if wm.command_palette_visible() { wm.refresh_palette_items(&app.all_users_by_ws) }` via `WindowManager::repaint_palette` (call `wm_menu_items` again and `overlay.set_menu_items`). This mirrors existing `focus.rs:76` live rebuild on focus change and keeps `WindowManager` stateless.
   - Cost: extra RPC/notify traffic for a UI that’s rarely open. Only worth it if you need palette to reflect joins/leaves *without closing/reopening*.

**Recommendation for this PR:** Ship **Option 1** (app-owned pass-by-args, single IPC, `WindowManager` field removed). It satisfies “show all users grouped by workspace” with one blocking call, zero new state in core, and zero new events. Document the event-based upgrade as a follow-up TODO if live-while-open ever matters.

# Bugfix: Workspace Notification N+2 Storm — Revert Wire, Single Subscribe Trigger (Plan Corrected per Review)

## Symptom
- 2 users on `ws-old`, user initiates `SwitchWorkspace` to `ws-new` → `Workspace ws-new` toast appears **3×** (N+2). User also sees own `user@host connected` though they just moved. After recent `RebindScope` change, switching broke entirely (no `OnWorkspaceRebind` delivered).

## Root Cause (confirmed)
- `push_workspace_entered` was called in **3** handlers: `RebindWorkspace` (1 per Rebind RPC), `Attach` (N per viewer Attach), `SubscribeInternalInput` (1 for cold-start). → N+2 storm. Previous fix added `RebindScope` + fallback decode and filtered `Rebind` by `ctx.conn_id` (transient `with_gateway` client, never `Attached(source)`) → 0 targets → switching broken. Wire mutation added schema drift and bitcode fallback complexity.

## Decision — **Revert wire, single source, no backward compat**
Per review: keep `RebindWorkspaceRequest` **strict 2-field** (`source_channel`, `target`), delete `RebindScope` and legacy decode, restore channel-wide `Rebind` broadcast (intended for multi-viewer sessions on same channel), and make `SubscribeInternalInput` the **single canonical** `OnWorkspaceEntered` trigger. Suppress self-echo for `UserConnected` in runner.

## Changes

### 1. `crates/term-session-muxio-service-definitions/src/methods.rs` — revert
- Delete `RebindScope` enum and `scope`/`initiator_conn_id` fields. Restore:
  ```rust
  #[derive(Debug, Clone, Encode, Decode)]
  pub struct RebindWorkspaceRequest { pub source_channel: String, pub target: String, }
  ```
- Restore `impl RpcMethodPrebuffered for RebindWorkspace` to strict:
  ```rust
  fn decode_request(bytes: &[u8]) -> Result<Self::Input,io::Error> {
    bitcode::decode::<RebindWorkspaceRequest>(bytes).map_err(|e| io::Error::new(InvalidData,e))
  }
  ```
  Delete `Legacy` struct and `if let Ok(r) ... else` fallback. No `Default` impl needed.

### 2. `crates/term-session-muxio-service-definitions/src/lib.rs`

### 3. `crates/term-session-server/src/session_server.rs`
- **Rebind handler:** restore original broadcast (no `ctx.conn_id` filtering):
  ```rust
  .register_prebuffered(RebindWorkspace::METHOD_ID, move |payload, _ctx| {
    let req = RebindWorkspace::decode_request(&payload)?;
    let source = ChannelName::parse(&req.source_channel)?;

    for entry in conns.values() if let ConnState::Attached(n)=&entry.state && n==&source {
      tokio::spawn(OnWorkspaceRebind::call(&entry.handle, OnWorkspaceRebindRequest{target:req.target.clone()}));

  ```
  **Delete** the `push_workspace_entered` call added in `RebindWorkspace` (warm push) — not needed.
- **Attach handler:** **delete** the `push_workspace_entered` block added at `859-875` (prevents N per-viewer pushes). Cold-start still covered by `Subscribe`.
- **SubscribeInternalInput handler:** **keep as single source** — `if !guard.clients.is_empty() { push_workspace_entered(state, caller, ws) }` with dedup `last_workspace_push` 500 ms window already added (retain). This gives exactly **1** toast per workspace entry for both warm (Attach raced ahead → Subscribe sees !empty) and cold (same).
- **Remove** `RebindScope` import. Keep `last_workspace_push` dedup map if desired, or keep simple (Subscribe-only gives 1 anyway, dedup harmless).
- **Tests:** update `tests/integration_session.rs` `RebindWorkspaceRequest{ source_channel, target }` back to 2 fields (remove `scope`).
