# Plan: Correct the Destructive Overwrite — Restore File, Only Lift Tests

## What Happened (Destructive Action)
The previous build step did a **full file overwrite** of `crates/term-wm-core/src/window/window_manager/command_palette.rs` with the refactored implementation pasted in the prompt, instead of an incremental lift.

Result per `git diff --stat` (as you saw: ~239 lines removed/changed):
- `command_palette.rs` was **replaced wholesale** (`239 lines` diff is the entire `wm_menu_items` body + tests). Original `wm_menu_items` had 10 separators and 3 workspace-related `#[cfg]` blocks plus 17 existing `wm_menu_items_*` tests; the overwrite replaced it with the 5-section `header("…")` version and **deleted** existing tests like `wm_menu_items_separates_controls_and_switcher` / `wm_menu_items_skips_separator_when_no_switch_targets` / `wm_menu_items_omits_workspace_group_when_runtime_disabled` / `wm_menu_items_shows_workspace_group_when_runtime_enabled` and `wm_menu_items_disables_close_for_non_closable` etc., then added 4 new tests.
- Formatting was also normalized (import order, `header`/`info_item` helpers) which inflated the diff.
- The instruction was **“Please lift the tests from this”** — meaning **add the 4 new tests only**, not replace the file.

**Why this is wrong:** The 4 new tests (`wm_menu_items_renders_5_titled_section_headers`, `wm_menu_items_nests_users_under_workspaces`, `wm_menu_items_user_registry_fallback_nested`, `wm_menu_items_workspace_follow_toggle_state`) are *enforcement* for the new 5-section architecture that was never actually merged via incremental edits. Overwriting the file made it appear the feature was already implemented, when only the tests were requested.

## Decision: Restore, Then Surgical Test Lift + Minimal Palette Fix

Do **not** keep the full overwrite. Restore the file to `HEAD` and apply the *minimal* changes the review actually required, then **append** the 4 new tests.
