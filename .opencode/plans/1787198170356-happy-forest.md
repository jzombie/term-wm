# Plan: Feature-Gate Project Tasks as Default Feature (Corrected)

## Context
Project Tasks is always compiled, pulling `shell-words` + `serde_json`. Need `project-tasks` feature gated but default-on, without breaking `--no-default-features` or mutating public API.

Current wiring: `project_tasks.rs` uses `shell_words::split` + `serde_json::from_str` + `term_wm_config::env`; `Cargo.toml` has `shell-words`/`serde_json` non-optional; `lib.rs: pub mod project_tasks` unconditional; `WindowManager::project_tasks` field and `wm_menu_items(project_tasks: &[ProjectTaskConfig])` are unconditional; `TermWmApp` fields/methods in `src/term_wm_app.rs` use `ProjectTaskConfig`.

Reference pattern: `session-persistence` forwards `term-wm-config/session-persistence` and is `default`.

## Decision
Keep `project_tasks` module and `ProjectTaskConfig` type and `WindowManager::project_tasks` field and `wm_menu_items` signature **unconditional** (additive features only). Gate **only** the heavy dependency usage inside `project_tasks.rs` (`shell-words`, `serde_json`) with `#[cfg(feature = "project-tasks")]` / `#[cfg(not)]` stubs, and gate **only** the menu loop that creates `RunProjectTask` items in `command_palette.rs`. Make `project-tasks` a default feature in both crates.

```rust
impl ProjectTaskConfig {
    pub fn argv(&self) -> Option<Vec<String>> {
        #[cfg(feature = "project-tasks")]
        {
            // shell_words::split + args handling
            let command = self.command.as_deref().filter(|s| !s.trim().is_empty());
            let mut argv = Vec::new();
            if let Some(cmd) = command {
                match shell_words::split(cmd) { Ok(t) if !t.is_empty() => argv = t, _ => return None }
            }
            if let Some(args) = &self.args { argv.extend(args.iter().cloned()); }
            if argv.is_empty() { None } else { Some(argv) }
        }
        #[cfg(not(feature = "project-tasks"))]
        { None }
    }
}

#[cfg(feature = "project-tasks")]
```

## Amendments per Review (SEV-2 — must be applied)

### 1. Silence unused `project_tasks` param in `command_palette.rs`
When `project-tasks` is disabled, the `project_tasks` slice is unused (loop gated out). Add fallback to silence `unused_variables`:
```rust
#[cfg(feature = "project-tasks")]
{
    let mut any_tasks_added = false;
    for task in project_tasks.iter().filter(|t| t.argv().is_some()) { ... }
    if any_tasks_added { items.push(Separator); }
}
#[cfg(not(feature = "project-tasks"))]
{
    let _ = project_tasks;
}
```

### 2. Gate unit tests in `project_tasks.rs`
Tests exercise `argv()`/`load_tasks_for_cwd` which return `None` when feature disabled. Gate the test module:
```rust
#[cfg(all(test, feature = "project-tasks"))]
mod tests { ... }
```

### 3. Inline or gate imports in `project_tasks.rs`
Top-level `use shell_words;` / `use serde_json;` would fail to resolve when `optional` deps are disabled. Gate the `use` or use fully-qualified paths inside the `#[cfg(feature = "project-tasks")]` blocks:
```rust
#[cfg(feature = "project-tasks")]
use shell_words::split;
// or inside method: shell_words::split(...)
```
