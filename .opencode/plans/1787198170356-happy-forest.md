# Plan: Guaranteed Workspace Notifications with Client-Side Time-Window Deduplication

## Architectural Diagnosis

The previous failure occurred because attempts were made to deduplicate workspace notifications at the server protocol layer by removing `push_workspace_entered` calls.

* **Why Warm Switches Failed:** When switching to an already running ("warm") workspace, the inner Window Manager is already running and **never re-subscribes** (`SubscribeInternalInput` does not fire). Removing notification pushes from `Attach` / `RebindWorkspace` meant warm workspace switches received zero workspace notifications.
* **The Disconnect Toast:** When detaching from the previous workspace socket during a switch, the server correctly informs remaining participants on that old channel that a user disconnected. Without the workspace notification firing on the new channel, the disconnect event was the only notification left visible.

### The Solution: UI-Layer Time-Window Deduplication

Instead of trying to suppress notifications on the server across complex asynchronous IPC paths, **guarantee that the server always emits notification events on all entry paths**, and handle deduplication **inside the client UI (`NotificationBus` / `WindowManager`) using a time-window filter**.

---

## Technical Implementation Plan

### 1. Server Layer: Restore Guaranteed Delivery (`crates/term-session-server/src/session_server.rs`)

Ensure `push_workspace_entered` is called whenever a client attaches or arrives at a workspace channel, guaranteeing 100% notification delivery for both cold starts and warm switches:

* **In `Attach`:** Call `push_workspace_entered` when a viewer attaches to a workspace channel that has an active `internal_wm_caller` (warm switch).
* **In `SubscribeInternalInput`:** Call `push_workspace_entered` when an internal WM subscribes to a channel with attached clients (cold start).
* **In `RebindWorkspace`:** Send `OnWorkspaceRebind` to all attached client handles on the source channel.

### 2. Client UI Layer: Time-Window Toast Deduplication (`crates/term-wm-core/src/notification.rs`)

Implement dedup directly in `NotificationBus::push` with `created_at` tracking (2000 ms window). No `WindowManager` wrapper needed. Server remains unconditional; client collapses bursts.

```rust
#[derive(Debug, Clone)]
pub struct Toast {
    pub id: u64,
    pub message: std::sync::Arc<str>,
    pub expires_at: std::time::Instant,
    pub created_at: std::time::Instant,
}

impl NotificationBus {
    pub fn push(&mut self, message: impl Into<String>, ttl: std::time::Duration) -> u64 {
        let msg_str: String = message.into();
        let now = std::time::Instant::now();
        let window = std::time::Duration::from_millis(2000);
        if let Some(existing) = self.toasts.iter().find(|t| {
            t.message.as_ref() == msg_str && now.saturating_duration_since(t.created_at) < window
        }) {
            return existing.id;
        }
        let id = self.next_id;
        self.next_id = self.next_id.saturating_add(1);
        let msg: std::sync::Arc<str> = msg_str.into();
        let expires_at = now + ttl;
        if self.toasts.len() >= self.max_capacity {
            self.toasts.pop_front();
        }
        self.toasts.push_back(Toast { id, message: msg, expires_at, created_at: now });
        id
    }
}
```

**Server stays unconditional** – `Attach` and `SubscribeInternalInput` both call `push_workspace_entered` when conditions met (`internal_wm_caller.is_some()` / `!clients.is_empty()`), no `pending` flags or ACK state machine. Rapid concurrent pushes (e.g., 2× `Attach` racing `Subscribe` at cold start) are collapsed by the 2 s window.

**Palette stays synchronous** – `open_command_palette` does single `list_channels()` inside `refresh_workspace_cache()` synchronously before `wm_menu_items`; `user_registry` is populated via background `OnUserConnected` events, not via an un-awaited async `list_users` spawned inside the menu build.

#### Why This Works Perfectly:

* **Guaranteed Notification:** Whether a workspace is opened fresh or switched to, `Workspace <name>` is **always** sent to the client.
* **Guaranteed 1x Rendering:** If 2 or 3 identical `Workspace <name>` events arrive at the client within 1–2 seconds, the client UI collapses them into **exactly 1 visible toast**.
* **Zero Server Protocol Fragility:** Eliminates complex server-side timing rules, tracking states, or protocol schema changes.

---

### 3. Event Loop Processing (`crates/term-wm-core/src/runner.rs`)

Keep event processing straightforward in the runner loop:

* When `driver.take_workspace_entered()` drains workspace events, pass them directly to `app.wm().push_notification(...)`.
* `push_notification` handles the deduplication automatically, presenting a single clean `"Workspace <name>"` notification to the user every time.

# Follow-up: Global Link/Unlink for Workspace Switching (Auto-Follow Toggle)

## Context (user clarified 2026-08-20)
- **Link semantics:** Auto-follow — linked users move together when someone switches.
- **Granularity:** Global toggle, not per-user/per-workspace. All viewers either move together or independently.
- **Default:** Independent (new users start unlinked). Global toggle flips the whole session.

**Current behavior:** `RebindWorkspace` (`session_server.rs:1538`) broadcasts `OnWorkspaceRebind` to **all** `ConnState::Attached(source)` — always linked. No toggle, no per-viewer scoping, no `TermWmAction` for follow. Palette shows workspaces/users as disabled headers only.

## Decision: Global Follow Toggle + Scoped Rebind

Keep decoupled, build-on-open palette for listing, but make switching respect a global `follow_enabled` flag. Use clean wire `RebindScope` (no backward-compat fallback) — hard break is acceptable per user.

### Fix 1 — Fallback for `initiator_conn_id == None` in `RebindWorkspace` (`session_server.rs`)
When `RebindScope::CallerOnly` and `initiator_conn_id` is `None` (keyboard shortcut before attribution, synthetic event, macro), `filter` would match 0 handles and lock workspace. Add fallback:
```rust
RebindScope::CallerOnly => {
    let conns = state.conns.read().await;
    let attached: Vec<_> = conns.values()
        .filter(|e| matches!(&e.state, ConnState::Attached(n) if n == &source))
        .collect();
    if let Some(init_id) = req.initiator_conn_id {
        attached.into_iter()
            .filter(|e| e.handle.0.conn_id == init_id)
            .map(|e| e.handle.clone())
            .collect()
    } else if attached.len() == 1 {
        vec![attached[0].handle.clone()]
    } else {
        Vec::new()
    }
}
```

## How to Control Auto-Follow (Answer: Global Toggle in Command Palette)

**Current implementation (after this plan):**
- **Default:** `Independent` — `workspace_follow_enabled = false` (`WindowManager::with_config`). Each viewer’s `SwitchWorkspace`/`NewWorkspace` moves **only** the initiator (`RebindScope::CallerOnly` with `initiator_conn_id` from `event_owner`).
- **Toggle:** Open **Command Palette** (`Ctrl+A` per `crates/term-wm-core/src/keybindings.rs:93` — `OpenCommandPalette: [(KeyCode::Char('a'), Ctrl)]`, also via FAB `WmFabComponent` or top-panel) → row `Follow Workspaces: Enable` (icon `◎`, `Category::Windows`). Selecting it runs `TermWmAction::ToggleWorkspaceFollow` (`src/main.rs: App::handle_custom_action`), flips `wm.workspace_follow_enabled`, and shows toast `Follow Workspaces: Enabled` (3 s) / `Disabled`. Label immediately flips to `Follow Workspaces: Disable` when enabled.
- **Effect when enabled:** `SwitchWorkspace`/`NewWorkspace` now uses `RebindScope::AllViewers` + same `initiator_conn_id` — server broadcasts `OnWorkspaceRebind` to **all** `Attached(source)` viewers, so everyone on that workspace follows together. Disabled again → back to caller-only.
- **Scope:** Global per-`WindowManager` instance (single `bool` under `#[cfg(feature="session-persistence")]`), not per-user/per-workspace. All viewers share the same daemon channel session, so toggle affects the whole session. No CLI flag or config file yet; state is in-memory (resets on restart). Turn off with `--no-session-persistence` at compile/runtime to hide the row entirely.
- **No extra steps:** Palette also shows `Connected Users (N)` grouped by workspace (`all_users_by_ws` via single `list_channels()` at open), so you can verify who will follow before toggling.
- **Only UI needed:** No `keybindings.json`, CLI flag, or config file — just the single `Follow Workspaces: Enable/Disable` row in the palette. That row *is* the toggle that determines whether `SwitchWorkspace`/`NewWorkspace` uses `CallerOnly` or `AllViewers`.

## Bug: Toggle Stuck on “Enable” (Dispatch Not Wired)

**Symptom (user 2026-08-20):** Clicking `Follow Workspaces: Enable` toasts `Enable` but never flips to `Disable`; palette always shows `Enable` on reopen. `workspace_follow_enabled` stays `false`.

**Root cause:** `crates/term-wm-core/src/runner.rs:183` and `src/term_wm_app.rs:904` delegate workspace actions to `app.handle_custom_action` via:
```rust
action @ (SwitchWorkspace(_) | NewWorkspace | DetachCurrentClient) => { if !handle_custom_action(&action) {…} }
```
`ToggleWorkspaceFollow` was added to `DEFAULT_STANDALONE_MENU_ACTIONS` and `always_pass` filtering, so the row **renders**, but it was never added to that `action @ (...)` matcher. Dispatch falls through to `comp.update()` (no-op), `handle_custom_action` never runs, `wm.workspace_follow_enabled` never flips.

**Fix (minimal, no new wire):**
- `crates/term-wm-core/src/runner.rs:186` + `src/term_wm_app.rs:904` (and `crates/term-wm-core/src/window/window_manager/focus.rs:99` always_pass) add `| ToggleWorkspaceFollow` to the workspace-action matcher so it routes through `App::handle_custom_action` (which already flips `wm.workspace_follow_enabled` and toasts).
- Keep `WindowManager::workspace_follow_enabled` as single source (no `TermWmApp` mirror, already corrected).
- Verify palette label now toggles `Enable ↔ Disable` and `SwitchWorkspace` scope flips accordingly. The `Ctrl+A` palette open (`keybindings.rs:93`) + FAB/top-panel remain the only entry points — no `keybindings.json`.
