# Plan: Streamlined Command Palette — Unified Workspaces & Collaboration

## Context (user 2026-08-20)
Paletter sections are hard to follow: workspace features split across 3 separate blocks (`Workspace` switcher → `Connected Users` global list → `Follow Workspaces` isolated toggle), connected users not under their workspace, no titles, feels cluttered. Request: single workspace section, nested users, follow toggle in same region, with lightweight titles without clutter.

Current `wm_menu_items` (`command_palette.rs:106`) indeed builds:
- `Workspace` switcher (New Workspace, Switch to, Detach) + `Separator`
- `Connected Users` global grouped (`BTreeMap` iteration with `disabled:true` headers) + `Separator`
- `Follow Workspaces` isolated toggle + `Separator`
→ 3 workspace-related sections, 3 separators, 3 `#[cfg]` blocks.

## Decision: 5 Titled Sections, Single Workspaces & Collaboration Block

Group into 5 logical categories with subtle `── TITLE ──` disabled headers (existing `MenuItem{disabled:true, action:CloseMenu}` primitive, no new `Separator` variant needed):

1. `QUICK ACTIONS` (Resume, New Terminal, Project Tasks)
2. `WORKSPACES & COLLABORATION` (New Workspace, Follow toggle, Detach, then per-workspace `Switch to Workspace: {ws} (current)` with nested `└ user@host` tree)
3. `WINDOW MANAGEMENT` (Send Super, Close, Maximize/Restore, Minimize, Switch Window)
4. `VIEW & LAYOUT` (Monocle, Tile/Float)
5. `SETTINGS & SYSTEM` (Mouse, Clipboard, Debug Log, Panel, Help, Exit)

Users nested directly under their workspace using `└` tree indicator keeps presence contextual; follow toggle lives in same region so link state is visible next to the list it affects.

Visual target (provided by user, single source of truth):
```
── QUICK ACTIONS ──────────────────────────────────────────
  ▶ Resume
  + New Terminal
  ▶ dev: Run Build Task

── WORKSPACES & COLLABORATION ──────────────────────────────
  + New Workspace
  ◎ Follow Workspaces: Disable
  - Detach Viewer
  → Switch to Workspace: dev (current)
      └ alice@host-a (192.168.1.50)
      └ bob@host-b
  → Switch to Workspace: prod
      └ carol@host-c

── WINDOW MANAGEMENT ───────────────────────────────────────
  A Send Super to Shell 1
  X Close Shell 1
  ▢ Maximize Shell 1
  _ Minimize Shell 1
  → Switch to: Shell 2

── VIEW & LAYOUT ───────────────────────────────────────────
  ▢ Enable Monocle Mode
  ⊞ View: Float Windows

── SETTINGS & SYSTEM ───────────────────────────────────────
  ◆ Mouse: Disable Capture
  ■ Clipboard: Enable
  ■ Paste
  ≣ System: Enable Debug Log
  * System: Enable Panel
  ? Help
  ⏻ Exit UI
```

- **Workspaces & Collaboration (consolidated, #[cfg(session-persistence)]):** push `header("WORKSPACES & COLLABORATION")`, then `New Workspace`, follow toggle (`if self.workspace_follow_enabled {"Disable"} else {"Enable"}` with `◎`/`○`), `Detach Viewer`, then for each `ws in workspaces` push `Switch to Workspace: {ws} (current)` (disabled if current) **immediately followed** by `if let Some(users)=all_users_by_ws.get(ws) { for u in users { info_item(format!("    └ {}@{} ({})",…)) } }`. ## Amendments per Code Review (SEV-1/SEV-2) — Must Be Applied Before Merge

**SEV-1 Fallback:** `wm_menu_items` must not assume `all_users_by_ws` is always populated. When palette is opened in standalone/embedded or IPC fails, `all_users_by_ws` is empty. Keep `user_registry` fallback **inside the per-workspace loop** (not as a separate global block):
```rust
let render_user = |u: &crate::user_registry::UserEntry| {
    if let Some(ip) = &u.ssh_ip {
        format!("    └ {}@{} ({})", u.user, u.hostname, ip)
    } else {
        format!("    └ {}@{}", u.user, u.hostname)
    }
};
let users_exist = all_users_by_ws.get(ws).map_or(false, |u| !u.is_empty());
if users_exist {
    for u in &all_users_by_ws[ws] {
        items.push(info_item(render_user(u)));
    }
} else if ws == current_workspace && !self.user_registry.is_empty() {
    for (_k, u) in self.user_registry.iter() {
        items.push(info_item(render_user(u)));
    }
}
```

**SEV-2 Test:** Update `wm_menu_items_separates_controls_and_switcher` in `command_palette.rs` — it currently asserts `items[idx-1] == Separator` immediately before `Switch to:`. In the 5-section layout, `Switch to:` is under `WINDOW MANAGEMENT` after `MinimizeWindow` (an `Item`), not after a `Separator`. Change to assert existence and ordering without `items[idx-1] == Separator`, e.g. `assert!(items.iter().any(|e| matches!(e, Item(m) if m.label.starts_with("Switch to:"))))` and `assert!(has_active)` only.

**SEV-2 Header Filter:** `TermWmApp::open_command_palette` filters `supported_menu_actions`; headers/info rows are `disabled:true, action:CloseMenu` and would be stripped if a custom `supported_menu_actions` omits `CloseMenu`. Fix filter to auto-pass disabled items:
```rust
let items: Vec<_> = items.into_iter().filter(|entry| match entry {
  MenuDisplayItem::Item(item) => item.disabled || supported.contains(&item.action) || always_pass,
  MenuDisplayItem::Separator => true,
}).collect();
