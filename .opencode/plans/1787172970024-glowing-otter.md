# Plan: Lower `muxio` RPC transport spam from DEBUG to TRACE

## Context

* Hammer: `~50-150ms` in `term-wm` Debug Log (`WmDebugLogComponent` via `term_wm_core::debug_log::DebugLogBuffer` / `src/logging.rs:25 DelegatingWriter`):
  ```
  2026-08-19T21:14:28.734830Z DEBUG Added request 2147484084 to queue.
  2026-08-19T21:14:28.734857Z DEBUG Request 2147484084 finalized.
  ```
* Root cause in `muxio` (maintained by user, consumed as `muxio-core 0.14.0-alpha` in `term-wm` `Cargo.toml:76`): `muxio-core/src/rpc/rpc_dispatcher.rs:169,206` inside `RpcDispatcher::init_catch_all_response_handler` (also `186,192,208` adjacent handlers). Current:
  ```rust
  tracing::debug!("Added request {} to queue.", id);
  tracing::debug!("Request {} finalized.", id);
  ```
  Fires on every `RpcStreamEvent::Header/End` (`IdSpace::Server = 0x8000_0000` → `2147484084 = 0x80000114`), i.e. every server→client push (`OnPtyResized`, `OnAttributedInput` `session_server.rs:346,1495`). Rate limited by `term-session-client/src/lib.rs:81 INPUT_POLL_MS=50` and per-frame `terminal.rs:262 resize` → `ResizePty`.
* Desired fix (per user):
  ```rust
  // BEFORE
  tracing::debug!("Added request to queue [id: {id}]");
  // AFTER
  tracing::trace!(target: "muxio_rpc_service::transport", id = id, "request enqueued");
  ```
  `DEBUG→TRACE` + structured `target` + field `id`. Hidden under default `Level::DEBUG` / `debug` filter; re-enable with `RUST_LOG=muxio_rpc_service::transport=trace` or `TERM_WM_LOG`.

## Approach

**Change at source in `muxio` repo, then bump in `term-wm`.** No `term-wm` `src/logging.rs:90 LevelFilter::DEBUG` change required (filter already `DEBUG` blanket, `trace` is below). This is lowest-risk: one crate, no subscriber behavior change.

Alternative (EnvFilter in term-wm) rejected — not needed now that source is writable.
