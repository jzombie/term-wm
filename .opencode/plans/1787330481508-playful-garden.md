# Plan: `opencar` — Open-World Braille TUI Driving Simulator

## Summary
New **standalone** crate `crates/opencar` (lib + bin). Zero coupling to term-wm crates: own crossterm terminal setup, own game loop, own keybindings. Infinite procedural terrain (hills/mountains), winding highways with guardrails/signs baked into the world, AI traffic, chase cam, HUD + minimap.

**Rendering model (revised per feedback):** every frame is rendered into a full **RGB pixel buffer** (like terminal video players), and only at the very end is that image encoded as Unicode braille dots (cell = 2×4 dots). All world content — terrain, cars, scenery — is drawn with real perspective projection, sun shading and fog so it reads like a photo/GTA-style render, not character-art sprites. No motion blur, no film grain. Target ~30–60 fps in release.

Only change to an existing file: add `"crates/opencar"` to `[workspace] members` in root `Cargo.toml` (explicit list, no glob — verified).

## Key Algorithms

### Noise / terrain (world/noise.rs, chunk.rs)
- Integer hash → [0,1): xorshift-multiply mix of `(x*PRIME1) ^ (y*PRIME2) ^ seed`; value noise = bilinear-smoothstep of corner hashes; fBm 4–5 octaves (lacunarity 2, gain 0.5); ridged = `1-|2n-1|`.
- Height: `continent = fbm(p/CONTINENT_SCALE)` (plains↔mountain regions), `mountains = ridged(p/RIDGE_SCALE)^1.5`, `hills = fbm(p/HILL_SCALE)`; `h = continent*MOUNTAIN_AMP*mountains + hills*HILL_AMP*(0.4+0.6*(1-continent))`. Sea plane at `SEA_LEVEL` (water/sand bands). Materials from height+slope+dither: grass / dirt / rock / snow above `SNOW_LINE`.

### Roads (world/roads.rs, baked in chunk.rs)
- Two highways: A ≈ E-W with centerline `x_c(z)`, B ≈ N-S with `z_c(x)`; each = sum of 2 sines + warped noise (deterministic, chunk-independent).
- **Unified road influence:** proximity weights `wA = max(0, 1 − dA/BLEND)`, `wB = max(0, 1 − dB/BLEND)`; elevation `(wA·eA + wB·eB)/max(wA+wB, ε)` away from junctions.
- **3-D junction surface (SEV-1/SEV-2 fix):** within `JUNCTION_HALF` meters of an A×B crossing, height comes from an **explicit pre-baked height grid** — a small axis-aligned regular grid (`JUNCTION_GRID_DIM²` ≈ 33²) over the junction box whose node heights are baked once from the two roads' elevation profiles (+ slopes), C¹-matched at the edges. Queries inside the zone are **O(1) bilinear lookups** of `Y = f(X,Z)` — no parametric surface, no inverse root-finding anywhere in the marcher or AI. All height/material/normal queries inside the zone read this grid.
- **Embankment blending:** terrain heightfield blends to the grid perimeter via radial smoothstep falloff (`JUNCTION_BLEND`) → no corner artifacts.
- Materials: asphalt `|d|<ROAD_HALF`; dashed center paint; solid edge lines; shoulders; guardrail steel band only where adjacent terrain drops > `RAIL_DROP_THRESH`.
- Curvature κ(s) → curve-warning sign placements (3-D post+plate meshes, spacing-deduped).

### Renderer (render/*) — image-first, braille last
1. **ImageBuffer**: `rgb: Vec<u8>` (W·H·3) + **`z: Vec<f32>` (W·H) — a single unified depth buffer**. Terrain and 3-D objects both read/write it, so occlusion between heightfield and meshes is exact. `braille.rs` converts once per frame.
2. **Sky**: continuous gradient + sun disk + cloud noise written as RGB pixels.
3. **Terrain** (voxel-space, **O(W′×steps)**, roll = 0, **true 3-D pitch rays** — SEV-1 fixes): one marched ray per column of the overscanned buffer (never per-pixel marching), but pitch is NOT a 1-D horizon offset: each column's direction is a **true 3-D vector derived from `R_cam_unrolled` (yaw+pitch)** — interpolated between the frustum edge rays. On a penetration at distance `t`, the hit point `(X,Y,Z)` is projected to its screen row **through the exact same perspective projection used by `raster.rs`**, so terrain and meshes stay pixel-locked under braking/throttle pitch. March writes sun-shaded, fog-blended RGB plus view depth into `z[]` for every written pixel; road paint is shaded during the march (terrain materials — never overlays).
   **Chassis roll = 3-stage pipeline (SEV-1 fix, replaces whole-frame post-rotation):** for a pinhole camera, rolling the camera IS rotating the image plane — valid only in isotropic space, so:
   - **Step 1 — terrain overscan:** compute the W×H screen box rotated by −roll; march the Comanche columns across that widened frustum into an oversized persistent `TerrainBuffer` (RGB + z), so no void corners exist for any roll within `ROLL_MAX`.
   - **Step 2 — terrain roll:** bilinear-rotate `TerrainBuffer`'s RGB **and z** channels into the final W×H `ImageBuffer` (skipped under `ROLL_EPS`; corners always covered thanks to overscan).
   - **Step 3 — meshes:** rasterize all 3-D geometry (cars, signs, shadows, light cones) **directly into the final `ImageBuffer` through the full 3×3 rolled camera matrix** — meshes are never 2D-rotated, so foreground perspective stays exact while the rotated terrain matches it by construction.
4. **3-D objects via mini rasterizer** — the realism core:
   - `raster.rs`: transform local quad verts → world → camera space via the **full 3×3 rolled matrix (yaw+pitch+roll)**, rasterizing straight into the final `ImageBuffer` (meshes are never 2D-rotated — SEV-2 perspective fix); **Sutherland–Hodgman clip against the near plane `Z ≥ Z_NEAR (0.1)` BEFORE perspective divide** (chase-cam proximity to the player car must never produce division-by-zero/inverted geometry); scanline-fill surviving polygons with per-pixel `z_new < z_buf[i]`; shade faces via interpolated normals ⊗ `SUN_DIR` + Fresnel specular; emissive light quads skip lighting; fog by face depth.
   - `models.rs`: car = low body box + cabin/windshield + 4 wheel boxes + emissive tail/brake/headlight quads (~20 quads); sign = thin post + tilted plate with color-mapped face. Player car uses the same model at close range with steering yaw applied → visible 3/4 rear when cornering.
   - **Surface-conforming decal shadows (SEV-2 fix):** no flat 2-D ellipses. Each car's shadow is a 3-D quad built from the terrain height **and normal sampled at the four wheel contact points**, lifted `SHADOW_EPS (0.03 m)` along the ground normal, rasterized through `raster.rs` with multiplicative darkening into `ImageBuffer.rgb` under the shared z-buffer → shadows hug slopes and never float or clip into hills.
5. **HUD/minimap**: terminal-native panels *outside* the camera feed (no text ever drawn into the 3-D view).
6. **Encode (`braille.rs`, hardened dual-color quantization per 2×4 cell)**: **dither lives in the buffer, not the cluster boundary (SEV-2 fix):** first inject the blue-noise/Bayer pattern as a small-amplitude additive perturbation to the `ImageBuffer` RGB pixels (pre-quantization); then cluster those dithered values with plain **3-D RGB Euclidean k-means** (≤4 iterations, seeded by min/max-luma pixels — never luma-only, which merges red brake lights with dark-blue sky). Bit assignment = nearest centroid on the same dithered values that produced the centroids, so a pixel pushed bright by noise genuinely contributes its RGB to (and is drawn with) the bright centroid — no false-color fringing/sparkles. Lit dots → glyph bits `U+2800+mask`; `fg`/`bg` = the two centroids. **Uniform/empty-cluster guards:** convergent centroids within `QUANT_UNIFORM_THRESH` or an emptied cluster collapse to `fg = bg` = block average with all-lit (`0xFF`) or blank glyph; every mean division guards `count == 0`. **Sole owner of aspect correction:** the encoder samples the isotropic render buffer at positions scaled by `CELL_ASPECT` — no aspect scalar exists anywhere in the 3-D pipeline. No NaNs, no div-by-zero on solid blocks.

### Photoreal fidelity upgrades (post-M4 pipeline layers)
Target look: **dashcam footage**, not Virtua Racing. Layered onto the image-first renderer:
1. **Procedural texturing — no flat colors**: multi-scale noise evaluated during the terrain march (asphalt gravel + lane wear + oil stains; organic grass/dirt mottling; rock striation). Mesh faces carry UVs → procedural texture fns for car paint flakes, sign faces, guardrail galvanization.
2. **Materials & smooth shading**: every face carries `{albedo, roughness, metallic}`. Quad vertices store normals, interpolated per-pixel (Gouraud→phong-lite) so car bodies/fenders shade as curved shells. Lighting = ambient + sun diffuse + **Fresnel-weighted specular** reflecting the sky gradient/sun disk (glossy paint, glass windshields, chrome trim vs matte asphalt vs rough dirt).
3. **Dynamic lighting & atmosphere** (tied to day/night cycle + weather factor):
   - Headlight/taillight **light-cone quads** (additive translucent volumes) cutting through fog/night;
   - **Halo/bloom** post-pass: small radial glow sprites dithered around bright emitters (brake lights, sun, streetlights);
   - **Wet-road mode**: rain factor raises roughness↓/reflectivity↑ so asphalt mirrors sky and taillights.
4. **Environmental density**: low-poly 3-D trees/bushes (cone+noise-blob clusters), power poles with sagging cable strips, streetlights, big highway gantry signs near junctions — all through the same z-buffered rasterizer, spawned deterministically per chunk.
5. **Higher-poly vehicles (~100+ quads)**: lofted body shell, side mirrors, 8-gon wheel prisms, recessed grilles/light housings, license plates. 20 cars × ~100 quads ≈ 2 k quads/frame — within budget.
6. **Directional shadows — deferred screen-space pass, high resolution (SEV-2 fix):** sun-space depth map sized for detail: `SHADOW_MAP_DIM = 256` over a tight `SHADOW_COVERAGE_M ≈ 30` player-centered box (~12 cm/texel — resolves car silhouettes, signposts and contact shadows; a wider ~120 m mode at 1024² exists as a const toggle). The terrain march and rasterizer write ONLY `rgb`+`z`. A deferred lighting pass then walks the completed depth buffer of the final rolled frame: reconstructs each pixel's world position by **inverse-projecting `(x, y, z)` through the inverse of the full 3×3 rolled camera matrix** (never via cached unrolled column rays), transforms world→sun-space (one affine MAD per pixel, outside any marching loop), samples the shadow map once with a normal-offset bias against acne, and multiplicatively darkens `rgb`. Mesh pixels may alternatively carry interpolated vertex shadow factors during rasterization. True projected + contact shadows, correct on the rolled frame.
7. **Camera film artifacts**: high-frequency shake scaled by speed/RPM/surface roughness (on top of chassis pitch/roll/heave); **auto-exposure tone mapping** (running scene-luma average → exposure compensation entering tunnels/against the sun); **blue-noise dithering** replaces the Bayer matrix in `braille.rs` quantization (precomputed tiled 64×64 blue-noise table) for film-like gradients in sky/fog/shadows.

### Physics (sim/car.rs, dt = 1/60 accumulator)
`speed += (throttle·ACCEL − drag·v² − roll·v − brake·BRAKE)·dt`; offroad adds `OFFROAD_DRAG` + caps speed; `heading += steer_smoothed · STEER_RATE · g(v) · dt · sign(v)` where `g(v) = clamp(v/12,0,1)·(1−0.55·v/MAX_SPEED)` (tight low, stable high); reverse steers inverted; Space = handbrake; soft circle collision vs traffic (pushback + mutual damping); clamps `[-MAX_REVERSE, MAX_SPEED]`.

### Traffic (sim/traffic.rs)
State `{hw, s, lane, dir, v, braking}`; IDM-lite leader gap keeping on straights; recycle beyond `RECYCLE_BEHIND/AHEAD` of the player → respawn ahead (constant density). Braking flag drives emissive brake quads.
**3-D junction traversal (SEV-2 fix):** when an NPC's path enters a junction zone it switches to a **cubic Bézier turn arc** from entry point+tangent to exit point+tangent (same-road arcs pass straight through), height-evaluated via O(1) bilinear lookups on the junction height grid. Orientation (yaw/pitch) derives from the grid surface normal ⊗ velocity direction — continuous kinematics, no orientation snapping or terrain clipping while turning across sloped junctions.

### Chase camera (render/camera.rs) — mounted-camera realism
- Spring-follow position behind the car; presets cycled with `C`.
- **Chassis dynamics:** pitch from weight transfer `k_p · longitudinal_accel` (nose dips on braking); heave/vibration from offroad + speed.
- **Roll via 3-stage pipeline (SEV-1 fix):** terrain marches with pitch+yaw only into an overscanned `TerrainBuffer` (rotated-bbox coverage → no void corners); the terrain RGB+z is rotated by roll into the final buffer; meshes rasterize through the full rolled matrix directly. Isotropic 1:1 render space throughout — rotation is metric-valid and terrain/mesh alignment is exact by construction.
- **Isotropic projection:** NO aspect scalar in the camera focal — circles render as circles in the buffer; terminal cell aspect (`CELL_ASPECT`) is applied once, inside `braille.rs` sampling, exclusively.

### Input (app.rs, own keybindings — zero WM coupling)
Arrows/WASD drive, Space handbrake, C cam cycle, M minimap, H HUD, P/Esc pause, Q or Ctrl-C quit. Single const keymap table.
Enable `KeyboardEnhancementFlags::REPORT_ALL_KEYS_AS_ESCAPE_CODES | REPORT_EVENT_TYPES` when `supports_keyboard_enhancement()` → true Press/Repeat/**Release**; held = down-until-release.
**Fallback state machine (SEV-2 fix):** on terminals without release events, `FALLBACK_HELD_TIMEOUT_MS = 600` (> worst-case OS initial repeat delay of 250–500 ms). `Press` → Active + timestamp; each `Repeat` refreshes the timestamp; only `now − last_event > 600 ms` marks Released. No mid-hold dropouts before auto-repeat begins.

## Data Structures (fields)
- `ImageBuffer { w,h, rgb: Vec<u8> (W·H·3), z: Vec<f32> (W·H) }` — final rolled frame, unified depth buffer
- `TerrainBuffer { w',h' (rotated-bbox overscan), rgb, z }` — unrolled march output; rotated into ImageBuffer
- `BrailleEncoder { dots: Vec<u8>, fg_rgb/bg_rgb accum per cell, cell_aspect }` — 3-D RGB k-means, post-centroid dither bias, sole aspect owner
- `World { chunks: HashMap<(i32,i32), Chunk>, roads: RoadNetwork, seed }`
- `Chunk { origin:(i32,i32), heights: Vec<f32>, mats: Vec<u8>, signs: Vec<SignDef> }`
- `RoadNetwork { ew, ns: Centerline }` + `JunctionGrid { origin, dim (≈33²), cell, heights }` — explicit O(1) bilinear `Y(X,Z)`
- `Vehicle { pos, heading, speed, steer, steer_sm, throttle, brake, long_accel }`
- `NpcCar { hw, s, lane, dir, v, braking, junction: Option<JunctionPath{bezier p0..p3, u}> }`
- `CameraState { pos, yaw, pitch, roll, heave, preset }`, `Projector { R_cam_rolled 3×3 (meshes), R_cam_unrolled yaw+pitch (terrain march), focal_x/y isotropic (no aspect scalar), center }`
- `ShadowMap { dim, sun_depth: Vec<f32>, bounds }`; `Environment { day_phase, rain: f32, exposure: f32 }`
- `App { mode, world, player, traffic, cam, image, hud, env, keys: HeldKeys }` (`HeldKeys` = kitty down-set OR 600 ms timestamp state machine)

## Performance Budget
Terrain stays **O(W′ × steps)** over the overscanned rotated-bbox width W′ ≤ W/cos(ROLL_MAX) (~+15% at 30° roll): ~55–60 k height samples/frame (+1 z-store each; per-column true-3-D pitch rays keep this independent of pitch angle) — never per-pixel marching. Terrain rotation: one bilinear pass over the overscan buffer (RGB+z). Meshes: ~2.5–4 k z-tested quads through the rolled matrix. Deferred shadows: 256² sun-depth pass + inverse-projection MAD + lookup per pixel, outside all loops. Quantization: dither injection + one 8-px RGB k-means pass per cell — negligible. Total inside 16.6 ms in release; debug builds ~10–20 fps (document `--release`). Steady-state zero heap allocs (all buffers persistent).

## Tests (repo pattern: headless `Buffer::empty(area)` renders)
- **pitch lock**: with camera pitched ±N°, every terrain hit row equals `raster.rs`'s projection of the same world point (shared matrix, no horizon-shift approximation); meshes stay glued to the road surface during simulated braking/throttle pitch sweeps
- braille encoder: **dither-before-clustering** — noise injected into RGB pre-k-means; bit assignment always equals nearest-centroid on the same dithered values that formed the centroids (no false-color sparkles: a dark pixel never renders in the bright centroid's color); **RGB-space clustering** keeps red-taillight-vs-dark-sky distinct; **uniform block** → fg=bg=average, no panic/NaN; constant-color ramp yields monotonic dot density; golden glyphs
- terrain raycast: W′ overscan columns only; roll = 0 in the march
- **roll pipeline**: at roll θ, (a) no void corners — every final-buffer pixel has a TerrainBuffer source within bounds; (b) mesh rendered through the rolled matrix aligns with rotated terrain of the same pose (sample-consistent within bilinear ε); (c) isotropic space — a world-space circle projects to a circular pixel set before encoding; aspect distortion appears only after `CELL_ASPECT` sampling in the encoder
- **deferred shadows on rolled frame**: inverse-matrix unprojection reconstructs world positions that match ground truth after terrain rotation
- **shadow resolution**: shadow map texel size ≤ `SHADOW_COVERAGE_M / SHADOW_MAP_DIM` (~12 cm at defaults); a pole/sign caster produces a thin (≤2-texel-wide) projected shadow, not a blocky smear; deferred factor matches direct sun-space sampling on a synthetic scene; caster removal restores base light
- junction grid: ONE height for both highways at the crossing, edge profiles C¹-matched; O(1) lookup path exercised
- **decal shadows**: quad corners sit ≈ `SHADOW_EPS` above sampled terrain heights on a slope
- **specular/tone-map**: mirror-facing-sun pose yields a highlight brighter than albedo allows; tone mapper keeps luma within [0,255] across a 100× exposure sweep
- **near-plane clipping**: quad crossing `Z = Z_NEAR` splits into valid sub-polygon(s); fully-behind quad draws nothing; no panics with camera intersecting car rear
- **unified depth**: terrain writes z per pixel; quad straddling a hill crest is occluded above the crest and visible below it
- rasterizer: projected quad covers expected pixel rect; nearer quad wins z-test
- roads: proximity-blend elevation away from junctions; physics clamps/reverse/offroad
- traffic: same-lane min-gap invariant over N steps; NPC turn arc stays on the junction surface (height continuity); recycle keeps count constant
- input fallback: Press with no follow-up events stays Active ≥600 ms
- render smoke: fixed seed+pose → non-empty buffer, byte-identical across two runs
- sim determinism: 300 ticks → bit-equal positions; too-small terminal renders message not panic

## Milestones (each runnable)
1. **M1**: skeleton + loop + ImageBuffer (unified z) + TerrainBuffer overscan/rotation + hardened/dithered braille encoder (aspect at encode) + sky + unrolled terrain flyover.
2. **M2**: player car physics + controls (kitty + 600 ms fallback) + speed HUD.
3. **M3**: roads baked + junction explicit height grids + offroad penalty; drive/follow a highway through a crossing.
4. **M4**: near-plane-clipped rasterizer; 3-D car models (player + traffic), surface-conforming decal shadows, collisions, Bézier junction turns, minimap.
5. **F1 — materials**: procedural terrain texturing; per-face `{albedo, roughness, metallic}`; per-pixel interpolated normals + Fresnel specular on meshes.
6. **F2 — density & detail**: 100+-quad vehicle shells (mirrors/wheels/grilles), trees/bushes/poles/cables/streetlights/gantries per chunk.
7. **F3 — lighting**: sun-space shadow map + contact shadows; day/night cycle; headlight cones, brake-light bloom halos; wet-road reflections.
8. **F4 — film**: auto-exposure tone mapping, speed/RPM shake refinement, blue-noise quantization dithering; pause overlay; perf pass; clippy/tests green.

## Risks
Font aspect variance handled once in `braille.rs` (`CELL_ASPECT` sampled at encode — 3-D pipeline stays isotropic) · slow debug builds (document `--release`) · weak braille-font terminals (noted in help) · Windows key repeat differences (600 ms heartbeat covers) · junction **explicit height grids** are cheap to query but must bake consistently per junction — deterministic world-coord baking + continuity tests · roll overscan widens the march by ≤1/cos(`ROLL_MAX`) and adds one bilinear rotation pass — bounded, skipped under `ROLL_EPS` · deferred shadow pass does one inverse-projection MAD + shadow lookup per pixel outside all loops — bounded, equivalence-tested on rolled frames · fidelity layers (F1–F4) strictly tiered so any layer can ship independently or be toggled off if the frame budget slips · shadow-map acne handled with a normal-offset bias const · blue-noise table generated procedurally at startup (no assets/licensing).
