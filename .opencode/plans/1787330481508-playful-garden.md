# Plan: `opencar` — Open-World Braille TUI Driving Simulator

## Summary
New **standalone** crate `crates/opencar` (lib + bin). Zero coupling to term-wm crates: own crossterm terminal setup, own game loop, own keybindings. Infinite procedural terrain (hills/mountains), winding highways with guardrails/signs baked into the world, AI traffic, chase cam, HUD + minimap.

**Rendering model (revised per feedback):** every frame is rendered into a full **RGB pixel buffer** (like terminal video players), and only at the very end is that image encoded as Unicode braille dots (cell = 2×4 dots). All world content — terrain, cars, scenery — is drawn with real perspective projection, sun shading and fog so it reads like a photo/GTA-style render, not character-art sprites. No motion blur, no film grain.

**Dual-backend engine (final blueprint):** a unified `Renderer` trait consumes the game state and emits the same linear array of 4,800 terminal cells (`120 × 40` × `{ braille_mask, fg, bg }`) regardless of backend:
1. **GPU path (`wgpu`, primary):** engaged only when a hardware adapter exists — `DeviceType::Cpu` software drivers (llvmpipe/WARP) are explicitly rejected. WGSL passes: sun-depth shadow map → forward pass (terrain as explicit height-grid vertices + car meshes with PCF shadows + Fresnel specular) into a `240×160` RGB texture → full-screen **fragment** quantization pass (no compute shaders, for VM compatibility) doing lens distortion + 2×2 box pre-filter + dual min/max-surface quantization with temporal threshold dither (identical to the CPU encoder v3) → async buffer readback of encoded cells.
2. **CPU path (software fallback):** the full pipeline already specified in this plan, upgraded with rayon band threading, portable SIMD (`wide` crate — NOT nightly `std::simd`), reverse-mapped barrel-distortion LUTs and a pre-generated 512² noise LUT for terrain textures.
The app initializes GPU first and seamlessly falls back; a HUD tag shows which backend is live. Target 60 fps on GPU, 30–60 fps on multi-core CPU release builds.

Only change to an existing file: add `"crates/opencar"` to `[workspace] members` in root `Cargo.toml` (explicit list, no glob — verified).

## Key Algorithms

### Noise / terrain (world/noise.rs, chunk.rs)
- Integer hash → [0,1): xorshift-multiply mix of `(x*PRIME1) ^ (y*PRIME2) ^ seed`; value noise = bilinear-smoothstep of corner hashes; fBm 4–5 octaves (lacunarity 2, gain 0.5); ridged = `1-|2n-1|`.
- Height: `continent = fbm(p/CONTINENT_SCALE)` (plains↔mountain regions), `mountains = ridged(p/RIDGE_SCALE)^1.5`, `hills = fbm(p/HILL_SCALE)`; `h = continent*MOUNTAIN_AMP*mountains + hills*HILL_AMP*(0.4+0.6*(1-continent))`. Sea plane at `SEA_LEVEL` (water/sand bands). Materials from height+slope+dither: grass / dirt / rock / snow above `SNOW_LINE`.

### Roads (world/roads.rs, baked in chunk.rs)
- Two highways: A ≈ E-W with centerline `x_c(z)`, B ≈ N-S with `z_c(x)`; each = sum of 2 sines + warped noise (deterministic, chunk-independent).
- **Unified road influence:** proximity weights `wA = max(0, 1 − dA/BLEND)`, `wB = max(0, 1 − dB/BLEND)`; elevation `(wA·eA + wB·eB)/max(wA+wB, ε)` away from junctions.
- **3-D junction surface (SEV-1/SEV-2 fix):** within `JUNCTION_HALF` meters of an A×B crossing, height comes from an **explicit pre-baked height grid** — a small axis-aligned regular grid (`JUNCTION_GRID_DIM²` ≈ 33²) over the junction box whose node heights are baked once from the two roads' elevation profiles (+ slopes), C¹-matched at the edges. Queries inside the zone are **O(1) bilinear lookups** of `Y = f(X,Z)` — no parametric surface, no inverse root-finding anywhere in the marcher or AI. All height/material/normal queries inside the zone read this grid.
- **Embankment blending:** terrain heightfield blends to the grid perimeter via radial smoothstep falloff (`JUNCTION_BLEND`) → no corner artifacts.
- Materials: asphalt `|d|<ROAD_HALF`; dashed center paint; solid edge lines; shoulders; guardrail steel band only where adjacent terrain drops > `RAIL_DROP_THRESH`.
- Curvature κ(s) → curve-warning sign placements (3-D post+plate meshes, spacing-deduped).

### Renderer (render/*) — image-first, braille last
1. **ImageBuffer**: `rgb: Vec<u8>` (W·H·3) + **`z: Vec<f32>` (W·H) — a single unified depth buffer**. Terrain and 3-D objects both read/write it, so occlusion between heightfield and meshes is exact. `braille.rs` converts once per frame.
2. **Sky**: continuous gradient + sun disk + cloud noise written as RGB pixels.
3. **Terrain** (voxel-space **sample-and-project**, O(W′×steps) — SEV-1 rewrite): the first implementation combined ray-intersection with voxel projection and smeared single-hit colors into vertical stripes. **Correct algorithm:** per overscan column, advance along the horizontal ray (`dir[0]`, `dir[2]` only), sample `h = height_at(x,z)` at EVERY step, project the actual ground point `[x, h, z]` through the unrolled basis (`project_unrolled` → row via perspective divide), and paint visible spans into the per-column y-top buffer:
   `if row < y_top { fill(row..y_top, shade(mat)); y_top = row }`.
   Flat ground now converges to the vanishing point. **Shadows are FORWARD-evaluated**: the exact, unaltered world point `(x, h, z)` is natively known at each visible span, so `shade()` samples the sun-depth map directly (Poisson-disk PCF) — never any screen-space reconstruction. Depth written per span is the correct forward distance `fwd_d`, which synchronizes the mesh z-test. Step growth tightened (`STEP_GROWTH 0.008`) so the ~9 m road band is never skipped between samples; road widened (`ROAD_HALF_WIDTH 4.6`) with thicker bright edge lines for anchoring contrast.
   **Chassis roll = 3-stage pipeline (SEV-1 fix, replaces whole-frame post-rotation):** for a pinhole camera, rolling the camera IS rotating the image plane — valid only in isotropic space, so:
   - **Step 1 — terrain overscan:** compute the W×H screen box rotated by −roll; march the Comanche columns across that widened frustum into an oversized persistent `TerrainBuffer` (RGB + z), so no void corners exist for any roll within `ROLL_MAX`.
   - **Step 2 — terrain roll:** DECOUPLED resampling into the final W×H `ImageBuffer`: RGB uses bilinear (anti-aliasing); **Z uses nearest-neighbor point fetch** `round(x), round(y)` — interpolating depth across foreground/background silhouettes synthesizes mid-air depths that corrupt mesh occlusion (skipped under `ROLL_EPS`; corners always covered thanks to overscan).
   - **Step 3 — meshes:** rasterize all 3-D geometry (cars, signs, shadows, light cones) **directly into the final `ImageBuffer` through the full 3×3 rolled camera matrix** — meshes are never 2D-rotated, so foreground perspective stays exact while the rotated terrain matches it by construction.
4. **3-D objects via mini rasterizer** — the realism core:
   - `raster.rs`: transform local quad verts → world → camera space via the **full 3×3 rolled matrix (yaw+pitch+roll)**, rasterizing straight into the final `ImageBuffer` (meshes are never 2D-rotated — SEV-2 perspective fix); **Sutherland–Hodgman clip against the near plane `Z ≥ Z_NEAR (0.1)` BEFORE perspective divide** (chase-cam proximity to the player car must never produce division-by-zero/inverted geometry); scanline-fill surviving polygons with per-pixel `z_new < z_buf[i]`; shade faces via interpolated normals ⊗ `SUN_DIR` + Fresnel specular; emissive light quads skip lighting; fog by face depth.
   - `models.rs`: car = low body box + cabin/windshield + 4 wheel boxes + emissive tail/brake/headlight quads (~20 quads); sign = thin post + tilted plate with color-mapped face. Player car uses the same model at close range with steering yaw applied → visible 3/4 rear when cornering.
   - **Surface-conforming decal shadows (SEV-2 fix, revised):** no flat 2-D ellipses and NO geometry lift (`SHADOW_EPS` eradicated — with `TERRAIN_DEPTH_MARGIN` pushing the voxel plane back, a lifted decal only ends up occluding tire bottoms). Decal quads are built exactly at `height_at` (coplanar with tire contact patches), conforming to sampled normals on slopes. Strict sub-pass order in the rasterizer:
     * **Phase A — decals:** z-test ENABLED, **z-write DISABLED**; they pass against the pushed-back terrain plane and darken `rgb` multiplicatively.
     * **Phase B — solids:** vehicles/signs render with full z-test + z-write, overwriting coplanar decals where they intersect — tires can never be painted over by their own shadow.
5. **HUD/minimap**: terminal-native panels *outside* the camera feed (no text ever drawn into the 3-D view).
6. **Lens pass — barrel distortion before encoding (SEV-2 fix)**: dashcams use wide-angle lenses; a perfect pinhole projection reads as CG. After all world rendering + lighting, remap the frame radially: normalize pixel coords to NDC `[-1,1]²`, compute `r² = x²+y²`, distort `x' = x·(1+k·r²)`, `y' = y·(1+k·r²)` with slight negative `LENS_K`, bilinear-resample `rgb` at the source coords. Runs once per frame on the composed image (after shadows, before quantization); center stays fixed so the road vanishing point is stable.
7. **Encode (`braille.rs` v3 — dual-surface model, both backends)**: each dot samples a clamped 2×2 box average in image space (kills single-dot scanline aliasing). Per cell: `bg` = RGB of the MIN-luma sample (surface base), `fg` = RGB of the MAX-luma sample (surface highlight). Structured cells (tonal range ≥ `FLAT_RANGE_EPS`): dot lit iff its luma exceeds the min/max midpoint + small temporal jitter → crisp edges. Flat cells: temporal coverage halftone with fg = mean of two brightest / bg = mean of two darkest samples. Ambient floor and detail boost unchanged. Guards: all divisions count-guarded; sole owner of aspect correction; no NaNs.

### Photoreal fidelity upgrades (post-M4 pipeline layers)
Target look: **dashcam footage**, not Virtua Racing. Layered onto the image-first renderer:
1. **Procedural texturing — no flat colors**: multi-scale noise evaluated during the terrain march (asphalt gravel + lane wear + oil stains; organic grass/dirt mottling; rock striation). Mesh faces carry UVs → procedural texture fns for car paint flakes, sign faces, guardrail galvanization.
2. **Materials & smooth shading**: every face carries `{albedo, roughness, metallic}`. Quad vertices store normals, interpolated per-pixel (Gouraud→phong-lite) so car bodies/fenders shade as curved shells. Lighting = ambient + sun diffuse + **Fresnel-weighted specular** reflecting the sky gradient/sun disk (glossy paint, glass windshields, chrome trim vs matte asphalt vs rough dirt).
3. **Dynamic lighting & atmosphere** (tied to day/night cycle + weather factor):
   - Headlight/taillight **light-cone quads** (additive translucent volumes) cutting through fog/night;
   - **Halo/bloom** post-pass: small radial glow sprites dithered around bright emitters (brake lights, sun, streetlights);
   - **Wet-road mode**: rain factor raises roughness↓/reflectivity↑ so asphalt mirrors sky and taillights.
4. **Environmental density**: low-poly 3-D trees/bushes (cone+noise-blob clusters), power poles with sagging cable strips, streetlights, big highway gantry signs near junctions — all through the same z-buffered rasterizer, spawned deterministically per chunk.
5. **Higher-poly vehicles (~100+ quads)**: lofted body shell, side mirrors, 8-gon wheel prisms, recessed grilles/light housings, license plates. 20 cars × ~100 quads ≈ 2 k quads/frame — within budget.
6. **Directional shadows — STRICTLY FORWARD, both backends (SEV-1 fix):** the deferred screen-space pass is ERADICATED. Nearest-neighbor rotation + `TERRAIN_DEPTH_MARGIN` make the composited Z-buffer mathematically unfit for spatial reconstruction (angular drift of meters at range, systematic Peter-Panning). Instead BOTH pipelines forward-evaluate Poisson-disk PCF against the shared 256² sun-depth map (`SHADOW_COVERAGE_M ≈ 30`, ~12 cm/texel; 1024²/120 m wide-mode const toggle):
   * **Terrain:** PCF evaluated inside `shade()` at the exact march-known world point.
   * **Meshes:** PCF evaluated PER-PIXEL — barycentric world-position interpolation → sun-space transform → tap fetch, inside the scanline fill.
   The sun-depth map is built FIRST each frame from collected caster geometry; the final rolled `ImageBuffer.z` is used strictly for mesh occlusion and fog — NEVER for spatial reconstruction.
7. **Camera film artifacts**: high-frequency shake scaled by speed/RPM/surface roughness (on top of chassis pitch/roll/heave); **auto-exposure tone mapping** (running scene-luma average → exposure compensation entering tunnels/against the sun); **temporal blue-noise grain + barrel lens** in the encode path (per-frame noise offset, `LENS_K` radial distortion) for the dashcam-feed look.

### Playtest fixes round 2 (M0.1 — shear/blocks/lift)
Diagnosis: the "stride misalignment" is not an index math bug (`cell*2 / cell*4` mapping is exact and identity-aspect); the visible tearing comes from three compounding sources, fixed as follows:
1. **Lens warp reading as shear**: reduce `LENS_K` AND bound it structurally through the linear NDC↔screen relationship: `|k_eff| = min(|LENS_K|, LENS_MAX_EDGE_CELLS · 2 / ImageBuffer.w)` — max NDC displacement (2k at corners) maps linearly to pixels, guaranteeing edge distortion ≤ one terminal cell at any resolution (`LENS_MAX_EDGE_CELLS = 1.0`).
2. **Grain-induced tearing**: `DITHER_AMP 16 → 11`. At 16 the pre-cluster jitter splits flat surfaces into per-cell speckle clusters that re-randomize every frame — long thin features (lane lines, car pillars) appear chopped into shifting bands. 11 keeps visible ISO grain without shredding geometry.
3. **Stride-lock regression test**: new encoder test renders an image whose pixel value encodes its own x-coordinate and asserts each cell's lit-dot columns match the expected parity bits exactly — locks `pixel_x = cell_x*2`, `pixel_y = cell_y*4` forever.
4. **Near-field chunking — CONTINUOUS filtering (no depth branch)**: material sampling in the march averages two samples straddling the ray with `spread = clamp(FILTER_NEAR_K / fwd_d, FILTER_MIN_SPREAD, FILTER_MAX_SPREAD)` — constant angular footprint, mip-style, smooth everywhere (a hard `fwd_d < N` toggle would paint a seam across the road).
5. **Z-fighting — TERRAIN-ONLY DEPTH MARGIN (static Y-lift eradicated; bias isolated)**: a world-space lift is invalid on steep grades, and a universal rasterizer bias would corrupt mesh-vs-mesh sorting (a car 0.3 m behind another would bleed through). Instead `terrain.rs` writes `z = fwd_d + TERRAIN_DEPTH_MARGIN (0.30 m)` into the buffer — the voxel plane sits a fraction of a meter behind reality while meshes keep EXACT linear depths, so vehicles/signs sort precisely among themselves and still always clear the road.
6. **HUD width safety**: replace ambiguous-width bar glyphs `█/░` with ASCII `#/.` so CJK-wide terminals can't shift HUD rows.

### Playtest fixes round 3 (M0.2 — THE tearing bug + encoder overhaul)
1. **SEV-1 — `MoveTo` off-by-one (the actual tearing bug, found by inspection):** `TermDisplay::present` passed `MoveTo(cx+1, cy+1)`, but crossterm's `MoveTo` is **0-based** (it emits `CSI row+1;col+1 H` internally). Every frame rendered one cell right + one row down; the last column wrapped to the next line and the bottom row wrapped off-screen, scrolling the alt screen continuously. That interleaving of stale and fresh rows IS the "hard discrete row-by-row lateral offsets" in the screenshot. **Fix:** `MoveTo(cx, cy)` verbatim + regression test asserting the first escape for cell (0,0) is exactly `\x1b[1;1H` (captured-writer test).
2. **Encoder overhaul — dots carry structure, background recedes (kills the mosaic):** the two-opaque-color k-means made every cell read as a solid color tile (bg dominance → green/red/gray mosaic). Replace with the terminal-video-player model:
   * `bg` = constant near-black `[8,8,10]` for every cell.
   * Mask: each dot's luma vs the cell MEAN luma (+ small per-frame threshold dither `DITHER_AMP` for gradient smoothing) — deterministic, spatially coherent; flat areas become uniform half-tone, edges snap.
   * `fg` = mean RGB of lit dots (fallback cell average); grain tints fg only, never the mask decision.
   * k-means removed from the CPU path entirely (simpler, coherent, faster).
3. **Horizon readability**: `FOG_DIST 470 → 620`; fog target mixed 50% toward `SKY_LOW` (slightly darker than sky) so mountain silhouettes separate; `SHADOW_MIN_LIGHT 0.42 → 0.50` (kills distant mud); PCF skipped (`factor = 1`) beyond 350 m.
4. **Near-field ease**: `CAM_PITCH_BASE −0.048`, preset-0 height `2.7 → 3.0` — pushes the most magnified ground out of frame.

### Playtest fixes round 4 (M0.3 — surface continuity + anti-aliasing)
1. **SEV-1 — dual-color quantization restored (static-black eradicated):** the static `[8,8,10]` bg stripped 50% of display payload — solid quads became floating dot clouds the eye cannot group. Encoder v3: per cell, `bg` = RGB of the MIN-luma sample (surface base), `fg` = RGB of the MAX-luma sample (surface highlight); structured mask thresholds at the min/max midpoint (+ temporal jitter); flat cells keep temporal coverage halftone with fg = mean of two brightest samples, bg = mean of two darkest. Ambient floor & detail boost unchanged. GPU fragment pass mirrors this exactly (min/max centroids, no k-means).
2. **Display/stride logic FROZEN:** zero changes to `display.rs`, buffer strides or index arithmetic — the 0-indexed `MoveTo(cx, cy)` mapping is verified correct by frame inspection.
3. **Sub-cell spatial filtering:** each dot's sample becomes a clamped 2×2 box average in image space (`box4`: own px + right/down neighbors, edge-clamped) BEFORE thresholding — single-pixel scanlines smear into their local area instead of aliasing into lone dots that flicker per cell.

### Playtest fixes round 5 (M0.4 — motion stability + off-road orientation)
1. **SEV-1 — rotation/vibration discipline:** off-road heave and speed vibration modify ONLY vertical translation `cam.y` — never the camera basis. `R_cam` receives smooth chassis pitch (slope+dive) and steering roll only; high-frequency jitter is banned from both the march and mesh matrices.
2. **Lens bypass during motion:** `LENS_K = 0.0` by default in TUI mode, AND the lens pass is skipped entirely whenever chassis vibration exceeds `SHAKE_BYPASS_M (0.01 m)` — discrete terminal cells cannot resolve non-linear radial curves while shaking.
3. **SEV-2 — road-edge contrast + recovery anchor:**
   * New bright shoulder-margin band (`PAL_SHOULDER_EDGE [168,164,152]`, ~0.25 m at |d| = ROAD_HALF+SHOULDER) baked into chunks — a continuous high-contrast border visible day/night.
   * HUD off-road navigator: persistent 8-way compass arrow + distance (m) pointing from the car to the nearest highway centerline point; drawn top-center whenever `player.offroad`.

### Playtest fixes round 6 (M0.5 — static readability + frustum integrity)
1. **SEV-1 — screen-space edge contours (static-frame readability)**: lightweight Sobel pass over the final `ImageBuffer.z` (sky/infinite skipped) BEFORE the lens: pixels where the **DISTANCE-NORMALIZED** gradient `|∇z| / (z_sample + ε)` exceeds `EDGE_DEPTH_GRAD` are forced toward bright contour luminance. Raw linear Δz grows with distance and would saturate far mountains while never triggering near-field road edges; normalization makes extraction scale-invariant across the frustum.
2. **SEV-2 — HUD header repair**: backend tag drawn explicitly at x=0 (`format!("[{backend}] …")`, ASCII `-` separators — no ambiguous-width glyphs), bounded writes asserted by a new unit test rendering the HUD into a grid and checking `[CPU]` glyphs occupy columns 0..4 of row 0.
3. **Static contrast boost**: when `player.kmh() < 1`, asphalt-family base colors multiply 1.25× and grass/dirt 0.85× inside `shade()` (≈1.5× contrast) so parked frames keep a readable road.
4. **Overscan bbox + edge-clamped resampling**: `overscan_dims` already uses the full rotated bounding box (`W′=⌈W·|cosθ|+H·|sinθ|⌉`, same for H′); `rotate_into` must additionally CLAMP rotated source coords to `[0,W′−1]/[0,H′−1]` returning edge pixels — never skip-and-zero-fill (kills any residual diagonal trapezoid under compound pitch+slope+roll).
5. **Minimap scissor viewport**: all minimap writes go through a panel-bounds guard (`MINIMAP_X/Y/W/H` derived top-right, border-inclusive); any blip/arrow outside the frame is rejected — nothing can bleed into the camera feed.
6. **Off-road roll normalization**: when `player.offroad`, roll target clamps to `min(ROLL_MAX, ROLL_OFFROAD_MAX (15°))` so frustum rotation stays within overscan capacity on bumpy ground.

(Also retained from round 5: rotation/vibration discipline — heave is Y-only, never in R_cam; `LENS_K` defaults 0.0 with shake-bypass; bright shoulder-edge band; off-road compass arrow.)

### Playtest fixes round 7 (M0.6 — diagnostics first + high-contrast stylized)
Facts locked in: braille glyphs render correctly in the user's environment for other tools ⇒ the problem is OUR pipeline output. Tearing STILL occurs post-MoveTo ⇒ an additional structural defect remains unfound. Therefore:
1. **SEV-1 — PPM frame-dump diagnostics (`--debug-frame=N`, key K)**: hand-rolled ~20-line P6 writer in `image.rs`; on trigger writes `frame_rgb.ppm` (raw pre-quantization buffer) and `frame_cells.txt` (ASCII art of the TermCell masks) — separates ENGINE-MATH bugs from TERMINAL-EMISSION bugs instantly. Serialization is LOCKED: `BufWriter::write_all(&self.rgb)` after a `P6\n{w} {h}\n255\n` header — zero-copy, byte-exact, no intermediate string allocations.
2. **SEV-1 — rotate_into out-of-bounds = SKY, never black, never edge-streak**: revert the `.clamp()` edge sampling added in M0.5 (it smeared border pixels into nauseating streaks during rotation); OOB rotated coords sample `sky_rgb()` with `z = INFINITY`.
3. **Vehicle solidity**: `Material.self_light` field — player/NPC bodies get `SELF_LIGHT (0.45)` additive so cars read as solid bright shapes instead of 15-dot clusters.
4. **Contrast masking**: Sobel contours restricted to near/mid-field (`z < EDGE_MAX_Z 220 m`) so flat grass never generates white-noise dots.
   * **SEV-2 NaN guard**: non-finite samples are filtered BEFORE subtraction in the edge pass — if the center or any neighbor fails `is_finite()`, the gradient magnitude is `0.0` (pure sky-to-sky boundaries produce no edge). No `∞ − ∞` NaN ever materializes in scalar passes (and none can poison future SIMD/WGSL lanes).
5. **High-contrast stylized palette + lighting**: asphalt `[30,30,34]`, shoulders `[120,118,112]`, paint `[255,255,250]`, grass vivid `[96,160,70]`/dark `[48,106,42]`/dry `[152,152,82]`, dirt `[142,106,64]`, rock `[148,144,136]`/light `[188,183,172]`; `AMBIENT 0.28`, `DIFFUSE 1.05` (clamped), exposure ×1.25 pre-fog; `EDGE_DEPTH_GRAD 0.18`, contour mix 85% white; `LUMA_FLOOR_COVERAGE 0.12`.
6. **SEV-2 — saturating clamps with self_light**: every final mesh pixel channel is `clamp(base·(lambert+specular)+self_light, 0, 255)` in f32 BEFORE the u8 cast — no truncation/color-inversion on lit bodies.
7. **SEV-2 — diagnostic dump isolation**: `--debug-frame=N` writes both files then `std::process::exit(0)` immediately (never resumes the loop); key-triggered (`K`) dumps spawn a detached `std::thread::spawn` writer so the frame budget is untouched.
8. **Sky-depth fog safety**: OOB rotated pixels carry `z = INFINITY`; verified that fog math never consumes them (sky drawn directly; `shade()` only runs on finite march hits; edge pass skips non-finite). Regression assert: encode/lens outputs contain no NaN-derived colors when the frame includes OOB-rotation margins.

### Playtest fixes round 8 (M0.7 — THE encoder fix: absolute-density mapping)
Evidence (from the user's own `/tmp/frame_rgb.ppm`, read directly): luma percentiles 5/25/50/75/95 = **49/63/74/125/193** — half the frame lives at luma 50–75, yet encoder v3's "structured" path (threshold vs cell min/max midpoint) renders every cell whose texture range exceeds ±12 at ~50% RANDOM coverage regardless of brightness. Bright grass, dark asphalt, sky — all became identical coin-flip noise. Density never encoded tone.
**Fix — encoder v4, one unified rule (delete the structured/flat split):**
* Per-dot: lit iff `L_i × EXPOSURE > noise01(i) × 255` where `EXPOSURE = 1.7` (const) and `noise01` is the temporally-offset blue-noise value ∈ [0,1).
* Consequences: flat bright (250→clamped) ≈ 100% dots; mid-gray 128×1.7≈218 → ~85%; dark asphalt 40×1.7≈68 → ~27% sparse; true black stays void. **Density finally encodes absolute tone**, so parked scenes read: dark road / mid grass / full sky — three distinct densities at v=0.
* Edges: adjacent different-tone cells get adjacent densities (structure free), Sobel contour pass remains for hard silhouettes.
* `fg` = mean RGB of lit dots; `bg` constant `[8,8,10]`; ambient floor kept (coverage floor for near-black cells); red/blue hue separation unchanged.
* Delete: min/max-midpoint branch, `FLAT_RANGE_EPS`. Reduce terrain mottle tex ±0.22 → ±0.15 (variance is now signal, not mud).
* Verification: re-dump a K-frame and re-run the percentile probe — target ground-band mean luma ≥ 110 and visibly distinct sky/horizon/ground bands in `frame_cells.txt`.

### Playtest fixes round 9 (M0.8 — kill the void: surfaces, not specks)
Root cause confirmed by frame_cells.txt: v4's constant near-black bg means any sub-threshold cell renders as empty black tiles — natural terrain disintegrates. Fix keeps the v4 density rule (density encodes tone) but restores SURFACE continuity:
1. **Material-aware background**: `bg` = RGB of the MIN-luma sample in the cell (darkest surface pixel), clamped channel-wise to a dimness ceiling of `[56,56,60]` so it never becomes a bright mosaic tile. Grass cells get dark-green fill, dirt dark-brown, asphalt near-black, sky its blue — unbroken planes at ANY dot density. (`BG_DARK` removed; k-means stays dead — min-sample ≠ clustering.)
2. **Natural-material luma lift**: palette albedos retuned so lit terrain lands in the 110–140 luma band (50–60% dot density): GRASS `[110,168,84]`, GRASS_DARK `[72,124,60]`, GRASS_DRY `[152,154,88]`, DIRT `[148,112,70]`, SAND `[214,198,152]`, ROCK `[152,149,142]`, ROCK_LIGHT `[192,187,177]`, SHOULDER `[118,116,112]`. Asphalt intentionally stays dark `[30,30,34]` for maximum road contrast.
3. **Material-boundary contours**: `edges.rs` gains a second trigger — per-pixel RGB jump vs the left neighbor (`Σ|Δchannel| > MAT_JUMP_THRESH 48`) with finite z — so asphalt↔shoulder↔grass borders draw bright contour dots even where depth gradients are gentle. Existing depth rule unchanged; display.rs/stride logic remains frozen.

### Playtest fixes round 10 (M0.9 — THE road-warp bug: angle-linear ray squeeze)
**Diagnosed by inspection of `camera.rs::march_ray`:** rays were computed as `tan((u−0.5)·FOV)` while the pinhole column mapping requires `(u−0.5)·ow/focal = (u−0.5)·2·tan(FOV/2)`. At frame edges those differ hugely (tan74°≈3.49 vs 1.51): each column painted geometry sampled from far-too-wide rays, bending straight roads into warped curves — worst at rest when there's no motion to mask it.
**Fix (partially applied; build currently RED pending one function):**
* `camera.rs`: replace `march_ray(u)` with `column_ray(col_f)` computing `tan_a = (col_f − center_x)/focal`, `dir = norm(fwd_u + right_u·tan_a)` — exact pinhole inverse, every column's samples project back onto themselves.
* `terrain.rs`: already updated to call `op.column_ray(col+0.5)`.
* Regression test `straight_road_stays_straight`: flat plane, for several columns verify the projected hit row/column round-trips within ±0.5 px.
* NOTE: crate does not compile until the camera.rs function swap lands.

### Physics (sim/car.rs, dt = 1/60 accumulator)
`speed += (throttle·ACCEL − drag·v² − roll·v − brake·BRAKE)·dt`; offroad adds `OFFROAD_DRAG` + caps speed; `heading += steer_smoothed · STEER_RATE · g(v) · dt · sign(v)` where `g(v) = clamp(v/12,0,1)·(1−0.55·v/MAX_SPEED)` (tight low, stable high); reverse steers inverted; Space = handbrake; soft circle collision vs traffic (pushback + mutual damping); clamps `[-MAX_REVERSE, MAX_SPEED]`.

### Traffic (sim/traffic.rs)
State `{hw, s, lane, dir, v, braking}`; IDM-lite leader gap keeping on straights; recycle beyond `RECYCLE_BEHIND/AHEAD` of the player → respawn ahead (constant density). Braking flag drives emissive brake quads.
**3-D junction traversal (SEV-2 fix):** when an NPC's path enters a junction zone it switches to a **cubic Bézier turn arc** from entry point+tangent to exit point+tangent (same-road arcs pass straight through), height-evaluated via O(1) bilinear lookups on the junction height grid. Orientation (yaw/pitch) derives from the grid surface normal ⊗ velocity direction — continuous kinematics, no orientation snapping or terrain clipping while turning across sloped junctions.

### Chase camera (render/camera.rs) — mounted-camera realism
- Spring-follow position behind the car; presets cycled with `C`.
- **Slope-tracking pitch (fix):** weight-transfer pitch is ADDED to terrain slope — sample `height_at` one car-length ahead and behind along the heading, `slope = (h_ahead − h_behind).atan2(2·LOOK)`, blended by `SLOPE_PITCH_GAIN` into the target pitch. Climbing tilts the camera up; descending down — the car stays framed instead of staring into dirt/sky.
- **Chassis dynamics:** braking/throttle dive via `long_accel`; heave/vibration from offroad + speed.
- **Roll via 3-stage pipeline:** terrain marches roll-free into the overscanned `TerrainBuffer` (rotated-bbox coverage), RGB+z bilinear-rotated into the final frame; meshes rasterize through the full rolled matrix directly.
- **Isotropic projection:** NO aspect scalar in camera focal; `CELL_ASPECT` applies once inside `braille.rs`.
- **Slope-proof clearance:** no world-space lift (invalid on grades — clearance shrinks by cos θ). Meshes sit exactly on `height_at` with exact depths; the terrain writes `+TERRAIN_DEPTH_MARGIN` so meshes draw over the voxel plane at any slope without corrupting mesh-vs-mesh sorting.

### Input (app.rs, own keybindings — zero WM coupling)
Arrows/WASD drive, Space handbrake, C cam cycle, M minimap, H HUD, P/Esc pause, Q or Ctrl-C quit. Single const keymap table.
Enable `KeyboardEnhancementFlags::REPORT_ALL_KEYS_AS_ESCAPE_CODES | REPORT_EVENT_TYPES` when `supports_keyboard_enhancement()` → true Press/Repeat/**Release**; held = down-until-release.
**Fallback state machine (SEV-2 fix):** on terminals without release events, `FALLBACK_HELD_TIMEOUT_MS = 600` (> worst-case OS initial repeat delay of 250–500 ms). `Press` → Active + timestamp; each `Repeat` refreshes the timestamp; only `now − last_event > 600 ms` marks Released. No mid-hold dropouts before auto-repeat begins.

## Performance Budget
**GPU path:** shadow map + forward pass + quantization fragment pass all run in parallel on hardware; CPU cost per frame is one async readback of 4,800 cells + the terminal diff/emit → 60 fps comfortably. **CPU path:** terrain stays **O(W′ × steps)** over the overscanned rotated-bbox width W′ ≤ W/cos(ROLL_MAX) (~+15% at 30° roll): ~55–60 k height samples/frame (+1 z-store each; true-3-D pitch rays keep this pitch-independent) — never per-pixel marching; rayon splits the frame into horizontal bands across cores; SIMD (`wide`) accelerates scanline fills and the 4,800-cell threshold pass. Terrain rotation + lens pass: two full-frame bilinear resamples via reverse-map LUTs.

## Risks
Font aspect variance handled once in `braille.rs` (`CELL_ASPECT` sampled at encode — 3-D pipeline stays isotropic) · slow debug builds (document `--release`) · weak braille-font terminals (noted in help) · Windows key repeat differences (600 ms heartbeat covers) · junction **explicit height grids** are cheap to query but must bake consistently per junction — deterministic world-coord baking + continuity tests · roll overscan widens the march by ≤1/cos(`ROLL_MAX`) and adds one bilinear rotation pass — bounded, skipped under `ROLL_EPS` · shadows are strictly forward (march/mesh-vertex PCF vs the sun map) — no z-buffer reconstruction exists to corrupt · **pipeline order is fixed: collect casters → sun-depth map → sky/march (forward PCF in shade) → rotate → meshes (forward PCF) → lens → encode** (lens is physical and last; z-buffer never reconstructed) · fidelity layers (F1–F4) strictly tiered so any layer can ship independently or be toggled off if the frame budget slips · shadow-map acne handled with a normal-offset bias const · blue-noise table generated procedurally at startup; grain randomized per frame via offset — no static-pattern risk · **wgpu** is a heavy, fast-churning dependency — isolated behind feature `gpu` (off by default for tests/CI), pinned version, hardware-enforced adapter request so VMs/software GL never take the GPU path · readback latency adds ≤1 frame on GPU — acceptable at 60 fps · `std::simd` is nightly → portable **`wide`** crate instead · rayon thread pool created once (no per-frame spawn).
