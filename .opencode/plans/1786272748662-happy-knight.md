# Plan: Emulator "History Pull-Down" on vertical grow (vendored `term-wm-vt100` fork)

## Problem
On a vertical **grow**, `Grid::set_size` (rows-only path, grid.rs:85) appends blank rows at
the bottom and leaves the cursor/prompt stranded mid-screen. When that blank region later
scrolls, it appears as blank space between prompts (worst in monocle, where the FAB
content-dodging reservation / height-only resizes fire repeatedly). The scroll-sync `resized`
fix (already committed in `TerminalComponent`) keeps the scrollbar thumb pinned; this change
fixes the **content** so the prompt stays bottom-anchored instead of leaving a blank gap.

Structural facts (verified):
- `Grid.rows` is `Vec<Row>`; `Grid.scrollback` is `VecDeque<Row>`; cursor `pos`/`saved_pos`
  live on `Grid` (not `Screen`). `Screen` owns two `Grid`s; the alternate is built with
  `scrollback_len: 0` (screen.rs:82), so its `scrollback` is always empty.
- `Grid.scrollback_offset` (grid.rs:15) tracks the viewport's distance from the tail.

## Change: `Grid::set_size` (grid.rs:71-104), before the blank-padding resize at line 85
On vertical **grow** while **following the tail** (`scrollback_offset == 0`), pull the most
recent scrollback rows into the top of the grid and shift the cursor down — mirroring the
shrink path's `ESC[S` scroll-up (which parks the cursor at the bottom). Insertion:

```rust
let old_rows = self.size.rows;
let new_rows = size.rows;
// ... existing scroll_bottom fix-up ...
self.size = size;

// History pull-down on vertical grow: reveal history at the top instead of
// padding blank rows at the bottom, keeping the cursor/prompt bottom-anchored.
// Alt screen auto-bypasses: its scrollback is always empty.
if new_rows > old_rows
    && self.scrollback_offset == 0
    && !self.scrollback.is_empty()
{
    let pull = usize::from(new_rows - old_rows).min(self.scrollback.len());
    // split_off preserves chronological order (the tail of the scrollback is the
    // most recent history, adjacent to the old grid's first row). Note: a naive
    // `pop_back()` loop would yield these rows newest→oldest and display the
    // revealed history upside-down — do NOT use it.
    let split_at = self.scrollback.len() - pull;
    let pulled: Vec<_> = self.scrollback.split_off(split_at).into_iter().collect();
    self.rows.splice(0..0, pulled); // O(n) front-splice; moves, not clones
    self.pos.row = self.pos.row.saturating_add(pull as u16);
    self.saved_pos.row = self.saved_pos.row.saturating_add(pull as u16);
}
```

Then the existing `for row in &mut self.rows { row.resize(...) }` + `self.rows.resize(new_rows)`
run normally: with `pull == delta` the grid is exactly `new_rows` tall (no blanks); with
insufficient history (`pull < delta`) the remainder pads blanks below the cursor, which is
the best possible (no history to reveal). The subsequent `row_clamp_*`/`col_clamp` and the
`saved_pos` clamps (lines 94-103) keep cursor/saved-cursor in bounds.

Guards/rationale:
- `scrollback_offset == 0` → only re-anchor when the user is at the tail; a scrolled-up view
  keeps the existing top-anchored grow (safe, and the bug is a tail-follow scenario).
- Empty scrollback (incl. alternate grid) → no-op, preserves current behavior.
- Rows-only path only: a combined width+height resize still routes to `reflow` (grid.rs:72-74),
  which already re-anchors the cursor line to the bottom on tail-follow.

## Tests (in `/Volumes/2TB Storage Vault/term-wm-vt100/src/grid.rs` `#[cfg(test)]`)
- `grow_pulls_history_into_grid`: build a grid, create scrollback (via `screen.su` /
  `Grid::scroll_up`), grow rows by N (`< scrollback.len()`); assert the top N grid rows equal
  the pulled history, the grid has no blank gap at the bottom, and `pos.row` moved down by N.
- `grow_without_scrollback_pads_blanks`: no scrollback → grow → rows padded with blanks, cursor
  unchanged (existing behavior preserved).
- `grow_pull_is_bounded_by_history`: grow by more than scrollback length → only `scrollback.len()`
  rows pulled, remainder blank.
- `scrolled_up_grow_does_not_pull`: set `scrollback_offset > 0` → grow → no pull (top-anchored).
- Alt-screen parity: `screen.set_size` on an empty-scrollback grid is already covered by
  `grow_without_scrollback_pads_blanks` (alternate grid = empty scrollback).
