# Plan: Debounce the FAB content-dodging reservation (stop resize churn in cramped monocle)

## Problem
Resizing a terminal window in cramped monocle "can add a ton of space between terminal
prompts." The user confirms typing does not change window height — it is purely the
**window resize**.

### Root cause: a resize→flag→resize feedback loop
In cramped monocle the focused window fills the screen, and the FAB content-dodging
reservation shrinks `managed_area` by 1 row while the app draws content under the FAB's
bottom-right footprint (`bottom_content` flag, consumed next frame in
`register_managed_layout`). Resizing the window triggers:

1. Window/screen size changes → `TerminalComponent::render` resize guard
   (`crates/term-wm-ui-components/src/terminal.rs:236-246`) → `Pty::resize`
   (`crates/term-wm-pty-engine/src/pty.rs:406-451`) → vt100 `set_size` reflow.
2. The reflow changes the grid's bottom-right row → the render pass recomputes
   `bottom_content` (`src/lib.rs` detection) → flag flips.
3. Next frame `register_managed_layout` (`layout.rs`, `apply_padding =
   is_monocle_cramped() && has_bottom_content()`) changes `managed_area` height by ±1 →
   another PTY resize → another reflow → flag can flip back → oscillation.

Each grow appends blank rows at the grid bottom without re-anchoring the cursor, so the
oscillation accumulates blank rows between prompts. The flag is currently set/cleared
immediately every frame (`WindowManager::set_bottom_content_flag`, mod.rs:971-973), giving
the loop no damping.

## Fix: trailing-edge debounce on the reservation flag
Hold the reservation for a short debounce window after the footprint clears, so the height
does not flip-flop during a resize. During a drag the flag stays latched once tripped,
breaking the feedback loop; a single settled resize still applies cleanly.

### Changes
1. `crates/term-wm-core/src/constants.rs`
   - Add a named const (AGENTS.md magic-constant rule):
     ```rust
     /// How long the FAB bottom-row reservation is held after the app's content
     /// clears the FAB footprint, so resize-driven reflow cannot oscillate the
     /// window height (and thus resize the PTY) frame-to-frame.
     pub const FAB_RESERVATION_DEBOUNCE: Duration = Duration::from_millis(250);
     ```
     (`Duration` is already used in this file.)
2. **New reusable type** `crates/term-wm-core/src/utils/debounce.rs`, exported from
   `utils/mod.rs`. Encapsulates the asymmetric (instant-`true`, delayed-`false`) debounce so
   the `WindowManager` stays free of timer/state-machine boilerplate:
   ```rust
   use std::time::{Duration, Instant};

   /// A boolean that turns on instantly but releases `false` only after `delay`
   /// has elapsed since the last `true` input. Used for layout flags whose rapid
   /// toggling would otherwise cause resize churn (e.g. the FAB bottom-row
   /// reservation). `set(false)` arms a one-shot timer that is NOT re-fed by
   /// repeated clears, so it always expires; `get()` is the time-aware read.
   #[derive(Debug, Clone)]
   pub struct DelayedReleaseBool {
       state: bool,
       delay: Duration,
       release_at: Option<Instant>,
   }

   impl DelayedReleaseBool {
       pub fn new(delay: Duration) -> Self {
           Self { state: false, delay, release_at: None }
       }

       pub fn set(&mut self, value: bool) {
           if value {
               self.state = true;
               self.release_at = None;
           } else if self.state {
               if let Some(at) = self.release_at {
                   if Instant::now() >= at {
                       self.state = false;
                       self.release_at = None;
                   }
               } else {
                   self.release_at = Some(Instant::now() + self.delay);
               }
           }
       }

       pub fn get(&self) -> bool {
           if !self.state {
               return false;
           }
           match self.release_at {
               Some(at) => Instant::now() < at,
               None => true,
           }
       }
   }
   ```
   `get()` acting as a time-aware read doubles as an expiry backstop even if `set(false)` is
   not called every frame.
3. `crates/term-wm-core/src/window/window_manager/mod.rs` — replace the two raw fields
   (`bottom_content: bool`, `bottom_content_debounce_until: Option<Instant>`) with a single
   encapsulated field:
   ```rust
   /// Delayed-release flag for the FAB bottom-row reservation (see `DelayedReleaseBool`).
   bottom_content: DelayedReleaseBool,
   ```
   initialized `DelayedReleaseBool::new(crate::constants::FAB_RESERVATION_DEBOUNCE)`. The
   accessors become thin delegates:
   ```rust
   pub fn set_bottom_content_flag(&mut self, has: bool) {
       self.bottom_content.set(has);
   }

   pub fn has_bottom_content(&self) -> bool {
       self.bottom_content.get()
   }
   ```
   The layout pass in `register_managed_layout` is unchanged
   (`is_monocle_cramped() && has_bottom_content()`). Semantics preserved: `true` applies
   immediately; a `false` holds the reservation for `FAB_RESERVATION_DEBOUNCE` measured from
   the first clear, then drops; the non-cramped `else` branch's `set_bottom_content_flag(false)`
   merely lets the timer run out (and the `is_monocle_cramped()` gate already prevents padding).

### Tests
- **Unit tests in `crates/term-wm-core/src/utils/debounce.rs`** (`DelayedReleaseBool`, no
  `WindowManager` dependency — decoupled timer testing):
  - defaults `false`; `set(true)` → `get()` true.
  - `set(false)` after `true` → `get()` still true (within delay).
  - repeated `set(false)` calls do NOT extend the timer (no watchdog refeed).
  - after `sleep(delay + small)` → `get()` false; a further `set(false)` stays false.
  - `set(true)` after a held `false` re-arms immediately.
- **`window/window_manager/mod.rs`**: drop the now-redundant inline flag tests
  (`bottom_content_flag_defaults_false_and_toggles`, `bottom_content_flag_trailing_edge_...`,
  `bottom_content_flag_re_arms_...`) since the logic moved to `DelayedReleaseBool`. Keep the
  reservation tests (`cramped_monocle_reserves_fab_bottom_row` etc.), which exercise the
  accessor end-to-end and are unaffected.
