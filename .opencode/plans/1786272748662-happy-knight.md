# Plan: Bottom-anchor reflowed content when the cursor was at the bottom (vendored fork)

## Problem
A physical window drag changes BOTH width and height, so `Grid::set_size` routes to the
`reflow` path (grid.rs:72-74), bypassing the rows-only history pull-down. `reflow` bottom-
anchors the cursor **only when the re-wrapped content is at least as tall as the new screen**
(`hold = all_new.len() - new_rows > 0` ⇒ cursor at `new_rows - 1`, grid.rs:337-378). When the
content is **shorter** than the new screen (limited scrollback, or lines de-wrap on a width
grow), `hold = 0`, content is top-anchored, and blanks pad the bottom (grid.rs:417-421) —
the shell's SIGWINCH redraw then draws the prompt at the new bottom, stranding the old
prompt mid-screen in a sea of blanks (the reported "massive block of whitespace").

## Change: bottom-anchor short content in `Grid::reflow` (grid.rs)
Mirror the rows-only pull-down guard: only re-anchor when the cursor was resting on the old
bottom row AND the view was following the tail. Content already tall enough is unaffected
(it is already bottom-anchored). Otherwise pad blanks **above** the visible content so the
prompt stays at the new bottom.

In `reflow`, capture the cursor's old position (already available as `old_pos` / `old_rows`,
grid.rs:111-117), then adjust the assembly (grid.rs:416-421):

```rust
// ... existing cursor resolution + `self.pos`/`self.saved_pos` assignment ...

// Reassemble the scrollback and visible rows.
self.scrollback = all_new[..hold].to_vec().into();
let mut visible: Vec<crate::row::Row> = all_new[hold..].to_vec();

// Bottom-anchor short content: when the cursor was on the old bottom row and
// we were following the tail, keep the prompt at the new bottom by padding
// blanks ABOVE instead of leaving it stranded mid-screen with blanks below.
if old_scrollback_offset == 0
    && old_pos.row >= old_rows.saturating_sub(1)
    && visible.len() < usize::from(new_size.rows)
{
    let pad = usize::from(new_size.rows) - visible.len();
    let mut padded = Vec::with_capacity(usize::from(new_size.rows));
    padded.resize(pad, crate::row::Row::new(new_size.cols));
    padded.extend(visible);
    visible = padded;

    // Shift the resolved cursors down by exactly the rows added above, so they
    // stay pinned to the text they were sitting on (do NOT hardcode the absolute
    // bottom row — line de-wrapping can leave the cursor above the content end).
    let pad_u16 = u16::try_from(pad).unwrap_or(u16::MAX);
    self.pos.row = self.pos.row.saturating_add(pad_u16);
    self.saved_pos.row = self.saved_pos.row.saturating_add(pad_u16);
}

self.rows = visible;
while self.rows.len() < usize::from(new_size.rows) {
    self.rows.push(crate::row::Row::new(new_size.cols));
}
```

The `while` padding loop becomes a no-op in the bottom-anchored branch (we padded to exactly
`new_rows`); it stays for the existing top-anchored path. `saved_pos` is left to the existing
resolution/clamping (DECSC is rarely relevant in this tail-follow scenario). Scrolled-up views
(`old_scrollback_offset != 0`) and cursors not at the bottom keep the current behavior — a
fresh, mostly-empty terminal (prompt at top) still grows top-anchored.

## Test (`/Volumes/2TB Storage Vault/term-wm-vt100/tests/reflow.rs`)
- `grow_bottom_anchors_short_content_when_cursor_at_bottom`:
  ```rust
  let mut p = term_wm_vt100::Parser::new(3, 10, 100);
  p.process(b"a\r\nb\r\nc");               // cursor at bottom row (2), no scrollback
  assert_eq!(p.screen().cursor_position().0, 2);
  p.screen_mut().set_size(6, 12);          // width + height grow → reflow, short content
  assert_eq!(p.screen().cursor_position().0, 5, "prompt stays at the new bottom");
  assert_eq!(p.screen().cell(5, 0).unwrap().contents(), "c", "content contiguous at bottom");
  ```
  Fails before the fix (cursor would be at row 2, blanks below), passes after.
- Add `grow_top_anchors_when_cursor_not_at_bottom` to lock the standard behavior:
  move the cursor to row 0 (`\x1b[1;1H`) before the same grow → cursor stays at the
  content position (top-anchored, blanks below), unchanged by the patch.
