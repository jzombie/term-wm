# Plan: Debounce the FAB content-dodging reservation (stop resize churn in cramped monocle)

## Problem
Resizing a terminal window in cramped monocle "can add a ton of space between terminal
prompts." The user confirms typing does not change window height — it is purely the
**window resize**.

### Root cause: a resize→flag→resize feedback loop
In cramped monocle the focused window fills the screen, and the FAB content-dodging
reservation shrinks `managed_area` by 1 row while the app draws content under the FAB's
bottom-right footprint (`bottom_content` flag, consumed next frame in
`register_managed_layout`). Resizing the window triggers:

1. Window/screen size changes → `TerminalComponent::render` resize guard
   (`crates/term-wm-ui-components/src/terminal.rs:236-246`) → `Pty::resize`
   (`crates/term-wm-pty-engine/src/pty.rs:406-451`) → vt100 `set_size` reflow.
2. The reflow changes the grid's bottom-right row → the render pass recomputes
   `bottom_content` (`src/lib.rs` detection) → flag flips.
3. Next frame `register_managed_layout` (`layout.rs`, `apply_padding =
   is_monocle_cramped() && has_bottom_content()`) changes `managed_area` height by ±1 →
   another PTY resize → another reflow → flag can flip back → oscillation.

Each grow appends blank rows at the grid bottom without re-anchoring the cursor, so the
oscillation accumulates blank rows between prompts. The flag is currently set/cleared
immediately every frame (`WindowManager::set_bottom_content_flag`, mod.rs:971-973), giving
the loop no damping.

## Fix: trailing-edge debounce on the reservation flag
Hold the reservation for a short debounce window after the footprint clears, so the height
does not flip-flop during a resize. During a drag the flag stays latched once tripped,
breaking the feedback loop; a single settled resize still applies cleanly.

### Changes
1. `crates/term-wm-core/src/constants.rs`
   - Add a named const (AGENTS.md magic-constant rule):
     ```rust
     /// How long the FAB bottom-row reservation is held after the app's content
     /// clears the FAB footprint, so resize-driven reflow cannot oscillate the
     /// window height (and thus resize the PTY) frame-to-frame.
     pub const FAB_RESERVATION_DEBOUNCE: Duration = Duration::from_millis(250);
     ```
     (`Duration` is already used in this file.)
2. `crates/term-wm-core/src/window/window_manager/mod.rs`
   - Add a field next to `bottom_content` (init `None` in `with_config`):
     ```rust
     /// When the reservation flag may next drop to false after a clear.
     bottom_content_debounce_until: Option<Instant>,
     ```
     (`Instant` is already imported — `tab_outline_until` uses it.)
   - Replace `set_bottom_content_flag` / `has_bottom_content` (mod.rs:962-973). The timer
     is armed only on the **first** frame without content (not re-fed every frame — that
     would keep it alive forever), and the flag is finalized to `false` once the timer
     expires:
     ```rust
     /// Record whether the app draws content under the FAB's footprint. A clear
     /// (false) is trailing-edge debounced by `FAB_RESERVATION_DEBOUNCE` so the
     /// window height (and PTY) does not oscillate when a resize reflow briefly
     /// changes the bottom-right footprint content. The timer is armed only on
     /// the first no-content frame, so it always expires after the debounce.
     pub fn set_bottom_content_flag(&mut self, has: bool) {
         if has {
             self.bottom_content = true;
             self.bottom_content_debounce_until = None;
         } else if self.bottom_content {
             if let Some(until) = self.bottom_content_debounce_until {
                 if Instant::now() >= until {
                     // Debounce elapsed: finalize the clear.
                     self.bottom_content = false;
                     self.bottom_content_debounce_until = None;
                 }
             } else {
                 // First frame without content: start the debounce timer.
                 self.bottom_content_debounce_until =
                     Some(Instant::now() + crate::constants::FAB_RESERVATION_DEBOUNCE);
             }
         }
     }

     pub fn has_bottom_content(&self) -> bool {
         if !self.bottom_content {
             return false;
         }
         match self.bottom_content_debounce_until {
             Some(until) => Instant::now() < until,
             None => true,
         }
     }
     ```
     `has_bottom_content` stays pure (`&self`, reads `Instant::now()` cheaply) and acts as a
     backstop expiry check even if `set_bottom_content_flag` is not called every frame; the
     layout pass in `register_managed_layout` is unchanged (`is_monocle_cramped() &&
     has_bottom_content()`).
   - Semantics preserved: a `true` set takes effect immediately (reserve as soon as content
     would collide); a `false` keeps reserving for a fixed debounce window measured from the
     **first** clear (subsequent `false` frames do not extend it), then drops; the
     non-cramped `else` branch's `set_bottom_content_flag(false)` merely lets the timer run
     out, and the `is_monocle_cramped()` gate already prevents padding there.
3. Update the doc comment on `has_bottom_content` / `set_bottom_content_flag` (currently
   says "Cleared by the render pass whenever cramped monocle is inactive") to reflect the
   debounce.

### Tests (`crates/term-wm-core/src/window/window_manager/mod.rs` tests)
- Update `bottom_content_flag_defaults_false_and_toggles` (mod.rs:3250-3262): after
  `set_bottom_content_flag(true)` then `set_bottom_content_flag(false)`,
  `has_bottom_content()` is still `true` (debounce holds) — adjust the existing assertion.
- Add `bottom_content_flag_trailing_edge_debounce_holds`:
  - `set(true)` → `has()` true; `set(false)` → `has()` still true (within debounce).
  - `std::thread::sleep(FAB_RESERVATION_DEBOUNCE + 100ms)` → `has()` false.
  - A further `set(false)` stays false (no re-arm).
- Add `bottom_content_flag_re_arms_on_content`:
  - `set(true)`, `set(false)` (held), `set(true)` → `has()` true immediately (debounce
    cleared).
- Existing reservation tests (`cramped_monocle_reserves_fab_bottom_row` etc.) set the flag
  `true` and are unaffected.
