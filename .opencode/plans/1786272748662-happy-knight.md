# Plan: Fix coverage hang in `connection_error_is_printed_to_stderr`

## Problem

`crates/term-session/tests/daemon_tests.rs` — `connection_error_is_printed_to_stderr`
(test starts at line 867) hangs for 60+ seconds under coverage reporting.

### Root cause (orphaned thread leak)
The test spawns an `acceptor` thread that runs an **infinite** `while let Ok(mut stream) =
listener.accept()` loop (line 882). At the end of the test, `drop(acceptor);` (line 904)
drops the `JoinHandle`, which in Rust only **detaches** the thread — it does not stop it.
The thread stays blocked forever on `accept()`.

The child `term-session` process itself fails fast (muxio decodes the garbage and the
`Attach`/`Spawn` RPC errors → `main` prints a diagnostic and exits non-zero), so
`Command::output()` returns and the test body completes. The leaked thread is what blocks
coverage tooling: coverage runners track spawned threads and wait for them to finish before
finalizing data, so the process never exits. A plain `cargo test` harness ignores the leaked
thread, which is why the hang only shows up in coverage reporting.

### Fix (per review directives — stop-flag + non-blocking loop, preserving test fidelity)
Keep the continuous `accept()` loop so the client's real RPC connection still receives the
garbage bytes (exercising the muxio decode path — the whole point of the test) but make the
loop **stoppable** so the thread always exits and is `join()`ed (no leaked thread to block
coverage finalization).

In `crates/term-session/tests/daemon_tests.rs`:
1. **Update the interprocess import** (line 868) to add `ListenerNonblockingMode` (it is
   re-exported at `local_socket::ListenerNonblockingMode`; it is NOT in the `prelude`):
   ```rust
   use interprocess::local_socket::{
       GenericNamespaced, ListenerNonblockingMode, ListenerOptions, ToNsName, prelude::*,
   };
   ```
2. **Set the listener to non-blocking accept mode.** interprocess 2.4.3's
   `set_nonblocking` takes a `ListenerNonblockingMode` enum (NOT a `bool`):
   `ListenerNonblockingMode::Accept` makes `accept()` return `io::ErrorKind::WouldBlock`
   when no client is waiting. Add `std::sync::atomic` / `std::time::Duration` imports.
3. **Replace the acceptor setup** (lines 876-886) with a stop-flag-controlled loop:
   ```rust
   let stop_flag = Arc::new(AtomicBool::new(false));
   let stop_clone = stop_flag.clone();
   let mut listener = ListenerOptions::new()
       .name(name)
       .try_overwrite(true)
       .create_sync()
       .expect("bind dummy gateway");
   listener
       .set_nonblocking(ListenerNonblockingMode::Accept)
       .expect("set nonblocking");

   let acceptor = std::thread::spawn(move || {
       while !stop_clone.load(Ordering::Relaxed) {
           match listener.accept() {
               Ok(mut stream) => {
                   // Garbage + close: muxio decode fails rather than silently EOF.
                   let _ = stream.write_all(b"not-a-muxio-frame");
               }
               Err(e) if e.kind() == std::io::ErrorKind::WouldBlock => {
                   std::thread::sleep(Duration::from_millis(10));
               }
               Err(_) => break,
           }
       }
   });
   ```
   The child connects exactly twice (probe, then the RPC client); the loop feeds garbage
   to **both**, so the RPC connection's decode failure is exercised (test fidelity
   preserved). Non-`WouldBlock` errors break out (e.g. listener torn down).
4. **Stop and join the thread** — replace `drop(acceptor);` (line 904) with:
   ```rust
   // Signal the acceptor to stop, then wait for it to exit so no leaked thread
   // survives to block coverage instrumentation at process exit.
   stop_flag.store(true, Ordering::Relaxed);
   acceptor.join().expect("acceptor thread failed");
   ```

### Behavior after the fix
- The client's RPC connection is accepted and fed garbage → muxio decode error → client
  prints a diagnostic and exits non-zero (the exact path the test was written for).
- The acceptor thread exits on the stop flag within one 10 ms poll cycle and is `join()`ed —
  no thread outlives the test, so coverage finalization is not blocked. Not brittle to the
  client's connection count: if the client connects more or fewer times, the loop either
  keeps poisoning connections or spins on `WouldBlock` until the flag is raised.
