# Plan: Fix History Pull-Down to only trigger when the cursor is at the bottom

## Problem
The History Pull-Down (just implemented in the vendored fork's `Grid::set_size`) triggers on
**every** vertical grow with non-empty scrollback. In a mostly-empty terminal the cursor sits
near the top, so growing prepends history/blanks above the active prompt and shoves the
cursor down. On the next shrink, the emulator scrolls up to keep the prompt visible, pushing
those blanks into scrollback; the next grow pulls them back out — an **infinite
blank-multiplication loop** across grow/shrink oscillations (worst during monocle resize
churn).

Standard terminal behavior is to leave the cursor alone and pad blanks at the bottom when
the cursor is not at the bottom edge. History pull-down should only run when the cursor is
already resting on the absolute bottom row of the old grid.

## Change: guard pull-down on cursor-at-bottom
In `/Volumes/2TB Storage Vault/term-wm-vt100/src/grid.rs`, `Grid::set_size`, add
`&& self.pos.row >= old_rows.saturating_sub(1)` to the existing guard:

```rust
if new_rows > old_rows
    && self.scrollback_offset == 0
    && !self.scrollback.is_empty()
    && self.pos.row >= old_rows.saturating_sub(1) // only pull if at the bottom edge
{
    let pull = usize::from(new_rows - old_rows).min(self.scrollback.len());
    let split_at = self.scrollback.len() - pull;
    let pulled: Vec<_> = self.scrollback.split_off(split_at).into_iter().collect();
    self.rows.splice(0..0, pulled);
    let pull_u16 = u16::try_from(pull).unwrap_or(u16::MAX);
    self.pos.row = self.pos.row.saturating_add(pull_u16);
    self.saved_pos.row = self.saved_pos.row.saturating_add(pull_u16);
}
```

Cursor elsewhere → the grid simply expands downward (blanks padded at bottom), which is the
correct behavior and breaks the blank-multiplication loop.
