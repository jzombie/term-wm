# Plan: Auto-offset the monocle FAB when the app has bottom-row content

## Problem

In monocle mode the term-wm FAB renders at the absolute bottom-right of the screen
(`crates/term-wm-sys-ui-components/src/wm_fab.rs`). When the focused app draws content
on the bottom row — a full-width status line (opencode's bottom border, tmux, vim) —
the FAB overlaps it. We want to reliably detect whether the app has content on the
bottom row and, if so, lift the FAB up one row.

## Feasibility (confirmed by exploration)

Yes, reliably. The FAB renders **after** the window compositing loop into the **same
shared ratatui frame buffer**:

- Window loop → `composite_window` blits each window's offscreen buffer into the main
  buffer (`crates/term-wm-console/src/draw_plan_renderer.rs:1095-1104`).
- FAB renders afterward (`src/lib.rs:255-271` → `WmFabComponent::render`,
  `wm_fab.rs:55-99`), so by then the main buffer already holds the app's final
  bottom-row pixels.
- In cramped monocle the window `dest` fills the full area and `show_borders: false`,
  so the app's last visible row == the screen's bottom row. Panels claim zero space in
  cramped monocle (`layout.rs:319`, `mod.rs:2376-2384`), so nothing else pollutes the
  bottom row before the FAB. The cursor overlay renders *after* the FAB, so the cursor
  can't cause false positives.

Detection pattern already exists in production: `!cell.symbol().starts_with(' ')`
(`draw_plan_renderer.rs:645`, `:954`, `:1369-1376`).

## Reliability caveats (document in code comment)

- The buffer is freshly re-created every frame (`Buffer::empty` in
  `console_render_target.rs:185-199`), so no stale FAB label pollutes detection.
- A status line rendered purely as background-colored spaces with no glyph would not be
  detected by a symbol-only check; this is rare and consistent with existing
  convention. Symbol check matches repo convention — keep it.
- Wide-char continuations render as `' '`; the leading half still has a real symbol on
  the same row, so whole-row detection still triggers.

## Changes (all in `crates/term-wm-sys-ui-components/src/wm_fab.rs`)

### 1. Add a named const (AGENTS.md magic-numbers rule)
```rust
/// Rows to lift the FAB when the app draws content on the bottom row.
const FAB_LIFT_OFFSET: i32 = 1;
```

### 2. Add a detection helper (private fn)
```rust
/// True if any cell on the given screen row (clipped to the buffer) has a
/// non-space symbol. Reads the shared frame buffer AFTER window compositing,
/// so it reflects exactly what the app drew.
fn bottom_row_has_content(buffer: &ratatui::buffer::Buffer, area: LayoutRect, y: i32) -> bool {
    if y < 0 {
        return false;
    }
    let x_start = area.x.max(0) as u16;
    let x_end = (area.x + i32::from(area.width))
        .min(i32::from(buffer.area.width))
        .max(0) as u16;
    (x_start..x_end).any(|x| {
        buffer
            .cell((x, y as u16))
            .is_some_and(|c| !c.symbol().starts_with(' '))
    })
}
```
(Exact shape can be adjusted; must use saturating/clamped arithmetic per AGENTS.md.)

### 3. Modify `render` (wm_fab.rs:55-99)
After computing `label`/`width` and **before** setting `self.fab_rect`:
- `let ratatui_backend = downcast_ratatui(backend);` (move this call earlier)
- `let bottom_y = area.y + i32::from(area.height).saturating_sub(1);`
- `let content = bottom_row_has_content(&ratatui_backend.buffer, area, bottom_y);`
- Set `y` to:
  - `bottom_y` when `content == false`
  - `area.y + i32::from(area.height).saturating_sub(1 + FAB_LIFT_OFFSET)` when true
  - `saturating_sub` guarantees no underflow when `area.height == 1`.
- Add a brief comment explaining why (the buffer already contains the composited app
  content at this point in the render order).
- Keep the rest unchanged (hitbox registration uses the lifted `fab_rect` automatically,
  so the tap target moves with the label).

Note: borrows are sequential — read cells into a `bool` first, drop the immutable
borrow, then call `safe_set_string(buffer, ...)`.

### 4. Tests (wm_fab.rs `mod tests`)
Existing tests use an empty buffer and already assert `y == 23` / `y == 2` — they stay
green because an empty bottom row triggers no offset. Add:
- `fab_lifts_when_bottom_row_has_content`: pre-write a glyph (e.g.
  `backend.buffer.cell_mut((40, 23)).set_symbol("x")`), render on an 80×24 area, assert
  `fab_rect().y == 22` and the label is drawn on row 22 (hitbox moved too).
- `fab_stays_on_bottom_row_when_only_other_rows_have_content`: pre-write content on row
  0 only, assert `y == 23`.
- `fab_lifts_does_not_underflow_tiny_area`: 1-row-tall area with content, assert the
  rect stays within the area (saturating behavior).
