# Plan: Fix Window Title Truncation Without Ellipsis

## Root Cause

Window titles in the **top panel** (`wm_top_panel.rs`) are truncated using `truncate_to_width` which removes characters beyond the max width **without** appending ellipsis (`…`). This makes it impossible to tell when a title has been cut off.

Additionally, the **session manager** overlay (`wm_session_manager.rs`) does its own manual truncation using byte-index slicing (`&title[..n]`), which is both buggy (can panic on multi-byte UTF-8) and uses `...` (three dots) instead of the proper `…` (U+2026) character used elsewhere.

## Changes

### 1. `crates/term-wm-sys-ui-components/src/wm_top_panel.rs`
- **Line 15:** Change import from `truncate_to_width` to `truncate_with_ellipsis`
- **Lines 228-229:** Replace `truncate_to_width(&label, max_label)` with `truncate_with_ellipsis(&label, max_label)`

### 2. `crates/term-wm-sys-ui-components/src/wm_session_manager.rs`
- **Add import** of `truncate_with_ellipsis` from `term_wm_core::utils`
- **Lines 133-140:** Replace manual byte-slicing truncation with `truncate_with_ellipsis(&title, max_width as usize)`. Remove the `title_width` variable and the if-else — `truncate_with_ellipsis` handles the non-truncated case internally.

### 3. `crates/term-wm-ui-components/src/menu.rs`
- **Line 244:** Replace `.chars().take(inner_width as usize)` with `truncate_with_ellipsis(&line, inner_width as usize)`. This fixes both the missing ellipsis and the incorrect Unicode-scalar-count truncation that could overflow menu borders with wide characters.
- **Add import** of `truncate_with_ellipsis` from `term_wm_core::utils`.
