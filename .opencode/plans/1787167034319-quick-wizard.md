# Implementation Plan: Session Notifications via Centralized NotificationBus (Final)

**GitHub Issue:** #274

## Why previous attempts failed
- Distributed `pending_workspace_entry` + `viewer_ack_received` + `AckViewerAttached` state machine coupled toast delivery to socket maps; every fix added a flag and still dropped when `Ack` raced `Subscribe` or `internal_wm_caller` was `None`.
- `OnUserConnected` to `chan.clients` (viewer passthrough) → invisible.
- `refresh_user_cache()` never wired, palette never showed users.
- `runner` drained only in `Some(event)` branch.

## Architecture — Centralized, no wire for workspace toasts
- `ChannelState` has no `pending`/`ack` — server does not generate workspace toasts via wire. `OnWorkspaceEntered`/`OnNotification`/`AckViewerAttached` are **deleted** from wire.
- `NotificationBus` (`crates/term-wm-core/src/notification.rs` extended) is pure `VecDeque<Toast { id, message, expires_at }>` with `push(msg, ttl)` + `tick(now)` called at top of `runner` loop. No `TaskScheduler` guard, no `pending_notifications` buffer.
- Workspace entry toast is **fire-and-forget local** in TUI client: `App::handle_custom_action(RebindWorkspace)` on `Ok` and `main.rs` spawned task after `SubscribeInternalInput` success directly call `wm.push_notification(format!("Workspace {ws}"), 3s)` on the local `WindowManager` (the destination workspace's `TermWmApp` for `Subscribe`, the source's `TermWmApp` for `Rebind` — but `Rebind`'s local push is in the source process, so we instead push in the **target's** next `Subscribe` or in the client's `Ack` path? No — for `Rebind` to existing, the toast must be pushed in the **target's** `TermWmApp`, not the source. So `Rebind`'s local push is wrong. Correct is: `Rebind` success in source does **not** push locally; the target's `TermWmApp` will push when its next `Subscribe` or when its `UserCacheRefreshed` is processed. For fresh `ws-N`, `Subscribe` success in that new `TermWmApp` pushes `Workspace ws-N`. For existing reattach, the outer viewer's `Attach` to target will cause that target's existing `TermWmApp` to receive `OnUserConnected` (if not sole) and the client's `Rebind` success will also spawn a local `Workspace` toast in the source? No.

**Simplified correct:** Keep `OnWorkspaceEntered(String)` **as wire** but only for destination, without `pending`/`ack` — server pushes `OnWorkspaceEntered` directly to `target.internal_wm_caller` in `RebindWorkspace` (if `Some`) and in `Attach` (if `internal_wm_caller` is `Some` after `Subscribe` has already run, i.e., existing workspace; for cold-start `ws-N` where `Attach` happens before `Subscribe`, `internal_wm_caller` is `None` at `Attach` time, so `Subscribe` will push `OnWorkspaceEntered` after setting caller if `!clients.is_empty()`). No `pending`, no `Ack`, no `viewer_ack_received`. Direct push, no deferred state.

But to keep it truly fire-and-forget and avoid any pending, we make `OnWorkspaceEntered` **always** push directly if `internal_wm_caller` is `Some` at that instant, and if `None` (cold-start), the subsequent `Subscribe` will push (since `Subscribe` now checks `!clients.is_empty()` and pushes). This is two pushes but with `clients.len()<=1` suppress for user toasts, not for workspace.

Final minimal:
- Wire: `UserInfo`, `OnUserConnected`, `OnUserDisconnected`, `OnWorkspaceEntered(String)`, `ListUsers` — no `OnNotification`, no `Ack`, no `pending`.
- Server: `Attach` → if `internal_wm_caller.is_some()` push `OnWorkspaceEntered(ws)`; `Rebind` → push `OnWorkspaceEntered` to target's `internal_wm_caller` if `Some` (no pending cache, if `None` the subsequent `Subscribe` will push via its `!clients.is_empty()` check); `notify_user_*` to `internal_wm_caller` with `len<=1` suppress.
- Client: `UnifiedEvent::WorkspaceEntered(String)` + `UserConnected`/`UserDisconnected`/`UserCacheRefreshed`, `runner` drains unconditionally, `WindowManager.push_notification` with `tick`, palette reads `user_registry`, `main.rs` spawns `list_users` async after `Subscribe`/`Rebind`.

## Parts
### Part 1 — Wire
`methods.rs`: `UserInfo`, `OnUserConnected`, `OnUserDisconnected`, `OnWorkspaceEntered(String)`, `ListUsers`

### Part 2 — NotificationBus + UserRegistry
`notification.rs` extended with `NotificationBus { toasts: VecDeque<Toast { id, message, expires_at }> }` + `tick`; `user_registry.rs` new

### Part 3 — Server
`ChannelState` no pending/ack. `Attach` and `Rebind` push `OnWorkspaceEntered` directly to `target.internal_wm_caller` if `Some`. `Subscribe` if `!clients.is_empty()` push `OnWorkspaceEntered` (cold-start fallback). `notify_*` to `internal_wm_caller` with suppress.

### Part 4 — Client
`unified_event_source.rs` `WorkspaceEntered`, `runner.rs` unconditional drain + `tick`, `main.rs` `OnWorkspaceEntered`→`WorkspaceEntered` + async `UserCacheRefreshed`, no local `push_notification` in `handle_custom_action`

### Part 5 — Palette
`command_palette.rs` `Connected Users (N)` from `user_registry`, `open_command_palette` spawns async refresh
