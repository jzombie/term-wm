# Implementation Plan: Session Notifications & User Registry

**GitHub Issue:** [#274 — sessions: Add notifications for users who have connected/disconnected](https://github.com/jzombie/term-wm/issues/274)

## Overview

Implement three features:
1. **Workspace entry notification** — "Workspace {workspace_name}" toast when entering a new workspace
2. **User connect/disconnect notifications** — Toast with user info (IP, hostname, user) when users join/leave
3. **Centralized UserRegistry** — Slotmap-based registry for looking up connected user information
4. **Command Palette integration** — Show connected users in the palette

## Architecture Decisions

| Question | Decision | Rationale |
|----------|----------|-----------|
| Where does `UserRegistry` live? | `term-wm-core/src/user_registry.rs` | Pure data structure, no RPC deps. Both server and clients need the same type. |
| How do user events flow? | New push RPCs (`OnUserConnected`, `OnUserDisconnected`) | Follows `OnPtyResized` pattern — server pushes to all clients on a channel. |
| How is registry populated? | Push (server broadcasts) + `ListUsers` poll for initial sync | Push gives real-time; poll handles reconnect/startup. |
| Slotmap key type? | `UserKey = slotmap::DefaultKey` | Consistent with existing `WindowKey` pattern. |
| Workspace notification trigger? | Inner process on startup after rebind | Notification appears inside the new workspace's WM. |

## Part 2: Client-Side UserRegistry

**New file:** `crates/term-wm-core/src/user_registry.rs`

```rust
pub type UserKey = slotmap::DefaultKey;

pub struct UserEntry {
    pub conn_id: usize,
    pub user: String,
    pub hostname: String,
    pub ssh_ip: Option<String>,
    pub channels: Vec<String>,
}

pub struct UserRegistry {
    users: SlotMap<UserKey, UserEntry>,
    by_conn_id: HashMap<usize, UserKey>,
}
```

API: `new()`, `upsert(conn_id, user, hostname, ssh_ip, channel)`, `remove_by_conn_id(conn_id)`, `get(key)`, `get_by_conn_id(conn_id)`, `iter()`, `len()`, `is_empty()`, `clear()`

## Part 3: Server-Side Push Notifications

**File:** `crates/term-session-server/src/session_server.rs`

### 3a. New broadcast functions (after `evict_conn`, ~line 683):

```rust
async fn notify_user_connected(state, channel, connected: UserInfo)
async fn notify_user_disconnected(state, channel, conn_id: usize)
```

Pattern: resolve channel → lock → clone client list → unlock → spawn `OnUserConnected::call` / `OnUserDisconnected::call` for each client.

### 3b. Call from Attach handler (~line 806):

After `Attach::encode_response(conn_id)`, spawn `notify_user_connected` with the new client's `UserInfo`.

### 3c. Call from `evict_conn` (~line 665):

After removing client from channel, call `notify_user_disconnected(state, &channel, conn_id)`.

### 3d. Register `ListUsers` handler (~after ListChannels handler):

Iterate `guard.clients.iter()` to build `Vec<UserInfo>` and return `ListUsersResponse`.

### 3e. Update imports:

Add `ListUsers`, `ListUsersResponse`, `OnUserConnected`, `OnUserDisconnected`, `UserInfo` to the `use term_session_muxio_service_definitions::{...}` block.

## Part 7: Command Palette Integration

**File:** `crates/term-wm-core/src/window/window_manager/command_palette.rs`

In `wm_menu_items()` (~line 196), after workspace group, add:

```rust
// Connected Users section
#[cfg(feature = "session-persistence")]
if term_wm_config::runtime::session_persistence_enabled() && !self.user_registry.is_empty() {
    items.push(MenuDisplayItem::Separator);
    items.push(mi(&format!("Connected Users ({})", self.user_registry.len()), Some("●"), CloseMenu));
    for (_key, user) in self.user_registry.iter() {
        let label = if let Some(ref ip) = user.ssh_ip {
            format!("  {}@{} ({})", user.user, user.hostname, ip)
        } else {
            format!("  {}@{}", user.user, user.hostname)
        };
        items.push(MenuDisplayItem::Item(MenuItem { label: label.into(), icon: None, action: CloseMenu, disabled: true }));
    }
}
```
