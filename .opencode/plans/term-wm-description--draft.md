Term WM is a terminal-based window manager for Linux, macOS, and Windows. Unlike traditional graphical window managers that require a desktop environment like GNOME or KDE, Term WM runs entirely within the terminal emulator. It manages multiple terminal sessions as tiled or floating windows inside your terminal window. This makes it ideal for users who prefer to work from the command line, or for remote environments where a full graphical desktop is not available.

The project was created by a developer named Jeremy who wanted a way to manage multiple terminal panes and windows with the power of a traditional window manager. The architecture is modular. The core crate handles window management, event routing, key bindings, and action dispatch. A separate layout engine provides both binary space partition tiling and N-ary tree tiling, as well as floating geometry with snap-to-edge behavior.

There are several UI component crates that provide the actual widgets. These include a terminal emulator component built on the VT100 parser, a scroll view component, a markdown viewer, a command palette, and various system panels. The window manager specific components include a top panel showing window titles, a bottom panel with keybinding hints, a floating action button, a help overlay, and a notification area.

The window manager supports multiple layout modes. In tiling mode, windows are automatically arranged in a binary space partition tree. As you open new windows the existing windows are split to make room. In floating mode, windows can be freely positioned and resized with mouse drag. Maximized mode makes the focused window fill the entire managed area. Monocle mode shows one window at a time full screen, which is especially useful when the terminal is narrow.

The command palette is the central way to interact with the window manager. It provides a searchable list of all available commands, from creating and closing windows to changing layouts and toggling features. The palette uses fuzzy matching powered by the nucleo matcher library and tracks recently used commands with exponential decay scoring.

There is also a remote session management system using the Muxio IPC framework. This allows terminal sessions to be hosted in a separate server process, enabling detachable sessions that survive the window manager lifecycle. Sessions are serialized with the Bitcode format and communicate over Unix sockets.

The rendering pipeline uses the Ratatui library for terminal graphics. Each frame, the Core Engine generates a draw plan that lists all visible regions sorted by Z-order. The draw plan is then rendered by a concrete renderer that handles the actual terminal output. There is a frame pacer that targets sixty frames per second by default, and a power profile tracker that adjusts frame rate based on activity level.

Term WM also supports alternate screen detection for applications like Vim and Tmux. When an application switches to the alternate screen, mouse events and keyboard input are passed directly through to the application without window manager intervention. The DirectInputTracker automatically detects these transitions and shows a notification toast.

The configuration system is extensive. Users can customize key bindings with different action layers for global use, the command palette, and the help overlay. The theme is fully customizable with colors for all UI elements. Feature flags control whether chrome, panels, clipboard support, mouse capture, and drop shadows are enabled.

Window management actions include creating new windows, closing windows, cycling focus, toggling floating and maximized modes, dragging window headers to reposition, snapping floating windows to edges, resizing floating windows, and adjusting tiling split ratios. Floating windows also have drop shadows and can be brought to front with a click.

The test infrastructure uses in-memory rendering buffers so that component rendering can be tested without a real terminal. There are property tests using the Proptest crate for the scroll synchronization logic, and a TestPane implementation that simulates a terminal without spawning a real PTY. The project follows strict conventions for component naming and file structure as documented in the AGENTS dot MD file. All components must be named with a Component suffix, and filenames must be lower snake case derived from the struct name.

The project has been under active development and the codebase continues to evolve with new features and improvements to the window management experience. The goal is to provide a full featured window manager that runs entirely within the terminal, combining the power of traditional window managers with the convenience and portability of terminal based interfaces.
