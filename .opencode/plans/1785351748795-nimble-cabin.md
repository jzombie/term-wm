# Plan: Smallest-Client Geometry Constraint in term-session-server

## Problem

`term-session-server` blindly passes through geometry mutations from `ResizePty` and `Spawn`. When Client A (100x40) and Client B (80x20) are attached, the PTY thrashes to the largest requested size, causing continuous vertical scroll on Client B.

## Design

### 1. Add geometry to `ClientEntry`

```rust
struct ClientEntry {
    conn_id: usize,
    cols: u16,
    rows: u16,
}
```

Sentinel `u16::MAX` = uninitialized.

### 2. Add `recalculate_pty_size()` to `ServerState`

Compute `min(cols)` and `min(rows)` across all connected clients (ignoring `u16::MAX`). Resize PTY and update `session.cols`/`session.rows`. Fallback `80×24` when no client has sent geometry yet.

### 3. Modify `ResizePty` handler

Update calling client's `ClientEntry`, call `recalculate_pty_size()`.

### 4. Modify `Spawn` handler

**Reuse path** (session exists, not exited): update client entry, call `recalculate_pty_size()`.
**Cold path** (session is None/exited): create session at payload size, call `set_session()`, then call `recalculate_pty_size()` to enforce constraints.

### 5. Modify event handlers

- `ClientConnected`: push `ClientEntry { conn_id, cols: u16::MAX, rows: u16::MAX }`
- `ClientDisconnected`: call `recalculate_pty_size()` so PTY expands if smallest client drops

### 6. Fix stale-cache bug

`ResizePty` currently doesn't update `session.cols`/`session.rows`. Fixed by `recalculate_pty_size()` which writes both.

## Files to modify

| File | Changes |
|------|---------|
| `crates/term-session-server/src/session_server.rs` | `ClientEntry` gains `cols`/`rows`. New `recalculate_pty_size()`. `ResizePty`/`Spawn` handlers constrain via min. Connect/disconnect handlers updated. |
