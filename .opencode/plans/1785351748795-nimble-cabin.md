# Plan: Revert client to raw ANSI rendering — keep RPC protocol fixes

## Problems with current Ratatui approach

1. **No cursor**: Ratatui `Terminal::draw()` doesn't forward the vt100 parser's cursor position
2. **Not centered**: `live_cols`/`live_rows` don't reflect constrained size on passive clients (no event streaming per user directive), so centering math produces zero offset
3. **Garbage from stale cells**: `render_centered` writes ALL parser cells (including stale rows beyond constrained PTY size) after `Clear`, making stale data visible
4. **Complexity**: Adds Ratatui dependency for no benefit

## Fix

**Revert the client to raw ANSI rendering** exactly like the original pre-Ratatui code:
- `out.write_all(&screen.contents_formatted())` for first frame
- `out.write_all(&diff)` for incremental frames via `contents_diff()`
- Remove Ratatui `Terminal`, `CrosstermBackend`, `render_centered` function

**Keep the RPC protocol changes** (these are correct):
- `ResizePty` returns `(u16, u16)` actual constrained size
- `Spawn` returns `(u64, u16, u16)` + actual size
- `RemotePane::resize()` resizes parser to actual constrained size
- Server sends raw bytes on `SUBSCRIBE_OUTPUT` (no framing)
- `SessionPushFrame` deleted

**Cursor works automatically**: vt100's `contents_formatted()` and `contents_diff()` include cursor positioning sequences that the terminal renders correctly.

**No stale cells visible**: The original code used `contents_diff()` which only sends CHANGED cells. Stale rows beyond the constrained PTY size don't change (no PTY output for them), so they're never re-sent.
