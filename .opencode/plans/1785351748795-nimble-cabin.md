# Fix: Third client not resizing existing clients

## Bug 1: Race between `ClientConnected` and `Spawn`

The `Spawn` handler uses `find(|c| c.conn_id == ctx.conn_id)` to update client geometry but doesn't insert if missing. If `Spawn` runs before `ClientConnected` adds the entry, the client's geometry is lost and stays `u16::MAX` forever.

**Fix: Change `clients` from `Vec<ClientEntry>` to `HashMap<usize, ClientEntry>` keyed on `conn_id`.**

This makes insertion idempotent — `ClientConnected` inserts the entry (caller handle, u16::MAX cols/rows), and `Spawn` updates the same entry (real cols/rows). Order doesn't matter.

Changes:
- `ServerState.clients` type: `HashMap<usize, ClientEntry>` (from `Vec`)
- `ClientConnected`: `clients.insert(conn_id, ClientEntry { ... })` (was `push`)
- `ClientDisconnected`: `clients.remove(&conn_id)` (was `retain`)
- `Spawn` handler: `clients.entry(ctx.conn_id).or_insert_with(...)` then update cols/rows
- `ResizePty` handler: `clients.get_mut(&ctx.conn_id)` (was `iter_mut().find(...)`)
- `recalculate_pty_size`: `self.clients.values()` (was `self.clients.iter()`)
- `notify_clients`: iterate `clients.values()`
- Derive `Clone` on `SubscriberEntry` too (for the cold Spawn path clone)

## Bug 2: Spawn response geometry discarded

Client does `let _id = Spawn::call(...)` — discards `(cols, rows)`.

**Fix: Use response to initialize parser immediately:**
```rust
let (_id, actual_cols, actual_rows) = rt.block_on(async {
    Spawn::call(&*client, (None, term_cols, term_rows)).await
})?;
let parser = pane.shared_parser();
let mut parser = parser.lock().unwrap();
parser.screen_mut().set_size(actual_rows, actual_cols);
```
