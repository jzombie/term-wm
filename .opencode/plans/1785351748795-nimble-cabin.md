# Plan: Fix term-resize-indicator Rendering & SetSize Debounce

## Problems

### SEV-1: Synchronous `SetSize` feedback loop
In `on_resize()` (lib.rs:97-108), every `Event::Resize` synchronously fires `SetSize` back to the locked size. In a multiplexed PTY (tmux/tmate) with multiple clients:
- Client A drags window → SIGWINCH → PTY resizes → Client B gets SIGWINCH → Client B fires SetSize → PTY resizes → Client A gets SIGWINCH → infinite thrash
- Even single-client: SetSize inside the event loop fights the OS window manager during drag at hundreds of Hz

### Rendering bugs in `draw_overlay()`
1. **u16 overflow in text label** (line 232): `text_x + i as u16` wraps when `text_x` > 65535 - label_len
2. **Asymmetrical centering** (lines 157-158): `full.width/2 - w/2` vs the more correct `(full.width - w)/2`. Off by 1 when full.width even and w odd.
3. **VT100 DECAWM auto-wrap at bottom-right cell**: Writing to `(full.right()-1, full.bottom()-1)` can trigger hardware scroll before the character appears, desyncing the buffer.

### What the code review correctly rejected
- The original plan proposed blanket saturating arithmetic on `i32` coordinates. This is WRONG: `i32` can't overflow from `u16` values (max 65535), and saturating would kill negative off-screen coordinates (e.g., `bx = -10`). We only fix the genuine `u16` overflow on line 232.
- The corner rendering code IS correct by-design: corners only draw when within the visible range.

## Design

### 1. Debounce `SetSize` (lib.rs)

New field in `App`:
```rust
struct App {
    mode: Mode,
    live_size: Size,
    pending_snap: Option<Instant>,  // non-None when a SetSize is deferred
}
```

`on_resize` in locked mode: set `live_size` to the new size immediately (so the visual overlay tracks the actual terminal), arm a 250ms debounce timer in `pending_snap`. Do NOT call `SetSize` synchronously.

`run_loop` before each `terminal.draw()`: check `pending_snap` — if the timer has expired, fire `SetSize` and reset `live_size` to locked size, clear `pending_snap`.

This breaks the feedback loop:
- During an active drag, SetSize is never emitted — no fight with OS/managers
- After the drag stops and 250ms passes, one final SetSize snaps the terminal back
- In multiplexer setups, the debounce prevents distributed thrashing

### 2. Fix centering algebra (lib.rs lines 157-158)

Change from:
```rust
let bx = full.left() as i32 + full.width as i32 / 2 - w as i32 / 2;
let by = full.top() as i32 + full.height as i32 / 2 - h as i32 / 2;
```
To:
```rust
let bx = full.left() as i32 + (full.width as i32 - w as i32) / 2;
let by = full.top() as i32 + (full.height as i32 - h as i32) / 2;
```

The `(A - B) / 2` form is exact rounding (midpoint toward negative infinity), matching the integer division pattern used elsewhere. The old `A/2 - B/2` form could be off by 1 when `A` is even and `B` is odd.

### 3. Fix u16 overflow in text label (lib.rs line 232)

Change from:
```rust
let cx = text_x + i as u16;
```
To:
```rust
let cx = text_x.saturating_add(i as u16);
```

### 4. Bottom-right cell exclusion (lib.rs draw_overlay)

VT100 DECAWM auto-wrap causes hardware scroll when writing to the bottom-right cell. Insert exclusion in three places:

a) Background fill loop (lines 146-153): skip the bottom-right cell
b) `set_cell` closure (lines 169-179): early-return if `(x, y) == (full.right()-1, full.bottom()-1)`
c) Text label loop (lines 231-238): skip the bottom-right cell

Define const/binding:
```rust
let br_x = full.right().saturating_sub(1);
let br_y = full.bottom().saturating_sub(1);
```

Note: i32 arithmetic is retained for box positioning — no saturating math on i32 coordinates.
