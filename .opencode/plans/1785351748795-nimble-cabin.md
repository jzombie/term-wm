# Plan: Fix term-resize-indicator — Passive Reticle Architecture

## Problem

In a multiplexed PTY environment (tmux/tmate), `SetSize(80, 24)` resizes the *virtual* PTY, but each physical client retains its own window size. The multiplexer projects the 80x24 grid onto each physical terminal by scrolling — causing continuous vertical scroll on every render frame for clients smaller than the locked size. `DisableLineWrap` only protects against horizontal X-axis wrapping, not Y-axis vertical scrolling.

## Resolution

Abandon the attempt to mutating physical window sizes. The tool becomes a **passive reticle** — it draws a measured border that clips naturally to the terminal area, visually informing each user when their terminal is too small.

### 1. Remove all `SetSize` calls
- Delete `SetSize` from imports
- Delete the `SetSize` call in `run()` (initial lock)
- Delete the `SetSize` call in `run_loop` (debounce timer)
- The Debounce architecture (`pending_snap`) is no longer needed

### 2. Remove debounce architecture
- Delete `pending_snap: Option<Instant>` from `App` struct
- Delete `Instant` import
- Delete the debounce check in `run_loop`
- Simplify `on_resize` to just update `app.live_size`
- Remove the `app.pending_snap = None` line from the `l` key handler

### 3. Keep `DisableLineWrap`/`EnableLineWrap`
Still useful for preventing horizontal wrapping artifacts during normal operation.

### 4. Keep existing rendering fixes
- Centering algebra: `(full.width - w) / 2`
- Text label: `saturating_add`
- `draw_overlay` math is correct as-is
