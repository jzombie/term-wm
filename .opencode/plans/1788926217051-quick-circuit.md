# Plan: Recently Used Commands in Command Palette

## Tracked Issue (read-only, do not update)
- jzombie/term-wm#305 `command-palette: Investigate optional predictive ordering` (open, enhancement + needs research)
- Rationale: closest existing tracker for learning desired actions and ordering. This plan is the minimal in-memory MRU slice of that larger predictive vision.
- Do NOT comment on, close, or edit #305 from automation.

## User Decisions
- UX: dedicated `Recently Used` section pinned at top on empty query (not in-place re-rank).
- Scope v1: in-memory per-process only, no disk persistence, no feature flag.

## Background Findings
- Generic palette: `crates/term-wm-ui-components/src/command_palette.rs` (`CommandPaletteComponent`, `rerank_with_registry`, `selected_stable_id()` exists but has zero production callers).
- WM wrapper: `crates/term-wm-sys-ui-components/src/wm_command_palette.rs` (`WmCommandPaletteComponent { registry, matcher, mru }`, `set_items()`, `refresh_if_dirty()`).
- Ranker: `crates/term-wm-core/src/command_menu/matcher.rs` (`MruRanker { record(), weight() }`, decay 0.95, keyed on `stable_id`; only empty-query path consumes it; tests only).
- Root cause of dead MRU: `src/term_wm_app.rs:1342 open_command_palette()` constructs a fresh `WmCommandPaletteComponent::new()` (fresh `MruRanker`) on every open, and nothing ever calls `mru.record()`, so weights are always 0.0.
- Fragile key: `set_items()` derives `stable_id = format!("core:{}", label.replace(' ','_').to_lowercase())`, so renames break history and parameterized actions (`Switch to Window: {title}`, `Run Project Task: {label}`) collide or churn. `TermWmAction::Display` in `crates/term-wm-core/src/actions.rs` must stay in sync with palette labels per `docs/UI-STYLE.md` and `AGENTS.md`.
- Listing source: `crates/term-wm-core/src/window/window_manager/command_palette.rs:190 wm_menu_items()` builds 5 sections; executor is `WindowManager::handle_command_palette_event()` + `crates/term-wm-core/src/runner.rs:816`.

## Proposal: Hoisted In-Memory MRU + Top Recent Section

### 1. Hoist MRU ownership so it survives palette rebuilds
- Add a single owned `MruRanker` (or `Vec<String>` recency list + weights) on the long-lived owner, either `TermWmApp` in `src/term_wm_app.rs` or `WindowManager` in `crates/term-wm-core/src/window/window_manager/`.
- Preferred: `WindowManager` field, since `open_command_palette`, overlays, and `handle_command_palette_event` already live there and it avoids threading app state through overlay enum `OverlayComponent::CommandPalette`.
- On `open_command_palette()`, inject the shared state into the fresh palette instead of `MruRanker::new()`: either `palette.mru = self.mru.clone()` (add `Clone` to `MruRanker`/`MruEntry`) or pass `&mut` / `Rc<RefCell<>>`. Keep `WmCommandPaletteComponent.mru` as the per-frame read view.
- Files: `src/term_wm_app.rs:1342`, `crates/term-wm-sys-ui-components/src/wm_command_palette.rs:35-92`, `crates/term-wm-core/src/command_menu/matcher.rs:71-120`, `crates/term-wm-core/src/window/window_manager/command_palette.rs:39-121`.

### 2. Record usage on execute (the missing producer)
- In `WindowManager::handle_command_palette_event()` close path (or `runner.rs` execute path), call `mru.record(&stable_id)` using the already-existing `selected_stable_id()` helper in `command_palette.rs:406`.
- Record only successful enabled selections, not `CloseMenu` dismissals or disabled rows (`selected_action()` returns `None` for disabled; skip those).
- Decide stable_id policy before recording:
  - Option A (minimal): keep label-derived `stable_id` for v1, accept rename churn.
  - Option B (recommended if cheap): derive from `TermWmAction` discriminant + payload key (e.g. `SwitchWorkspace(name)`, `FocusWindow(key)`, `RunProjectTask(label)`), falling back to label for static actions. Prevents title churn from polluting history.
- Files: `crates/term-wm-core/src/window/window_manager/command_palette.rs:102`, `crates/term-wm-ui-components/src/command_palette.rs:396-410`, `crates/term-wm-core/src/runner.rs:816`.

### 3. Render `Recently Used` section on empty query only
- Behavior:
  - Empty query: prepend `── RECENTLY USED ──` header + up to N (suggest 5) most-recent enabled items (by `mru.weight` desc), then a separator, then the full existing list (existing empty-query MRU sort may stay or be removed to avoid double-boost; prefer removing it so Recent section is the single MRU signal).
  - Non-empty query: hide the Recent section entirely, use pure nucleo fuzzy scores (no MRU blending) to keep search predictable.
  - Empty history: hide the section entirely (no header, no extra separator) so first-run palette is unchanged.
  - Skip disabled rows and stale ids (label/action no longer present); dedupe parameterized duplicates.
  - Selection starts at 0 (first recent item), preserving existing `last_ranked_query` reset semantics.
- Implementation point (pick one during build):
  - Preferred: synthesize in `rerank_with_registry()` in `crates/term-wm-ui-components/src/command_palette.rs:412-498` by prepending to `display_nodes`/`filtered_items`.
  - Alternative: prepend in `wm_menu_items()` or `set_items()` in `wm_command_palette.rs:130`. Less ideal because it mixes history into the canonical 5-section source of truth and complicates `compute_stable_size`.
- Respect `docs/UI-STYLE.md`: Chicago title-case header, no em/en dashes in comments or copy. Stable palette footprint (`compute_stable_size`, `PALETTE_MAX_HEIGHT`) must account for the extra rows or clamp.

### 4. Conventions and guardrails
- Cross-platform: no OS-specific APIs; pure in-memory `HashMap`/`Instant` stays as-is (no `SystemTime` needed since no persistence in v1).
- Saturating arithmetic on all row/height math; no new hardcoded terminal size limits.
- Extract any new magic numbers to named consts (e.g. `MAX_RECENT_ITEMS: usize = 5`); follow `*Component` naming and `render_content` helper rules per `AGENTS.md`.

## Tests
- Unit (`matcher.rs`): record-then-weight ordering, decay, unknown id is 0.0 (already exist, extend for clone/snapshot if added).
- Unit (`command_palette.rs`): empty query with history shows Recent header + N items first; empty history shows no header; non-empty query hides Recent; disabled/stale ids excluded; selection reset semantics.
- Unit (`wm_command_palette.rs`): `set_items` + injected MRU renders stable size; `Restore` clears query but preserves MRU.
- Integration (`window_manager/command_palette.rs` or `tests/overlay_dismissal.rs` pattern): execute action then reopen palette and assert it appears in Recent section. Use in-memory render pattern `Buffer::empty(area) + RatatuiBackend::new_simple(buffer, area)`.
- Existing pin: `display_strings_for_all_action_variants` in `actions.rs:510` must keep passing if labels change.
