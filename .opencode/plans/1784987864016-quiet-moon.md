# Unify Keyboard Event Handling

**Goal**: Eliminate 3 copies of crossterm-to-core event translation and 2 copies of
core-to-PTY key encoding, so fixes like BackTab/shift+Tab apply everywhere.

## Current Duplication

### Three copies of crossterm → core event translation

| Location | File | Approach |
|---|---|---|
| **A** | `src/unified_event_source.rs:205-251` | 3 private functions: `translate_key_event`, `translate_key_code`, `translate_key_modifiers` |
| **B** | `crates/term-wm-console/src/console_event_source.rs:24-70` | Literal copy of A |
| **C** | `crates/term-session-client/src/lib.rs:138-242` | Single inline `convert_crossterm_event` |

All three have identical match arms (17 key codes + modifiers + kind), except:
- A/B fallback to `KeyCode::Esc` on unrecognized keys; C returns `None` (drops event)
- C now has BackTab handling (our fix); A/B already had it

### Two copies of core KeyEvent → PTY bytes

| Location | File | Lines | Shift+Tab behavior |
|---|---|---|---|
| Terminal component | `crates/term-wm-ui-components/src/terminal.rs` | 129-162 | `\t` (same as Tab) |
| Session client | `crates/term-session-client/src/lib.rs` | 460-527 | `\x1b[Z` (CSI backtab) via local override |

Both have identical match arms for the core → pty-engine type conversion.

### Dependency chain

```
term-wm-core ──depends-on──> term-wm-pty-engine      (core depends on pty-engine)
term-wm-console ──depends-on──> term-wm-core
term-session-client ──depends-on──> term-wm-core, term-wm-pty-engine
```

`term-wm-core` does NOT have `crossterm` as a direct dependency.
`term-wm-pty-engine` does NOT depend on `term-wm-core` (avoids circular dep).

**Constraint**: Do NOT add `crossterm` as a mandatory dependency of `term-wm-core`.
It must be optional behind a feature flag to keep the core domain model agnostic
to I/O backends.

## Plan

### Step 1: Add shared crossterm → core translation to `term-wm-core`

**Add `crossterm` as an optional dependency** behind a feature flag in
`crates/term-wm-core/Cargo.toml`:
```toml
[dependencies.crossterm]
workspace = true
optional = true

[features]
default = []
crossterm = ["dep:crossterm"]
```

**Create `crates/term-wm-core/src/translate.rs`** with public functions, gated:

```rust
// term_wm_core::translate

pub fn translate_key_code(code: crossterm::event::KeyCode) -> Option<term_wm_core::events::KeyCode>
pub fn translate_key_modifiers(mods: crossterm::event::KeyModifiers) -> term_wm_core::events::KeyModifiers
pub fn translate_key_event(key: crossterm::event::KeyEvent) -> Option<term_wm_core::events::KeyEvent>
pub fn translate_mouse_event(mouse: crossterm::event::MouseEvent) -> term_wm_core::events::MouseEvent
pub fn translate_event(evt: crossterm::event::Event) -> Option<term_wm_core::events::Event>
```

**Gate the module** in `crates/term-wm-core/src/lib.rs`:
```rust
#[cfg(feature = "crossterm")]
pub mod translate;
```

**Enable the feature** in all consuming crates that need it:
- `crates/term-wm-console/Cargo.toml`: `term-wm-core = { workspace = true, features = ["crossterm"] }`
- `crates/term-session-client/Cargo.toml`: same
- `term-wm` workspace root's `Cargo.toml` or the main `src/` crate.

Key design decisions:
- Returns `Option` for unrecognized key codes (catches unknown crossterm variants)
- Handles `BackTab` → `KeyCode::Tab` with forced `modifiers.shift = true`
- Exports a `translate_key_event` that the `KeyboardNormalizer` can be applied after

### Step 2: Add shared core → PTY bytes conversion to `term-wm-core`

Since `term-wm-core` depends on `term-wm-pty-engine`, add a function in the new `translate` module that converts core events directly to PTY bytes:

```rust
// in term_wm_core::translate

/// Convert a core KeyEvent to PTY bytes.
/// shift+Tab produces \x1b[Z (CSI backtab) per ANSI terminal standard.
pub fn key_event_to_pty_bytes(key: &term_wm_core::events::KeyEvent) -> Vec<u8>
```

Internally this delegates to `key_to_bytes` for most keys, but handles the
shift+Tab case explicitly (producing `\x1b[Z` instead of `\t`).

### Step 3: Replace the 3 copies with shared functions

**A. `src/unified_event_source.rs`**: Replace private `translate_key_event`/`translate_key_code`/`translate_key_modifiers` with calls to `term_wm_core::translate::*`.

**⚠️ Preserve existing fallback**: A/B currently map unrecognized keys to
`KeyCode::Esc`, not `None`. The shared `translate_key_code` returns `Option`,
so the callers must map `None → KeyCode::Esc` explicitly:
```rust
// Instead of: translate_key_code(key.code)
// Use:
translate_key_code(key.code).unwrap_or(KeyCode::Esc)
```
Keep the existing call to `KeyboardNormalizer::normalize()`.

**B. `crates/term-wm-console/src/console_event_source.rs`**: Same replacement as A.

**C. `crates/term-session-client/src/lib.rs`**: Replace `convert_crossterm_event` body with `term_wm_core::translate::translate_event`. Replace `key_to_bytes` + local override with `term_wm_core::translate::key_event_to_pty_bytes(key)`.

### Step 4: Update `crates/term-wm-ui-components/src/terminal.rs`

Replace the manual core → pty-engine conversion and `key_to_bytes` call (lines 129-162) with:
```rust
let bytes = term_wm_core::translate::key_event_to_pty_bytes(key);
if bytes.is_empty() {
    return EventResult::Ignored;
}
EventResult::Action(TermWmAction::KeyToBytes(bytes))
```

This eliminates the duplicate conversion match arms and gives shift+Tab the correct `\x1b[Z` encoding in the main app too.

### Step 5: Fix `KeyboardNormalizer` docs

Update the misleading comment in `crates/term-wm-core/src/utils/keyboard_normalizer.rs` that claims to "Convert Shift+Tab to BackTab" but does nothing of the sort.
