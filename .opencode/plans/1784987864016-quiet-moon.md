# Unify Keyboard Event Handling

**Goal**: Eliminate 3 copies of crossterm-to-core event translation and 2 copies of
core-to-PTY key encoding, so fixes like BackTab/shift+Tab apply everywhere.

## Duplication Summary

### Three copies of crossterm → core event translation

| Location | File | Approach |
|---|---|---|
| **A** | `src/unified_event_source.rs:205-251` | 3 private functions (`translate_key_event`, `translate_key_code`, `translate_key_modifiers`) |
| **B** | `crates/term-wm-console/src/console_event_source.rs:24-70` | Copy of A |
| **C** | `crates/term-session-client/src/lib.rs:138-242` | Inline `convert_crossterm_event` |

All have identical 17-arm match on `KeyCode` + modifiers + kind. Differences:
- A/B fallback on unknown keys → `KeyCode::Esc`; C returns `None` (drops event)
- A/B had BackTab already; C now has it (our prior fix)

### Two copies of core KeyEvent → PTY bytes

| Location | File | Lines | Shift+Tab |
|---|---|---|---|
| `terminal.rs` | `crates/term-wm-ui-components/src/terminal.rs` | 129-162 | `\t` (same as Tab) |
| `lib.rs` | `crates/term-session-client/src/lib.rs` | 460-527 | `\x1b[Z` via local override |

Both manually convert `events::KeyEvent` → `input_encoding::KeyEvent` (28 identical match lines).

## Design

Two architectural boundaries:

1. **Crossterm adapter** — translates crossterm event types to core domain types.
   Lives in its own crate so `term-wm-core` never depends on `crossterm`.

2. **PTY serialization** — converts a domain `KeyEvent` to the byte stream sent to
   a PTY. Implemented as an inherent method `KeyEvent::to_pty_bytes()` so the
   behavior lives with the data it operates on. `term-wm-core` already depends on
   `term-wm-pty-engine` which provides `key_to_bytes`.

```
New dependency graph:
                                 ┌─────────────────────┐
                                 │ term-wm-crossterm-   │
                                 │ adapter              │
                                 ├─────────────────────┤
                                 │ translate_key_code() │
                                 │ translate_key_event()│
                                 │ translate_event()    │
                                 └─────────┬───────────┘
                                           │ depends on
                                           ▼
┌─────────────────────┐           ┌─────────────────────┐
│ term-wm-console      │──────────▶│ term-wm-core         │◀──────────┐
│ (ConsoleEventSource) │           │                      │           │
└─────────────────────┘           │ events::KeyEvent      │           │
                                  │   .to_pty_bytes()     │───────────┤
┌─────────────────────┐           │                      │           │
│ term-session-client  │──────────▶│ depends on           │           │
│ (remote pane)        │           │ term-wm-pty-engine   │           │
└─────────────────────┘           └──────────────────────┘           │
                                           │                         │
                                           ▼                         │
                                  ┌─────────────────────┐           │

```

## Steps

### Step 1: Create `crates/term-wm-crossterm-adapter`

New crate with `Cargo.toml`:
```toml
[package]
name = "term-wm-crossterm-adapter"
edition = "2021"

[dependencies]
crossterm = { workspace = true }
term-wm-core = { workspace = true }

[lib]
name = "term_wm_crossterm_adapter"
```

`src/lib.rs` — public translation functions (extracted from the 3 copies):
```rust
pub fn translate_key_code(code: crossterm::event::KeyCode)
    -> Option<term_wm_core::events::KeyCode>;

pub fn translate_key_modifiers(mods: crossterm::event::KeyModifiers)
    -> term_wm_core::events::KeyModifiers;

pub fn translate_key_event(key: crossterm::event::KeyEvent)
    -> Option<term_wm_core::events::KeyEvent>;

pub fn translate_mouse_event(mouse: crossterm::event::MouseEvent)
    -> term_wm_core::events::MouseEvent;

pub fn translate_event(evt: crossterm::event::Event)
    -> Option<term_wm_core::events::Event>;
```

Design:
- Returns `Option` for unrecognized codes (callers decide fallback)
- BackTab → `KeyCode::Tab` with `shift = true` (centralizing the macOS fix)
- Includes mouse/resize/paste/focus translation (eliminates all inline conversion)

Register in workspace `Cargo.toml`
```toml
members = ["crates/term-wm-crossterm-adapter"]
```

### Step 2: Add `KeyEvent::to_pty_bytes()` in `term_wm_core`

In `crates/term-wm-core/src/events.rs`, add an inherent method:
```rust
impl KeyEvent {
    /// Serialize this key event to the byte sequence to send to a PTY.
    /// Shift+Tab produces \x1b[Z (CSI backtab) per ANSI terminal standard.
    pub fn to_pty_bytes(&self) -> Vec<u8> {
        use term_wm_pty_engine::input_encoding::{self, key_to_bytes, KeyCode, KeyModifiers};
        // Convert core KeyEvent → pty-engine KeyEvent inline (single match, no duplication)
        let pty_key = input_encoding::KeyEvent {
            code: match self.code {
                term_wm_core::events::KeyCode::Char(c) => KeyCode::Char(c),
                term_wm_core::events::KeyCode::Enter => KeyCode::Enter,
                term_wm_core::events::KeyCode::Tab => KeyCode::Tab,
                // ... all other variants ...
                _ => return Vec::new(),
            },
            modifiers: KeyModifiers {
                shift: self.modifiers.shift,
                control: self.modifiers.control,
                alt: self.modifiers.alt,
            },
        };
        // Handle shift+Tab before delegating to key_to_bytes
        if pty_key.code == KeyCode::Tab && pty_key.modifiers.shift {
            b"\x1b[Z".to_vec()
        } else {
            key_to_bytes(&pty_key)
        }
    }
}
```

This replaces 28 lines of duplicate conversion in `terminal.rs` and the session-client.

### Step 3: Replace the 3 copies with shared functions

**A. `src/unified_event_source.rs`**: Add `use term_wm_crossterm_adapter::*;`.
Replace private `translate_key_event`/`translate_key_code`/`translate_key_modifiers`
with direct calls. Map `None` → `KeyCode::Esc` to preserve existing behavior:
```rust
// Before (private fn):
let code = translate_key_code(key.code);

// After (shared fn):
let code = translate_key_code(key.code).unwrap_or(term_wm_core::events::KeyCode::Esc);
```

**B. `crates/term-wm-console/src/console_event_source.rs`**: Same as A.

**C. `crates/term-session-client/src/lib.rs`**: Replace `convert_crossterm_event`
with `term_wm_crossterm_adapter::translate_event`. Replace the `key_to_bytes` +
local override with `key.to_pty_bytes()`.

### Step 4: Update `crates/term-wm-ui-components/src/terminal.rs`

Replace lines 129-162 (core → pty-engine conversion + `key_to_bytes`) with:
```rust
let bytes = key.to_pty_bytes();
if bytes.is_empty() {
    return EventResult::Ignored;
}
EventResult::Action(TermWmAction::KeyToBytes(bytes))
```

This eliminates the 28-line manual conversion and applies uniform `\x1b[Z` encoding
for shift+Tab.

### Step 5: Fix `KeyboardNormalizer` docs

Update misleading comment in `crates/term-wm-core/src/utils/keyboard_normalizer.rs`
that says "Convert Shift+Tab to BackTab" (it doesn't transform, just passes through).
