# Fix: Command Palette client screen sizes update in real-time

## Root cause (regression introduced by `021b1a81`, Aug 21 "perf: Eliminate idle overlay 60 FPS spin")

The palette shows per-user `{cols}×{rows}` labels (`command_palette.rs:348-366`). Two independent gaps broke real-time updates:

1. **No resize event exists.** The server's `ResizePty` handler (`crates/term-session-server/src/session_server.rs:1089-1127`) updates `client.cols/rows` and broadcasts PTY min-geometry (`OnPtyResized`), but there is **no per-user resize notification** and the WM host registers no handler for geometry changes. Palette size data therefore only refreshes via the slow paths left by the perf commit: 30 s IPC (`PALETTE_IPC_INTERVAL`, `src/term_wm_app.rs:33-36`) instead of the old ~1 s full-refresh tick.
2. **Refreshes don't repaint.** Palette mutations happen in the runner prologue (`poll_palette_tick` at `runner.rs:534`) during idle iterations. The tickers are plain structs (`PeriodicTicker`/`Debouncer`, not scheduler tasks), so nothing calls `driver.request_redraw()`; the `FramePacer` is already disarmed by then (`frame_pacer.rs:62-71` clears the deadline after firing), so `try_expire` fails in the None branch (`runner.rs:879-889`) and rebuilt items stay invisible until the next input/PTY render.

**Chosen approach (user-approved): push-based event**, mirroring the existing `OnUserConnected`/`OnUserDisconnected` pipeline end-to-end, plus a redraw latch so registry/tick-driven rebuilds actually paint.

## Implementation steps

### 1. Protocol: add `OnUserResized`
- `crates/term-session-muxio-service-definitions/src/methods.rs` — after `OnUserDisconnected` (ends :1071), add `OnUserResizedRequest { conn_id: usize, cols: u16, rows: u16 }` + `pub struct OnUserResized;` with `METHOD_ID = rpc_method_id!("session.on_user_resized")`, `Input = (usize, u16, u16)`, `Output = ()`. Copy the `OnWorkspaceEntered` impl shape (:1079-1106).
- Add codec round-trip tests mirroring the `OnPtyResized` tests (:741-753).
- Export from `src/lib.rs:13` and from every `term_session::protocol` re-export site (grep for `OnUserDisconnected` across crates to find them all).

### 2. Server: throttled push on resize
Interactive window drags fire `ResizePty` at high frequency (tens–hundreds/sec), so notifications MUST be coalesced server-side (trailing edge) instead of firing one RPC per cell step.

- `crates/term-session-server/src/session_server.rs`:
  - Const `RESIZE_NOTIFY_DEBOUNCE: Duration = Duration::from_millis(100)` (AGENTS.md magic-number rule).
  - Channel-state fields beside `internal_wm_caller` (:162, init near :229): `pending_wm_resizes: HashMap<usize, (u16, u16)>` (latest size per conn_id) and `wm_resize_flush_scheduled: bool`.
  - Helper `notify_user_resized(caller, conn_id, cols, rows)` next to `notify_user_disconnected` (:766-780): detached `tokio::spawn`, `OnUserResized::call`, `tracing::debug!` on failure.
  - In the `ResizePty` handler (:1089-1127): capture the client's previous `(cols, rows)` before mutating at :1107-1110; **skip entirely if unchanged**. Otherwise, under the same lock: insert/overwrite `pending_wm_resizes.insert(ctx.conn_id, (cols, rows))`; if `!wm_resize_flush_scheduled`, set it, capture the channel name, `drop(guard)`, and spawn ONE detached flush task: `sleep(RESIZE_NOTIFY_DEBOUNCE)` → re-resolve channel → lock → drain the pending map + clear the flag + clone `internal_wm_caller` → send `OnUserResized` per entry. Trailing-edge semantics guarantee the final size is always delivered while intermediate drag steps collapse to ≤1 batch per 100 ms.
  - Cleanup safety: channel reaped mid-sleep → `resolve_channel` returns None → task exits (flag dies with the state); conn_id disconnected mid-window → host-side `update_size` misses → ignored.
  - Leave the existing `OnPtyResized` min-geometry broadcast (:1119-1122) untouched.

### 3. Host registration
- `src/main.rs` — add a block beside the `OnUserDisconnected` registration (:356-377): register `OnUserResized::METHOD_ID`, decode `(conn_id, cols, rows)`, `tx.try_send(UnifiedEvent::UserResized((conn_id, cols, rows)))`, encode empty response.

  - Variant `#[cfg(feature = "session-persistence")] UserResized((usize, u16, u16))` in `UnifiedEvent` (~:49).
  - New queue field `user_resized` beside `user_connected`/`user_disconnected`, cfg-gated to avoid unused-field warnings under `-D warnings`.
  - Arm in `handle_unified_poll` (:358-374 pattern): push + `frame_pacer.notify_pending` + `UnifiedPoll::RenderDue`.
  - Arm in `handle_unified_read` (:423-442 pattern): push, return `None`.
  - **Unconditional** `take_user_resized()` in the `EventSource` impl — NO cfg attribute on the method; internal branch returns accumulated events when the feature is active, `Vec::new()` otherwise.
  - Test mirroring `take_user_disconnected_drains_accumulator` (:2176).
- `crates/term-wm-core/src/io/event_source.rs`: **unconditional** trait default `take_user_resized -> Vec<(usize, u16, u16)> { Vec::new() }` (~:103) + `&mut T` blanket forwarding (:180 pattern). No cfg on either — this is what lets `runner.rs` call it unconditionally and keeps `--no-default-features` builds green.

### 5. Registry patch
- `crates/term-wm-core/src/user_registry.rs` — add `pub fn update_size(&mut self, conn_id: usize, cols: u16, rows: u16) -> bool` patching `cols`/`rows` in place via `by_conn_id`. Contract: returns `true` ONLY when the entry exists **and** `(cols, rows)` actually differ (no-op resizes and unknown conn_ids return `false` so callers never flag spurious mutations). Unit tests: hit-with-change → true / same-size no-op → false / unknown conn_id → false / overwrite applies new values.

### 6. Runner: drain + instant palette rebuild + redraw latch
The palette renders **cached menu items** built by `refresh_palette_items()` (from `all_users_by_ws`), not live registry data — so patching `user_registry` alone never changes displayed strings. The resize path must rebuild the item cache in the same iteration it patches state.

- `crates/term-wm-core/src/runner.rs`:
  - New trait method beside `on_user_registry_changed` (:100): `fn on_user_resized(&mut self, _conn_id: usize, _cols: u16, _rows: u16) -> bool { false }` — default no-op keeps other implementors compiling.
  - Prologue drain, beside `take_user_disconnected` (:501-511) — unconditional call, **guarded flagging**:
    ```rust
    for (conn_id, cols, rows) in driver.take_user_resized() {
        if app.on_user_resized(conn_id, cols, rows) {
            user_changed = true; // only for real mutations on visible palettes
        }
    }
    ```
  - Change trait method `poll_palette_tick` (:105) to return `bool` ("palette state mutated"); refresh its doc comment (it currently says "~1s", outdated since the 5 s tick).
  - Keep the latch at the call site (:529-534): `let palette_mutated = app.poll_palette_tick(); if user_changed || palette_mutated { driver.request_redraw(); }` — covers both Some(event) and idle None-branch deliveries.

### 7. App: instant rebuild + debounced reconciliation
- `src/term_wm_app.rs` — implement `on_user_resized(conn_id, cols, rows) -> bool` (delegated from `main.rs` wrapper):
  1. `if !self.wm.user_registry.update_size(conn_id, cols, rows) { return false; }` — filters unknown conn_ids and no-op resizes.
  2. Inline-patch `all_users_by_ws` in BOTH copies (app-owned field and `self.wm.all_users_by_ws`): scan `BTreeMap<String, Vec<UserEntry>>` values for the matching `conn_id`, update `cols`/`rows`. Maps are tiny (dozens of entries); O(n) scan per event is negligible and events are server-coalesced to ≤1 batch/100 ms.
  3. If `self.wm.command_menu_visible()`: `self.wm.refresh_palette_items();` — rebuilds the overlay's cached display items with the new `{cols}×{rows}` strings immediately; return `true`.
  4. If palette closed: skip the rebuild and return `false` (no frame spent while nothing shows the result; caches stay correct for next open).
- Reconciliation needs no new wiring: returning `true` sets `user_changed`, and the **existing** runner line `if user_changed { app.on_user_registry_changed(); }` (:529-531) arms the ≤2 s trailing-edge debouncer whose flush runs the authoritative IPC refresh (`refresh_workspace_cache`).
- `poll_palette_tick` (:894-935) returns `bool`, strictly edge-triggered: `true` ONLY on iterations where a mutation actually executed (`Debouncer::poll()` flush fired / ticker consumed — all consume-on-read APIs); `false` when closed or nothing expired. Two consecutive calls without intervening time MUST yield at most one `true`.
- Update `main.rs:748-752` delegation and the test `poll_palette_tick_resets_when_palette_closed` (:1337).

Resulting latency: server 100 ms coalesce → RPC transit → host drains on the next loop wake → item cache rebuilt and painted within ~150–250 ms typical, well under one frame of pacer delay. No inline IPC needed for display; the debounced flush remains as authoritative reconciliation.

## Code-review directive coverage
1. **"Trigger palette refresh on registry size mutations"** — covered by steps 6–7, superseding the proposed `app.trigger_palette_refresh()`: the runner drain loop calls `app.on_user_resized(...)`, which (a) checks `update_size()`'s return value, (b) rebuilds the palette's cached menu items **inline** via `refresh_palette_items()` in the same iteration, so the redraw paints new `{cols}×{rows}` strings rather than stale cache. The directive's debouncer-arming effect still occurs via the existing `if user_changed { app.on_user_registry_changed(); }` line (:529-531) for IPC reconciliation. Net: no stale-cache repaint window, and latency drops from ~2 s to ≲250 ms.
2. **"Guard `user_changed` assignment"** — covered: `user_changed = true` only when `on_user_resized` returns `true`, which requires `update_size()` to have found the entry AND observed an actual dimension change (step 7.1). No-op resizes and unknown conn_ids flag nothing, request no redraw, and never arm the pacer.
3. **Architecture items previously amended**: unconditional `EventSource::take_user_resized` default (`--no-default-features` safe), server-side 100 ms trailing-edge coalescing (`RESIZE_NOTIFY_DEBOUNCE`), strictly edge-triggered `poll_palette_tick -> bool`.
