# Plan: Minimal outside-click for help overlay

## Goal

When the help overlay is open and the user clicks **outside the dialog bounds**, the click should dismiss it and activate the window/panel underneath — same behavior as the command palette. No generic barrier refactoring; just add a spatial check before the existing `handle_help_event` call.

## Architecture

Keep the existing per-overlay event handlers intact. Add a bounds check before each one:

```rust
if app.wm().help_overlay_visible() {
    // Spatial check for outside-click dismissal
    if let Event::Mouse(mouse_evt) = &evt
        && matches!(mouse_evt.kind, MouseEventKind::Press(_))
        && let Some(bounds) = app.wm().help_overlay_bounds()
        && !bounds.contains(mouse_evt.column, mouse_evt.row)
    {
        app.wm().close_help_overlay();
        let mut actions = VecDeque::new();
        if !app.wm().handle_outside_click(col, row, &evt, &mut actions, None) {
            app.wm().handle_mouse_focus_click(col, row);
        }
        drain_action_queue(app, &mut actions);
        update_selection_snapshot(app);
        return flush_state_changes(...);
    }
    // Inside-click → existing handler (unchanged)
    let _ = app.wm().handle_help_event(&evt);
    ...
}
```

```rust
pub fn help_overlay_bounds(&self) -> Option<LayoutRect> {
    self.help_key
        .and_then(|key| self.overlays.get(key))
        .and_then(|o| o.render_area())
}
```

Add the outside-click block before the existing `handle_help_event` call. If the click is outside the dialog bounds, close the overlay and call `handle_outside_click`. Otherwise, fall through to the existing handler.
