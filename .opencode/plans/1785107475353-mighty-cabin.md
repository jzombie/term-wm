# Plan: Panel click support when command palette is open

## Goal

When the command palette is open and the user clicks **outside the palette bounds**, the click should:
1. Dismiss the palette
2. Route to panels, overlays, window chrome, or activate the window under the cursor — in priority order, in a single unified method.

Panels are pure UI chrome (they switch windows/tabs and never forward clicks to terminal processes), so routing clicks to them is safe from PTY event leakage.

## The Root Cause

Panel sub-elements (window title tabs, hamburger button, tiling indicator) NEVER register hitboxes into the `HitboxRegistry`. They do hit-testing internally in `on_mouse_press()` by comparing click coordinates against stored rects (`self.list.window_hits`, `self.menu_rect`, etc.). See `wm_top_panel.rs` where `render()` takes `_registry` (unused).

In normal mode, `register_panel_hitboxes()` registers the panel's outer hitbox with `ComponentOwner::Layer(layer_id)` and the `top_claimed` area. But in monocle cramped mode, `top_claimed` is empty (panels render as overlays), so this registration is skipped.

Without ANY panel hitbox in the registry, `handle_outside_click`'s `hit_test_all` can never find a panel at the click coordinates — only the full-screen Window hitbox is found.

## Architecture

### Change 1: Register panel outer hitbox in `render_overlays()`
After the panel overlay renders in monocle mode, manually register its outer hitbox with `ComponentOwner::Layer(layer_id)` and the overlay `top_area`. This gives `handle_outside_click` a panel hitbox to find.

### Change 2: `handle_outside_click` (via `hit_test_all`)
Iterates all hitboxes at position, dispatches Layer/Overlay events, focuses Chrome/Window directly.

### 2. `render_overlays` — Register panel outer hitbox in monocle mode

File: `crates/term-wm-console/src/draw_plan_renderer.rs`, after line 819

```rust
        wm.hitbox_registry_mut().merge(top_hb);

        // Extract panel metadata first (hitbox_id, layer_id) while holding
        // an immutable borrow, then register with an exclusive (mutable) borrow.
        let panel_meta = wm
            .get_semantic_component(ComponentTag::TopPanel)
            .and_then(|p| p.hitbox_id())
            .and_then(|hitbox_id| {
                wm.semantic_registry
                    .get(&ComponentTag::TopPanel)
                    .copied()
                    .map(|layer_id| (hitbox_id, layer_id))
            });

        if let Some((hitbox_id, layer_id)) = panel_meta {
            wm.hitbox_registry_mut().register(
                hitbox_id,
                ComponentOwner::Layer(layer_id),
                top_area,
            );
        }
```

Apply the same registration for the bottom panel overlay immediately below (same file, after `merge(bottom_hb)`).

### 3. Bottom panel overlay — Populate keybinding hints before render

The bottom panel overlay rendering currently calls `p.render(...)` without setting keybinding hints. Without hints, `self.hint_rects` is empty and `hit_test_hint` returns `None` for all clicks. Fix: call `process_action(SetKeybindingHints(...))` before `render()`.

File: `crates/term-wm-console/src/draw_plan_renderer.rs`, lines 850-853

Change from:
```rust
if let Some(p) = wm.get_semantic_component_mut(ComponentTag::BottomPanel) {
    let ctx = ComponentContext::new(false).with_screen_area(bottom_area);
    p.render(backend, bottom_area, &ctx, &mut bottom_hb);
}
```

To (extract hints before mutable borrow, then register hitbox after merge):
```rust
        // Extract hints before mutable borrow (borrow checker).
        let hints = wm.keybindings().bottom_hints(crate::constants::MAX_BOTTOM_HINTS);

        if let Some(p) = wm.get_semantic_component_mut(ComponentTag::BottomPanel) {
            p.process_action(&ComponentAction::SetKeybindingHints(hints));
            let ctx = ComponentContext::new(false).with_screen_area(bottom_area);
            p.render(backend, bottom_area, &ctx, &mut bottom_hb);
        }
        wm.hitbox_registry_mut().merge(bottom_hb);

        // Register bottom panel outer hitbox (borrow-decoupled pattern).
        let bottom_meta = wm
            .get_semantic_component(ComponentTag::BottomPanel)
            .and_then(|p| p.hitbox_id())
            .and_then(|hitbox_id| {
                wm.semantic_registry
                    .get(&ComponentTag::BottomPanel)
                    .copied()
                    .map(|layer_id| (hitbox_id, layer_id))
            });

        if let Some((hitbox_id, layer_id)) = bottom_meta {
            wm.hitbox_registry_mut().register(
                hitbox_id,
                ComponentOwner::Layer(layer_id),
                bottom_area,
            );
        }
```

This ensures the bottom panel has its clickable keybinding hint rects populated before rendering in monocle overlay mode.
