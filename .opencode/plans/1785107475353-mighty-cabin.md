# Plan: Single-click dismiss command palette + activate background window

## Goal

When the command palette is open and the user clicks **outside the palette bounds**, the palette should:
1. Dismiss immediately
2. The **same click** should activate the window under the cursor (focus + bring to front)

Clicking **inside the palette** (on items or background) must never propagate to windows below.

## Architecture: Explicit Bounds Hit-Testing at Runner Level

Do NOT infer click locality from `TermWmAction` values (this conflates action semantics with spatial geometry and can regress the click-through bug). Instead, query the command palette bounding box directly at the top of the event barrier in `runner.rs` before delegating to the overlay component. On outside-click, execute window focus mutation explicitly and return immediately — do NOT fall through to `dispatch_mouse` or `handle_focused_app_event`.

## Changes Required

### 1. `runner.rs` — Replace blind barrier with spatial hit-test barrier

File: `crates/term-wm-core/src/runner.rs`, lines 438-509.

Replace the current barrier:

```rust
if app.wm().command_palette_visible() {
    if let Some(action) = app.wm().handle_command_palette_event(&evt) {
        match action {
            TermWmAction::CloseMenu => {}
            // ... other actions handled, then return early ...
        }
    }
    // Focus routing while menu is open
    // ...
    update_selection_snapshot(app);
    return flush_state_changes(app, driver, ControlFlow::Continue, false, None);
}
```

With explicit bounds hit-testing:

**Fast-path spatial hit-test (bounds available):** If `command_palette_bounds()` returns `Some` with non-zero dimensions, use the bounds check directly — click outside → close palette + activate window.

**Fallback (bounds unavailable):** If `command_palette_bounds()` returns `None` (e.g. before first render), fall through to `handle_command_palette_event` which handles outside-clicks via `handle_click_outside`. No window activation is triggered from the fallback — the spatial fast path is the only path that activates windows.

```rust
if app.wm().command_palette_visible() {
    if let Event::Mouse(mouse_evt) = &evt
        && matches!(mouse_evt.kind, MouseEventKind::Press(_))
    {
        // Fast path: spatial bounds available → direct hit-test
        if let Some(palette_bounds) = app.wm().command_palette_bounds() {
            if !palette_bounds.contains(mouse_evt.column, mouse_evt.row) {
                app.wm().close_command_palette();
                app.wm().handle_mouse_focus_click(mouse_evt.column, mouse_evt.row);

                update_selection_snapshot(app);
                return flush_state_changes(app, driver, ControlFlow::Continue, false, None);
            }
        }
    }

    // Process inside-clicks and keyboard events (single invocation)
    if let Some(action) = app.wm().handle_command_palette_event(&evt) {
        match action {
            TermWmAction::CloseMenu => {}  // No-op: palette already closed
            TermWmAction::ToggleDebugWindow => app.toggle_debug_window(),
            // ... all other existing action handlers (unchanged) ...
            _ => {}
        }
    }

    // Focus routing while menu is open (Tab/Shift+Tab)
    if matches!(&evt, Event::Key(_)) && app.wm().handle_focus_event(&evt) {
        update_selection_snapshot(app);
        return flush_state_changes(app, driver, ControlFlow::Continue, false, None);
    }

    update_selection_snapshot(app);
    return flush_state_changes(app, driver, ControlFlow::Continue, false, None);
}
```

Key differences from the current code:
- Outside-click is detected by spatial bounds check **before** calling `handle_command_palette_event` (fast path)
- On outside-click (fast path): palette dismissed, `handle_mouse_focus_click` called for activation, then **return immediately** — no event leakage
- Inside-palette clicks fall through to the existing `handle_command_palette_event` logic (verbatim) — **no action-based focus trigger** is added to `CloseMenu` to avoid click-through regression
- `MouseEventKind::Press(_)` guard prevents activation on Release/Drag/Move events
- When bounds are `None` (pre-render), outside-click still works via `handle_click_outside` in the overlay, but without window activation (bounds will be populated on next render)

### 2. Add `command_palette_bounds()` to `WindowManager`

File: `crates/term-wm-core/src/window/window_manager/overlays.rs` or `mod.rs`.

The `WmCommandPaletteComponent` already caches its render area in `self.area` (type `Cell<LayoutRect>`), set during `render()`. We need a way to expose this through the facade.

**Option A (recommended):** Add a method on `WindowManager`:
```rust
pub fn command_palette_bounds(&self) -> Option<LayoutRect> {
    self.command_palette_key
        .and_then(|key| self.overlays.get(key))
        .and_then(|o| o.render_area())
}
```

Add `render_area()` to the `Overlay` trait (or use an existing method that exposes bounds).

**Option B (even simpler if render area is cached):** Track it directly in `WindowManager` — store the palette's `LayoutRect` in a field set during render. Less clean but avoids trait changes.

**Recommended: Option A.** Add a `render_area()` method to the `Overlay` trait or use `Any` downcast to access `WmCommandPaletteComponent::area()`.

### 4. `WmCommandPaletteComponent` — Cache dialog bounds (not full screen area)

**Important:** `self.area` stores the **full managed area** passed to `render()`, not the dialog bounds. The actual dialog is a **centered rectangle** computed as `content_rect` in `render()`. We need a separate field: `dialog_bounds: Cell<LayoutRect>`.

Changes to `crates/term-wm-sys-ui-components/src/wm_command_palette.rs`:

**a) Add field:**
```rust
area: Cell<LayoutRect>,
dialog_bounds: Cell<LayoutRect>,  // NEW: actual dialog rectangle
```

**b) Initialize in `new()`:**
```rust
dialog_bounds: Cell::new(LayoutRect::default()),
```

**c) Set in `render()` after computing `content_rect`:**
```rust
self.dialog_bounds.set(content_rect);
```

**d) `render_area()` returns dialog bounds (validating non-zero dimensions):**
```rust
fn render_area(&self) -> Option<LayoutRect> {
    let bounds = self.dialog_bounds.get();
    if bounds.width > 0 && bounds.height > 0 {
        Some(bounds)
    } else {
        None
    }
}
```

## Verification

1. **Outside-click**: Open palette, click outside on a window → palette closes, that window activates (focus chrome, z-order). No click forwarded to PTY.

2. **Inside-click on item**: Open palette, click menu item → palette closes, action executes, no window activation from click.

3. **Inside-click on background (between items)**: Open palette, click gap between rows → palette stays open, nothing happens.

4. **Keyboard dismissal**: Press Escape → palette closes, no window activation side-effect.

5. **Inside-item + release/drag**: Drag from inside palette → no activation.

6. **Regression test**: Run `cargo clippy --workspace --all-targets --all-features -- -D warnings` and `cargo test`.
