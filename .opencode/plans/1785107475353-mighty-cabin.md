# Plan: Panel click support when command palette is open

## Goal

When the command palette is open and the user clicks **outside the palette bounds**, the click should:
1. Dismiss the palette
2. Activate the window under the cursor (body or header) — **already implemented**
3. OR route to a panel (taskbar, status bar) if the click lands on one — **new**

Panels are pure UI chrome (they switch windows/tabs and never forward clicks to terminal processes), so routing clicks to them is safe from PTY event leakage.

## Architecture

After the palette is closed on outside-click:
1. `handle_mouse_focus_click(col, row)` handles window activation (already works)
2. A single-hit `dispatch_mouse` call is made, but only `ComponentOwner::Layer` results are processed — `ComponentOwner::Window` and `ComponentOwner::Overlay` hits are treated as `Ignored` to prevent PTY leakage.

This reuses the existing hitbox registry (which already has panel sub-hitboxes registered from the render pass) and the existing dispatch logic, avoiding any duplication.

## Changes

### 1. `WindowManager` — Add `dispatch_panel_event()` method

File: `crates/term-wm-core/src/window/window_manager/mod.rs`

New method that runs a single hit-test on the registry and, if the hit is a panel (`ComponentOwner::Layer`), dispatches the event using the same pattern as `dispatch_mouse` (lines 1792-1810):

```rust
/// After palette dismissal, route a mouse event to panels if the click
/// landed on one. Only Layer-owned hitboxes are processed — Window and
/// Overlay hits are ignored to prevent PTY event leakage.
pub fn dispatch_panel_event(&mut self, event: &Event, col: u16, row: u16) {
    let position = MousePosition { column: col as i16, row: row as i16, coord_space: CoordSpace::Screen };
    let Some((hitbox_id, owner, hit_rect)) = self.hitbox_registry.hit_test(position) else {
        return;
    };
    let ComponentOwner::Layer(layer_id) = owner else {
        return; // Only route to layers (panels), skip windows/overlays
    };
    let core_event = crate::events::core_event_to_wm(event);
    let Some(core_event) = core_event else { return };
    let ctx = self
        .component_context(false)
        .with_screen_area(hit_rect)
        .with_active_hitbox(hitbox_id);
    if let Some(layer_comp) = self.layer_manager.get_mut(layer_id) {
        let _ = layer_comp.handle_events(&core_event, &ctx);
    }
}
```

**Note:** This is safe because the palette was already closed before this method is called (via `close_command_palette`), so overlay hitboxes are gone. The only remaining hitboxes are windows (skipped) and layers/panels (dispatched).

### 2. `runner.rs` — Add panel dispatch after window activation

File: `crates/term-wm-core/src/runner.rs`, spatial fast-path block (lines 444-460)

```rust
if !palette_bounds.contains(mouse_evt.column, mouse_evt.row) {
    app.wm().close_command_palette();
    app.wm().handle_mouse_focus_click(mouse_evt.column, mouse_evt.row);
    // Route to panels if click landed on one (safe: no PTY forwarding)
    app.wm().dispatch_panel_event(&evt, mouse_evt.column, mouse_evt.row);
    update_selection_snapshot(app);
    return flush_state_changes(app, driver, ControlFlow::Continue, false, None);
}
```
