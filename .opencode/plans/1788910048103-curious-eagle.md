# Plan: oxdock as Optional Interpreter for term-wm Tasks (JSON-first v1)

## Goal
Run OxDock scripts through a bundled in-process interpreter, declared from the existing `tasks.json` format. No new task-file discovery in v1; script files live wherever the repo keeps them (e.g. `scripts/*.oxfile`).

## Background (researched)
- Open PRs in `jzombie/term-wm`: #335 is the copy/paste PR (`--util copy` + `{wm.exe}` placeholder, shared `copy::run_copy_util`, `LoadTasksResult::Found/NotFound/ParseError`); also #339 (signal-killed messages), #340 (reject invalid CLI flags), #342 (dependabot smallvec).
- `jzombie/rust-oxdock` v0.10.0-alpha: Dockerfile-inspired DSL (`oxdock <PATH>`, `--script`, stdin). SNAPSHOT workspace by default, `WORKSPACE LOCAL` for in-place work, `RUN` is the only non-portable command, `INHERIT_ENV` gates host env, `{{ env:KEY }}` templates.
- Current engine (`crates/term-wm-core/src/project_tasks.rs`, `docs/tasks.md`, `src/cli.rs`, `src/term_wm_app.rs`): flat JSONC array, `command` shell-words split + `args`, `cwd`, `env`, `environments`, `platforms`, `{wm.pid}` (plus `{wm.exe}` after #335), direct-argv spawn, palette + `--list-tasks` / `--task`.

## User decisions (confirmed, revised)
- Optional cargo feature, enabled by default; oxdock wired as optional library dependency (bundled, in-process eval).
- v1 keeps tasks in JSON only: add one script-pointer field to the existing schema rather than auto-discovering `.term-wm/*.oxfile`.
- Oxdock script files live outside `tasks.json` (repo-relative paths), resolved like `cwd`.
- Assume PR #335 merges first so `{wm.pid}` / `{wm.exe}` can be passed into oxdock scripts.
- Keep the direct CLI escape hatch (`term-wm --oxdock <PATH>`) on the same evaluator, since it is cheap and matches the earlier ask.

## Proposed design (recommended only)

### 1. Feature and dependency
- Root `Cargo.toml`: add `oxdock-core` (+ `oxdock-parser` only if needed) as workspace deps pinned like other deps.
- `crates/term-wm-core/Cargo.toml`: new `oxdock` feature with `dep:oxdock-core`; root re-exports `oxdock = ["term-wm-core/oxdock"]` and adds it to `default`. Feature-off behavior mirrors `project-tasks`: schema field parses but task is hidden with a warning, CLI errors cleanly. No `unwrap` (clippy `unwrap_used = deny`).

### 2. Schema: one new field
- `ProjectTaskConfig` gains `#[serde(default)] pub oxdock: Option<String>` (path to `.oxfile`, substitution-aware, relative to task root or absolute).
- Validation rule (document in `docs/tasks.md`): `oxdock` is mutually exclusive with `command`/`args`. If combined, task is invalid (hidden from palette, `--task` refuses with a clear error). This keeps v1 clean and avoids precedence debates.
- `environments`, `platforms`, `cwd`, `env` keep working unchanged, so gating and working dir come for free.

### 3. Placeholder and env bridging (needs #335)
- `substitute_vars` already handles `{wm.pid}` / `{wm.exe}` in `oxdock`, `cwd`, and `env` values. Reuse it verbatim.
- Before eval, inject `TERM_WM_PID` and `TERM_WM_EXE` into the oxdock script env (explicit `ENV` prelude, not `INHERIT_ENV`), documenting `{{ env:TERM_WM_PID }}` / `{{ env:TERM_WM_EXE }}` as the oxdock-side spelling. Task `env` entries layer on top.
- Run with `WORKSPACE LOCAL` rooted at the resolved task root so `RUN` / `WRITE` / `COPY` act on the live repo, not the SNAPSHOT temp dir. Document this.

### 4. Execution: one evaluator, two entries
- New `crates/term-wm-core/src/oxdock_runner.rs`: `run_oxdock_script(script_path, cwd, env, ctx: &TaskVarContext) -> Result<exit_code>` plus consts (`OXDOCK_FIELD`, `TERM_WM_PID`, `TERM_WM_EXE`); no magic strings per AGENTS.md.
- `resolve_task` gains an oxdock branch returning a resolved script path instead of argv; launchers branch on it:
  - Palette (`src/term_wm_app.rs`): open task window titled with label, run evaluator, keep existing finished-toast behavior.
  - CLI (`src/cli.rs`, `src/main.rs`): `--task` runs it headless with inherited stdio and exit-code propagation; new `--oxdock <PATH>` flag runs any file directly through the same function (headless dispatch next to `--util`, before WM/gateway startup).

### 5. Files to touch
- `Cargo.toml`, `crates/term-wm-core/Cargo.toml` (deps + default-on `oxdock` feature).
- `crates/term-wm-core/src/project_tasks.rs` (field, validation, substitution on the path).
- New `crates/term-wm-core/src/oxdock_runner.rs` (evaluator, bridging, tests).
- `src/cli.rs`, `src/main.rs` (`--oxdock` flag + dispatch, `--task`/`--list-tasks` oxdock display).
- `src/term_wm_app.rs` (oxdock run branch, reuse parse-error notification pattern from #335).
- `docs/tasks.md`, `.term-wm/tasks.json` header comment, `CHANGELOG.md` (Unreleased Added entry).

### 6. Out of scope for v1
- No `.term-wm/*.oxfile` auto-discovery; no `interpreter:` enum; no per-script platform/guard parsing (use task-level `platforms`).
- No sandbox beyond oxdock `oxdock-fs`; document `RUN` can touch the host.
