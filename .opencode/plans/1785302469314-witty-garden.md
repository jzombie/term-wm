# Plan: Fix Terminal Bottom-Row Loss on Vertical Shrink & Bouncy Scrollbar

## Issue 1 — Bottom n rows deleted from visual buffer on vertical shrink

### Root Cause
vt100 `grid.set_size()` (0.16.2) calls `self.rows.resize(new_rows, ...)` at `grid.rs:81`, which **truncates rows from the end** — the bottom N rows of the viewport are dropped without being pushed into scrollback.

### Fix: Pre-scroll in `Pty::resize()` with DECSTBM reset

**File:** `crates/term-wm-pty-engine/src/pty.rs` — `Pty::resize()` line 249

When `new_rows < self.pty_size.rows`, before calling `set_size()`:

```rust
if new_rows < self.pty_size.rows {
    let delta = self.pty_size.rows - new_rows;
    // Reset DECSTBM to full screen (standard SIGWINCH behavior — old margins
    // reference stale row indices; apps re-query size and re-set margins).
    guard.process(b"\x1b[r");
    // SU = scroll content up (pushes top delta rows into scrollback,
    //      adds delta empty rows at bottom)
    // CUU = move cursor up to stay anchored to its content line
    let seq = format!("\x1b[{delta}S\x1b[{delta}A");
    guard.process(seq.as_bytes());
}
guard.screen_mut().set_size(new_rows, new_cols);
```

**Why this works:**
1. `\x1b[r` resets DECSTBM to full screen, ensuring SU scrolls the entire viewport (not a sub-region). This is the standard terminal emulator behavior on SIGWINCH — old margins reference stale row indices and must be reset. Applications like `vim`/`tmux` receive SIGWINCH and re-set margins.
2. `\x1b[<delta>S` (SU) scrolls content up by `delta` rows → top `delta` rows enter scrollback, `delta` blank rows appear at bottom
3. `\x1b[<delta>A` (CUU) moves cursor up by `delta` rows → cursor tracks its content line (SU does NOT move cursor)
4. `set_size(new_rows, new_cols)` truncates the blank rows from the bottom → original bottom content preserved

**No vt100 crate patching needed** — no fork, no new accessors.

## Issue 2 — Bouncy Scrollbar (Layout Thrashing)

### Root Cause
`ScrollViewComponent::render()` starts every frame assuming `needs_vertical = false`. Pass 1 renders at full width W. If content overflows at W, pass 2 renders at W-1. This triggers **two child renders per frame**. For reflowing children (markdown viewer), the W-1 render can increase line wraps, making `content_h` at W-1 larger than at W — creating oscillation.

### Fix: Persistent scroll state + scratch-buffer probe + state restore

**File:** `crates/term-wm-core/src/component_context.rs` — Add `last_needs_vertical: bool` and `last_needs_horizontal: bool` to `ScrollBounds`

**File:** `crates/term-wm-ui-components/src/scroll_view.rs` — Modify `ScrollViewComponent::render()`:

**Part A — Seed pass 1 from persistent state (prevents dual-resize):**
```rust
let mut needs_vertical = state.last_needs_vertical;
let mut needs_horizontal = state.last_needs_horizontal;
```

**Part B — Probe at unconstrained width using a scratch buffer:**
```rust
loop {
    let inner_area = self.compute_layout(area, needs_vertical, needs_horizontal);

    // Render child at inner_area into live backend...
    self.content.borrow_mut().render(backend, inner_area, &child_ctx, registry);
    // ...read content_w, content_h from state...

    if needs_vertical {
        // If content at W-1 is near viewport boundary, probe at full width W
        // to avoid latching (wrapping at W-1 may inflate content_h).
        if content_h <= outer_area.height as usize + 2 {
            let probe_area = self.compute_layout(area, false, false);
            let mut scratch = Buffer::empty(probe_area);
            // Probe into scratch buffer to avoid corrupting live framebuffer
            self.content.borrow_mut().render(
                &mut RatatuiBackend::new_simple(scratch, probe_area),
                probe_area, &probe_ctx, registry,
            );
            let unconstrained_h = state.content_height;

            if unconstrained_h <= outer_area.height as usize {
                // Content fits at full width — turn off scrollbar
                needs_vertical = false;
                // Re-render into real backend at full width W
                let inner_area = self.compute_layout(area, false, needs_horizontal);
                continue;
            }
            // Probe failed: restore child state to W-1.
            // (Scratch probe may have resized PTY; re-render at W-1 fixes it.)
            let inner_area = self.compute_layout(area, true, needs_horizontal);
            self.content.borrow_mut().render(backend, inner_area, &child_ctx, registry);
        }
    } else if content_h > inner_area.height as usize {
        needs_vertical = true;
        let inner_area = self.compute_layout(area, true, needs_horizontal);
        continue; // re-render with scrollbar ON
    }

    // ...determine retry_vertical / retry_horizontal / offset_changed...
    break;
}
```

**Why scratch buffer + restore:**
- Probe into scratch avoids corrupting the live `backend` if the probe render writes cells at column W (the scrollbar gutter column)
- If probe fails (scrollbar still needed), explicit re-render at W-1 restores PTY dimensions and framebuffer state
- If probe succeeds, continue re-renders at full width W
