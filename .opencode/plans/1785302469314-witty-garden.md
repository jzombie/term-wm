# Plan: Fix Terminal Bottom-Row Loss on Vertical Shrink & Bouncy Scrollbar

## Issue 1 — Bottom n rows deleted from visual buffer on vertical shrink

### Root Cause
vt100 `grid.set_size()` (0.16.2) calls `self.rows.resize(new_rows, ...)` at `grid.rs:81`, which **truncates rows from the end** — the bottom N rows of the viewport are dropped without being pushed into scrollback.

### Fix: Pre-scroll in `Pty::resize()` with scroll-region guard

**File:** `crates/term-wm-pty-engine/src/pty.rs` — `Pty::resize()` line 249

When `new_rows < self.pty_size.rows`, inject SU + CUU **only when no custom DECSTBM scroll region is active**, then call `set_size()`:

```rust
if new_rows < self.pty_size.rows {
    let delta = self.pty_size.rows - new_rows;
    // Guard: only pre-scroll if no custom DECSTBM margins are active.
    // TUI apps (tmux, vim, less, htop) set scroll regions; injecting SU
    // would scroll within the sub-region and corrupt the screen.
    if !guard.screen().scroll_region_active() {
        // SU = scroll content up (pushing top delta rows into scrollback)
        // CUU = move cursor up to stay anchored to its text line
        let seq = format!("\x1b[{delta}S\x1b[{delta}A");
        guard.process(seq.as_bytes());
    }
}
guard.screen_mut().set_size(new_rows, new_cols);
```

**Why both sequences:** `SU` scrolls viewport up by `delta` rows → top rows enter scrollback, blank rows appear at bottom. `CUU` moves cursor up by `delta` (SU does NOT move the cursor). Then `set_size()` truncates the blank rows from bottom, preserving original bottom content.

- Add test: write N lines, shrink viewport by K, verify line N is still at bottom and line 0 moved to scrollback
- Add test: with custom scroll region active, verify resize doesn't corrupt

## Issue 2 — Bouncy Scrollbar (Layout Thrashing)

### Root Cause
`ScrollViewComponent::render()` starts every frame assuming `needs_vertical = false`, forcing pass 1 at full width W. If the terminal overflows at W, a second pass runs at W-1. This triggers **two `pane.resize()` calls per frame** — layout churn that causes the scrollbar to flicker and the terminal to reflow repeatedly.

### Fix: Persistent scroll state + unconstrained-width deoscillation

**File:** `crates/term-wm-core/src/component_context.rs` — Add `last_needs_vertical: bool` and `last_needs_horizontal: bool` to `ScrollBounds`

**File:** `crates/term-wm-ui-components/src/scroll_view.rs` — Modify `ScrollViewComponent::render()`:

**Part A — Seed pass-1 layout from persistent state (prevents dual-resize):**
```rust
// Seed pass 1 with last frame's scrollbar state to avoid double-resize thrashing.
let mut needs_vertical = state.last_needs_vertical;
let mut needs_horizontal = state.last_needs_horizontal;
```

**Part B — De-oscillate using unconstrained-width check (no artificial slack):**
```rust
// Only disable scrollbar if content at UNCONSTRAINED width fits viewport.
// This prevents the oscillation: scrollbar ON → W-1 → content reflows →
// content_height may change → but we check: "would it still need scrollbar at W?"
// If not, turn it off. If yes, keep it on.
if needs_vertical {
    // Check content height at full width (no scrollbar gutter)
    // If it fits without scrollbar, we can safely turn it off
    if unconstrained_content_h <= outer_area.height as usize {
        needs_vertical = false;
    }
} else if !needs_vertical && content_h > inner_area.height as usize {
    needs_vertical = true;
}

state.last_needs_vertical = needs_vertical;
```

Where `unconstrained_content_h` is the child's content height when rendered at full width (without scrollbar gutter). For terminals, this is equivalent to `content_h` since terminals don't reflow text — the key fix is Part A (seeding from persistent state) which eliminates the double-resize per frame.
