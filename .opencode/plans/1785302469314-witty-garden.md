# Plan: Fix Bouncy Scrollbar & Prompt Duplication on Drag

## Issue 1 — Prompt duplication during window drag

### Root Cause
Previous code injected `SU` (`\x1b[S`) unconditionally on every vertical shrink, regardless of cursor position. If the cursor is at row 5 and the viewport shrinks from 30 to 24, the bottom 6 rows are empty (`new_row()` blanks) — no shift needed. Unconditional shifting forced text off the top of the screen and created an artificial gap that Zsh filled with duplicate prompts on SIGWINCH.

### Fix: Cursor-bounded SU injection

**File:** `crates/term-wm-pty-engine/src/pty.rs`

Only inject `SU` when the cursor is below the new viewport height. The shift amount is `cursor_row - new_rows + 1` (the minimum needed to keep the cursor visible). No debouncing needed — guard eliminates spurious SU entirely.

```rust
let old_rows = self.pty_size.rows;
let new_rows = size.rows;
let (cursor_row, _) = guard.screen().cursor_position();

if new_rows < old_rows && !self.tracker.has_custom_margins() {
    if cursor_row >= new_rows as u16 {
        let scroll_lines = cursor_row - new_rows as u16 + 1;
        let seq = format!("\x1b[{scroll_lines}S");
        guard.process(seq.as_bytes());
    }
}
guard.screen_mut().set_size(new_rows, size.cols);
```

**Why this works:** When dragging the window border down by 10 rows, the cursor moves with the viewport. If the cursor is at row 29 (bottom) and the viewport shrinks by 1 to 29, `cursor_row (29) >= new_rows (29)` → shift by 1. Next frame, cursor is at row 28 (shifted by SU), viewport shrinks to 28, `cursor_row (28) >= new_rows (28)` → shift by 1. Each frame shifts exactly 1 row. The shell only receives SIGWINCH once per frame, sees the cursor at the bottom (after SU's automatic cursor decrement), and draws zero corrective newlines. No duplication.

When the cursor is above the new viewport height (e.g., cursor at row 5, shrink to 24), `cursor_row (5) < new_rows (24)` → no SU. The bottom 6 rows (which are empty `new_row()` blanks) are truncated cleanly.

**No debounce, no vt100 patch, no Cargo.toml change, no vendor directory.**

### Files Changed (Issue 1)

| File | Change |
|------|--------|
| `crates/term-wm-pty-engine/src/pty.rs` | Cursor-bounded SU injection (only when cursor occluded by new height) |

## Issue 2 — Bouncy Scrollbar (Layout Thrashing)

### Root Cause
`ScrollViewComponent::render()` starts every frame assuming `needs_vertical = false`, forcing pass 1 at width W and pass 2 at W-1 — dual child renders per frame. For reflowing children this creates oscillation.

### Fix: Seed pass-1 from persistent state; passive bounds for OFF-transition; monotonic attempt counter

**File:** `crates/term-wm-core/src/component_context.rs` — Add `last_needs_vertical: bool` and `last_needs_horizontal: bool` to `ScrollBounds`

**File:** `crates/term-wm-ui-components/src/scroll_view.rs` — Two changes:

**Change 1 — `compute_layout` accepts explicit scrollbar state:
```rust
pub(crate) fn compute_layout(&self, area: LayoutRect, needs_vertical: bool, needs_horizontal: bool) -> LayoutRect {
    let mut view_w = area.width;
    let mut view_h = area.height;
    if needs_vertical && view_w > 0 { view_w = view_w.saturating_sub(1); }
    if needs_horizontal && view_h > 0 { view_h = view_h.saturating_sub(1); }
    LayoutRect { x: area.x, y: area.y, width: view_w, height: view_h }
}
```

**Change 2 — Render loop seeds from persistent state; monotonic attempt (no reset):**
```rust
// Before loop:
let mut needs_vertical = {
    let state = self.scroll_state.borrow();
    state.last_needs_vertical
};
let mut needs_horizontal = {
    let state = self.scroll_state.borrow();
    state.last_needs_horizontal
};

// Inside loop, after child render:
if needs_vertical {
    // OFF-transition: only when content at W-1 fits strictly
    if content_h <= inner_area.height as usize {
        needs_vertical = false;
        attempt += 1;
        if attempt < MAX_ATTEMPTS { continue; }
    }
} else {
    if inner_area.height > 0 && content_h > inner_area.height as usize {
        needs_vertical = true;
        attempt += 1;
        if attempt < MAX_ATTEMPTS { continue; }
    }
}

// After loop, before scrollbar paint:
{
    let mut state = self.scroll_state.borrow_mut();
    state.last_needs_vertical = needs_vertical;
    state.last_needs_horizontal = needs_horizontal;
}
```

Also update `on_mouse`'s `compute_layout(sa)` call to pass `last_needs_vertical/horizontal`.

**Monotonic attempt counter** (no `attempt = 0` reset): prevents infinite loop on oscillating content. MAX_ATTEMPTS (3) bounds the retry budget.

**No speculative probes, no scratch buffers, no SIGWINCH flooding.**

| `crates/term-wm-ui-components/src/scroll_view.rs` | Seed pass-1 from persistent state; passive OFF-transition; `compute_layout` signature change |

#### 1. `cursor_bounded_shrink_preserves_bottom_when_cursor_at_bottom`

Add to `crates/term-wm-pty-engine/src/pty.rs` test module:

```rust
#[test]
fn cursor_bounded_shrink_preserves_bottom_when_cursor_at_bottom() {
    let mut parser = vt100::Parser::new(30, 80, 200);
    for i in 0..30 {
        parser.process(format!("line {i}\r\n").as_bytes());
    }
    // Cursor is at row 29 (bottom) after 30 \n's
    parser.process(b"LASTLINE");

    let (cursor_row, _) = parser.screen().cursor_position();
    let new_rows: u16 = 24;
    assert_eq!(cursor_row, 29, "cursor at bottom row");

    // Cursor (29) >= new_rows (24) → shift 29-24+1 = 6 rows
    let scroll_lines = cursor_row - new_rows + 1;
    assert_eq!(scroll_lines, 6);
    parser.process(format!("\x1b[{}S", scroll_lines).as_bytes());
    parser.screen_mut().set_size(new_rows, 80);

    assert!(parser.screen().contents().contains("LASTLINE"),
        "bottom content preserved when cursor at bottom");
    assert_eq!(parser.screen().size(), (24, 80));
}
```
