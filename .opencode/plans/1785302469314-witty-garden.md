# Plan: Fix Bouncy Scrollbar & Terminal Bottom-Row Loss on Shrink

## Issue 1 — Bottom row loss on shrink

### Root Cause
vt100 `grid.set_size()` calls `self.rows.resize(new_rows, ...)` (grid.rs:81) which truncates bottom N rows of the viewport without pushing them into scrollback. Synthetic ANSI sequence injection (`SU`/`CUU`) via `guard.process()` desyncs the shell's internal cursor tracking from the emulator's state, causing prompt duplication on `SIGWINCH`.

### Fix: Patch vt100 `set_size` to migrate truncated rows to scrollback

**File:** `patches/vt100-0.16.2/src/grid.rs` — modify `set_size()` to push rows that would be truncated into the scrollback VecDeque before truncating.

Replace `self.rows.resize(usize::from(size.rows), self.new_row())` (line 81) with:

```rust
let new_len = usize::from(size.rows);
let old_len = self.rows.len();
if new_len < old_len {
    let delta = old_len - new_len;
    // Only migrate rows when no custom DECSTBM margins are active.
    // TUI apps (vim, tmux) set margins and manage their own layout.
    if !self.scroll_region_active() {
        for _ in 0..delta {
            let row = self.rows.remove(0);
            if self.scrollback_len > 0 {
                self.scrollback.push_back(row);
                while self.scrollback.len() > self.scrollback_len {
                    self.scrollback.pop_front();
                }
                if self.scrollback_offset > 0 {
                    self.scrollback_offset =
                        self.scrollback.len().min(self.scrollback_offset + 1);
                }
            }
            self.rows.push(self.new_row());
        }
        // Decrement cursor.row by delta so cursor tracks its content line
        let u16_delta = u16::try_from(delta).unwrap_or(u16::MAX);
        self.pos.row = self.pos.row.saturating_sub(u16_delta);
    }
    self.rows.truncate(new_len);
} else {
    self.rows.resize(new_len, self.new_row());
}
```

This is a direct grid memory operation — no synthetic ANSI bytes, no parser involvement, no shell cursor desync. It removes the top `delta` rows from the viewport Vec, appends them to the scrollback VecDeque, and adds blank rows at the bottom. The `truncate` then removes the blank rows, keeping the original bottom content visible.

**Cargo.toml:** Add `[patch.crates-io]` section pointing to `patches/vt100-0.16.2`.

**Pty::resize():** Revert to pure `set_size()` + `master.resize()` — no sequence injection.

## Issue 2 — Bouncy Scrollbar (Layout Thrashing)

### Root Cause
`ScrollViewComponent::render()` starts every frame assuming `needs_vertical = false`, forcing pass 1 at width W and pass 2 at W-1 — dual child renders per frame. For reflowing children this creates oscillation.

### Fix: Seed pass-1 from persistent state; passive bounds for OFF-transition; monotonic attempt counter

**File:** `crates/term-wm-core/src/component_context.rs` — Add `last_needs_vertical: bool` and `last_needs_horizontal: bool` to `ScrollBounds`

**File:** `crates/term-wm-ui-components/src/scroll_view.rs` — Two changes:

**Change 1 — `compute_layout` accepts explicit scrollbar state:
```rust
pub(crate) fn compute_layout(&self, area: LayoutRect, needs_vertical: bool, needs_horizontal: bool) -> LayoutRect {
    let mut view_w = area.width;
    let mut view_h = area.height;
    if needs_vertical && view_w > 0 { view_w = view_w.saturating_sub(1); }
    if needs_horizontal && view_h > 0 { view_h = view_h.saturating_sub(1); }
    LayoutRect { x: area.x, y: area.y, width: view_w, height: view_h }
}
```

**Change 2 — Render loop seeds from persistent state; monotonic attempt (no reset):**
```rust
// Before loop:
let mut needs_vertical = {
    let state = self.scroll_state.borrow();
    state.last_needs_vertical
};
let mut needs_horizontal = {
    let state = self.scroll_state.borrow();
    state.last_needs_horizontal
};

// Inside loop, after child render:
if needs_vertical {
    // OFF-transition: only when content at W-1 fits strictly
    if content_h <= inner_area.height as usize {
        needs_vertical = false;
        attempt += 1;
        if attempt < MAX_ATTEMPTS { continue; }
    }
} else {
    if inner_area.height > 0 && content_h > inner_area.height as usize {
        needs_vertical = true;
        attempt += 1;
        if attempt < MAX_ATTEMPTS { continue; }
    }
}

// After loop, before scrollbar paint:
{
    let mut state = self.scroll_state.borrow_mut();
    state.last_needs_vertical = needs_vertical;
    state.last_needs_horizontal = needs_horizontal;
}
```

Also update `on_mouse`'s `compute_layout(sa)` call to pass `last_needs_vertical/horizontal`.

**Monotonic attempt counter** (no `attempt = 0` reset): prevents infinite loop on oscillating content. MAX_ATTEMPTS (3) bounds the retry budget.

**No speculative probes, no scratch buffers, no SIGWINCH flooding.**

| `crates/term-wm-ui-components/src/scroll_view.rs` | Seed pass-1 from persistent state; passive OFF-transition; `compute_layout` signature change |

```rust
#[test]
fn shrink_grid_preserves_bottom_rows() {
    let mut parser = vt100::Parser::new(30, 80, 200);

    for i in 0..30 {
        parser.process(format!("line {i}\r\n").as_bytes());
    }
    parser.process(b"BOTTOMLINE");

    // Shrink viewport from 30 to 24
    parser.screen_mut().set_size(24, 80);

    // Scrollback should have grown (delta = 6 rows moved to scrollback)
    parser.screen_mut().set_scrollback(usize::MAX);
    let sb = parser.screen().scrollback();
    assert!(sb >= 6, "at least 6 rows should be in scrollback after shrink");

    // Reset to bottom and verify bottom content is visible
    parser.screen_mut().set_scrollback(0);
    let visible = parser.screen().contents();
    assert!(visible.contains("BOTTOMLINE"),
        "bottom content must be visible after shrink");
    assert_eq!(parser.screen().size(), (24, 80),
        "viewport should be 24 rows after shrink");
}
```

#### Test 2 — `term_scroll_sync_shrink_then_expand_no_duplication`

Add to `crates/term-wm-ui-components/src/terminal.rs` test module (uses existing `make_term_with_content` helper from the test module):

```rust
#[test]
fn shrink_then_expand_no_duplication() {
    let mut term = TerminalComponent::from_pane(Box::new(TestPane::new(200)));
    let area30 = LayoutRect { x: 0, y: 0, width: 80, height: 30 };
    let area24 = LayoutRect { x: 0, y: 0, width: 80, height: 24 };
    let (handle, _shared) = make_handle();
    let ctx30 = ComponentContext::new(true)
        .with_viewport(ScrollViewport { offset_x:0, offset_y:0, width:80, height:30 }, Some(handle.clone()));
    let ctx24 = ComponentContext::new(true)
        .with_viewport(ScrollViewport { offset_x:0, offset_y:0, width:80, height:24 }, Some(handle.clone()));

    // Write 30 lines + a bottom marker
    let mut pane = term.pane.borrow_mut();
    for i in 0..30 { pane.write_bytes(format!("line {i}\r\n").as_bytes()).ok(); }
    pane.write_bytes(b"BOTTOMMARKER").ok();
    drop(pane);

    // Render at 30 -> triggers pane.resize(30)
    render_term(&mut term, area30, &ctx30);
    // Shrink -> triggers pane.resize(24)
    render_term(&mut term, area24, &ctx24);
    // Expand -> triggers pane.resize(30)
    render_term(&mut term, area30, &ctx30);

    let pane = term.pane.borrow();
    let parser = pane.shared_parser().lock().unwrap();
    let contents = parser.screen().contents();

    // "BOTTOMMARKER" should appear exactly once, at the bottom
    assert_eq!(contents.matches("BOTTOMMARKER").count(), 1,
        "bottom marker must not be duplicated after shrink+expand cycle");
    assert!(contents.trim_end().ends_with("BOTTOMMARKER"),
        "bottom marker must be at the last line of content");
}

fn render_term(term: &mut TerminalComponent, area: LayoutRect, ctx: &ComponentContext) {
    let rect = layout_rect_to_clipped_rect(area);
    let mut buffer = Buffer::empty(rect);
    let mut backend = RatatuiBackend::new_simple(buffer, rect);
    let mut registry = HitboxRegistry::new(area);
    term.render(&mut backend, area, ctx, &mut registry);
}
```
