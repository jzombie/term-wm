# Plan: Fix Terminal Bottom-Row Loss on Vertical Shrink & Bouncy Scrollbar

## Issue 1 — Bottom n rows deleted from visual buffer on vertical shrink

### Root Cause
vt100 `grid.set_size()` calls `self.rows.resize(new_rows, ...)` which truncates bottom N rows of the viewport without pushing them into scrollback.

### Fix: Pre-scroll in `Pty::resize()`, guard via existing tracker

**File:** `crates/term-wm-pty-engine/src/pty.rs` — `Pty::resize()` line 249

`PtyStateTracker` already tracks `has_custom_margins` via DECSTBM parsing in `PtyPerformAdapter::csi_dispatch`. Use it to guard SU injection — **no vt100 fork needed**:

```rust
// After the size change check, before master.resize:
if size.rows < self.pty_size.rows && !self.tracker.has_custom_margins() {
    let delta = self.pty_size.rows - size.rows;
    let seq = format!("\x1b[{delta}S\x1b[{delta}A");
    guard.process(seq.as_bytes());
}
```

`\x1b[<delta>S` (SU) scrolls content up by delta rows → top rows enter scrollback, blank rows at bottom. `\x1b[<delta>A` (CUU) moves cursor up. Then `set_size()` truncates blank rows, preserving bottom content. When custom margins are active (vim/tmux), the guard skips injection and `set_size()` runs directly — the app handles SIGWINCH.

### Testing
- Fix `TestPane::resize` (no-op at `terminal.rs:1201`) to call `self.set_parser_size(size.rows, size.cols)` so render-invoked resize is exercised
- Add test: fill N rows, shrink viewport by K, verify N-1 is at bottom and row 0 is in scrollback

## Issue 2 — Bouncy Scrollbar (Layout Thrashing)

### Root Cause
`ScrollViewComponent::render()` starts every frame assuming `needs_vertical = false`, forcing pass 1 at width W and pass 2 at W-1 — dual child renders per frame. For reflowing children this creates oscillation.

### Fix: Seed pass-1 from persistent state; passive bounds for OFF-transition

**File:** `crates/term-wm-core/src/component_context.rs` — Add `last_needs_vertical: bool` and `last_needs_horizontal: bool` to `ScrollBounds`

**File:** `crates/term-wm-ui-components/src/scroll_view.rs` — Two changes:

**Change 1 — `compute_layout` accepts explicit scrollbar state:**
```rust
pub(crate) fn compute_layout(&self, area: LayoutRect, needs_vertical: bool, needs_horizontal: bool) -> LayoutRect {
    let mut view_w = area.width;
    let mut view_h = area.height;
    if needs_vertical && view_w > 0 { view_w = view_w.saturating_sub(1); }
    if needs_horizontal && view_h > 0 { view_h = view_h.saturating_sub(1); }
    LayoutRect { x: area.x, y: area.y, width: view_w, height: view_h }
}
```

**Change 2 — Render loop seeds from persistent state:**
```rust
// Before loop:
let mut needs_vertical = {
    let state = self.scroll_state.borrow();
    state.last_needs_vertical
};
let mut needs_horizontal = {
    let state = self.scroll_state.borrow();
    state.last_needs_horizontal
};

// Inside loop, after child render:
if needs_vertical {
    // OFF-transition: only when content at W-1 fits strictly
    if content_h <= inner_area.height as usize {
        needs_vertical = false;
        attempt = 0;
        continue; // re-render at full width W
    }
} else {
    if inner_area.height > 0 && content_h > inner_area.height as usize {
        needs_vertical = true;
        attempt = 0;
        continue;
    }
}

// After loop, before scrollbar paint:
{
    let mut state = self.scroll_state.borrow_mut();
    state.last_needs_vertical = needs_vertical;
    state.last_needs_horizontal = needs_horizontal;
}
```

Also update `on_mouse`'s `compute_layout(sa)` call to pass `last_needs_vertical/horizontal`.

**No speculative probes, no scratch buffers, no SIGWINCH flooding.**
