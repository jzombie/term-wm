# Plan: Fix Terminal Bottom-Row Loss on Vertical Shrink & Bouncy Scrollbar

## Issue 1 — Bottom n rows deleted from visual buffer on vertical shrink

### Root Cause
vt100 `grid.set_size()` calls `self.rows.resize(new_rows, ...)` which truncates bottom N rows of the viewport without pushing them into scrollback.

### Fix: Pre-scroll in `Pty::resize()`, guard via existing tracker

**File:** `crates/term-wm-pty-engine/src/pty.rs` — `Pty::resize()` line 249

`PtyStateTracker` already tracks `has_custom_margins` via DECSTBM parsing in `PtyPerformAdapter::csi_dispatch`. Use it to guard SU injection — **no vt100 fork needed**:

```rust
let old_rows = self.pty_size.rows;
let new_rows = size.rows;

if new_rows < old_rows && !self.tracker.has_custom_margins() {
    // SHRINK: Push top rows into scrollback, move cursor up.
    // Then set_size truncates blank rows added at bottom, preserving content.
    let delta = old_rows - new_rows;
    let seq = format!("\x1b[{delta}S\x1b[{delta}A");
    guard.process(seq.as_bytes());
    guard.screen_mut().set_size(new_rows, size.cols);
} else if new_rows > old_rows && !self.tracker.has_custom_margins() {
    // EXPAND: set_size appends blank rows at bottom. Pull scrollback
    // rows back into viewport (SD) and move cursor down (CUD) so the
    // prompt isn't stranded mid-screen.
    guard.screen_mut().set_size(new_rows, size.cols);
    let delta = new_rows - old_rows;
    let scrollback_avail = guard.screen().scrollback();
    let pull_count = (delta as usize).min(scrollback_avail) as u16;
    if pull_count > 0 {
        let seq = format!("\x1b[{pull_count}T\x1b[{pull_count}B");
        guard.process(seq.as_bytes());
    }
} else {
    guard.screen_mut().set_size(new_rows, size.cols);
}
```

**Shrink:** `\x1b[<delta>S` (SU) scrolls content up → top rows enter scrollback, blank rows at bottom. `\x1b[<delta>A` (CUU) moves cursor up. `set_size()` truncates blank rows, preserving bottom content.

**Expand:** `set_size()` appends blank rows at bottom. `\x1b[<pull_count>T` (SD) scrolls content down, pulling rows back from scrollback into the top of the viewport. `\x1b[<pull_count>B` (CUD) moves cursor back down to keep it anchored to its text line.

When custom margins are active (vim/tmux), both guards skip injection — the app handles SIGWINCH.

## Issue 2 — Bouncy Scrollbar (Layout Thrashing)

### Root Cause
`ScrollViewComponent::render()` starts every frame assuming `needs_vertical = false`, forcing pass 1 at width W and pass 2 at W-1 — dual child renders per frame. For reflowing children this creates oscillation.

### Fix: Seed pass-1 from persistent state; passive bounds for OFF-transition

**File:** `crates/term-wm-core/src/component_context.rs` — Add `last_needs_vertical: bool` and `last_needs_horizontal: bool` to `ScrollBounds`

**File:** `crates/term-wm-ui-components/src/scroll_view.rs` — Two changes:

**Change 1 — `compute_layout` accepts explicit scrollbar state:**
```rust
pub(crate) fn compute_layout(&self, area: LayoutRect, needs_vertical: bool, needs_horizontal: bool) -> LayoutRect {
    let mut view_w = area.width;
    let mut view_h = area.height;
    if needs_vertical && view_w > 0 { view_w = view_w.saturating_sub(1); }
    if needs_horizontal && view_h > 0 { view_h = view_h.saturating_sub(1); }
    LayoutRect { x: area.x, y: area.y, width: view_w, height: view_h }
}
```

**Change 2 — Render loop seeds from persistent state:**
```rust
// Before loop:
let mut needs_vertical = {
    let state = self.scroll_state.borrow();
    state.last_needs_vertical
};
let mut needs_horizontal = {
    let state = self.scroll_state.borrow();
    state.last_needs_horizontal
};

// Inside loop, after child render:
if needs_vertical {
    // OFF-transition: only when content at W-1 fits strictly
    if content_h <= inner_area.height as usize {
        needs_vertical = false;
        attempt = 0;
        continue; // re-render at full width W
    }
} else {
    if inner_area.height > 0 && content_h > inner_area.height as usize {
        needs_vertical = true;
        attempt = 0;
        continue;
    }
}

// After loop, before scrollbar paint:
{
    let mut state = self.scroll_state.borrow_mut();
    state.last_needs_vertical = needs_vertical;
    state.last_needs_horizontal = needs_horizontal;
}
```

Also update `on_mouse`'s `compute_layout(sa)` call to pass `last_needs_vertical/horizontal`.

**No speculative probes, no scratch buffers, no SIGWINCH flooding.**

#### 1. Shrink preserves bottom rows (`terminal.rs` — scroll sync test suite)

Add a test that fills the parser with N distinct lines, shrinks the viewport by K, and asserts the bottom line of the original content remains visible while the top line moved to scrollback:

```rust
#[test]
fn shrink_preserves_bottom_rows() {
    let mut term = TerminalComponent::from_pane(Box::new(TestPane::new(200)));
    let area = LayoutRect { x: 0, y: 0, width: 80, height: 30 };
    let (handle, _shared) = make_handle();
    let ctx = ComponentContext::new(true).with_viewport(
        ScrollViewport { offset_x: 0, offset_y: 0, width: 80, height: 30 },
        Some(handle),
    );

    // Fill 30 rows with distinct content
    let mut pane = term.pane.borrow_mut();
    for i in 0..30 {
        pane.write_bytes(format!("line {i}\r\n").as_bytes()).ok();
    }
    drop(pane);

    // Render at 30 rows tall
    let mut buffer = Buffer::empty(Rect::new(0, 0, 80, 30));
    let mut backend = RatatuiBackend::new_simple(buffer, Rect::new(0, 0, 80, 30));
    let mut registry = HitboxRegistry::new(area);
    term.render(&mut backend, area, &ctx, &mut registry);

    // Now shrink to 24 rows
    let area24 = LayoutRect { x: 0, y: 0, width: 80, height: 24 };
    let ctx24 = ComponentContext::new(true).with_viewport(
        ScrollViewport { offset_x: 0, offset_y: 0, width: 80, height: 24 },
        Some(handle),
    );
    let mut buffer24 = Buffer::empty(Rect::new(0, 0, 80, 24));
    let mut backend24 = RatatuiBackend::new_simple(buffer24, Rect::new(0, 0, 80, 24));
    term.render(&mut backend24, area24, &ctx24, &mut registry);

    // After shrink: scrollback should be 6 (delta = 30 - 24)
    // The bottom visible row should contain "line 29"
    // The top scrollback row should contain "line 0"
    let pane = term.pane.borrow();
    assert!(pane.scrollback() > 0, "rows should have moved to scrollback");
    let parser = pane.shared_parser().lock().unwrap();
    let contents = parser.screen().contents();
    assert!(contents.contains("line 29"), "bottom line preserved");
    assert!(parser.screen().scrollback() >= 6, "at least 6 rows in scrollback");
}
```

#[test]
fn expand_does_not_duplicate_prompt() {
    let mut term = TerminalComponent::from_pane(Box::new(TestPane::new(200)));
    let area30 = LayoutRect { x: 0, y: 0, width: 80, height: 30 };
    let area24 = LayoutRect { x: 0, y: 0, width: 80, height: 24 };
    let (handle, _shared) = make_handle();
    let ctx30 = ComponentContext::new(true).with_viewport(
        ScrollViewport { offset_x: 0, offset_y: 0, width: 80, height: 30 }, Some(handle.clone()));
    let ctx24 = ComponentContext::new(true).with_viewport(
        ScrollViewport { offset_x: 0, offset_y: 0, width: 80, height: 24 }, Some(handle.clone()));

    // Fill 30 rows with distinct content
    let mut pane = term.pane.borrow_mut();
    for i in 0..30 {
        pane.write_bytes(format!("line {i}\r\n").as_bytes()).ok();
    }
    pane.write_bytes(b"prompt$ ").ok(); // final prompt, no newline
    drop(pane);

    // Render at 30 rows → shrink to 24
    render_term(&mut term, area30, &ctx30);
    render_term(&mut term, area24, &ctx24);

    // Expand back to 30
    render_term(&mut term, area30, &ctx30);

    // Content should contain "prompt$" exactly once at the bottom
    let pane = term.pane.borrow();
    let parser = pane.shared_parser().lock().unwrap();
    let contents = parser.screen().contents();
    let prompt_count = contents.matches("prompt$").count();
    assert_eq!(prompt_count, 1, "prompt must not be duplicated on expand");
    assert!(contents.trim_end().ends_with("prompt$"), "prompt must be at bottom");
}

#### 3. ScrollView hysteresis (`scroll_view.rs` — new test module)

```rust
#[test]
fn scrollbar_hysteresis_does_not_oscillate() {
    let content = ScrollViewComponent::new(SimpleComponent::new(80, 11));

    assert_eq!(inner.width, 79);

    // content_height=10 = viewport_height=10 → scrollbar should stay ON (hysteresis)
    // because OFF-transition requires content_h <= inner_area.height (10 <= 10)
    // After the OFF check: 10 <= 10 is true → scrollbar turns OFF
    // This is correct per the design: strictly fits, so we can turn it off

```

Wait — let me reconsider test 3. The design says OFF when `content_h <= inner_area.height`. At 10 rows content in 10 rows viewport, that IS strictly fitting, so OFF is correct. The hysteresis comes from the *seed* pattern: if scrollbar was ON last frame, pass 1 renders at W-1, and the OFF check uses `content_h` at W-1. For terminals (non-reflowing), `content_h` at W-1 = `content_h` at W, so it would turn OFF correctly. For reflowing children, content_h at W-1 might be > viewport_height even though at W it would fit — those cases stay ON until content shrinks further. That's the hysteresis mechanism.
