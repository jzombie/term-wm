> **PERF-FIX-II (current): honest frame rate + payload diet.** F1–F4 landed; user
> reports "perf is a bit better, but that frame rate isn't honest." Two root
> causes verified in code:
> 1. **Metering lie:** `io` only measures time inside our `flush()` — once bytes
>    land in the pty buffer, Terminal.app can lag arbitrarily far behind while we
>    count 60 fps. The fps stat also derived from segment-sum inverse, not actual
>    inter-draw intervals.
> 2. **Payload still TrueColor-heavy:** every dirty cell emits `\x1b[38;2;R;G;Bm`
>    (~22 B × 2 for fg+bg). Sky/gradient rows change color nearly per cell, so
>    color bytes dominate the stream Terminal.app must parse.
>
> Fixes:
>
> - **G1 — honest meters** (`main.rs`, `hud.rs`):
>   - `fps` := wall-clock between successive `present()` calls (real inter-draw
>     interval), not segment-sum inverse.
>   - `io` renamed **`b` (blocked)**: time spent inside `present()`'s
>     write/flush — i.e., exactly how long the terminal made us wait.
>   - HUD: `{fps}fps u{u} r{r} b{blocked}`.
> - **G2 — indexed-color payload diet** (`display.rs`, ~50 % byte cut on
>   color-heavy frames): emit SGR as `\x1b[38;5;Nm` / `48;5` (xterm-256,
>   ~12 B vs ~22 B). TermCell colors are noise-tinted arbitrary RGBs
>   (`fg = avg·(0.92 + 0.16·grain)`), so quantize with a **zero-allocation
>   O(1) arithmetic converter — no memo cache** (a HashMap thrashes under
>   gradient-heavy motion and violates the F2 no-alloc invariant):
>   - Per-channel nearest-cube-level via const-built `[u8; 256]` tables
>     computed against the *real* level array `{0,95,135,175,215,255}`
>     (uniform rounding mis-snaps dim/shadow colors — the levels aren't
>     evenly spaced).
>   - Near-gray tolerance: when `max−min ≤ GRAY_EPS`, use the grayscale ramp
>     with **bounded endpoints** (review: an unbounded `(lum−8)·24/240`
>     yields offset 24 ⇒ palette index 256 ⇒ u8 wrap to black on bright
>     grays):
>     `lum < 8 → 16` (cube black); `lum > 238 → 231` (cube white — nearer
>     than the ramp's `#eee` ceiling); otherwise
>     `232 + min(((lum−8)·24)/231, 23)`. The landed implementation already
>     behaves this way (`.min(23)` + distance-compare against the cube
>     candidate); the spec text now matches it.
>   - Pure stack arithmetic, `#[inline(always)]`, deterministic. Nearest-index
>     snapping shifts shades slightly (mild gradient banding) — braille dots
>     carry structure, so this trades imperceptible fidelity for doubled
>     throughput. `--truecolor` CLI flag restores the exact-RGB path.
> - **G3 — surface backpressure honestly** (`main.rs`, `config.rs`):
>   - `OUT_BUF_BYTES` 256 KiB → **64 KiB**: sustained overload now blocks
>     writes within a frame or two instead of dozens, making `b` a real signal.
>   - Adaptive cadence: if blocked-ms EMA exceeds 30 % of frame budget for
>     3 consecutive draws ⇒ gate widens to `2×TARGET_FRAME_TIME` (30 fps cap);
>     two consecutive clean windows step back to 1×. Deterministic hysteresis,
>     no oscillation.
> - Deferred: periodic consumption probe via `crossterm::cursor::position()`
>   (its internals are pub(crate); stock call risks 2 s stalls + input-queue
>   interactions — diagnostic-only, not in the pacing path).

> **PERF-FIX-III (current): byte-stream squeezing for Terminal.app's parser.**
> All six gains come from shaping the output stream itself:
>
> - **T1 — merged SGR slices** (`display.rs`): when a dirty cell changes BOTH
>   fg and bg, emit one sequence `\x1b[38;5;X;48;5;Ym` (indexed) or
>   `\x1b[38;2;R;G;B;48;2;R;G;Bm` (truecolor) instead of two commands — saves
>   an `\x1b[` + duplicate mode prefix per dual change across sky/gradient
>   rows. Compute both changed-flags first; update both state fields together.
> - **T2 — relative cursor moves**: with logical-cursor tracking already in
>   place, a same-row skip of 1–3 clean cells emits `\x1b[C` / `\x1b[2C` /
>   `\x1b[3C` instead of an absolute `\x1b[Y;XH` — 3–4 bytes vs 6–8 and a much
>   cheaper parse in Terminal.app. Wider jumps stay absolute.
> - **T3 — row-end carriage advance**: moving to column 0 of the next row
>   emits `\r\n` (2 B) instead of `\x1b[Y+1;1H`. Correct under raw mode
>   (OPOST/ONLCR are off: `\r`=col 0, `\n`=row+1). Guarded to target rows
>   `< H` so the bottom row can never scroll.

>   `pub const BRAILLE_UTF8: [[u8; 3]; 256]` built in `const fn`
>   (`0x2800 + mask` → 3-byte UTF-8). The hot path writes a 3-byte slice copy
>   when `ch == '\0'`; HUD text chars keep the `encode_utf8` fallback.

> **PERF-FIX-IV (current): perceptual SGR skipping + vertical moves.**
>
> - **V1 — color delta hysteresis (amended: post-quantization, lossless)**:
>   evaluate skipping **after** G2 quantization, comparing the cell's
>   xterm-256 index against the currently active index — skip only when
>   **`quantize(new) == active_idx`**, i.e. when Terminal.app would draw the
>   identical color anyway. This makes indexed-mode hysteresis *lossless*
>   (the draft's pre-quantized RGB epsilon could suppress a 3-unit change
>   that crosses a cube boundary, visually jumping 40 units). In
>   `--truecolor` mode keep the perceptual rule: per-channel
>   |Δ| ≤ `COLOR_SKIP_EPS` against the emitted RGB. **Text cells exempt**
>   either way so glyph colors always resync exactly. `cur_*` continue
>   tracking what was emitted; larger changes resync normally.
> - **V2 — vertical moves (amended ×2: Δy-gated + cost-compared)**: all
>   short-circuit forms require **`Δy == 1` exactly**; multi-row skips never
>   reuse single-line advances. Selection order:
>   1. `Δy == 1 && target.x == 0 && cur_x == 0` → `\n`
>   2. `Δy == 1 && target.x == 0 && cur_x > 0` → `\r\n`
>   3. `Δy == 1 && target.x == cur_x != 0` → `\n` (column-preserving LF)
>   4. `target.x == cur_x && 2 ≤ |Δy| ≤ 9` → `\x1b[{N}B`/`\x1b[{N}A`,
>      emitted only when its byte length is **strictly smaller** than the
>      equivalent absolute `\x1b[Y;XH`; ties and larger `|Δy|` fall through
>      to absolute (absolute also wins ties deliberately — it doubles as a
>      state-resync point after any PTY anomaly).
>   - Different-column targets go straight to absolute.
>   Bottom-row guard unchanged (`\x1b[B`/`\n` never issued from the last row);
>   cursor tracking updated for every branch.
> - **V3 — alternate screen**: verified already satisfied —
>   `EnterAlternateScreen` emits `?1049h` at startup (`main.rs:24`); nothing
>   to change.
> - **V4 — per-row dirty bitmaps: rejected.** The renderer regenerates every
>   cell every frame, so "changed" is only knowable by comparing against the
>   previous grid — the exact work `present()`'s linear diff already does.
>   Row masks would relocate those comparisons (encoder-side bookkeeping +
>   emitter-side mask walk), not remove them, and the current diff costs tens
>   of µs against a multi-ms I/O budget. Revisit only if a profile ever shows
>   diff cost mattering.
> - **V5 — half-block mode toggle: deferred** (separate stage). Real ~50 %
>   payload cut but a new encode path (1×2 px cells), halved grid rows,
>   HUD/minimap layout scaling, and a mode key/flag. Scoped sketch: encoder
>   branch keyed off a runtime mode; grid sizing derives from cell aspect;
>   minimap/HUD positions scale by cell height ratio.
> - **V6 — temporal interlacing under backpressure: deferred.** Alternating
>   odd/even row sets during Slow-gate frames requires force-dirty bookkeeping
>   (skipped rows must not update `prev`) and risks comb shimmer on motion;
>   G3's plain 30 fps cap reaches similar throughput with simpler visuals.
>   Revisit only if blocked time still exceeds budget at 30 fps.
>
> Tests: hysteresis (indexed: identical quantized index emits nothing —
> including a 3-unit RGB change that crosses a cube boundary MUST still emit;
> truecolor: ≤eps change silent, larger resyncs; text cells exempt);
> **cross-column row transition emits `\r\n` (never bare `\n` when

> **PERF-FIX (current): terminal-I/O stall.** Confirmed root cause of "7 fps, low CPU"
> in Terminal.app/SSH while Zed is smooth: `run()` passes raw `io::Stdout`
> (line-buffered `LineWriter`, 1 KB buf) into the frame loop, and the braille
> escape stream contains no newlines ⇒ one **blocking write syscall per ~1 KB**
> against an emulator that consumes slowly. Hundreds of syscalls per frame park
> the main thread (low CPU, low FPS). Fixes:
>
> - **F1 — bulk buffering, teardown-safe**: wrap the stdout handle in
>   `BufWriter::with_capacity(OUT_BUF_BYTES)` **owned by `drive()`'s scope**
>   (not re-created per frame — that would reintroduce allocation churn).
>   Teardown safety: the writer lives and dies inside `drive()`; `run()`
>   executes crossterm teardown (`PopKeyboardEnhancementFlags`,
>   `LeaveAlternateScreen`, `disable_raw_mode`) only *after* `drive()`
>   returns and the writer (hence the `StdoutLock`) is dropped — no held lock
>   across teardown. `present()` flushes once per frame as the single drain
>   point. On panic-unwind the writer drops during stack unwinding,
>   releasing the lock before the panic hook writes (stderr — different fd,
>   no contention).
> - **F2 — zero-allocation state-tracking ANSI encoder** (`display.rs`) —
>   review points 1+2 mapped; existing vs new:
>   | Mechanism | Status |
>   |---|---|
>   | Cell delta diff vs previous grid; skip unchanged cells | ✔ exists (`TermDisplay.prev`); layout upgraded below |
>   | fg/bg dedup — escapes only when color changes vs previous cell | ✔ exists (`cur_fg`/`cur_bg`, carried across frames) |
>   | `TermCell` repacked `#[repr(C)] { char_code: u32, fg: u32, bg: u32, flags: u32 }` (16 B, braille mask rides in `flags`) | **new** — derived `PartialEq` compiles to whole-word compares; HUD text stores code points instead of `char`. NOTE: literal `core::simd` is nightly-only; stable Rust gets equivalent vectorization from POD word-compare loops without unsafe |
>   | **DIGIT_LUT byte writer**: variable-length ASCII table `AsciiSlice { bytes: [u8;3], len: u8 }` (unpadded — `'5'` is 1 byte, not `"005"`; fixed-width would bloat TrueColor sequences +35 %) built in `const`; MoveTo/color sequences emitted as fixed prefix bytes + LUT slices via direct buffer writes — no `write!`, no crossterm style calls, no integer-divide formatting in the hot path | **new** |
>   | Logical-cursor tracking: `MoveTo` only on real jumps between dirty runs | **new** |
> - **F3 — deterministic draw gate / physics decoupling** (`main.rs`): sim
>   must never wait on Terminal.app. Loop becomes: drain events → fixed-step
>   `app.update` (already accumulator-based) → **draw gate**:
>   `render+present` only when `now >= next_draw`; otherwise continue ticking
>   inputs/physics.
>   **Cadence anchoring (review ×3):** anchor to the previous draw's *start*
>   — classic fixed-cadence limiter:
>   `next_draw = draw_started_at + TARGET_FRAME_TIME`.
>   Overrun self-corrects: if a cycle finishes late, `next_draw` is already
>   in the past ⇒ next iteration draws immediately, which is precisely PTY
>   backpressure behavior — no invented extra delay. Rejected formulas, for
>   the record: post-render anchor (`finish + dur` double-counts), pre-frame
>   anchor (`start + dur` < finish whenever update time > 0 ⇒ gate stuck
>   open), and `now + TARGET.saturating_sub(elapsed)` (overrun saturates the
>   subtraction to zero ⇒ also stuck open). Start-anchored cadence has none
>   of these failure modes and degenerates gracefully to "as fast as the
>   terminal drains" under sustained overload.
> - **F4 — perf HUD**: rolling averages of update/render/present ms + fps

>   lands (no streamer exists today — nothing blocks on channels now);

## H2. Angle-capped steering, bicycle-model yaw (`sim/car.rs`, `config.rs`)
Replace the broken authority curve (`sf = clamp(speed/REF, floor, 1) * (1 - stability·ratio)` — zeroed at standstill, choked yaw rate at speed) with the arcade-standard model:

```text
state: steer_sm is now the FRONT-WHEEL ANGLE (radians), not −1..1 input.
speed_ratio      = |v| / MAX_SPEED
angle_cap        = min(ANGLE_LOCK, atan(WHEELBASE · MAX_LAT_ACCEL / max(v², ε)))
                   // full 32° lock below ~city speeds; cap tightens with v²
input != 0       : steer_sm += input · STEER_WHEEL_RATE · dt; clamp(±angle_cap)
input == 0       : steer_sm moves toward 0 at fixed STEER_RECENTER_RATE · dt
yaw              : heading += (v / WHEELBASE) · steer_sm.tan() · dt
                   // reverse flips yaw sign naturally; standstill never spins
```

New/changed constants (`config.rs`, replacing `LOW_SPEED_REF`, `LOW_SPEED_FLOOR`,
`HIGH_SPEED_STABILITY`, `STEER_SMOOTH_RATE`):
| Const | Value | Meaning |
|---|---|---|
| `ANGLE_LOCK` | `0.56` rad (32°) | physical front-wheel lock |
| `WHEELBASE` | `2.6` m | bicycle model length |
| `MAX_LAT_ACCEL` | `22` m/s² | grip budget ⇒ cap angle from v² |
| `STEER_WHEEL_RATE` | `4.0` rad/s | wheel slews to lock in ~140 ms — crisp |
| `STEER_RECENTER_RATE` | `4.0` rad/s | fixed auto-center on release |
| `STEER_RATE` | *(delete — superseded)* | |

Resulting behavior: parking turn radius ≈ 3–7 m; at 180 km/h the grip-derived
cap (≈ 1.3°) yields ≈ 130 m radius at exactly `MAX_LAT_ACCEL` — stable yet
fully responsive, because the *wheel* still reaches its (small) cap in ~35 ms.
Camera roll: retune `ROLL_GAIN` 0.0035 → 0.006 (wheel-angle scale shrank from
±1 to ±0.56) so cornering lean is preserved.

Tests rewritten in `car.rs`: standstill cranks wheel but heading frozen;
low-speed parking turn > 10°/s; at MAX_SPEED lateral accel ≤ MAX_LAT_ACCEL+ε
and wheel reaches its cap within one tick-window; recenter returns wheel to 0
in ≤ 2/RECENTER seconds; reverse yaw-sign flip retained.

|---|---|

### 0a. Bake fast path — per-chunk centerline cache (`world/chunk.rs`, `world/roads.rs`)
During one bake, `cross(t)` depends only on the along-axis coordinate (z for EW, x for NS), yet it is re-evaluated (3-octave fBm) for every vertex via `lateral()`→`point()` and again per material cell. Add a `RoadCache` built once per `Chunk::bake`: arrays of `cross(t)` and `cross_slope(t)` over `[base−1, base+SIZE+1]` per highway; bake-path lookups become O(1) array reads instead of fBm. Removes most of the 33 % road-math share.

### 0b. Trim terrain octaves (`world/chunk.rs`, `config.rs`)
`raw_terrain_height` = fbm(3) + ridged(4) + fbm(4) ≈ 11 value-noise evals per query. Extract octave counts to named consts and reduce: continent 3→2, ridge 4→3, hills 4→3 (~25–30 % off this path). Visual delta is negligible after fog blending.

### 0c. March distance cap + far-field step growth (`render/terrain.rs`, `config.rs`)
The march runs to `VIEW_FAR = 1400 m` while fog fully saturates at `FOG_DIST = 470`. With the current step law (`step = 0.4 + 0.008·t`, i.e. `t_{n+1} = 1.008·t_n + 0.4`) a column takes ~413 steps to 1400 m but only ~312 to 600 m. Cap march length at `MARCH_FAR ≈ 600` (**~25 % fewer steps**) *and* add a second-stage growth const (`STEP_GROWTH_FAR`, applied beyond `STEP_FAR_START ≈ 250` m, e.g. 0.02) so distant spans — which cover dozens of screen cells each — advance in big jumps: combined **~50–60 % fewer height samples per column** with no visible change past the fog knee. Keep the existing horizon early-exit.

### 0d. Far-field LOD height/material (`world/mod.rs`, `render/terrain.rs`) — *amended: C1 blend zone*
Beyond loaded-chunk reach (~320 m), every march step falls back to full analytic terrain, and each visible span's `material_at` fallback even computes slope with 4 extra terrain evals. Add `height_far()` (cont fbm(2) + hills fbm(2) only, skip ridged) and a moisture-only material guess used by the marcher when `t > CHUNK_REACH_M`.

**Seam guard (review):** `height_far()` drops ridge octaves, so an abrupt switch at 320 m pops as the boundary moves with the player. Crossfade instead:

### 0f. Background chunk streaming (rayon worker + mpsc) — *amended: epoch cancellation*
Verified: zero concurrency today — `drive()` runs `app.update` (physics + bake) → `backend.render` → `present` sequentially on the main thread. `Chunk::bake(ox, oy, &Noise, &RoadNetwork)` is pure and `Noise`/`RoadNetwork` are `Copy`, so baking needs no access to `World` until insertion.

- New `crates/opencar/src/world/stream.rs`, `struct ChunkStreamer`:
  - `spawn(noise, roads)` moves `Copy` values into a worker that receives `Vec<(i32,i32)>` batches, bakes them **in parallel on the rayon pool**, and ships results back over a **bounded** channel (see below).
  - **Bounded result channel + backoff eviction (review ×5):** results flow through `std::sync::mpsc::sync_channel(MAX_INFLIGHT_CHUNKS = 8)` matching the in-flight cap. The worker uses `try_send`; on a full channel it pushes a tombstone `(key)` over a lightweight unbounded `mpsc`. `collect()` drains both channels, but a tombstone **does not clear** its pending entry — it stamps `retry_after = now + REQUEST_BACKOFF_SECS (0.2)`:
    - `request()` skips keys with an active backoff ⇒ no bake→drop→re-request thrash while the main thread is stalled;
    - 0.2 s bounds any void risk to ~10 m at top speed — two orders of magnitude better than a blind TTL;
    - entries still expire from `pending` after `PENDING_TTL_SECS = 1.0` as a final net.
    Ordering guarantee: `App::update` runs `collect()` **before** `request()` so completed work and tombstones are processed within the same frame before new work is issued.
  - `request(wants)`: **two disjoint structures (review ×2)** —
    `in_flight: HashSet<key>` (batches sent, result pending) and
    `backoff: HashMap<key, Instant>` (dropped-on-full, cooling down).
    Admission: `room = MAX_INFLIGHT_CHUNKS − in_flight.len()`; candidates
    filtered against *both* sets; tombstones move a key from `in_flight` to
    `backoff(now + REQUEST_BACKOFF_MILLIS)` instead of blocking capacity, so
    saturated backoffs can never starve brand-new view-front chunks. Backoff
    entries expire into removal via the TTL sweep.
  - **Epoch cancellation:** an `Arc<AtomicU64>` generation counter bumps whenever the player crosses a chunk boundary or reverses travel axis. The check runs **per chunk inside the batch loop** — not once per batch — so staleness granularity is bounded by a single bake (~0.41 ms release). `collect()` additionally discards late results whose key now lies outside the load radius.
  - `collect(world)`: drain the channel non-blocking, insert fresh chunks into the map.
- Refactor `World::ensure_chunks_around` into reusable pieces: `missing_chunks_around(x,z)` (nearest-ring sorted), `insert_chunk`, `evict_far`; keep the synchronous path for startup and tests.
- `App` owns the streamer; `update()` each frame does request → collect → evict. **Startup stays synchronous** (first ring baked before the loop).
- Test: spawn streamer → bump epoch → request → assert stale batch produces no bake within a generous window while a fresh batch does.

## Stage 1 — Drivable Car (core fixes)

### 1a. Input: fix sticky keys (`app.rs`, `config.rs`) — *amended ×2: per-control two-state timers*
The last two reviews correctly identified opposite failure modes of a single uniform timeout (long window ⇒ stale steering taps; short window ⇒ throttle cut during the OS initial-repeat-delay phase). Resolution: **policy follows control semantics**, since legacy terminals make tap-vs-hold fundamentally undecidable until the first auto-repeat arrives:

| Control | Initial window (post-Press, no 2nd event yet) | Confirmed-hold silence window |
|---|---|---|
| ↑ throttle / ↓ brake / space handbrake | `INITIAL_DELAY_TIMEOUT_SECS = 0.5` at **fixed low force** (see below) | `REPEAT_GAP_SECS = 0.15` |
| ← / → steering | `TAP_CONFIRM_SECS = 0.15` (**crisp taps**: residual ≤ 9 ticks) | `REPEAT_GAP_SECS = 0.15` |

**Fixed low provisional force (review ×4 supersedes the ramp):** the previous linear ramp was unsound — in fallback mode there is no Release event, so `t_press.elapsed()` keeps growing after the user has already let go, and any time-based ramp reaches full power even for a 50 ms tap. Instead, `Provisional` applies a **constant** `PROVISIONAL_FORCE = 0.25` of nominal input:
- A 50 ms tap ⇒ impulse ≈ `8 × 0.05 × 0.25` ≈ **0.1 m/s** — a parking nudge.
- Transition to `Holding` (first auto-repeat) snaps to 1.0; expiry of the window without a second event transitions straight to `Released`.
- The value never depends on unobservable release timing, which is what made both earlier drafts fail.
- `VehicleInput.throttle/brake` are already `f32`; plumbing is `HeldKeys::value(ctrl, now) -> f32` replacing bool `held()` for these controls (kitty mode returns 1.0 while `down`). Steering stays binary-crisp (its slew limiter provides proportional attack).

Rationale: throttle/brake are hold-dominant and car inertia smooths a lingering release; steering is precision tap-driven and its hold-start pulse (one gap until first repeat, smoothed further by the `STEER_SMOOTH_RATE` slew decay) is the least-bad legacy-terminal behavior. Windows ConPTY delivers true releases and is unaffected by all of this. Kitty protocol remains the exact-semantics path.

- Always honor explicit `KeyEventKind::Release`: if `down[ctrl] == false` → not held, in **both** modes.
- Opposing-input cancellation: pressing Right instantly clears Left (and Up↔Down, throttle↔brake).
- Clear all held state on pause/Esc and window focus loss.
- State machine per control: `Provisional{t_press}` → (2nd event) → `Holding{t_last}` → (silence > window) → released.

The optimizations you’ve put in place will **largely insulate you from performance regressions**. Adding buildings, cars, and scenery won't drag you back down to single-digit frame rates, provided you stick to the quad-rasterization design already laid out in Stage 3.

Here is why your new architecture will absorb world additions cleanly:

### 1. Terminal I/O Payload is Grid-Capped

The single biggest performance killer was stdout/PTY saturation. Your display pipeline is bounded by the terminal's cell grid resolution (e.g., $160 \times 90$), **not** the number of 3D objects in the world.

* Drawing a building or a car doesn't add more terminal cells to the output stream; it simply replaces a terrain or sky cell with a building cell.
* Cell delta diffing (**F2**), `MoveTo` cursor jump suppression, and xterm-256 palette indexing (**G2**) keep the byte throughput minimal regardless of what geometry occupies those cells.

### 2. Mesh Rasterization vs. Raymarching Split

The terrain raymarcher (`march_columns`) is the heaviest CPU loop because it steps through noise functions per ray.

* Objects like buildings (`BuildingDef`), cars, and road signs do **not** run inside the raymarcher loop.
* They are rasterized as painter-ordered 3D quads/boxes depth-tested directly against the terrain Z-buffer (`ColumnMajorImage.z`). Drawing 50–100 box quads in software takes under $100\ \mu\text{s}$ of host CPU time—orders of magnitude cheaper than the terrain raymarch.

### 3. Asynchronous Object Baking

Generating building positions or town clusters happens during chunk baking inside the background Rayon pool (`ChunkStreamer`, **0f**).

* Main-thread frame time won't spike as you drive into a dense town because the main thread only receives pre-baked `BuildingDef` arrays when the chunk drops into the map.

---

### Potential Traps to Avoid

While the architecture is shielded, performance can still degrade if objects are wired up incorrectly:

* **DO NOT put object bounds in the raymarcher:** Never try to include box/mesh height functions inside `height_at()` or `march_columns()`. That would force every ray to run bounding-box intersection tests per step, which *would* tank your frame rate. Keep objects on the Z-buffered quad rasterizer.
* **Cull unvisited objects aggressively:** Always apply frustum culling and a distance cap (`SPRITE_FAR`) so you only sort and rasterize objects within the visible view cone.
* **Keep quad counts sane:** Sorting and depth-testing 50–100 quads per frame is practically free. Doing it for 10,000 un-culled trees across the horizon will waste CPU time in sorting loops.
