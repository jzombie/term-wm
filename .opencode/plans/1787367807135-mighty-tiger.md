# OpenCar Drivability & World Overhaul

## Problem Summary
The car is nearly undrivable and the world feels chaotic. Root causes found in code:

| Symptom | Root cause |
|---|---|
| Chaotic/unpredictable inputs | Non-kitty terminals never send key releases; `HeldKeys::held()` (`app.rs:74`) ignores real key state and keeps inputs latched **5 s** after a tap (`FALLBACK_HELD_TIMEOUT_SECS = 5.0`) |
| Can't steer | `STEER_RATE = 0.5` rad/s; authority ramps from **zero** at standstill to full only at 10 m/s, then drops to 38 % at top speed → turn radius ≈ 315 m at speed (`sim/car.rs:73-76`). Lane magnetism fights corrections |
| Comically hilly roads | Road elevation waves ±16 m / 380 m + ±6 m / 95 m → worst-case **~66 % grade** (`world/roads.rs:60-64`, `config.rs:53-56`); car `y` snaps to terrain with zero suspension smoothing |
| Throttle slows you down | Engine force falls off linearly to **zero** at MAX_SPEED while quadratic drag grows → equilibrium ≈ 120 km/h; above that full throttle *decelerates* (`config.rs:93-99`, `sim/car.rs:83-107`) |
| Downhill feels like braking | **No slope physics at all**; perception chaos amplified by phantom off-road penalties: unloaded chunks fall back to raw-terrain material (grass on asphalt!) → instant clamp to 35 m/s (`world/mod.rs:102-112`, `sim/car.rs:115`); NPC collision halves speed every tick inside 2.4 m |

## User Goals
- Press gas → go; release → coast. Tap steering responds immediately.
- Physical hills (gravity along slope), sane road grades.
- An explorable world: flatland stretches AND mountain stretches on the same drive, lakes, scenery/buildings, intersections worth finding.
- CPU no longer pinned at 100% — the game must run smoothly.

## Stage 0 — Performance (profile-grounded)

Evidence: `target/debug/samply.json` (symbolicated via `atos -offset`; the root `samply.json` is unsymbolicated). Main thread, ~14.6 s sampled. Inclusive shares:

| Hot path | Share | What it is |
|---|---|---|
| `World::ensure_chunks_around` → `Chunk::bake` | **43 %** | Per chunk: 65×65 vertex heights × raw terrain noise + road math per vertex/cell |
| `Noise::hash` / `value` / `fbm` (self) | **~38 %** | Hash-based value noise evaluated millions of times/frame |
| `Renderer::render` → `terrain::march_columns` | **46 %** | Ray march per column; `height_at` every step; SipHash map lookup per step |
| `Centerline::cross/lateral/tangent…` chain | **33 %** | Road math recomputed from fBm for *every* vertex and material cell during bake |

Non-findings (do NOT chase): crossterm event polling is absent from top frames (<1 %); frame pacing at 60 FPS already exists (`main.rs:96`). The CPU is pegged because real work exceeds the 16.7 ms budget — so make the work cheaper.

### 0a. Bake fast path — per-chunk centerline cache (`world/chunk.rs`, `world/roads.rs`)
During one bake, `cross(t)` depends only on the along-axis coordinate (z for EW, x for NS), yet it is re-evaluated (3-octave fBm) for every vertex via `lateral()`→`point()` and again per material cell. Add a `RoadCache` built once per `Chunk::bake`: arrays of `cross(t)` and `cross_slope(t)` over `[base−1, base+SIZE+1]` per highway; bake-path lookups become O(1) array reads instead of fBm. Removes most of the 33 % road-math share.

### 0b. Trim terrain octaves (`world/chunk.rs`, `config.rs`)
`raw_terrain_height` = fbm(3) + ridged(4) + fbm(4) ≈ 11 value-noise evals per query. Extract octave counts to named consts and reduce: continent 3→2, ridge 4→3, hills 4→3 (~25–30 % off this path). Visual delta is negligible after fog blending.

### 0c. March distance cap + far-field step growth (`render/terrain.rs`, `config.rs`)
The march runs to `VIEW_FAR = 1400 m` while fog fully saturates at `FOG_DIST = 470`. With the current step law (`step = 0.4 + 0.008·t`, i.e. `t_{n+1} = 1.008·t_n + 0.4`) a column takes ~413 steps to 1400 m but only ~312 to 600 m. Cap march length at `MARCH_FAR ≈ 600` (**~25 % fewer steps**) *and* add a second-stage growth const (`STEP_GROWTH_FAR`, applied beyond `STEP_FAR_START ≈ 250` m, e.g. 0.02) so distant spans — which cover dozens of screen cells each — advance in big jumps: combined **~50–60 % fewer height samples per column** with no visible change past the fog knee. Keep the existing horizon early-exit.

### 0d. Far-field LOD height/material (`world/mod.rs`, `render/terrain.rs`)
Beyond loaded-chunk reach (~320 m), every march step falls back to full analytic terrain, and each visible span's `material_at` fallback even computes slope with 4 extra terrain evals. Add `height_far()` (cont fbm(2) + hills fbm(2) only, skip ridged) and a moisture-only material guess used by the marcher when `t > CHUNK_REACH_M`. Distant terrain is fog-dimmed; silhouette stays plausible.

### 0e. Fast chunk-map hashing (`world/mod.rs`)
`chunks.get(&(ckx, cky))` runs std SipHash per call (~5 % self time across sip frames). Replace key with packed `u64` + a tiny hand-rolled FxHasher (`BuildHasherDefault`) — no new dependencies, matching the crate's minimal-deps convention.

**Expected result:** bake < 15 % incl, march < 20 % incl, hash self < 5 % — frame budget met, pacing sleep actually engages, CPU leaves 100 %.

## Stage 1 — Drivable Car (core fixes)

### 1a. Input: fix sticky keys (`app.rs`, `config.rs`)
Rework `HeldKeys` so behavior matches "release = stop seeing repeats":
- Always honor explicit `KeyEventKind::Release` (Windows ConPTY sends these even without kitty): if `down[ctrl] == false` → not held, in **both** modes.
- Fallback mode (no releases ever seen): two-phase heartbeat
  - After initial Press: provisionally held until `INITIAL_REPEAT_GRACE_SECS` (covers worst-case OS delay-until-repeat ~500 ms → use **0.75 s**).
  - Once an auto-repeat arrives (hold confirmed): held while gaps < `REPEAT_GAP_SECS` (**0.25 s**, repeat intervals are ~30–90 ms). Silence ⇒ released.
- Opposing-input cancellation: pressing Right instantly clears Left (and Up↔Down, throttle↔brake).
- Clear all held state on pause/Esc and window focus loss.
- Replace `FALLBACK_HELD_TIMEOUT_SECS` with the two constants above (repo convention: named consts in `config.rs`).

### 1b. Steering model (`sim/car.rs`, `config.rs`)
Replace authority calculation at `car.rs:73-76`:
- `STEER_RATE`: 0.5 → **1.4 rad/s**
- Low-speed factor: saturating ramp with floor — `(speed.abs()/LOW_SPEED_REF).clamp(LOW_SPEED_FLOOR, 1.0)` with `LOW_SPEED_FLOOR = 0.35` (parking-speed maneuvering works; reverse inversion via `speed.signum()` stays).
- `HIGH_SPEED_STABILITY`: 0.62 → **0.45** (top-speed turn radius ≈ 80–100 m instead of 315 m).
- Gate lane magnetism (`app.rs:236`): apply only when `steer_input.abs() < LANE_MAGNET_STEER_GATE` (**0.25**) so it never fights deliberate steering.

### 1c. Longitudinal model: press gas = go (`config.rs`, `sim/car.rs`)
- `MAX_SPEED = 50.0` m/s (real **180 km/h**, matching HUD/comment).
- Engine falloff `(1 − v/MAX)` → **quadratic power curve** `(1 − (v/MAX)²)`, `ENGINE_ACCEL = 8.0`.
- `DRAG_COEFF` 0.0012 → **0.0004**, `ROLL_RESIST` 0.045 → **0.012**.
  Result: equilibrium ≈ 51–52 m/s (≥ 180 km/h reachable), monotonic acceleration below ~95 % top speed, coasting decel ≈ 1 m/s².
- Extract a pure model fn `model_longitudinal(speed, throttle, brake, handbrake, offroad, slope) -> f32` (mirrors the repo's `model_scroll_sync` testability pattern) and have `Vehicle::update` call it.

### 1d. Physical hills (`sim/car.rs`, `render/camera.rs`, `config.rs`)
- Move `terrain_slope()` from `render/camera.rs` into `world` (or `sim`) so sim doesn't depend on render; camera imports it from the new home.
- In `Vehicle::update`: `accel -= GRAVITY * slope_fraction` (slope fraction = dh/ds along heading, clamped to `±MAX_SLOPE_GRADE`). `GRAVITY = 9.81`.
- Suspension: replace `self.y = world.height_at(...)` snap with exponential smoothing `y += (ground_y − y) * (1 − exp(−SUSPENSION_RATE·dt))`, `SUSPENSION_RATE = 12.0`.

### 1e. Kill phantom speed cuts (`world/mod.rs`, `sim/car.rs`)
- `is_offroad_at`: when chunk not resident, decide off-road **geometrically** (`roads.sample(x,z).dist > ROAD_HALF_WIDTH + SHOULDER_WIDTH`) instead of raw-material guess → no grass-on-asphalt misdetection.
- Replace instant `OFFROAD_MAX_SPEED` clamp (`car.rs:115-117`) with continuous extra drag ramp above threshold (no discontinuity).
- NPC collision: keep positional push; soften speed penalty 0.55 → **COLLISION_KEEP = 0.88**, applied only when closing (dot product check) so passing traffic doesn't machine-gun halve your speed.

## Stage 2 — Regional World: Flatlands, Mountains, Lakes

### 2a. Roads follow regions (`world/roads.rs`, `config.rs`)
Make road elevation region-aware (signature becomes `elevation(&self, t, noise)`; caller `sample()` already has `noise`; chunk bake passes it through):
- Sample continent noise at the centerline point → `mtn = smoothstep(CONTINENT_LOW, CONTINENT_HIGH, cont)`.
- Base rolling profile retuned: `ELEV1_AMP` 16 → **4.0** (≈ 6.6 % max grade), `ELEV2_AMP` 6 → **1.2** (≈ 8 %).
- Mountain multiplier: elevation amplitude × `(1 + MTN_ELEV_GAIN · mtn)`, `MTN_ELEV_GAIN = 1.5` → plains are near-flat, ranges give dramatic but bounded (~16 %) climbs.
- Result: driving along either highway traverses flatland ↔ foothill ↔ mountain zones (continent scale is 1350 m, so zones arrive every few km).

### 2b. Lakes & terrain contrast (`config.rs`)
- Lower `BASE_ELEV` 8 → **7.0** and/or raise `SEA_LEVEL` 5 → **5.5** so low-continent plains dip below sea level in basins → visible lakes adjacent to flatland roads.
- Keep `HILL_AMP = 4` in plains (gentle), rely on existing `mountain_mask` for relief.

## Stage 3 — Destinations: Junction Towns & Scenery

- Extend the existing chunk-baking prop system (`SignDef` in `world/chunk.rs`, billboard/sprite rendering already proven by signs + NPC cars):
  - New `BuildingDef { x, z, w, d, h, palette_idx }` baked in `Chunk::bake` when a cell sits within `TOWN_RADIUS` (**90 m**) of a junction area (reuse `JUNCTION_HALF` proximity via road-lateral checks) on dry land.
  - Cluster 3–10 simple boxes per town (vary size via seeded noise) → recognizable towns AT intersections, giving destinations and landmarks.
  - Render through the existing mesh/sprite path used for cars/signs (depth-correct, fog-blended).
- Optional stretch (explicitly separable): generalize `RoadNetwork` from one EW + one NS line to a coarse parallel grid (`Vec<Centerline>` per axis, per-index salt) for guaranteed frequent intersections. Requires mechanical refactor of `traffic.rs` (`Highway` enum → line index). Only attempt after Stages 1–2 are green.

## Tests (add alongside changes)
- `car.rs`: `model_longitudinal` unit tests — full throttle from 0 reaches ≥ 0.9·MAX_SPEED and never negative net accel below 0.95·MAX on flat; downhill (positive slope input) accelerates, uphill decelerates; brake stops; reverse builds.
- `roads.rs`: grade bound test — dense-sample `elevation(t)` for several seeds; assert |dh/dt| ≤ configured max grade in low-mtn regions.
- `app.rs`: HeldKeys state machine — tap releases after grace; repeated events sustain; silence after confirmed hold releases quickly; opposing press cancels.
- `chunk.rs`: RoadCache correctness — bake-path `lateral`/`tangent` via cache match direct analytic evaluation within epsilon for sample points.
- `world/mod.rs`: far-field LOD stays within a few meters of full eval at representative points (fog tolerance); chunk map fast hasher returns identical lookups.
- Existing tests updated for renamed constants (`speed_clamps_to_max`, `brake_stops_and_reverses`, `steering_inverts_in_reverse`, traffic population test).
