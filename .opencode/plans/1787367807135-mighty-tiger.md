# OpenCar Drivability & World Overhaul

## Problem Summary
The car is nearly undrivable and the world feels chaotic. Root causes found in code:

| Symptom | Root cause |
|---|---|
| Chaotic/unpredictable inputs | Non-kitty terminals never send key releases; `HeldKeys::held()` (`app.rs:74`) ignores real key state and keeps inputs latched **5 s** after a tap (`FALLBACK_HELD_TIMEOUT_SECS = 5.0`) |
| Can't steer | `STEER_RATE = 0.5` rad/s; authority ramps from **zero** at standstill to full only at 10 m/s, then drops to 38 % at top speed → turn radius ≈ 315 m at speed (`sim/car.rs:73-76`). Lane magnetism fights corrections |
| Comically hilly roads | Road elevation waves ±16 m / 380 m + ±6 m / 95 m → worst-case **~66 % grade** (`world/roads.rs:60-64`, `config.rs:53-56`); car `y` snaps to terrain with zero suspension smoothing |
| Throttle slows you down | Engine force falls off linearly to **zero** at MAX_SPEED while quadratic drag grows → equilibrium ≈ 120 km/h; above that full throttle *decelerates* (`config.rs:93-99`, `sim/car.rs:83-107`) |
| Downhill feels like braking | **No slope physics at all**; perception chaos amplified by phantom off-road penalties: unloaded chunks fall back to raw-terrain material (grass on asphalt!) → instant clamp to 35 m/s (`world/mod.rs:102-112`, `sim/car.rs:115`); NPC collision halves speed every tick inside 2.4 m |

## User Goals
- Press gas → go; release → coast. Tap steering responds immediately.
- Physical hills (gravity along slope), sane road grades.
- An explorable world: flatland stretches AND mountain stretches on the same drive, lakes, scenery/buildings, intersections worth finding.
- CPU no longer pinned at 100% — the game must run smoothly.

## Stage 0 — Performance (profile-grounded)

> **Status:** 0a–0e implemented and green (`cargo clippy -D warnings` clean workspace-wide after resolving a pre-existing rebase-conflict marker in `term-wm-core/src/project_tasks.rs`; 41 opencar tests pass; bake diagnostic ≈ **0.41 ms/chunk** release). Remaining: 0f + 0g below, then release-binary re-profile.

Evidence: `target/debug/samply.json` (symbolicated via `atos -offset`; the root `samply.json` is unsymbolicated). Main thread, ~14.6 s sampled. Inclusive shares:

| Hot path | Share | What it is |
|---|---|---|
| `World::ensure_chunks_around` → `Chunk::bake` | **43 %** | Per chunk: 65×65 vertex heights × raw terrain noise + road math per vertex/cell |
| `Noise::hash` / `value` / `fbm` (self) | **~38 %** | Hash-based value noise evaluated millions of times/frame |
| `Renderer::render` → `terrain::march_columns` | **46 %** | Ray march per column; `height_at` every step; SipHash map lookup per step |
| `Centerline::cross/lateral/tangent…` chain | **33 %** | Road math recomputed from fBm for *every* vertex and material cell during bake |

Non-findings (do NOT chase): crossterm event polling is absent from top frames (<1 %); frame pacing at 60 FPS already exists (`main.rs:96`). The CPU is pegged because real work exceeds the 16.7 ms budget — so make the work cheaper.

### 0a. Bake fast path — per-chunk centerline cache (`world/chunk.rs`, `world/roads.rs`)
During one bake, `cross(t)` depends only on the along-axis coordinate (z for EW, x for NS), yet it is re-evaluated (3-octave fBm) for every vertex via `lateral()`→`point()` and again per material cell. Add a `RoadCache` built once per `Chunk::bake`: arrays of `cross(t)` and `cross_slope(t)` over `[base−1, base+SIZE+1]` per highway; bake-path lookups become O(1) array reads instead of fBm. Removes most of the 33 % road-math share.

### 0b. Trim terrain octaves (`world/chunk.rs`, `config.rs`)
`raw_terrain_height` = fbm(3) + ridged(4) + fbm(4) ≈ 11 value-noise evals per query. Extract octave counts to named consts and reduce: continent 3→2, ridge 4→3, hills 4→3 (~25–30 % off this path). Visual delta is negligible after fog blending.

### 0c. March distance cap + far-field step growth (`render/terrain.rs`, `config.rs`)
The march runs to `VIEW_FAR = 1400 m` while fog fully saturates at `FOG_DIST = 470`. With the current step law (`step = 0.4 + 0.008·t`, i.e. `t_{n+1} = 1.008·t_n + 0.4`) a column takes ~413 steps to 1400 m but only ~312 to 600 m. Cap march length at `MARCH_FAR ≈ 600` (**~25 % fewer steps**) *and* add a second-stage growth const (`STEP_GROWTH_FAR`, applied beyond `STEP_FAR_START ≈ 250` m, e.g. 0.02) so distant spans — which cover dozens of screen cells each — advance in big jumps: combined **~50–60 % fewer height samples per column** with no visible change past the fog knee. Keep the existing horizon early-exit.

### 0d. Far-field LOD height/material (`world/mod.rs`, `render/terrain.rs`) — *amended: C1 blend zone*
Beyond loaded-chunk reach (~320 m), every march step falls back to full analytic terrain, and each visible span's `material_at` fallback even computes slope with 4 extra terrain evals. Add `height_far()` (cont fbm(2) + hills fbm(2) only, skip ridged) and a moisture-only material guess used by the marcher when `t > CHUNK_REACH_M`.

**Seam guard (review):** `height_far()` drops ridge octaves, so an abrupt switch at 320 m pops as the boundary moves with the player. Crossfade instead:
- `h = lerp(h_far, h_full, smoothstep(LOD_BLEND_START_M, CHUNK_REACH_M, t))` with `LOD_BLEND_START_M = 280.0`.
- Both functions evaluate only inside the 40 m shell; outside it, exactly one runs.
- Material pick switches at the blend midpoint; residual color pop is masked by fog (exp(-t/470) ≈ 47 % sky-blend at 320 m).
- Test: sample along a ray crossing the shell; assert max |Δh| per meter stays below the terrain's own gradient bound (no cliffs introduced by blending).

### 0e. Fast chunk-map hashing (`world/mod.rs`)
`chunks.get(&(ckx, cky))` runs std SipHash per call (~5 % self time across sip frames). Replace key with packed `u64` + a tiny hand-rolled FxHasher (`BuildHasherDefault`) — no new dependencies, matching the crate's minimal-deps convention.

### 0f. Background chunk streaming (rayon worker + mpsc) — *amended: epoch cancellation*
Verified: zero concurrency today — `drive()` runs `app.update` (physics + bake) → `backend.render` → `present` sequentially on the main thread. `Chunk::bake(ox, oy, &Noise, &RoadNetwork)` is pure and `Noise`/`RoadNetwork` are `Copy`, so baking needs no access to `World` until insertion.

- New `crates/opencar/src/world/stream.rs`, `struct ChunkStreamer`:
  - `spawn(noise, roads)` moves `Copy` values into a worker that receives `Vec<(i32,i32)>` batches, bakes them **in parallel on the rayon pool**, and ships results back over a **bounded** channel (see below).
  - **Bounded result channel (review ×3):** results flow through `std::sync::mpsc::sync_channel(MAX_INFLIGHT_CHUNKS = 8)` — capacity matches the in-flight cap, so outstanding bakes can never exceed what the receiver can hold. The worker uses `try_send` and **drops** the chunk on a full channel rather than blocking a pool thread. Self-healing: pending-set entries carry timestamps and expire after `PENDING_TTL_SECS = 2.0`; because `missing_chunks_around` diffs against map contents each frame, any dropped chunk is automatically re-requested once its pending entry expires — no lost-forever state, and no crossbeam dependency.
  - `request(wants)`: dedupe against an in-flight set, cap at `MAX_INFLIGHT_CHUNKS`.
  - **Epoch cancellation:** an `Arc<AtomicU64>` generation counter bumps whenever the player crosses a chunk boundary or reverses travel axis. The check runs **per chunk inside the batch loop** — not once per batch — so staleness granularity is bounded by a single bake (~0.41 ms release). `collect()` additionally discards late results whose key now lies outside the load radius.
  - `collect(world)`: drain the channel non-blocking, insert fresh chunks into the map.
- Refactor `World::ensure_chunks_around` into reusable pieces: `missing_chunks_around(x,z)` (nearest-ring sorted), `insert_chunk`, `evict_far`; keep the synchronous path for startup and tests.
- `App` owns the streamer; `update()` each frame does request → collect → evict. **Startup stays synchronous** (first ring baked before the loop).
- Test: spawn streamer → bump epoch → request → assert stale batch produces no bake within a generous window while a fresh batch does.

### 0g. Parallel terrain march — *amended ×2: column-major overscan ⇒ direct-write, zero-copy*
`march_columns` writes disjoint screen columns; the previous band-buffer draft (seed + scatter copies) is rejected per review. Root cause of the copies: `ImageBuffer` is **row-major** (`idx = y*w + x`) while rays are per-**column**. Fix the layout for exactly one buffer:

- New `render::image::ColumnMajorImage { w, h, rgb: Vec<u8>, z: Vec<f32> }` with `idx = x*h + y`, same public API (`put_pixel`, etc.) so sky and march code don't change shape.
- `TerrainPass.buf` and the sky pass switch to it (both are pre-rotation stages). Everything downstream of `rotate_into` stays row-major and untouched — rotation already exists as the single transform point; only its gather indexing flips (`sidx = sx*h + sy`).
- **Zero-copy parallelism:** in column-major storage a vertical band `[c0..c1)` IS contiguous (`rgb[c0*h*3 .. c1*h*3]`, `z[c0*h .. c1*h]`). Bands become disjoint safe slices via successive `split_at_mut` → wrapped in a `BandView` with band-local `put_pixel`. Rayon `par_iter` over views; each calls `march_range(view, op, world, sm, boost, c0..c1)`.
- No seeding, no scattering, no intermediate allocations, no unsafe. Sky paints directly into the column-major buffer beforehand as today.
- Small widths (`w < MIN_PAR_BAND_COLS = 32`) stay single-threaded; bands ≥ **24 cols**; threads `min(available_parallelism, w / MIN_BAND_COLS)`.
- Per-column math unchanged ⇒ output **byte-identical regardless of thread count**; `render_smoke_deterministic` enforces it (and guards the index-math flip in `rotate_into`).
- Add `rayon` to `crates/opencar/Cargo.toml`.

**Expected result:** main-thread frame work fits the 16.7 ms budget so pacing sleep engages — CPU leaves sustained 100 %; bake leaves the critical path entirely; march scales across cores with no allocator churn and no copy passes. Frame-rate target: 60 FPS at large terminal sizes **in release**.

> Profiling correction: the earlier `samply.json` captured the **debug** binary (`target/debug/opencar`) — absolute ms/fps were inflated ~10–50×. Relative hot-spot shares remain valid as guides. All Stage 0 gates must be re-measured against `target/release/opencar`.

## Stage 1 — Drivable Car (core fixes)

### 1a. Input: fix sticky keys (`app.rs`, `config.rs`) — *amended ×2: per-control two-state timers*
The last two reviews correctly identified opposite failure modes of a single uniform timeout (long window ⇒ stale steering taps; short window ⇒ throttle cut during the OS initial-repeat-delay phase). Resolution: **policy follows control semantics**, since legacy terminals make tap-vs-hold fundamentally undecidable until the first auto-repeat arrives:

| Control | Initial window (post-Press, no 2nd event yet) | Confirmed-hold silence window |
|---|---|---|
| ↑ throttle / ↓ brake / space handbrake | `INITIAL_DELAY_TIMEOUT_SECS = 0.5` (**ramped force**, see below) | `REPEAT_GAP_SECS = 0.15` |
| ← / → steering | `TAP_CONFIRM_SECS = 0.15` (**crisp taps**: residual ≤ 9 ticks) | `REPEAT_GAP_SECS = 0.15` |

**Ramped provisional force (review ×3):** a flat 0.5 s provisional window turns one W-tap into 4 m/s of unintended launch (`ENGINE_ACCEL 8 × 0.5 s`). During `Provisional`, throttle/brake/handbrake apply **analog force scaled linearly by elapsed time**: `value = base * min(1.0, t_press.elapsed() / INITIAL_DELAY_TIMEOUT_SECS)`. Consequences:
- A short tap delivers a proportionally small nudge (50 ms tap ≈ 0.4 km/h at standstill) — parking-speed precision restored.
- A genuine hold ramps smoothly toward full force across the OS initial-delay phase, then `Holding` snaps to 1.0 on the first auto-repeat — no stutter, no cliff.
- `VehicleInput.throttle/brake` are already `f32` fields, so plumbing is a `HeldKeys::value(ctrl, now) -> f32` replacing the bool `held()` for these controls (kitty mode returns 1.0 while `down`).
- Steering stays binary-with-crisp-taps: its slew limiter already provides proportional attack.

Rationale: throttle/brake are hold-dominant and car inertia smooths a lingering release; steering is precision tap-driven and its hold-start pulse (one gap until first repeat, smoothed further by the `STEER_SMOOTH_RATE` slew decay) is the least-bad legacy-terminal behavior. Windows ConPTY delivers true releases and is unaffected by all of this. Kitty protocol remains the exact-semantics path.

- Always honor explicit `KeyEventKind::Release`: if `down[ctrl] == false` → not held, in **both** modes.
- Opposing-input cancellation: pressing Right instantly clears Left (and Up↔Down, throttle↔brake).
- Clear all held state on pause/Esc and window focus loss.
- State machine per control: `Provisional{t_press}` → (2nd event) → `Holding{t_last}` → (silence > window) → released.

### 1b. Steering model (`sim/car.rs`, `config.rs`)
Replace authority calculation at `car.rs:73-76`:
- `STEER_RATE`: 0.5 → **1.4 rad/s**
- Low-speed factor: saturating ramp with floor — `(speed.abs()/LOW_SPEED_REF).clamp(LOW_SPEED_FLOOR, 1.0)` with `LOW_SPEED_FLOOR = 0.35` (parking-speed maneuvering works; reverse inversion via `speed.signum()` stays).
- `HIGH_SPEED_STABILITY`: 0.62 → **0.45** (top-speed turn radius ≈ 80–100 m instead of 315 m).
- Gate lane magnetism (`app.rs:236`): apply only when `steer_input.abs() < LANE_MAGNET_STEER_GATE` (**0.25**) so it never fights deliberate steering.

### 1c. Longitudinal model: press gas = go (`config.rs`, `sim/car.rs`)
- `MAX_SPEED = 50.0` m/s (real **180 km/h**, matching HUD/comment).
- Engine falloff `(1 − v/MAX)` → **quadratic power curve** `(1 − (v/MAX)²)`, `ENGINE_ACCEL = 8.0`.
- `DRAG_COEFF` 0.0012 → **0.0004**, `ROLL_RESIST` 0.045 → **0.012**.
  Result: equilibrium ≈ 51–52 m/s (≥ 180 km/h reachable), monotonic acceleration below ~95 % top speed, coasting decel ≈ 1 m/s².
- Extract a pure model fn `model_longitudinal(speed, throttle, brake, handbrake, offroad, slope) -> f32` (mirrors the repo's `model_scroll_sync` testability pattern) and have `Vehicle::update` call it.

### 1d. Physical hills (`sim/car.rs`, `render/camera.rs`, `config.rs`) — *amended: dt-stability note*
- Move `terrain_slope()` from `render/camera.rs` into `world` (or `sim`) so sim doesn't depend on render; camera imports it from the new home.
- In `Vehicle::update`: `accel -= GRAVITY * slope_fraction` (slope fraction = dh/ds along heading, clamped to `±MAX_SLOPE_GRADE`). `GRAVITY = 9.81`.
- Suspension: replace `self.y = world.height_at(...)` snap with exponential smoothing `y += (ground_y − y) * (1 − exp(−SUSPENSION_RATE·dt))`, `SUSPENSION_RATE = 12.0`.
- **dt stability (review):** already guaranteed by construction, now documented and enforced:
  - `App::update` clamps frame time to `MAX_FRAME_SECS = 0.05` **before** accumulation; physics only ever runs at the fixed `SIM_TICK_DT = 1/60` step (≤ 5 substeps, backlog dropped on hitches). `Vehicle::update` can never see a spike dt ⇒ no tunneling or blow-up from lag spikes/chunk stalls.
  - Suspension smoothing therefore evaluates at fixed dt inside `Vehicle::update` — deterministic per tick.
  - Camera springs (`cam.update`) run per-frame but receive the same pre-clamped dt and use exp-decay form (unconditionally stable for all dt > 0). Add a debug_assert documenting this invariant.

### 1e. Kill phantom speed cuts (`world/mod.rs`, `sim/car.rs`)
- `is_offroad_at`: when chunk not resident, decide off-road **geometrically** (`roads.sample(x,z).dist > ROAD_HALF_WIDTH + SHOULDER_WIDTH`) instead of raw-material guess → no grass-on-asphalt misdetection.
- Replace instant `OFFROAD_MAX_SPEED` clamp (`car.rs:115-117`) with continuous extra drag ramp above threshold (no discontinuity).
- NPC collision: keep positional push; soften speed penalty 0.55 → **COLLISION_KEEP = 0.88**, applied only when closing (dot product check) so passing traffic doesn't machine-gun halve your speed.

## Stage 2 — Regional World: Flatlands, Mountains, Lakes

### 2a. Roads follow regions (`world/roads.rs`, `config.rs`)
Make road elevation region-aware (signature becomes `elevation(&self, t, noise)`; caller `sample()` already has `noise`; chunk bake passes it through):
- Sample continent noise at the centerline point → `mtn = smoothstep(CONTINENT_LOW, CONTINENT_HIGH, cont)`.
- Base rolling profile retuned: `ELEV1_AMP` 16 → **4.0** (≈ 6.6 % max grade), `ELEV2_AMP` 6 → **1.2** (≈ 8 %).
- Mountain multiplier: elevation amplitude × `(1 + MTN_ELEV_GAIN · mtn)`, `MTN_ELEV_GAIN = 1.5` → plains are near-flat, ranges give dramatic but bounded (~16 %) climbs.
- Result: driving along either highway traverses flatland ↔ foothill ↔ mountain zones (continent scale is 1350 m, so zones arrive every few km).

### 2b. Lakes & terrain contrast (`config.rs`)
- Lower `BASE_ELEV` 8 → **7.0** and/or raise `SEA_LEVEL` 5 → **5.5** so low-continent plains dip below sea level in basins → visible lakes adjacent to flatland roads.
- Keep `HILL_AMP = 4` in plains (gentle), rely on existing `mountain_mask` for relief.

## Stage 3 — Destinations: Junction Towns & Scenery — *amended: no march-path cost*

- **Buildings render through the existing mesh/quad pipeline, never the marcher.** Cars and signs already rasterize as painter-ordered quads (`draw_quad`) depth-tested against the terrain z-buffer; `BuildingDef { x, z, w, d, h, palette_idx }` boxes join that same path:
  - Bake-time: cluster 3–10 simple boxes per town in `Chunk::bake` when a cell sits within `TOWN_RADIUS` (**90 m**) of a junction on dry land.
  - Per frame: gather candidate buildings via the existing `signs_near`-style chunk query (distance ≤ `SPRITE_FAR`), then **frustum + distance cull** before rasterization. Typical visible set is a handful of boxes — orders of magnitude below the car mesh load.
  - Zero ray-box tests are added to `terrain.rs`; the review's per-step intersection hazard cannot arise because occlusion comes from the existing terrain-depth z-test.
- Optional stretch (explicitly separable): generalize `RoadNetwork` from one EW + one NS line to a coarse parallel grid (`Vec<Centerline>` per axis, per-index salt) for guaranteed frequent intersections. Requires mechanical refactor of `traffic.rs` (`Highway` enum → line index). Only attempt after Stages 1–2 are green.
