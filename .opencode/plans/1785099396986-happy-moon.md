# Fix plan

## 1. Silent callback failure in `spawn_terminal_window`

**File**: `src/term_wm_app.rs:182-183`

**Problem**: `if let` silently skips callback wiring when component type doesn't match. Terminal appears dead.

**Fix**: Replace `if let` with `else` logging:

```rust
if let AppRootComponent::Core(CoreWmComponent::Terminal(scroll_view)) = ... {
    // existing callback wiring
} else {
    tracing::error!(
        "[STAGE 2] Window {:?} is not a Terminal component — \
         status callback will NOT be wired. PTY events will not fire.",
        key
    );
}
```

Also wrap the `.unwrap()` — if `component_for_key_mut` returns `None`, that's also a bug worth logging:

```rust
match self.wm.component_for_key_mut(key) {
    Some(AppRootComponent::Core(CoreWmComponent::Terminal(scroll_view))) => {
        // existing callback wiring
    }
    Some(other) => tracing::error!("..."),
    None => tracing::error!("[STAGE 2] No component for key {:?}", key),
}
```

## 2. `next_key()` / `next_mouse()` discard `DirectInputChanged`

**File**: `src/unified_event_source.rs:381, 409`

**Problem**: Empty match arms lose the event. Only `read()` and `drain_pending()` buffer it. Buffering alone isn't enough — `next_key()` returns `KeyEvent` (not `UnifiedEvent`), so there's no way to yield the non-input event to the caller. The loop continues to `recv()` and blocks.

**Fix**: Buffer the event and return a synthetic no-op event to break the blocking loop.

`next_key()` — return `Ok(KeyEvent { code: KeyCode::Char('\0'), modifiers: KeyModifiers::empty(), kind: KeyKind::Release })`:
```rust
Ok(UnifiedEvent::DirectInputChanged(key, enabled)) => {
    self.dirty_windows.insert(key);
    self.direct_input_changed.push((key, enabled));
    return Ok(KeyEvent {
        code: KeyCode::Char('\0'),
        modifiers: KeyModifiers::empty(),
        kind: KeyKind::Release,
    });
}
```

`next_mouse()` — return `Ok(MouseEvent { kind: MouseEventKind::Moved, ... })` — a `Moved` event is inert and won't corrupt drag state:
```rust
Ok(UnifiedEvent::DirectInputChanged(key, enabled)) => {
    self.dirty_windows.insert(key);
    self.direct_input_changed.push((key, enabled));
    return Ok(MouseEvent {
        kind: MouseEventKind::Moved,
        column: 0,
        row: 0,
        modifiers: KeyModifiers::empty(),
    });
}
```

These synthetic events won't match any real input and are silently ignored by downstream handlers, but they break the `recv()` block and let the event loop reach `handler(None)`. `next_key()`/`next_mouse()` are fallback paths not used by the main event loop (`poll()` → `read()`), but this ensures correctness regardless.
