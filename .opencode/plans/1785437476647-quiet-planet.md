# Plan: Mouse Event Coalescing & Backpressure

## Problem

Rapid mouse movements in `term-session-client` produce a burst of individual
`Moved`/`Drag` events from crossterm. Each is encoded as a ~15-byte SGR
sequence and sent as a separate muxio IPC packet. This causes packet
amplification, high CPU overhead, and potential input lag during fast drags.

## Root Cause

**`crates/term-session-client/src/lib.rs:391-433`** — Every `Event::Mouse` from
`input_rx` is immediately encoded and sent via `pane.write_bytes()` with no
coalescing.

**`crates/term-session-server/src/session_server.rs:312`** — Server input
handler uses `mpsc::unbounded_channel` with no memory protection against
bursts.

## Invariants (Must Preserve)

1. **Only motion events may be coalesced:**
   - `Moved` → `Moved` — safe to collapse
   - `Drag(btn)` → `Drag(btn)` — safe only if same button
2. **Modifier state must match:** Coalescing two motion events with differing
   `KeyModifiers` (Shift/Ctrl/Alt pressed/released mid-drag) silently destroys
   the modifier transition state. Terminal apps rely on Shift-Drag, Alt-Drag,
   etc. for selection vs. tracking overrides.
3. **Discrete events are NEVER dropped:** `Press`, `Release`, `ScrollUp/Down/Left/Right`, `Key` events must be preserved in order.
4. **Strict order preservation:** When draining the channel for coalescing, stop
   immediately on a non-coalescable event and buffer it via `pending_input`.

## Changes

### A. Client-Side Coalescing (`crates/term-session-client/src/lib.rs`)

**1. Add `is_coalescable_mouse` helper** that checks both kind AND modifiers:

```rust
fn is_coalescable_mouse(
    a_kind: &MouseEventKind,
    a_mod: &KeyModifiers,
    b_kind: &MouseEventKind,
    b_mod: &KeyModifiers,
) -> bool {
    if a_mod != b_mod {
        return false;
    }
    match (a_kind, b_kind) {
        (Moved, Moved) => true,
        (Drag(btn1), Drag(btn2)) => btn1 == btn2,
        _ => false,
    }
}
```

**2. Add `pending_input: Option<Event>` before main loop.**

**3. Restructure the event loop:** When a `Moved` or `Drag` event is dequeued,
non-blocking-drain `input_rx` for additional coalescable motion events (matching
both kind and modifiers), keeping only the latest coordinates. Buffer the first
non-coalescable event in `pending_input` for the next iteration.

### B. Bounded Server Channel (`crates/term-session-server/src/session_server.rs`)

Change to `mpsc::channel::<Vec<u8>>(128)` with `try_send`. This provides server
memory safety (sheds overflow when PTY write falls behind). Log dropped chunks
at `tracing::warn!` level for debuggability. Note: true transport backpressure
isn't achievable via muxio's sync callback — client-side coalescing does the
real traffic suppression. Dropped chunks may corrupt the PTY byte stream (the
server path processes raw bytes that may contain partial multi-byte sequences),
which is an accepted trade-off for memory safety under extreme bursts.

## Files to Modify

| File | Change |
|------|--------|
| `crates/term-session-client/src/lib.rs` | Add `is_coalescable_mouse`, `pending_input`, restructure main event loop for coalescing |
