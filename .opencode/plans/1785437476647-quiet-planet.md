# Plan: Coalesce Rapid Mouse Events in term-session-client/server

## Problem

Rapid mouse movements produce a burst of individual `Moved`/`Drag` events from
crossterm. In the **term-session-client** path, each event is encoded as a
~15-byte SGR sequence and sent as a separate muxio network packet. Compared to
batched PTY output, this is dramatically more network-expensive because:

1. No coalescing exists for mouse `Moved`/`Drag` events — every event from
   crossterm is individually processed and transmitted.
2. The server input handler uses `mpsc::unbounded_channel` (no backpressure).
3. Intermediate mouse positions are irrelevant — only the latest position
   matters for rendering.

## Root Cause

**File:** `crates/term-session-client/src/lib.rs` lines 391-433
In `run_session()`, each `Event::Mouse` from `input_rx` is immediately encoded
to SGR bytes and sent over the network via `pane.write_bytes()`. No coalescing
or rate-limiting is applied.

**File:** `crates/term-session-server/src/session_server.rs` line 312
The server's `STREAM_INPUT` handler feeds into `mpsc::unbounded_channel`,
providing no backpressure against input bursts.

## Changes

### 1. Coalesce mouse events in session-client (`lib.rs`)

Before the match on `Event::Mouse`, drain and coalesce any additional mouse
events from `input_rx` using `try_recv()`. Keep only the **last** `Moved` or
`Drag` event (per button), discarding intermediate ones. Press/Release/Scroll
events are never dropped — only continuous-motion events.

This is in the main event loop at `lib.rs:339-434`. After receiving the first
input event via `select!`, try_recv additional events; if they are motion
mouse events, update the last-known position and continue draining.

### 2. Bound server input channel (`session_server.rs`)

Change `mpsc::unbounded_channel::<Vec<u8>>()` to `mpsc::channel::<Vec<u8>>(128)`
(bounded capacity of 128) to provide backpressure. When the PTY write task is
overwhelmed, the streaming channel will apply backpressure to the client.

### 3. (Optional) Rate-limit mouse sends in session-client

Add a `last_mouse_send: Option<Instant>` tracker. If the last mouse send was
<16ms ago, skip the current mouse event and wait for a newer one. This aligns
mouse dispatch with the 60fps render cadence.

### Files to Modify

| File | Change |
|------|--------|
| `crates/term-session-client/src/lib.rs` | Add mouse event coalescing in main loop (lines ~391-433) |
| `crates/term-session-server/src/session_server.rs` | Change unbounded channel to bounded (line ~312) |
