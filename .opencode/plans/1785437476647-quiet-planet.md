## Remaining: Resize Black-Screen Fix

### Root Cause 1: Stale render gate

In `term-session-client/src/lib.rs`, `has_new_data` is computed *before* the
`Event::Resize` handler runs:

```rust
let has_new_data = pane.drain_pushes() || input_event.is_none();  // pre-computed
...
match evt {
    Event::Resize(w, h) => {
        pane.resize(size);   // parser.set_size happens here
    }
}
...
if has_new_data {            // false — resize didn't produce PTY data
    render_frame(...)        // skipped → black screen until next key press
}
```

`pane.resize()` calls `parser.screen_mut().set_size(rows, cols)` which fills
the new screen with blank cells. But the render is gated by `has_new_data`,
which was already evaluated to `false` (the event was `Resize`, not PTY
output). The resized-but-blank screen is never drawn.

### Root Cause 2: OnPtyResized registered after Spawn

The client registers `OnPtyResized` handler **after** calling `Spawn::call()`.
The server's `Spawn` handler calls `notify_clients()`, which fires
`OnPtyResized::call()` back to the client over the same IPC connection.
Since the client's endpoint hasn't registered the handler yet, it returns
`RpcMethodNotFound`.

This is the source of the intermittent `RpcMethodNotFound` error — it happens
when `ClientConnected` arrives before `Spawn` is processed (the client entry
has `caller: Some(handle)` at that point), so `notify_clients()` tries to
call the client but the handler isn't ready.

### Fixes

**1. Force render after resize** — add a `force_render` flag:

```rust
let mut force_render = false;
...
Event::Resize(w, h) => {
    ...
    force_render = pane.resize(size).is_ok();
}
...
if has_new_data || force_render {
    render_frame(...)
}
```

**2. Register OnPtyResized before Spawn** — move the
`register_prebuffered(OnPtyResized::METHOD_ID, ...)` call to right after
the muxio IPC connection is established, before `Spawn::call()`.

Also log the `pane.resize()` error with `tracing::warn!` instead of `let _ =`.
