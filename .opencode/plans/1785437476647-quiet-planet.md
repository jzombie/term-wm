## Remaining: Resize Black-Screen Fix + DECAWM Row Duplication Race

### Root Cause 1: Stale render gate

In `term-session-client/src/lib.rs`, `has_new_data` is computed *before* the
`Event::Resize` handler runs:

```rust
let has_new_data = pane.drain_pushes() || input_event.is_none();  // pre-computed
...
match evt {
    Event::Resize(w, h) => {
        pane.resize(size);   // parser.set_size happens here
    }
}
...
if has_new_data {            // false — resize didn't produce PTY data
    render_frame(...)        // skipped → black screen until next key press
}
```

`pane.resize()` calls `parser.screen_mut().set_size(rows, cols)` which fills
the new screen with blank cells. But the render is gated by `has_new_data`,
which was already evaluated to `false` (the event was `Resize`, not PTY
output). The resized-but-blank screen is never drawn.

### Root Cause 2: OnPtyResized registered after Spawn

The client registers `OnPtyResized` handler **after** calling `Spawn::call()`.
The server's `Spawn` handler calls `notify_clients()`, which fires
`OnPtyResized::call()` back to the client over the same IPC connection.
Since the client's endpoint hasn't registered the handler yet, it returns
`RpcMethodNotFound`.

This is the source of the intermittent `RpcMethodNotFound` error — it happens
when `ClientConnected` arrives before `Spawn` is processed (the client entry
has `caller: Some(handle)` at that point), so `notify_clients()` tries to
call the client but the handler isn't ready.

### Root Cause 3: resize_pending screen-wipe without redraw

When `OnPtyResized` arrives after registration, the handler sets
`resize_pending = true`. The event loop checks this flag and executes
`out.write_all(b"\x1b[0m\x1b[2J\x1b[H")` — which erases the terminal —
but if `has_new_data` is false, `render_frame()` is skipped, leaving
a blank screen.

### Fixes

**1. Decouple OnPtyResized handler from RemotePane** — use atomic registers
so registration can happen before `Spawn::call()`:

```rust
let server_cols = Arc::new(AtomicU16::new(0));
let server_rows = Arc::new(AtomicU16::new(0));
let resize_pending = Arc::new(AtomicBool::new(false));

// Register immediately after client connect, before Spawn::call()
{
    let cols_ref = Arc::clone(&server_cols);
    let rows_ref = Arc::clone(&server_rows);
    let pending_ref = Arc::clone(&resize_pending);
    rt.block_on(client.get_endpoint().register_prebuffered(
        OnPtyResized::METHOD_ID,
        move |payload, _ctx| {
            let (cols, rows) = OnPtyResized::decode_request(&payload)?;
            cols_ref.store(cols, Ordering::Relaxed);
            rows_ref.store(rows, Ordering::Relaxed);
            pending_ref.store(true, Ordering::Relaxed);
            OnPtyResized::encode_response(())
        },
    ))?;
}
```

**2. Update event loop** — apply server geometry + force render when
`resize_pending` fires, and force render on local `Event::Resize`:

```rust
let mut force_render = false;

// (in match on event)
Event::Resize(w, h) => {
    let size = PtySize { rows: h, cols: w, .. };
    if let Err(err) = pane.resize(size) {
        tracing::warn!(error = %err, "resize failed");
    }
    force_render = true;
}

// (after event match, before render gate)
if resize_pending.swap(false, Ordering::Relaxed) {
    let cols = server_cols.load(Ordering::Relaxed);
    let rows = server_rows.load(Ordering::Relaxed);
    if cols > 0 && rows > 0 {
        let mut parser = pane.shared_parser().lock().unwrap();
        parser.screen_mut().set_size(rows, cols);
    }
    let _ = out.write_all(b"\x1b[0m\x1b[2J\x1b[H");
    let _ = out.flush();
    force_render = true;
}

// Render gate
if has_new_data || force_render {
    render_frame(&mut out, screen, rows, cols)?;
}
```

### Root Cause 4: PTY stream vs OnPtyResized channel race (DECAWM row dup)

When Client A resizes:

1. Server resizes PTY, broadcasts `OnPtyResized` to Client B via RPC.
2. Shell/TUI process gets `SIGWINCH`, redraws UI for new bounds, writes
   bytes into PTY master.
3. Server streams those bytes to Client B via `push_rx` (streaming channel).

Because `push_rx` (PTY stream) and `OnPtyResized` (RPC) travel on separate
muxio channels, the new PTY redraw bytes often arrive at Client B **before**
it processes `OnPtyResized`.

The PTY output was formatted for the new larger grid, but Client B's VTE
parser still has the old smaller grid. Writing to the bottom-right cell
triggers ANSI auto-scroll (`DECAWM`), shifting content up and duplicating
the last row. A few ms later `OnPtyResized` expands the grid and fixes it.

### Fix: Check resize_pending BEFORE processing PTY data (two sites)

The resize check must run at two points:

1. **Top of loop** — catches geometry changes that arrived before `select!`.
2. **Inside the `push_rx` arm** — catches geometry changes that arrived
   *while the thread was blocked in `select!`*. The PTY bytes in the arm
   were formatted for the new grid size, so the parser must be resized
   before `parser.process(&data)`.

```rust
loop {
    let mut force_render = false;

    // ── Site 1: top of loop ──────────────────────────────────────────
    if resize_pending.swap(false, Ordering::Relaxed) {
        // ... apply geometry, clear screen ...
        force_render = true;
    }

    let input_event = if let Some(evt) = pending_input.take() {
        Some(evt)
    } else {
        crossbeam_channel::select! {
            recv(input_rx) -> msg => { ... }
            recv(push_rx) -> msg => {
                match msg {
                    Ok(data) => {
                        // ── Site 2: inside push_rx arm ────────────
                        // PTY bytes may be for a resized grid; apply
                        // geometry before feeding them to the parser.
                        if resize_pending.swap(false, Ordering::Relaxed) {
                            // ... apply geometry, clear screen ...
                            force_render = true;
                        }
                        let parser = pane.shared_parser();
                        let mut parser = parser.lock().unwrap();
                        parser.process(&data);
                        None
                    }
                    Err(_) => None,
                }
            }
        }
    };

    let has_new_data = pane.drain_pushes() || input_event.is_none();

    // ... clipboard, sigint, event match ...

    // ── Render gate ────────────────────────────────────────────────────
    if has_new_data || force_render {
        render_frame(...)?;
    }

    if pane.has_exited() { return Ok(()); }
}
```

## New Fixes: Intermittent Black Screen After Resize

### Root Cause A: Server echo loop (primary vector)

When **Client A** resizes:
1. Client A sends `ResizePty` RPC → server resizes PTY → broadcasts `OnPtyResized` to **all** clients — including Client A.
2. The PTY app receives `SIGWINCH` and writes redraw bytes into the stream, arriving at Client A via `push_rx`.
3. Client A processes the redraw bytes successfully.
4. **Milliseconds later**, the echoed `OnPtyResized` arrives at Client A. `resize_pending = true` fires `\x1b[0m\x1b[2J\x1b[H`, **erasing the already-rendered screen**.
5. No further PTY data arrives → the screen stays black.

### Root Cause B: No-op resize guard missing

The `OnPtyResized` handler stores `(cols, rows)` and sets `resize_pending = true` unconditionally — even when the new dimensions match the already-applied parser size. Duplicate/identical resize notifications trigger unnecessary `\x1b[2J` wipes.

### Root Cause C: Diff cache invalidation (N/A here)

Exploration confirmed **no** `previous_frame` / diff cache exists in `render_frame` or vt100 — this codebase does a full-cell render every frame. Root Cause C is not applicable.

### Fix 1: Server — filter originating client from broadcast

In `session_server.rs` `ResizePty` handler, exclude the client whose `conn_id` matches `ctx.conn_id` from the `OnPtyResized` broadcast. This eliminates the echo loop entirely.

```rust
let origin = ctx.conn_id;
let targets: Vec<ClientEntry> = guard.clients.iter()
    .filter(|(&id, _)| id != origin)
    .map(|(_, entry)| entry.clone())
    .collect();
drop(guard);
ServerState::notify_clients(&targets, ncols, nrows);
```

### Fix 2: Client — guard OnPtyResized handler against no-ops

Store new cols/rows and set `resize_pending = true` **only** when the incoming dimensions differ from the already-stored `server_cols` / `server_rows`.

```rust
async move {
    let (cols, rows) = OnPtyResized::decode_request(&payload)
        .map_err(|e| Box::new(e) as Box<dyn std::error::Error + Send + Sync>)?;
    let cur_cols = cols_ref.load(Ordering::Relaxed);
    let cur_rows = rows_ref.load(Ordering::Relaxed);
    if cols != cur_cols || rows != cur_rows {
        cols_ref.store(cols, Ordering::Relaxed);
        rows_ref.store(rows, Ordering::Relaxed);
        pending_ref.store(true, Ordering::Relaxed);
    }
    OnPtyResized::encode_response(())
        .map_err(|e| Box::new(e) as Box<dyn std::error::Error + Send + Sync>)
}
```

### Fix 3: Client — update atomic dimensions immediately on local resize

In `Event::Resize(w, h)`, write `(w, h)` to `server_cols`/`server_rows` **before** sending the RPC. This ensures the OnPtyResized no-op guard (Fix 2) catches the echoed notification when it arrives.

Also resize the parser locally + issue `\x1b[2J` + set `force_render = true` directly in the handler, so the render gate fires regardless of `has_new_data`.

```rust
Event::Resize(w, h) => {
    // Pre-emptively update atomics so echoed OnPtyResized is a no-op
    server_cols.store(w, Ordering::Relaxed);
    server_rows.store(h, Ordering::Relaxed);

    // Resize parser locally
    let parser = pane.shared_parser();
    let mut parser_lk = parser.lock().unwrap();
    parser_lk.screen_mut().set_size(h, w);

    // Send RPC to server
    let size = PtySize { rows: h, cols: w, pixel_width: 0, pixel_height: 0 };
    if let Err(err) = pane.resize(size) {
        tracing::warn!(error = %err, "resize request failed on PTY pane");
    }

    // Clear terminal + force the render gate
    let _ = out.write_all(b"\x1b[0m\x1b[2J\x1b[H");
    let _ = out.flush();
    force_render = true;
}
```

### Fix 4: Client — guard `apply_pending_resize` against redundant clear

Add a dimension comparison against the **parser's current size** before issuing `\x1b[2J`. Defense-in-depth for any remaining stray resize notifications.

```rust
let mut apply_pending_resize = |shared_parser: &Arc<Mutex<Parser>>,
                                 stdout: &mut io::Stdout|
{
    if resize_pending.swap(false, Ordering::Relaxed) {
        let cols = server_cols.load(Ordering::Relaxed);
        let rows = server_rows.load(Ordering::Relaxed);
        if cols > 0 && rows > 0 {
            let mut parser_lk = shared_parser.lock().unwrap();
            let (cur_rows, cur_cols) = parser_lk.screen().size();
            if cur_cols != cols || cur_rows != rows {
                parser_lk.screen_mut().set_size(rows, cols);
                let _ = stdout.write_all(b"\x1b[0m\x1b[2J\x1b[H");
                let _ = stdout.flush();
                force_render = true;
            }
        }
    }
};
```
