# Plan: Gate top drag gestures on the window's rect (not just the cursor)

## Goal

Stop the window manager from offering the **top-half snap** and **maximize** previews
during a drag unless **the dragged window itself** has actually reached the top of the
workspace AND the cursor is in the top drag-handle space. Current code decides top
gestures purely from cursor position (`mouse_y == 0` → Maximize; `detect_edge_snap`
returns `Top` when the cursor is within 3 cells of the top edge), so dragging a
top-anchored window sideways instantly offers a top snap.

Root cause (confirmed by the user): every previous revision checked the **cursor**,
never the **window's rect**. The user's minimal check:

```rust
let window_at_top    = window_rect.y <= area.y;   // window's own top edge
let cursor_in_handle = mouse_y     <= area.y;     // cursor in the drag-handle space
// snap only when BOTH are true
```

## Behavioral spec (user-confirmed)

- **Top-half snap** fires only when `window_at_top && mouse_y == area.y`
  (cursor on the top workspace border row — the window's top border).
- **Maximize** fires only when `window_at_top && mouse_y < area.y`
  (cursor overshot into the header/panel above the workspace).
- **No header case** (`area.y == 0`): `mouse_y < area.y` is impossible, so
  drag-to-maximize is unreachable; the top border row (`mouse_y == 0`) → top-half snap.
  Maximize remains available via title-bar double-click / keyboard. (Confirmed Option 1.)
- Side/bottom edge snaps and corner snaps are unchanged.

## Implementation (single function: `update_snap_preview`, drag.rs:186)

Edit `crates/term-wm-core/src/window/window_manager/drag.rs` only.

1. Compute the dragged window's **live** top edge. `self.region()` reflects the last
   layout projection and can lag during an active drag; `move_floating` updates
   `self.floating_rect(key)` every drag event, so use it. For the fallback (floating
   rect absent), use `full_region()` — NOT `region()` — because `region()` returns the
   chrome-subtracted **content** rect (`content_rect` adds `TOP_BORDER_HEIGHT +
   HEADER_HEIGHT` offset, so `content.y` sits at `area.y + 2` for a frame parked at
   `area.y`, breaking the `<=` check). `full_region()` returns the full frame bounds:

   ```rust
   let window_at_top = self
       .floating_rect(dragging_key)
       .map(|spec| spec.resolve_signed(area))
       .is_some_and(|r| r.y <= area.y)
       || (self.floating_rect(dragging_key).is_none()
           && self.full_region(dragging_key).y <= area.y);
   ```

2. Replace Priority 2 (the `mouse_y == 0 → Maximize` block, drag.rs:276-281) with the
   gated top-gesture branch:

   ```rust
   if window_at_top {
       if (mouse_y as i32) < area.y {
           // Overshoot into top header/panel → maximize (needs area.y >= 1).
           self.drag_snap = Some((None, InsertPosition::Top, area));
           self.snap_preview = Some(SnapPreviewState::Maximize);
           return;
       }
       if (mouse_y as i32) == area.y {
           // Cursor on the top workspace border row → top-half snap.
           let top_pos = Some(InsertPosition::Top);
           // fall through to the shared edge-snap preview computation below
           // with top_pos forced, reusing get_projected_preview / edge_preview_rect.
       }
   }
   ```

   Then run the existing Priority 3 edge-snap block with the position forced to
   `InsertPosition::Top` when the gated condition matched, otherwise with
   `detect_edge_snap(...)` **filtered to exclude Top**. The forced `top_pos` MUST feed
   straight into the existing Priority 3 preview pipeline (`snap_preview_cache` +
   `get_projected_preview`, with `edge_preview_rect` fallback) so `Edge(Top)` previews
   render the same dry-run tiling projection as `Edge(Left)`/`Edge(Right)` — do NOT
   create a separate preview code path:

   ```rust
   let edge_pos = top_pos.or_else(|| {
       detect_edge_snap(mouse_x, mouse_y, managed_layout_rect, EDGE_SNAP_THRESHOLD)
           .filter(|p| *p != InsertPosition::Top)
   });
   if let Some(pos) = edge_pos {
       // ... existing edge-snap preview body unchanged ...
   }
   ```

   Filtering `Top` out of `detect_edge_snap` is required: without it, a cursor within
   3 cells of the top edge would still snap to Top even when the window is NOT at the
   top — the exact bug being fixed.

3. Keep the comment preservation rule: update the Priority 2 doc comment (drag.rs:176
   "Sacred top edge maximize") to describe the new window-rect gating.

## Tests

`update_snap_preview` is `pub(super)` and the `mod tests` block lives in the same
module (mod.rs:2949) plus the helper `set_panel_visible`. Add tests that call
`wm.update_snap_preview(key, col, row, &mut detach)` directly (via the existing
`WindowManager::<TestComponent>` fixture) with a floating rect / `managed_area`
primed:

1. `window at top (fr.y == area.y) + mouse_y == area.y` → `Edge(Top)`, drag_snap Some.
2. `window at top + mouse_y < area.y` (area.y = 1, header visible) → `Maximize`.
3. `window NOT at top (fr.y > area.y) + mouse_y == area.y` → no snap (cleared).
4. `window NOT at top + mouse_y < area.y` → no maximize.
5. `window at top + mouse_y > area.y` (sideways drag on the title bar) → no top snap;
   `Left`/`Right` edge snap still works when near a side edge.
6. `area.y == 0` (panel hidden): window at top + `mouse_y == 0` → `Edge(Top)`, never
   `Maximize`.
7. Corner snap unchanged: `detect_corner_snap` still produces TopLeft/TopRight
   regardless of window position.
8. **Frame (not content) rect gate**: with `floating_rect` absent and a frame parked
   at `area.y` (chrome-enabled, `region().y == area.y + 2`), `window_at_top` is true
   via `full_region().y` — verifies the SEV-2 fallback fix.

## Out of scope / notes

- Corner snaps (including TopLeft/TopRight) remain cursor-based, per current behavior.
  If the user wants top corners gated on `window_at_top` too, that's a follow-up.
- No changes to `detect_edge_snap` / `detect_corner_snap` in the layout engine.
- No changes to the release handler (mod.rs:1616) — `Maximize` → `toggle_maximize`,
  else `drag_snap.is_some()` → `apply_snap` already does the right thing.
