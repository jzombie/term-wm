# Fix flaky `spawn_round_trips_non_utf8_cwd` (Ubuntu CI)

## Root cause (confirmed by code reading)

Failure signature: `assert_eq!(path_wire::decode_path(&reported), expected)` at
`crates/term-session-server/src/session.rs:325` got `left: ""`.

1. The mock's `pwd` subcommand publishes its report with `std::fs::write`
   (`crates/term-session-mock/src/main.rs:349-367`). That call is
   `open(O_CREAT|O_TRUNC)` followed by `write_all`, so there is a real window
   where the report file exists with 0 bytes.
2. `read_report` (`crates/term-session-server/src/session.rs:235`) treats any
   successful `fs::read` as final, including a 0-byte read. With 41 other tests
   running concurrently on CI, the freshly exec'd child can be preempted inside
   that window; the parent's 20 ms poll then observes an empty file, decodes it
   to `""`, and the assertion fails. Suite finished in 0.28 s: consistent with
   an early empty read, not with the 10 s timeout path.
3. Precedent proves this class was known: `crates/term-session/tests/daemon_tests.rs:364-381`
   polls with `.filter(|content| !content.is_empty())` and comments "a read
   that races the truncate can observe a zero-length file". The newer shared
   helper lost that guard.

`PathWire` / `encode_path` / `decode_path` are byte-lossless on Unix; not involved.

## Changes

### 1. Consumer guard: `crates/term-session-server/src/session.rs`

In `read_report` (~line 241), treat a zero-byte read as an uncommitted write
and keep polling:

```rust
if let Ok(bytes) = std::fs::read(report)
    && !bytes.is_empty()
{
    ...
}
```

Update the doc comment to cite the truncate race and point at the
`daemon_tests.rs` precedent. Safe for both callers: `pwd` reports are always an
absolute path (>= 1 byte) and `envvar` reports always carry the `NAME=` prefix
(>= 2 bytes) even when the value is unset (see test at session.rs:374).

### 2. Producer atomicity: `crates/term-session-mock/src/main.rs`

Add a small `write_report_atomic(file, bytes)` helper used by both `pwd` and
`envvar`:

- Build a unique sibling temp name embedding the pid,
  `{file}.tmp.{pid}` (`std::process::id()`), so concurrent mock invocations
  that happen to share a report directory can never collide on the staging
  path.
- Write the bytes to the temp path, then `std::fs::rename` onto the final
  path. Same-directory rename is atomic on Unix and Windows, so consumers see
  either no final file or complete content.
- If the rename fails, remove the leftover temp file (best-effort) before
  returning the error, then exit nonzero like other mock failures.

This removes the race class for every consumer of these fixtures, not just
`read_report`.

### 3. Loud failure: `pwd` must not publish an empty report

Replace `std::env::current_dir().map(encode).unwrap_or_default()` with error
propagation: if `current_dir()` fails, print diagnostics to stderr and exit
with code 1 without creating the report. Today that failure silently writes
0 bytes, which would mask the real cause behind an empty-path assertion (or,
after fix 1, behind a timeout).
