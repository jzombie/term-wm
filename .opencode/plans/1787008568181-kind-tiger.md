# Plan: Fix Workspace Switching Bugs

## Bug 1: Double `/main` path construction

**Root cause:** The launcher does `format!("{}/main", current_workspace)`. If the user passes `-w ws-1787010145/main`, the channel becomes `ws-1787010145/main/main` (3 segments), which `ChannelName::parse` rejects.

**Fix in `src/main.rs`:** Normalize the workspace name before use. If it already contains `/`, extract just the first segment (the workspace name). Apply this normalization once at startup:

```rust
let mut current_workspace = cli.workspace
    .split('/')
    .next()
    .unwrap_or("default")
    .to_string();
```

Also apply the same normalization in `App::new_with` when setting `current_workspace`:
```rust
let workspace = workspace.split('/').next().unwrap_or(&workspace).to_string();
```

## Bug 2: Rebind check unreachable while blocked on select

**Root cause:** The `rebind_target` check is at the **bottom** of the event loop, after `crossbeam_channel::select!` which blocks waiting for PTY output or input. If the `OnWorkspaceRebind` handler fires on the tokio runtime but there's no pending PTY output, the main thread stays blocked on select and never reaches the rebind check.

**Fix in `crates/term-session-client/src/lib.rs`:** Move the rebind check to the **top** of the loop (before the blocking select), matching the pattern used by `OnPtyResized` (resize is checked at the top via `apply_pending_resize`). This ensures the rebind signal is processed on every iteration without waiting for PTY data.
