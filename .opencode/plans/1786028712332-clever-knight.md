# Plan: Revert resize-garbage experiments — accept the zsh protocol limitation

## Status
Final. Every attempt to eliminate the resize artifact was rejected by code review on valid
grounds. The review's conclusion is binding: the artifact is an inherent limitation of
zsh's SIGWINCH redraw (`\r ESC[J` erases only downward) combined with universal reflow,
and cannot be fixed at the emulator or compositor without destroying data or corrupting
coordinates. Revert all experiments; keep pure reflow; accept the artifact.

## What was tried and why each was rejected

- **Preserve the cursor's active line in reflow** — rejected: non-universal reflow,
  data loss for canonical apps.
- **Collapse/truncate the active line** — rejected: unconditional data destruction.
- **Snap the cursor to the line start** — rejected: corrupts cursor coordinates.
- **OSC 133 (Shell Integration) active-zone collapse** — rejected as a VTE hack and,
  later, to be stripped entirely (pure reflow isolation).
- **Compositor-layer active-line wipe in `Pty::resize`** — rejected: races the
  asynchronous SIGWINCH/redraw stream, and destroys data for non-redrawing processes.
- **Frame-buffer pre-blanking** — rejected: `render_screen` repaints from the grid, so
  blanking is inert.

The common thread: the artifact is caused by **zsh emitting `\r ESC[J` (erase-down) for a
prompt that reflow re-wrapped into rows above the cursor**. The shell's clear cannot reach
those rows, and no emulator/compositor mutation can remove them without breaking the
state machine or the data.

## Actions

1. **`vendor/vt100` — strip all experiments, restore pure universal reflow**:
   - Remove OSC 133 parsing (`perform.rs` `[b"133", ...]` arm), the `prompt_zone` flag
     (`row.rs`), the `prompt_marking`/`prompt_zone_active` fields + `text()` marking +
     `prompt_zone_*` methods (`screen.rs`).
   - Remove the active-zone collapse branch in `Grid::reflow` and the
     `prompt_zone_active` parameter threading; restore `Screen::set_size` /
     `Grid::set_size` to `(size, reflow)`.
   - Keep the fundamental soft-wrap reflow (universal) unchanged.
2. **`vendor/vt100/tests/reflow.rs`, `basic.rs`, `csi.rs` — restore universal-reflow
   expectations**: remove the OSC 133 / active-zone / cursor-line-preservation tests;
   keep only grid-integrity and coordinate tests.
3. **Remove temporary harnesses**: `vendor/vt100/tests/probe.rs`,
   `crates/term-wm-pty-engine/tests/probe_shell.rs` (already deleted), any test files
   added during the experiments.
4. **No new code in `term-wm-pty-engine` / `term-wm-ui-components`**: no `Pty::resize`
   mutation, no frame pre-blanking, no compositor active-line handling.

## Documentation (so the behavior is not a surprise)

Add a note (e.g. in the pty-engine or terminal docs / AGENTS.md) stating:
- term-wm uses universal grid reflow on resize, which preserves all scrollback data.
- On width shrink, a shell prompt that re-wraps may briefly show duplicated/stale prompt
  rows because the shell's `\r ESC[J` SIGWINCH redraw only erases downward. This is a
  protocol limitation of shell-driven redraw, present in other reflowing terminals.
- Data is never lost; scrolling shows the full buffer.
