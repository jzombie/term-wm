# Plan: Terminal "garbage" on horizontal resize — revert to universal reflow (final)

## Status
Decision confirmed by user + review: keep universal reflow, accept the zsh redraw artifact,
revert all cursor-line special-casing. This plan is ready to execute.

## Symptoms

Resizing horizontally (worst with tiled windows running `ls -lsa`) leaves garbage rows:
partial/duplicated shell prompt rows (`administrator`, `administrator@d17-4 term-w`,
`administ`), corrupted `ls` wrap boundaries, one stale prompt row accumulating per cycle.

## Root cause (confirmed, reproduced)

- `Grid::reflow` re-wraps every logical line including the cursor's active line (the shell
  prompt). Shrinking re-wraps a 1-row prompt into 2 rows.
- The shell redraws its prompt on SIGWINCH with `\r \r ESC[0m ESC[27m ESC[24m ESC[J
  <prompt>`. `ESC[J` (ED) erases **only downward from the cursor**. After reflow, the
  prompt's first row sits above the cursor row, survives the erase, and the shell draws a
  second copy below → duplicated/stale prompt rows that accumulate across resizes.
- The byte stream is correct; the emulator leaves stale rows the shell's erase-from-cursor
  redraw cannot reach. This is a **zsh application-layer defect** (incomplete erase for its
  own multi-row prompt geometry), not a VTE bug.

## Decision

Keep **universal reflow** (the cursor line reflows with the exact same wrapping math as
every other line, retaining 100% of its character data) and **accurate cursor
coordinates**. **Accept the visual artifact.** No emulator-level hacks (data loss,
coordinate repositioning, or per-line divergence) are permitted; the VTE is a presentation
layer and must not mask application-layer rendering defects. If the artifact must be
resolved, the fix belongs upstream in `zsh`'s SIGWINCH handler.

## Actions

1. **`vendor/vt100/src/grid.rs` — remove the `is_cursor_line` divergence** in
   `Grid::reflow`: delete the preserve/collapse branch so the cursor's logical line is
   flattened and re-wrapped exactly like all other lines (universal reflow, accurate
   `reflow_forward`/`reflow_reverse` cursor mapping).
2. **`vendor/vt100/tests/reflow.rs`, `tests/basic.rs`, `tests/csi.rs` — revert test
   expectations** back to universal reflow semantics: content on the cursor line re-wraps
   too; the earlier cursor-line-preservation expectations (`cursor_line_is_preserved…`,
   `cursor_in_short_early_wrapped_row`, `pending_wrap_cursor_survives_reflow`,
   `saved_cursor_…`, `set_size`, `xtwinops`) are restored to the pre-divergence values.
3. **Remove shell-specific / temporary tests**: `vendor/vt100/tests/probe.rs` and
   `crates/term-wm-pty-engine/tests/probe_shell.rs`. The VTE suite must validate grid
   integrity and coordinate math only — no `\r ESC[J …` payload simulations.

## Notes for the user

- After this change, narrowing a terminal whose prompt wraps will still show stale-prompt
  rows (the accepted zsh artifact). No data is lost; scrolling shows all content intact.
- To actually eliminate the artifact, a patch to `zsh`'s SIGWINCH handler (clear the full
  prompt region, not just erase-down) is the correct venue — out of scope for this repo.

## Verification

1. `cargo test -p vt100` — all pass (universal reflow expectations restored; no
   shell-specific tests).
2. `cargo test -p term-wm-pty-engine`, `cargo clippy --workspace --all-targets
   --all-features -- -D warnings` — clean.
3. Manual: narrow resize leaves the accepted stale-row artifact; confirm **no data loss**
   (typed commands / `ls` output fully preserved in the buffer and when scrolled).
