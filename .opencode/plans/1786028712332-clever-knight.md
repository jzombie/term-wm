# Plan: Fix resize "garbage" via OSC 133 (Shell Integration) prompt zones

## Status
Investigations complete. Prior emulator-side fixes (cursor-line divergence, single-row
collapse, coordinate anchoring) were rejected because the VTE cannot *know* a line is
shell-owned without explicit signaling. Final directive: implement **OSC 133 Semantic
Zones**, apply special reflow treatment **only** to explicitly-marked prompt zones, and
keep universal reflow for all unmarked text.

## Problem / symptoms

Resizing horizontally (tiled windows, `ls -lsa`) leaves garbage rows: duplicated/partial
shell prompt text (`administrator`, `administrator@d17-4 term-w`, `administ`) that
accumulates one stale row per resize cycle.

## Root cause (reproduced)

- `Grid::reflow` re-wraps the cursor's active line. Shrinking re-wraps a 1-row prompt into
  2 rows.
- zsh redraws its prompt on SIGWINCH with `\r ESC[0m ESC[27m ESC[24m ESC[J <prompt>`.
  `ESC[J` erases **only downward from the cursor**. The reflowed prompt's first row sits
  above the cursor, survives the erase, and the shell draws a second copy below.
- The byte stream is correct; the emulator lacks context about which rows the shell owns.
  Without explicit signaling, ANY emulator-side change either destroys data or corrupts
  cursor coordinates.

## Design: OSC 133 semantic zones

### 1. OSC 133 parsing (vendored `vt100`, escape-sequence layer)
Handle the Shell Integration OSC sequences in the existing OSC dispatch:
- `OSC 133 ; A ST` — **Prompt Start**
- `OSC 133 ; B ST` — **Command Start**
- `OSC 133 ; C ST` / `;D` / `;E` / `;F` — Command End / Executed / more output /
  sub-prompt (parsed; only A/B drive zone tracking)

### 2. Persistent row-level prompt-zone metadata (`Screen`/`Grid`/`Row`)
- When `;A` arrives, open the zone and begin marking rows as they are written.
- When `;B` arrives, **stop marking new rows but do NOT clear the marker** (the resize that
  matters happens while typing, after `;B`, before `;C`).
- The marker is persistently bound to the rows and survives until one of: the row is
  explicitly erased (`ED`/`EL`), it scrolls into scrollback (flag carried; dropped only on
  scrollback eviction), or a terminal reset (`RIS`).
- Implementation: a `prompt_zone: bool` flag on `Row` (or a parallel bitmask in `Grid`).

### 2b. Active-zone state (decouples the semantic marker from the render heuristic)
- Maintain a separate `zone_active` flag in `Screen`: **true** from the most recent
  `OSC 133 ; A` until it is finalized by `OSC 133 ; C` / `;D` (Command Executed). The
  resize artifact is exclusively a phenomenon of this *active* input line.
- The persistent `prompt_zone` marker and the `zone_active` flag are **independent**:
  a historical prompt row is marked `prompt_zone` but `zone_active` is false.

### 3. Zone-aware reflow (`Grid::reflow`)
The specialized treatment is gated on **`prompt_zone` AND `zone_active`**:
- **Active prompt zone rows only**: 
  - Respect hard line breaks: explicit `\r\n` inside the prompt keeps the prompt on
    multiple physical rows (a 2-line p10k-style prompt stays 2 lines).
  - Truncate soft wraps only: characters beyond `new_cols` are truncated (not soft-wrapped
    into a new row), so the active prompt never spills into extra rows and the shell's
    SIGWINCH redraw clears it cleanly.
  - Anchor the cursor to the active zone so the shell's erase-from-cursor covers it.
  - Authorized only because the shell explicitly marked the zone (it owns and redraws it).
- **Historical prompt-zone rows** (marked but `zone_active == false`) and **all unmarked
  text** (`/bin/sh`, `cat`, REPLs, ordinary output): strict **universal reflow** — wrap to
  as many rows as mathematically required, preserve 100% of character data, exact cursor
  coordinates. The shell never redraws historical output, so truncating it would be
  pure data destruction; the destructive path exists only for the active zone.

### 3. Environment dependency
The fix only activates when the shell emits OSC 133. zsh emits it when Shell Integration
is enabled (e.g. `p10k`, `zsh`'s `PROMPT`/`zle` integration, or a
`preexec`/`precmd` hook emitting `\e]133;A\a` / `\e]133;B\a`). Document this in
`term-wm` so users enable it; plain `/bin/sh` and unconfigured shells fall back to
universal reflow (artifact remains — accepted, per prior review).

## Files to change

- `vendor/vt100/src/` — OSC 133 handling + prompt-zone tracking (`perform.rs`/`screen.rs`/
  `grid.rs`); `Grid::reflow` zone-aware special path.
- `vendor/vt100/tests/` — OSC 133 parsing tests; zone-marked reflow tests (prompt zone
  truncates cleanly, no stale rows); unmarked lines still reflow universally.
- `crates/term-wm-pty-engine/` — verify no regression in the reader loop / env sanitizer.
- Remove temporary harnesses: `vendor/vt100/tests/probe.rs`,
  `crates/term-wm-pty-engine/tests/probe_shell.rs`.

## Tests to add

- **OSC 133 parse / state**: feed `ESC]133;A … ESC]133;B`; assert rows are marked and
  `zone_active` is true; feed `ESC]133;C`; assert `zone_active` flips false while the
  `prompt_zone` marker **persists**; assert the marker clears only on `ED`/`EL`, scrollback
  eviction, or `RIS`.
- **Active-zone reflow (state-machine, no shell byte simulation)**: inject `ESC]133;A`,
  mock prompt text, `ESC]133;B`, trigger a resize. Assert: active prompt rows truncated to
  `new_cols`, hard `\r\n` breaks preserved (a 2-line prompt stays 2 lines), no extra
  soft-wrap rows, cursor anchored correctly.
- **Historical zone falls back to universal reflow**: after `ESC]133;C`, resize again;
  assert the now-historical prompt rows wrap fully with **100% data preserved** (identical
  to unmarked output).
- **Unmarked universal reflow**: no OSC 133 → cursor-line content re-wraps fully,
  coordinates accurate, no data loss (restores the original reflow test expectations).
- Do **not** feed shell redraw payloads (`\r ESC[J …`) into the VTE suite — the VTE tests
  validate the terminal state machine only.
