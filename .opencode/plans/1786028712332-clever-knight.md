# Plan: Add line-reflow on terminal resize (fix scrollback truncation in normal mode)

## Problem

When a terminal is **not** in alternate-screen mode, resizing the window loses/garbles
text. The shell prompt re-wraps (the shell redraws that line on SIGWINCH) but
previously-buffered scrollback and on-screen output stay at the old wrap width and get
**truncated** — trailing characters past the new column count are silently dropped.

### Root cause
`vt100` 0.16.2 (`doy/vt100-rust`) does **no reflow** on resize. `Grid::set_size`
(`grid.rs:66-100`) calls `row.wrap(false)` and `Row::resize` truncates/pads cells
(`row.rs:73-76`). Wrapped lines are never re-chunked to the new width. The repo already
abandoned history-replay for `set_size` because replay re-interprets absolute cursor moves
and corrupts rows (`history_replay_corrupts_percent_lines_via_ansi_cursor_movements`,
pty.rs:1966).

Alt-screen appears fine only because (a) its grid has zero scrollback and (b) full-screen
apps redraw everything on SIGWINCH.

### Decision (from user + review)
Vendor `vt100` as a **git submodule** and implement grid-level reflow in `Grid::set_size`.
Reflow cost is paid only on `SIGWINCH`. Rejected: alacritty_terminal (per-frame overhead)
and byte re-emit (corrupts, per existing test).

## Files to change

- `.gitmodules` (+ new submodule `vendor/vt100` tracking a fork of `doy/vt100-rust`)
- `Cargo.toml` (workspace root) — add `[patch.crates-io] vt100 = { path = "vendor/vt100" }`
- `Cargo.lock` — refresh vt100 entry (`cargo update -p vt100`)
- Vendored `vendor/vt100/src/screen.rs` — thread a reflow flag to the main grid only
- Vendored `vendor/vt100/src/grid.rs` — reflow implementation
- Vendored `vendor/vt100/src/row.rs` — helpers to build a `Row` from a reflow chunk stream
- Vendored `vendor/vt100/src/grid.rs` (or `tests/`) — reflow unit tests
- `crates/term-wm-pty-engine/src/pty.rs` — update `history_replay_corrupts...`; add resize test

## Steps

### 1. Vendor vt100 as a submodule and wire it in
- `git submodule add <fork-of-doy/vt100-rust> vendor/vt100` at tag `0.16.2`. The submodule
  tracks a fork that can hold the reflow commit (or a local repo); during development cargo
  reads the submodule working tree, so uncommitted patches are picked up immediately.
- Workspace `Cargo.toml`:
  ```toml
  [patch.crates-io]
  vt100 = { path = "vendor/vt100" }
  ```
- `cargo update -p vt100` to regenerate `Cargo.lock`.

### 2. Bypass reflow on the alternate screen (review SEV-1)
`Screen::set_size` (screen.rs:88-92) resizes both grids. Change `Grid::set_size` to accept
`reflow: bool` (or add `set_size_reflow`):
- Main `grid` → `set_size(size, /*reflow=*/ true)`
- `alternate_grid` → `set_size(size, /*reflow=*/ false)`

When `reflow == false`, execute the **legacy** truncate/pad path (`Row::resize`) exactly as
today. Rationale: alt-screen apps (vim/htop/tmux) lay out a 2D matrix via absolute cursor
positioning and repaint on SIGWINCH; reflowing their grid before the redraw only corrupts
the intermediate frame and risks garbled structure. Zero regression risk — this preserves
the status quo that already "works".

### 3. Reflow algorithm — `Grid::reflow(new_cols)`, run inside `set_size` when cols change
Flatten → re-chunk → reassemble → remap cursor, all in one pass.

**(a) Collect logical lines.** Walk `scrollback` (oldest→newest) then `rows`. A row
continues the current logical line if `row.wrapped()`, **plus** one vt100-specific edge:
vt100 wraps a wide char to the next row *without* setting the wrap flag when only one
column remained and the last cell was empty (screen.rs:721-745). So a non-wrapped row whose
last cell is content-less AND whose next row begins with a wide char is also a continuation.
A row that ends exactly on the last column with a wide char (vt100 deliberately clears the
flag, screen.rs:918-924) stays its own line — tmux behavior; acceptable ambiguity.

**(b) Flatten each logical line into a cell stream** of `(contents, attrs, width_units)`
where `width_units = is_wide ? 2 : 1`:
- Skip wide-continuation cells (no contents, default attrs).
- **Preserve explicit whitespace (review SEV-1):** keep every cell with
  `has_contents()` — this includes explicitly written `' '` cells; never trim by character
  value. Drop only trailing cells that are content-less **and** default-attr (unwritten
  padding), and only up to the column past `max(last_written_col, cursor_col)` for the
  cursor's logical line — never trim storage from beneath the cursor.
- Strip wide-char wrap pads (review SEV-2): when a row is a soft-wrap continuation and its
  last cell is a content-less pad that exists only because a wide char was pushed to the
  next row, do not emit it as a space in the stream.

**(c) Re-wrap each logical line at `new_cols`.** Accumulate `width_units`; break to a new
row before exceeding `new_cols`; **never split a wide char** — if a wide char would straddle
the boundary, break before it (leaving the row short, standard behavior). Intermediate rows
get `wrapped(true)`, the final row `wrapped(false)`.
**Synthesized wide-continuation cells (review SEV-2):** when a wide char
(`width_units == 2`) is emitted into a re-wrapped row, generate its continuation cell with
the exact `Attrs { fgcolor, bgcolor, mode }` copied from the lead cell (`Attrs` is
`Copy`) before setting `set_wide_continuation(true)` — so SGR styling, colors, and
selection highlighting survive row boundaries.

**(d) Reassemble atomically (review SEV-2).** `all = concatenated re-wrapped rows`. Split in
a single pass: `rows = last new_rows`, `scrollback = earliest rows of all` capped to the
last `scrollback_len`, tail anchored. Apply legacy scroll-region clamping after the
rebuild. Do **not** run the old independent row-resize when cols changed.

**(e) Cursor & saved-position remapping via structural traversal (review SEV-1).**
No integer division by `new_cols` (rows are not uniformly packed — wide chars force early
wraps at `new_cols - 1`), and no flat `rows * old_cols` arithmetic (stripped wrap-pad and
wide-continuation cells are absent from the flattened stream, so row-width sums would
inflate the index).
- **Forward mapping (old grid → stream index):** walk the flattened cell stream of the
  cursor's logical line entry-by-entry, summing `width_units` (standard=1, wide=2),
  skipping wide-continuation and stripped wrap-pad cells, up to the entry whose source
  physical `(row, col)` contains the cursor. If the cursor sits on a wide-continuation
  cell, target the wide char's leading cell instead. **Stripped wrap-pad cursor (review
  SEV-2):** during flattening (3b) record each stripped wrap-pad coordinate `(row,
  old_cols - 1)`; if the cursor's physical coordinate matches one, redirect the target to
  the stream entry of the wide char at `(row + 1, 0)` (the pad and the pushed wide char
  occupy the same logical position in the stream). This is exact because both directions
  operate on the *same* flattened stream that re-wrapping consumes.
- **Reverse projection (stream index → new grid):** walk the *re-wrapped* rows of that
  logical line, accumulating each row's **actual** width (usually `new_cols`, but
  `new_cols - 1` when a wide char early-wrapped), until the accumulated index reaches the
  target; the target row is the one whose range contains it, and the target col is the
  remainder. If the target col lands on a wide-continuation cell, clamp back to the wide
  start.
- **Pending wrap state machine:** `cursor_col == old_cols` ⇒ target index one past the
  row's end; after projection set `wrap_pending` (col == `new_cols`) only if the index lands
  exactly at the end of a fully-packed re-wrapped row, else clear it.
- **`saved_pos` (DECSC / SCOSC) is projected through the identical pipeline** (review
  SEV-1): locate its logical line, forward-map to a stream index, reverse-project to the new
  grid. Apply the same treatment under `saved_origin_mode`; clamp to grid bounds as a last
  resort only (never boundary-clamp alone, or `DECRC` restores the wrong cell).

**(f) Scrollback viewport anchoring (review SEV-2).**
- Before reflow, compute the viewport top's physical row in the combined content stream:
  `top_row = scrollback.len() - scrollback_offset`. Locate the `(logical_line_id,
  row_offset_within_logical_line)` of `top_row`. (If `scrollback_offset == 0`, i.e. tail
  followed, skip — anchor to cursor below.)
- After reassembly, locate `logical_line_id` in `all`, and **clamp the recorded offset to
  the re-wrapped line's new row count** (review SEV-2): with `M` = number of re-wrapped rows
  for that logical line, `row_offset = min(row_offset_within_logical_line, M - 1)` — on
  width expansion a line's row count shrinks, and an unclamped offset would point into the
  *next* logical line. Add `row_offset` to the line's start index to get its new physical
  row `top_new_row` (0-indexed in `all`). Recompute
  `scrollback.len() = all.len() - new_rows`. The first visible row is
  `all[scrollback.len() - scrollback_offset]`; require it to be `all[top_new_row]`:
  `scrollback_offset = all.len() - new_rows - top_new_row`, clamped to
  `[0, min(scrollback.len(), scrollback_len)]`. If the target line has moved into the
  visible region (formula underflows below 0), fall back to cursor anchoring
  (`scrollback_offset` such that the cursor line is the last visible row).

**(g) Eviction guards (review SEV-1).** Shrinking width expands row counts, so `all` may
exceed `scrollback_len + new_rows` and evict the oldest lines at the head. All logical-line
lookups (`logical_line_id`) must be `Option`-checked against the final `all`:
- If the logical line containing **`saved_pos`** is evicted (or only partially retained),
  reset `saved_pos` to `(0, 0)` and clear `saved_origin_mode`.
- If the logical line anchoring the **viewport top** is evicted, set
  `scrollback_offset = min(scrollback.len(), scrollback_len)` (view to top of remaining
  scrollback).
- The **cursor** line is never evicted (tail-anchored into `rows`), so no guard needed there.

**(h) Tab stops and scroll margins.**
- **Tab stops (review SEV-2):** no action needed — vt100 0.16.2 has no `Grid.tabs`
  bitset; `Grid::col_tab` computes stops arithmetically every 8 columns (grid.rs:667-671),
  so tab handling is naturally width-independent after reflow.
- **Scroll margins (DECSTBM):** keep vt100's established clamp/extend semantics
  (grid.rs:73-75, 83-88) on resize. term-wm's `PtyStateTracker` deliberately persists
  margin state across resize (test pty_state_tracker.rs:429-439) and `Pty::resize`'s CSI-SU
  workaround (pty.rs:376) gates on `has_custom_margins()`. Switching to an unconditional
  reset of `scroll_top`/`scroll_bottom` would require a coordinated tracker change and is
  out of scope for the reflow fix; note as a possible follow-up.

**Row-only resize** (cols unchanged) → legacy path, no reflow. `Pty::resize`'s CSI-SU
row-shrink workaround (pty.rs:376-383) stays: it scrolls rows into scrollback before
`set_size`, then reflow re-wraps them. Min-size clamp (pty.rs:364) unchanged.

### 4. Tests

**Vendored crate (grid.rs / tests):**
- Width shrink re-wraps soft-wrapped scrollback lines; **no characters lost** (compare
  flattened content before/after).
- Width grow re-joins previously-wrapped lines.
- Wide/CJK glyphs never split across rows; wrap-pad cells not re-emitted as spaces; a wide
  char that re-wraps keeps its SGR attrs on the synthesized continuation cell.
- Explicit trailing spaces preserved across resize.
- Cursor remap: normal position; wide-continuation clamp; pending-wrap (`cursor.col ==
  cols`); cursor in a short (early-wrapped) row; **cursor preceded within its logical line
  by a wide char** (exercises entry-by-entry forward mapping, no `rows * old_cols`
  inflation); **cursor placed on a stripped wrap pad at `old_cols - 1`** (redirects to the
  pushed wide char's stream entry, no lookup failure).
- **`saved_pos` (DECSC → resize → DECRC) restores the same cell character** after both
  shrink and grow; `saved_pos` **eviction** (line pushed past `scrollback_len + new_rows`)
  resets to `(0, 0)` with `saved_origin_mode` cleared.
- Scrollback anchoring: scrolled-up viewport stays on the same logical line across a width
  change; **width expansion with an anchor at the tail of a multi-row line clamps to that
  line's last row (never leaks into the next line)**; tail-follow stays anchored to the
  cursor; **evicted anchor falls back to the top of remaining scrollback** without panicking.
- Tab stops after a width grow/shrink remain correct (arithmetic tab stops; no
  out-of-bounds on `\t`).
- Alternate grid (`reflow=false`) uses legacy truncation — no re-wrapping.

**term-wm (`pty.rs`):**
- **Update** `history_replay_corrupts_percent_lines_via_ansi_cursor_movements` (pty.rs:1966).
  With reflow the 5 absolute-positioned 65-char lines re-wrap to ~15 rows at 30 cols. Change
  the assertion from `lines().count() == 5` to **content preservation**: all 5 `%` markers
  present, text re-wrapped, no characters dropped.
- Add: `Pty::resize` from 80→30 cols keeps scrollback content (normal mode) intact and
  re-wrapped; no truncation. Optionally a `TestPane` render-level check in terminal.rs.
