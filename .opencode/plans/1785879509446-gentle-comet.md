# Fix: streamed input ordering + mouse-movement latency (term-session)

## Status
- **Done:** voice-typing reorder bug fixed via per-connection ordered forwarder (`input_forwarders` + `drain_input_forwarder`), regression test `session_stream_input_preserves_order_under_burst` passing. Changelog entry added.
- **Remaining:** mouse-movement latency introduced by that forwarder.

## Part 1 (done) — voice-typing reorder fix
`crates/term-session-server/src/session_server.rs` `StreamInput` handler used to `tokio::spawn` one task per chunk; those tasks raced on the async routing locks so chunk N+1 could reach `input_tx` before chunk N. Fixed by a per-connection FIFO forwarder:
- `ServerState.input_forwarders: std::sync::Mutex<HashMap<conn_id, mpsc::Sender<Vec<u8>>>>`.
- Sync handler `try_send`s each chunk in wire order; one `drain_input_forwarder` task per connection drains FIFO into the channel's `input_tx`; `End`/`Error` removes the forwarder.
- Regression test in `tests/integration_session.rs`.

## Part 2 — mouse-movement latency (current work)
### Root cause
The forwarder resolves routing locks and dispatches a `spawn_blocking` write **per chunk**. High-frequency input (mouse drags emit hundreds of tiny 6-byte SGR chunks/sec) pays this cost every event:
1. `drain_input_forwarder` runs `bound_channel()` (RwLock read), `resolve_channel()` (RwLock read), and `ch.lock()` (Mutex) on **every chunk**.
2. The `input_rx` consumer task calls `tokio::task::spawn_blocking(...).await` for **every chunk**, so hundreds of threadpool context switches queue up a backlog.

Ordering must stay correct for all input types (keyboard, mouse, paste) — coalescing preserves byte order because it merges already-ordered chunks, so we keep the FIFO and optimize the two hot loops.

### Fix (in `crates/term-session-server/src/session_server.rs`)
1. **Cache `input_tx` in `drain_input_forwarder`:** a connection stays bound to its channel for the stream lifetime, so resolve once and reuse; re-resolve only when the cached sender is closed.
2. **Coalesce queued chunks via `try_recv`:** after `rx.recv().await` returns, non-blockingly drain any immediately-queued chunks and merge them into one buffer before forwarding.
3. **Batch PTY writes:** the `input_rx` consumer task similarly drains all immediately-available chunks via `try_recv` and issues a **single** `spawn_blocking` write for the combined buffer.

Net effect: routing lookups and threadpool dispatches drop ~50x during bursts while FIFO order is maintained.

### New `drain_input_forwarder`
```rust
/// Drain one connection's ordered input queue, forwarding chunks to the
/// bound channel's `input_tx` in exact arrival order. Exits when the forwarder
/// sender is dropped (connection End/Error) or the channel's input receiver
/// closes. Exactly one of these tasks exists per connection, so chunk ordering
/// is preserved end-to-end even under input bursts.
///
/// Chunks queued during bursts (e.g. mouse drags or IME voice typing) are
/// coalesced via non-blocking `try_recv` before forwarding, and `input_tx` is
/// cached across chunks to eliminate per-chunk routing lookup overhead.
async fn drain_input_forwarder(
    state: SharedState,
    conn_id: usize,
    mut rx: mpsc::Receiver<Vec<u8>>,
) {
    let mut cached_tx: Option<mpsc::Sender<Vec<u8>>> = None;

    while let Some(mut bytes) = rx.recv().await {
        // Coalesce any additional chunks currently queued in the forwarder channel.
        while let Ok(mut next) = rx.try_recv() {
            bytes.append(&mut next);
        }

        // Re-resolve the target channel's `input_tx` if not cached or closed.
        if cached_tx.as_ref().map_or(true, |tx| tx.is_closed()) {
            cached_tx = None;
            if let Some(channel) = bound_channel(state.as_ref(), conn_id).await {
                if let Some(ch) = resolve_channel(state.as_ref(), &channel).await {
                    let guard = ch.lock().await;
                    if !guard.is_reaped {
                        cached_tx = Some(guard.input_tx.clone());
                    }
                }
            }
        }

        if let Some(ref tx) = cached_tx {
            // Backpressure: `input_tx` is bounded (INPUT_CHANNEL_CAPACITY); a full
            // buffer parks this consumer instead of silently dropping the chunk.
            if tx.send(bytes).await.is_err() {
                cached_tx = None;
            }
        }
    }
}
```

### New channel input task (in `get_or_create_channel`)
```rust
    tokio::spawn(async move {
        let mut input_rx = input_rx;
        while let Some(mut data) = input_rx.recv().await {
            // Coalesce any additional chunks currently queued in input_rx.
            while let Ok(mut next) = input_rx.try_recv() {
                data.append(&mut next);
            }

            let writer = {
                let guard = ch.lock().await;
                guard.session.as_ref().map(|s| s.pty.writer_handle())
            };
            if let Some(writer) = writer {
                let _ = tokio::task::spawn_blocking(move || writer.write_bytes(&data)).await;
            }
        }
        // Note: the input task runs for the daemon lifetime; the channel's
        // `input_rx` is only dropped when the channel's senders all vanish.
    });
```

### Why ordering is preserved
Coalescing only concatenates chunks that are already in FIFO order within the same channel, so the byte stream is identical — just batched into fewer `send()`/`spawn_blocking` calls. The existing burst-ordering test must still pass unchanged.
