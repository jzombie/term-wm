# Fix Unconditional 60 FPS Overlay Redraw Loop

## Root Cause

`runner.rs:937` calls `system_handle.set_keep_awake(!app.wm().overlays().is_empty())`. When any overlay is open:

1. `keep_awake = true` → `pending_work = true` (`runner.rs:938`)
2. `pending_work` feeds into `profile_from_activity()` as `has_dirty_windows` (`unified_event_source.rs:978`)
3. `has_dirty_windows = true` → profile stays `Streaming` (16ms/60fps) even when idle (`power_profile.rs:65`)
4. `driver_has_work = current_profile() != PowerSaver` → `true` (`runner.rs:541`)
5. Idle `None` branch: `driver.take_redraw_request() || driver_has_work` → arms pacer at 60fps every tick

**Result:** Opening Command Palette or Help Overlay forces continuous 60fps re-rendering indefinitely, bypassing PowerSaver.

## Fix

Delete line 937 in `crates/term-wm-core/src/runner.rs`:
```rust
// DELETE: system_handle.set_keep_awake(!app.wm().overlays().is_empty());
```

Keep line 938 unchanged — `set_pending_work` still works via `app_handle.has_pending()`.

Overlays still render correctly because:
- Opening via input event arms pacer at `runner.rs:587` (`frame_pacer.notify_pending()`)
- Once idle, pacer expires → profile drops to PowerSaver → no re-render until next input
- `palette_tick_deadline()` still clamps sleep for periodic background updates
