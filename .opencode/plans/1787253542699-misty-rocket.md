# Optimize `render_screen` Idle CPU on macOS

## Problem

Profiling with `samply` shows the main thread consuming **2630ms CPU** during idle. The dominant hotspot is `TerminalComponent::render_screen` in `crates/term-wm-ui-components/src/terminal.rs:514-768`, which does O(rows² × cols) work per frame due to an O(row) linear scan in `Grid::visible_row()`.

The issue is macOS-specific — Linux shows lower idle CPU. The likely causes are:
1. Debug-mode alignment checks (`core::ptr::is_aligned_to`) appearing in the profile
2. `unicode_segmentation` grapheme handling being more expensive on macOS
3. The O(rows²) hidden cost being masked on Linux by faster system calls

## Root Cause Analysis

### 1. O(rows²) `visible_row` Chain (CRITICAL)

`screen.cell(row, col)` calls `Grid::visible_cell()` → `visible_row(row)` → `visible_rows().nth(row)`.

`visible_rows()` returns an iterator chaining `scrollback.iter().skip(...)` and `rows.iter()`. Calling `.nth(row)` on this chain iterates element-by-element — **O(row) per call**.

In the double loop at `terminal.rs:685-686`:
```rust
for row in start_row..start_row + visible.height {
    for col in start_col..start_col + visible.width {
        if let Some(cell) = screen.cell(row, col) {  // O(row) per call!
```

For a 100-row terminal: row 0 costs 0 iterator steps, row 1 costs 1, ..., row 99 costs 99. Total: ~5000 extra iterator steps per frame. This is the **single biggest optimization target**.

**File:** `term-wm-vt100/src/grid.rs:620-622`

### 2. Per-Cell Bounds Checks

Both `screen.cell(row, col)` and `buffer.cell_mut((x, y))` do bounds checks per cell:
- `screen.cell`: `visible_row().nth(row)` (iterator) + `Row::get(col)` (`Vec::get`)
- `buffer.cell_mut`: `index_of_opt` (`area.contains()`) + `content.get_mut(index)`

The loop bounds are already constrained by `visible` (line 622) intersected with `buffer.area`, so these checks are redundant within the loop.

**Files:** `terminal.rs:692,740`

### 3. No Diff-Based Rendering

Every frame renders ALL visible cells. The `BufferDiff` iterator in ratatui can skip unchanged cells, but it's not used in `render_screen`. Since the vt100 `Screen` tracks dirty state, we could skip cells that haven't changed.

**File:** `terminal.rs:685-753`

### 4. Link Overlay Doubles Iteration

Lines 648-678 iterate ALL cells for link detection before the main render loop. This is a second full pass over the grid that could be merged or deferred.

**File:** `terminal.rs:648-678`

### 5. Debug Alignment Checks

`core::ptr::is_aligned_to` appears in the profile (0.5%). These are debug assertions that vanish in release builds. Ensure profiling uses `--release`.

**Impact:** Only affects debug builds.

## Implementation Plan

### Phase 1: Fix O(rows²) in `term-wm-vt100` (CRITICAL)

**File:** `term-wm-vt100/src/grid.rs`

Add a direct-indexed method that bypasses the iterator chain when `scrollback_offset == 0` (the common case during rendering — user is at the bottom):

```rust
/// Direct row access for the common case (scrollback_offset == 0).
/// Returns a reference to the visible row at index `row` without
/// iterating through the scrollback chain.
pub fn visible_row_fast(&self, row: u16) -> Option<&crate::row::Row> {
    let row = usize::from(row);
    let rows_len = self.rows.len();
    if row >= rows_len {
        return None;
    }
    if self.scrollback_offset == 0 {
        // Fast path: all visible rows are in `self.rows`
        Some(&self.rows[row])
    } else {
        // Slow path: fall back to iterator
        self.visible_rows().nth(row)
    }
}

/// Direct cell access using fast row lookup.
pub fn visible_cell_fast(&self, pos: Pos) -> Option<&crate::Cell> {
    self.visible_row_fast(pos.row).and_then(|r| r.get(pos.col))
}
```

Then update `Screen::cell()` to use the fast path:

**File:** `term-wm-vt100/src/screen.rs:546-548`

```rust
pub fn cell(&self, row: u16, col: u16) -> Option<&crate::Cell> {
    self.grid().visible_cell_fast(crate::grid::Pos { row, col })
}
```

**Expected impact:** Eliminates ~5000 iterator steps per frame. This is the highest-ROI change.

### Phase 2: Eliminate Per-Cell Bounds Checks in `render_screen`

**File:** `crates/term-wm-ui-components/src/terminal.rs:685-753`

Replace `screen.cell(row, col)` + `buffer.cell_mut((cell_x, cell_y))` with direct row-level access:

```rust
// Before the row loop, get a reference to the visible row
for row in start_row..start_row + visible.height {
    let viewport_row = row.saturating_sub(start_row) as usize;
    let cell_y = area.y.saturating_add(row);

    // Get the row reference once (O(1) after Phase 1)
    let Some(visible_row) = screen.visible_row_fast(row) else {
        continue;
    };

    for col in start_col..start_col + visible.width {
        let cell_x = area.x.saturating_add(col);
        let viewport_col = col.saturating_sub(start_col) as usize;

        // Direct column access (Vec::get, one bounds check)
        if let Some(cell) = visible_row.get(col) {
            // ... style building (unchanged) ...

            // Direct buffer index (one bounds check, not two)
            let buf_idx = cell_y as usize * buffer.area.width as usize + cell_x as usize;
            if let Some(buf_cell) = buffer.content.get_mut(buf_idx) {
                // ... set symbol and style ...
            }
        }
    }
}
```

This eliminates:
- The `visible_rows().nth(row)` O(n) scan (replaced by Phase 1)
- The second `buffer.cell_mut()` bounds check (use direct indexing)
- The `index_of_opt` area check (loop bounds already guarantee safety)

**Expected impact:** ~30-40% reduction in render_screen CPU.

### Phase 3: Precompute Style Lookup Table

**File:** `crates/term-wm-ui-components/src/terminal.rs:680-753`

Instead of building a `Style` per cell with 7+ conditional checks, precompute a style lookup for common cases:

```rust
// Precompute style lookup for common modifier combinations
// Most cells are: default fg/bg + no modifiers
// Cache the "default style" to avoid rebuilding it
let default_style = {
    let mut s = Style::default();
    if let Some(fg) = fg { s = s.fg(fg); }
    if let Some(bg) = bg { s = s.bg(bg); }
    s
};

// In the loop, check if cell has the same fg/bg as default
// and no modifiers → use cached default_style
```

This avoids the `Style::default()` + 7 conditional `add_modifier` calls for the common case (plain text cells).

**Expected impact:** ~10-15% reduction in style-building overhead.

### Phase 4: Merge Link Overlay Pass

**File:** `crates/term-wm-ui-components/src/terminal.rs:648-678`

The link overlay pass (lines 648-678) iterates all cells for link detection. This could be merged into the main render loop:

1. During the main render loop, collect row data for link detection
2. After the render loop, update the link overlay with the collected data

This eliminates one full grid traversal per frame.

**Expected impact:** ~5-10% reduction in total render_screen CPU.

### Phase 5: Buffer Diff for Incremental Rendering

**File:** `crates/term-wm-ui-components/src/terminal.rs`

Maintain a "previous frame" buffer and use `BufferDiff` to skip unchanged cells:

```rust
// Before the render loop
let diff_iter = prev_buffer.diff_iter(&current_buffer);

// In the loop, skip cells where diff == Skip
```

This requires:
1. Storing a `prev_buffer: Buffer` in `TerminalComponent`
2. After render, copying current → prev
3. Using the diff to skip unchanged cells

**Expected impact:** Significant for idle rendering (most cells don't change between frames).
