# Optimize term-wm Idle CPU (macOS)

## Problem

Profiling with `samply` shows **CPU spikes when overlays (Help Menu, Command Palette) are open**, with low CPU when closed. The event loop calls `driver.request_redraw()` unconditionally on every handler invocation (runner.rs:421), driving 60fps rendering even when nothing has changed. Combined with per-frame allocations in overlay render methods, this causes sustained high CPU while overlays are visible.

## Root Causes (Ordered by Impact)

### 1. `BackgroundConsoleReader` Busy-Spin (CRITICAL — 100% of 1 core)

**File:** `crates/term-wm-console/src/background_console_reader.rs:97-122`

On macOS, `crossterm::event::poll()` frequently returns `Ok(false)` **immediately** (0µs) without blocking for the 100ms timeout. The empty `Ok(false)` arm means the thread executes millions of `poll()` calls per second, consuming 100% of a CPU core while idle.

**Proof from profile:** Thread `<13365839>` has weight 25,441ms in a ~25.8s profile — a single thread running at ~98.6% CPU for the entire duration.

### 2. Unconditional `request_redraw()` in Event Loop

**File:** `crates/term-wm-core/src/runner.rs:421`

`driver.request_redraw()` is called unconditionally in the `None` branch (no input event), even when no system tasks fired. This arms the FramePacer at 60fps on every poll timeout, causing full renders when nothing has changed.

### 3. Per-Frame Allocations in Command Palette

**File:** `crates/term-wm-ui-components/src/command_palette.rs:571-583`

`render()` clones `display_nodes` into `Vec<MenuDisplayItem>` every frame, copying `String` fields (display_name, description, stable_id) even when query and data haven't changed.

### 4. Per-Frame String Allocation in Help Overlay

**File:** `crates/term-wm-sys-ui-components/src/wm_help_overlay.rs:45`

`format!("{} — About / Help", self.app_ctx.app_name)` allocates a new `String` every frame.

### 5. Per-Frame Line Height Computation in TextRendererComponent

**File:** `crates/term-wm-ui-components/src/text_renderer.rs`

`actual_wrapped_height()` creates `Paragraph::new(line).wrap()` + `Buffer::empty()` per line per frame. For 100 lines, that's 100 throwaway allocations + full `unicode_segmentation` grapheme iteration per frame.

### 6. Session Server 100ms Polling

**File:** `crates/term-session-server/src/session_server.rs:38`

Every active channel wakes 10×/second to check for exited sessions.

## Implementation Plan

### Phase 1: Fix BackgroundConsoleReader Busy-Spin (CRITICAL)

**File:** `crates/term-wm-console/src/background_console_reader.rs:97-122`

```rust
Ok(false) => {
    thread::sleep(CROSSTERM_POLL_INTERVAL);
}
```

**Why not blocking `event::read()`:** `BackgroundConsoleReader::drop` relies on `shutdown.store(true)` to terminate the loop. A thread blocked inside `event::read()` cannot evaluate the atomic flag until an external TTY event occurs, leaking the thread and causing process teardown hangs.

**Impact:** Eliminates 100% CPU spin on 1 core.

### Phase 2: Expose `visible_row` on `term_wm_vt100::Screen`

**Dependency setup:** `term-wm-vt100` is a crates.io dependency. A local fork exists at `../term-wm-vt100` and can be activated via `.cargo/config.toml`:

```toml
[patch.crates-io]
term-wm-vt100 = { path = "../term-wm-vt100" }
```

**File:** `term-wm-vt100/src/screen.rs`

```rust
impl Screen {
    pub fn visible_row(&self, row: u16) -> Option<&crate::row::Row> {
        self.grid().visible_row(row)

```

**Impact:** Enables Phase 3 without private field access errors.

### Phase 6: Cache Wrapped Line Heights in TextRendererComponent

**File:** `crates/term-wm-ui-components/src/text_renderer.rs`

**Problem:** `actual_wrapped_height()` creates a temporary `Paragraph::new(line).wrap(Wrap { trim: false })` + `Buffer::empty()` per line per render frame just to count visual line count.

**Fix:** Cache the wrapped visual height per line. Invalidate on `set_text()` or width change.

Add fields:
```rust
pub struct TextRendererComponent {
    // ... existing fields ...
    line_heights: RefCell<Vec<usize>>,
    line_heights_width: Cell<u16>,
}
```

In `set_text()`:
```rust
self.line_heights.borrow_mut().clear();
```

In `render()`, replace `compute_display_lines` with cached version:
```rust
let usable_width = area.width.max(1);
let content_height = if self.wrap {
    if self.line_heights_width.get() != usable_width {
        self.line_heights.borrow_mut().clear();
        self.line_heights_width.set(usable_width);
    }
    let mut heights = self.line_heights.borrow_mut();
    if heights.is_empty() {
        for line in &self.text.lines {
            heights.push(actual_wrapped_height(line, usable_width));
        }
    }
    heights.iter().copied().sum::<usize>().max(1)
} else {
    self.text.lines.len().max(1)
};
```

**Impact:** Eliminates ~100 `Paragraph::new().wrap().render()` calls per frame. Drops `unicode_segmentation` from 19.2% to ~1-2%.

### Phase 7: Cache Command Palette Menu Items

**File:** `crates/term-wm-ui-components/src/command_palette.rs:551-648`

**Problem:** `render()` clones `display_nodes` into `Vec<MenuDisplayItem>` every frame (lines 571-583).

**Fix:** Cache the built `menu_items` Vec. Only rebuild when `query_dirty` or `data_dirty` is true.

`render()` takes `&mut self` (line 552), so direct mutation is valid — no `RefCell`/`Cell` needed.

Add fields:
```rust
pub struct CommandPaletteComponent {
    // ... existing fields ...
    cached_menu_items: Vec<MenuDisplayItem<TermWmAction>>,
    items_dirty: bool,
}
```

In `render()`:
```rust
if self.items_dirty {
    self.cached_menu_items = self.display_nodes.iter().map(|node| match node {
        PaletteDisplayNode::Item(p) => MenuDisplayItem::Item(MenuItem {
            icon: p.icon,
            label: Cow::Owned(p.display_name.clone()),
            action: p.action.clone(),
            disabled: p.disabled,
        }),
        PaletteDisplayNode::Separator => MenuDisplayItem::Separator,
    }).collect();
    self.items_dirty = false;
}
let items = std::mem::take(&mut self.cached_menu_items);
self.list_scroll.content.borrow_mut().set_display_items(items);
// ... after render, swap back:
self.cached_menu_items = self.list_scroll.content.borrow_mut().take_display_items();
```

Set `items_dirty = true` in `rerank()` and `rerank_with_registry()`.

**Impact:** Eliminates ~N String clones per frame when idle with palette open.

### Phase 8: Gate Redraws at Event Loop Level

**File:** `crates/term-wm-core/src/runner.rs:418-421`

**Problem:** `driver.request_redraw()` is called unconditionally at line 421, even when no system tasks fired and no state changed. This arms the FramePacer at 60fps on every poll timeout.

**Fix:** Make `request_redraw()` conditional on whether state actually changed:

```rust
let mut state_changed = false;

// Process expired system tasks
for (_id, task) in system_handle.drain_expired() {
    state_changed = true;
    match task {
        SystemTask::DragSnap => { app.wm().apply_drag_snap_if_pending(); }
        SystemTask::TemporalDwellTick => { app.wm().on_temporal_dwell_tick(); }
        SystemTask::DismissNotification(id) => { app.wm().dismiss_notification(id); }
        SystemTask::FlushDirectModeToast(key) => { app.wm().flush_direct_mode_toast(key); }
        SystemTask::ClearTabOutline => { /* ... */ }
    }
}

// Drain app-level callback tasks
for (_id, task) in app_handle.drain_expired() {
    state_changed = true;
    task.run(app);
}

// Only request redraw when state actually changed
if state_changed {
    driver.request_redraw();
}
```

Also make the second `request_redraw()` at line 455 conditional:
```rust
// PTY child exit removed a window — redraw the layout.
if !transitions.is_empty() {
    driver.request_redraw();
}
```

**Impact:** When no system tasks fire and no input events arrive, the FramePacer is not armed. The event loop drops to PowerSaver (3600s poll), eliminating 60fps rendering of overlays when idle.

### Phase 9: Cache Help Overlay Title String

**File:** `crates/term-wm-sys-ui-components/src/wm_help_overlay.rs:45`

**Problem:** `format!("{} — About / Help", self.app_ctx.app_name)` allocates a new `String` every frame.

**Fix:** Cache the title in the struct. `render()` takes `&mut self` (line 35), so direct mutation is valid.

```rust
pub struct WmHelpOverlayComponent {
    // ... existing fields ...
    cached_title: String,
}
```

Set `cached_title` in constructor or `open()`:
```rust
cached_title: format!("{} \u{2014} About / Help", app_ctx.app_name),
```

In `render()`:
```rust
let title = &self.cached_title;
```

**Impact:** Eliminates per-frame String allocation.
