# Optimize term-wm Idle CPU (macOS)

## Problem

Profiling with `samply` shows **12% CPU usage during idle** on macOS (1 core pegged at 100% on an 8-core machine). Linux shows lower idle CPU. The profile captures ~25.8 seconds of idle time, and one background thread (`Thread <13365839>`) has a weight of **25,441ms** — confirming a busy-spin.

## Root Causes (Ordered by Impact)

### 1. `BackgroundConsoleReader` Busy-Spin (CRITICAL — 100% of 1 core)

**File:** `crates/term-wm-console/src/background_console_reader.rs:97-122`

```rust
fn input_loop(tx: Sender<Event>, shutdown: Arc<AtomicBool>) {
    loop {
        if shutdown.load(Ordering::Acquire) { break; }
        match crossterm::event::poll(CROSSTERM_POLL_INTERVAL) {  // 100ms timeout
            Ok(true) => { /* read and send event */ }
            Ok(false) => {}  // BUG: empty — no sleep, immediate loop
            Err(_) => break,
        }
    }
}
```

On macOS, `crossterm::event::poll()` frequently returns `Ok(false)` **immediately** (0µs) without blocking for the 100ms timeout. This happens when:
- Terminal raw mode is active with non-blocking stdin flags
- The TTY file descriptor has `O_NONBLOCK` set
- macOS `select()`/`poll()` on the pty returns immediately for certain terminal configurations

The empty `Ok(false)` arm means the thread executes millions of `poll()` calls per second, consuming 100% of a CPU core while idle.

**Proof from profile:** Thread `<13365839>` has weight 25,441ms in a ~25.8s profile — that's a single thread running at ~98.6% CPU for the entire duration.

### 2. O(rows²) `visible_row` Chain in Rendering

**File:** `term-wm-vt100/src/grid.rs:620-622`

```rust

    self.visible_rows().nth(usize::from(row))  // O(row) linear scan!

```

`visible_rows()` returns an iterator chaining scrollback + visible rows. `.nth(row)` iterates element-by-element. In the render loop at `terminal.rs:685-686`:

```rust
    for col in start_col..start_col + visible.width {
        if let Some(cell) = screen.cell(row, col) {  // O(row) per call!
```

For a 100-row terminal: ~5000 extra iterator steps per frame.

### 3. Per-Cell Bounds Checks in Render Loop

**File:** `crates/term-wm-ui-components/src/terminal.rs:685-753`

Each cell does:
- `screen.cell(row, col)` → `visible_row().nth(row)` (iterator) + `Row::get(col)` (`Vec::get`)
- `buffer.cell_mut((cell_x, cell_y))` → `index_of_opt` (`area.contains()`) + `content.get_mut(index)`

Two bounds checks per cell, even though the loop bounds are already constrained.

## Implementation Plan

### Phase 1: Fix BackgroundConsoleReader Busy-Spin (CRITICAL)

**File:** `crates/term-wm-console/src/background_console_reader.rs:97-122`

**Option A (Recommended):** Use blocking `event::read()` directly. Since this runs on a dedicated OS thread, blocking is fine:

```rust
fn input_loop(tx: Sender<Event>, shutdown: Arc<AtomicBool>) {
    loop {
        if shutdown.load(Ordering::Acquire) {
            break;
        }
        // Blocking read — the thread sleeps until an event arrives.
        // No poll() needed; the OS blocks the thread on the TTY fd.
        match crossterm::event::read() {
            Ok(evt) => {
                let Some(core_evt) = term_wm_crossterm_adapter::try_translate_event(evt)
                else { continue; };
                if tx.send(core_evt).is_err() {
                    break; // receiver dropped
                }
            }
            Err(_) => break, // TTY broken
        }
    }
}
```

**Option B:** Add a fallback sleep on `Ok(false)`:

```rust
Ok(false) => {
    thread::sleep(Duration::from_millis(10));
}
```

Option A is preferred because it eliminates the polling entirely and lets the OS wake the thread only when input arrives. The shutdown flag check happens naturally when `event::read()` returns after the terminal is closed.

**Impact:** Eliminates 100% CPU spin on 1 core. This is the single highest-ROI fix.

### Phase 2: Fix O(rows²) in term-wm-vt100

**File:** `term-wm-vt100/src/grid.rs:620-643`

Add fast-path methods that bypass the iterator chain when `scrollback_offset == 0` (the common case during rendering — user is at the bottom):

```rust
/// Direct row access for the common case (scrollback_offset == 0).
pub fn visible_row_fast(&self, row: u16) -> Option<&crate::row::Row> {
    let row = usize::from(row);
    if self.scrollback_offset == 0 {
        // Fast path: all visible rows are in self.rows
        self.rows.get(row)
    } else {
        // Slow path: fall back to iterator
        self.visible_rows().nth(row)
    }
}

/// Direct cell access using fast row lookup.
pub fn visible_cell_fast(&self, pos: Pos) -> Option<&crate::Cell> {
    self.visible_row_fast(pos.row).and_then(|r| r.get(pos.col))
}
```

**File:** `term-wm-vt100/src/screen.rs:546-548`

```rust
pub fn cell(&self, row: u16, col: u16) -> Option<&crate::Cell> {
    self.grid().visible_cell_fast(crate::grid::Pos { row, col })
}
```

**Impact:** Eliminates ~5000 iterator steps per frame. O(rows²) → O(rows).

### Phase 3: Eliminate Per-Cell Bounds Checks in Render Loop

**File:** `crates/term-wm-ui-components/src/terminal.rs:685-753`

Rewrite the render loop to:
1. Get the row reference once before the column loop (O(1) after Phase 2)
2. Use direct buffer indexing instead of `buffer.cell_mut()`

```rust
for row in start_row..start_row + visible.height {
    let cell_y = area.y.saturating_add(row);
    let Some(vt_row) = screen.visible_row_fast(row) else { continue; };

    for col in start_col..start_col + visible.width {
        let cell_x = area.x.saturating_add(col);
        if let Some(cell) = vt_row.get(col) {
            let mut symbol = cell.contents().chars().next().unwrap_or(' ');
            let (fg, bg) = resolve_colors_with_defaults(cell, default_fg, default_bg);
            // ... style building ...

            // Direct index: one bounds check, not two
            let idx = cell_y as usize * buffer.area.width as usize + cell_x as usize;
            if let Some(buf_cell) = buffer.content.get_mut(idx) {
                let mut buf = [0u8; 4];
                let sym = symbol.encode_utf8(&mut buf);
                buf_cell.set_symbol(sym).set_style(style);
            }
        }
    }
}
```

**Impact:** ~30-40% reduction in render_screen CPU.

### Phase 4: Precompute Style Lookup Table

**File:** `crates/term-wm-ui-components/src/terminal.rs:680-753`

Instead of building a `Style` per cell with 7+ conditional checks, precompute a default style for the common case (plain text cells with default fg/bg and no modifiers):

```rust
let default_style = {
    let mut s = Style::default();
    if let Some(fg) = fg { s = s.fg(fg); }
    if let Some(bg) = bg { s = s.bg(bg); }
    s
};

// In the loop: if cell has same fg/bg as default and no modifiers → use cached default_style
```

**Impact:** ~10-15% reduction in style-building overhead.

### Phase 5: Merge Link Overlay Pass (Optional)

**File:** `crates/term-wm-ui-components/src/terminal.rs:648-678`

The link overlay pass iterates ALL cells before the main render loop. This could be merged into the main loop to eliminate one full grid traversal.

**Impact:** ~5-10% reduction in render_screen CPU.

### Phase 6: Reduce Session Server Polling Frequency

**File:** `crates/term-session-server/src/session_server.rs:38,534`

Increase `SESSION_EXIT_POLL_INTERVAL` from 100ms to 500ms or 1000ms. The session exit check is not latency-sensitive — a 500ms delay in detecting an exited process is acceptable.

```rust
const SESSION_EXIT_POLL_INTERVAL: std::time::Duration =
    std::time::Duration::from_millis(500);
```

**Impact:** Reduces 10 wakeups/sec to 2 wakeups/sec per active channel.
