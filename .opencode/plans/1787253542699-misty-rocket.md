# Fix Lingering Command Palette CPU Usage

## Problem

After gating unconditional redraws (Phase 8), the Command Palette still consumes CPU when left open. Two real issues remain; one was already fixed and one is a false positive.

## Verified Findings

### 1. Background Terminal Rendering Under Modal (HIGH IMPACT — CONFIRMED)

**Files:**
- `crates/term-wm-ui-components/src/terminal.rs:514-768` — `render_screen()` acquires parser lock, iterates all rows/cols, resolves styles
- `crates/term-wm-ui-components/src/dialog_overlay.rs:194-208` — `render_backdrop()` applies DIM to existing buffer cells
- `crates/term-wm-core/src/engine.rs:82-106` — `generate_regions()` adds all windows with `hidden: false`

**Root cause:** When the Command Palette is open, `render_screen()` executes full VT100 processing (parser lock, row iteration, cell style resolution, link overlay) for every terminal pane on every frame. The palette then applies DIM on top. The VT100 processing is redundant when terminal content hasn't changed.

**Why region culling fails:** `render_backdrop()` mutates existing buffer cells via `cell.set_style(dim_style)`. If background regions are culled, buffer cells are empty — DIM on empty cells gives a blank screen, not dimmed terminal content. The visual result is NOT identical.

### 2. Un-debounced User Registry Updates (MEDIUM IMPACT — CONFIRMED)

**Files:**
- `src/term_wm_app.rs:880-894` — `on_user_registry_changed()` has no throttling
- `src/term_wm_app.rs:324-369` — `refresh_workspace_cache()` does synchronous IPC

**Root cause:** `on_user_registry_changed()` fires immediately on every user event. Each call does synchronous IPC + full palette rebuild. The periodic tick path has debouncing (5s/30s), but the event-driven path has none.

**Naive debouncing risk:** A simple `duration_since(last) < debounce` check drops events without trailing-edge execution, leaving stale state until an external event fires after the quiet window.

### 3. ScrollContent Re-indexing (ALREADY FIXED)

The `items_dirty` guard from Phase 7 already prevents per-frame work. **No fix needed.**

### 4. Cursor Blink Timer (FALSE POSITIVE)

No cursor blink timer exists in the codebase. **No fix needed.**

## Implementation Plan

### Phase 1: Cache Rendered Terminal Cells for Skip-Render Path

**File:** `crates/term-wm-ui-components/src/terminal.rs`

**Approach:** Cache the terminal's rendered cell data. When terminal content hasn't changed (same `bytes_received`, same scrollback, same size), copy cached cells directly to the buffer instead of re-running VT100 processing. The palette's `render_backdrop()` then applies DIM to these cached cells, preserving the correct visual result.

Add fields to `TerminalComponent`:
```rust
pub struct TerminalComponent {
    // ... existing fields ...
    cached_cells: RefCell<Vec<ratatui::buffer::Cell>>,
    cached_area: Cell<Option<ratatui::layout::Rect>>,
    last_bytes_seen: Cell<u64>,
}
```

In `render()`, capture `bytes_received` before calling `render_screen()`:
```rust
let bytes_seen = self.pane.borrow().bytes_received();
self.render_screen(backend, area, ctx, resized);
```

In `render_screen()`, add fast-path at the top (after scroll state sync, before parser lock):
```rust
let content_unchanged = bytes_seen == self.last_bytes_seen.get()
    && !resized
    && self.pane.borrow().scrollback() == self.last_scrollback.get()
    && self.selection.borrow().selection_range().is_none();

if content_unchanged {
    if let Some(cached_area) = self.cached_area.get() {
        if let Some(cached) = self.cached_cells.borrow().first() {
            let backend = crate::helpers::downcast_ratatui(backend);
            let visible = area.intersection(backend.buffer.area);
            // Copy cached cells directly — skip VT100 processing
            for (i, cell) in self.cached_cells.borrow().iter().enumerate() {
                let y = visible.y + (i / visible.width as usize) as u16;
                let x = visible.x + (i % visible.width as usize) as u16;
                if y < visible.y + visible.height && x < visible.x + visible.width {
                    if let Some(buf_cell) = backend.buffer.cell_mut((x, y)) {
                        *buf_cell = cell.clone();
                    }
                }
            }
            return;
        }
    }
}
```

After the existing render loop (line ~770), cache the rendered cells:
```rust
// Cache rendered cells for skip-render path
let backend = crate::helpers::downcast_ratatui(backend);
let visible = area.intersection(backend.buffer.area);
if visible.width > 0 && visible.height > 0 {
    let mut cells = Vec::with_capacity(visible.width as usize * visible.height as usize);
    for y in visible.y..visible.y.saturating_add(visible.height) {
        for x in visible.x..visible.x.saturating_add(visible.width) {
            if let Some(cell) = backend.buffer.cell((x, y)) {
                cells.push(cell.clone());
            }
        }
    }
    self.cached_cells.borrow_mut().clear();
    self.cached_cells.borrow_mut().extend(cells);
    self.cached_area.set(Some(visible));
    self.last_bytes_seen.set(bytes_seen);
}
```

**Why this works:** When the palette is open and terminal content hasn't changed, we skip the expensive VT100 processing (parser lock, row iteration, style resolution) and copy cached cells directly. The palette's `render_backdrop()` then applies DIM to these cached cells, producing the correct dimmed-terminal-content visual. When content changes (new PTY bytes, scroll, resize), we do a full render and update the cache.

**Impact:** Eliminates N×O(rows×cols) VT100 processing per frame when palette is open and terminals are idle. Only the palette renders + DIM loop runs.

### Phase 2: Trailing-Edge Debounce for User Registry Updates

**File:** `src/term_wm_app.rs:880-894`

**Approach:** Use trailing-edge debouncing with a dirty flag. When events arrive during the debounce window, set `user_registry_dirty = true`. The pending update is flushed on the next `poll_palette_tick()` call (which runs every event loop iteration), ensuring eventual consistency.

Add constant and fields:
```rust
const USER_REGISTRY_DEBOUNCE: Duration = Duration::from_secs(2);

// In TermWmApp struct:
user_registry_last_refresh: Option<Instant>,
user_registry_dirty: bool,
```

In `on_user_registry_changed()`:
```rust
fn on_user_registry_changed(&mut self) {
    if !self.wm.command_menu_visible() {
        self.user_registry_dirty = false;
        return;
    }
    let now = Instant::now();
    if let Some(last) = self.user_registry_last_refresh {
        if now.duration_since(last) < USER_REGISTRY_DEBOUNCE {
            self.user_registry_dirty = true; // Mark pending — will flush on next tick
            return;
        }
    }
    self.user_registry_last_refresh = Some(now);
    self.user_registry_dirty = false;
    // ... existing IPC + refresh logic
}
```

In `poll_palette_tick()`, flush pending registry updates:
```rust
fn poll_palette_tick(&mut self) {
    if !self.wm.command_menu_visible() {
        self.user_registry_dirty = false;
        // ... existing early return
        return;
    }
    // Flush pending registry updates (trailing-edge debounce)
    if self.user_registry_dirty {
        if let Some(last) = self.user_registry_last_refresh {
            if Instant::now().duration_since(last) >= USER_REGISTRY_DEBOUNCE {
                self.user_registry_last_refresh = Some(Instant::now());
                self.user_registry_dirty = false;
                // ... existing IPC + refresh logic
            }
        }
    }
    // ... existing periodic tick logic
}
```

**Why trailing-edge:** The dirty flag ensures no event is permanently dropped. If events arrive at t=0.1s and t=0.4s, the second event sets `dirty=true`. At t=2.1s (next tick after debounce window), the pending update flushes, giving the palette correct state within 2s of the last event.

**Impact:** Reduces IPC + palette rebuild from per-event to per-2s during multi-user sessions.
