# Fix: Profiling term-wm with samply

## Problem
`samply record --save-only -o samply.json ./target/release/term-wm` doesn't open the CLI window.

## Root Cause
The default build includes the `session-persistence` feature (`Cargo.toml:148`), which creates a multi-process architecture:

1. Outer launcher calls `connect_or_spawn_server()` (`crates/term-session/src/auto_spawn.rs:271-309`)
2. Daemon is spawned via `setsid()` (a separate process)
3. Outer launcher then spawns **another copy of itself** with `--internal-session`
4. The **inner child process** is what actually creates the terminal UI

`samply record` instruments the outer launcher process, but the actual UI runs in the inner child — so no window appears in the profiled process.

## Solution

### Option A: Run with `--no-session-persistence` (no rebuild needed)
```bash
samply record --save-only -o samply.json -- ./target/release/term-wm --no-session-persistence
```
This bypasses the gateway/daemon dance and puts the entire UI in a single process (`main.rs:183` → `runtime_config_for()` at line 138).

### Option B: Build without the feature
```bash
cargo build --release --no-default-features
samply record --save-only -o samply.json -- ./target/release/term-wm
```

### Option C: Environment variable
```bash
samply record --save-only -o samply.json -- env TERM_WM_NO_SESSION_PERSISTENCE=1 ./target/release/term-wm
```
Read at `crates/term-wm-config/src/env.rs:35`.

## Files Involved
- `src/main.rs:79-80` — `--no-session-persistence` CLI flag
- `src/main.rs:138-141` — `runtime_config_for()` function
- `src/main.rs:183` — config initialization
- `src/main.rs:231-276` — outer launcher path (session-persistence enabled)
- `src/main.rs:278+` — direct UI path (session-persistence disabled)
- `crates/term-wm-config/src/env.rs:35` — `TERM_WM_NO_SESSION_PERSISTENCE` env var
- `crates/term-session/src/auto_spawn.rs:271-309` — `connect_or_spawn_server()` with setsid + poll loop
