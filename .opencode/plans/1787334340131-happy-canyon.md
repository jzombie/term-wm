# Fix: Command Palette Search Ordering

## Root Cause

MRU sort destroys search order. Both `rerank()` and `rerank_with_registry()` apply `self.filtered_items.sort_by(|a, b| mru.weight(...))` unconditionally — even when a query is active. This reorders fuzzy-match results, scattering section headers away from their items.

## Fix

### `command_palette.rs` — Only apply MRU sort when query is empty

In both `rerank()` (~line 331) and `rerank_with_registry()` (~line 491), wrap the MRU sort in `if self.query.is_empty()`:

```rust
if self.query.is_empty() {
    self.filtered_items.sort_by(|a, b| {
        let wa = mru.weight(&a.stable_id);
        let wb = mru.weight(&b.stable_id);
        wb.partial_cmp(&wa).unwrap_or(std::cmp::Ordering::Equal)
    });
}
```

When a query is active, preserve the fuzzy-match score order. MRU still boosts recently-used items via the fuzzy scorer's internal weighting, and is most useful for the empty-query idle state.

**Note:** `skip_disabled_items` stays `true`. The jumpy navigation was caused entirely by MRU scrambling the list order. Once items stay in natural/fuzzy order, skipping disabled headers produces smooth, predictable navigation.
