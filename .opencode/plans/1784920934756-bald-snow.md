# Fix pre-loop initial render + failing test

## Changes

### 1. `runner.rs` — unconditional pre-loop render with panic catch

Insert before `event_loop.run(...)`:

```rust
app.wm().begin_frame();
app.wm().prepare_draw();
if std::panic::catch_unwind(std::panic::AssertUnwindSafe(|| {
    output.draw(|frame| draw(frame, app))
})).is_err() {
    output.repair()?;
}
```

No `if` condition. Unconditional. The `catch_unwind` handles tests that intentionally panic on frame zero.

### 2. `runner.rs` — remove captured `now`, use `Instant::now()` at each call

Ensure all FramePacer calls inside the None branch use fresh `Instant::now()`:

```rust
// Arm
if driver.take_redraw_request() || driver_has_work {
    frame_pacer.notify_pending(Instant::now());
}
// Expire check
if frame_pacer.try_expire(Instant::now()) {
    ...
}
// Poll clamp
frame_pacer.time_until_deadline(Instant::now())
```

No `let now = Instant::now();` capture.

### 3. `tests/panic_debug_log.rs` — mock poll must block

`ImmediateDriver::poll()` returns immediately, causing the event loop to spin
at max speed. The FramePacer deadline (16ms) never expires because the loop
is too fast. Fix: block for the timeout:

```rust
fn poll(&mut self, timeout: Duration) -> io::Result<bool> {
    if !timeout.is_zero() {
        std::thread::sleep(timeout);
    }
    Ok(false)
}
```

Same fix for `WakeupDriver`.

## Why this fixes both cases

| Scenario | Pre-loop render | Loop behavior |
|----------|----------------|---------------|
| `dual_image` (ConsoleEventSource, no events) | Renders immediately | Loop parks (PowerSaver), user sees image |
| `render_panic_test` (ImmediateDriver, Streaming) | Panics, caught, repair | Loop arms pacer via `driver_has_work`, deadline expires after 16ms sleep, second draw quits |
| Normal app (UnifiedEventSource, PTY active) | Renders immediately | PTY wakeups keep loop active |
