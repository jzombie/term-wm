# Plan: Refactor Event Sources to Eliminate `Esc` Fallback

## Background

All prior event-pipeline fixes are complete and merged:
- Media key mapping
- Repeat key suppression removal (normalizer + runner direct mode)
- Wildcard elimination + surjectivity test + snapshot testing

This addresses the one remaining caveat: the infallible `translate_key_event` path.

## Problem

`translate_key_event` in `crates/term-wm-crossterm-adapter/src/lib.rs:60-67` maps unrecognized keys to `KeyCode::Esc` with preserved modifiers. This is used by `unified_event_source.rs` and `console_event_source.rs`. While the wildcard elimination means no current crossterm keys reach this fallback, it remains a theoretical input-distortion path and a code smell.

## Changes

### 1. Switch `unified_event_source.rs` to fallible path

At `src/unified_event_source.rs:192-206`, the `translate_crossterm_event` function uses `translate_key_event` (infallible). Switch to `try_translate_event` — it already exists and returns `Option<Event>`. The `None` case is already handled by the `if let Some(core_event) = ...` guard at line 115.

### 2. Switch `console_event_source.rs` to fallible path

At `crates/term-wm-console/src/console_event_source.rs:12-25`, same pattern. Switch `translate_key_event` to `try_translate_event`. The `None` case is already handled by the `if let Some(translated) = ...` guard at line 59.

### 3. Remove or deprecate infallible helpers

In `crates/term-wm-crossterm-adapter/src/lib.rs`:
- Remove `translate_key_event` (infallible wrapper) once no call sites remain
- Remove `translate_event` if it only existed for the infallible path

### 4. Update tests

Add a test verifying an explicitly-dropped key (e.g., CapsLock) produces `None` through the top-level event source pipeline.

## Files to Modify

- `crates/term-wm-console/src/console_event_source.rs`
- `crates/term-wm-crossterm-adapter/src/lib.rs`
