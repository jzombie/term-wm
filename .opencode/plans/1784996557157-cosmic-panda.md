# Plan: Input Fidelity — Media Key Handling & Kitty Protocol Foundation

## Background

All prior event-pipeline hardening is complete:
- Media key mapping in adapter (`MediaKeyCode` → `KeyCode`)
- Repeat key suppression removed (normalizer + runner direct mode)
- Wildcard eliminated, surjectivity test, snapshot tests
- Esc fallback removed, event sources now fallible

This addresses the remaining gap: `to_pty_bytes()` still uses a wildcard `_ => &[]` for unmapped key codes, meaning media keys, releases, and lock keys silently produce no output even though they reach the PTY serialization layer.

## Staged Approach

### Stage 1 (Now): Explicit Media Key Handling in `to_pty_bytes()`

**File:** `crates/term-wm-core/src/events.rs`

Replace the wildcard fallback in `to_pty_bytes()` with explicit match arms for `KeyCode::MediaPlayPause`, `MediaStop`, `MediaTrackNext`, and `MediaTrackPrevious`, returning empty byte slices with a clear comment:

```rust
// Media keys have no standard VT100/xterm escape sequence.
// Explicitly handled to prevent hitting the unmapped wildcard.
KeyCode::MediaPlayPause
| KeyCode::MediaStop
| KeyCode::MediaTrackNext
| KeyCode::MediaTrackPrevious => Vec::new(),
```

Then change the remaining `_ => Vec::new()` wildcard to also be explicit for whatever is actually left (non-media unmapped codes).

**Test:** Add a test verifying `to_pty_bytes()` returns an empty vec for media keys (regression guard against silent wildcard changes).

### Stage 2 (Follow-up Milestone): Kitty Keyboard Protocol Support

Scope to be planned in a separate RFC. Required components:
1. PTY session state tracking for Kitty protocol negotiation flags
2. Conditional formatting in `to_pty_bytes()`:
   - Key releases → `CSI keycode ; modifiers : 3 u`
   - Lock keys (CapsLock, NumLock, ScrollLock) → Kitty functional keycodes
   - Standalone modifiers (Shift, Ctrl, Alt, Super) → Kitty functional keycodes
3. Adapter updates to forward `KeyEventState` (CapsLock/NumLock flags)
4. Escape sequence response to child process `CSI ? u` queries
