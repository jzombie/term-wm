# Plan: Make command palette icons searchable

## Goal

When typing in the command palette search, fuzzy match against the menu item's icon text in addition to the display name. This lets users find a command by typing its icon character (e.g., `*` for "Toggle System Panel").

## Data Flow

Currently `display_items` is `Vec<(display_name, description, disabled)>` — the `FuzzyMatch::score` loop reads `name` and builds a `Utf32Str` haystack from it (zero allocations per item, just the `Utf32Str` view).

To add icons we precompute a `searchable_text` field once in the cache phase, so the hot matching loop remains allocation-free.

## Changes

### 1. `crates/term-wm-ui-components/src/command_palette.rs` — Precompute `searchable_text` in cache

**Field type (line 44):** `Vec<(String, String, bool)>` → `Vec<(String, String, String, bool)>`  
Semantics: `(display_name, description, searchable_text, disabled)`

**`rebuild_data_cache`:** Precompute a `searchable_text` that includes both icon and display name. This allocates once per item when the cache is rebuilt, not per keystroke:

```rust
self.display_items = self
    .active_ids
    .iter()
    .filter_map(|id| {
        let node = registry.get(*id)?;
        let display_name = node.name.format(self.current_context_mask);
        let desc = node.description.clone().unwrap_or_default();
        let icon_text = node.icon.unwrap_or("");
        let searchable_text = if icon_text.is_empty() {
            display_name.clone()
        } else {
            format!("{} {}", icon_text, display_name)
        };
        Some((display_name, desc, searchable_text, node.disabled))
    })
    .collect();
```

**`rerank` (line 124):** Destructure the 4-tuple, discard `searchable_text`:

```rust
let (display_name, description, _, is_disabled) = self.display_items.get(i)?;
```

**`rerank_with_registry` (line 208):** Same:

```rust
let (ref display_name, ref desc, _, _disabled) = self.display_items[i];
```

### 2. `crates/term-wm-core/src/command_menu/matcher.rs` — Read precomputed haystack

**Tuple type:** `&[(String, String, bool)]` → `&[(String, String, String, bool)]`  
Semantics: `(name, description, searchable_text, disabled)`

**Body:** Read the precomputed `searchable_text` field directly — no `format!`, no allocation:

```rust
pub fn score(&mut self, query: &str, items: &[(String, String, String, bool)]) -> Vec<usize> {
    if query.is_empty() {
        return (0..items.len()).collect();
    }
    self.matcher = Matcher::new(NucleoConfig::DEFAULT.match_paths());
    let pattern = Pattern::new(query, CaseMatching::Ignore, Normalization::Smart, AtomKind::Fuzzy);
    let mut scored: Vec<(u32, usize)> = items
        .iter()
        .enumerate()
        .filter_map(|(i, (_name, _desc, searchable_text, _disabled))| {
            self.char_buf.clear();
            let haystack = Utf32Str::new(searchable_text, &mut self.char_buf);
            let score = pattern.score(haystack, &mut self.matcher);
            score.map(|s| (s, i))
        })
        .collect();
    scored.sort_by_key(|&(score, _)| std::cmp::Reverse(score));
    scored.into_iter().map(|(_, i)| i).collect()
}
```

### `matcher.rs` — New test `test_icon_searchability`

Add after `fuzzy_case_and_multi_char`. Creates items with icon-based `searchable_text` (`"* Toggle System Panel"`, `"+ New Tab"`, `"x Close Tab"`) and one without an icon. Asserts:

- Query `"*"` returns exactly `"Toggle System Panel"` (index 0)
- Query `"+"` returns exactly `"New Tab"` (index 1)
- Query `"* sys"` (icon + partial name combination) matches `"Toggle System Panel"`
- Query `"Tab"` (normal text) returns both `"New Tab"` and `"Close Tab"`

### `command_palette.rs` — New test `test_searchable_text_generation`

Add to the existing `#[cfg(test)] mod tests` block. Tests the formatting logic in isolation:

- Icon present: `"*"` + `"System Panel"` → `"* System Panel"`
- Icon absent (empty string): `""` + `"System Panel"` → `"System Panel"`

This is a pure-function test of the `rebuild_data_cache` string formatting — no component setup needed.
