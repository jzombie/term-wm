# Plan: Fix flaky `session_child_exit` on Windows

## Root Cause

The session exits (mock `exit 0`) before any subscriber attaches. The server's polling loop at `session_server.rs:335-341` only calls `session.check_exited()` when there are active subscribers. When the child exits early:

1. Reader thread reads EOF, tries `status_cb` → `None` (not yet set) → **callback dropped silently**
2. `set_status_callback()` sets callback later — but reader thread already exited
3. Polling loop wakes (prime notify), sees no subscribers → `sync_screen()` → `continue`
4. Polling loop blocks on `notify.notified()` forever
5. SubscribeOutput handler eventually attaches subscriber, calls `notify_one()`
6. Polling loop calls `check_exited()` → may return false if `try_wait()` not yet ready → loop goes back to sleep
7. On Windows ConPTY: reader thread is blocked on `read()` (no EOF delivered by `conhost.exe`), so `status_cb` never fires → no notification at all

## Changes

### Fix 1: `pty.rs:194-201` — Fire exit callback immediately in `set_status_callback()`

When the callback is registered, check if the child already exited (via `self.exited` or OS-level `child.try_wait()`). Fire `PtyStatus::Exited` immediately to wake the async polling loop. This handles the race where EOF was detected before the callback was set (reader thread fired into `None`), and the ConPTY case where the reader thread is blocked on the pipe.

```rust
pub fn set_status_callback(&mut self, cb: Option<Box<dyn Fn(PtyStatus) + Send + Sync>>) {
    let mut fire_cb = None;

    if let Ok(mut guard) = self.status_cb.lock() {
        if self.exited {
            // Child already exited — consume the callback and fire after
            // dropping the lock. Don't store it; terminal state consumed it.
            self.exited_emitted.store(true, Ordering::Release);
            fire_cb = cb;
            *guard = None;
        } else if let Some(child) = self.child.as_mut()
            && let Ok(Some(status)) = child.try_wait()
        {
            self.exited = true;
            self.exit_status = Some(status);
            self.child = None;
            self.exited_emitted.store(true, Ordering::Release);
            fire_cb = cb;
            *guard = None;
        } else {
            *guard = cb;
        }
    }

    if let Some(reader) = &self.reader {
        reader.thread().unpark();
    }

    if let Some(cb_fn) = fire_cb {
        cb_fn(PtyStatus::Exited);
    }
}
```

### Fix 2: `session_server.rs:335-341` — Tear down session when exit detected without subscribers

In the no-subscriber branch, call `session.check_exited()`. If true, immediately set `guard.session = None` to trigger `Drop` (PTY shutdown, ConPTY cleanup). Do NOT keep a zombie session alive.

```rust
if guard.subscribers.is_empty() {
    let mut exited = false;
    if let Some(session) = guard.session.as_mut() {
        session.sync_screen();
        exited = session.check_exited();
    }
    if exited {
        tracing::info!("Session exited, tearing down");
        guard.session = None;  // drops Pty → shuts down reader thread + ConPTY
    }
    continue;
}
```

### Fix 3: `session_server.rs:264-294` — Send end marker in SubscribeOutput when session is dead

When a subscriber attaches to a session that was already torn down (`guard.session.is_none()`), the handler sends `respond.respond(Vec::new(), true)` directly. This gives the subscriber an immediate clean end-of-stream instead of waiting for the polling loop (which will never produce output for a dead session).

```rust
guard.subscribers.push(SubscriberEntry {
    conn_id: ctx.conn_id,
    respond: respond.clone(),
});
guard.notify.notify_one();

let is_dead = guard.session.is_none();
drop(guard);

// Send snapshot and early data (captured above while session existed, or None)
if let Some(data) = snapshot
    && !data.is_empty()
{
    respond.respond(data, false);
}
if let Some(data) = early {
    respond.respond(data, false);
}

// If session was already torn down, subscriber needs immediate end marker
if is_dead {
    respond.respond(Vec::new(), true);
}
```

Note: `session` and `snapshot` are captured using `guard.session.as_mut()` before the subscriber push, so they're valid even if `is_dead` is true (the session existed when we started the handler but was torn down between the capture and the push).

## Recovery from the "late try_wait" race

If `try_wait()` returns `Ok(None)` during the no-subscriber check (process not yet reaped):
- The session stays alive (`guard.session` not cleared)
- The polling loop goes back to `notified()`
- When the reader thread sees EOF (Unix) → fires callback → wakes loop → re-checks → detects exit
- On Windows ConPTY: if reader thread is stuck, this won't happen until subscriber attaches
- When subscriber attaches: SubscribeOutput handler → `notify_one()` → polling loop re-checks → `try_wait()` succeeds → detects exit → tears down session

The subscriber handler in the "session alive" case doesn't send an end marker directly (since the session is alive, the polling loop will handle it). The `notify_one()` wake ensures the polling loop processes the exit.

## Tests

### Unit test: `pty.rs` — `set_status_callback_fires_immediately_when_child_already_exited`

```rust
#[test]
fn set_status_callback_fires_immediately_when_child_already_exited() {
    let cmd = CommandBuilder::new(get_test_executable());
    let size = PtySize { rows: 24, cols: 80, pixel_width: 0, pixel_height: 0 };
    let mut pty = Pty::spawn_with_scrollback(cmd, size, 100).expect("spawn_with_scrollback");

    // Kill and reap the child process via has_exited() (which consumes the latch)
    if let Some(child) = pty.child.as_mut() {
        let _ = child.kill();
    }
    for _ in 0..250 {
        if pty.has_exited() { break; }
        std::thread::sleep(std::time::Duration::from_millis(20));
    }

    let exited_fired = Arc::new(AtomicBool::new(false));
    let exited_cb = Arc::clone(&exited_fired);

    // Registering a new callback should fire immediately since child already exited.
    // This exercises the self.exited branch with latch reset.
    pty.set_status_callback(Some(Box::new(move |status| {
        if status == PtyStatus::Exited {
            exited_cb.store(true, Ordering::Relaxed);
        }
    })));

    assert!(
        exited_fired.load(Ordering::Relaxed),
        "set_status_callback must fire PtyStatus::Exited when child already exited"
    );
}
```

### Unit test: `pty.rs` — `set_status_callback_fires_after_direct_kill` (no `has_exited` call)

Exercises the `else if let Some(child) = self.child.as_mut()` → `try_wait()` branch (bypasses latch entirely):

```rust
#[test]
fn set_status_callback_fires_after_direct_kill() {
    let cmd = CommandBuilder::new(get_test_executable());
    let size = PtySize { rows: 24, cols: 80, pixel_width: 0, pixel_height: 0 };
    let mut pty = Pty::spawn_with_scrollback(cmd, size, 100).expect("spawn_with_scrollback");

    // Kill the child but do NOT call has_exited() — let try_wait() in
    // set_status_callback detect the exit.
    if let Some(child) = pty.child.as_mut() {
        let _ = child.kill();
    }
    // Wait for process to actually terminate (direct try_wait polling)
    for _ in 0..250 {
        if let Ok(Some(_)) = pty.child.as_mut().map(|c| c.try_wait()) {
            break;
        }
        std::thread::sleep(std::time::Duration::from_millis(20));
    }

    let exited_fired = Arc::new(AtomicBool::new(false));
    let exited_cb = Arc::clone(&exited_fired);

    pty.set_status_callback(Some(Box::new(move |status| {
        if status == PtyStatus::Exited {
            exited_cb.store(true, Ordering::Relaxed);
        }
    })));

    assert!(
        exited_fired.load(Ordering::Relaxed),
        "set_status_callback must fire via try_wait() path when child killed"
    );
}
```

### Integration test: `integration_session.rs` — `session_child_exit_before_subscribe`

Tests the late-subscriber path (Fix 3) by waiting for the session to exit first, then subscribing:

```rust
#[tokio::test]
#[serial]
async fn session_child_exit_before_subscribe() {
    let mock = get_mock_bin();
    let (client, _dir) = spawn_session(vec![mock, "exit".into(), "0".into()], TEST_COLS, TEST_ROWS).await;

    // Give the server time to detect child exit and tear down the session
    tokio::time::sleep(Duration::from_millis(500)).await;

    let (_, mut reader) = client
        .open_channel(SUBSCRIBE_OUTPUT_METHOD_ID, 0)
        .await
        .unwrap();

    let mut got_end = false;
    let start = std::time::Instant::now();
    while start.elapsed() < Duration::from_secs(3) {
        match tokio::time::timeout(Duration::from_millis(500), reader.recv()).await {
            Ok(None) => {
                got_end = true;
                break;
            }
            Ok(Some(_)) => continue,
            Err(_) => continue,
        }
    }
    assert!(got_end, "Should get immediate end-of-stream when subscribing after child exit");
}
```
