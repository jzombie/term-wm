# term-wm-config: Centralize session-persistence feature, runtime toggles, and TERM_WM_* env vars

## Goal
Create a new std-only leaf workspace crate `term-wm-config` that is the single home for:
1. the `session-persistence` Cargo feature flag,
2. process-global runtime boolean toggles that layer on top of that feature (so the app behaves **at runtime** as if the feature were not compiled in), and
3. every `TERM_WM_*` environment variable constant.

Sits at the bottom of the dependency graph so `term-wm-core`, `term-wm-pty-engine`, `term-session*`, and the `term-wm` binary can all depend downward without cycles.

## User decisions (already confirmed)
- **Runtime trigger:** compile-time feature takes precedence. When compiled in, session persistence is disabled at runtime if `--no-session-persistence` CLI flag **OR** `TERM_WM_NO_SESSION_PERSISTENCE` env var is present. When not compiled in, it is off regardless.
- **Disable scope:** EVERYTHING — including daemon modes (`--stop-daemon`, `--daemon`, `--no-wm`, outer launcher, `--internal-session` listener) — must be unavailable at runtime when disabled.
- **Env var migration:** migrate all existing `TERM_WM_*` env vars now: `TERM_WM_GATEWAY`, `TERM_WM_CHANNEL`, `TERM_WM_TRACE_ESC` (plus the new `TERM_WM_NO_SESSION_PERSISTENCE`).

## Design
- `term-wm-config` is std-only (no deps beyond workspace lints). `serial_test` as dev-dep for env/global tests.
- Feature forwarding chain: root `session-persistence` → `term-wm-core/session-persistence` → `term-wm-config/session-persistence`.
- `runtime::session_persistence_enabled()` = `cfg!(feature = "session-persistence") && CONFIG.session_persistence` — the single full gate; safe to call from any crate, any time. Default runtime flag is `true` (non-breaking for library consumers that never call `init`).
- Config stored in a `Mutex<RuntimeConfig>` (not `OnceLock`) so tests can set/restore and future fields can be toggled at runtime. Never `.lock().unwrap()` (violates `unwrap_used = "deny"` + `ci/check-mutex-unwrap.sh`) — use `.unwrap_or_else(|p| p.into_inner())`.
- The existing `#[cfg(feature = "session-persistence")]` gates scattered across core/root are kept and remain the compile-time layer; the new runtime check is added **inside** those gated blocks. No reverting.
- `GATEWAY_CHANNEL_ENV_VAR` / `CHANNEL_ENV_VAR` remain available under their old names via `pub use term_wm_config::env::...` so public re-exports (`term_session::protocol::GATEWAY_CHANNEL_ENV_VAR`, `term_session::CHANNEL_ENV_VAR`) keep working.

### 11. Attributed-input consumer coalescing (`crates/term-session-client/src/lib.rs`)
Context: the producer already merges consecutive `Moved`/`Drag` events (lines ~688-709) and uses `try_send` drop-on-saturation (lines ~711-720), so the `mpsc::channel(1024)` can never accumulate a 1024-event motion backlog and stale positions are bounded to the queue depth. The single background task (`lines ~492-506`) is therefore not the source of a 1s+ drain — but it is worth hardening with **consumer-side** latest-position coalescing so a burst already in the queue collapses to its newest position before the IPC roundtrip.

Change the consumer task to a `pending_req` loop that merges only *consecutive, coalescable* queued motion events. A popped event that cannot be coalesced is **stashed into `pending_req`** (never dropped) and sent on the next iteration, so discrete-event ordering and delivery are preserved:
```rust
rt.spawn(async move {
    use muxio_rpc_service_caller::prebuffered::RpcCallPrebuffered;
    use term_session_muxio_service_definitions::SendAttributedInput;

    let mut pending_req = None;
    loop {
        let mut req = match pending_req.take() {
            Some(r) => r,
            None => match attributed_rx.recv().await {
                Some(r) => r,
                None => break,
            },
        };

        // Latest-position coalescing for queued motion events. A popped event
        // that cannot be merged is stashed in `pending_req` (NOT dropped) and
        // processed on the next iteration, preserving discrete-event ordering.
        while attributed_mouse_is_motion(&req.event) {
            match attributed_rx.try_recv() {
                Ok(next_req) if attributed_mouse_coalescable(&req.event, &next_req.event) => {
                    req = next_req;
                }
                Ok(next_req) => {
                    pending_req = Some(next_req);
                    break;
                }
                Err(_) => break,
            }
        }
        let _ = SendAttributedInput::call(&*client_clone, req).await;
    }
});
```
Add two small free helpers beside `is_coalescable_mouse` in the same file:
```rust
fn attributed_mouse_is_motion(e: &Event) -> bool {
    matches!(e, Event::Mouse(m) if matches!(m.kind, MouseEventKind::Moved | MouseEventKind::Drag(_)))
}
fn attributed_mouse_coalescable(a: &Event, b: &Event) -> bool {
    match (a, b) {
        (Event::Mouse(am), Event::Mouse(bm)) => {
            is_coalescable_mouse(&am.kind, &am.modifiers, &bm.kind, &bm.modifiers)
        }
        _ => false,
    }
}
```
No behavioral change for discrete events: each is sent exactly once, in order (a popped non-motion event is stashed in `pending_req`, never dropped); motion events collapse to newest-position before each roundtrip.

## Out of scope / notes
- Renaming `TERM_WM_CHANNEL` → `TERM_SESSION_CHANNEL` (existing TODO) is not part of this change.
- The standalone `term-session` binary (`crates/term-session/src/main.rs`) is a separate tool and is NOT subject to the runtime toggle — only the `term-wm` binary is.
- The `#[cfg(feature)]` gates from the earlier session-persistence work remain intact; this adds the runtime layer on top.
- §11 coalescing: the producer already bounds the attributed-input queue via motion-event merging + `try_send` drop-on-saturation; the consumer-side merge is defensive hardening and must never drop or reorder discrete events (popped non-coalescable events are stashed in `pending_req`, not discarded).
