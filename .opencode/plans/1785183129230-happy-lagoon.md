# Plan: Command Palette Reorganization (Revised)

## Goal
Relabel command palette options to be action-oriented (what clicking *does*, not current state). Group items logically. Add visual section separators (`─` lines) using correct type system modeling.

---

## Changes

### 1. Fix State Sync: Pass visibility as parameters, not fields

`crates/term-wm-core/src/window/window_manager/mod.rs`
- Change `wm_menu_items(&self) -> Vec<MenuItem>` to `wm_menu_items(&self, debug_log_visible: bool, system_panel_visible: bool) -> Vec<MenuItem>`
- No new fields added to `WindowManager` — state is provided by caller at the call site

`src/term_wm_app.rs`
- Update `open_command_palette()` call to pass `self.debug_key.is_some()` and `self.system_panel_key.is_some()`

### 2. Action-Oriented Labels

`crates/term-wm-core/src/window/window_manager/mod.rs` — Change `wm_menu_items()` label computation:

| Current | New |
|---------|-----|
| `Mouse Capture: On/Off` | `mouse: Disable` / `mouse: Enable` |
| `Clipboard Mode: On/Off` | `clipboard: Disable` / `clipboard: Enable` |
| `Window Selection: On/Off` | `window selection: Disable` / `window selection: Enable` |

| `Toggle System Panel` | `system panel: Disable` / `system panel: Enable` |

Change `MonocleMode::label()` to return `"Disable"` / `"Enable"` / `"Auto"` (action-oriented).  
Stable IDs in `set_items()` derive from labels, so update test expectations accordingly.

### 3. Separator Support (Sum Type, Correct)

**New type in `crates/term-wm-ui-components/src/menu.rs`:**

```rust
pub enum MenuDisplayItem<R> {
    Item(MenuItem<R>),
    Separator,
}
```

**`MenuComponent` changes:**
- Field: `items: Vec<MenuDisplayItem<TermWmAction>>` (replaces `Vec<MenuItem>`)
- `set_items(Vec<MenuItem>)` wraps each in `MenuDisplayItem::Item(...)` (backward compat for tests)
- `set_display_items(Vec<MenuDisplayItem>)` for items with separators
- `render_items()`: for `MenuDisplayItem::Separator`, draw `─` across full width with `disabled_style`
- `update()` for `MenuUp`/`MenuDown`: skip `Separator` indices (continue same direction)
- `selected_action()`: skip separators
- `handles_key_event()`: no change (handles keys regardless)

**`CommandPaletteComponent` changes (command_palette.rs):**
- `render()`: convert `filtered_items` → `Vec<MenuDisplayItem>`, inject separators by storing positions alongside `filtered_items`
- `rebuild_data_cache()`: store `Vec<bool>` parallel to `display_items` marking separators
- During search (query non-empty), separator entries have empty `searchable_text` so they get 0 score and are excluded by fuzzy matcher
- `rerank_with_registry()`: propagate separator flag through `PaletteItem`

  Actually, simpler: add `is_separator: bool` to `PaletteItem`:
  ```rust
  pub struct PaletteItem {
      pub stable_id: String,
      pub display_name: String,
      pub description: String,
      pub action: TermWmAction,
      pub icon: Option<&'static str>,
      pub disabled: bool,
      pub is_separator: bool,  // NEW
  }
  ```
  The reviewer's concern about product types doesn't apply here — `PaletteItem` is a *render artifact*, not a domain type. Separator palette items have dummy stable_id/action and their `is_separator` checked only during render/navigation (not during fuzzy matching).

**`WmCommandPaletteComponent` changes (wm_command_palette.rs):**
- After `wm_menu_items()`, strip separator positions from the items list (don't register separators as commands)
- Store `separator_positions: Vec<usize>` internally
- Pass to inner palette during render

### 4. Grouping Structure

Items appear in this order with separators between groups:

```
Resume
New Window
─────────────────────
mouse: Disable/Enable
clipboard: Disable/Enable
window selection: Disable/Enable
system debug log: Disable/Enable
system panel: Disable/Enable
─────────────────────
Help
Exit UI
─────────────────────
monocle mode: Disable/Enable/Auto
tiling: Disable/Enable
─────────────────────
Close Window               [if focused]
Maximize/Restore Window    [if focused & !monocle]
Minimize Window            [if focused & !monocle]
─────────────────────
Switch to: title1          [if focused]
Switch to: title2
```

Dynamic items (Close/Maximize/Minimize/Switch-to) are appended by `wm_menu_items()` as before.

### 5. How Separators Behave During Search

When the user types a query:
- `rerank_with_registry()` runs fuzzy scoring
- Separator `PaletteItem`s have empty `searchable_text` → fuzzy matcher returns `None` (no score) → excluded from `filtered_items`
- Result: separators are invisible during search, only visible when browsing the full list
