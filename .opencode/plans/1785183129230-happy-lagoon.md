# Bug Fix Plan

Root cause: `Overlay::set_menu_items` trait signature accepts `Vec<MenuItem<Msg>>`, erasing the `MenuDisplayItem` sum type at the trait boundary. Every `set_menu_items` call coerces separators into items, losing them permanently.

Secondary root cause: `wm_menu_items()` takes external visibility params, but `focus.rs` hardcodes `false, false`. Fix by owning the window keys inside `WindowManager` so state is resolved internally.

## Changes

### 1. Propagate sum type through `Overlay` trait

**`crates/term-wm-core/src/components.rs:283`**
`fn set_menu_items(&mut self, _items: Vec<MenuItem<Msg>>) {}`
→ `fn set_menu_items(&mut self, _items: Vec<MenuDisplayItem<Msg>>) {}`

**`crates/term-wm-core/src/macros.rs:241`**
Update delegate macro signature to match.

### 2. Update overlay impls

**`crates/term-wm-sys-ui-components/src/wm_command_palette.rs`**
`set_menu_items` currently wraps `Vec<MenuItem>` in `MenuDisplayItem::Item(...)`. Accept `Vec<MenuDisplayItem>` and pass directly to `set_items()`.

### 3. `TypeId` registry for system windows, remove visibility params

**`crates/term-wm-core/src/window/window_manager/mod.rs`**
- Replace hardcoded fields with `HashMap<TypeId, WindowKey>`:
  ```rust
  pub system_windows: HashMap<TypeId, WindowKey>,
  ```
- Define marker types for dependency inversion:
  ```rust
  pub mod system_tags {
      pub struct DebugLog;
      pub struct SystemPanel;
  }
  ```
- Add generic accessors:
  ```rust
  pub fn register_system_window<T: 'static>(&mut self, key: WindowKey) {
      self.system_windows.insert(TypeId::of::<T>(), key);
  }
  pub fn get_system_window<T: 'static>(&self) -> Option<WindowKey> {
      self.system_windows.get(&TypeId::of::<T>()).copied()
  }
  ```
- Remove visibility params from `wm_menu_items()` signature.
- Inside `wm_menu_items()`, compute visibility via generic accessor:
  ```rust
  use crate::window::window_manager::system_tags;
  use crate::window::WindowState;
  let debug_visible = self.get_system_window::<system_tags::DebugLog>()
      .is_some_and(|k| self.window_state(k) == Some(WindowState::Mapped));
  let panel_visible = self.get_system_window::<system_tags::SystemPanel>()
      .is_some_and(|k| self.window_state(k) == Some(WindowState::Mapped));
  ```

**`src/term_wm_app.rs`**
- After creating debug window / system panel, call `self.wm.register_system_window::<system_tags::DebugLog>(debug_key)` / `self.wm.register_system_window::<system_tags::SystemPanel>(sys_key)`.
- In `open_command_palette()`: remove visibility params — just call `self.wm.wm_menu_items()`.

### 4. Fix `focus.rs` — preserve separators, no hardcoded state

**`crates/term-wm-core/src/window/window_manager/focus.rs`**
Replace the item-rebuild block:

```rust
let items = self.wm_menu_items();
let supported = &self.supported_menu_actions;
let filtered: Vec<MenuDisplayItem<_>> = items
    .into_iter()
    .filter(|entry| match entry {
        MenuDisplayItem::Item(item) => {
            supported.contains(&item.action)
                || matches!(item.action, FocusWindow(_) | MaximizeWindow(_) | MinimizeWindow(_) | CloseWindow(_))
        }
        MenuDisplayItem::Separator => true, // PRESERVE SEPARATORS
    })
    .collect();
if let Some(overlay) = self.overlays.get_mut(palette_key) {
    overlay.set_menu_items(filtered);
}
```

### 5. Dialog height fix (confirm already applied)

`crates/term-wm-sys-ui-components/src/wm_command_palette.rs`
