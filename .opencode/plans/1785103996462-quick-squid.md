# Plan: Make `AppRootComponent` extensible via generic parameter

## Problem

`AppRootComponent` is a closed enum — adding custom components requires modifying library source.

## Solution

Make `AppRootComponent` generic over a custom component type `C`, with a `Custom(C)` variant. All core components stay in the `Core(CoreWmComponent)` variant — zero dynamic dispatch and contiguous memory layout for the hot path.

## Design

### `src/components.rs`

```rust
use term_wm_core::components::NoopComponent;
use term_wm_ui_facade::core_component::CoreWmComponent;

pub enum AppRootComponent<C = NoopComponent> {
    Core(CoreWmComponent),
    Custom(C),
}

impl<C: Component<TermWmAction>> Component<TermWmAction> for AppRootComponent<C> {
    // match self { Self::Core(c) => c.method(...), Self::Custom(c) => c.method(...) }
    // for every Component trait method — same pattern as impl_component_delegate!
    // but with the extra Custom(C) arm
}
```

Key detail: the `impl_component_delegate!` macro can't handle the generic + extra variant. We write the `Component` impl manually (or extend the macro). Manual is safer — it mirrors what the macro generates but with `Custom(C)` added.

### `src/term_wm_app.rs`

Make `TermWmApp` generic over `C`:

```rust
pub struct TermWmApp<C = NoopComponent> {
    wm: WindowManager<AppRootComponent<C>, LayerComponent, OverlayComponent>,
    // ... same fields
}
```

All constructors (`new`, `bare`, `embedded`, `from_wm`) need `C: Component<TermWmAction>` bound — they only construct `AppRootComponent::Core(...)`, so any `C` works. Move these into a generic `impl<C: Component<TermWmAction>> TermWmApp<C>` block.

Existing match patterns (e.g., `Some(AppRootComponent::Core(CoreWmComponent::Terminal(...)))` → callback wiring) stay **exactly as-is** — `SvgImage` was the only non-Core variant that gets removed, replaced by `Custom`. So internal code just ignores `Custom`.

`TermWmApp::open_window` already takes `AppRootComponent` — updating the type to `AppRootComponent<C>` is the only signature change.

### `examples/dual_image.rs`

```rust
// Before:
let mut app = TermWmApp::new(AppContext::new("example", "0.0.0"));
let left_key = app.open_window(AppRootComponent::SvgImage(left));

// After:
let mut app: TermWmApp<SvgImageComponent> = TermWmApp::new(AppContext::new("example", "0.0.0"));
let left_key = app.open_window(AppRootComponent::Custom(left));
```

## Files to modify

| File | Change |
|------|--------|
| `src/components.rs` | Replace enum with `AppRootComponent<C = NoopComponent>` + manual `Component` impl dispatching on `Core`/`Custom` |
| `src/term_wm_app.rs` | Add `<C = NoopComponent>` generic to `TermWmApp`, move impl blocks to `impl<C: Component<TermWmAction>>`, update `AppRootComponent::Core(...)` calls (drop `SvgImage`) |
| `src/prelude.rs` | Re-export stays the same (still `AppRootComponent`) |
| `src/lib.rs` | `render_app` is already generic over `C: Component<TermWmAction>` — no change needed |
| `examples/dual_image.rs` | Use `AppRootComponent::Custom(...)` with explicit `TermWmApp<SvgImageComponent>` |

## What stays the same

- `CoreWmComponent` enum — unchanged
- `WindowManager<C, L, O>` — unchanged
- `render_app` generic signature — unchanged
- All internal pattern matches on `AppRootComponent::Core(CoreWmComponent::Terminal(...))` — unchanged (just lose the `SvgImage` arm)
