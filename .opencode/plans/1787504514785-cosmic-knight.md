# Stabilize Windows CI: remove real IPC from unit binary entirely

## Why previous rounds did not suffice

Two compounding facts, now confirmed:

1. **The 60s warnings are queue timers, not four hangs.** libtest starts a
   test's clock when its thread SPAWNS; `#[serial]` acquires its lock INSIDE
   the body. One holder blocks three queued tests whose clocks tick without
   executing a line. Each round we fixed one holder and another surfaced.
2. **Per-call bounds left unbounded TOTAL loops.** With
   `ConnectWaitMode::Timeout(2s)`, `ensure_gateway`'s spawn-probe loop can
   legally grind 150x2s = ~5 minutes and the down-loops 50x2s = ~100s when a
   Windows pipe stays busy, exceeding any watchdog deadline while "working as
   designed".

Conclusion: a unit test binary must not contain real gateway IPC at all. The
real shutdown proof ALREADY lives in tests/integration_session.rs
(`ShutdownGateway::call(&*client, true)` at :1758, non-forced rejection at
:1741), which passes on every platform.

`stop_gateway_daemon_e2e_from_app_actions` (src/main.rs:1418) holds ONLY
`env_lock()`. It is NOT in the `runtime_config` serial group. Meanwhile these
tests install `session_persistence: false` into the process-global config for
their duration, serialized against each other but NOT against the e2e test:

### 1. Hermetize `handle_custom_action_consumes_stop_gateway_actions`

Keep every CONTRACT assertion, drop all live-daemon machinery:
- DELETE: `ensure_gateway(...)` call, shutdown probe loop + socket-die
  assertions, `install_diagnostic_panic_hook()` usage.
- REPLACE env pinning target: set `GATEWAY_CHANNEL_ENV_VAR` to a guaranteed-
  dead unique name (`term-wm/testgw-dead-{pid}-{counter}`, NEVER spawned).
  Connect fails instantly on every platform (file-not-found / ConnectionRefused),
  so:
  - dialog counts render the "unavailable" fallback while still containing
    "Active workspaces:" (assert unchanged);
  - `stop_gateway(true)` fails fast and the executor STILL returns true
    (src/main.rs:1013-1024 match-with-toast), proving consumption.
- Assertions kept: opened, visible, Enter == Some(Confirm), close clears,
  StopGatewayDaemon consumed.

### 2. Delete the real-IPC e2e from the bin

Remove `stop_gateway_daemon_e2e_from_app_actions` +
`stop_gateway_daemon_e2e_from_app_actions_inner`. Coverage accountability:
- forced-shutdown RPC semantics + live-socket death: already pinned by
  integration_session.rs (:1741-1768 region);
- WM-layer dispatch contract (overlay routing to host): pinned by
  `dispatch_action_routes_stop_gateway_actions_to_host` in term-wm-core;
- palette consumption contract: pinned by the hermetized test from (1).

### 3. Hermetize remaining daemon dialers

- `handle_custom_action_consumes_workspace_actions`: replace
  `ensure_test_gateway()` with the same pinned dead-name env var (actions
  tolerate IPC failure by design; asserts unchanged). Keep serial key (env).
- `switch_workspace_follow_enabled_uses_all_viewers_scope` (and its CallerOnly
  sibling if present): same replacement; rebind failures log-and-continue,
  consumption asserts unchanged.
- After this, NO test in src/main.rs spawns daemons or probes sockets.

### 4. Remove orphaned harness code

Delete now-unused items: `ensure_gateway`, `ensure_test_gateway`,
`test_gateway_runtime`, `arm_watchdog`, `WatchdogGuard`, `Breadcrumbs`,
`phase!` macro, `install_diagnostic_panic_hook`/`PanicHookGuard` (no longer
installed anywhere). Serial scope after purge:
- `#[serial(process_global_state)]` remains ONLY on tests that mutate env
  (the pinned dead-name tests + help_shows_resolved_gateway + runtime_config
  quartet). All members are pure-CPU sub-millisecond apart from instant
  connect-refused errors; convoy starvation becomes impossible because no
  member can block.

Review directive compliance:
- Child::wait audit: grep of these flows shows daemons here are tokio TASKS,
  not Child processes; `auto_spawn` Child handling lives outside the bin test
  paths (recorded in plan for the record).
- recv audit: event pumps use crossbeam select with timeouts; no bare
  blocking `recv()` in tested action paths.
