# Fix #306: Real-time screen size updates not working from all clients

## Problem

With multiple connected clients, the Command Palette shows real-time terminal-size
updates only for some clients. Others receive broadcasts but their own resizes never
appear in real time.

## Root cause (verified by tracing the full pipeline)

Palette user rows come from two caches in the internal WM: `wm.user_registry` and
`all_users_by_ws` (both copies). When a client resizes, the daemon sends a debounced
`OnUserResized(conn_id, cols, rows)` to the internal WM, and
`TermWmApp::on_user_resized` (src/term_wm_app.rs:1076) drops the event entirely unless:

1. the conn_id is already in `user_registry`, AND
2. the conn_id is found in BOTH `all_users_by_ws` copies.

Registry seeding is racy: a one-shot `ListUsers` right after SubscribeInternalInput
(src/main.rs:669-687), plus `OnUserConnected` pushes that are suppressed for the sole
client (`clients.len() > 1` gate, session_server.rs:1102) or skipped when
`internal_wm_caller` is still None (WM booting). Reconnecting viewers get fresh
conn_ids the registry never learns. There is no periodic re-sync, so gaps are permanent
and those clients silently stop receiving real-time updates.

Secondary gap: the server's `ResizePty` handler (session_server.rs:1222-1231) ignores
size reports from conns without a `ClientEntry` (entries are created only in Spawn),
instead of creating one on demand.

## Fix (user chose: Full fix)

### 1. Resilient `on_user_resized` (src/term_wm_app.rs)

Rework `TermWmApp::on_user_resized` (:1076-1095) so a miss in any cache reconciles
instead of dropping, WITHOUT generating redraw work while the palette is closed
(idle-pacer constraint: per-user size labels render only inside the palette overlay,
so hidden-state resizes have zero visual representation):

- Distinguish "conn not present" from "same-size no-op":
  - `user_registry`: check `get_by_conn_id(conn_id).is_some()` before `update_size`.
  - Change `patch_users_by_ws` (:156-173) to return `(present, changed)` instead of
    `bool` (single call site; update its doc comment). Keep patching BOTH copies
    (`self.all_users_by_ws` and `self.wm.all_users_by_ws`); presence = found in either.
- New return-value contract (`bool` = "mutation worth a repaint/reconcile"; runner.rs
  :549-553 turns `true` into `on_user_registry_changed`, arming the 2s debouncer when
  the palette is open):
  - Fully known (registry + both maps) and nothing changed anywhere: return `false`.
  - Fully known, changed, palette visible: immediate `refresh_palette_items()`,
    return `true` (today's happy path).
  - Fully known, changed, palette closed: return `false` (caches are patched directly;
    preserves current semantics, no redraw).
  - Cache miss (ANY source missing the conn): return `palette_visible`. When open, this
    arms the debounced full `refresh_workspace_cache()` + `refresh_palette_items()`
    (~2s heal). When closed, return `false`: no redraw spam during resize drags, and
    `open_command_palette()` already calls `refresh_workspace_cache()` so entries heal
    before the next render anyway.
- Update comments accordingly (keep existing comment style; no em/en dashes).

### 2. Periodic `ListUsers` registry re-sync (src/main.rs)

Spawn the re-sync as an INDEPENDENT background task inside the listener-task block;
never run it sequentially in the listener task itself (the listener task must stay
responsive and its existing keep-alive loop at :689-691 stays as-is). Mirror the
stats-reporter pattern (:655-667):

```rust
// Independent periodic re-sync of the user cache. Runs on its own task so the
// listener task keeps processing RPC notifications uninterrupted.
let client_for_users = Arc::clone(&client);
let channel_for_users = channel.clone();
tokio::spawn(async move {
    let mut interval = tokio::time::interval(USER_CACHE_REFRESH_INTERVAL);
    loop {
        interval.tick().await; // first tick fires immediately (preserves the one-shot)
        match ListUsers::call(&*client_for_users, channel_for_users.clone()).await {
            Ok(resp) => {
                let _ = tx_for_users.try_send(UnifiedEvent::UserCacheRefreshed(resp.users));
            }
            Err(e) => tracing::debug!("ListUsers refresh failed: {e:?}"),
        }
    }
});
```

- New const near main.rs's other consts or beside the spawn site:
  `const USER_CACHE_REFRESH_INTERVAL: Duration = Duration::from_secs(15);`
- Replace only the one-shot block at :669-687 with the spawned task above.
- `UnifiedEvent::UserCacheRefreshed` already bulk-syncs `user_registry` without toast
  spam (runner.rs:554-570), so this self-heals stale conn_ids (reconnects, cold-start
  races).

### 3. Server: create missing ClientEntry on resize (crates/term-session-server/src/session_server.rs)

Extract a shared, testable helper used by both Spawn (:1071-1099) and ResizePty
(:1213-1240) handlers:

```rust
/// Insert or update a client's geometry. Creates the entry from connection
/// metadata when absent. Returns true when the reported size differs from
/// what was stored (a newly created entry always counts as changed).
fn upsert_client_geometry(
    clients: &mut HashMap<usize, ClientEntry>,
    conn_id: usize,
    seed: Option<ClientEntry>,
    cols: u16,
    rows: u16,
) -> bool
```

- In the ResizePty handler, fetch conn metadata exactly like Spawn does
  (conns.read().await → clone, drop the guard BEFORE locking the channel; never hold
  two locks), pass it as `seed`, replace the current `get`/`get_mut` dance.
- Keep the existing `pending_wm_resizes` + `spawn_wm_resize_flush` + broadcast logic
  driven by the returned `changed` flag.
- Refactor Spawn to call the same helper (dedupe; behavior preserved).

## Risks / edge cases

- Cache-miss `true` returns occur ONLY while the palette is open, so no redraw churn
  during resize drags in normal (closed-palette) use; the debounced full IPC refresh
  runs at most once per unknown-client burst (debounce collapses). Blocking IPC already
  runs on the main loop today via `poll_palette_tick`.
- The ListUsers re-sync task must own `Arc` clones of the client/tx/channel and be
  spawned independently; the listener task's keep-alive loop (:689-691) is untouched so
  RPC notification processing is never blocked.
- Debouncer arming only matters while the palette is open (`on_user_registry_changed`
  resets it otherwise, term_wm_app.rs:1068-1074); closed-palette staleness is healed on
  next open via `open_command_palette` → `refresh_workspace_cache()`.
- Lock ordering in the server: fetch conn metadata under `conns.read()`, drop it, then
  lock the channel (existing resolve-and-drop rule).
- `u16` size arithmetic unchanged (pure assignments); no new coordinate math.
