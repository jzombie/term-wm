# Workspace-wide test stabilization: eliminate indefinite hangs at the source

## Root cause chain (fully traced this round)

The remaining hangs are NOT gateway RPC timeouts (those were fixed); they are
**unbounded named-pipe CONNECT waits inside `probe_ipc_endpoint`**, which sits
OUTSIDE every timeout introduced so far:

- interprocess 2.4.3 `Stream::connect` defaults to
  `ConnectWaitMode::Unbounded`: on Windows, if the pipe exists but its instance
  is busy (our freshly spawned daemon still serving the previous probe's
  connection), `CreateFile` returns `ERROR_PIPE_BUSY` and interprocess enters an
  INDEFINITE `WaitNamedPipeW`-style wait (verified in vendored source:
  options.rs "defaults to unbounded waiting"; lib.rs `ConnectWaitMode` docs).
- `probe_ipc_endpoint` (crates/term-session-muxio-service-definitions/src/channel.rs:91)
  uses exactly that default sync connect, and is called by `ensure_gateway`,
  ensure/down probe loops, and daemon selfchecks.
- In `handle_custom_action_consumes_stop_gateway_actions`, a probe races the
  just-spawned daemon's single pipe instance, blocks forever INSIDE
  `ensure_gateway`/down-loop while HOLDING `#[serial(process_global_state)]`,
  and the convoy starves the other three (two of which do no I/O at all).
  Evidence fit: `consumes_workspace_actions` became healthy once its own path
  was bounded last round; this member still holds an unbounded primitive.

The good news: interprocess exposes exactly what we need:
`ConnectOptions::new().name(n).wait_mode(ConnectWaitMode::Timeout(d)).connect_sync()`
returning `WouldBlock` on expiry (lib.rs:53-60), and
`Stream::connect` is literally documented as the `Unbounded` shorthand
(stream/trait.rs:30-34).

## Changes

### 1. Bound the probe connect (crates/term-session-muxio-service-definitions/src/channel.rs)

```rust
/// Client-side cap for one reachability probe connect. Interprocess defaults
/// to ConnectWaitMode::Unbounded, which on Windows parks in WaitNamedPipeW
/// indefinitely when a server instance is busy; probes must stay finite.
/// 2s floor per review: named-pipe allocation on loaded CI workers can
/// exceed sub-second budgets.
const PROBE_CONNECT_TIMEOUT: std::time::Duration = std::time::Duration::from_millis(2000);

pub fn probe_ipc_endpoint(channel: &ChannelName) -> bool {
    let Ok(name) = channel.to_string().to_ns_name::<GenericNamespaced>() else {
        return false;
    };
    match interprocess::local_socket::ConnectOptions::new()
        .name(name)
        .wait_mode(interprocess::ConnectWaitMode::Timeout(PROBE_CONNECT_TIMEOUT))
        .connect_sync()
    {
        Ok(_) => true,
        Err(e) if e.kind() == std::io::ErrorKind::WouldBlock => false, // timed out
        Err(_) => false,
    }
}
```

Probe semantics note: connect-and-immediate-drop is the DEFINITION of a
reachability probe and predates this change (the current implementation does
the same); the daemon side observes a zero-byte client that closes, which the
muxio listener must treat as benign. During implementation, verify the
listener logs handshake EOF at debug (downgrade to debug if it warns); no
synthetic handshake is added, since pretending to speak muxio would corrupt
server state far worse than a clean early EOF.

Every caller (ensure_gateway loops, e2e up/down probes, daemon selfcheck,
auto-spawn probing in prod startup paths) becomes bounded automatically.
Existing probe-loop iteration counts already tolerate WouldBlock-as-false.

### 2. Serial keys: revert the split (src/main.rs)

Review SEV-1 accepted: distinct serial keys run CONCURRENTLY, and
`std::env::set_var` writers racing unrelated threads' env reads is undefined
behavior territory we will not re-enter. ALL existing members return to ONE
key, `#[serial(process_global_state)]`. The previously feared convoy is
harmless now: with (1) plus the already-shipped `with_gateway_timeout`, every
member terminates in seconds, so worst case is a short serialized wait, never
an indefinite one. The explicit-config injection refactor remains the
long-term follow-up ticket.

### 3. Test watchdog: bounded evidence with a SHARED breadcrumb buffer

Round-2 corrections adopted wholesale: `thread_local!` breadcrumbs would be
INVISIBLE to the watchdog thread (TLS is per-thread), and process-wide
`exit` sacrifices unrelated in-flight tests. Revised mechanics:

```rust
/// Shared, append-only breadcrumb buffer for one armed test. The TEST thread
/// pushes phases through the cloned handle; the watchdog thread reads the
/// SAME buffer when firing. (thread_local! was rejected: TLS is invisible
/// across the watchdog boundary.)
type Breadcrumbs = std::sync::Arc<std::sync::Mutex<Vec<String>>>;

struct WatchdogGuard {
    done: std::sync::Arc<std::sync::atomic::AtomicBool>,
    label: &'static str,
}

fn arm_watchdog(label: &'static str, phases: Breadcrumbs) -> WatchdogGuard {
    let done = std::sync::Arc::new(std::sync::atomic::AtomicBool::new(false));
    let done_thread = std::sync::Arc::clone(&done);
    let deadline = std::time::Duration::from_secs(90);
    std::thread::Builder::new()
        .name(format!("watchdog-{label}"))
        .spawn(move || {
            // Wall-clock deadline via monotonic Instant: thread::sleep only
            // guarantees a MINIMUM, so accumulating nominal step durations
            // would inflate the bound under loaded CI schedulers.
            let start = std::time::Instant::now();
            let step = std::time::Duration::from_millis(250);
            while start.elapsed() < deadline {
                if done_thread.load(std::sync::atomic::Ordering::Relaxed) {
                    return;
                }
                std::thread::sleep(step);
            }
            // Last-resort evidence dump. Re-check done so a test finishing
            // exactly now wins the race.
            if done_thread.load(std::sync::atomic::Ordering::Relaxed) {
                return;
            }
            let crumbs = phases.lock().unwrap_or_else(|p| p.into_inner()).join("\n  ");
            let path = std::env::temp_dir().join(format!("twm-watchdog-{label}.log"));
            let _ = std::fs::write(&path, format!("WATCHDOG {label}:\n  {crumbs}\n"));
            eprintln!(
                "TEST WATCHDOG: '{label}' exceeded {deadline:?}; phases:\n  {crumbs}\nlog: {}",
                path.display()
            );
            std::process::exit(101);
        })
        .expect("spawn watchdog");
    WatchdogGuard { done, label }
}

impl Drop for WatchdogGuard {
    fn drop(&mut self) {
        self.done
            .store(true, std::sync::atomic::Ordering::Relaxed);
    }
}
```

Call sites:

```rust
let phases: Breadcrumbs = Default::default();
let _wd = arm_watchdog("consumes_stop_gateway", std::sync::Arc::clone(&phases));
phase!(phases, "ensure_gateway");
let gw_socket = ensure_gateway(...);
...
```

(`phase!(handle, fmt-args)` macro pushes onto the shared buffer.)

Deliberate tradeoff, documented instead of hidden: on expiry the watchdog
still terminates the runner process, which under parallel execution forfeits
other in-flight tests' individual reporting. Rationale: every layer beneath
it is already bounded (probe 2s, gateway exchange 10s, loops finite), so the
watchdog firing means an UNKNOWN regression outside those layers; a fast,
evidence-rich red build strictly dominates resuming an indefinite hang, and
completed tests' results have already streamed to the log line-by-line. The
structural cure reviewers asked for, relocating real-IPC e2e coverage into a
dedicated `tests/` integration target where each binary owns its process, is
BLOCKING for the next work cycle (per review directive 2): it requires a
`#[doc(hidden)] pub mod test_support` facade in the lib exporting bin-private
constructors (`App`, `build_wm`, `test_app`), after which both this watchdog's
exit path and the serial key are deleted. Recorded as follow-up ticket;
expected to delete both this watchdog and the serial key entirely.

Apply to every test that spawns gateways or mutates env (both stop-gateway
tests, consumes_workspace_actions, switch_workspace_*, help_shows_resolved_gateway);
sprinkle `phase!("...")` at each stage boundary (before/after ensure_gateway,
dialog open, Enter, shutdown, down-probe).
