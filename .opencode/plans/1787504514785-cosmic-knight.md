# De-flake Windows CI: indefinite hang in process_global_state test group

## Evidence and root cause

CI shows FOUR tests stuck >60s: `handle_custom_action_consumes_stop_gateway_actions`,
`handle_custom_action_consumes_workspace_actions`,
`handle_custom_action_returns_false_when_runtime_disabled`,
`help_shows_resolved_gateway`. libtest prints "has been running" once a thread
ENTERED the test body, so three of these are queued on the
`#[serial(process_global_state)]` lock while ONE holder blocks forever. Two of
the queued tests do no IPC at all (pure config init / help rendering), which
rules out per-test causes and confirms the convoy.

The unbounded primitive every gateway-touching flow shares is
`term_session::with_gateway` (crates/term-session/src/lib.rs:122-148):

```rust
std::thread::spawn(move || {
    rt.block_on(async {
        let client = RpcIpcClient::new(&gateway.to_string()).await ...?;
        Ok(op(client).await)
    })
})
.join()
```

- `RpcIpcClient::new` performs a single `LocalSocketStream::connect` with NO
  timeout (muxio-tokio-rpc-ipc-client rpc_ipc_client.rs:81); on Windows named
  pipes a connect against an instance being torn down or in a busy state can
  wait in the kernel indefinitely.
- The op itself (`RebindWorkspace::call`, `ShutdownGateway::call`, ...) has no
  deadline either.
- `.join()` then parks the TEST thread forever.

Flows hit by the hanging group: `stop_gateway(true)` and
`request_workspace_rebind_with_scope` (both via `with_gateway`) plus the plain
connect. Precedent exists in-repo: `list_channels_bounded` /
`list_wm_stats_bounded` were added precisely because the unbounded variants
froze callers; they abandon the worker thread on timeout.

The serial consolidation is NOT reverted: it correctly turned what would be
scattered individual hangs into one visible convoy. Once every member is
bounded, the convoy cannot form.

## Review directives: adopt / rebut

- Directive 2 (unique pipe names): ALREADY satisfied. Every test gateway uses
  pid/counter-suffixed names (`testgw-stop-{pid}-{n}`, `testgw-stop-{id}`,
  ensure_gateway's caller-supplied unique names). No static reuse exists.
- Directive 1 (inject instance-bound config, drop globals): REJECTED for this
  ticket as an architecture rewrite spanning crates (`session_persistence_enabled()`
  readers across core/app), disproportionate to de-flaking. Filed as follow-up.
  Note the reviewer's cross-binary collision claim is factually wrong: env vars
  and the RuntimeConfig static are PER-PROCESS; two test binaries cannot collide
  through them. Only named pipes are system-global, and those are already
  uniquely named. The serial key stays until that refactor lands; with every
  member now bounded, worst case is a finite delay, never an infinite hang.
- SEV-1 correction: muxio's client uses interprocess's TOKIO `LocalSocketStream`
  (cooperative connect), so inner tokio timeouts do fire. The thread-level
  `recv_timeout` bound is still adopted as defense-in-depth per directive.
  Compile-level corrections to the directive itself, verified against
  muxio-tokio-rpc-ipc-client 0.15.0-alpha source: `RpcIpcClient::new` ALREADY
  returns `Result<Arc<Self>, _>` (rpc_ipc_client.rs:77), so the proposed extra
  `Arc::new(client)` would double-wrap and fail E0308; and ops' futures keep
  their existing generic output type (the inner service Result), since changing
  the bound to `Future<Output = io::Result<T>>` would break every existing call
  site. The `total_timeout` binding for error formatting is adopted.
- Directive 3 (RAII TestGatewayGuard): PARTIALLY covered: shutdown is explicit
  today and worker threads are deliberately abandoned on timeout (documented
  in-repo pattern); full join-on-drop harness deferred to the same follow-up.
  On abandonment leaks: an abandoned worker's client handles reference that
  test's UNIQUE pipe name only; they cannot produce ERROR_PIPE_BUSY against
  other tests' differently-named pipes, and all handles are reclaimed at
  process exit.

## Changes

### 1. Bound `with_gateway` at BOTH layers (crates/term-session/src/lib.rs)

Factual note on the review's SEV-1: muxio imports
`interprocess::local_socket::tokio::prelude::*`, so `LocalSocketStream::connect`
inside `RpcIpcClient::new` is the COOPERATIVE tokio type and inner
`tokio::time::timeout` does fire today. The thread-level bound is adopted
anyway as defense-in-depth: it keeps the guarantee even if a future transport
revision introduces a non-cooperative call, and it bounds the whole exchange
(connect + call) with one deadline at the OS join boundary instead of two
stacked futures timeouts.

```rust
/// Upper bound for ONE gateway IPC exchange (connect + call combined).
/// Generous for slow CI but finite. On expiry the worker thread is
/// abandoned (in-repo precedent from the *_bounded helpers); its handles
/// die with the process and every test gateway name is already
/// pid/counter-unique, so no cross-test pipe contention results.
const GATEWAY_CALL_TIMEOUT: std::time::Duration = std::time::Duration::from_secs(5);

pub fn with_gateway<F, Fut, T>(op: F) -> io::Result<T>
where ... { with_gateway_timeout(GATEWAY_CALL_TIMEOUT, op) }

pub fn with_gateway_timeout<F, Fut, T>(
    timeout: std::time::Duration,
    op: F,
) -> io::Result<T>
where
    F: FnOnce(Arc<muxio_tokio_rpc_ipc_client::RpcIpcClient>) -> Fut + Send + 'static,
    Fut: std::future::Future<Output = T> + Send + 'static,
    T: Send + 'static,
{
    let gateway = gateway_channel_name();
    let (tx, rx) = std::sync::mpsc::channel();
    let total_timeout = timeout.saturating_mul(2);
    std::thread::spawn(move || {
        let runtime = tokio::runtime::Builder::new_current_thread()
            .enable_all()
            .build();
        let result = match runtime {
            Err(e) => Err(io::Error::other(format!("runtime: {e}"))),
            Ok(rt) => rt.block_on(async {
                // Verified against muxio-tokio-rpc-ipc-client 0.15.0-alpha:
                // RpcIpcClient::new already returns Result<Arc<RpcIpcClient>>,
                // so the client satisfies op's Arc parameter WITHOUT an extra
                // Arc::new wrapper (double-wrapping would not type-check).
                let client =
                    tokio::time::timeout(timeout, RpcIpcClient::new(&gateway.to_string()))
                        .await
                        .map_err(|_| {
                            io::Error::new(
                                io::ErrorKind::TimedOut,
                                format!("gateway connect timed out after {timeout:?}"),
                            )
                        })?
                        .map_err(|e| {
                            io::Error::new(io::ErrorKind::ConnectionRefused, e)
                        })?;
                // Ops keep their EXISTING output type (the inner service
                // Result under generic T); wrapping them in io::Result here
                // would break every call site's subsequent `.map_err`.
                let out = tokio::time::timeout(timeout, op(client)).await
                    .map_err(|_| {
                        io::Error::new(io::ErrorKind::TimedOut,
                            format!("gateway call timed out after {timeout:?}"))
                    })?;
                Ok(out)
            }),
        };
        let _ = tx.send(result);
    });
    // Hard OS-level bound: even a kernel-stuck worker cannot park the caller
    // past this recv_timeout.
    match rx.recv_timeout(total_timeout) {
        Ok(result) => result,
        Err(_) => Err(io::Error::new(
            io::ErrorKind::TimedOut,
            format!("gateway exchange timed out after {total_timeout:?} on '{gateway}'"),
        )),
    }
}
```

Generic `T` preserved so NO call site changes. All ops (`stop_gateway`,
`request_workspace_rebind*`, `list_users`, ...) become bounded automatically.
`list_channels_bounded` / `list_wm_stats_bounded` keep their tighter UI-facing
deadlines (they already wrap with their own shorter windows; verify unchanged).
