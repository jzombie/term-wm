# Extract `KeyedTaskDebouncer` into debounce.rs

## Goal

Replace the ad-hoc Direct Mode toast debounce currently embedded in `WindowManager`
(`direct_mode_debounce: HashMap<WindowKey, (TaskId, DirectInputMode)>` + hand-rolled submit/flush
logic) with a reusable, generic `KeyedTaskDebouncer<K, P, T>` in a new `debounce.rs` module.

The debouncer preserves the exact semantics already shipped (leading-edge with hard cap): the first
`submit` for a key arms one flush timer; later submits only update the buffered payload (deadline
is never pushed back, so trickling sequences can't starve the flush).

## Design — `crates/term-wm-core/src/debounce.rs`

Generic over key `K`, buffered payload `P`, and the scheduler task payload `T`:

```rust
pub struct KeyedTaskDebouncer<K, P, T> {
    pending: HashMap<K, (TaskId, P)>,
    handle: Option<TaskHandle<T>>,
    delay: Duration,
    make_task: fn(K) -> T,
}
```

Bounds: `K: Eq + Hash + Copy` (WindowKey = `slotmap::DefaultKey`, which is Copy). `make_task` is a
function pointer `K -> T` so the caller controls what flush task the runner will drain
(e.g. `SystemTask::FlushDirectModeToast`).

API:
- `new(delay: Duration, make_task: fn(K) -> T) -> Self`
- `set_handle(&mut self, handle: TaskHandle<T>)` — wire the scheduler handle (mirrors the fact that
  `run_with_defaults` installs the WM's `system_task_handle` after construction).
- `submit(&mut self, key, payload)` — leading-edge: update buffered payload if present; else
  `handle.schedule_once(delay, make_task(key))` and store `(TaskId, payload)`. If no handle:
  `tracing::warn!` + no-op (same behavior as today's no-handle branch; tests must set a handle).
- `flush(&mut self, key) -> Option<P>` — remove + return the buffered payload (called by the runner
  when the flush task fires).
- `cancel(&mut self, key)` — remove the entry and `handle.cancel(id)` the armed task (window close).
- Inspectors: `len()`, `is_empty()`, `contains_key(key)`, `peek(key) -> Option<&P>`,
  `pending_task_id(key) -> Option<TaskId>` (used by tests to prove the deadline isn't re-armed).

## Changes

### 1. `crates/term-wm-core/src/debounce.rs` (new)
- Implement `KeyedTaskDebouncer` as above, using `crate::task_scheduler::{TaskHandle, TaskId}`.
- Unit tests (no timing; use `TaskScheduler::<T>::new()` + `handle()`):
  - `submit_arms_timer_on_first_submit` — first submit schedules one task
    (`handle.has_pending()`, `time_until_next()` is Some).
  - `second_submit_updates_buffer_without_reschedule` — after two submits, `peek(key)` is the
    latest payload and `pending_task_id(key)` is unchanged.
  - `flush_returns_latest_and_clears` — `flush` yields the latest payload and `is_empty()`.
  - `flush_returns_none_when_absent`.
  - `cancel_removes_and_cancels_task` — after `cancel`, `len()==0`, `has_pending()` is false, and
    `drain_expired_once()` yields nothing after sleeping past the delay.
  - `submit_without_handle_is_noop` — `new(...)` without `set_handle`: `submit` leaves `is_empty()`
    true (logs a warning).
  - `cap_no_starvation` — several submits over time (sleeps between) still produce exactly ONE
    flush task on `drain_expired_once()` once the 200 ms window elapses, and it carries the latest
    payload.

### 2. `crates/term-wm-core/src/lib.rs`
- Add `pub mod debounce;` (alphabetical, near `constants`/`debug_*`).

### 3. `crates/term-wm-core/src/window/window_manager/mod.rs`
- Replace the field:
  ```rust
  direct_mode_debounce: HashMap<WindowKey, (TaskId, DirectInputMode)>,
  ```
  with
  ```rust
  direct_mode_debounce: KeyedTaskDebouncer<WindowKey, DirectInputMode, SystemTask>,
  ```
- Constructor init (~line 888): `direct_mode_debounce:
  KeyedTaskDebouncer::new(DIRECT_MODE_TOAST_DEBOUNCE, SystemTask::FlushDirectModeToast),`
  (`SystemTask::FlushDirectModeToast` is a `fn(WindowKey) -> SystemTask`, matching `fn(K) -> T`).
- `set_system_task_handle` (~line 2590): also wire the debouncer:
  `self.direct_mode_debounce.set_handle(handle.clone());` before storing `self.system_task_handle`.
- `direct_input_mode_changed` (~line 2696): collapse to
  `self.direct_mode_debounce.submit(key, mode);` (drop the hand-rolled map/handle logic).
- `flush_direct_mode_toast` (~line 2718): `let Some(mode) = self.direct_mode_debounce.flush(key)
  else { return };` then the existing window-exists + `window_title` + `push_notification` logic
  (uses `DIRECT_MODE_TOAST_TTL`).
- `close_window` (chrome.rs ~line 121, `ClosePolicy::Destroy` branch): replace
  `self.direct_mode_debounce.remove(&key);` with `self.direct_mode_debounce.cancel(key);`.
- Constants: keep `DIRECT_MODE_TOAST_DEBOUNCE` (passed to `new`) and `DIRECT_MODE_TOAST_TTL`.
  `HashMap` import may still be needed elsewhere (it is — `system_windows`); `DirectInputMode`
  import stays.
- Tests in `window_manager/mod.rs`:
  - `direct_mode_toast_debounce_coalesces`: `wm.direct_mode_debounce.len()` → `len()`;
    `wm.direct_mode_debounce.get(&key).map(|(_, m)| *m)` → `wm.direct_mode_debounce.peek(&key).copied()`.
  - `direct_mode_toast_cap_does_not_reschedule`: `wm.direct_mode_debounce.get(&key).unwrap().0` →
    `wm.direct_mode_debounce.pending_task_id(key).unwrap()`.
  - Other three tests unchanged (they don't touch the field).
