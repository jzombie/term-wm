# Consolidate the two debounce modules

## Problem

`term-wm-core` now has two debounce modules:
- `crates/term-wm-core/src/debounce.rs` (crate root) — `KeyedTaskDebouncer` (added recently)
- `crates/term-wm-core/src/utils/debounce.rs` — `DelayedReleaseBool` (pre-existing)

Two files both named `debounce` in one crate is confusing. Both are debounce primitives and belong
together.

## Approach

Move `KeyedTaskDebouncer` into the existing `utils/debounce.rs` (beside `DelayedReleaseBool`) and
remove the crate-root module. This is the minimal-churn consolidation: `DelayedReleaseBool` is
already re-exported from `crate::utils` and consumed via that path; the crate-root `debounce`
module has exactly one consumer.

## Changes

### 1. `crates/term-wm-core/src/utils/debounce.rs`
- Append the `KeyedTaskDebouncer` struct, `impl`, and `#[cfg(test)] mod tests` (moved verbatim from
  the current `src/debounce.rs`, lines 6–209).
- Add imports to the top of the file:
  `use std::collections::HashMap;` and `use crate::task_scheduler::{TaskHandle, TaskId};`
  (the file already has `use std::time::{Duration, Instant};`).
- `crate::task_scheduler::TaskScheduler` references in the tests resolve unchanged from this
  location (crate-relative path).

### 2. `crates/term-wm-core/src/utils/mod.rs`
- Add `pub use debounce::KeyedTaskDebouncer;` next to the existing
  `pub use debounce::DelayedReleaseBool;` (line 7).

### 3. `crates/term-wm-core/src/window/window_manager/mod.rs`
- Line 39: `use crate::debounce::KeyedTaskDebouncer;` → `use crate::utils::KeyedTaskDebouncer;`.
- No other code changes — the `direct_mode_debounce` field, `submit`/`flush`/`cancel` call sites,
  and `set_system_task_handle` wiring are unchanged.

### 4. `crates/term-wm-core/src/lib.rs`
- Remove `pub mod debounce;` (line 9).

### 5. Delete `crates/term-wm-core/src/debounce.rs`.
