# Split Direct Mode: keyboard vs mouse capture

## Problem

Direct Mode today is a single all-or-nothing bool (`ctx.direct_mode()`) driven by
`PtyStateTracker::requires_app_routing()` = `alt_screen || mouse_tracking || custom_margins`.

In `TerminalComponent::handle_events`, native text selection / right-click paste / link clicks are
gated behind `!ctx.direct_mode()` (terminal.rs:90-115). So an app on the **alternate screen without
mouse tracking** (pico/nano) disables native selection **and** gets no mouse events forwarded
(`mouse_event_allowed(None, …) == false`). The mouse is dead — text can't be selected or copied.

Desired model:
- **Default state (off):** app did NOT write mouse-enable sequences (`\x1b[?1000h/1002h/1003h` + `\x1b[?1006h`) → the terminal keeps mouse control → native selection + clipboard copy work, even on the alternate screen.
- **Captured state (on):** app enabled mouse tracking → suppress native selection, forward mouse events to app stdin as SGR bytes.
- **Override:** holding Shift (or Option/Alt on macOS) while click-dragging forces native selection even in a captured app.

Additionally, represent Direct Mode as a structured, serializable snapshot with independent
`keyboard` and `mouse` dimensions, log it to the debug logger, and show the access level in the toast.

## Design

New `DirectInputMode` struct (pty-engine), built by the tracker, carried on `ComponentContext`,
used for logging + toast, and used to split mouse routing from keyboard routing.

| Signal | Definition | Gates |
|---|---|---|
| `keyboard` | `alt_screen \|\| custom_margins` | runner key-forward, ScrollView key-scroll & scrollbar render, Terminal Shift+PgUp, Terminal render scroll-suppression |
| `mouse` | `mouse_tracking != None` | Terminal mouse branch (native vs forward), ScrollView wheel→scrollback (via aggregate) |
| `requires_direct_input()` | `keyboard \|\| mouse` (aggregate) | kept for `direct_mode()`, wheel routing, toast "enabled" check |

The Terminal mouse branch keys the native-vs-forward decision on the **app's parsed mouse-protocol
state** (`screen.mouse_protocol_mode()` / `mouse_protocol_encoding()`) plus the Shift/Option
override — **not** on `ctx.direct_mode()`.

## Changes

### 1. `crates/term-wm-pty-engine/src/pty_state_tracker.rs`
- New struct (derive `Debug, Clone, Copy, PartialEq, Eq, Default`; no serde — the debug log is
  plain `String` lines, so `Debug`/`tracing` are sufficient):
  ```rust
  pub struct DirectInputMode {
      pub keyboard: bool,   // alt screen || custom margins
      pub mouse: bool,      // mouse tracking requested
      // informational (logged, not gating):
      pub alt_screen: bool,
      pub application_cursor_keys: bool,
      pub custom_margins: bool,
      pub mouse_tracking: MouseTrackingMode,
      pub sgr_mouse: bool,
      pub alt_scroll: bool,
  }
  ```
- Methods: `requires_direct_input() -> bool` (`keyboard || mouse`), `access_label() -> &'static str`
  (`"Full"`/`"Keyboard"`/`"Mouse"`/`"Off"`), `is_active()`.
- `DirectInputTracker` trait: replace `fn requires_direct_input(&self) -> bool` with
  `fn direct_input_mode(&self) -> DirectInputMode`.
- `impl DirectInputTracker for PtyStateTracker` → `direct_input_mode()` reads all atomics.
  `requires_app_routing()` redefined as `self.direct_input_mode().requires_direct_input()` (same
  aggregate semantics — existing tests at lines 277-533 still pass).
- `crates/term-wm-pty-engine/src/lib.rs`: re-export `DirectInputMode`.

### 2. `crates/term-wm-core`
- `window/entry.rs`: `requires_direct_input()` → `tracker.direct_input_mode().requires_direct_input()`; add `direct_input_mode()`.
- `window/window_manager/mod.rs`: keep `direct_mode(key)` (aggregate); add `direct_input_mode(key) -> DirectInputMode`; in `component_context_for` (~1124) pass the mode via `.with_direct_input_mode(mode)`.
- `component_context.rs`: replace field `direct_mode: bool` with `direct_input_mode: DirectInputMode`.
  - `direct_mode()` getter → `mode.requires_direct_input()` (aggregate, back-compat).
  - New getters: `keyboard_direct()` → `mode.keyboard`, `mouse_captured()` → `mode.mouse`.
  - Keep `with_direct_mode(bool)` (maps to `{ keyboard: b, mouse: b, ..Default::default() }`, so existing tests keep passing); add `with_direct_input_mode(DirectInputMode)`.
- `runner.rs`:
  - Line 241-245: build ctx with `.with_direct_input_mode(app.wm().direct_input_mode(focus_id))`.
  - Line 649: key-forward gate → `app.wm().direct_input_mode(focus_id).keyboard` (the split: a
    mouse-only app no longer gets full keyboard passthrough).
  - `DirectInputChanged` drain (~377-388): query `app.wm().direct_input_mode(key)`, toast with
    access label (e.g. `Direct Mode (Full) enabled for vim` / `Direct Mode disabled for vim`),
    `tracing::debug!(?key, ?mode, %enabled, ...)`, and push
    `format!("[direct-mode] window={:?} enabled={} mode={:?}", key, enabled, mode)` to
    `term_wm_core::debug_log::global_debug_log()`.

### 3. `crates/term-wm-ui-components/src/terminal.rs` — the behavioral fix
Rework the `Event::Mouse` branch (89-147) so the native-vs-forward decision no longer consults `ctx.direct_mode()`:
- Hoist one scoped parser read at the top: `(mode, encoding)` from `screen.mouse_protocol_mode()`
  / `screen.mouse_protocol_encoding()`. Drop the lock before branching.
- `app_captures_mouse = mode != None && matches!(encoding, Default | Sgr)`.
- `override_active = force_native_selection(mouse.modifiers)` — new helper returning
  `modifiers.shift || modifiers.alt` (Option on macOS arrives as `alt`).
- `gesture_active = selection.button_down() || selection.is_dragging()` (keeps a native drag alive
  even if the override is released mid-gesture).
- If `!app_captures_mouse || override_active || gesture_active` → native handling (right-click
  paste, `handle_selection_mouse`, `try_handle_link_click`); return `Consumed` if handled, else
  `Ignored` (never forward while overriding / mid-gesture).
- Else → existing forward path (`mouse_event_allowed`, `localize_coordinate`,
  `mouse_event_to_bytes` → `TermWmAction::MouseToBytes`).
- Change scroll-suppression gates from `ctx.direct_mode()` to `ctx.keyboard_direct()`:
  line 73 (Shift+PgUp), line 513 (`suppress_scroll`), line 577 (scroll-sync push). Leave wheel &
  selection rendering semantics otherwise untouched.
- Keep `right_click`/`selection` code comments updated (AGENTS.md: update, don't delete).

### 4. `crates/term-wm-ui-components/src/scroll_view.rs`
- Line 384 (key scroll bindings) and line 539 (scrollbar render): `!ctx.direct_mode()` → `!ctx.keyboard_direct()`.
- Line 359 (wheel→scrollback): keep `ctx.direct_mode()` (aggregate) so wheel is still forwarded
  when the app captured the mouse or is on the alt screen.

### 5. Docs
- `README.md` (~60-77, 109-113) and `crates/term-wm-sys-ui-components/assets/help.md` (~35-41):
  document the default/captured mouse states, that native selection works for non-mouse-capturing
  apps (e.g. pico/nano), and the Shift/Option override.

Manual (macOS/Linux/Windows):
1. Run the WM; open `nano` (alt screen, no mouse) → mouse drag selects text, release copies to clipboard.
2. Open a mouse-capturing TUI (helix/micro/opencode-style) → clicks/drags/moves are routed to the app (cursor follows).
3. In the captured TUI, hold Shift (or Option on macOS) and drag → native text selection works instead.
4. Check the toast on transitions shows the level (e.g. "Direct Mode (Full) enabled for vim").
5. Open the debug log (command palette) → line like `[direct-mode] window=... enabled=true mode=DirectInputMode { keyboard: true, mouse: false, ... }`.

- `mouse_event_allowed`/encoding logic in `term-session-client` (embedded mode) left unchanged.
- serde: not needed for the text debug log; add only if JSON/wire serialization is ever required.
