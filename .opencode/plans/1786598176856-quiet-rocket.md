# Plan: A "dumb" `view!` macro — unified on a single `Component` trait (zero-cost)

## Goal

A declarative `view!` macro (JSX/RSX) that builds component trees — "dumb" (no reactivity, no reconciliation, no runtime tree) and zero-cost (fully-monomorphized code a developer could hand-write). The tree IS a genuine `Component`, so the macro plugs directly into the existing component system.

## Architectural pivot (post-review)

The previous plan introduced a parallel `View` trait (because `Component<Msg>: Any` forbids non-`'static` trees that borrow `{ &mut self.x }`). Review verdict AMEND: that creates a split-brain (two trait hierarchies, duplicate containers, behavioral drift). Resolution — **unify on `Component` and delete the `View` idea entirely**:

1. **Remove `: std::any::Any` from `pub trait Component<Msg>`** (`crates/term-wm-core/src/components.rs:35`). The `'static`/`Any` requirement moves to the WindowManager boundary: `WindowManager<C: Component<TermWmAction> + 'static, L, O>` (`mod.rs:296`). `L`/`O` already keep `'static` implicitly via their own `as_any_mut -> &mut dyn Any` methods. No method signatures change; this is a **bound relocation only**.
2. **`view!` emits `Component`s**: leaf tags → component constructors; `{ expr }` / `{ &mut expr }` → owned components / `&mut` references; containers → the existing `VerticalStackComponent`/`CenterComponent` + two new `HStackComponent`/`GridComponent`; heterogeneous siblings → generated per-invocation delegate enums implementing `Component` (the established `impl_component_delegate!` pattern).
3. **Delete** the `View` trait, `LeafView`, `BorrowedView`, `ViewComponent`, `NoopView`, `VStackView`, `HStackView`, `CenterView`, `GridView`, and the whole `view.rs` scaffolding from the earlier plan (none of it was committed — nothing to unwind beyond files I created locally: `crates/term-wm-core/src/view.rs`, `crates/term-wm-ui-components/src/view.rs`, plus lib.rs edits).
4. **Fix the behavioral drift** the review flagged: `VerticalStackComponent::handle_events` drops key events; give it focus-gated key routing (identical semantics to the shared helpers) so a terminal inside a `view!` stack receives keys. This is a strictly-improving, focus-gated change (unfocused children still get nothing → existing `wm_system_panel.rs` usage unaffected).

### External compatibility (verified)

`../rust-argtuner` (real consumer, deps on term-wm 0.9.24): implements `Component` for its own `ChartsView` (a `'static` type), uses `impl_component_delegate!(AppComponent { .. })`, `AppRootComponent::Custom(..)`, and `component_for_key_mut` + enum pattern matching. **No `Any` downcasting of components.** So removing `: Any` is fully backward-compatible for it. The explicit `+ 'static` on `WindowManager<C>` is satisfied by every existing consumer.

## Context: relevant component-system facts

- `Component<Msg>` (components.rs:35): lifecycle `init`/`on_mount`/`hitbox_id`/`handle_events`/`update`/`render(&mut self, &mut dyn RenderBackend, Rect, &ComponentContext, &mut HitboxRegistry)`/`destroy`/`desired_height`/selection/paste. Default `handle_events` already self-filters keys by `ctx.keyboard_focus_id()` (components.rs:94-101).
- `ComponentContext` (component_context.rs:32): immutable, builder-style; `screen_area()`, `with_screen_area(rect)`, `keyboard_focus_id()`, `with_keyboard_focus_id`, `active_hitbox()`, `scroll_handle()`, `with_window_key`. WM sets `screen_area` + `keyboard_focus_id` per frame (`mod.rs:1156-1170`).
- Containers generic over one child type `C: Component<TermWmAction>`: `VerticalStackComponent<C>` (`vertical_stack.rs:18`, `Vec<C>`, `.new()/.with_gap(u16)/.add(C)`, slices stripes by `desired_height`, 0 = stretch; **ignores key events today**), `CenterComponent<C>` (single child + size; forwards all events). `ScrollViewComponent<C>` is stateful — intentionally NOT a `view!` tag; injected via `{ &mut self.sv }`.
- `ButtonComponent` (`button.rs:104`) routes clicks by `ctx.localize_mouse_click` (screen-area), no hitbox identity → safe to reconstruct per frame. Stateful widgets (terminal/list/scroll) use hitbox ids + cross-frame state → must be app-owned and injected by `{ &mut ... }`.
- Delegate enums: `impl_component_delegate!` (`macros.rs:9`) generates full `Component` `match self` delegation; used by `AppRootComponent<C>` (`src/components.rs:9`), `CoreWmComponent`, `LayerComponent`, `OverlayComponent`. No `Any` references in the macro.
- Layout engine: `split_rects_nary`, `split_rects_with_gaps(area, orientation, weights, n, gap)`, `build_rects_from_sizes` (all re-exported from `split.rs`), `Orientation`, `LayoutRect{x:i32,y:i32,width:u16,height:u16}` — saturating ops required (AGENTS.md).
- Consumer entry: `TermWmApp<C>::new_custom(...)` → `open_window(AppRootComponent::Custom(comp))` (`examples/dual_image.rs`). Root crate re-exports `term_wm_core::*` + `term_wm_ui_components::*`. Edition 2024. `syn`/`quote`/`proc-macro2` in lockfile; `rstml` 0.13 (maintained, MIT) not yet.

## Syntax

```rust
fn view(&mut self) -> impl Component<TermWmAction> + '_ {
    view! {
        <VerticalStack gap=1>
            <Label text="System Status" />
            <Button label="Refresh" action={TermWmAction::OpenCommandPalette} />
            <Center width=60 height=8> { &mut self.terminal } </Center>
            { &mut self.scroll_view }
            { build_owned_widget(&self.state) }
        </VerticalStack>
    }
}
```

Two integration patterns:
1. **All-owned view** (no `&mut` blocks) → the `view!` value is a `'static` `Component` → `app.open_window(AppRootComponent::Custom(view!{ .. }))` directly. No wrapper type.
2. **Borrowed view** (has `{ &mut self.x }`) → app implements `Component` for its (owned) window struct and forwards lifecycle calls to a per-frame `fn view(&mut self) -> impl Component<TermWmAction> + '_` (see canonical usage below). The `'_`-returning `Component` is now legal because the trait no longer demands `'static`.

State rule (the honest "dumb" compromise): ephemeral tags must be stateless (Label, Button, layout containers); stateful components are app-owned and injected by reference (`{ &mut self.terminal }`). `ScrollView` is not a tag.

Three tiers, all resolved at compile time:
1. **Layout-primitive tags**: `<VerticalStack gap>`/`<Column>`, `<Row>`/`<HStack>`, `<Center width height>`, `<Grid cols="200px 1fr" rows="2fr 1fr">` → the container components (geometry from layout-engine helpers). Constraint strings parsed at expansion time into `GridConstraint::Fixed(u16) | Fraction(u16)`.
2. **Built-in tags**: `<Label text>` → `LabelComponent::new(text)`; `<Button label action|onClick>` → `ButtonComponent::new(label, action)`. Small extensible registry in the proc-macro.
3. **Expression braces**: `{ expr }` → owned `Component` value moved in; `{ &mut expr }` → borrowed `&mut Component` field.

## Phase 0 — Unbind `Any` from `Component` (careful, compiler-guided)

Files: `crates/term-wm-core/src/components.rs`, `crates/term-wm-core/src/window/window_manager/mod.rs`, and whatever `cargo check` flags.

1. `components.rs`: `pub trait Component<Msg>: std::any::Any` → `pub trait Component<Msg>`; update the doc comment (Any-bound rationale moves to the WM).
2. **Add a blanket `Component` impl for mutable references** (enabled by step 1; impossible while `: Any` forces `'static`). This is what lets `{ &mut expr }` children work without any macro token-inspection or lifetime-parameterized enums — a borrowed reference *is* a `Component`:

## Phase 1 — Container hardening + new containers (`term-wm-ui-components`)

1. **Fix `VerticalStackComponent::handle_events` key routing** (`vertical_stack.rs`): keep mouse spatial routing unchanged; add focus-gated key routing (route `Event::Key` to child whose `hitbox_id() == ctx.keyboard_focus_id()`, fallback sequential first-non-`Ignored`); route `Paste`/`Focus`/`Resize` to all children (first non-`Ignored`). Extract the shared `route_key`/`route_mouse`/`route_broadcast` helpers into `helpers.rs` (used by all container components). Add tests: multi-child focus isolation (two terminals, only focused gets keys), fallback, mouse routing unchanged.
2. **New `HStackComponent<C>`** (`hstack.rs`): horizontal counterpart of `VerticalStackComponent`; equal-width splits via `split_rects_with_gaps`. **`desired_height` must be stretch-aware**: return `0` (stretch) if *any* child returns `0` — otherwise a fixed-height sibling clamps the whole row and caps the stretching child — else `max` of child heights. Same ctx-rebinding + event routing. Naming per AGENTS.md (`*Component` → `hstack.rs`).
3. **New `GridComponent<C>` + `GridConstraint`** (`grid.rs`): row-major placement; `cols`/`rows: Vec<GridConstraint>` (`Fixed(u16)|Fraction(u16)`); `resolve_sizes` (fixed consume, fractions share remainder via `split_rects_nary`-style math). **`desired_height` must return `0` (stretch) when any row is `Fraction`** (or `rows` is empty → synthesized `Fraction` rows at render) — a plain `sum(fixed_rows)` would make the parent allocate only the fixed total and leave zero space for `Fraction` rows; when all rows are `Fixed`, return their saturated sum. ctx rebinding per cell; focus-gated key routing. Re-export in `lib.rs`.
4. Correctness directives (apply to all containers, matching `vertical_stack.rs`): never pass parent `ctx` to a child — always `ctx.clone().with_screen_area(child_rect)` in render AND event paths; never cache layout (recompute from `ctx.screen_area()`); saturating ops.
5. Unit tests (in-memory `Buffer` + `RatatuiBackend::new_simple`): slicing/stretch/gap, grid constraint math, cell ctx rebinding, focus routing, empty-container compile, **and the stretch-regression cases**: `HStackComponent::desired_height` returns `0` when one child is fixed (`desired_height = 5`) and another stretches (`0`); `GridComponent::desired_height` returns `0` when `rows` contains a `Fraction` (and when `rows` is empty), and equals the fixed sum when all rows are `Fixed`.

## Phase 2 — `term-wm-view` proc-macro crate (new)

`crates/term-wm-view` (`proc-macro = true`), deps `rstml = "0.13"`, `syn = "2"`, `quote`, `proc-macro2` (build-time only, added to `[workspace.dependencies]` + members).

Expansion strategy:
1. `rstml::parse2(input)` → `Vec<Node>`; single root required (else `compile_error!` with span).
2. `Node::Block` (`{ expr }`): **emitted verbatim as a plain Rust expression** — no `&mut` token inspection, no branching. Whether the child is owned (`C: Component`) or borrowed (`&'a mut C: Component` via the Phase-0 blanket impl) is decided purely by the expression's type. The value becomes a field of the sibling enum.
3. `Node::Element`:
   - container tag → recurse into children, build `VerticalStackComponent`/`CenterComponent`/`HStackComponent`/`GridComponent` value (branch on child count);
   - leaf tag → registry constructor call (e.g. `LabelComponent::new(text)`);
   - unknown tag / missing attr → `compile_error!` at the rstml span (precise diagnostics — the DX win over `macro_rules!`).
   - non-whitespace text child → `compile_error!`.
4. **Child-count branches**: 0 children → container typed `::<NoopComponent>` (exists in core); 1 child → pass child directly (no enum); ≥2 children → generate a block-scoped **un-parameterized** generic delegate enum, one type param per child (inferred at construction). No lifetime params, ever — a borrowed child's field is just `&'a mut T`, whose `Component` impl comes from the Phase-0 blanket, so `B` = `&'a mut T` satisfies `B: Component` like any owned type. The enum implements `Component<TermWmAction>` via an inline generated `match self` delegation using **UFCS** (`Component::<TermWmAction>::render(c, …)`), which resolves correctly for both owned fields (`&mut C`) and borrowed fields (`&mut &'a mut T` → blanket impl) while avoiding inherent-`render` shadowing; `#[allow(clippy::large_enum_variant)]`. All-owned trees are `'static` (usable directly in `open_window`); borrowed trees carry the borrow inside a field type and are used via the app-root `impl Component + '_` pattern — the macro emits identical code either way.

```rust
// expansion of: view! { <VerticalStack gap=1><Label text="hi"/>{ &mut self.terminal }</VerticalStack> }
{
    use ::term_wm::LabelComponent;
    use ::term_wm::VerticalStackComponent;
    use ::term_wm::components::Component;
    enum __View0<A, B> { V0(A), V1(B) }
    impl<A: Component<TermWmAction>, B: Component<TermWmAction>>
        Component<TermWmAction> for __View0<A, B>
    {
        fn render(&mut self, b, a, c, r) {
            match self { Self::V0(v) => v.render(b, a, c, r), Self::V1(v) => v.render(b, a, c, r) }
        }
        // handle_events / update / destroy / desired_height / hitbox_id likewise
    }
    let mut __s = VerticalStackComponent::new().with_gap(1);
    __s.add(__View0::V0(LabelComponent::new("hi")));
    __s.add(__View0::V1(&mut self.terminal));  // B = &'a mut TerminalComponent: Component via blanket
    __s
}
```

Block-scoped items ⇒ no cross-invocation name collisions; `__ViewN` counter per expansion; `V0..Vn` positional variants. Fully monomorphized; no `Box`/`dyn`/`Rc`; one `Vec` per container (parity with hand-written `VerticalStackComponent`).

5. **Tag registry**: const table in the macro crate — containers `VerticalStack`/`Column` (gap), `Row`/`HStack` (gap), `Center` (width, height), `Grid` (cols, rows); leaves `Label` (text), `Button` (label, action|onClick). Extensible by appending entries; `{ expr }` covers everything else.
6. **Grid constraint parsing** (compile-time): `cols="200px 1fr"` → `GridConstraint::Fixed(200), GridConstraint::Fraction(1)`; bad token → `compile_error!` at the literal's span. Plain `fn parse_constraint(&str) -> Result<GridConstraint, String>` → unit-testable.
7. **Path resolution — `::term_wm::` umbrella convention**: generated code references `::term_wm::components::Component`, `::term_wm::actions::{EventResult, TermWmAction}`, `::term_wm::components::NoopComponent`, and the container/leaf components via the crate-root glob re-export (`::term_wm::LabelComponent`, `::term_wm::VerticalStackComponent`, …). Rationale: the umbrella crate re-exports `term_wm_core::*` + `term_wm_ui_components::*` (src/lib.rs), and external consumers like `../rust-argtuner` depend on the umbrella crate (not the leaf `term-wm-ui-components` — verified in its Cargo.toml). Since `view!` is re-exported from the umbrella, every consumer necessarily depends on it, so `::term_wm::` resolves under the default crate name. Document the constraint: the `term-wm` dependency must not be renamed in the consumer's Cargo.toml.

## Risks & mitigations

1. **Blast radius of the trait change** — contained: no `dyn Component`/`Box<dyn Component>`/`Any` downcasting anywhere in the workspace or in `../rust-argtuner` (verified). `+ 'static` additions are compiler-driven; external consumer verified via patch-build in P0 before any further work.
2. **`VerticalStackComponent` key-routing change** — focus-gated so unfocused children (and the existing `wm_system_panel` usage) are unaffected; covered by new unit tests + existing `vertical_stack.rs` tests.
3. **rstml 0.13 API surface** — 20-line spike first in P2; fallback: hand-rolled `syn` mini-parser.
4. **Borrowck of `{ &mut self.x }` in `fn view(&mut self) -> impl Component + '_`** — disjoint-field borrow into an ephemeral tree; validate with a compile test in P2 before building further.
5. **Borrowed-variant forwarding** — the Phase-0 blanket impl makes `&'a mut C: Component`, so the generated enum forwards with UFCS (`Component::<TermWmAction>::render(c, …)`), resolving correctly for owned (`&mut C`) and borrowed (`&mut &'a mut C`) fields alike and avoiding inherent-`render` shadowing (AGENTS.md warns against inherent `render`).
6. **Coherence of the `&mut C` blanket impl** — trait is local (term-wm-core); no existing direct `impl Component for &mut _` exists; verified no conflicts across workspace + argtuner patch-build. The blanket requires the `: Any` removal (step 1) so it lands in the same Phase 0 commit.
7. **Inference with deep trees** — keep construction turbofish-free; if needed, annotate the top-level container type. Empty containers use `NoopComponent` (no uninhabited enum).
8. **Scope creep** — `ScrollView` as a tag, `#[component]`-style derive, second `window!`/`tile!` macros: out of scope (follow-ups).

# Phase 5 — Dogfood: the system panel becomes a scrolling `view!` grid

User directive: the framework must be able to build its own internal components with `view!`; a macro the core can't rely on is a toy. `WmSystemPanelComponent` (opened via the `ToggleSystemPanel` keybinding) becomes a **scrolling grid** declared with `view!` + `GridComponent`.

## 5.1 Macro path resolution — `proc_macro_crate` (term-wm-view)

`view!` is re-exported from the `term-wm` umbrella, but `term-wm-sys-ui-components` is a **leaf** crate that the umbrella depends on → it cannot depend on the umbrella (circular). Generated code therefore must reference leaf crates when the consumer has no `term-wm` dep.

- Add `proc-macro-crate = "3"` to `crates/term-wm-view/Cargo.toml` + `[workspace.dependencies]`.
- Resolve the path style **once per expansion** via `proc_macro_crate::crate_name(...)`, using the returned name (renaming-aware), not hardcoded idents. One helper maps a package name to a `::<ident>::` prefix:
  - `crate_name("term-wm")` → `Ok(FoundCrate::Itself)` → umbrella self-alias `::term_wm::`; `Ok(FoundCrate::Name(n))` → `::#n::` (handles a renamed umbrella dep); **otherwise (leaf crate)** → query each leaf package the same way: `comp = crate_path("term-wm-ui-components")`, `core = crate_path("term-wm-core")`, `backend = crate_path("term-wm-render") ++ RenderBackend`. Unknown packages fall back to the canonical `::term_wm_ui_components::` / `::term_wm_core::` / `::term_wm_render::` idents (the compiler then reports a clear unresolved-crate error if a consumer genuinely lacks the dep).
- **Self-aliases so the fallback resolves from within the leaf crates themselves**: add `extern crate self as term_wm_ui_components;` to `crates/term-wm-ui-components/src/lib.rs` (the realistic case — a ui-component using `view!`). `term-wm-core` / `term-wm-render` don't build UI trees, so no aliases there.
- Thread three prefix fragments through the `Generator` (replacing the hardcoded `::term_wm::`): `comp` (component namespace), `core` (core namespace), `backend` (RenderBackend path). All generated paths (`Label`, `Button`, `VerticalStack`/`HStack`/`Center`/`Grid`/`GridConstraint`, `Component`, `TermWmAction`, `ComponentContext`, `Event`, `HitboxId`/`HitboxRegistry`, `WindowKey`, `AppContext`, `SelectionStatus`, `NoopComponent`, `Rect`, `RenderBackend`) become `#comp::` / `#core::` / `#backend` interpolations.
- Keep the umbrella re-exports added in Phase 3 (`src/lib.rs`); they remain valid public API and still serve umbrella consumers.
- Consumers must have `term-wm-core` + `term-wm-ui-components` (+ `term-wm-render`) as direct deps when they use `view!` in a leaf crate; umbrella consumers need only `term-wm`. Document both in macro docs, README, AGENTS.md (update the "must not rename" note — renames now resolve via `crate_name`).

## 5.2 `WmSystemPanelComponent` → scrolling grid view (`wm_system_panel.rs`)

Current shape: `ScrollViewComponent<CanvasScrollView<VerticalStackComponent<PanelChild>>>` where `PanelChild` is a delegate enum over `{ Label, Button, Spacer, KeyMonitor, Separator }`, built from a dynamic `children: Vec<PanelChild>`.

New shape (per the user's directive):

```rust
pub struct WmSystemPanelComponent {
    scroll_view: ScrollViewComponent<CanvasScrollView<PanelContentView>>,
}

struct PanelContentView {                      // nameable, so it can be the scroll content
    key_monitor: KeyMonitorComponent,          // always present; "—" until a key is pressed
}

// Fixed grid row heights from the view! `<Grid rows="1 3 3">` below. Keep in
// sync when editing that attribute. `desired_height` MUST reflect this sum so
// `CanvasScrollView` sizes its scrollable canvas (a 0 default would disable
// scrolling and strand content below the fold).
const PANEL_GRID_HEIGHT: u16 = 1 + 3 + 3;

impl PanelContentView {
    fn view(&mut self) -> impl Component<TermWmAction> + '_ {
        view! {
            <Grid cols="1fr 2fr" rows="1 3 3">
                { &mut self.key_monitor }                 // last-key line
                { SpacerComponent::new(1) }               // fills the second cell
                <Label text="Notifications:" />
                <Button label=" Send Notification " action={TermWmAction::SendNotification("Hello from System Panel!".to_string())} />
                <Label text="Debug utilities:" />
                <Button label=" Trigger Panic " action={TermWmAction::Callback(|| panic!("Manual panic from system panel"))} />
            </Grid>
        }
    }
}
impl Component<TermWmAction> for PanelContentView {
    fn render(&mut self, b, a, c, r) { self.view().render(b, a, c, r); }
    fn handle_events(&mut self, e, c) -> EventResult<TermWmAction> { self.view().handle_events(e, c) }
    fn update(&mut self, a, c, acts) { self.view().update(a, c, acts); }
    fn destroy(&mut self) { self.view().destroy(); }
    // NOTE: `desired_height` cannot forward to `self.view()` — view() needs
    // `&mut self` (for `{ &mut self.key_monitor }`) but desired_height is
    // `&self`. Report the static grid height instead.
    fn desired_height(&self, _width: u16) -> u16 { PANEL_GRID_HEIGHT }
    // selection_* default (no selectable content)
}
```

> **Status: IMPLEMENTED & VERIFIED** — the responsive reflow (`grid_reflows`, `FRACTION_COL_MIN_WIDTH`, stretch-aware reflowed `row_heights`/`desired_height`, area-based `render`), the panel restructure (`<VerticalStack>{ key monitor }<Grid cols="16 1fr" rows="3 3">…</Grid></VerticalStack>`, consts 7/9), the 7 new unit/regression tests, docs, and the width-sweep + click-routing + clippy + 59-target + argtuner verification are all done and green. ## Status / scope of uncommitted work

Phases 0–5 are committed (`3e6d0f99 Prototype view! tree integration in System Panel`). The **only uncommitted changes** are the responsive-reflow fix below, touching 3 files:
`crates/term-wm-ui-components/src/grid.rs`, `crates/term-wm-ui-components/src/lib.rs`, `crates/term-wm-sys-ui-components/src/wm_system_panel.rs`.

## The bug (user report)

> If you make the component really small, the layout doesn't adjust accordingly — the buttons just write over their labels and shrink down to a point. Try making the width really narrow.

## Diagnosis (reproduced via a headless render dump at widths 30/20/12/8/4)

`GridComponent` split `cols="1fr 2fr"` purely by weight. At narrow widths `resolve_sizes` collapses the `1fr` label column to 1–2 cols, so the label truncates to `No`/`N` and the button sits flush against it (`N╭─╮`) — the "write over their labels" look — and both shrink to a point. No adaptivity.

## The fix (approach; implementation must incorporate the review amendments below)

**`GridComponent` gains responsive reflow** (`grid.rs`): a multi-column grid reflows to a single stacked column when the available width can't fit the columns' minimums.
- `pub const FRACTION_COL_MIN_WIDTH: u16 = 10` — the floor given to each `Fraction` column before reflow.
- `fn min_total_width(cols)` — `Fixed(n)` → `n`, `Fraction(_)` → `FRACTION_COL_MIN_WIDTH`, summed.
- `pub fn grid_reflows(cols, width)` — `cols.len() > 1 && width < min_total_width(cols)` (shared so a scroll-content wrapper can report the same adaptive height).
- Reflowed layout: 1 full-width column; one row per child sized by `child.desired_height(width).max(1)`; reflowed `desired_height` = sum of child heights (each `.max(1)`). `render`/`handle_events`/`desired_height` all use the reflow-aware geometry.

**The System Panel adapts** (`wm_system_panel.rs`): restructured so the key monitor is a full-width row and only the label/button pairs live in the grid:
```
<VerticalStack>
    { &mut self.key_monitor }                     // full-width row (h 1)
    <Grid cols="16 1fr" rows="3 3">               // reflows to a stack when narrow
        <Label text="Notifications:" /> <Button label=" Send Notification " action=.. />
        <Label text="Debug utilities:" /> <Button label=" Trigger Panic " action=.. />
    </Grid>
</VerticalStack>
```
- `cols="16 1fr"` (`PANEL_COLS = [Fixed(16), Fraction(1)]`) — a fixed 16-col label column fits "Debug utilities:" when wide, so labels never truncate.
- **No spacer child** — the 2-col grid has no empty second cell to fill, so reflow produces no spurious blank rows (SEV-2).
- `desired_height(width)` is reflow-aware: `grid_reflows(&PANEL_COLS, width)` → `PANEL_GRID_HEIGHT_STACKED` (9 = 1 key monitor + 1+3+1+3 stacked grid) else `PANEL_GRID_HEIGHT` (7 = 1 + 3+3), keeping the scroll canvas correct in both layouts.

**Re-exports** (`lib.rs`): `grid_reflows`, `FRACTION_COL_MIN_WIDTH` added to the crate-root re-export.

## Phase 6 review amendments (apply with the implementation)

1. **SEV-1 (render/event reflow desync)** — resolved by contract, NOT by overriding `render`'s bounds. `render` MUST drive all geometry from `area` (the locally-allocated rect): using `ctx.screen_area()` there would draw past the allocated buffer (overflow into neighbors on a sidebar/pane where `area.width < screen_area.width`). `handle_events` keeps using `ctx.screen_area()` (events are screen-space). The two agree because parent containers rebind each child's context (`ctx.with_screen_area(child_screen_rect)`) in both paths; the panel's chain (`CanvasScrollView` + `VerticalStack`) already does this, so the grid's `area.width == screen_area.width`. (Reverts the earlier "render uses screen dims" idea; that was wrong.) No `GridComponent` code change beyond the original area-based render.
2. **SEV-1b (static stacked height vs. wrapping)** — general grids can contain wrapped/multi-line children; the grid's reflowed `desired_height` is dynamic (sums child heights). The **panel's** children are constant-height (`LabelComponent` = 1, `ButtonComponent` = 3, `KeyMonitorComponent` = 1 — verified: they truncate, never wrap), so `PANEL_GRID_HEIGHT_STACKED` is exact; document that caveat.
3. **SEV-2 (spacer row in reflow)** — fixed by the panel restructure (`<VerticalStack>{ key monitor }<Grid cols="16 1fr" rows="3 3">…</Grid></VerticalStack>`, no spacer; key monitor is a full-width row).
4. **SEV-2-new (stretch collapse in reflow)** — a reflowed grid must not clamp `desired_height == 0` children to 1 row nor report a fixed height that suppresses stretch:
   - `row_heights(width, height)` reflowed: non-stretch children keep `desired_height`; stretch children (0) split the remaining vertical space (`height − fixed_total`) equally (floored at 1).
   - `desired_height(width)` reflowed: if any child returns `0` (stretch) → return `0` (stretch propagates up); else sum of child heights.

## Remaining implementation steps (after approval)

1. Apply the amendments to the working tree (`grid.rs`, `wm_system_panel.rs`):
   - keep `render` area-based (no change needed);
   - add stretch handling to reflowed `row_heights`/`desired_height`;
   - restructure the panel to `<VerticalStack>{ key monitor }<Grid cols="16 1fr" rows="3 3">…</Grid></VerticalStack>`; consts `PANEL_GRID_HEIGHT` = 7, `PANEL_GRID_HEIGHT_STACKED` = 9.
2. **Add unit tests** in `grid.rs`:

   - **containment**: rendering with `area.width = 30` while `ctx.screen_area().width = 120` keeps every cell within the 30-column area (no overflow);
   - wide grid does not reflow (existing tests still pass); `grid_reflows` truth table.

## Why this design (vs. alternatives)

- **Grid reflow, default-on** — matches "the view should adapt": a multi-column grid degrades to a readable stack when it can't fit. Opinionated but documented; `GridComponent` is new (no external users beyond the panel/demo), so no existing behavior is silently changed for consumers.

## 7.1 `BoxComponent<C>` — `crates/term-wm-ui-components/src/box.rs` (new)

```rust
pub struct BoxComponent<C: Component<TermWmAction>> {
    content: C,
    title: Option<String>,
    padding: u16,
    border: bool,                  // default true — draw the border
    border_color: Color,           // term_wm_core::theme::Color, default DarkGray
}
impl<C: Component<TermWmAction>> BoxComponent<C> {
    pub fn new(content: C) -> Self;
    pub fn with_title(mut self, title: impl Into<String>) -> Self;
    pub fn with_padding(mut self, padding: u16) -> Self;
    pub fn with_border(mut self, border: bool) -> Self;
    pub fn with_border_color(mut self, color: Color) -> Self;   // theme::Color
}
```

**Implementation notes & edge cases** (mirror the `ButtonComponent` render pattern — `layout_rect_to_clipped_rect` + `downcast_ratatui` + one `Paragraph` per row):

- **`border: bool` (default true)**: when `false`, no border is drawn and the border's spatial overhead is 0 — `inner_rect` and `desired_height` use `border_inset = if self.border { 1 } else { 0 }` per side. A `title` renders only when `border == true` (a floating title without a border is meaningless).
- **`inner_rect(area)`**: `inset = border_inset + padding`; returns `{ x: area.x+inset, y: area.y+inset, width: area.width − 2·inset, height: area.height − 2·inset }` with saturating arithmetic. Recompute per call from `area` (render) and `ctx.screen_area()` (events) — never cached.
- **`border_color: term_wm_core::theme::Color`** — converted at render via `crate::helpers::color_to_ratatui`. view! consumers never import ratatui (`border_color={term_wm::theme::Color::Cyan}`).
- **`render`**: if `area.width < 2 || area.height < 2` → return. When `border`, draw with `inner_w = area.width − 2`:
  - top row: with title → `╭─ {title} ─…╮`; without → `╭{dashes}╮`.
  - middle rows (`y` in `1..area.height−1`): `│{spaces}│`.
  - bottom row: `╰{dashes}╯`.
  **UTF-8-safe title**: compute `title_width = unicode_width::UnicodeWidthStr::width(title)`; when it exceeds `inner_w.saturating_sub(3)`, truncate by accumulating `unicode_width::UnicodeWidthChar::width` per char and taking chars (`chars().take(...)`) — never byte-slicing, so multi-byte/wide characters can't panic or overflow the row; dash fill = `"─".repeat((inner_w − title_width − 3).saturating)`.
  Content renders into `inner_rect(area)` (local) with `child_ctx = ctx.clone().with_screen_area(inner_rect(screen_area))`.
- **`desired_height(width)`**: `inner_w = width − 2·border_inset − 2·padding`; `content_h = content.desired_height(inner_w)`; if `content_h == 0` → return `0` (stretch propagates); else `2·border_inset + 2·padding + content_h`.
- **`handle_events`**:
  - mouse **Down only**: if the cursor is inside `inner_rect(ctx.screen_area())` → forward with `child_ctx = ctx.clone().with_screen_area(inner)`; else `Ignored` (a Down on the border/padding starts nothing).
  - **all other mouse kinds (`Drag`, `Up`, `Moved`, `Scroll*`) forward unconditionally** — so an in-progress drag isn't dropped when the cursor crosses the border, and the release reaches the child that started it.
  - keys and other events → forward to content with `ctx` (focus-based, no geometry — same as `CenterComponent`).
- `update`/`destroy`/`clear_selection`/`selection_status`/`selection_text`/`take_pending_title`/`take_alternate_screen_transition`/`take_teardown_parts`/`set_selection_enabled`/`paste` all forward to `content`; `hitbox_id` forwards to content.
- Directives: saturating arithmetic; `render` geometry strictly from `area`; no `Cell<Rect>` caching.
- **Module naming (pinned)**: `mod r#box;` in `crates/term-wm-ui-components/src/lib.rs` (raw identifier — `box` is a reserved keyword) loads `src/box.rs`; `pub use r#box::BoxComponent;`. Consumers only ever see the re-export; the `view!` macro emits `::term_wm_ui_components::BoxComponent`. No fallback.

# Phase 8 — Fix `view_demo` bugs + apply `impl_view_component!`

Two real bugs in `examples/view_demo.rs`, both diagnosed from running the demo under a pty and a headless render.

## Bug A — the Quit button never renders (and the Center must still center)

**Root cause (confirmed by headless render + user observation):** `VerticalStackComponent`'s layout (`child_layouts`, vertical_stack.rs:71-99) **breaks at the first stretch child** (`desired_height == 0`), allocating it all remaining rows and never rendering trailing siblings. `CenterComponent` reports `0` (stretch) by default, so `<Center>` in the demo swallowed the stack and the `Button` after it never rendered.

**Correct fix (amended after the user observed that clamping the Center killed centering):**
1. `crates/term-wm-ui-components/src/vertical_stack.rs` — fix the stack to handle **middle stretch children**:
   - `desired_height`: return `0` if *any* child returns `0` (stretch propagates, consistent with `HStackComponent`/`GridComponent`); else sum + gaps.
   - `child_layouts` (shared by render + handle_events): first pass sums fixed (non-zero) child heights + gaps; remaining space is split among stretch children (`remaining / stretch_count`, floor 1); render every child in order — fixed children keep their heights, stretch children take their share, and **trailing siblings still render**.
2. `crates/term-wm-ui-components/src/center.rs` — **revert the `desired_height` clamp** (keep an explicit `0` = stretch): a Center must stretch to fill its allocated region so it can *visibly center* its `width`×`height` content within it. (The earlier "return `self.size.1`" fix stopped the button bug but destroyed centering — the stack fix is the correct fix, keeping both.)
- Tests: a stack `[Label(1), stretch, Button(3)]` renders all three (button at the bottom, stretch child in the middle); `desired_height == 0` when any child stretches; `CenterComponent::desired_height == 0` and `inner_rect` still centers.
- Demo note: `<Center width=80 height=12>` now fills the window between the header and the button and centers the 80×12 content within it (visible top/bottom + horizontal margins when the window is wider than 80).

## Bug B — typing errors on direct-mode transitions (`status_cb is NONE`)

**Root cause (from the pty-captured logs):** the demo hosts a live `TerminalComponent` inside a `Custom` window but never wires it:
1. **No `DirectInputTracker`** — `set_window_tracker` is never called (only `spawn_terminal_window` does), so `WindowManager::direct_mode` defaults to `false` and the WM doesn't adapt when the app enters alt-screen/direct mode.
2. **No PTY status callback** — `wire_pty_callback` only matches `CoreWmComponent::Terminal`, so the demo's custom-window terminal has a `None` status callback. On every `DirectInputChanged` transition, `crates/term-wm-pty-engine/src/pty.rs` logs `[STAGE 1] status_cb is NONE when transition occurred!` at `tracing::error!`, and `PtyWakeup` is never delivered — terminal output never wakes the render loop ("something is blocking").

**Fixes (per review: keep the error, close the API gap — do NOT downgrade or bypass `run()`):**
1. `crates/term-wm-pty-engine/src/pty.rs` — **keep** `[STAGE 1] status_cb is NONE…` at `tracing::error!`. An un-wired live PTY reader is a broken event pipeline (wakeups dropped → UI freezes), so it must stay loud. The fix is to *wire* the terminal, not silence the log.
2. `src/term_wm_app.rs` — **add a high-level launch hook that encapsulates the PTY wiring** (no `Sender<UnifiedEvent>` / `UnifiedEvent` leaks into consumer code):
   ```rust
   /// Opaque launch context: consumers wire terminals here without touching
   /// the engine's event channel.
   pub struct AppSetupContext<'a> {
       tx: &'a crossbeam_channel::Sender<UnifiedEvent>,
   }
   impl AppSetupContext<'_> {
       /// Wire a terminal's PTY status events (wakeup / exit / direct-input
       /// transition) into the live event loop. Call after `open_window`.
       pub fn wire_terminal(&self, terminal: &mut TerminalComponent, key: WindowKey);
   }

   pub fn run_with_setup<F>(mut self, setup: F) -> io::Result<()>
   where F: FnOnce(&mut TermWmApp<C>, &AppSetupContext<'_>)
   ```
   `run_with_setup` mirrors `run()` (create `ConsoleRenderTarget` + `UnifiedEventSource`, point `pty_wakeup_tx` at the source's channel, `rewire_terminal_callbacks` for `CoreWmComponent::Terminal`), then builds an `AppSetupContext` and calls `setup(&mut self, &ctx)` before the loop. `AppSetupContext::wire_terminal` internally builds the `Box::new(move |status| match status { PtyStatus::Wakeup => send PtyWakeup(key), Exited => send AppExited(key), DirectInputChanged(mode) => send DirectInputChanged(key, mode) })` and passes it to `TerminalComponent::set_pty_callback`. `run()` becomes `self.run_with_setup(|_, _| {})` (no behavior change).
3. `examples/view_demo.rs` — stay on the high-level runner via `app.run_with_setup(...)`:
   - capture `let tracker = pty.direct_input_tracker();` before wrapping; after `open_window`, `app.wm().set_window_tracker(key, tracker);`
   - in the setup closure, reach the terminal via `app.wm().component_for_key_mut(key)` → `MyWindow.terminal.content.borrow_mut()` and call `ctx.wire_terminal(&mut *term, key)` — no `PtyStatus`/`UnifiedEvent` mapping in the demo.

## Phase 8 review amendments
1. **Keep the `status_cb is NONE` error at `error!`** — an un-wired live PTY drops wakeups and freezes the UI; it must stay loud. The fix is wiring, not log suppression.
2. **`TermWmApp::run_with_setup` + opaque `AppSetupContext`** — the launch hook exposes `&AppSetupContext`, NOT the `Sender<UnifiedEvent>` / `UnifiedEvent` (internal engine plumbing stays encapsulated). `AppSetupContext::wire_terminal(&mut TerminalComponent, key)` performs the `PtyStatus → UnifiedEvent` translation internally, so consumer code (and the demo) never hand-roll PTY status closures. Consumers stay on the high-level `run()` path.
3. **Center / stack fix (amended after user observed the clamped Center no longer centers)** — `CenterComponent` keeps `desired_height == 0` (stretch); the **`VerticalStackComponent` middle-stretch fix** is what bounds the Center's region *while still rendering trailing siblings* (the button). The earlier "Center reports `size.1`" directive is withdrawn — it traded the button bug for a no-op Center.
