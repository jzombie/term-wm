# Plan: A "dumb" `view!` macro — unified on a single `Component` trait (zero-cost)

## Goal

A declarative `view!` macro (JSX/RSX) that builds component trees — "dumb" (no reactivity, no reconciliation, no runtime tree) and zero-cost (fully-monomorphized code a developer could hand-write). The tree IS a genuine `Component`, so the macro plugs directly into the existing component system.

## Architectural pivot (post-review)

The previous plan introduced a parallel `View` trait (because `Component<Msg>: Any` forbids non-`'static` trees that borrow `{ &mut self.x }`). Review verdict AMEND: that creates a split-brain (two trait hierarchies, duplicate containers, behavioral drift). Resolution — **unify on `Component` and delete the `View` idea entirely**:

1. **Remove `: std::any::Any` from `pub trait Component<Msg>`** (`crates/term-wm-core/src/components.rs:35`). The `'static`/`Any` requirement moves to the WindowManager boundary: `WindowManager<C: Component<TermWmAction> + 'static, L, O>` (`mod.rs:296`). `L`/`O` already keep `'static` implicitly via their own `as_any_mut -> &mut dyn Any` methods. No method signatures change; this is a **bound relocation only**.
2. **`view!` emits `Component`s**: leaf tags → component constructors; `{ expr }` / `{ &mut expr }` → owned components / `&mut` references; containers → the existing `VerticalStackComponent`/`CenterComponent` + two new `HStackComponent`/`GridComponent`; heterogeneous siblings → generated per-invocation delegate enums implementing `Component` (the established `impl_component_delegate!` pattern).
3. **Delete** the `View` trait, `LeafView`, `BorrowedView`, `ViewComponent`, `NoopView`, `VStackView`, `HStackView`, `CenterView`, `GridView`, and the whole `view.rs` scaffolding from the earlier plan (none of it was committed — nothing to unwind beyond files I created locally: `crates/term-wm-core/src/view.rs`, `crates/term-wm-ui-components/src/view.rs`, plus lib.rs edits).
4. **Fix the behavioral drift** the review flagged: `VerticalStackComponent::handle_events` drops key events; give it focus-gated key routing (identical semantics to the shared helpers) so a terminal inside a `view!` stack receives keys. This is a strictly-improving, focus-gated change (unfocused children still get nothing → existing `wm_system_panel.rs` usage unaffected).

### External compatibility (verified)

`../rust-argtuner` (real consumer, deps on term-wm 0.9.24): implements `Component` for its own `ChartsView` (a `'static` type), uses `impl_component_delegate!(AppComponent { .. })`, `AppRootComponent::Custom(..)`, and `component_for_key_mut` + enum pattern matching. **No `Any` downcasting of components.** So removing `: Any` is fully backward-compatible for it. The explicit `+ 'static` on `WindowManager<C>` is satisfied by every existing consumer.

## Context: relevant component-system facts

- `Component<Msg>` (components.rs:35): lifecycle `init`/`on_mount`/`hitbox_id`/`handle_events`/`update`/`render(&mut self, &mut dyn RenderBackend, Rect, &ComponentContext, &mut HitboxRegistry)`/`destroy`/`desired_height`/selection/paste. Default `handle_events` already self-filters keys by `ctx.keyboard_focus_id()` (components.rs:94-101).
- `ComponentContext` (component_context.rs:32): immutable, builder-style; `screen_area()`, `with_screen_area(rect)`, `keyboard_focus_id()`, `with_keyboard_focus_id`, `active_hitbox()`, `scroll_handle()`, `with_window_key`. WM sets `screen_area` + `keyboard_focus_id` per frame (`mod.rs:1156-1170`).
- Containers generic over one child type `C: Component<TermWmAction>`: `VerticalStackComponent<C>` (`vertical_stack.rs:18`, `Vec<C>`, `.new()/.with_gap(u16)/.add(C)`, slices stripes by `desired_height`, 0 = stretch; **ignores key events today**), `CenterComponent<C>` (single child + size; forwards all events). `ScrollViewComponent<C>` is stateful — intentionally NOT a `view!` tag; injected via `{ &mut self.sv }`.
- `ButtonComponent` (`button.rs:104`) routes clicks by `ctx.localize_mouse_click` (screen-area), no hitbox identity → safe to reconstruct per frame. Stateful widgets (terminal/list/scroll) use hitbox ids + cross-frame state → must be app-owned and injected by `{ &mut ... }`.
- Delegate enums: `impl_component_delegate!` (`macros.rs:9`) generates full `Component` `match self` delegation; used by `AppRootComponent<C>` (`src/components.rs:9`), `CoreWmComponent`, `LayerComponent`, `OverlayComponent`. No `Any` references in the macro.
- Layout engine: `split_rects_nary`, `split_rects_with_gaps(area, orientation, weights, n, gap)`, `build_rects_from_sizes` (all re-exported from `split.rs`), `Orientation`, `LayoutRect{x:i32,y:i32,width:u16,height:u16}` — saturating ops required (AGENTS.md).
- Consumer entry: `TermWmApp<C>::new_custom(...)` → `open_window(AppRootComponent::Custom(comp))` (`examples/dual_image.rs`). Root crate re-exports `term_wm_core::*` + `term_wm_ui_components::*`. Edition 2024. `syn`/`quote`/`proc-macro2` in lockfile; `rstml` 0.13 (maintained, MIT) not yet.

## Syntax

```rust
fn view(&mut self) -> impl Component<TermWmAction> + '_ {
    view! {
        <VerticalStack gap=1>
            <Label text="System Status" />
            <Button label="Refresh" action={TermWmAction::OpenCommandPalette} />
            <Center width=60 height=8> { &mut self.terminal } </Center>
            { &mut self.scroll_view }
            { build_owned_widget(&self.state) }
        </VerticalStack>
    }
}
```

Two integration patterns:
1. **All-owned view** (no `&mut` blocks) → the `view!` value is a `'static` `Component` → `app.open_window(AppRootComponent::Custom(view!{ .. }))` directly. No wrapper type.
2. **Borrowed view** (has `{ &mut self.x }`) → app implements `Component` for its (owned) window struct and forwards lifecycle calls to a per-frame `fn view(&mut self) -> impl Component<TermWmAction> + '_` (see canonical usage below). The `'_`-returning `Component` is now legal because the trait no longer demands `'static`.

State rule (the honest "dumb" compromise): ephemeral tags must be stateless (Label, Button, layout containers); stateful components are app-owned and injected by reference (`{ &mut self.terminal }`). `ScrollView` is not a tag.

Three tiers, all resolved at compile time:
1. **Layout-primitive tags**: `<VerticalStack gap>`/`<Column>`, `<Row>`/`<HStack>`, `<Center width height>`, `<Grid cols="200px 1fr" rows="2fr 1fr">` → the container components (geometry from layout-engine helpers). Constraint strings parsed at expansion time into `GridConstraint::Fixed(u16) | Fraction(u16)`.
2. **Built-in tags**: `<Label text>` → `LabelComponent::new(text)`; `<Button label action|onClick>` → `ButtonComponent::new(label, action)`. Small extensible registry in the proc-macro.
3. **Expression braces**: `{ expr }` → owned `Component` value moved in; `{ &mut expr }` → borrowed `&mut Component` field.

## Phase 0 — Unbind `Any` from `Component` (careful, compiler-guided)

Files: `crates/term-wm-core/src/components.rs`, `crates/term-wm-core/src/window/window_manager/mod.rs`, and whatever `cargo check` flags.

1. `components.rs`: `pub trait Component<Msg>: std::any::Any` → `pub trait Component<Msg>`; update the doc comment (Any-bound rationale moves to the WM).
2. **Add a blanket `Component` impl for mutable references** (enabled by step 1; impossible while `: Any` forces `'static`). This is what lets `{ &mut expr }` children work without any macro token-inspection or lifetime-parameterized enums — a borrowed reference *is* a `Component`:
   ```rust
   impl<'a, Msg, C: Component<Msg> + ?Sized> Component<Msg> for &'a mut C {
       fn init(&mut self) { (**self).init() }
       fn on_mount(&mut self, key: WindowKey, app: &AppContext) { (**self).on_mount(key, app) }
       fn hitbox_id(&self) -> Option<HitboxId> { (**self).hitbox_id() }
       fn handle_events(&mut self, e: &Event, ctx: &ComponentContext) -> EventResult<Msg> { (**self).handle_events(e, ctx) }
       fn update(&mut self, a: Msg, ctx: &ComponentContext, acts: &mut VecDeque<(WindowKey, Msg)>) { (**self).update(a, ctx, acts) }
       fn render(&mut self, b: &mut dyn RenderBackend, area: Rect, ctx: &ComponentContext, r: &mut HitboxRegistry) { (**self).render(b, area, ctx, r) }
       fn destroy(&mut self) { (**self).destroy() }
       fn clear_selection(&mut self) { (**self).clear_selection() }
       fn selection_status(&self) -> SelectionStatus { (**self).selection_status() }
       fn selection_text(&self) -> Option<String> { (**self).selection_text() }
       fn desired_height(&self, w: u16) -> u16 { (**self).desired_height(w) }
       fn take_pending_title(&mut self) -> Option<String> { (**self).take_pending_title() }
       fn take_alternate_screen_transition(&mut self) -> Option<bool> { (**self).take_alternate_screen_transition() }
       fn take_teardown_parts(&mut self) -> Option<(Box<dyn Any + Send + Sync>, JoinHandle<()>)> { (**self).take_teardown_parts() }
       fn set_selection_enabled(&mut self, e: bool) { (**self).set_selection_enabled(e) }
       fn paste(&mut self, t: &str) -> bool { (**self).paste(t) }
   }
   ```
   Forwarding uses `(**self)` (place, auto-reborrowed) which works for `C: ?Sized`; match the **actual** `Component` method signatures in components.rs (the method set above), not illustrative ones.
3. `mod.rs`: struct + impl blocks `WindowManager<C: Component<TermWmAction>, ...>` → `WindowManager<C: Component<TermWmAction> + 'static, ...>`. (`L`/`O` unchanged — their `as_any_mut` methods already pin `'static`.)
4. Sweep: `cargo check --workspace --all-targets --all-features`; add `+ 'static` wherever the compiler demands (likely `AppBuilder::build<C,O>` at `config.rs:131`, `TermWmApp<C>` impl bounds `term_wm_app.rs:116`, `render_app` in `src/lib.rs`, test helpers). These are storage sites that already require `'static` in practice — mechanical additions.
5. Confirm `impl_component_delegate!` needs no change (verified: no `Any` usage).

## Phase 1 — Container hardening + new containers (`term-wm-ui-components`)

1. **Fix `VerticalStackComponent::handle_events` key routing** (`vertical_stack.rs`): keep mouse spatial routing unchanged; add focus-gated key routing (route `Event::Key` to child whose `hitbox_id() == ctx.keyboard_focus_id()`, fallback sequential first-non-`Ignored`); route `Paste`/`Focus`/`Resize` to all children (first non-`Ignored`). Extract the shared `route_key`/`route_mouse`/`route_broadcast` helpers into `helpers.rs` (used by all container components). Add tests: multi-child focus isolation (two terminals, only focused gets keys), fallback, mouse routing unchanged.
2. **New `HStackComponent<C>`** (`hstack.rs`): horizontal counterpart of `VerticalStackComponent`; equal-width splits via `split_rects_with_gaps`. **`desired_height` must be stretch-aware**: return `0` (stretch) if *any* child returns `0` — otherwise a fixed-height sibling clamps the whole row and caps the stretching child — else `max` of child heights. Same ctx-rebinding + event routing. Naming per AGENTS.md (`*Component` → `hstack.rs`).
3. **New `GridComponent<C>` + `GridConstraint`** (`grid.rs`): row-major placement; `cols`/`rows: Vec<GridConstraint>` (`Fixed(u16)|Fraction(u16)`); `resolve_sizes` (fixed consume, fractions share remainder via `split_rects_nary`-style math). **`desired_height` must return `0` (stretch) when any row is `Fraction`** (or `rows` is empty → synthesized `Fraction` rows at render) — a plain `sum(fixed_rows)` would make the parent allocate only the fixed total and leave zero space for `Fraction` rows; when all rows are `Fixed`, return their saturated sum. ctx rebinding per cell; focus-gated key routing. Re-export in `lib.rs`.
4. Correctness directives (apply to all containers, matching `vertical_stack.rs`): never pass parent `ctx` to a child — always `ctx.clone().with_screen_area(child_rect)` in render AND event paths; never cache layout (recompute from `ctx.screen_area()`); saturating ops.
5. Unit tests (in-memory `Buffer` + `RatatuiBackend::new_simple`): slicing/stretch/gap, grid constraint math, cell ctx rebinding, focus routing, empty-container compile, **and the stretch-regression cases**: `HStackComponent::desired_height` returns `0` when one child is fixed (`desired_height = 5`) and another stretches (`0`); `GridComponent::desired_height` returns `0` when `rows` contains a `Fraction` (and when `rows` is empty), and equals the fixed sum when all rows are `Fixed`.

## Phase 2 — `term-wm-view` proc-macro crate (new)

`crates/term-wm-view` (`proc-macro = true`), deps `rstml = "0.13"`, `syn = "2"`, `quote`, `proc-macro2` (build-time only, added to `[workspace.dependencies]` + members).

Expansion strategy:
1. `rstml::parse2(input)` → `Vec<Node>`; single root required (else `compile_error!` with span).
2. `Node::Block` (`{ expr }`): **emitted verbatim as a plain Rust expression** — no `&mut` token inspection, no branching. Whether the child is owned (`C: Component`) or borrowed (`&'a mut C: Component` via the Phase-0 blanket impl) is decided purely by the expression's type. The value becomes a field of the sibling enum.
3. `Node::Element`:
   - container tag → recurse into children, build `VerticalStackComponent`/`CenterComponent`/`HStackComponent`/`GridComponent` value (branch on child count);
   - leaf tag → registry constructor call (e.g. `LabelComponent::new(text)`);
   - unknown tag / missing attr → `compile_error!` at the rstml span (precise diagnostics — the DX win over `macro_rules!`).
   - non-whitespace text child → `compile_error!`.
4. **Child-count branches**: 0 children → container typed `::<NoopComponent>` (exists in core); 1 child → pass child directly (no enum); ≥2 children → generate a block-scoped **un-parameterized** generic delegate enum, one type param per child (inferred at construction). No lifetime params, ever — a borrowed child's field is just `&'a mut T`, whose `Component` impl comes from the Phase-0 blanket, so `B` = `&'a mut T` satisfies `B: Component` like any owned type. The enum implements `Component<TermWmAction>` via an inline generated `match self` delegation using **UFCS** (`Component::<TermWmAction>::render(c, …)`), which resolves correctly for both owned fields (`&mut C`) and borrowed fields (`&mut &'a mut T` → blanket impl) while avoiding inherent-`render` shadowing; `#[allow(clippy::large_enum_variant)]`. All-owned trees are `'static` (usable directly in `open_window`); borrowed trees carry the borrow inside a field type and are used via the app-root `impl Component + '_` pattern — the macro emits identical code either way.

```rust
// expansion of: view! { <VerticalStack gap=1><Label text="hi"/>{ &mut self.terminal }</VerticalStack> }
{
    use ::term_wm::LabelComponent;
    use ::term_wm::VerticalStackComponent;
    use ::term_wm::components::Component;
    enum __View0<A, B> { V0(A), V1(B) }
    impl<A: Component<TermWmAction>, B: Component<TermWmAction>>
        Component<TermWmAction> for __View0<A, B>
    {
        fn render(&mut self, b, a, c, r) {
            match self { Self::V0(v) => v.render(b, a, c, r), Self::V1(v) => v.render(b, a, c, r) }
        }
        // handle_events / update / destroy / desired_height / hitbox_id likewise
    }
    let mut __s = VerticalStackComponent::new().with_gap(1);
    __s.add(__View0::V0(LabelComponent::new("hi")));
    __s.add(__View0::V1(&mut self.terminal));  // B = &'a mut TerminalComponent: Component via blanket
    __s
}
```

Block-scoped items ⇒ no cross-invocation name collisions; `__ViewN` counter per expansion; `V0..Vn` positional variants. Fully monomorphized; no `Box`/`dyn`/`Rc`; one `Vec` per container (parity with hand-written `VerticalStackComponent`).

5. **Tag registry**: const table in the macro crate — containers `VerticalStack`/`Column` (gap), `Row`/`HStack` (gap), `Center` (width, height), `Grid` (cols, rows); leaves `Label` (text), `Button` (label, action|onClick). Extensible by appending entries; `{ expr }` covers everything else.
6. **Grid constraint parsing** (compile-time): `cols="200px 1fr"` → `GridConstraint::Fixed(200), GridConstraint::Fraction(1)`; bad token → `compile_error!` at the literal's span. Plain `fn parse_constraint(&str) -> Result<GridConstraint, String>` → unit-testable.
7. **Path resolution — `::term_wm::` umbrella convention**: generated code references `::term_wm::components::Component`, `::term_wm::actions::{EventResult, TermWmAction}`, `::term_wm::components::NoopComponent`, and the container/leaf components via the crate-root glob re-export (`::term_wm::LabelComponent`, `::term_wm::VerticalStackComponent`, …). Rationale: the umbrella crate re-exports `term_wm_core::*` + `term_wm_ui_components::*` (src/lib.rs), and external consumers like `../rust-argtuner` depend on the umbrella crate (not the leaf `term-wm-ui-components` — verified in its Cargo.toml). Since `view!` is re-exported from the umbrella, every consumer necessarily depends on it, so `::term_wm::` resolves under the default crate name. Document the constraint: the `term-wm` dependency must not be renamed in the consumer's Cargo.toml.

## Risks & mitigations

1. **Blast radius of the trait change** — contained: no `dyn Component`/`Box<dyn Component>`/`Any` downcasting anywhere in the workspace or in `../rust-argtuner` (verified). `+ 'static` additions are compiler-driven; external consumer verified via patch-build in P0 before any further work.
2. **`VerticalStackComponent` key-routing change** — focus-gated so unfocused children (and the existing `wm_system_panel` usage) are unaffected; covered by new unit tests + existing `vertical_stack.rs` tests.
3. **rstml 0.13 API surface** — 20-line spike first in P2; fallback: hand-rolled `syn` mini-parser.
4. **Borrowck of `{ &mut self.x }` in `fn view(&mut self) -> impl Component + '_`** — disjoint-field borrow into an ephemeral tree; validate with a compile test in P2 before building further.
5. **Borrowed-variant forwarding** — the Phase-0 blanket impl makes `&'a mut C: Component`, so the generated enum forwards with UFCS (`Component::<TermWmAction>::render(c, …)`), resolving correctly for owned (`&mut C`) and borrowed (`&mut &'a mut C`) fields alike and avoiding inherent-`render` shadowing (AGENTS.md warns against inherent `render`).
6. **Coherence of the `&mut C` blanket impl** — trait is local (term-wm-core); no existing direct `impl Component for &mut _` exists; verified no conflicts across workspace + argtuner patch-build. The blanket requires the `: Any` removal (step 1) so it lands in the same Phase 0 commit.
7. **Inference with deep trees** — keep construction turbofish-free; if needed, annotate the top-level container type. Empty containers use `NoopComponent` (no uninhabited enum).
8. **Scope creep** — `ScrollView` as a tag, `#[component]`-style derive, second `window!`/`tile!` macros: out of scope (follow-ups).
