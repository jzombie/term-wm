# Plan: A "dumb" `view!` macro for the term-wm component system (zero-cost)

## Goal

Implement a declarative `view!` macro (JSX/RSX syntax) that builds component trees for term-wm — "dumb" (no reactivity, no reconciliation, no hooks, no runtime tree) and zero-cost (expands to fully-monomorphized, allocation-free-at-rest code that a developer could hand-write). Plugs into the existing component system. This addresses issue #241 (declarative layering) as the first slice of #131's "declarative macro helpers".

## Context: what we discovered about the component system

- `Component<Msg>` (`crates/term-wm-core/src/components.rs:35`) requires `std::any::Any`, i.e. **only `'static` types can implement it**. This is the load-bearing constraint.
- Containers are generic over a single child type: `VerticalStackComponent<C>` (`vertical_stack.rs:18`, `Vec<C>` + `.add()`), `CenterComponent<C>` (single child), `ScrollViewComponent<C>` (single child, **stateful** scroll state).
- Heterogeneous composition today = delegate enums via `impl_component_delegate!` (`crates/term-wm-core/src/macros.rs:9`), e.g. `CoreWmComponent`, `LayerComponent`, `AppRootComponent`.
- `ButtonComponent` (`button.rs:104`) routes clicks by **screen-area** (`ctx.localize_mouse_click`), no hitbox identity → safe to reconstruct each frame. Stateful widgets (terminal, list, scroll view) use **hitbox ids** and hold cross-frame state → they must be stable/owned.
- Layout engine (`crates/term-wm-layout-engine`): `split_rects_nary(area, orientation, weights, count)` (`split.rs:65`), `build_rects_from_sizes(area, orientation, sizes)` (`split.rs:305`), `Orientation` (rect.rs). All geometry is pure rect math with saturating ops.
- Consumer entry: `TermWmApp<C>::new_custom(...)` → `app.open_window(AppRootComponent::Custom(comp))` (`examples/dual_image.rs`). Root crate re-exports `term_wm_core::*` and `term_wm_ui_components::*` (`src/lib.rs`). Workspace edition 2024. `syn`/`quote`/`proc-macro2` already in lockfile; `rstml` (0.13, maintained, MIT) is not.

## Design overview

`view!` produces an **ephemeral per-frame render tree** (iocraft/ratatui-kit-style, minus all the framework machinery). Because the tree borrows stateful components via `{ &mut self.terminal }`, it is non-`'static` and therefore **cannot implement `Component`** (the `Any` supertrait). So we introduce a lightweight `View` trait (the same lifecycle subset, no `Any`), plus a small set of reusable view-node types, plus the proc-macro.

Two integration patterns:
1. **All-owned view** (`view!` contains no `&mut` blocks) → wrap in `ViewComponent<C: View + 'static>` (implements `Component<TermWmAction>`) → `open_window(AppRootComponent::Custom(...))`. Compile-time guard: borrowed trees fail `'static` here, directing the user to pattern 2.
2. **Borrowed view** (contains `{ &mut self.x }`) → app implements `Component` for its window struct and forwards each lifecycle method to a `fn view(&mut self) -> impl View + '_` (see example below).

State rule (the honest "dumb" compromise): **ephemeral tags must be stateless** (Label, Button, layout containers); **stateful components are held by the app and injected by reference** (`{ &mut self.terminal }`, `{ &mut self.scroll_view }`). `ScrollView` is intentionally NOT a tag (its scroll state would reset every frame).

## Syntax

```rust
fn view(&mut self) -> impl term_wm::view::View + '_ {
    view! {
        <VerticalStack gap=1>
            <Label text="System Status" />
            <Button label="Refresh" action={TermWmAction::OpenCommandPalette} />
            <Center width=60 height=8> { &mut self.terminal } </Center>
            { &mut self.scroll_view }
            { build_owned_widget(&self.state) }
        </VerticalStack>
    }
}
```

Three tiers, resolved at compile time:
1. **Layout-primitive tags**: `<VerticalStack gap=..>` / `<Column>`, `<Row>` / `<HStack>`, `<Center width=.. height=..>`, `<Grid cols="200px 1fr" rows="2fr 1fr">` → geometry nodes backed by layout-engine rect math. Constraint strings parsed at expansion time into `GridConstraint::Fixed(u16) | Fraction(u16)`.
2. **Built-in component tags**: `<Label text=../>`, `<Button label=.. action=|onClick={expr}/>` → registered constructors. Small, extensible registry in the proc-macro.
3. **Expression braces**: `{ expr }` → owned component, wrapped in `LeafView::new(expr)`; `{ &mut expr }` → `BorrowedView::new(expr)`. Zero registry maintenance for third-party/fallible components.

## New types

### `View` trait — `crates/term-wm-core/src/view.rs` (new), exported in `lib.rs`

```rust
pub trait View {
    fn render(&mut self, backend: &mut dyn term_wm_render::RenderBackend, area: Rect,
              ctx: &ComponentContext, registry: &mut HitboxRegistry);
    fn handle_events(&mut self, event: &Event, ctx: &ComponentContext) -> EventResult<TermWmAction> { EventResult::Ignored }
    fn desired_height(&self, _width: u16) -> u16 { 0 }
    /// Hitbox identity (forwarded from a wrapped component), used to route
    /// keyboard focus and match `ctx.keyboard_focus_id()`.
    fn hitbox_id(&self) -> Option<HitboxId> { None }
    fn update(&mut self, action: TermWmAction, ctx: &ComponentContext, actions: &mut VecDeque<(WindowKey, TermWmAction)>) {}
    fn destroy(&mut self) {}
}
```
Mirrors the `Component` lifecycle subset. No `Any` supertrait (allows non-`'static` nodes). Render is required; the rest default. `hitbox_id` is the focus-routing hook (see "Correctness directives" below).

### View-node helpers — `crates/term-wm-ui-components/src/view.rs` (new module)

- `LeafView<C: Component<TermWmAction>> { inner: C }` — owned component → `View` (forwards all methods, including `hitbox_id`).
- `BorrowedView<'a, C: Component<TermWmAction>> { inner: &'a mut C }` — `&mut` component → `View` (forwards, including `hitbox_id`).
- `NoopView` — unit struct, all-`View`-methods no-op. Used by the macro for **empty containers** (`VStackView::<NoopView>::new()`); renders nothing, `desired_height` 0 (stretch).
- `VStackView<C: View> { children: Vec<C>, gap: u16 }` — `new()` / `with_gap(u16)` / `add(C)`. Render slices vertical stripes by each child's `desired_height` (mirror `vertical_stack.rs` render logic, saturating ops). `handle_events`: route mouse by per-child screen area (mirror `vertical_stack.rs`), **route `Event::Key` to the focused child only** (see directives). `desired_height` sums children+gaps. `update`/`destroy` fan out.
- `HStackView<C: View>` — horizontal counterpart; equal splits by default (no `desired_width` exists in the component system), `gap` honored.
- `CenterView<C: View> { content: C, size: (u16,u16) }` — centers child (mirror `center.rs`).
- `GridView<C: View> { children: Vec<C>, cols: Vec<GridConstraint>, rows: Vec<GridConstraint> }` — row-major placement. Fixed constraints consume size; Fraction constraints share the remainder evenly (via `split_rects_nary`-style math + `build_rects_from_sizes` for placement). `desired_height` = sum of fixed row heights.
- `GridConstraint = Fixed(u16) | Fraction(u16)`.
- `ViewComponent<C: View + 'static> { view: C }` — **the bridge into the component system**: implements `Component<TermWmAction>` by forwarding `render`/`handle_events`/`update`/`destroy`/`desired_height`/`hitbox_id` (others use defaults). Only `'static` views satisfy the `Any` supertrait.

**Correctness directives (non-negotiable, apply to every container view — `VStackView`, `HStackView`, `CenterView`, `GridView`):**

1. **Never pass the parent `ctx` to a child unchanged.** In `render()`, derive `let child_ctx = ctx.clone().with_screen_area(child_rect);` and pass `&child_ctx` — otherwise children query `ctx.screen_area()` and get the parent's bounds, corrupting `HitboxRegistry` registration and mouse-coordinate localization (`localize_mouse_click`). Same in `handle_events()` when building the per-child `ctx` for hit-testing.
2. **Never cache layout.** Containers recompute child `LayoutRect`s on the fly in BOTH `render()` and `handle_events()` from `ctx.screen_area()` (exactly `vertical_stack.rs:146-199`). This makes the "stale cache between render and event" case impossible and complies with the AGENTS.md rule (read from `ctx.screen_area()`, no `Cell<Rect>`).
3. **Mouse routing** = spatial: pick the child whose recomputed `screen_area` contains the cursor; forward with that child's `ctx`; first non-`Ignored` wins; outside all children → `Ignored`.
4. **Keyboard routing = focus, not broadcast.** Forward `Event::Key` ONLY to the child whose `hitbox_id() == ctx.keyboard_focus_id()` (falls back to sequential first-non-`Ignored` when no child matches, e.g. focused ephemeral buttons). Blind broadcast would let the first input-consuming child (e.g. the first of two terminals) starve all others. Note: `VerticalStackComponent` currently drops key events entirely — the view layer deliberately fixes this so injected terminals receive keys.

Naming note: these are view-node composition types, not WM-registered widgets; only `ViewComponent` is a real `*Component` (filename `view.rs` per AGENTS.md). All children held in `Vec`s like the existing containers (zero-cost parity — no `Box`/`dyn`/`Rc` anywhere).

## The `view!` proc-macro — `crates/term-wm-view` (new, `proc-macro = true`)

Deps: `rstml = "0.13"`, `syn = "2"`, `quote`, `proc-macro2`. (Build-time only; added under `[workspace.dependencies]` in root `Cargo.toml`.)

### Expansion strategy

1. `rstml::parse2(input)` → `Vec<Node>`.
2. **Single root required**; multiple roots → `compile_error!` at the rstml span ("wrap in a container tag").
3. Recursively expand nodes:
   - `Node::Block` (the `{ ... }`): if the token stream starts with `&mut` → emit `BorrowedView::new(<expr>)`; else `LeafView::new(<expr>)`. Type is inferred; no registry needed.
   - `Node::Element` with a registered **container tag** → expand children per the child-count branches (step 4), build the container value (`VStackView::new().with_gap(g)` / `CenterView::new(child, w, h)` / `GridView::new(children).with_cols(..).with_rows(..)`), recurse.
   - `Node::Element` with a registered **leaf tag** → emit `LeafView::new(<CtorName>::new(<args…>))` from the registry.
   - Unknown tag → `compile_error!` naming the tag + available tags + the `{ expr }` escape hatch. Missing required attr → `compile_error!` at that attr's span (rstml preserves spans → precise rustc diagnostics, the key DX win over `macro_rules!`).
   - `Node::Text` non-whitespace → `compile_error!`.
4. **Sibling heterogeneity — branch on child count**:
   - **0 children** → no enum, no `.add()` calls; emit the container typed with `NoopView` (e.g. `VStackView::<NoopView>::new().with_gap(g)`). An uninhabited `enum __View0 {}` would fail to instantiate/type-infer.
   - **1 child** → no enum; pass the child value directly (e.g. `CenterView::new(child, w, h)`, `VStackView::<ChildTy>::new().with_gap(g)` + one `.add(child)`).
   - **≥2 children** → generate a block-scoped **generic delegate enum**, one type param per child, all params inferred at the construction site. This is why arbitrary `{ expr }` types work (a generated *non-generic* enum could not name them):

```rust
{
    // injected imports (single dep: term_wm_ui_components)
    use ::term_wm_ui_components::view::{View, VStackView, LeafView, BorrowedView};
    use ::term_wm_ui_components::view::{EventResult, TermWmAction};

    enum __View0<A, B, C> { V0(A), V1(B), V2(C) }
    impl<A: View, B: View, C: View> View for __View0<A, B, C> {
        fn render(&mut self, b, a, c, r) { match self { Self::V0(v)=>v.render(b,a,c,r), Self::V1(v)=>v.render(b,a,c,r), Self::V2(v)=>v.render(b,a,c,r) } }
        fn handle_events(&mut self, e, c) -> EventResult<TermWmAction> { match self { Self::V0(v)=>v.handle_events(e,c), Self::V1(v)=>v.handle_events(e,c), Self::V2(v)=>v.handle_events(e,c) } }
        fn desired_height(&self, w) -> u16 { match self { Self::V0(v)=>v.desired_height(w), Self::V1(v)=>v.desired_height(w), Self::V2(v)=>v.desired_height(w) } }
        fn hitbox_id(&self) -> Option<HitboxId> { match self { Self::V0(v)=>v.hitbox_id(), Self::V1(v)=>v.hitbox_id(), Self::V2(v)=>v.hitbox_id() } }
        fn update(&mut self, a, c, acts) { match self { Self::V0(v)=>v.update(a,c,acts), Self::V1(v)=>v.update(a,c,acts), Self::V2(v)=>v.update(a,c,acts) } }
        fn destroy(&mut self) { match self { Self::V0(v)=>v.destroy(), Self::V1(v)=>v.destroy(), Self::V2(v)=>v.destroy() } }
    }
    let mut __s = VStackView::new().with_gap(1);
    __s.add(__View0::V0(LeafView::new(::term_wm_ui_components::LabelComponent::new("System Status"))));
    __s.add(__View0::V1(LeafView::new(::term_wm_ui_components::ButtonComponent::new("Refresh", TermWmAction::OpenCommandPalette))));
    __s.add(__View0::V2(CenterView::new(BorrowedView::new(&mut self.terminal), 60, 8)));
    __s
}
```
   Block-scoped items ⇒ no cross-invocation name collisions; `__ViewN` counter per expansion; positional variant names `V0..Vn` (no tag-name collisions). Fully monomorphized, `match`-dispatch — byte-for-byte the code one would hand-write.

### Tag registry

A const table in the macro crate, e.g. `ComponentSpec { ctor: fn(&Attrs) -> TokenStream2 }` keyed by tag string:
- Containers: `VerticalStack`/`Column` (`gap`), `Row`/`HStack` (`gap`), `Center` (`width`, `height`), `Grid` (`cols`, `rows` string-literal → parsed constraints).
- Leaves: `Label` (`text` → `LabelComponent::new`), `Button` (`label`, `action` or `onClick` → `ButtonComponent::new`).
- Extensible by appending entries; `{ expr }` covers everything else (no registry maintenance needed for third-party components).

### Grid constraint parsing (compile-time)

`cols="200px 1fr"` → split on whitespace; `Npx` → `Fixed(N)`, `Nfr` → `Fraction(N)`. Emitted as `vec![GridConstraint::Fixed(200), GridConstraint::Fraction(1)]`. Bad token → `compile_error!` with the token's span. Parser is a plain `fn parse_constraint(&str) -> Result<GridConstraint, String>` in the macro crate → unit-testable.

### Path resolution

Generated code references only `::term_wm_ui_components::view::*` (which re-exports `View`, `EventResult`, `TermWmAction`, `Event`, `Rect`, `RenderBackend`, `ComponentContext`, `HitboxRegistry` from core) plus `::term_wm_ui_components::<LeafName>Component`. **Consumer needs `term-wm-ui-components` as a direct dep** (documented in macro docs + README) — standard for proc macros.

## Canonical usage

```rust
use term_wm::prelude::*;

struct MyWindow { terminal: ScrollViewComponent<TerminalComponent> }

impl MyWindow {
    fn view(&mut self) -> impl View + '_ {
        view! {
            <VerticalStack gap=1>
                <Label text="Status" />
                <Button label="Refresh" onClick={TermWmAction::OpenCommandPalette} />
                { &mut self.terminal }
            </VerticalStack>
        }
    }
}

impl Component<TermWmAction> for MyWindow {
    fn render(&mut self, b, a, c, r) { self.view().render(b, a, c, r); }
    fn handle_events(&mut self, e, c) -> EventResult<TermWmAction> { self.view().handle_events(e, c) }
    fn update(&mut self, a, c, acts) { self.view().update(a, c, acts) }
    fn destroy(&mut self) { self.view().destroy(); }
    // desired_height defaults to 0 (stretch) — correct for a window root
}
```

All-owned variant:
```rust
let root = ViewComponent::new(view! { <VerticalStack><Label text="hi"/></VerticalStack> });
app.open_window(AppRootComponent::Custom(root));
```

## Zero-cost audit

Walk of `view! { <VerticalStack gap=1><Label/>{ &mut self.terminal }</VerticalStack> }`:
- **No allocations beyond existing parity**: `VStackView` uses `Vec<C>` — identical to `VerticalStackComponent`. No `Box`, no `dyn`, no `Rc`, no trait objects anywhere in the tree (the only `dyn` is the `&mut dyn RenderBackend` handed down by the WM, exactly as today).
- **No dispatch indirection**: everything is generics + `enum` `match` → monomorphized, LLVM-inlined.
- **No per-frame framework cost**: the tree is re-constructed per frame but only by running the component constructors directly (a `LabelComponent::new(String)` etc.). One-shot model, no reconciliation/diffing/identity bookkeeping.
- **One known, documented, same-as-today cost**: the `Vec` in each container + per-frame construction of stateless leaves. Parity with hand-written `VerticalStackComponent`; no framework overhead added.
- Constraint strings are parsed at macro-expansion time (compile-time constants), never at runtime.

## Risks & mitigations

1. **rstml 0.13 API surface** (`Node`/`NodeElement`/`NodeAttribute`/`NodeBlock` shapes) — do a 20-line spike in P2 first; fallback is a hand-rolled `syn`-based mini-parser.
2. **Borrowck of `{ &mut self.x }` in `fn view(&mut self) -> impl View + '_`** — conceptually sound (single disjoint field borrow into the ephemeral tree); validate with a compile test in P2 before building further.
3. **Keyboard routing** — solved by the focus-based rule (directive 4): route `Event::Key` to the child matching `ctx.keyboard_focus_id()` (fallback: sequential first-non-`Ignored`). `VerticalStackComponent` currently drops key events entirely; the view layer deliberately fixes this so injected terminals receive keys. Covered by P1 multi-terminal tests.
4. **Hitbox/event routing for injected stable components** — terminal registers hitbox with `ComponentOwner::Window(key)` from `ctx.window_key()` (unchanged); WM routes to app root, which forwards the raw ctx; **every container rebinds `ctx.with_screen_area(child_rect)` for children in both render and handle_events (directive 1)** so hitbox rects and `localize_mouse_click` are correct. Verified path: `ButtonComponent`/`TerminalComponent` already route by screen-area/hitbox. Add an integration test in P4 to prove click-through + typing.
5. **Compile-time / inference with deep trees** — generic enums are cheap; but keep construction fully inferable (no explicit turbofish). If a deep tree hits inference limits, add explicit type params on the top-level `ViewComponent::<...>::new(...)`. Empty containers are handled via `NoopView` (no uninhabited enum).
6. **Scope creep** — `ScrollView` as a tag, `#[view_component]` derive, second macro `view_component!`: all explicitly out of scope for this plan (noted as follow-ups).

## Code review amendments (post-review)

The plan was reviewed against four SEV-1/SEV-2 findings. Resolution:
1. **Child `screen_area` corruption** — accepted; now a mandatory directive (recompute + `with_screen_area` rebinding in every container, render and event paths).
2. **Empty/single-child enum degeneracy** — accepted; macro branches on 0/1/≥2 children, `NoopView` for the empty case.
3. **Stale layout cache between render and events** — the concern is real but the proposed fix (caching rects + emergency fallback) violates the AGENTS.md no-cache rule; instead containers recompute child rects from `ctx.screen_area()` on every call, making staleness structurally impossible.
4. **Unfocused keyboard interception** — accepted; `View` gains `hitbox_id()`, containers route keys via `ctx.keyboard_focus_id()` instead of blind broadcast.
