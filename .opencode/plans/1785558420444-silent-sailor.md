# Plan: Clipboard temp-store + OSC 52 relay hardening

Status: **Approved** — supersedes the prior IN-PROGRESS plan
(`IN-PROGRESS-1785642020653-osc52-clipboard-hardening.md`), amended per the
AMEND code-review verdict plus the architectural directive on relay flushing.

## Goal

Harden the temp-file clipboard backing store and OSC 52 relay in
`term-wm-pty-engine`:

1. Test isolation (no test ever touches the real user store).
2. Reliable `set()` ordering (internal paste guaranteed first).
3. 1 MB OSC 52 emission cap via **safe UTF-8 char-boundary truncation**
   (local file cache + arboard stay uncapped).
4. No handle-lifetime coupling to store lifetime (no unlink-on-Drop).

Preserves the tree's deliberate **OSC 52-last** design (`525a3eb`, X11
final-clipboard-owner rationale) and the **temp-store-only-when-headless**
privacy property.

## Review outcome (all 4 findings addressed)

| Code-review finding | Resolution |
| --- | --- |
| SEV-1 unlink-on-`Drop` | No `Drop` impl. Store is session-scoped; cleanup via consume-on-read in `get()` plus OS-level temp cleanup. |
| SEV-1 naive debounce drops tail | **No timing debounce at all.** One hoisted `Clipboard` above the reader loop; `set()` runs synchronously on every extracted sequence. |
| SEV-2 atomic path counter in `new()` | `new()` resolves deterministically to `default_temp_path()`. Test isolation via explicit `with_options(test_path, limit)` / `with_temp_path`. |
| SEV-2 total OSC 52 suppression | Char-boundary truncation (`str::floor_char_boundary`), not suppression. |

## 1. `clipboard.rs` — Option A API

- `pub const DEFAULT_MAX_OSC52_BYTES: usize = 1024 * 1024;` (1 MB).
- Add field `osc52_limit: usize` to `Clipboard`.
- Add `pub fn with_options(cache_path: PathBuf, osc52_limit: usize) -> Self`.
- `with_temp_path(path)` delegates to `with_options(path, DEFAULT_MAX_OSC52_BYTES)`;
  `new()` -> `with_options(default_temp_path(), DEFAULT_MAX_OSC52_BYTES)`.

## 2. `clipboard.rs` — test isolation

- All clipboard tests bind explicit isolated paths via `with_temp_path` /
  `with_options` + `tempfile::tempdir()`.
- `clipboard_set_emits_osc52` (clipboard.rs:893) must stop using
  `Clipboard::new()` — on headless CI arboard fails, `temp_store_enabled`
  becomes true, and `set()` would write to the real store. Move it to an
  isolated `with_temp_path`.
- `Clipboard::new()` stays deterministic (always `default_temp_path()`).

## 3. `clipboard.rs` — `set()` ordering + truncation

Reorder to: **(1) temp store** (if `temp_store_enabled`, uncapped) ->
**(2) arboard** (with `StderrSuppressGuard`) -> **(3) OSC 52 last**, truncated
via `text.floor_char_boundary(self.osc52_limit)` applied to both the stdout
path and the `#[cfg(test)]` capture. Full text always goes to file cache +
arboard. Doc comment updated.

## 4. `clipboard.rs` — store lifecycle

No `Drop` impl (none exists today — keep it that way). `get()` keeps its
consume-on-read semantics; the store is otherwise cleaned by OS-level
mechanisms. Documented in the module/struct docs.

## 5. `pty.rs` — relay: hoisted handle, no debounce

- Instantiate `let mut clipboard = Clipboard::new();` **once, above the reader
  loop** (removes the per-sequence `Clipboard::new()` at pty.rs:671, which
  re-runs arboard display-server handshakes per copy event).
- On each extracted OSC 52 sequence: record the `osc52_text` test hook, then
  call `clipboard.set(&text)` immediately. Synchronous, per-sequence delivery
  guarantees the tail payload is never dropped and never stalls on a blocked
  `read()`.
- No `Instant` tracking, no `OSC52_RELAY_DEBOUNCE`, no `pending_osc52` buffer.

## Tests (added/changed in `clipboard.rs`)

- `osc52_emission_truncated_over_limit` — small `osc52_limit` via
  `with_options`; oversized text -> `osc52_output` decodes to the truncated
  (`<= limit`) text, while the temp store retains the full text.
- `osc52_truncation_respects_utf8_boundary` — a limit landing mid-multibyte
  char truncates at a valid boundary (no panic, valid UTF-8).
- `clipboard_set_emits_osc52` — moved to an isolated `with_temp_path`.
- Existing 33 clipboard tests and pty tests keep passing (`osc52_text` hook
  ungated; the hoisted `Clipboard::new()` in the loop is only exercised when a
  sequence is actually extracted).
