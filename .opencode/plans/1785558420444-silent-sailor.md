# Plan: Clipboard backend orchestration refactor (Option 4)

Status: **Approved** per the AMEND code-review verdict — implements the
"Explicit Static Orchestration with Encapsulated Helpers" directive.

## Goal

Restore readability to `crates/term-wm-pty-engine/src/clipboard.rs`. The
three backends (arboard, temp-file store, OSC 52) are currently woven into
nested if/then blocks inside `Clipboard::set()`/`get()`. Keep `Clipboard` as
a static orchestrator, but extract each backend operation into a private,
named helper so `set()`/`get()` read as short, explicit pipelines — and drop
the false-fallible `Result` from `set()`.

## Design (from review)

- **Reject** trait registries / `Box<dyn ClipboardBackend>` / priority-ordered
  iteration (breaks write-only OSC 52 + mandatory "OSC 52 last" ordering).
- **Reject** wrapping fields into exposed sub-structs (`cb.system`, etc.).
- Keep `Clipboard` as the direct orchestrator owning its current fields;
  dispatch stays static and compile-time verified.
- Extract each backend operation into a **private module-level helper**.
- `set()` becomes infallible: `pub fn set(&mut self, text: &str)`.
- `get()` stays `pub fn get(&mut self) -> Result<String, ClipboardError>`;
  `ClipboardError` remains for `get()` and `set_via_osc52_with_writer`.
- No new `pub` fields. Existing private fields (`arboard`, `temp_store_enabled`,
  `temp_path`, `osc52_limit`) and the `#[cfg(test)] pub osc52_output` capture
  stay as-is.

## Files changed

- `crates/term-wm-pty-engine/src/clipboard.rs`
- `crates/term-wm-pty-engine/src/pty.rs` (call site)
- `crates/term-session-client/src/lib.rs` (call site)
- `crates/term-wm-core/src/window/window_manager/mod.rs` (call site uses
  `.is_ok()`; `crate::clipboard` is a re-export of `term_wm_pty_engine::clipboard`)

## `clipboard.rs`

### 1. Private module-level helpers

- `fn write_temp_store(path: &Path, enabled: bool, text: &str)` — headless
  temp-file write + tracing (moved out of `set()`).
- `fn write_system_clipboard(clipboard: &mut Option<arboard::Clipboard>, text: &str)`
  — arboard write with `StderrSuppressGuard` + tracing (moved out of `set()`).
- `fn read_temp_store(path: &Path, enabled: bool) -> Option<String>` — temp-file
  read with consume-on-read (`remove_file`) + tracing (moved out of `get()`).
- `fn read_system_clipboard(clipboard: &mut Option<arboard::Clipboard>) -> Result<Option<String>, ClipboardError>`
  — arboard read; `Ok(None)` when no system backend (headless).
- `fn truncate_for_osc52(text: &str, limit: usize) -> &str` — char-boundary
  truncation via `floor_char_boundary` (extracts the escape-sequence-adjacent
  slicing).

### 2. `set()`

```rust
pub fn set(&mut self, text: &str) {
    write_temp_store(&self.temp_path, self.temp_store_enabled, text);
    write_system_clipboard(&mut self.arboard, text);
    let osc52_text = truncate_for_osc52(text, self.osc52_limit);
    #[cfg(not(test))]
    if let Err(e) = set_via_osc52_with_writer(osc52_text, &mut std::io::stdout().lock()) {
        tracing::debug!("clipboard: set OSC 52 to stdout failed ({e})");
    }
    #[cfg(test)]
    {
        let mut buf = Vec::new();
        let _ = set_via_osc52_with_writer(osc52_text, &mut buf);
        self.osc52_output = buf;
    }
}
```

Ordering preserved: temp store → arboard → OSC 52 **last** (host terminal owns
the clipboard). No trailing `Ok(())`.

### 3. `get()`

Rewrite with `read_system_clipboard` + `read_temp_store`, preserving the exact
current semantics:

```rust
pub fn get(&mut self) -> Result<String, ClipboardError> {
    match read_system_clipboard(&mut self.arboard) {
        Ok(Some(text)) => return Ok(text),
        Ok(None) if !self.temp_store_enabled => {
            tracing::debug!("clipboard: get no backends available");
            return Err(ClipboardError::NotAvailable);
        }
        Ok(None) => {}
        Err(e) if !self.temp_store_enabled => {
            tracing::debug!("clipboard: get via arboard failed; temp store inactive");
            return Err(e);
        }
        Err(_) => {}
    }
    read_temp_store(&self.temp_path, self.temp_store_enabled)
        .ok_or(ClipboardError::NotAvailable)
}
```

### 4. Docs

Update the `set()` doc comment to reflect the infallible signature; keep the
OSC 52-last and backend-ordering rationale.

# Amendment: Consolidate clipboard configuration

The clipboard configuration is scatterbrained: constants are split between the
top of `clipboard.rs` and halfway down (the OSC 52 protocol constants), and the
runtime configuration is only implicit in constructor params. Reorganize so the
configuration is a first-class, documented type and all constants live in one
block.

## Files changed

- `crates/term-wm-pty-engine/src/clipboard.rs` (only; all constants are private
  to this file, 39 refs, no external consumers)

## 1. Centralized constants block

Move **all** module constants into a single labeled block immediately after the
module docs, each with a one-line doc, grouped:

- Path resolution: `ENV_XDG_RUNTIME_DIR`, `CLIPBOARD_CACHE_FILENAME`,
  `APP_TEMP_DIR_PREFIX`.
- Caps: `DEFAULT_MAX_OSC52_BYTES`, `MAX_OSC52_BUFFER_BYTES`.
- OSC 52 protocol: `OSC52_HEADER_LEN`, `OSC52_HEADER_LEN_WIN`,
  `CLIPBOARD_PARAM_LEN`, `OSC52_HDR_STD`, `OSC52_HDR_WIN`.

Carry the existing explanatory comments (including the "no longer needed"
notes for `OSC52_ESC_OFFSET` / `ST_TERMINATOR_LEN`) up with the moved consts.

## 2. `ClipboardConfig`

Add a public runtime-config type so "what the configuration is" is answerable:

```rust
/// Runtime configuration for the clipboard subsystem.
#[derive(Debug, Clone)]
#[non_exhaustive]
pub struct ClipboardConfig {
    /// Resolved file path for the headless single-use temp store fallback.
    pub cache_path: PathBuf,
    /// Maximum payload byte limit for OSC 52 emission (default 1 MB).
    pub osc52_limit: usize,
}

impl Default for ClipboardConfig {
    fn default() -> Self {
        Self {
            cache_path: default_temp_path(),
            osc52_limit: DEFAULT_MAX_OSC52_BYTES,
        }
    }
}
```

`#[non_exhaustive]` lets future fields (e.g. a rate limit) be added without
breaking external construction.

## 3. Constructors

- `Clipboard::with_config(config: ClipboardConfig) -> Self` — primary
  constructor; maps `cache_path` → `temp_path`, `osc52_limit`, and derives
  `temp_store_enabled` from arboard availability (unchanged logic).
- `new()` → `with_config(ClipboardConfig::default())`.
- `with_temp_path(path)` → `with_config(ClipboardConfig { cache_path: path, ..Default::default() })`.
- Remove `with_options(cache_path, osc52_limit)`; update its test call sites
  (in `clipboard.rs` tests) to `with_config(ClipboardConfig { cache_path, osc52_limit })`.
  (`with_options` has no callers outside the crate.)

## 4. Reorganize by concern (Option 3)

File order becomes:

1. Module docs (unchanged, incl. "Design: explicit static orchestration").
2. Configuration constants block.
3. `ClipboardError`.
4. `ClipboardConfig` + `Default`.
5. **Core orchestrator** — `Clipboard` struct, `Default`, `impl Clipboard`
   (constructors, `get`, `set`), and the private orchestration helpers
   (`write_temp_store`, `write_system_clipboard`, `read_system_clipboard`,
   `read_temp_store`, `truncate_for_osc52`).
6. **Temp-file store helpers** — `default_temp_path`, `ensure_clipboard_store_dir`,
   `write_clipboard_temp`, `read_clipboard_temp`.
7. **OSC 52 protocol & extractor** — `format_osc52_bytes`,
   `set_via_osc52_with_writer`, `find_osc52_header`, `is_base64_char`,
   `extract_osc52_text`, `Osc52Extractor` + `Default`.
8. `mod tests`.

Behavior-identical: Rust item order does not affect resolution, so moving
functions/consts is a pure readability change.

## Behavior preservation

- Same `set()`/`get()` semantics, ordering, consume-on-read, headless-only temp
  store, and OSC 52 truncation.
- `new()`, `with_temp_path`, `get`, `set`, `DEFAULT_MAX_OSC52_BYTES`,
  `format_osc52_bytes`, `set_via_osc52_with_writer`, `extract_osc52_text`,
  `Osc52Extractor` all keep their public signatures. Only `with_options` is
  removed (crate-internal usage).
