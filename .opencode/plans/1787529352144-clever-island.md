## Phase B: Extend `src/term_wm_app.rs`

### Step B1 — injectable custom-action hook (CHOSEN DESIGN)

Field (added to struct, term_wm_app.rs:182-241, unconditional — no cfg):
```rust
/// Optional external handler consulted by `handle_custom_action` AFTER the
/// built-in `RunProjectTask` branch and the runtime persistence guard.
/// Returning `true` consumes the action.
custom_action_handler: Option<Box<dyn FnMut(&TermWmAction, &mut TermWmApp<C>) -> bool>>,
```
Setter (in the generic inherent impl block):
```rust
pub fn set_custom_action_handler(
    &mut self,
    handler: Box<dyn FnMut(&TermWmAction, &mut Self) -> bool>,
) { self.custom_action_handler = Some(handler); }
```

Getter:
```rust
/// Current workspace name, for IPC hooks resolving channel names.
#[cfg(feature = "session-persistence")]
pub fn current_workspace(&self) -> &str { &self.current_workspace }
```

**Why `&mut TermWmApp<C>` (not `&mut WindowManager`)** — validated per arm: SwitchWorkspace/NewWorkspace call `on_user_registry_changed()` which is a *trait method of the app* touching app-owned caches/debouncer (term_wm_app.rs:1075-1081), unreachable via `&mut WindowManager`; DetachCurrentClient needs `event_owner` + `current_workspace` (private app state). A WM-only hook cannot implement the arms faithfully. Full-app access requires passing `self` while the hook lives in a self field → **`std::mem::take` pattern is mandatory and sound**:
```rust
if let Some(mut hook) = self.custom_action_handler.take() {
    let handled = hook(action, self);
    self.custom_action_handler = Some(hook);
    if handled { return true; }
}
```
After `take()`, the field is `None`, so `hook(action, self)` borrows no part of `self` twice. Known trade-offs (documented, accepted): a panicking hook is lost for the process lifetime; a hook re-entering `handle_custom_action` observes `None` and falls through (recursion-proof).

## Risks / gotchas & mitigations
1. **`_rt_guard` premature drop**: replacing `let _rt_guard = rt.enter();` with `rt.enter();` drops the guard instantly and breaks tokio-context lookups downstream. Mitigation: keep the named binding; noted in Phase D checklist.
2. **Double `pty_wakeup_tx` fetch collapse**: safe (both are clones; unified_event_source.rs:203). Flagged in commit message for reviewability.
3. **Hook lost on panic / recursion**: documented semantics of mem::take design; acceptable (hook is a startup-installed singleton; recursion is programmer error).
4. **Feature-gate drift**: `internal_session.rs` fully cfg(sp); `build_inner_command` keeps `any(sp, test)`; FALLBACK_WORKSPACE keeps `not(sp)`. Both clippy/test variants in verification cover this.
5. **Behavior widening scope creep**: ONLY the three absorbed deltas change library-visible behavior; review diff for any other semantic edit inside moved bodies (move = cut/paste + visibility + mechanical renames).
6. **Guardrail false positives later**: `term_wm_app.rs` inclusion is verified-clean today; if a legit future name collides, needles are concat!-assembled so the test file itself never self-matches (pattern preserved).
7. **`resolve_task_spec` dead-code attr**: looks vestigial but preserved verbatim to keep the diff purely structural.
