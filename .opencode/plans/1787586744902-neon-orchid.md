## Goal

Make PR CI reliably green by fixing flaky test root causes (no nextest, no retries, per owner decision), and make failures diagnosable by capturing daemon/WM logs to configurable files (#270) uploaded as CI artifacts.

Issue references: https://github.com/jzombie/term-wm/issues/309 and https://github.com/jzombie/term-wm/issues/270

## Constraints

- NO cargo-nextest, NO test retries. Every fix must be deterministic.
- Cross-platform: macOS, Linux, Windows.
- Repo rules: extract repeated literals to consts, no em/en dashes in prose/comments, preserve and update comments, saturating coordinate math, verification = clippy + cargo test.
- Keep workspace green between commits (phased workstreams).

## Phase 1: Shared test-support crate (foundation) [Size: S]

New workspace member `crates/term-test-support` (dev-dependency only consumers; no production deps beyond std; optional `tokio` feature for the async helper). Add to root `Cargo.toml` workspace members.

Contents:

1. `wait_for` (sync) and `wait_for_async` (tokio): deadline-bounded predicate polling with fail-fast error message. Signature sketch:
   - `pub fn wait_for<T>(deadline: Duration, desc: &str, probe: impl FnMut() -> Option<T>) -> T`
   - `pub async fn wait_for_async<T>(deadline: Duration, desc: &str, probe: impl FnMut() -> Fut...) -> T` (async closure emulated via returning `Option<T>` from an async block)
2. `KillOnDrop`: generic RAII guard running a closure on drop (`KillOnDrop::new(cleanup: impl FnMut())`). Used for PTY child kills and daemon process kills so panicking tests cannot leak them.
3. `ManualClock`: thread-safe virtual clock, `Send + Sync`. Backed by an atomic offset, not `Cell`:
   ```rust
   #[derive(Clone, Debug)]
   pub struct ManualClock {
       base: Instant,
       elapsed_nanos: Arc<AtomicU64>,
   }
   ```
   with `new()` (base = `Instant::now()`, offset 0), `advance(Duration)` (`fetch_add` on nanos), `now() -> Instant` (`base + Duration::from_nanos(load)`). `Arc<AtomicU64>` keeps it usable from multi-threaded contexts and cloneable into closures.
4. `unique_gateway_name(tag: &str) -> String`: process-atomic counter PLUS process id, format `term-wm/{tag}-{pid}-{n}`. Replaces the duplicated AtomicU64 counters in `tests/common/session.rs:69` and `crates/term-session/tests/daemon_tests.rs:35-39`. The pid component makes names collision-free across processes (concurrent runs, leftovers from crashed runs).

Files: new `crates/term-test-support/Cargo.toml`, `src/lib.rs`, `src/clock.rs`, `src/poll.rs`; root `Cargo.toml` members list; `[dev-dependencies]` additions in root, `term-session`, `term-session-server`, `term-wm-pty-engine`, `term-wm-crossterm-adapter`.

## Phase 3: Deterministic timer tests [Size: M]

1. Injectable clock in `crates/term-wm-core/src/task_scheduler.rs`:
   - Add `SchedulerInner.now: Arc<dyn Fn() -> Instant + Send + Sync>` (Send + Sync closure type so the injected clock never constrains the scheduler's future thread-safety; `ManualClock` satisfies the bound). `TaskScheduler::new()` keeps the real clock; add `TaskScheduler::new_with_clock(...)`. `schedule_once`/`schedule_repeating`/`drain_expired*` route through it. API additive; production callers (`runner.rs`) unchanged.
   - Mechanics rule: advancing virtual time only moves the timestamp provider; it never executes queued timers. Every `clock.advance(d)` in tests MUST be followed by an explicit drain (`drain_expired_once()` / `drain_expired()`) before asserting. No test asserts on timer state after a bare advance.
2. Rewrite tests on virtual time (no wall-clock sleeps):
   - `task_scheduler.rs` tests (~12 sleeps): construct with `ManualClock`; `clock.advance(...)` then drain.
   - `crates/term-wm-core/src/utils/debounce/keyed_task_debouncer.rs` tests (179, 199-204): `make()` uses clock-injected scheduler; trickling submits become submit/advance pairs; `cancel_removes_and_cancels_task` advances past the window instead of sleeping.
   - `crates/term-wm-core/src/window/window_manager/mod.rs:5879` (`direct_mode_toast_cap_does_not_reschedule`, 300 ms sleep): if `make_direct_mode_wm()` constructs the scheduler, inject the manual clock there and advance; if the WindowManager owns construction, fall back to a bounded `wait_for` on `drain_expired_once()` producing exactly one task (still removes the fixed sleep).
   - `crates/term-wm-core/src/notification.rs:253` (`bus_push_and_tick_expiry`): pure test fix, no production change. Push with a large TTL, assert `tick(Instant::now())` retains, then `tick(far_future_instant)` expires. Also fixes the inverse flake (toast expiring before the first tick on loaded CI).
   - `crates/term-wm-core/src/reaper.rs:438` (`reaper_drains_burst_on_shutdown`, 200 ms): add a test-visible processed-count signal (AtomicU64 incremented when the reaper thread picks up a zombie; accessor `processed_count()`), then `wait_for(2 s, count >= states.len())` before drop. Reuses the file's existing `wait_for` idiom.
3. Leave the flood/throttle stress timings (terminal.rs:3703, pty.rs Windows regression) as-is: timing-bound by design.

## Risks and mitigations

- Clock injection touches `TaskScheduler` (callers in `runner.rs`): additive API only, default constructor unchanged.
- Window-manager debounce test may not own scheduler construction: fall back to bounded poll on drain result (still removes the fixed sleep).
- `Session` Drop kill-net: audit drop paths first (ShutdownGateway, CloseSession escalation, exited-session cleanup all kill explicitly first; kill on dead child is a no-op).
- Stale macOS `/tmp` socket files from old crashes: `try_overwrite` binding already handles rebinding; pid-suffixed names prevent attaching to a stale live daemon (the documented hijack hazard).
- Coverage job re-running the suite remains a second flake surface per PR: accepted; identical fixes cover it; timeouts prevent freezes.
- Toolchain drift (floating @stable) is out of scope for this effort.
