## #244 — term-session `created:` shows military clock time

**Root cause.** `format_unix_relative` in `crates/term-session/src/lib.rs:25-45` has two incompatible output modes. Under 24h it emits elapsed time (`2h`); the `else` branch (lines 40-44) emits `ts % 86400` — the **UTC time-of-day** of the creation timestamp, formatted as `HH:MM:SS`. That's the "military time" the user sees (`created: 18:48:46`). The switch happens the moment a channel crosses 24h old. The bug shipped silently: the function has no tests.

**Fix** (`crates/term-session/src/lib.rs`):
1. Add named consts per AGENTS.md: `SECS_PER_MIN: u64 = 60`, `SECS_PER_HOUR: u64 = 3600`, `SECS_PER_DAY: u64 = 86400`.
2. Replace the `else` branch (lines 40-44) to always render elapsed time with **d + h precision** (user choice):
   ```rust
   } else {
       format!("{}d {}h", diff / SECS_PER_DAY, (diff % SECS_PER_DAY) / SECS_PER_HOUR)
   }
   ```
   Drop the `ts % 86400` clock-time fallback entirely. Update the doc comment on lines 23-24 to describe the new behavior.
3. Make it testable: refactor to `format_unix_relative_at(ts: u64, now: u64) -> String` and have `format_unix_relative(ts)` call it with `now` from `SystemTime` (keeps the public API unchanged). Add `#[cfg(test)]` unit tests in `lib.rs` for: `0 → "-"`, `<60s`, `<1h`, `<24h`, exactly `86400 → "1d 0h"`, `90000 → "1d 1h"`, and a timestamp older than the current `now` (saturating to `0s`-class output, no panic).

Both display sites (`created:` at `main.rs:195-198` and `connected:` at `main.rs:217-220`) already call this one function, so a single change fixes both. No server/wire changes.

## #239 — Separator between window controls and window switcher

**Current state.** In `wm_menu_items` (`crates/term-wm-core/src/window/window_manager/command_palette.rs`), the "Window management group" builds per-window controls (Send Super / Close / Maximize / Minimize, lines 184-220) then immediately the `Switch to:` list (lines 222-230) with no `MenuDisplayItem::Separator` in between. The separator concept is fully supported end-to-end (core builds `MenuDisplayItem::Separator`, `WmCommandPaletteComponent` maps it to `ActivePaletteNode::Separator`, `CommandPaletteComponent` renders a full-width `─` row, and `focus.rs:76-99` re-filters with separators preserved).

**Fix** (`command_palette.rs`): emit the separator **lazily**, only when the switch list is non-empty. `window_titles()` (`mod.rs:793-827`) returns every window in display order, but can be empty while `has_active` is true when the focused window is a system window excluded from display order — pushing the separator unconditionally would leave a dangling trailing `─` row. Restructure the block at lines 222-230:
```rust
// Switch to windows
let switch_titles = self.window_titles();
if !switch_titles.is_empty() {
    items.push(MenuDisplayItem::Separator);
    for (key, switch_title) in switch_titles {
        items.push(MenuDisplayItem::Item(MenuItem {
            label: format!("Switch to: {}", switch_title).into(),
            icon: Some("→"),
            action: crate::actions::TermWmAction::FocusWindow(key),
            disabled: key == focused,
        }));
    }
}
```
`window_titles()` already allocates its Vec; checking `.is_empty()` adds no extra allocation and guarantees no dangling separator.

**Tests**: add a unit test in `command_palette.rs` (pattern: `WindowManager::<TestComponent>::with_config(...)` + `make_keys` + focus a window) that calls `wm_menu_items()` and asserts:
- a `MenuDisplayItem::Separator` exists between the last window-control item (e.g. `Close …` / `Minimize …`) and the first `Switch to:` item;
- when the focused window is the only window, the `Switch to:` item (focused, disabled) still follows the separator;
- when no switchable windows exist (e.g. only a system window focused), **no** separator precedes the next group's items (i.e. no dangling separator).

## #240 — Unify clipboard toggles in Command Palette

**Current state.** Two independent WM flags feed two menu items in `wm_menu_items` (`command_palette.rs:119-133`, 267-276):
- `clipboard_enabled` (gates OSC52 copy/paste) → `Clipboard: Disable/Enable` → `TermWmAction::ToggleClipboardMode`.
- `window_selection_enabled` (gates mouse text selection → clipboard copy via `copy_selection_to_clipboard`, `mod.rs:2297-2311`) → `Clipboard: Disable/Enable Selection` → `TermWmAction::ToggleWindowSelection`.

Both flags default `true` in `WmConfig` (`wm_config.rs:126-127`) and are set from config on startup (`runner.rs:418-421`).

**Fix (user chose: one combined toggle, keep both underlying flags for config compat)**:

1. `crates/term-wm-core/src/window/window_manager/mod.rs` — make **both** toggle entry points route through the same combined logic, so keybinding dispatches can never desynchronize the two flags:
   ```rust
   pub fn toggle_clipboard_enabled(&mut self) {
       let next = !self.clipboard_enabled;
       self.set_clipboard_enabled(next);
       self.set_window_selection_enabled(next);
   }

   pub fn toggle_window_selection(&mut self) {
       self.toggle_clipboard_enabled();
   }
   ```
   `clipboard_enabled` is the source of truth for the label; selection mirrors it. `set_window_selection_enabled` (line 2322) sets `window_selection_dirty`, `set_clipboard_enabled` (line 2339) sets `clipboard_dirty` + syncs overlays — both already emit change notifications, so toggling both flags keeps every consumer (runner IPC `take_window_selection_change`, overlays) consistent. Making `toggle_window_selection` delegate guarantees that a direct `TermWmAction::ToggleWindowSelection` keybinding produces the exact same combined state as the palette toggle.
2. `command_palette.rs` — remove the `selection_label` computation (lines 129-133) and its `mi(...)` push (lines 272-276). Keep the single `clipboard_label` item (label already based on `self.clipboard_enabled`, lines 124-128) with action `ToggleClipboardMode`.
3. Keep `TermWmAction::ToggleWindowSelection` in `DEFAULT_SUPPORTED_MENU_ACTIONS` (`constants.rs:14`) and the runner dispatch (`runner.rs:104`) — the action remains valid and now toggles the same combined state.

**Tests**: verify/adjust existing menu tests that assert on the two clipboard items (e.g. any test walking `wm_menu_items` in `command_palette.rs` tests or `mod.rs`), and add an assertion that the Settings group contains exactly one clipboard item. Add a test that `toggle_window_selection()` and `toggle_clipboard_enabled()` keep `clipboard_enabled == window_selection_enabled` after dispatch (both action paths in `runner.rs`), including after repeated alternating toggles. Confirm the runner toggle test (`runner.rs:1829-1840`) still passes.

## #245 — Move viewport-clamping math into the layout engine

**Goal.** Pure refactor, zero behavior change. All WM coordinates already use `LayoutRect` (aliased as `crate::Rect`), and `term-wm-core` already depends on `term-wm-layout-engine` (dependency-free, `no_std`-capable crate).

**Code being moved** (all in `term-wm-core`):
- `clamp_rect` (`mod.rs:2862-2882`) and `float_rect_visible` (`mod.rs:2884-2906`) — these are intersection clamps already provided by the engine as `LayoutRect::clamp` / `LayoutRect::visible_portion` (`crates/term-wm-layout-engine/src/rect.rs:69-96`). **Delete them and switch call sites to the engine method** — no new engine API needed for these.
- `clamp_floating_to_bounds` (`layout.rs:719-820`) — the min-visible-margin translate clamp used every frame via `register_managed_layout` (`layout.rs:452`) for both (a) keeping a dragged window from going fully off-screen and (b) re-homing windows on viewport change. The per-rect math (lines 739-815) moves verbatim into the engine as a new pure function.

**New engine API** (`crates/term-wm-layout-engine/src/floating.rs`, next to `apply_resize_drag_signed` where `FLOATING_MIN_WIDTH`/`FLOATING_MIN_HEIGHT` already live):
```rust
/// Clamp a floating window rect into `bounds`, preserving its size.
/// When `allow_offscreen` is true the window may sit partially off-screen
/// but must keep at least `min_visible_margin` cells visible; otherwise it
/// is fully contained. Size is enlarged to the floating minimums and capped
/// at `bounds` when `!allow_offscreen`.
pub fn clamp_floating_to_bounds(
    rect: LayoutRect,
    bounds: LayoutRect,
    min_visible_margin: u16,
    allow_offscreen: bool,
) -> LayoutRect
```
Body = the per-rect math from `layout.rs:739-815` verbatim (saturating ops per AGENTS.md). Export from `lib.rs` (`floating::{...}` re-export list, `lib.rs:27-30`). `MIN_FLOATING_VISIBLE_MARGIN` stays a WM constant passed as the parameter — no new magic numbers in the engine.

**WM call-site changes** (`term-wm-core`):
1. `layout.rs` — shrink `clamp_floating_to_bounds` to an in-place, allocation-free wrapper. `set_floating_rect` (`mod.rs:676-684`) is a plain field write into `self.windows`, so we can iterate `self.windows.values_mut()` and mutate each floating rect directly — no intermediate `Vec` for keys or updates (the current code allocates **two** Vecs per frame; the refactor removes both, a net win for this per-frame hot path):
   ```rust
   pub(super) fn clamp_floating_to_bounds(&mut self) {
       let bounds = self.managed_area;
       if bounds.width == 0 || bounds.height == 0 {
           return;
       }
       for window in self.windows.values_mut() {
           let Some(FloatRectSpec::Absolute(fr)) = window.floating_rect() else {
               continue;
           };
           let clamped = term_wm_layout_engine::clamp_floating_to_bounds(
               fr,
               bounds,
               MIN_FLOATING_VISIBLE_MARGIN,
               self.floating_resize_offscreen,
           );
           window.set_floating_rect(Some(FloatRectSpec::Absolute(clamped)));
       }
   }
   ```
   (`crate::window::FloatRect` is an alias of `LayoutRect`, so the engine's return value feeds straight back in.) Behavior identical: same per-window math, same apply timing via `register_managed_layout` (`layout.rs:452`).
2. `layout.rs:124` — `super::clamp_rect(rect, self.managed_area)` → `rect.visible_portion(self.managed_area)`.
3. `layout.rs:708` — `super::float_rect_visible(spec.resolve_signed(self.managed_area), self.managed_area)` → `spec.resolve_signed(self.managed_area).visible_portion(self.managed_area)`.
4. `mod.rs` — delete `clamp_rect` / `float_rect_visible` and their tests (`clamp_rect_inside_and_outside` at 3002, `float_rect_visible_clips_negative_offsets` at 3030). Grep to confirm no other callers.

**Tests**:
- Port the two deleted WM tests to the engine (assert `visible_portion` clips negative offsets / returns default for fully-outside rects — these now test the existing engine method).
- Add engine unit tests for `clamp_floating_to_bounds` mirroring the WM margin behavior: partially off-screen with `allow_offscreen=true` keeps ≥ `min_visible_margin` visible; fully-contained when `allow_offscreen=false`; size never below floating minimums; bounds with zero width/height.
- Keep the WM regression tests `enforce_min_visible_margin_horizontal` (`mod.rs:3336`) and `enforce_min_visible_margin_vertical` (`mod.rs:3375`) unchanged — they drive `register_managed_layout` end-to-end and must still pass.
- No new dependencies; the engine stays dependency-free.

## Content to add

### Changed

- **Exit confirmation overlay buttons are now explicit and app-aware:** the `[ Cancel ]` / `[ Exit ]` buttons in the Exit UI overlay are no longer hardcoded. `ConfirmOverlayComponent` now stores configurable, fully pre-formatted labels (defaults unchanged), and the bundled app renders `[ Return to term-wm ]` / `[ Exit term-wm ]` from `AppContext.app_name`. Labels are formatted once when the overlay opens, so the render path stays allocation-free and mouse hitboxes stay exactly aligned with the drawn text.
- **Command Palette: separator between window controls and the window switcher:** the window-management group now draws a `─` separator between the per-window controls (Send Super / Close / Maximize / Minimize) and the `Switch to:` list. The separator is emitted lazily only when at least one switchable window exists, so focusing a window outside the display order never leaves a dangling trailing separator row.
- **Command Palette: unified clipboard toggle:** the redundant `Clipboard: Disable` and `Clipboard: Disable Selection` entries are now a single `Clipboard: Enable/Disable` item that controls both OSC 52 copy/paste and mouse text-selection copy together. Both toggle entry points — `ToggleClipboardMode` and the still-available `ToggleWindowSelection` action — keep `clipboard_enabled` and `window_selection_enabled` in sync, so a direct keybinding can never desynchronize the two flags from what the palette shows (the separate underlying flags and config still apply).
- **Floating-window viewport clamping moved into the layout engine (no functional change):** the per-window math that keeps floating windows from being dragged fully off-screen and re-homes them when the viewport changes now lives as a pure `clamp_floating_to_bounds(rect, bounds, min_visible_margin, allow_offscreen)` in `term-wm-layout-engine` (exported alongside the existing floating-window helpers). The window manager's `clamp_floating_to_bounds` is now an in-place wrapper that iterates windows without allocating intermediate vectors each frame, and the duplicate WM `clamp_rect` / `float_rect_visible` helpers were deleted in favor of the engine's existing `LayoutRect::visible_portion`. The clamping tests moved into the engine with the same coverage.

### Fixed

- **`term-session list` showed old channel ages as military wall-clock time:** when a channel was more than 24 hours old, `format_unix_relative` fell back to rendering the creation timestamp's UTC time-of-day (`created: 18:48:46`) instead of elapsed time, so output silently switched from `2h` to a clock time that was usually wrong. Timestamps are now always rendered as elapsed time — seconds, minutes, hours, then combined days + hours (`2d 5h`) — for any age, with unit tests covering the day boundary, long ages, and timestamps in the future.
