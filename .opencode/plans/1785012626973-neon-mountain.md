# Fix: Command Palette State Synchronization (Final)

## Root Cause
The invocation-bound capture already exists in `term_wm_app.rs:289-304` — `wm_menu_items()` is called once when the palette opens. The stateful label in `wm_menu_items()` correctly evaluates `self.direct_mode(self.focused_window())` at that instant. No additional refresh mechanism needed.

The previous attempts added:
- `refresh_command_palette()` helper (unnecessary)
- JIT refresh in render loop (trashed UI state)
- Mutator hooks in `set_direct_mode`/`focus.rs` (duplication)

## Changes

### 1. Keep the stateful label in `wm_menu_items()` (already applied)
The MenuItem uses `self.windows.contains_key(self.focused_window())` for both label and `disabled` state:

```rust
let has_active = self.windows.contains_key(self.focused_window());
items.push(MenuItem {
    label: {
        let on = has_active && self.direct_mode(self.focused_window());
        format!("Direct Mode: {}", if on { "On" } else { "Off" }).into()
    },
    icon: Some("D"),
    action: TermWmAction::ToggleDirectMode,
    disabled: !has_active,
});
```

### 2. Remove `refresh_command_palette()` helper from `mod.rs`
Delete the method entirely — it's unused.

### 3. Remove JIT refresh from `src/lib.rs`
Delete the `if wm.command_menu_visible() { wm.refresh_command_palette(); }` block.

### 4. Verify no mutator hooks
No calls to `refresh_command_palette` exist in `set_direct_mode` or `focus.rs` (already clean).
