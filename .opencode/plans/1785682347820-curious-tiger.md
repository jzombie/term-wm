# Plan: Extract command palette into `command_palette.rs`

## Goal
Consolidate all command-palette-related `WindowManager` methods currently spread
across `mod.rs`, `overlays.rs`, and `command_menu.rs` into one new submodule file
`crates/term-wm-core/src/window/window_manager/command_palette.rs`, matching the
established `window_manager` submodule pattern (`focus.rs`, `drag.rs`, `overlays.rs`,
`chrome.rs`).

## Background (verified)
The command palette menu items are built by a single cohesive method
`WindowManager::wm_menu_items` (mod.rs:2680–2873). Related overlay lifecycle
methods are split across:
- `mod.rs`: `open_command_palette_overlay` (2327), plus `set_tab_outline_mode` (2337) / `clear_tab_outline` (2351) which operate on the palette overlay.
- `overlays.rs`: `command_palette_key` (35), `command_palette_visible` (102),
  `command_palette_bounds` (107), `close_command_palette` (119), `handle_command_palette_event` (129).
- `command_menu.rs`: thin aliases `command_menu_visible`, `close_command_menu`.

Callers (`src/term_wm_app.rs:484`, `focus.rs:76`) only use the public associated
method names, which stay unchanged, so the extraction is caller-agnostic.

Convention confirmed: submodule files in `window/window_manager/` declare
`mod <name>;` in `mod.rs` and define `impl WindowManager<C,L,O> { .. }` blocks
(like `overlays.rs`). Being a child module, it can access `WindowManager`'s private
fields/methods, so `wm_menu_items` will keep working with no signature change.

## Changes

### 0. Review disposition (verified against source — see Resolution section)
- Claim 1 (invalid `super::OverlayKey` import): **Rejected.** `OverlayKey` is defined at
  `crate::window::OverlayKey` (`window/mod.rs:16`), NOT in `overlays.rs`. `overlays.rs:7`
  already uses the identical `use super::{OverlayKey, WindowManager};` and compiles, so the
  same import in the new child module `command_palette.rs` is equally valid. No visibility
  change or re-export is required.
- Claim 2 (dead imports in `overlays.rs`): **Rejected for overlays.rs.** After removing the
  5 palette methods, every remaining import is still used by the kept help/exit methods
  (`TypeId`, `Event`, `LayoutRect`, `OverlayKey`, `ConfirmAction`, `EventResult`,
  `TermWmAction`, `system_tags`). `WmInputMode` (in `crate::actions`) is only used by the
  moved methods and relocates to `command_palette.rs`.
  `mod.rs` imports are validated by the clippy gate below.
- Claim 3 (delete `command_menu_*` aliases): **Rejected as written.** These aliases are
  production API used at `runner.rs:105,198,618`, `focus.rs:65`, `mod.rs:2050,2068` — NOT a
  single test. Removing them would churn 6+ runtime call sites in the runner. They are
  *moved* (not deleted) to `command_palette.rs`, keeping the extraction caller-agnostic.
