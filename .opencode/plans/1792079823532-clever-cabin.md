# Plan: Fix Issue #115 (bottom-right cell color duplication / full-window color bleed)

## Issue summary
- `https://github.com/jzombie/term-wm/issues/115`: PowerShell `dir` (yellow) paints all surrounding text yellow; localized to one multiplexed window.
- Follow-up: not PowerShell-only. Generic ANSI bug duplicating bottom-right cell color. Nested `term-wm` + resize one window smaller reproduces.
- Owner hypothesis: DECAWM last-column pending-wrap mismatch between nested instances, BCE erase with wrong region, ConPTY translation in the middle.

## Scope guard
- No changes to `Cargo.toml` / `Cargo.lock`. Dependency updates are out of scope.
- Changeset restricted to terminal emulation logic, frame serialization, and regression tests.
- No unconditional `buf_cell.reset()` in the blit layer. Ratatui relies on buffer diffing; wiping every cell forces full repaints. Presentation must not mask a corrupted parser state.
- No fix-by-trial across layers. Causal hierarchy: emulator grid first, serializer second, presentation last and read-only.

## Causal hierarchy
1. Emulator (`term-wm-vt100` fork): owns pending-wrap latch and BCE erase. If `EL0`/`ED`/cursor-restore evaluate against the wrong column because pending-wrap was dropped, the grid itself is wrong.
2. Serializer (`crates/term-session-client/src/lib.rs render_frame()` ~974-1046): re-encodes inner `Parser` grid as bulk `CUP` rows. Currently forces `?7l` plus clamped `CUP`, clearing pending-wrap in the outer parser per ECMA-48.
3. Presentation (`crates/term-wm-ui-components/src/terminal.rs render_screen()` ~563-845): trusts the grid. Fix grid or resolver input, not the blit.

## Fix (in order, stop when round-trip is green)

### 1. Margin sanitation: default-bg clear, strictly outside content, 1-based coords
Prior revisions wrongly sampled the content cell bg and cleared at the content column, which both floods the margin with content color and erases the boundary cell (`EL0` is cursor-inclusive; 0-based index `render_cols - 1` is 1-based column `render_cols`).
- Compute `render_cols = min(inner.cols(), target_cols)`; bound row iteration to `0..render_cols`.
- Execute margin clear if and only if `render_cols < target_cols`. If `render_cols >= target_cols`, bypass margin clearing entirely (no margin exists; clearing would destroy the boundary char on every line).
- When clearing, position at 1-based `\x1b[{row + 1};{render_cols + 1}H` (first column strictly past content), then emit default-bg clear `\x1b[0m\x1b[K`. Never sample cell `(row, render_cols - 1)` bg for this: trailing margin is outside the inner app and must not inherit syntax-highlight colors (e.g. PowerShell yellow).
- Set serializer `active_style = CellStyle::default()` after the clear.
- Existing in-row pre-margin `\x1b[0m\x1b[K` (lib.rs:1011-1014, while cursor is still at `col`) keeps its current placement semantics; audit it against the same rule (must not erase cell `cols - 1` content, must use default bg, must update `active_style`).

### 2. Pending-wrap reconstruction: exact sequence with SGR termination and 1-based coords
No sequence sets the latch directly and every `CUP` clears it; the only reconstruction is printing into the final column with DECAWM on. `SGR 0` is non-motion and preserves the latch, so termination is safe.
- Keep `\x1b[?7l` during bulk row blitting.
- At cursor restore, `cursor_position()` is 0-based; all `CUP` emissions are 1-based:
  - If `cur_col < cols` or autowrap off: `\x1b[{cur_row + 1};{cur_col + 1}H`.
  - If pending (`cur_col >= cols`, autowrap on):
    1. `\x1b[{cur_row + 1};{cols}H` (final column, 1-based col equals 0-based `cols` count).
    2. `\x1b[?7h`.
    3. Re-emit boundary cell `(cur_row, cols - 1)` char plus its SGR attributes.
    4. Immediately emit `\x1b[0m` and reset `active_style = CellStyle::default()`. Omitting this leaks the bottom-right cell rendition into all subsequent output (the reported full-window bleed).

### 3. Emulator fork only on proof
Fix `EL0` / `write_cursor_position_formatted` / `?7l`-cancel in `term-wm-vt100` only if round-trip proves grid divergence on identical input. No compensations in `term-wm-pty-engine` or `term-wm-ui-components`.

### 4. Presentation: no blit change
No blit change unless grid + serializer round-trip is green and a stale-style case remains; then fix the specific `resolve_colors_with_defaults` input, preserving conditional `reset()` and Ratatui diffing.
