# Plan: Fix Bouncy Scrollbar

## Investigation Results

After reading the actual ratatui source (`ratatui-widgets-0.3.2/src/scrollbar.rs`), the `part_lengths` method shows:

```rust
let max_position = state.content_length.saturating_sub(1);
let start_position = state.position.clamp(0, max_position);
let max_viewport_position = max_position.saturating_add(viewport_length);

let thumb_length = rounding_divide(viewport_length * track_length, max_viewport_position);
let thumb_start = rounding_divide(start_position * track_length, max_viewport_position);
```

With original `content_length = total - view + 1`:
- `max_position = total - view`
- `max_viewport_position = total`
- `thumb_start = rounding_divide(offset * track, total)` ≈ `(offset * track / total).round()`

**This is the formula we must match in `handle_mouse`.**

## Root Cause: Two bugs

### Bug 1: Drifting thumb (formula mismatch)
In `handle_mouse`, the drag math uses `available_track = track_length - thumb_size` where `thumb_size = round(view * track / total)`. But ratatui computes the max thumb position as `max_thumb_rel = round(max_offset * track / total)`. These can differ by ±1 at `.5` rounding boundaries:

```
track=3, total=16, view=8:
  available_track = 3 - round(1.5) = 3 - 2 = 1
  max_thumb_rel  = round(1.5) = 2
```

When `available_track ≠ max_thumb_rel`, dragging to the bottom of the track produces `max_offset`, but ratatui renders the thumb at a different position — the thumb "drifts" away from the cursor.

### Bug 2: Bouncy scrollbar (hit-test too strict)
The hit-test `mouse_rel >= current_thumb_rel && mouse_rel < current_thumb_rel + thumb_size` had no tolerance for the ±1 rounding difference, causing near-edge clicks to register as track clicks ("snap to center" jump).

## Changes (3 changes to `handle_mouse` + new tests)

All changes in `ScrollbarDrag::handle_mouse`:

### 1. Unify track math with ratatui's formula

Replace the three variable computations at the top of the press/drag logic:

```rust
// OLD (diverges from ratatui):
let track_len = match axis { ... };
let thumb_size = ((view as f64 / total as f64) * track_len as f64).round() as i32;
let thumb_size = thumb_size.clamp(MIN_THUMB_SIZE, track_len);
let available_track = track_len - thumb_size;
let current_thumb_rel = ((current_offset as f64 / max_offset as f64) * available_track as f64).round() as i32;

// NEW (exactly matches ratatui's rounding_divide):
let track_len = match axis { ... };
let thumb_size = ((view as f64 * track_len as f64) / total as f64).round().max(MIN_THUMB_SIZE as f64) as i32;
let thumb_size = thumb_size.min(track_len);
let available_track = ((max_offset as f64 * track_len as f64) / total as f64).round() as i32;
let current_thumb_rel = ((current_offset as f64 * track_len as f64) / total as f64).round() as i32;
```

### 2. Widen hit-target (line 97–98)


### 3. Add boundary tests (after line 796)

```rust
#[test]
fn scrollbar_press_on_thumb_edge_with_tolerance_does_not_jump() {
    let mut drag = ScrollbarDrag::new();
    let area = sb_area();
    let offset = 30usize;
    // Strict math: thumb starts at row 9. Click at row 8 (1 cell above, inside tolerance).
    let down = mouse_event(MouseEventKind::Press(MouseButton::Left), 79, 8);
    let resp = drag.handle_mouse(&down, area, SB_TOTAL, SB_VIEW, offset, ScrollbarAxis::Vertical);
    assert_eq!(resp, Some(offset), "1-cell tolerance should absorb edge click");
    assert!(drag.dragging);
}

#[test]
fn scrollbar_press_outside_tolerance_jumps() {
    let mut drag = ScrollbarDrag::new();
    let area = sb_area();
    let offset = 30usize;
    // Click at row 7 (2 cells above strict math, 1 cell outside tolerance).
    let down = mouse_event(MouseEventKind::Press(MouseButton::Left), 79, 7);
    let resp = drag.handle_mouse(&down, area, SB_TOTAL, SB_VIEW, offset, ScrollbarAxis::Vertical);
    assert!(resp.is_some_and(|o| o < offset), "clicking outside tolerance should jump");
    assert!(drag.dragging);
}
```
