# Issue #169 — Double-click selects full word + word-granularity drag

## Goal
When direct mode is off and double-clicking a word in a view, select the whole word. After a double-click, dragging extends the selection word-by-word. Introduce a `SelectionGranularity` enum (Cell / Word / Line) in the shared selection state machine (`crates/term-wm-core/src/utils/selectable_text.rs`). Line is reserved for a future triple-click feature.

## Verified architecture facts (confirmed against source)
- `handle_selection_mouse` lives at `selectable_text.rs:294`; `maintain_selection_drag` at `:492`; `maintain_selection_drag_active` at `:527` (calls `update_drag(pos)` at `:540`).
- `SelectionState` (`selectable_text.rs:137`) is `Clone + Copy`; `Instant` is `Copy`, so new `Instant` fields are fine.
- `LogicalPosition` already implements `Ord`/`PartialOrd` (row-major) — `pos < anchor` works directly.
- `SelectionViewport` (`:93`) and `SelectionHost` (`:127`) are the shared traits. Only 3 non-test impls exist: `TerminalComponent` (`terminal.rs:802`), `RenderDragHost` (`terminal.rs:1040`), `TextRendererComponent` (`text_renderer.rs:661`), plus `TestHost` in selectable_text tests (`:617`).
- `RenderDragHost` (`terminal.rs:1033`) is constructed in `render_screen` step 2 (`:587-596`); the parser lock is taken later at `:643` — no lock held during drag maintenance, so locking the parser inside word lookup is safe.
- Terminal mouse flow: `handle_events` (`terminal.rs:107`) → `handle_selection_mouse(self, ...)` (`:147`) gated by `!app_captures_mouse || override_active || gesture_active` (`:131`). Link click handling (`try_handle_link_click` `:1007`) runs AFTER selection and already never fires on a Press when selection is enabled (selection consumes the press) — so double-click-on-link is a pre-existing non-issue, no regression.
- vt100 API confirmed in `term-wm-vt100` 0.16.2-patch3: `Screen::cell(row, col) -> Option<&Cell>`, `Cell::contents() -> &str`, `Cell::is_wide()`, `Cell::is_wide_continuation()`, `Screen::size() -> (u16,u16)`, `set_scrollback`, `scrollback`, `row_wrapped`. Matches `selection_text_for_range` usage (`terminal.rs:878`).
- TextRenderer: `on_mouse_*` → `handle_local_mouse` (`text_renderer.rs:629`) → `handle_selection_mouse`. `text_for_range` (`:429`) is the paragraph-into-scratch-buffer pattern. `selection_text()` (`:266`) calls it. `content_width/content_height` are `Cell<usize>` set in `render()` (`:84-85`); `logical_position_from_point` (`:666`) uses `viewport_cache` (also set in render) — the codebase already assumes render-before-events.
- `ComponentContext::new(bool)` is `focused`; `with_screen_area`, `with_direct_mode` builders exist. Terminal tests use `ComponentContext::new(true).with_screen_area(...)` and `make_term_with_content` (`terminal.rs:1771`). `max_scrollback()` returns *used* scrollback rows, so `row_base = max_scrollback` for a single rendered line is 0.

## Design

### 1. Shared core — `crates/term-wm-core/src/utils/selectable_text.rs`

**New consts** (module-level, named per AGENTS.md):
```rust
const DOUBLE_CLICK_WINDOW: Duration = Duration::from_millis(500);
const DOUBLE_CLICK_MOVE_TOLERANCE: usize = 4; // logical-cell Manhattan distance
```

**New public enum** (with `Default` → `Cell`):
```rust

pub enum SelectionGranularity { #[default] Cell, Word, Line }
```

**`SelectionState` additions** (all `Copy`-safe; `Default` covers them):

**New pure word primitives** (`pub`, importable from `term_wm_core::utils::selectable_text`):
```rust
pub fn is_word_char(c: Option<char>) -> bool {
    matches!(c, Some(ch) if ch.is_alphanumeric() || ch == '_')
}

/// End-exclusive word bounds around `index`. Returns `(index, index)` (empty)
/// when `index` is out of range or the cell is not a word char.
pub fn find_word_bounds(cells: &[Option<char>], index: usize) -> (usize, usize) {
    if cells.is_empty() || index >= cells.len() || !is_word_char(cells[index]) {
        return (index.min(cells.len()), index.min(cells.len()));
    }
    let mut start = index;
    while start > 0 && is_word_char(cells[start.saturating_sub(1)]) {
        start = start.saturating_sub(1);
    }
    let mut end = index;
    while end < cells.len() && is_word_char(cells[end]) {
        end = end.saturating_add(1);
    }
    (start, end)
}
```
Decision: non-word → `(index, index)` (empty range). `end` may legally equal `cells.len()` (word runs to row edge) — selection_text extractors already accept `end_col == width`.

**`SelectionViewport` trait** — new defaulted method (no existing impl breaks):
```rust
fn word_range_at(&mut self, _pos: LogicalPosition) -> Option<SelectionRange> { None }
```
Contract: returns `Some` only when `pos` is on a word char; range end-exclusive, single row.

**`SelectionController` new methods** (all `pub`):
```rust
/// Records a press at `pos`. Returns consecutive click count (1, 2, 3…).
/// Counter resets to 1 when the window, move tolerance, or button-up
/// precondition fails. Time injectable for deterministic tests.
pub fn note_click_at(&mut self, pos: LogicalPosition, now: Instant) -> u8 {
    let within_window = self.state.last_click_at
        .is_some_and(|t| now.duration_since(t) <= DOUBLE_CLICK_WINDOW);
    let within_tol = self.state.last_click_pos.is_some_and(|p| {
        p.row.abs_diff(pos.row).saturating_add(p.column.abs_diff(pos.column))
            <= DOUBLE_CLICK_MOVE_TOLERANCE
    });
    let ready = !self.state.button_down && self.state.phase != Phase::Dragging;
    let count = if within_window && within_tol && ready {
        self.state.click_count.saturating_add(1)
    } else { 1 };
    self.state.click_count = count;
    self.state.last_click_at = Some(now);
    self.state.last_click_pos = Some(pos);
    count
}
pub fn note_click(&mut self, pos: LogicalPosition) -> u8 { self.note_click_at(pos, Instant::now()) }

pub fn begin_word_selection(&mut self, range: SelectionRange) {
    self.state.anchor = Some(range.start);
    self.state.cursor = Some(range.end);
    self.state.word_anchor_end = Some(range.end);
    self.state.phase = Phase::Dragging;
    self.state.button_down = true;
    self.state.granularity = SelectionGranularity::Word;
    self.touch_pointer_clock();
}

/// Standard word-drag UX: dragging right snaps cursor to the dragged word's
/// end; dragging left of the anchor moves the anchor to the dragged word's
/// start and pins the cursor at the anchor word's end.
pub fn update_word_drag(&mut self, pos: LogicalPosition, word: SelectionRange) {
    if self.state.phase != Phase::Dragging { return; }
    let Some(anchor) = self.state.anchor else { return };
    if pos < anchor {
        self.state.anchor = Some(word.start);
        self.state.cursor = self.state.word_anchor_end;
    } else {
        self.state.cursor = Some(word.end);
    }
}

pub fn granularity(&self) -> SelectionGranularity { self.state.granularity }
pub fn anchor(&self) -> Option<LogicalPosition> { self.state.anchor }
```
**Existing methods that must set `granularity = Cell`**: `prepare_drag`, `begin_drag`, `activate_drag` (word mode only ever enters via `begin_word_selection`). `finish_drag` resets `granularity` to `Cell` and leaves `last_click_*` untouched (they are managed solely by `note_click` — do **not** clear them in `prepare_drag`, or double-click detection breaks). `clear()` inherits the new defaults.

**Borrow-safe `handle_selection_mouse` Press arm** (replaces `selectable_text.rs:307-317`):
```rust
MouseEventKind::Press(MouseButton::Left) => {
    if rect_contains(area, mouse.column, mouse.row)
        && let Some(pos) = host.logical_position_from_point(area, mouse.column, mouse.row)
    {
        let count = {
            let selection = host.selection_controller();
            selection.set_pointer(mouse.column, mouse.row);
            selection.note_click(pos)
        };
        // click_count >= 2 = double (or triple, etc.) click. Line granularity
        // is reserved for triple-click (future); for now >= 2 re-words.
        if count >= 2 && let Some(word) = host.word_range_at(pos) {
            host.selection_controller().begin_word_selection(word);
            return true;
        }
        host.selection_controller().prepare_drag(pos);
        return true;
    }
    false
}
```
The borrow trick: `note_click` runs inside a block whose result is the count; the `&mut` borrow of `host` ends at the block, so the subsequent `host.word_range_at(pos)` and `host.selection_controller()` calls are fresh NLL-valid reborrows. This is the only tricky part — every other arm borrows host once per statement already.

**Shared word-aware drag updater** (new private helper; replaces the three bare `update_drag` call sites at `:337`, `:376`, `:540`):
```rust
fn update_drag_for_position<H: SelectionHost>(host: &mut H, pos: LogicalPosition) {
    if host.selection_controller().granularity() == SelectionGranularity::Word {
        if let Some(word) = host.word_range_at(pos) {
            host.selection_controller().update_word_drag(pos, word);
        }
    } else {
        host.selection_controller().update_drag(pos);
    }
}
```
If the drag lands on whitespace (`word_range_at` → None), the cursor is left unchanged — the selection simply doesn't extend over the gap. `maintain_selection_drag_active` (`:540`) swaps to this helper so render-time drag continuation is word-snapped too.

### 2. Terminal host — `crates/term-wm-ui-components/src/terminal.rs`

**New free fn** (shared by both hosts; mirrors `selection_text_for_range` pagination):
```rust
fn word_range_at_in_pane(
    pane: &RefCell<Box<dyn Pane>>,
    pos: LogicalPosition,
) -> Option<SelectionRange> {
    let mut pane = pane.borrow_mut();
    let max_scrollback = pane.max_scrollback();               // read BEFORE parser lock (deadlock rule)
    let parser_arc = pane.shared_parser();
    let mut parser = parser_arc.lock().unwrap();
    let screen = parser.screen_mut();
    let (viewport_rows, cols) = screen.size();
    if viewport_rows == 0 || cols == 0 { return None; }
    let guard = ScrollbackGuard::new(screen);
    guard.screen.set_scrollback(max_scrollback);
    let vt100_max_scrollback = guard.screen.scrollback();
    let vt100_total_lines = vt100_max_scrollback + viewport_rows as usize;
    let offset_from_pane_to_vt100 = max_scrollback.saturating_sub(vt100_max_scrollback);

    let vt100_row = pos.row.saturating_sub(offset_from_pane_to_vt100);
    if vt100_row >= vt100_total_lines { return None; }
    let viewport_start = vt100_row.min(vt100_max_scrollback);
    let offset = vt100_max_scrollback.saturating_sub(viewport_start);
    guard.screen.set_scrollback(offset);
    let viewport_row = (vt100_row - viewport_start) as u16;
    if viewport_row >= viewport_rows { return None; }

    // Per-cell char stream; wide continuation cells repeat the lead char so
    // wide glyphs count as word chars across both cells.
    let mut cells: Vec<Option<char>> = Vec::with_capacity(cols as usize);
    for col in 0..cols {
        match guard.screen.cell(viewport_row, col) {
            Some(c) if c.is_wide_continuation() => cells.push(cells.last().copied().flatten()),
            Some(c) => cells.push(c.contents().chars().next()),
            None => cells.push(None),
        }
    }
    if cells.is_empty() { return None; }
    let index = pos.column.min(cells.len().saturating_sub(1));
    let (start, end) = find_word_bounds(&cells, index);
    if start == end { return None; }
    Some(SelectionRange {
        start: LogicalPosition::new(pos.row, start),
        end: LogicalPosition::new(pos.row, end),
    })
}
```

### 3. Text renderer host — `crates/term-wm-ui-components/src/text_renderer.rs`

**New fields** on `TextRendererComponent`:
```rust
display_grid: Vec<Vec<Option<char>>>,            // content-height × content-width
grid_signature: Cell<(u64, bool, usize, usize)>, // (text_generation, wrap, content_width, content_height)
text_generation: Cell<u64>,                      // bumped in set_text / set_linkified_text
```
Plain `Vec` field (not `RefCell`) — both `render` and `word_range_at` are `&mut self`.

**Invalidation strategy (validated):** signature `(text_generation, wrap, content_width, content_height)` is the correct key — `content_width`/`content_height` are already computed in `render()` (`:84-85`) and change only on real width/text/wrap changes; the generation counter covers text mutation without needing `PartialEq` on ratatui `Text`. `render()` and `word_range_at` both call `maybe_rebuild_grid`, so a double-click before the first render self-heals (with zero dims the grid is empty → returns `None`, matching the existing render-before-events invariant).

```rust
fn maybe_rebuild_grid(&mut self, content_width: usize, content_height: usize) {
    let sig = (self.text_generation.get(), self.wrap, content_width, content_height);
    if self.grid_signature.get() == sig { return; }
    self.display_grid = build_display_grid(&self.text, self.wrap, content_width, content_height);
    self.grid_signature.set(sig);
}

fn build_display_grid(text: &Text<'static>, wrap: bool, width: usize, height: usize)
    -> Vec<Vec<Option<char>>> {
    let rect = ratatui::layout::Rect { x: 0, y: 0, width: width.max(1) as u16, height: height.max(1) as u16 };
    let mut buffer = ratatui::buffer::Buffer::empty(rect);
    let mut paragraph = ratatui::widgets::Paragraph::new(text.clone());
    if wrap { paragraph = paragraph.wrap(ratatui::widgets::Wrap { trim: false }); }
    paragraph.render(rect, &mut buffer);
    (0..height).map(|row| {
        let mut line = Vec::with_capacity(width);
        for col in 0..width {
            let sym = buffer.cell((col as u16, row as u16)).map(|c| c.symbol().to_owned());
            let ch = sym.as_deref().and_then(|s| s.chars().next());
            if ch.is_some() {
                line.push(ch);
            } else if col > 0 && line[col - 1].is_some() {
                line.push(line[col - 1]); // wide-char continuation: repeat lead char
            } else {
                line.push(None);
            }
        }
        line
    }).collect()
}
```
Performance: one extra full-paragraph render only when the signature changes (text/wrap/width); `compute_display_lines` already pays O(content) per change, and steady-state render is O(1). Word lookups during drag are O(1) grid reads — the reason to prefer this over re-rendering a paragraph per drag event.

**`word_range_at`** (call it from `render()` after `content_width/height` are set, and from `word_range_at`):
```rust
fn word_range_at(&mut self, pos: LogicalPosition) -> Option<SelectionRange> {
    self.maybe_rebuild_grid(self.content_width.get(), self.content_height.get());
    let row = self.display_grid.get(pos.row)?;
    if row.is_empty() { return None; }
    let index = pos.column.min(row.len().saturating_sub(1));
    let (start, end) = find_word_bounds(row, index);
    if start == end { return None; }
    Some(SelectionRange {
        start: LogicalPosition::new(pos.row, start),
        end: LogicalPosition::new(pos.row, end),
    })
}
```

## Edge cases and flagged issues

1. **Triple-click**: `note_click` returns a *count*, not a bool. A third rapid click yields count 3 → same word path (re-selects word at the new position). The count is the future hook for `SelectionGranularity::Line`. A third press *without* releasing between 2 and 3 resets the count (button still down) — correct, that's a drag, not a click.
2. **Click on whitespace**: `word_range_at` → None → falls through to `prepare_drag`, which clears any prior word selection and starts a normal cell drag. Correct.
3. **Wide chars**: terminal repeats lead chars into continuation cells via `is_wide_continuation()`; text renderer propagates the lead symbol into the empty continuation cell. Both hosts agree that "世world" is one word and a trailing wide char's continuation column is included in the end-exclusive range (matches the `end_col == width` handling in both extractors).
4. **Scrollback**: `word_range_at_in_pane` uses the same `ScrollbackGuard` pagination as `selection_text_for_range`, so scrolled-up rows work; `ScrollbackGuard` restores parser scrollback on drop. Render-time drag continuation via `RenderDragHost` uses the same helper.
5. **Link clicks**: selection already consumes single presses when enabled, so link handling on Press is pre-existing-unreachable; double-click adds word selection, no regression. Double-click on a link now selects the word instead of opening it — desired.
6. **`selection_enabled == false` / app mouse capture**: `handle_selection_mouse` returns early on `!enabled`; the terminal's `!app_captures_mouse` gate means captured apps never reach it. No `note_click` bookkeeping leaks in either case.
7. **Test flakiness**: `note_click_at(pos, now)` injects `Instant` so the 500ms window is tested deterministically; real double-clicks in integration tests are microseconds apart (real `Instant` is fine).
8. **`end_col == 0` adjustment**: a word range's `end` is always ≥ `start+1` (non-empty word), so the `end_col == 0 && end_row > start_row` adjustment in the extractors is never triggered by word selections — but the range can end at a row's edge (end == width), which is already handled.
9. **Host grid staleness**: text-renderer `word_range_at` rebuilds on a stale signature, and both components already assume render-before-events (`viewport_cache`). Documented, not a new assumption.
10. **Word char set**: `is_word_char` = Unicode alphanumeric + `_`. Paths like `/usr/bin` select as one run (slashes are non-word, so double-click on a slash yields nothing). This matches the issue's minimal spec; a configurable extra-char set is future work.

## Corrections to the proposed design (from validation)
- `note_click` should return a click **count** (`u8`), not `bool`, to keep triple-click from silently clearing the word selection on a rapid third press (with a bool + "not busy" guard, the 3rd press resets to `prepare_drag` and destroys the selection; with a count the guard is irrelevant because a real triple-click releases between presses).
- `prepare_drag` must **not** clear `last_click_at`/`last_click_pos` (that would break double-click detection); only `granularity` resets there.
- `update_word_drag` should compare with `pos < anchor` using the existing `Ord` (already implemented — no new comparison helper needed).
- `RenderDragHost::selection_content_size` uses `viewport_width/height` fields already stored on the struct (`:1036-1037`) — no change needed for word lookup.
- `find_word_bounds` empty-range contract `(index, index)` is right; hosts convert to `None` on `start == end`.
