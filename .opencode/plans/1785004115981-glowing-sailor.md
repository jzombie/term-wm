# Plan: Fix maximize-while-tiled tabbing issue

## Bug
When a tiled window is maximized, other windows become inaccessible:
1. The maximized window covers the full managed area (floating → renders on top of tiled windows)
2. Mouse clicks always hit the maximized window (its region fills the entire area)
3. Tab-cycling focus (via command palette) changes focus logically but the maximized window stays on top
4. Tiled windows behind it cannot be clicked or interacted with

## Root Cause
`toggle_maximize()` (chrome.rs:46-72) detaches a tiled window from the tiling layout and makes it a full-area floating window. When focus later moves to another window (via Tab, command palette, or mouse), nothing unmaximizes or restores the original window. The two key focus-change paths are:

- `focus_window_key` (focus.rs:51-81) — called by `advance_focus` (Tab cycling), `FocusWindow` action dispatch, and `register_managed_layout`
- `focus_app_window` (focus.rs:45-49) — called by `handle_mouse_focus_click` (mouse click focus switching)

Neither checks if the *previous* focus was maximized and unmaximizes it before switching.

## Fix

### 1. `focus_window_key` — auto-unmaximize when leaving a maximized window
**File:** `crates/term-wm-core/src/window/window_manager/focus.rs:51-81`

Add at the start, before `self.focus.set_current(key)`:
- Capture `prev_focus = *self.focus.current()`
- If `prev_focus != key` and the prev window has `is_maximized == true`:
  1. `self.toggle_maximize(prev_focus)` — unmaximizes, restores `prev_floating_rect` (the original tile position)
  2. `self.reattach_to_tiling_layout(prev_focus)` — puts it back in the tiling tree using its current floating rect for spatial placement
  3. `self.clear_floating_rect(prev_focus)` — window is now tiled again, not floating

### 2. `focus_app_window` — delegate to `focus_window_key`
**File:** `crates/term-wm-core/src/window/window_manager/focus.rs:45-49`

Replace the method body with `self.focus_window_key(key)` so mouse-click focus changes also trigger the unmaximize logic.

### 3. `handle_focus_event` mouse handler — use `focus_window_key`
**File:** `crates/term-wm-core/src/window/window_manager/focus.rs:164-196`

Replace the two `self.focus.set_current(key) + self.bring_floating_to_front_key(key)` pairs with `self.focus_window_key(key)`. This ensures the embedded-mode mouse click path (and command-palette-mode path) also unmaximizes when switching away from a maximized window.

### 4. Tests
Add tests in `crates/term-wm-core/src/window/window_manager/mod.rs` (tests module, ~line 2997):
- `maximize_then_focus_other_window_unmaximizes`: Create 2 tiled windows, maximize one, focus the other via `focus_window_key` → verify first window is no longer maximized and is back in the tiling layout
- `maximize_then_advance_focus_unmaximizes`: Create 2 tiled windows, maximize one, `advance_focus` → verify unmaximize
