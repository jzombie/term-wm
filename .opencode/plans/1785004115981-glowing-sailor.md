# Plan: Fix maximize-while-tiled tabbing issue

## Bug
When a tiled window is maximized, other windows become inaccessible:
- The maximized window covers the full managed area (floating → renders on top of tiled windows)
- Mouse clicks always hit the maximized window (its region fills the entire area)
- Tab-cycling focus (via command palette) changes focus logically but the maximized window stays on top
- Tiled windows behind it cannot be clicked or interacted with

## Root Cause
`toggle_maximize()` (chrome.rs:46-72) detaches a tiled window from the tiling layout and makes it a full-area floating window. When focus later moves to another window, nothing unmaximizes the original. The two key focus-change paths (`focus_window_key` and `focus_app_window`) don't check if the *previous* focus was maximized and need to unmaximize it.

**Key insight from code review:** The fix must also handle the case where an *originally floating* window is maximized. Unmaximizing it should restore it as floating (not forcefully tile it). This requires tracking whether the window was tiled before maximize.

## Changes

### 1. Add `was_tiled_before_maximize` to `Window`
**File:** `crates/term-wm-core/src/window/entry.rs`

Add field `pub was_tiled_before_maximize: bool` to the `Window` struct, initialized to `false` in `Window::new()`.

### 2. Rewrite `toggle_maximize` to use `was_tiled_before_maximize`
**File:** `crates/term-wm-core/src/window/window_manager/chrome.rs:16-73`

Rewrite the function body:

**Maximize path:**
- If window already has `floating_rect` (was floating): save current floating rect as `prev_floating_rect`, set `is_maximized=true`, `was_tiled_before_maximize=false`
- If window is tiled (no `floating_rect`): capture current region rect as `prev_floating_rect`, `detach_from_tiling_layout(key)`, set `is_maximized=true`, `was_tiled_before_maximize=true`

**Unmaximize path (when `is_maximized` is true):**
- If `was_tiled_before_maximize`:
  1. `take_prev_floating_rect(key)` — extract the pre-maximize tile region
  2. `set_floating_rect(key, prev_spec)` — temporarily set so `reattach_to_tiling_layout` uses the original spatial center for quadrant placement
  3. `reattach_to_tiling_layout(key)` — put it back in the tiling tree at the correct position
  4. `clear_floating_rect(key)` — window is now tiled, not floating
- If NOT `was_tiled_before_maximize` (was originally floating): restore `prev_floating_rect` as the window's floating rect
- Set `is_maximized=false`, `was_tiled_before_maximize=false`, `borders_enabled=true`

### 3. Update `focus_window_key` — delegate to `toggle_maximize`
**File:** `crates/term-wm-core/src/window/window_manager/focus.rs:51-81`

Add at start, before `self.focus.set_current(key)`:
```
if prev_focus != key && self.window(prev_focus).is_some_and(|w| w.is_maximized) {
    self.toggle_maximize(prev_focus);
}
```

### 4. `focus_app_window` — delegate to `focus_window_key`
**File:** `crates/term-wm-core/src/window/window_manager/focus.rs:45-49`

Replace body with `self.focus_window_key(key)`.

### 5. `handle_focus_event` mouse handler — use `focus_window_key`
**File:** `crates/term-wm-core/src/window/window_manager/focus.rs:164-196`

Replace the two `self.focus.set_current(key) + self.bring_floating_to_front_key(key)` pairs with `self.focus_window_key(key)`.

### 6. Tests
Add tests in `crates/term-wm-core/src/window/window_manager/mod.rs` (tests module):
- `maximize_tiled_then_focus_other_unmaximizes_and_retiles`: tiled window maximized → focus shifts → window is unmaximized and back in `managed_layout`
- `maximize_floating_then_focus_other_unmaximizes_and_refloats`: floating window maximized → focus shifts → window is unmaximized and remains floating (NOT tiled)
- `manual_unmaximize_tiled_restores_tiling`: tiled window maximized → `toggle_maximize()` called directly → window returns to tiling layout
