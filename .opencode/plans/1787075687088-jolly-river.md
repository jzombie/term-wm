# Env-scoped persistence gateway (`TERM_WM_ENV`)

Separate the persistence gateway endpoint by environment (dev/prod/test) so dev
builds never attach to / tear down production sessions, while keeping the shared
`term-wm` family namespace and exposing the resolved gateway in both binaries'
`--help` output.

## Design decision: `Environment` enum (not String / &'static str)

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Environment { Dev, Prod, Test }
```

Justification:
- **`&'static str`**: fine for the single `format!` consumer but stringly-typed; callers can't pattern-match, tests can't assert typed equality, and future logic ("if test, use isolation socket") becomes string compares.
- **`String`**: adds heap allocation for fixed compile-time values; no benefit.
- **enum**: invalid states unrepresentable (resolver normalizes trim/lowercase/fallback before it ever returns), `Copy`, exhaustiveness, `as_str()`/`Display` for formatting, directly testable with `assert_eq!(active_environment(), Environment::Test)`. `Display` gives `"dev"`/`"prod"`/`"test"` so `format!("{env}/{user}/gateway")` works.

```rust
use std::fmt;

/// Active environment override (`dev`/`prod`/`test`, case-insensitive).
/// Read by `term-session-muxio-service-definitions` to scope the gateway.
pub const ENVIRONMENT_ENV_VAR: &str = "TERM_WM_ENV";

/// Supported runtime environments.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Environment {
    Dev,
    Prod,
    Test,
}

impl Environment {
    /// Canonical lowercase identifier used in channel names.
    pub fn as_str(&self) -> &'static str {
        match self {
            Environment::Dev => "dev",
            Environment::Prod => "prod",
            Environment::Test => "test",
        }
    }
}

impl fmt::Display for Environment {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        f.write_str(self.as_str())
    }
}

/// The compile-time default environment: dev in debug builds, prod in release.
pub fn default_environment() -> Environment {
    if cfg!(debug_assertions) {
        Environment::Dev
    } else {
        Environment::Prod
    }
}

/// Parse a user-supplied value into an [`Environment`]. Case-insensitive and
/// whitespace-trimmed. Unknown or empty values return `None`.
pub fn parse_environment(raw: &str) -> Option<Environment> {
    match raw.trim().to_ascii_lowercase().as_str() {
        "dev" => Some(Environment::Dev),
        "prod" => Some(Environment::Prod),
        "test" => Some(Environment::Test),
        _ => None,
    }
}

/// The environment this build should behave as: `TERM_WM_ENV` when set and
/// valid, else [`default_environment`].
pub fn active_environment() -> Environment {
    std::env::var(ENVIRONMENT_ENV_VAR)
        .ok()
        .and_then(|raw| parse_environment(&raw))
        .unwrap_or_else(default_environment)
}
```

```rust
/// Resolve the logical gateway channel name.
///
/// Deterministic and static by default: `TERM_WM_GATEWAY` env override wins
/// wholesale at runtime; otherwise the gateway resolves to
/// `term-wm/<env>/<user>/gateway` where `<env>` is the active environment
/// (`TERM_WM_ENV`, defaulting to `dev` in debug / `prod` in release builds)
/// and `<user>` is the current OS user. Environment-scoping keeps dev builds
/// from ever attaching to (or tearing down) production gateways while the
/// `term-wm` namespace keeps all binaries interoperating on the same socket
/// family. No build-time entropy is involved; the compiled artifact is
/// reproducible and an upgraded binary probes the same endpoint as a running
/// daemon. Test isolation is the test harness's job — it injects a unique
/// `TERM_WM_GATEWAY` per suite into the client and daemon subprocesses.
pub fn gateway_channel_name() -> ChannelName {
    if let Ok(name) = std::env::var(GATEWAY_CHANNEL_ENV_VAR) {
        return ChannelName::parse(&name).unwrap_or_else(|_| ChannelName {
            namespace: "term-wm".to_string(),
            name: "gateway".to_string(),
        });
    }
    let env = term_wm_config::env::active_environment();
    let user = current_os_user();
    ChannelName {
        namespace: "term-wm".to_string(),
        name: format!("{env}/{user}/gateway"),
    }
}
```

(The `unwrap_or_else` invalid-override fallback → `term-wm/gateway` is pre-existing
and intentionally unchanged — "override wins wholesale".)

## Risks / gotchas

- **In-flight `term-wm-config` work**: `runtime.rs` won't compile its tests until
  the trivial `impl Default` (step 3) lands. `env.rs` is independent, but
  `cargo test -p term-wm-config` compiles the whole crate. Fix step 3 first;
  flag if the user's in-flight work supersedes it.
- **`GATEWAY_CHANNEL_ENV_VAR` duplication**: migrating to term-wm-config is
  recommended (step 5a). Low risk — only `channel.rs` itself and the lib.rs:6
  re-export reference it; `daemon_tests.rs` uses the literal `"TERM_WM_GATEWAY"`
  string. If you prefer minimal churn, keep both consts (they're equal strings);
  nothing breaks either way. If migrated, keep the `pub` re-export name at the
  service-definitions crate root to preserve the public API.
- **`Cli::from_arg_matches(...)` sketch bug**: takes `&ArgMatches`, not owned;
  bind `let mut matches` and use `from_arg_matches_mut` (exactly what
  `Parser::parse()` does). Also `FromArgMatches` must be imported into scope.
- **`render_*`/`write_long_help` deprecated?** No — only under clap's
  `deprecated` feature, which the workspace doesn't enable. `render_help`/
  `render_long_help` are the non-deprecated choices for tests.
- **`after_help` only covers `--help`?** Yes — long help falls back to
  `after_help` when `after_long_help` is unset (help_template.rs:353-358). Set
  `after_long_help` too only if the footer should differ for `--help`.
- **Help-smoke tests must be hermetic**: a developer's shell with
  `TERM_WM_GATEWAY`/`TERM_WM_ENV` exported would change the rendered footer (an
  override like `test/iso-gateway` drops the `term-wm/` segment). The bin tests
  therefore remove both vars under a mutex; keep that pattern if tests grow.
- **Migration of legacy daemons** bound to `term-wm/<user>/gateway` (old default):
  a new dev build probes `term-wm/dev/<user>/gateway`, finds nothing, and spawns
  a new daemon there — it never touches the old one. The stale daemon keeps
  running until stopped manually:
  `TERM_WM_GATEWAY=term-wm/<user>/gateway term-session stop`
  (or `term-wm --stop-daemon`). Same story for release (`prod` segment).
  A dev-only "legacy-name fallback probe" would smooth upgrades but reintroduces
  cross-build coupling and cross-user collisions — deliberately out of scope;
  document the manual stop instead.
- **Pre-existing quirk, unchanged**: an invalid `TERM_WM_GATEWAY` value falls back
  to `term-wm/gateway` (no user, no env) — a shared, collision-prone name. Keep
  as-is (override-wins-wholesale), but note it.
- **3-segment name is safe**: the gateway string is never re-parsed (only
  `to_string()` → `to_ns_name`/`RpcIpcClient::new`); `GenericNamespaced` accepts
  any name. Windows named-pipe path stays well under length limits.
- **Cross-platform**: no new OS-specific APIs. `TERM_WM_ENV` read via
  `std::env`; tests use `#[cfg(windows)]`-aware `current_os_user` unchanged.
