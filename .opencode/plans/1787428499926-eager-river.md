# Plan — Cross-workspace totals (#298/#290 follow-up) + Exit-label fix

Goal:
1. Stop Gateway Daemon dialog: windows and tasks = totals across ALL workspaces; tasks counted only while still running.
2. Command Palette WORKSPACES section: per-workspace running totals of windows and tasks.
3. Fix: Exit UI confirmation must use the dynamic brand label (currently raw `app_ctx().app_name`, i.e. hardcoded "term-wm").

Conventions: AGENTS.md applies (NO em/en dashes in comments/docs/changelog; consts for literals; cfg gates on session-persistence; saturating/cheap ops). Verify with:
```bash
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test
cargo test --workspace --no-default-features   # feature-gate compile gate
```

Architecture decision: PUSH model with a dedicated stats method (no change to ListChannels wire format).
Each WM publishes `(windows, tasks_running)` to the gateway whenever its counts change; the gateway caches per channel; the UI pulls the cache on its existing refresh cadence and at dialog open. Rationale: reads stay instant, writes are user-paced, version-skew degrades gracefully (older daemon => MethodNotFound => "unavailable"/omitted counts), and we avoid breaking `ChannelInfo` bitcode wire layout (the repo restarts daemons on upgrade, but a separate method is strictly safer and follows the KillClient/ListChannels templates exactly).

## Step 3 — WM publishes its own counts (ordered single writer)

File: `src/term-wm_app.rs` (+ call sites in `src/main.rs`).

Local live-task count: add
```rust
pub fn live_project_task_count(&self) -> usize {
    self.project_task_windows.keys().filter(|k| !self.exited_task_windows.contains(k)).count()
}
```
(`project_task_windows.len()` over-counts because ended task windows stay open; `exited ⊆ project_task_windows` while open, both purged together in `close_window` :600-604.)

Publishing MUST be strictly ordered: NO detached per-call threads (races could let a stale snapshot land after a newer one). Instead, one long-lived worker owns all reports:

- New fields (cfg session-persistence):
  - `stats_tx: Option<std::sync::mpsc::SyncSender<(u32, u32)>>`
  - `last_published_stats: Option<(u32, u32)>`
  - `const WM_STATS_QUEUE_CAPACITY: usize = 16;` and `const WM_STATS_REPORT_TIMEOUT_MS: u64 = 200;`
- Worker startup: `fn spawn_stats_reporter(&mut self)` creates a bounded `mpsc::sync_channel(WM_STATS_QUEUE_CAPACITY)`, stores the tx, and spawns ONE OS thread that loops:
  ```rust
  while let Ok((w, t)) = rx.recv() {
      let _ = term_session::report_wm_stats_bounded(WM_STATS_REPORT_TIMEOUT_MS, w, t);
  }
  ```
  Single consumer => FIFO delivery => strictly monotonic updates at the gateway even under rapid mutations. Thread exits when the app (and its tx clone) drops. Started lazily on first publish or at construction (cfg-gated).
- `publish_wm_stats(&mut self)` (cfg): skip when `!session_persistence_enabled()` or `stats_tx.is_none()`; snapshot `(user_window_count() as u32, live_project_task_count() as u32)`; dedup against `last_published_stats` (return if unchanged). Enqueue with `try_send` and update the dedup marker ONLY on success:
  ```rust
  if let Some(tx) = &self.stats_tx {
      if tx.try_send(snap).is_ok() {
          self.last_published_stats = Some(snap);
      }
  }
  ```
  Rationale: if the queue is saturated the snapshot was dropped, so `last_published_stats` must keep its PREVIOUS value; otherwise a later call with identical counts would short-circuit on the dedup guard and the dropped sample would never reach the gateway.
- Call sites (each after the mutation settles):
  - `spawn_terminal_window` success path
  - `close_window` (:600-604)
  - `on_terminal_exited` (:641-700, both purge and mark-exited branches)
  - `spawn_project_task` (:607-616)
  - once at startup: end of `App::new_with` in src/main.rs (publishes initial state even for zero windows)
- System windows already excluded via `user_window_count()`.

## Step 4 — UI aggregates totals

File: `src/term-wm_app.rs`.

Numeric types are `u32` end to end (wire type is u32; convert local usize once at the publish/aggregation boundary with `usize::from(u32)` / `as u32`).

- New cache `cached_wm_totals: WorkspaceTotals` (= `BTreeMap<String, (u32, u32)>`, keyed by WORKSPACE name parsed from each stats entry's channel via `ChannelName::parse_workspace`). Populated in `refresh_workspace_cache()` (:370-415) by one additional bounded call `list_wm_stats_bounded(GATEWAY_COUNT_TIMEOUT_MS)`; on error or timeout, CLEAR the map (unknown beats stale).
- Totals helper trusts the gateway's multi-client aggregation; local numbers are a FALLBACK ONLY for when the gateway has no data for us:
  ```rust
  pub fn total_windows_and_tasks_across_workspaces(&self) -> Option<(u32, u32)> {
      if self.cached_wm_totals.is_empty() {
          // Gateway cache unavailable (timeout, older daemon, offline):
          // fall back to what this instance knows locally.
          return Some((self.wm.user_window_count() as u32,
                       self.live_project_task_count() as u32));
      }
      let mut totals = self.cached_wm_totals.values().fold((0u32, 0u32), |acc, &(w, t)| {
          (acc.0.saturating_add(w), acc.1.saturating_add(t))
      });
      // Inject local numbers only when the gateway has no entry for OUR
      // workspace (e.g. our first report is still in flight). Never override:
      // an existing entry already includes OTHER clients' contributions.
      if !self.cached_wm_totals.contains_key(&self.current_workspace) {
          totals.0 = totals.0.saturating_add(self.wm.user_window_count() as u32);
          totals.1 = totals.1.saturating_add(self.live_project_task_count() as u32);
      }
      Some(totals)
  }
  ```
- `open_stop_gateway_confirm` (:1130-1158): replace local-only windows/tasks lines with totals:
  - Body becomes three clauses, sentence-case: active workspace sessions (unchanged logic), `Total windows: N`, `Running tasks: M`, where N/M come from the helper (which now always yields Some).
  - Keep the strict-timeout behavior; the whole body build stays within `GATEWAY_COUNT_TIMEOUT_MS` bounds (two bounded calls total).
- Update the dialog consts if wording changes (`GATEWAY_STOP_*` in term_wm_app.rs :44-56); keep dash-free strings.
