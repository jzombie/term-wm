# Plan: Add CI to ensure Dockerfile doesn't go out of date (#251)

## Goal

Ensure the `Dockerfile` (added in #249) cannot silently drift out of date as the
codebase evolves, and that its pinned base-image versions are kept current.

## What "goes out of date"

The Dockerfile pins `rust:1.97-alpine3.24` (build) and `alpine:3.24` (runtime),
while CI (`rust-tests.yml`, `rust-lint.yml`) compiles on `stable`. Drift modes:
- A dependency bump raises MSRV past 1.97 → `cargo build` inside the image fails
  while `stable` CI passes.
- New workspace members / build-required files outside the `COPY` list break
  the build.
- Base image tags (`rust:1.97-alpine3.24`, `alpine:3.24`) go stale or are
  removed upstream.

## Approach

1. **New workflow `.github/workflows/docker-build.yml`** that actually builds the
   image on every PR + push to `main` + a weekly schedule (catches upstream base
   image tag removal) + manual dispatch. Uses Buildx with GHA cache backend so
   uncached Rust release builds don't rebuild from scratch on every run.
2. **Add the `docker` package ecosystem to `.github/dependabot.yml`** so
   Dependabot opens PRs to bump the pinned `FROM` image tags proactively.

Note: an injected code review claimed an un-commented `Dockerfile` syntax error
(`Add/remove tools...`). Verification (`nl -ba`, byte dump via `od -c`, and

## Files to change

### 1. EDIT `Dockerfile` (cosmetic only — requested; no functional change)

Split line 39's inline comment onto two lines so the prose reads as separate
commented lines (both are already `#`-prefixed; the file passes `docker build
--check` either way):

```dockerfile
# Layer 2: apps installed into the image.
# Add/remove tools (htop, git, ...)
# here without touching the WM layer above.
# bash is the default shell fallback, used for spawned panes.
RUN apk add --no-cache bash htop
```

### 2. NEW `.github/workflows/docker-build.yml`

```yaml
name: docker-build

on:
  push:
    branches: [main]
  pull_request:
  schedule:
    - cron: '0 6 * * 1'
  workflow_dispatch:

# Ensure only one run per branch/PR at a time (matches rust-lint/rust-tests).
concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  build:
    name: build docker image
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v6

      # Buildx + docker-container driver is required for the GHA cache backend
      # (and gives cross-run layer caching for the cargo fetch/build layers).
      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v4

      - name: Build Docker image
        uses: docker/build-push-action@v7
        with:
          context: .
          file: ./Dockerfile
          push: false
          tags: term-wm:test
          load: true
          cache-from: type=gha
          cache-to: type=gha,mode=max

      # Smoke test: the runtime image actually starts the musl binary
      # (clap derives `version`, so `--version` exits 0 on headless runners).
      - name: Smoke test image
        run: docker run --rm term-wm:test --version
```

### 3. EDIT `.github/dependabot.yml`

Append a `docker` package-ecosystem entry so base image tags get update PRs:

```yaml
  - package-ecosystem: "docker"
    directory: "/" # Location of Dockerfile
    schedule:
      interval: "weekly"
```

## Verification

- Local (Docker 29.4.0 available):
  `docker build -t term-wm .` must succeed; then
  `docker run --rm term-wm --version` must print a version and exit 0.
- After pushing the branch / opening the PR, the `docker-build` workflow runs
  and must be green on `pull_request`.
- `cargo clippy --workspace --all-targets --all-features -- -D warnings` and
  `cargo test` are unaffected (no Rust code changes).
- Dependabot: config is validated by GitHub; a `docker` entry will surface as a
  pending update config once merged.
