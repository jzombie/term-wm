# Workspace Switch Fix — Updated Plan

## Root Cause: Double-Spawn on New Workspace

**File:** `src/main.rs:339-405`

The `NewWorkspace` handler calls `Attach` + `Spawn` on the new channel (creating an inner process), then calls `request_workspace_switch`. The outer launcher rebinds, and `run_session_with_control` (line 947-985) calls `Attach` + `Spawn` **again** on the same channel — two inner processes on one PTY.

The outer launcher's event loop detects the conflict: `client.is_connected()` returns false (line 1250) or `pane.has_exited()` (line 1262) → returns `ControlEvent::ClientExit` → outer launcher calls `return Ok(())` → shell drop.

## Fix: Strip `Attach` + `Spawn` from `NewWorkspace`

**File:** `src/main.rs:339-405`

Remove the entire `with_gateway` block (lines 349-389) that calls `Attach` and `Spawn`. The outer launcher's `run_session_with_control` handles both when it rebinds.

Replace with:

```rust
TermWmAction::NewWorkspace => {
    #[cfg(feature = "session-persistence")]
    {
        let ts = std::time::SystemTime::now()
            .duration_since(std::time::UNIX_EPOCH)
            .unwrap_or_default()
            .as_secs();
        let target_ws = format!("ws-{}", ts);

        let source_channel = format!("{}/main", self.current_workspace);
        if let Err(e) = term_session::request_workspace_switch(&source_channel, &target_ws) {
            tracing::error!("Failed to create workspace: {e}");
            self.inner.wm().push_notification(
                format!("Failed to create workspace: {e}"),
                std::time::Duration::from_secs(5),
            );
        } else {
            self.inner.refresh_workspace_cache();
            self.inner.wm().push_notification(
                format!("Created workspace: {target_ws}"),
                std::time::Duration::from_secs(3),
            );
        }
    }
    true
}
```

### Why this works

1. Inner process calls `request_workspace_switch("current/main", "ws-{ts}")`
2. Daemon sends `WorkspaceRebind("ws-{ts}")` frame to the outer launcher
3. Outer launcher sets `current_workspace = "ws-{ts}"` and `continue`s the loop
4. On next iteration, `run_session_with_control` calls `Attach` + `Spawn` on `ws-{ts}/main` — exactly one inner process, no conflict

### Also: Launcher fallback recovery (SEV-2)

**File:** `src/main.rs:128-169`

Track `last_working_workspace` and revert on `ClientExit`:

```rust
let mut current_workspace = cli.workspace.clone();
let mut last_working_workspace = current_workspace.clone();

// ... in the loop ...

ControlEvent::RebindWorkspace(target) => {
    last_working_workspace = target.clone();
    current_workspace = target;
    continue;
}
ControlEvent::ClientExit => {
    if current_workspace != last_working_workspace {
        current_workspace = last_working_workspace.clone();
        continue;
    }
    return Ok(());
}
```
