# Fix: Arrow Keys Not Scrolling Help Menu

## Root Cause

`ScrollViewComponent::on_key` (scroll_view.rs:368) does not intercept bare Up/Down arrow keys even in `ScrollKeyMode::Full` mode. The `ScrollKeyMode::Full` docs say it should handle "Up/Down/PageUp/PageDown/Home/End" but only PageUp/PageDown/Home/End are implemented. Arrow keys pass through to the child MarkdownViewerComponent → TextRendererComponent which returns `EventResult::Ignored`.

Terminal uses `ScrollKeyMode::PaginationOnly` (arrow keys must pass through for shell history), so it is **not affected**.

## Changes

### 1. `crates/term-wm-ui-components/src/scroll_view.rs`

**Add import** at line 7:
```
use term_wm_core::events::{Event, KeyCode, MouseEvent, MouseEventKind};
```

**Add arrow key interception in `on_key`** — insert after the `ScrollEnd` match (after line 392), before falling through to child delegation (line 395):

```rust
// Full mode also intercepts bare Up/Down for line scrolling
if self.keyboard_mode == ScrollKeyMode::Full
    && key.modifiers == KeyModifiers::NONE
{
    match key.code {
        KeyCode::Up => return EventResult::Action(TermWmAction::ScrollView(-1)),
        KeyCode::Down => return EventResult::Action(TermWmAction::ScrollView(1)),
        _ => {}
    }
}
```

`KeyModifiers` already available via `use term_wm_core::events::...`.

**Why `KeyModifiers::NONE` guard?** — Matches the existing keybinding pattern (PageUp/PageDown only intercepted with NONE modifier). Prevents intercepting Ctrl+Up/Alt+Up/etc., which would break the existing `scroll_view_modifier_chords_pass_through` test.

**Update test `scroll_view_full_mode_passes_arrow_keys`** — rename to `scroll_view_full_mode_intercepts_arrow_keys`, change assertions: Up/Down should produce `Action(ScrollView(-1))` / `Action(ScrollView(1))` not `Ignored`. Assert child did NOT receive the event.

**No changes needed to** `scroll_view_modifier_chords_pass_through` — Ctrl+Up still passes through thanks to the modifier guard.

## Event Flow After Fix

1. User presses `Down` in help overlay
2. `WmHelpOverlayComponent::handle_events` → delegates to `self.content.handle_events(event, ctx)` (ScrollViewComponent, line 87)
3. `ScrollViewComponent::on_key` → `ScrollKeyMode::Full` + bare `Down` → returns `EventResult::Action(ScrollView(1))`
4. `handle_help_event` (overlays.rs:65-72) calls `boxed.update(action, &ctx, &mut queue)`
5. `WmHelpOverlayComponent::update` → `self.content.update(action, ctx, actions)`
6. `ScrollViewComponent::update` handles `ScrollView(1)`: increments `scroll_state.offset_y`
7. Next render pass renders content at new offset
