# Fix: `term-session` new channels spawn in daemon's cwd, not the caller's

## Root cause

`term-session` is a client that talks to a long-lived detached gateway daemon over muxio IPC. When a NEW channel is created, the PTY child is spawned **inside the daemon process**, and its working directory is set to `std::env::current_dir()` evaluated in the daemon — which is frozen at daemon startup (inherited from whoever first auto-spawned it). The caller's cwd is **never transmitted**: the `Spawn` RPC payload (`crates/term-session-muxio-service-definitions/src/methods.rs:69-74`) carries only `cmd`, `cols`, `rows`.

Chain:
1. `crates/term-session-client/src/lib.rs:405-413` — client sends `(cmd, cols, rows)`; never reads its own cwd.
2. `crates/term-session-server/src/session_server.rs:627` decodes 3-tuple; line 699 calls `Session::spawn(...)`.
3. `crates/term-session-server/src/session.rs:21-22,49-50` — `builder.cwd(std::env::current_dir())` = **daemon's** cwd.
4. `crates/term-session/src/auto_spawn.rs:127-154` — daemon inherits the first launcher's cwd and keeps it forever.

## Fix (minimal): thread the client's cwd through the `Spawn` RPC

Per user decision: respawn behavior doesn't matter (live sessions are joined, cwd is irrelevant); always use the spawning client's cwd for any new spawn.

### 1. Wire protocol — `crates/term-session-muxio-service-definitions/src/methods.rs`
- Add `pub cwd: Option<String>` to `SpawnRequest` (lines 69-74).
- Change `Spawn::type Input` from `(Option<Vec<String>>, u16, u16)` to `(Option<Vec<String>>, u16, u16, Option<String>)` (line 88).
- Update `encode_request` (line 91-97) and `decode_request` (line 99-103) to carry `input.3` / return `r.cwd`.

### 2. Client — `crates/term-session-client/src/lib.rs`
- In `run_session`, before the `Spawn::call` (lines 404-413), capture the launch dir:
  `let launch_cwd = std::env::current_dir().ok().map(|p| p.to_string_lossy().into_owned());`
- Pass it as the 4th tuple element: `Spawn::call(&*client, (cmd, term_cols, term_rows, launch_cwd))`.

### 3. Server handler — `crates/term-session-server/src/session_server.rs`
- Line 627: `let (cmd, cols, rows, cwd) = Spawn::decode_request(&payload)?;`
- After the `effective_cmd` block (line 686-697), add:
  `let effective_cwd = cwd.filter(|c| !c.is_empty());`
- Line 699: pass it through —
  `Session::spawn(id, effective_cmd, cols, rows, Some(&channel), effective_cwd.as_deref())?;`

### 4. Session spawn — `crates/term-session-server/src/session.rs`
- Add a `cwd: Option<&str>` parameter to `Session::spawn` (line 27-34).
- Resolve the working directory once: use the provided `cwd` when present, else fall back to `std::env::current_dir()` (preserves behavior for legacy clients that send `None` / `current_dir()` failure).
- Apply `builder.cwd(resolved)` in both branches (default shell at line 53-59, explicit cmd at line 41-52). Keep `default_shell_command()` but have it set the cwd from the caller-provided value via the unified resolution so it can't override the client's cwd.

### 5. Fix existing test call sites — `crates/term-session/tests/daemon_tests.rs`
All 6 `Spawn::call` sites (lines 138, 158, 191, 408, 422, 632, 670) now need the 4th element `None`:
`Spawn::call(&*client, (cmd, 80u16, 24u16, None))`.

## Verification

### Regression test (recommended, follows repo's mock-bin E2E pattern)
- `crates/term-session-mock/src/main.rs`: add a `pwd <file>` subcommand that writes `std::env::current_dir()` (the child process's actual cwd) to an absolute file path and exits.
- `crates/term-session/tests/daemon_tests.rs`: new test `session_starts_in_client_cwd`:
  1. Create two distinct temp dirs (daemon dir, client dir).
  2. Spawn the daemon with `.current_dir(daemon_dir)` (add a cwd param to the `spawn_daemon` helper or a variant).
  3. Attach and `Spawn::call(&*client, (Some(vec![mock, "pwd", file]), 80, 24, Some(client_dir)))`.
  4. Read the file; assert it equals `client_dir` (not `daemon_dir`). Without the fix this fails (reports daemon dir).

### Manual end-to-end
1. `term-session stop` (a running old daemon can't decode the new `Spawn` payload; the client's existing `abi_fault` handler already diagnoses this).
2. `cd /tmp/a && term-session chan-a` → prompt must show `/tmp/a`.
3. `cd /tmp/b && term-session chan-b` → prompt must show `/tmp/b` (previously `/tmp/a`, the daemon's cwd).

## Notes / constraints
- **Protocol ABI change**: bitcode is non-self-describing; adding a field breaks decoding against an old daemon. The client's `abi_fault` error path (`crates/term-session-client/src/lib.rs:331-335`) already produces the "legacy daemon occupying the socket" diagnostic — no new handling needed. Upgrading requires restarting the daemon.
- **Cross-platform**: `std::env::current_dir()` and `CommandBuilder::cwd` are portable (Windows `CreateProcessW lpCurrentDirectory` handled by `portable-pty`). Path → `String` uses `to_string_lossy` (non-UTF8 paths are rare and acceptable on the wire).
- No `ChannelState` / respawn-template changes needed (per user decision; client always sends a non-empty cwd).
- All coordinate/size arithmetic untouched — no terminal-size concerns.
