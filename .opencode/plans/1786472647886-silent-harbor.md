# Anchored Command Palette + Reusable Anchor Placement

## Goal

When the command palette is opened via a mouse click, anchor it to the hitbox that
triggered it (top-left hamburger, bottom-left shortcut, FAB / term-wm button), shown
as an adjacent popup that auto-flips to stay on-screen. Keyboard-opened palettes
stay centered. The positioning logic must be a reusable primitive so any element can
be anchored.

Secondary (user-specified) behavior: the palette must keep a **stable size** computed
from the full unfiltered item list (no bouncing while typing). When anchored, the full
palette background is drawn; when unanchored (centered), only the rows are backgrounded
(Spotlight-like), while the stable allocation/position is preserved.

## Architecture recap (verified)

- Triggers return `TermWmAction::OpenCommandPalette`: FAB (`wm_fab.rs:116`), top-panel
  hamburger (`wm_top_panel/mod.rs:283`), bottom-panel hint (`wm_bottom_panel.rs:370`),
  empty-state placeholder (`window_manager/mod.rs:1898`).
- `WindowManager::dispatch_mouse` hit-tests and has the triggering `hit_rect` in scope
  (`mod.rs:1802`), then returns the action to the runner.
- Runner (`runner.rs:209-216`) calls `app.open_command_palette()`.
- `TermWmApp::open_command_palette` (`term_wm_app.rs:543`) builds a
  `WmCommandPaletteComponent`, shows it, sets items, and inserts it as an overlay.
- Rendering (`draw_plan_renderer.rs:936`) passes `wm.managed_area()` as `area`;
  `WmCommandPaletteComponent::render` centers via `dialog.rect_for(...)`.
- `CommandPaletteComponent::render` fills its entire given rect with `menu_bg`
  (`command_palette.rs:593-605`) — this is the "full background". A smaller rect
  produces a "rows-only" box automatically.
- `MousePosition`/`LayoutRect` provide pure geometry helpers; layout-engine is the
  no-dependency geometry crate.

## Design

### Design contract (resolves the "stable size" vs "rows-only background" tension)

Two distinct quantities, per the user's two explicit requirements:

- **Allocation / footprint** (`content_rect`, and therefore `dialog_bounds`) is the
  **stable full size** (computed once from the unfiltered item list). It never changes
  while typing → the palette's position, anchor, hit-test, dismissal and shadow never
  bounce. This satisfies *"use that same full size, so that it does not bounce around
  when filtering results."*
- **Filled / backgrounded region** (`rows_rect`) covers only the search bar + displayed
  rows and **varies with the filtered row count** — this is the Spotlight effect the user
  explicitly asked for (*"only background the rows (similar to the effect of spotlight)"*).
  It is always **top-pinned** to `content_rect` (same x and y), so only its bottom edge
  grows/shrinks; the box never moves. A stable-size filled region was considered and
  rejected: it would render a solid full-size box identical to the anchored case and
  eliminate the user-specified rows-only look entirely.

`rows_rect` invariants (asserted in tests):
- `rows_rect ⊆ content_rect` (x/y equal to `content_rect`, `height ≤ content_rect.height`).
- `rows_rect.height = 1 + min(content_rect.height.saturating_sub(1), display_nodes.len())`
  (saturating — never underflows; zero results still yields the search-bar row).
- `content_rect`/`dialog_bounds` is byte-for-byte identical across renders with different
  filter states (stable allocation).

### 1. Reusable primitive — `term-wm-layout-engine/src/anchor.rs` (new)

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum AnchorPlacement {
    BelowLeft, BelowRight, AboveLeft, AboveRight,
}

/// Place `content_size` adjacent to `anchor` per `placement`, flipping to the
/// opposite side when the preferred side overflows `bounds`, then saturating-
/// clamp into `bounds`. Pure function — reusable for any element.
pub fn place_anchored(
    anchor: LayoutRect,
    content_size: (u16, u16),
    placement: AnchorPlacement,
    bounds: LayoutRect,
) -> LayoutRect
```

Rules (order matters — **truncate size FIRST, then position**):
1. `let w = content_size.0.min(bounds.width); let h = content_size.1.min(bounds.height);`
   — the returned rect is **never larger than `bounds`**, regardless of `content_size`
   (guards small-terminal / post-resize cases where `content_size` exceeds `bounds` and
   would otherwise make later buffer slices in `draw_plan_renderer` go out of bounds).
2. Preferred corner: `Left` = align left edge to `anchor.x`; `Right` = align right edge
   to `anchor` right; `Below` = below `anchor` bottom; `Above` = above `anchor` top.
3. Auto-flip vertical if the preferred y overflows, horizontal if x overflows.
4. Final saturating clamp of the origin:
   `x ∈ [bounds.x, bounds.x + bounds.width − w]`, `y ∈ [bounds.y, bounds.y + bounds.height − h]`
   (all `saturating_add/sub`), so the strict post-condition holds:
   `rect.x + rect.width ≤ bounds.x + bounds.width` and
   `rect.y + rect.height ≤ bounds.y + bounds.height`.
- Unit tests: each placement corner; flip at each of the four edges; clamp; content larger
  than bounds (dimensions truncated, rect fully inside bounds); zero-size bounds.

Export from `crates/term-wm-layout-engine/src/lib.rs`:
`mod anchor; pub use anchor::{AnchorPlacement, place_anchored};`

### 2. `DialogOverlayComponent` — reusable anchored dialog (`dialog_overlay.rs`)

- `pub fn rect_for_anchored(&self, area: Rect, anchor: LayoutRect, placement: AnchorPlacement) -> Rect`
  — same size-clamp logic as `rect_for`, then `place_anchored(anchor, (width, height), placement, bounds)`.
- `pub fn handle_click_outside_rect(&mut self, event: &Event, rect: Rect) -> bool`
  — refactor of `handle_click_outside` that checks against an explicit rect (the
  existing `handle_click_outside(event, area)` delegates to it with `rect_for(area)`).
- Keep `rect_for` (centered) unchanged for confirm/help overlays.

`rect_for_anchored` must apply the same size clamp as `rect_for` (`width.min`, `height.min`,
24/5 min-floors) **before** calling `place_anchored`, so `place_anchored` is handed a size
already ≤ `area` and its own truncation is a no-op in the dialog path (still required for
standalone reuse). Post-condition: returned `Rect` lies fully inside `area`.

### 3. `WmCommandPaletteComponent` (`wm_command_palette.rs`)

New fields:
- `anchor: Option<(LayoutRect, AnchorPlacement)>` + `pub fn set_anchor(&mut self, Option<LayoutRect>)`
  (placement defaulted to `AnchorPlacement::BelowLeft`; auto-flip handles FAB/shortcut).
- `stable_size: (u16, u16)` — computed once in `set_items` from the full unfiltered
  `MenuDisplayItem` list (rows incl. collapsed separators + max label width, same
  `+2`/`min(20)`/`min(30)` heuristics as `compute_content_dimensions`).
  `compute_content_dimensions()` now returns `stable_size` instead of reading live
  filtered data.

New helper used by `render` and `handle_events` (keeps draw + hit-test consistent):
```rust
fn dialog_rect(&self, area: LayoutRect) -> LayoutRect {
    // anchored: dialog.rect_for_anchored(area, anchor, placement)
    // else: dialog.rect_for(area)   (centered)
}
```

Render changes (`is_tab_outline_active` path and normal path):
- Compute `content_rect = dialog_rect(area)` (stable size). `dialog_bounds = content_rect`
  (stable in both modes — used by `render_area()`/shadows).
- **Anchored**: current behavior — `render_backdrop(area, exclude=content_rect)`, `Clear`
  on the rect, `palette.render(content_rect, ...)` (full background).
- **Unanchored (centered)**: compute `rows_rect` = search row + visible display rows,
  top-aligned within `content_rect`:
  `height = 1 + min(content_rect.height.saturating_sub(1), display_nodes.len())`. Draw
  `render_backdrop(area, exclude=rows_rect)`, `Clear` rows_rect, `palette.render(rows_rect, ...)`.
  The palette fills `rows_rect` fully, so it looks like a Spotlight box hugging the rows;
  the trailing area inside `content_rect` is dimmed backdrop. Position never jumps because
  `rows_rect` is top-anchored to the stable centered `content_rect`.

`handle_events` changes:
- Dismissal uses the *drawn* rect via `handle_click_outside_rect` (content_rect when
  anchored, rows_rect when unanchored) so clicks in the transparent zone close the palette.
- Route to `palette.handle_events` with the drawn rect (matches `last_list_area`).

### 4. WindowManager plumbing (`window_manager/mod.rs`, `command_palette.rs`)

Anchor state lifecycle — the field is **valid only within a single mouse-dispatch cycle**,
so a keyboard open can never consume stale mouse state:

- Add field `pending_palette_anchor: Option<LayoutRect>` (near `hover`, ~line 330).
- **Clear it at the start of `dispatch_mouse`** (`self.pending_palette_anchor = None;` before
  the hit-test), so the field is `None` at the start of every input pass and only becomes
  `Some` when the *same* dispatch produces an `OpenCommandPalette` result.
- In `dispatch_mouse` Phase 2, record the trigger rect when the produced action is
  `OpenCommandPalette`:
  - Wrap the owner-match result (line 1943) with
    `if matches!(result, EventResult::Action((_, TermWmAction::OpenCommandPalette))) { self.pending_palette_anchor = Some(hit_rect); }`.
  - In the `ChromeTarget::EmptyStatePlaceholder` arm (line 1898) set it before returning.
- `pub fn take_pending_palette_anchor(&mut self) -> Option<LayoutRect>` (`take()`).
- The runner consumes it synchronously in the same event cycle (`open_command_palette()`
  takes it). Every `OpenCommandPalette` result is either an open (take clears it) or a
  close (`close_command_palette` clears it) — so no stale state survives an event cycle.
- In `close_command_palette` (`command_palette.rs:58`) set `self.pending_palette_anchor = None`
  (belt-and-suspenders for the toggle-close path).

Result: a keyboard trigger (`dispatch_action`/keybinding, which never runs through
`dispatch_mouse`) always sees `None` → centered. Guaranteed by: start-of-dispatch clear +
consumption-on-open + clear-on-close.

### 5. App wiring (`src/term_wm_app.rs`)

In `open_command_palette` (line 543): `let anchor = self.wm.take_pending_palette_anchor();`
then `palette.set_anchor(anchor);` before `open_command_palette_overlay(...)`.

## Follow-up fix — "no results" state

### Symptom
When a query filters out **every** item, the palette disappears completely instead of
leaving the search bar in place with a no-results hint.

### Root cause
- `WmCommandPaletteComponent::drawn_rect` (centered/unanchored) computes
  `height = 1 + min(content.height - 1, display_nodes.len())` → collapses to **1** row.
- `CommandPaletteComponent::render` early-returns when `rect.height < 2`
  (`command_palette.rs:541`), so nothing is drawn; the dimmed backdrop covers the
  whole managed area → the palette looks gone.

### Changes

1. `crates/term-wm-sys-ui-components/src/wm_command_palette.rs` — `drawn_rect`:
   when `display_nodes.is_empty()`, floor the height at **2 rows**
   (`2.min(content_rect.height)`) so the search bar + a no-results row always fit.
   Add a named `const NO_RESULTS_MIN_HEIGHT: u16 = 2` (magic-number rule).
   Anchored case is unchanged (already renders the full `content_rect`).

2. `crates/term-wm-ui-components/src/command_palette.rs`:
   - Add `const NO_RESULTS_PLACEHOLDER: &str = "[no search results]";`
     (matches the bracket style of the `[type to search]` search-bar placeholder).
   - Add `fn render_no_results(&self, buffer, area: Rect, theme)` — draws the
     placeholder centered in the first list row, styled like the search-bar
     placeholder (`menu_bg` bg + `panel_inactive_fg` fg), via `safe_set_string`
     (clamps to area).
   - In `render`, after `self.list_scroll.render(...)`, when
     `self.display_nodes.is_empty()`, call `render_no_results` with the list area
     (rows 1.. converted with `layout_rect_to_clipped_rect`).

### Tests
- `wm_command_palette.rs`: update `zero_results_still_shows_search_bar` to assert
  `rows.height == 2` (search bar + no-results row; still top-pinned to content rect).
- `command_palette.rs`: new render test — palette with empty `display_nodes` renders
  the search-bar row **and** a row containing `[no search results]` (inspect buffer
  cell symbols, following the `label.rs`/`list.rs` buffer-assert pattern).

## ClearQuery binding — Ctrl+C clears the palette search (through the main keybindings)

### Symptom / request
While the command palette's search bar is populated, pressing Ctrl+C should clear the
query (restoring the full item list). The binding must route through the **main
keybindings table** (`WmConfig.keybindings` / `KeyBindings::default()`), not a hardcoded
check inside the component.

### Key facts (verified)
- **Ctrl+C is currently unbound** in the default table (`keybindings.rs:89`); there is no
  `Copy`/`Interrupt` action. Today, with the palette open, Ctrl+C reaches
  `CommandPaletteComponent::handle_events` (`command_palette.rs:650-704`), fails the
  `!key.modifiers.control` char guard, falls to `_ => EventResult::Ignored` (line 702),
  and is swallowed by the palette barrier. Locked in by `ctrl_chars_ignored`
  (`command_palette.rs:936-953`).
- **Dismiss semantics**: `WindowManager::handle_command_palette_event`
  (`window_manager/command_palette.rs:88-92`) closes the palette on **any**
  `EventResult::Action`. A clear must return **`EventResult::Consumed`** so the palette
  stays open.
- **Main-table lookup from a component**: `ComponentContext::config` is always populated
  (overlay ctx in `handle_command_palette_event`, and `ComponentContext::new(true)` →)
  `WmConfig::default()` in tests). Established pattern: `ScrollViewComponent` uses
  `ctx.config().keybindings` (`scroll_view.rs:385-416`). The `with_keybindings` context
  channel is dead (zero callers) — do NOT wire it up.
- Adding a `TermWmAction` variant only requires updating `category()` and `Display`
  (both exhaustive, `actions.rs:225-307` and `328-408`); `layer()` (wildcard → CommandPalette),
  `bottom_hint_priority()` (wildcard → None), and `dispatch_action` (catch-all
  `action =>`, `runner.rs:163`) need no change. `default_keybindings_is_not_empty` only
  asserts non-empty.

### Changes

1. **`crates/term-wm-core/src/actions.rs`** — add variant in the "Universal input mode
   actions" section, right after `CloseCommandPalette` (line 124):
   ```rust
   /// Clear the command palette's search query (main keybindings table).
   ClearCommandPaletteQuery,
   ```
   Then update the two exhaustive matches:
   - `category()`: append `| TermWmAction::ClearCommandPaletteQuery` to the
     `Category::Windows` group (next to `OpenCommandPalette`/`CloseCommandPalette`, line 260).
   - `Display`: add `TermWmAction::ClearCommandPaletteQuery => "Clear command palette query",`
     (near line 388).

2. **`crates/term-wm-core/src/keybindings.rs`** — register the default binding inside the
   `default_keybindings!` block (line ~89):
   ```rust
   ClearCommandPaletteQuery: [ (KeyCode::Char('c'), KeyModifiers { control: true, shift: false, alt: false }) ],
   ```
   No collision (Ctrl+C unbound). Rebinding possible via `AppBuilder::keybindings`.

3. **`crates/term-wm-ui-components/src/command_palette.rs`** — in
   `CommandPaletteComponent::handle_events`, after the `nav_keys` checks (line 687) and
   before the `match key.code` block (line 690), add:
   ```rust
   if !self.query.is_empty()
       && ctx
           .config()
           .keybindings
           .matches(TermWmAction::ClearCommandPaletteQuery, key)
   {
       self.query.clear();
       self.cursor = 0;
       self.query_dirty = true;
       return EventResult::Consumed;
   }
   ```
   - `Consumed` (not `Action`) keeps the palette open — the WM closes it on any `Action`.
   - `query_dirty = true` → `refresh_if_dirty` re-runs `rerank_with_registry` with the empty
     query, restoring the full list.
   - `!self.query.is_empty()` gate: the binding is active only when the search bar is
     populated. With an empty bar Ctrl+C stays `Ignored` (same as today — the lookup
     short-circuits and never even consults the table).
   - **Cursor-sync invariant** (review AMEND): also reset `self.cursor = 0`. The field
     (`cursor`, `command_palette.rs:57`) is currently only ever *reset* — never read for
     slicing today — so this is not a live-panic fix, but it mirrors the exact reset
     sequence already used on palette open (`wm_command_palette.rs:413-417`:
     `query.clear(); cursor = 0; selected = 0;`) and guarantees a stale `cursor` can never
     be inherited by future cursor-positioned editing (mid-string insertion, `Delete`,
     cursor rendering) that slices `query` by index.

## Follow-up: Ctrl+C dismisses the palette when the search bar is empty

### Request / rationale
Make the Ctrl+C binding a full cancel gesture: **populated query → clear** (current
behavior); **empty query → close the palette** (same as Esc). Standard launcher idiom;
unifies "interrupt/cancel" under one key.

### Behavior
- Populated search → unchanged: clear `query` + `cursor = 0`, `query_dirty = true`,
  return `EventResult::Consumed` (palette stays open).
- Empty search → return `EventResult::Action(TermWmAction::CloseMenu)`. This is byte-for-byte
  the same result Esc already produces (`command_palette.rs:706`), so it flows through the
  unchanged chain: `WmCommandPaletteComponent` passes `CloseMenu` through
  (`wm_command_palette.rs:331`) → `WindowManager::handle_command_palette_event` closes the
  palette and returns `Some(CloseMenu)` (`window_manager/command_palette.rs:88-92`).
- Other Ctrl+letter combos remain `Ignored` — the lookup only fires for the combo bound to
  `ClearCommandPaletteQuery`.

### Change (single edit, `crates/term-wm-ui-components/src/command_palette.rs:689-702`)
Swap the two conditions; the binding check runs first (cheap `matches` on one action, same
per-key cost scroll_view already pays), then branch on emptiness:
```rust
if ctx
    .config()
    .keybindings
    .matches(TermWmAction::ClearCommandPaletteQuery, key)
{
    if self.query.is_empty() {
        return EventResult::Action(TermWmAction::CloseMenu);
    }
    self.query.clear();
    self.cursor = 0;
    self.query_dirty = true;
    return EventResult::Consumed;
}
```
Update the block's trailing comment (currently says "active only while the search bar is
populated").

### Tests

  `ctrl_c_closes_when_query_empty` — empty query + Ctrl+C →
  `matches!(result, EventResult::Action(TermWmAction::CloseMenu))`, query stays empty.
  `ctrl_c_clears_populated_query` and

- `wm_command_palette.rs`: add `ctrl_c_empty_query_closes_palette` — empty query + Ctrl+C
  through `WmCommandPaletteComponent::handle_events` →
