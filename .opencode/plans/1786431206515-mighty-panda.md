# PART A — New `term-sys-io` leaf crate + extract clipboard into `term-clipboard` (+ standalone CLI)

## A0. New leaf crate `crates/term-sys-io` — all FD/handle redirection in one place

`term-sys-io` is a zero-heavy-dep leaf crate that centralizes **every** unsafe
process-global FD/`STDERR` manipulation. It is the single home for both `StderrSuppressGuard`
(see A2) and the pipe-redirection helpers, and it sits at the bottom of the dependency graph so
`term-clipboard`, `term-wm-pty-engine`, `term-session-client`, and the root package all depend
downward on it with no cycles.

### Dependency topology

```
                 term-sys-io (leaf: libc + tracing only, all unsafe FD/handle code)
                    ▲               ▲               ▲               ▲
                    │               │               │               │
        term-clipboard   term-wm-pty-engine   term-session-client   root (logging)
             ▲               ▲
             └───────────────┴────── term-wm-core
```

## A2. `StderrSuppressGuard` thread safety (SEV-2.1)

The guard now lives in `term-sys-io`, but the design is unchanged from the earlier plan:
`dup2` on `STDERR_FILENO` is process-global; `arboard` calls can race with `tracing` logging
or parallel tests. Serialize with a process-global mutex held for the guard's lifetime:

```rust
/// Serialises process-global stderr redirection across threads.
static STDERR_MUTEX: std::sync::Mutex<()> = std::sync::Mutex::new(());

#[cfg(unix)]
pub struct StderrSuppressGuard {
    saved_fd: libc::c_int,
    _lock: std::sync::MutexGuard<'static, ()>,   // field order: Drop restores fd first, then releases lock
}
```

- `new()` acquires the lock **first** (poison-recover via `.unwrap_or_else(|e| e.into_inner())`),
  then performs the existing open/dup/dup2 dance. On early `None` return (open failure) the lock
  drops naturally.
- `Drop` restores the original fd (existing body); the `_lock` field drops after `Drop::drop`,
  releasing the mutex post-restore.
- Apply the same lock field to the `#[cfg(windows)]` impl. The fallback impl
  (`#[cfg(not(any(unix, windows)))])` performs no redirection → no lock needed.
- The moved test runs single-threaded and is unaffected.

## A3. Standalone binary `src/bin/term-clipboard.rs` (SEV-2.3, via clap)

**Amendment (user):** the CLI parser is **clap derive** — the repo convention
(`term-wm`, `term-bench`, `term-session` all use clap) — replacing the earlier
hand-rolled `std::env::args_os()` scanner and hard-coded `USAGE` string. This still
satisfies SEV-2.3's determinism concern: clap enforces flag-anywhere + single-positional
semantics and generates the usage/help text.

```rust
use std::path::PathBuf;
use std::process::ExitCode;

use clap::Parser;
use term_clipboard::{Clipboard, set_via_osc52_with_writer};

/// Copy text to the clipboard (system + OSC 52), cross-platform.
#[derive(Parser, Debug)]
#[command(
    name = env!("CARGO_PKG_NAME"),
    version = env!("CARGO_PKG_VERSION"),
    about = env!("CARGO_PKG_DESCRIPTION"),
    long_about = concat!(
        env!("CARGO_PKG_NAME"), " ", env!("CARGO_PKG_VERSION"), ": ",
        env!("CARGO_PKG_DESCRIPTION"),
        "\n\nReads UTF-8 text from FILE (or stdin when omitted) and copies it to the ",
        "clipboard.  Default mode uses the full Clipboard pipeline (shared in-memory ",
        "buffer -> arboard -> OSC 52); --osc52 emits the OSC 52 escape sequence to ",
        "stdout only.  Only UTF-8 text is supported; binary input is an error (exit code 1)."
    ),
)]
struct Cli {
    /// Emit the OSC 52 escape sequence to stdout only (no arboard).
    #[arg(long)]
    osc52: bool,

    /// Text to copy, read as UTF-8.  When omitted, reads from stdin.
    file: Option<PathBuf>,
}

fn main() -> ExitCode {
    let cli = Cli::parse();
    let text = match read_input(cli.file) {
        Ok(text) => text,
        Err(msg) => {
            eprintln!("term-clipboard: {msg}");
            return ExitCode::FAILURE;
        }
    };
    let result = if cli.osc52 {
        let mut out = std::io::stdout().lock();
        set_via_osc52_with_writer(&text, &mut out)
    } else {
        let mut cb = Clipboard::new();
        cb.set(&text);
        Ok(())
    };
    match result {
        Ok(()) => ExitCode::SUCCESS,
        Err(e) => {
            eprintln!("term-clipboard: error: {e}");
            ExitCode::FAILURE
        }
    }
}
```

- `Cli::parse()`: `--osc52` accepted in any position; at most one `[FILE]` positional
  (a second is a clap error); `-h`/`--help` and `--version` handled automatically.
- **Exit codes:** clap parse errors (unknown flag, too many positionals) exit with clap's
  default **`2`**; `--help`/`--version` exit `0`. Runtime errors below stay **`1`**. This is
  a deliberate, documented deviation from SEV-2.3's "exit 1 on invalid flags" — the
  determinism requirement (no flag/positional ordering bugs) is fully preserved.

Read path (unchanged shape, takes `Option<PathBuf>`):
- File: `File::open(path)` **first** (validates readability; missing/unreadable → clean
  `error: cannot read <path>: <io>` to stderr, exit `1`), then `read_to_string`.
- Stdin: `std::io::read_to_string(std::io::stdin().lock())`.
- Either source producing **non-UTF-8** → `error: input is not valid UTF-8`, exit `1`.

Dispatch:
- `--osc52`: `set_via_osc52_with_writer(&text, &mut std::io::stdout().lock())?`; on `Err` →
  stderr + exit `1`. No arboard.
- default: `let mut cb = Clipboard::new(); cb.set(&text);` (infallible fan-out: shared
  in-memory → arboard → OSC 52, exactly the existing behavior).

Non-UTF-8 file *contents* are out of scope (document in `long_about`); non-UTF-8
*filenames* are fine (`PathBuf` + `to_string_lossy` in error messages).

# PART B — Wrap-aware selection copy (line joining)

## Root cause

`TerminalComponent::selection_text_for_range`
(`crates/term-wm-ui-components/src/terminal.rs`, lines 878–959) unconditionally inserts `\n`
between every pair of selected rows (lines 953–955), corrupting soft-wrapped lines. The fork
already exposes the distinction via `Screen::row_wrapped(row)` (viewport-relative; returns
`false` for out-of-bounds rows).

## B1. Core fix — `selection_text_for_range` (SEV-1.1 + SEV-1.2)

In the pagination loop (lines 928–956). `viewport_row` at **line 933** is already the correct
viewport-relative index for the row *after* `set_scrollback(offset)` at line 931
(`viewport_start = absolute_row.min(vt100_max_scrollback)`; `viewport_row = absolute_row - viewport_start`).
SEV-1.1: **use that value** — never pass `absolute_row` to `row_wrapped` — and bounds-check
defensively against `viewport_rows` (captured at line 889 from `screen.size()`).

```rust
let line = guard
    .screen
    .contents_between(viewport_row, col_start, viewport_row, col_end);

// SEV-1.2: never let width-padded grid cells (or gap spaces) leak into the
// middle of a joined continuous string from a soft-wrapped row.
let wrapped = guard.screen.row_wrapped(viewport_row);
let line = if wrapped {
    line.trim_end_matches(' ').to_owned()
} else {
    line
};
result.push_str(&line);

// SEV-1.1: `viewport_row` (line 933) is the viewport-relative index; the
// bounds check is defensive — `row_wrapped` is OOB-safe (returns false).
if absolute_row < vt100_end_row
    && viewport_row < viewport_rows
    && !wrapped
{
    result.push('\n');
}
```

Notes:
- `row_wrapped` is queried per-row **after** the existing `set_scrollback()` pagination, so it
  is correct for both viewport and scrollback selections.
- SEV-1.2 trim is defensive: the fork's `Row::write_contents` already strips trailing empty
  cells, so in the current `contents_between` path it is normally a no-op. It guards against
  grid padding leaking via any raw-row path and against internal gap spaces at a wrap seam.
  Tradeoff: a wrapped row whose *actual* content ends in spaces would lose them (matches the
  "join with nothing" behavior of mainstream terminals).
- Join-with-nothing is unconditional (no config flag). Genuine `\r\n` rows keep their `\n`
  because those rows are `wrapped == false`.
