# PART A — New `term-sys-io` leaf crate + extract clipboard into `term-clipboard` (+ standalone CLI)

## A0. New leaf crate `crates/term-sys-io` — all FD/handle redirection in one place

`term-sys-io` is a zero-heavy-dep leaf crate that centralizes **every** unsafe
process-global FD/`STDERR` manipulation. It is the single home for both `StderrSuppressGuard`
(see A2) and the pipe-redirection helpers, and it sits at the bottom of the dependency graph so
`term-clipboard`, `term-wm-pty-engine`, `term-session-client`, and the root package all depend
downward on it with no cycles.

## A2. `StderrSuppressGuard` thread safety (SEV-2.1)

The guard now lives in `term-sys-io`, but the design is unchanged from the earlier plan:
`dup2` on `STDERR_FILENO` is process-global; `arboard` calls can race with `tracing` logging
or parallel tests. Serialize with a process-global mutex held for the guard's lifetime:

```rust
/// Serialises process-global stderr redirection across threads.
static STDERR_MUTEX: std::sync::Mutex<()> = std::sync::Mutex::new(());

#[cfg(unix)]
pub struct StderrSuppressGuard {
    saved_fd: libc::c_int,
    _lock: std::sync::MutexGuard<'static, ()>,   // field order: Drop restores fd first, then releases lock
}
```

- `new()` acquires the lock **first** (poison-recover via `.unwrap_or_else(|e| e.into_inner())`),
  then performs the existing open/dup/dup2 dance. On early `None` return (open failure) the lock
  drops naturally.
- `Drop` restores the original fd (existing body); the `_lock` field drops after `Drop::drop`,
  releasing the mutex post-restore.
- Apply the same lock field to the `#[cfg(windows)]` impl. The fallback impl
  (`#[cfg(not(any(unix, windows)))])` performs no redirection → no lock needed.
- The moved test runs single-threaded and is unaffected.

## A3. Standalone binary `src/bin/term-copy.rs` — flagless, thin wrapper

**Amendment (user):** the binary is renamed `term-copy` ("term-clipboard doesn't say 'hey, this
copies'"), the `--osc52` flag is **removed** (fully flagless), and it becomes a **thin CLI
wrapper**: all file/stdin ingestion and UTF-8 validation lives in the library
(`Clipboard::set_from_reader` / `set_from_path`, see **A6**) so MCP servers, AI agents, and
external tools can ingest files/streams programmatically without spawning the binary.

```rust
use std::path::PathBuf;
use std::process::ExitCode;

use clap::Parser;
use term_clipboard::Clipboard;

/// Copy text to the clipboard, cross-platform.
#[derive(Parser, Debug)]
#[command(
    name = env!("CARGO_BIN_NAME"),
    version = env!("CARGO_PKG_VERSION"),
    about = env!("CARGO_PKG_DESCRIPTION"),
    long_about = concat!(
        env!("CARGO_BIN_NAME"), " ", env!("CARGO_PKG_VERSION"), ": ",
        env!("CARGO_PKG_DESCRIPTION"),
        "\n\nReads UTF-8 text from FILE (or stdin when omitted) and copies it to the ",
        "clipboard.  Writes to every available backend in order: the system clipboard, ",
        "the shared in-memory buffer, and OSC 52 to the host terminal — so it works ",
        "locally and over SSH with no flags.  Only UTF-8 text is supported; binary ",
        "input is an error (exit code 1)."
    ),
)]
struct Cli {
    /// Text to copy, read as UTF-8.  When omitted, reads from stdin.
    file: Option<PathBuf>,
}

fn main() -> ExitCode {
    let cli = Cli::parse();
    let mut cb = Clipboard::new();

    let result = match cli.file {
        Some(path) => cb.set_from_path(&path),
        None => cb.set_from_reader(std::io::stdin().lock()),
    };

    match result {
        Ok(()) => ExitCode::SUCCESS,
        Err(e) => {
            eprintln!("term-copy: {e}");
            ExitCode::FAILURE
        }
    }
}
```

- `Cli::parse()`: single optional `[FILE]` positional (or stdin when absent); `-h`/`--help` and
  `--version` handled automatically. `name = env!("CARGO_BIN_NAME")` renders the **binary**
  name `term-copy` (Cargo sets `CARGO_BIN_NAME` when compiling a bin target), not the package
  name; `about`/`version` come from cargo vars like the other binaries.
- The local `read_input` helper and `use std::io::Read` are **deleted** — the binary only
  parses args and formats errors; `set_from_path` / `set_from_reader` (A6) do the I/O and
  validation, returning typed `ClipboardError`s that `Display` directly in `eprintln!`.
- **Exit codes:** clap parse errors (extra positional, unknown flag) exit **`2`**;
  `--help`/`--version` exit `0`; any `ClipboardError` (unreadable file → `Io`, non-UTF-8 →
  `InvalidUtf8`) exits **`1`**.
- No `--osc52` and no `set_via_osc52_with_writer` in the binary — OSC 52 is just one backend
  in the cascade (A5). Over SSH the arboard backend fails harmlessly and the OSC 52 backend
  emits to stdout automatically **when stdout is an active terminal** (SEV-1.1 TTY gate); on
  pipes/redirects it is suppressed so structured streams stay clean.
- **No-hang guard (user):** with no `FILE` argument and a **TTY stdin** there is nothing to
  read — `read_to_string` would block forever waiting for EOF. `term-copy` checks
  `std::io::stdin().is_terminal()` and exits `1` with
  `term-copy: error: no input; pass a FILE argument or pipe stdin` instead of hanging.
  Callers must pass a file or pipe stdin.
- Error-message note: because `set_from_path`'s `File::open` failure surfaces as
  `ClipboardError::Io` (the underlying `io::Error` carries no path), the CLI message becomes
  `term-copy: I/O error: No such file or directory (os error 2)` rather than naming the path —
  an acceptable, documented tradeoff for the typed library contract.

## A5. Backend registry system (replaces the imperative pipeline)

**Amendment (user):** the hardcoded imperative pipeline inside `Clipboard` (`set()` =
`if let`-chain writing the shared buffer, calling `write_system_clipboard`, then conditionally
emitting OSC 52) is replaced by a **pluggable backend registry** — a public trait + concrete
backends + a `Clipboard` that composes them. This is what lets the `term-copy` CLI be flagless:
`set()` simply fans out to every registered backend.

### Trait

```rust
/// A pluggable clipboard backend.  `Clipboard` composes backends and fans
/// `set()` out to all of them in registration order; `get()` returns the
/// first backend that can supply text.
pub trait ClipboardBackend: Send {
    /// Best-effort write.  `Err` is logged by the caller; the fan-out continues.
    fn set(&mut self, text: &str) -> Result<(), ClipboardError>;
    /// Read the clipboard.  `Ok(None)` when this backend cannot supply text
    /// (e.g. OSC 52 is write-only); `Err` on backend failure.
    fn get(&mut self) -> Result<Option<String>, ClipboardError>;
    /// Stable identifier for logging / diagnostics.
    fn name(&self) -> &'static str;
}
```

### Concrete backends

- **`ArboardBackend { clipboard: Option<arboard::Clipboard> }`** — `new()` probes
  `arboard::Clipboard::new().ok()` (None headless/SSH). `set` wraps `cb.set_text` in
  `term_sys_io::StderrSuppressGuard`; `get` returns `cb.get_text()`. Absorbs the logic of the
  deleted `write_system_clipboard` / `read_system_clipboard` helpers.
- **`InMemoryBackend { shared: Arc<RwLock<Option<String>>> }`** — Tier-1 copy→paste round-trip.
  `set` writes the buffer (poison-tolerant `if let Ok`); `get` reads with poison recovery.
- **`Osc52Backend { enabled: bool, limit: usize }`** — write-only. `set` truncates via
  `truncate_for_osc52`, then **only if stdout is an active terminal** writes the escape via
  `set_via_osc52_with_writer` to `stdout().lock()` (captured to `#[cfg(test)] output: Vec<u8>`
  in tests, bypassing the TTY check); `get` returns `Ok(None)`.
  > **AMEND (review SEV-1.1):** gate stdout emission on `std::io::stdout().is_terminal()`
  > (`use std::io::IsTerminal;`). Unconditional emission corrupts structured IPC streams
  > (MCP servers, daemons) and redirected pipes/files (`term-copy file > out.txt`). In
  > `#[cfg(test)]` builds the capture path must NOT call `is_terminal()` (test stdout is a
  > pipe). Tradeoff: over SSH, OSC 52 is only emitted when stdout is a terminal (`ssh -t`);
  > without `-t` the escape is suppressed and only arboard (if a display exists) writes.
  > ```rust
  > #[cfg(not(test))]
  > {
  >     if std::io::stdout().is_terminal() {
  >         let mut out = std::io::stdout().lock();
  >         set_via_osc52_with_writer(osc52_text, &mut out)?;
  >     }
  > }
  > ```

### `Clipboard` composition

```rust
pub struct Clipboard { backends: Vec<Box<dyn ClipboardBackend>> }

impl Clipboard {
    pub fn new() -> Self { Self::with_config(ClipboardConfig::default()) }

    pub fn with_config(config: ClipboardConfig) -> Self {
        Self::with_backends(default_backends(config))
    }

    /// Headless seam used by pty-engine tests: in-memory + OSC 52, no arboard.
    pub fn with_shared_buffer(buffer: Arc<RwLock<Option<String>>>) -> Self {
        Self::with_backends(vec![
            Box::new(InMemoryBackend::new(buffer)),
            Box::new(Osc52Backend::new(ClipboardConfig::default())),
        ])
    }

    /// Compose a clipboard from a custom backend list (public — the "actual
    /// backend system" entry point).
    pub fn with_backends(backends: Vec<Box<dyn ClipboardBackend>>) -> Self {
        Self { backends }
    }

    pub fn set(&mut self, text: &str) {
        for backend in &mut self.backends {
            if let Err(e) = backend.set(text) {
                tracing::debug!("clipboard: backend {} set failed ({e})", backend.name());
            }
        }
    }

    pub fn get(&mut self) -> Result<String, ClipboardError> {
        for backend in &mut self.backends {
            match backend.get() {
                Ok(Some(text)) => return Ok(text),
                Ok(None) => {}
                Err(e) => tracing::debug!("clipboard: backend {} get failed ({e})", backend.name()),
            }
        }
        Err(ClipboardError::NotAvailable)
    }
}

/// Default order: arboard, in-memory, OSC 52 last (host terminal becomes the
/// final X11 owner).  `set()` fans out in this order (in-memory is always
/// written — the loop never aborts on a backend error); `get()` resolves
/// arboard first (authoritative), then in-memory, and OSC 52 never yields.
fn default_backends(config: ClipboardConfig) -> Vec<Box<dyn ClipboardBackend>> {
    vec![
        Box::new(ArboardBackend::new()),
        Box::new(InMemoryBackend::new(default_shared_buffer())),
        Box::new(Osc52Backend::new(config)),
    ]
}
```

### Semantics preserved (behavior-compatible)

- `set()` infallible fan-out to all backends; per-backend failures logged, never fatal.
- `get()` = arboard (authoritative, real system clipboard) → in-memory fallback; `Err::NotAvailable`
  when empty. OSC 52 is write-only and never consulted. This is exactly the current behavior.
- OSC 52 emitted **last** so the host terminal becomes the final owner (unchanged ordering intent).
- Public surface unchanged for all external consumers (`new`, `set`, `get`, `with_shared_buffer`,
  `Default`) → **zero consumer edits** (verified: pty-engine, term-session-client, term-wm-core,
  integration tests only use those). New surface: `ClipboardBackend`, `ArboardBackend`,
  `InMemoryBackend`, `Osc52Backend`, `with_backends`.
- `ClipboardConfig` (osc52_enabled/osc52_limit) and `ClipboardError` unchanged.

### Ingestion methods on `Clipboard` (`crates/term-clipboard/src/clipboard.rs`)

```rust
impl Clipboard {
    /// Read UTF-8 content from any `Read` stream (file, stdin, network socket) and
    /// copy it across all backends.
    pub fn set_from_reader<R: std::io::Read>(&mut self, mut reader: R) -> Result<(), ClipboardError> {
        let mut text = String::new();
        match reader.read_to_string(&mut text) {
            Ok(_) => {
                self.set(&text);
                Ok(())
            }
            Err(e) if e.kind() == std::io::ErrorKind::InvalidData => Err(ClipboardError::InvalidUtf8),
            Err(e) => Err(ClipboardError::Io(e)),
        }
    }

    /// Read UTF-8 content from a file path and copy it across all backends.
    pub fn set_from_path<P: AsRef<std::path::Path>>(&mut self, path: P) -> Result<(), ClipboardError> {
        let file = std::fs::File::open(path)?;
        self.set_from_reader(file)
    }
}
```

- Both reuse the existing infallible `Clipboard::set` fan-out once the stream is read.
- `set_from_reader` takes any `std::io::Read` (generic), so agents can hand over a file,
  stdin lock, socket, or in-memory `Cursor`. `set_from_path` opens + delegates.
- `InvalidUtf8` is produced only for the `InvalidData` read failure (the stream wasn't valid
  UTF-8); any other read/open failure is `Io`, and callers can inspect `io::Error::kind()`.

# PART B — Wrap-aware selection copy (line joining)

## Root cause

`TerminalComponent::selection_text_for_range`
(`crates/term-wm-ui-components/src/terminal.rs`, lines 878–959) unconditionally inserts `\n`
between every pair of selected rows (lines 953–955), corrupting soft-wrapped lines. The fork
already exposes the distinction via `Screen::row_wrapped(row)` (viewport-relative; returns
`false` for out-of-bounds rows).

## B1. Core fix — `selection_text_for_range` (SEV-1.1 + SEV-1.2 + SEV-2.1)

In the pagination loop (lines 928–956). `viewport_row` at **line 933** is already the correct
viewport-relative index for the row *after* `set_scrollback(offset)` at line 931
(`viewport_start = absolute_row.min(vt100_max_scrollback)`; `viewport_row = absolute_row - viewport_start`).
SEV-1.1: **use that value** — never pass `absolute_row` to `row_wrapped`. SEV-2.1: the bounds
guard runs **before** any screen query.

```rust
// SEV-2.1 (AMEND): validate the coordinate BEFORE touching the grid.  `viewport_row`
// is always in 0..viewport_rows by construction, but guard first so no query is ever
// issued with an out-of-range row (defensive against scrollback/resize races).
if viewport_row >= viewport_rows {
    continue;
}

let line = guard
    .screen
    .contents_between(viewport_row, col_start, viewport_row, col_end);

// SEV-1.2: never let width-padded grid cells (or gap spaces) leak into the
// middle of a joined continuous string from a soft-wrapped row.
let wrapped = guard.screen.row_wrapped(viewport_row);
let line = if wrapped {
    line.trim_end_matches(' ').to_owned()
} else {
    line
};
result.push_str(&line);

// SEV-1.1: `viewport_row` (line 933) is the viewport-relative index; `wrapped`
// is only consulted for rows already validated in-bounds above.
if absolute_row < vt100_end_row && !wrapped {
    result.push('\n');
}
```

Notes:
- `row_wrapped` is queried per-row **after** the existing `set_scrollback()` pagination, so it
  is correct for both viewport and scrollback selections. The early `continue` is behavior-
  neutral in every reachable case (`viewport_row < viewport_rows` always holds) — it is a
  defensive reordering, per review SEV-2.1.
- SEV-1.2 trim is defensive: the fork's `Row::write_contents` already strips trailing empty
  cells, so in the current `contents_between` path it is normally a no-op. It guards against
  grid padding leaking via any raw-row path and against internal gap spaces at a wrap seam.
  Tradeoff: a wrapped row whose *actual* content ends in spaces would lose them (matches the
  "join with nothing" behavior of mainstream terminals).
- Join-with-nothing is unconditional (no config flag). Genuine `\r\n` rows keep their `\n`
  because those rows are `wrapped == false`.

# PART C — "Paste System Clipboard" palette action (split-brain escape hatch)

## Motivation

The internal shared in-memory buffer and the real OS clipboard can diverge when a terminal
doesn't support OSC 52, when arboard is absent (SSH/headless), or when X11 arboard serves stale
data. `Clipboard::get()` prefers arboard but **silently falls back to the internal buffer**, so a
paste can deliver term-wm's stale internal value while the OS clipboard holds something else.
There is today **no way to read only the real system clipboard**. A palette command **"Paste
System Clipboard"** reads arboard **only** (no internal fallback) and pastes it — an explicit,
discoverable escape hatch. Per user decision: **silent no-op** when no system clipboard exists.

## C1. Library — `Clipboard::get_system` (`crates/term-clipboard/src/clipboard.rs`)

- `ClipboardBackend` trait gains a marker method, defaulting to `false`:
  ```rust
  /// Whether this backend is the OS/system clipboard (as opposed to an
  /// internal buffer).  Used to read the real system clipboard explicitly.
  fn is_system(&self) -> bool {
      false
  }
  ```
  `ArboardBackend` overrides it to `true`.
- `Clipboard::get_system(&mut self) -> Result<Option<String>, ClipboardError>` — iterate the
  backends, consulting **only** `is_system()` ones: first `Ok(Some)` wins, `Ok(None)` continues
  to the next system backend, `Err` propagates; `Ok(None)` when there is no system backend.
  This never consults the in-memory / OSC 52 backends, so it cannot serve the internal buffer.
- Tests:
  - `get_system_reads_only_system_backend` — `with_backends([RecordingBackend(read: Some("internal")),
    ArboardBackend::new() (no display -> None), InMemoryBackend(filled)])` → `get_system()` is
    `Ok(None)` (no system backend) **even though** in-memory holds text and `get()` returns it.
  - `get_system_returns_text_from_system_backend` — a fake `is_system()==true` backend returning
    `Ok(Some("sys"))` → `get_system() == Ok(Some("sys"))`.
  - `get_system_propagates_system_error` — a system backend returning `Err` → propagated.

## C2. WM action, palette entry, dispatch (`term-wm-core` + root)

- `crates/term-wm-core/src/actions.rs`:
  - New payload-free variant `PasteSystemClipboard` (next to `PasteClipboard`).
  - `Category::Selection` alongside `PasteClipboard`/`ClearSelection`.
  - Display label: `"Paste system clipboard"`.
- `crates/term-wm-core/src/runner.rs` `dispatch_action` — new arm mirroring the `PasteClipboard`
  arm, with **no internal fallback**:
  ```rust
  TermWmAction::PasteSystemClipboard => {
      if let Some(text) = app
          .wm()
          .clipboard_mut()
          .and_then(|cb| cb.get_system().ok().flatten())
      {
          queue.push_back((key, TermWmAction::ClipboardPaste(text)));
      }
  }
  ```
  (`ok().flatten()` ⇒ silent no-op when no system clipboard, per user decision.)
- `crates/term-wm-core/src/window/window_manager/command_palette.rs` `wm_menu_items` — add a
  clipboard-group entry mirroring `ToggleClipboardMode`:
  ```rust
  items.push(mi("Paste System Clipboard", Some("■"), TermWmAction::PasteSystemClipboard));
  ```
- Allow-lists so the palette item isn't filtered out:
  - `crates/term-wm-core/src/constants.rs` `DEFAULT_SUPPORTED_MENU_ACTIONS` += `PasteSystemClipboard`.
  - `src/term_wm_app.rs` `DEFAULT_STANDALONE_MENU_ACTIONS` += `PasteSystemClipboard`.
- **No default keybinding** — palette-only, exactly like `ToggleClipboardMode`.
- Right-click paste (`PasteClipboard`) is unchanged (still get() with internal fallback); the new
  command is the explicit system-only variant.
