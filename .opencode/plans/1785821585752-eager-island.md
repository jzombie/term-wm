# Fix: `term-session --list` silently opens the default connection instead of erroring

## Problem

Running `term-session --list` (or any unknown flag like `--bogus`, `-x`) does not
error. It silently treats the token as the command to run and opens/auto-spawns the
default channel session. A typo therefore hijacks your terminal into a real session.

## Root Cause

`crates/term-session/src/main.rs:41` — the trailing command positional is declared as:

```rust
#[arg(value_name = "CMD", num_args = 0.., trailing_var_arg = true, allow_hyphen_values = true)]
cmd: Vec<String>,
```

`allow_hyphen_values = true` makes clap swallow **any** leading-hyphen token as a value
for `cmd`, even when it is not a real flag. Then in `run()` (main.rs:117)
`!cli.cmd.is_empty()` is true, so the implicit-attach path runs `attach()` and spawns
the session with `--list` as the command.

Verified empirically against clap 4.6.5: with `allow_hyphen_values`,
`term-session --list` parses to `cmd = ["--list"]`; without it, clap rejects it with
`unexpected argument '--list' found` (exit code 2).

## Fix

`crates/term-session/src/main.rs:41` — remove `allow_hyphen_values = true` from the
`cmd` field. `trailing_var_arg = true` alone is sufficient and is exactly what makes
everything after `--` (and trailing args after the first command word) pass through
verbatim, including hyphen values.

Verified behavior matrix with the real full `Cli` struct (all flags present):
- `--list`, `--bogus`, `-x` → error `unexpected argument ... found`, exit 2 ✅ (the fix)
- `-- git log --oneline` → `cmd=["git","log","--oneline"]` ✅ (unchanged)
- `--channel work -- vim -l` → `cmd=["vim","-l"]` ✅ (unchanged)
- `--channel work vim` (no `--`) → `cmd=["vim"]` ✅ (unchanged)
- `vim -l` (no `--`) → `cmd=["vim","-l"]` ✅ (unchanged — trailing_var_arg allows hyphens once the positional has started)
- `list` → `List` subcommand; `-- list` → `cmd=["list"]` ✅ (unchanged)
- `--daemon`, `--gateway g --channel work -- vim`, `stop --force`, `kill-client a 4` ✅ (unchanged)

## Regression Test

Add to `crates/term-session/tests/daemon_tests.rs` (alongside the existing
`dash_dash_disambiguates_command_from_subcommand` test):

`unknown_flag_errors_without_spawning_gateway`:
1. `Command::new(bin())` with a `unique_gateway("unknown_flag")` `TERM_WM_GATEWAY` env
   and arg `--list`.
2. Assert `output.status.code()` is non-zero (clap exits with code 2).
3. Assert stderr contains `unexpected argument` and mentions `--list`.
4. Assert `!probe_ipc_endpoint(&gw)` — no gateway was auto-spawned.

Optionally also loop over `--bogus` / `-x` in the same test.

## Files to modify
