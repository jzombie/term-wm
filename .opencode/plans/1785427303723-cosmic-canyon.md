# Plan: Fix Window Manager State/Layout Bugs (SEV-1 & SEV-2)

## Summary

Three interdependent bugs in the window manager's layout/state coordination:

1. **SEV-1: `register_managed_layout` purges `z_order` via geometric filter** — `z_order.retain` uses `active_keys` (geometry-derived) instead of authoritative `WindowState`. Windows that fail geometry generation are permanently removed from tracking.
2. **SEV-1: `toggle_maximize` assumes void placeholder is permanent** — If window is minimized while maximized, `detach_from_tiling_layout` destroys the void. Unmaximize silently aborts re-insertion.
3. **SEV-2: `reattach_to_tiling_layout` never scans for void holes** — Always splits the focused leaf, ignoring empty Void regions, causing pathological nesting.
4. **SEV-1 (omitted): `detach_from_tiling_layout` root erasure** — Minimizing the last tiled window leaves a root `Void` node that forces a 50/50 dead-space split on next insertion.

## Change 1: Decouple State Tracking from Geometry (layout.rs:488)

**Current:**
```rust
self.z_order.retain(|key| active_keys.contains(key));
```

**Replace with:**
```rust
self.z_order.retain(|k| self.window_state(*k).is_some_and(|s| s != WindowState::Unmapped));
```

`active_keys` is a downstream geometric artifact — not state authority. Only `Unmapped` windows should be pruned from `z_order`. All other states (Mapped, Iconic, Shaded) are valid tracking entries.

## Change 2: Topological Fallback on Stale Void (chrome.rs:28–36)

**Current** (unmaximize → was-tiled branch, lines 28–36):
```rust
} else {
    // Was tiled: restore Void → Leaf in layout tree
    self.clear_floating_rect(key);
    let void_id = self.window(key).and_then(|w| w.void_id());
    if let Some(vid) = void_id
        && let Some(ref mut layout) = self.managed_layout
    {
        layout.replace_void_by_id(vid, LayoutNode::leaf(key));
    }
}
```

Problem: If window was minimized while maximized, `detach_from_tiling_layout` calls `remove_void_by_id` + `clear_void_id`, so `void_id` is `None` — the `if let` is skipped, window is not reattached, and has no floating rect, so `register_managed_layout` purges it from `z_order`.

**Replace with:**
```rust
} else {
    // Was tiled: restore Void → Leaf in layout tree
    self.clear_floating_rect(key);
    let void_id = self.window(key).and_then(|w| w.void_id());

    let mut restored = false;
    if let Some(vid) = void_id {
        if let Some(ref mut layout) = self.managed_layout {
            restored = layout.replace_void_by_id(vid, LayoutNode::leaf(key));
        }
    }

    // Force re-attachment if the Void node was destroyed (e.g., during minimize)
    if !restored && self.window_state(key) == Some(WindowState::Mapped) {
        self.reattach_to_tiling_layout(key);
    }
}
```

## Change 3: Consume Void Topology Before Leaf Splitting (layout.rs:827–878)

**Current `reattach_to_tiling_layout`:**
1. Early return if `layout_contains`
2. Create layout if `None`
3. Capture `current_focus` + `floating_info`
4. Try spatial placement via `floating_rect`
5. Fallback: split `current_focus` leaf

**Problem:** Never checks for existing `Void` nodes. If voids exist in the tree, they should be consumed before any split.

**Replace with:**
1. Early return if `layout_contains`
2. Create layout if `None`
3. Capture `current_focus` + `floating_info`
4. **NEW: Void consumption** — query `layout.void_regions(self.managed_area)`, if non-empty, replace first void with `LayoutNode::leaf(key)` and return
5. Try spatial placement via `floating_rect` (unchanged)
6. Fallback: split `current_focus` leaf (unchanged)

The new code for the void consumption step:
```rust
    let Some(layout) = self.managed_layout.as_mut() else {
        return;
    };

    // 1. VOID CONSUMPTION — fill existing void holes before splitting
    let voids = layout.void_regions(self.managed_area);
    if !voids.is_empty() {
        let target_void_id = voids[0].0;
        layout.replace_void_by_id(target_void_id, LayoutNode::leaf(key));
        return;
    }
```

## Change 4: Single-Leaf Root Nullification (layout.rs:802–820)

**Current `detach_from_tiling_layout`** (the `else` branch):
```rust
} else {
    let _ = layout.root_mut().remove_leaf(key);
    layout.root_mut().cleanup_after_removal();
    // If the tree was a single leaf matching key, remove_leaf
    // cannot remove it.  Clear it explicitly to prevent stale
    // leaves from persisting in the tree.
    layout.root_mut().clear_leaf(key);
}
```

Problem: When the last tiled window is detached (minimized/destroyed), `remove_leaf` fails on a single-leaf root. `clear_leaf` replaces the leaf with a `Void`, leaving a permanent root `Void` that forces a 50/50 dead-space split on next window insertion.

**Replace with:**
```rust
} else {
    if layout.root().unwrap_leaf() == Some(key) {
        // Single-leaf root — nullify the entire layout tree
        self.managed_layout = None;
    } else {
        let _ = layout.root_mut().remove_leaf(key);
        layout.root_mut().cleanup_after_removal();
        // If the tree was a single leaf matching key, remove_leaf
        // cannot remove it.  Clear it explicitly to prevent stale
        // leaves from persisting in the tree.
        layout.root_mut().clear_leaf(key);
    }
}
```

## Change 5: Concrete Invariant Tests

### Test 1: Stale Void Fallback Invariant

Add to the `#[cfg(test)] mod tests` block in `layout.rs`:

```rust
#[test]
fn maximize_minimize_unmaximize_retains_window() {
    use crate::window::WindowKey;
    let mut wm = make_wm();

    // Create and map two windows so we have a tiling layout
    let key_a = wm.create_window(NoopComponent);
    let key_b = wm.create_window(NoopComponent);
    wm.transition_window(key_a, WindowState::Mapped);
    wm.transition_window(key_b, WindowState::Mapped);

    // Register a layout to set up managed_area + tiling tree
    wm.register_managed_layout(Rect { x: 0, y: 0, width: 80, height: 24 });

    // 1. Maximize window A (creates Void, assigns void_id)
    wm.toggle_maximize(key_a);
    assert!(wm.window(key_a).is_some_and(|w| w.is_maximized()));
    assert!(wm.is_window_floating(key_a));

    // 2. Minimize window A (destroys Void, clears void_id)
    wm.minimize_window(key_a);
    assert_eq!(wm.window_state(key_a), Some(WindowState::Iconic));

    // 3. Restore window A (state -> Mapped)
    wm.restore_minimized(key_a);
    assert_eq!(wm.window_state(key_a), Some(WindowState::Mapped));

    // 4. Unmaximize window A (toggle_maximize — void pointer is stale)
    wm.toggle_maximize(key_a);
    assert!(!wm.window(key_a).is_some_and(|w| w.is_maximized()));
    assert!(!wm.is_window_floating(key_a));

    // Assert: Window A is in z_order and has valid geometry
    assert!(wm.z_order.contains(&key_a), "must be in z_order");
    assert!(wm.region(key_a).width > 0 && wm.region(key_a).height > 0,
        "must have valid geometry after unmaximize");
}
```

### Test 2: Single-Leaf Nullification Invariant

Add to the same test module:

```rust
#[test]
fn single_leaf_minimization_nullifies_layout() {
    let mut wm = make_wm();

    // 1. Tile single window A
    let key = wm.create_window(NoopComponent);
    wm.transition_window(key, WindowState::Mapped);

    wm.register_managed_layout(Rect { x: 0, y: 0, width: 80, height: 24 });
    assert!(wm.managed_layout.is_some(), "must have layout after first tile");

    // 2. Minimize window A
    wm.minimize_window(key);
    assert_eq!(wm.window_state(key), Some(WindowState::Iconic));

    // Assert: managed_layout is explicitly None (root nullified)
    assert!(wm.managed_layout.is_none(),
        "single-leaf minimization must nullify layout tree");

    // 3. Restore window A
    wm.restore_minimized(key);
    assert_eq!(wm.window_state(key), Some(WindowState::Mapped));

    // Assert: Window A is the new root Leaf
    assert!(wm.managed_layout.is_some(), "must have layout after restore");
    if let Some(ref layout) = wm.managed_layout {
        assert_eq!(layout.root().unwrap_leaf(), Some(key),
            "restored window must be the root leaf");
    }
}
```
