# Plan: Fix Nesting Guard + Stop Retry on Fatal Error

## Problem
Two issues prevent the nesting guard from working:
1. The guard fires correctly but the error gets swallowed by the launcher's retry loop
2. The launcher retries on ALL errors, including fatal ones

## Changes

### 1. `crates/term-wm/src/main.rs` (line 241-253)

In the `Err(e)` branch of the workspace rebind loop, exit immediately on fatal errors instead of retrying:

```rust
Err(e) => {
    let msg = e.to_string();
    if msg.contains("FATAL") {
        return Err(e);
    }
    tracing::error!(
        "Connection dropped for workspace '{}': {}",
        current_workspace,
        e
    );
    std::thread::sleep(std::time::Duration::from_secs(2));
    if current_workspace != term_session::DEFAULT_WORKSPACE {
        current_workspace = term_session::DEFAULT_WORKSPACE.to_string();
        continue;
    }
    return Err(e);
}
```

### No other changes needed

The guard in `term-session-client` already works correctly:
- `TERM_SESSION_GATEWAY` set by server on every spawned PTY child
- `should_block_nesting` compares `active == target_socket`
- Returns `Err(NESTED_SESSION_FATAL)` when same-gateway

The `term-session` CLI also works correctly — `attach()` propagates the error directly to `run_and_exit()` which prints and exits 1.
