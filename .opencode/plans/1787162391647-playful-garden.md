# Plan: Simplify Inception Guard — `TERM_SESSION_GATEWAY` Only

## Problem
The current implementation includes a legacy fallback (`active_in_session` bool) that re-introduces the exact false-positive behavior we're fixing. Since all binaries are compiled/deployed together from the same workspace, there's no version skew to defend against.

## Changes

### 1. `crates/term-session-client/src/lib.rs`

**`should_block_nesting`** — remove `active_in_session` param, simplify to:
```rust
fn should_block_nesting(
    active_gateway: Option<&str>,
    target_socket: &str,
    allow_nested: bool,
) -> bool {
    if allow_nested {
        return false;
    }
    match active_gateway {
        Some(active) => active == target_socket,
        None => false,
    }
}
```

**`run_session` guard** — remove `active_in_session` variable:
```rust
let host_gateway = std::env::var(term_session_muxio_service_definitions::SESSION_GATEWAY_ENV_VAR).ok();
if should_block_nesting(host_gateway.as_deref(), socket_path, allow_nested) {
    return Err(io::Error::other(NESTED_SESSION_FATAL));
}
```

**`should_block_nesting_truth_table` test** — update to 3-param signature, remove legacy fallback cases.

### 2. `crates/term-session-server/src/session.rs`

Remove `builder.env(term_wm_config::env::SESSION_ACTIVE_ENV_VAR, "1");` from `Session::spawn`. Only `SESSION_GATEWAY_ENV_VAR` is injected now.

### 3. `crates/term-session/tests/daemon_tests.rs`

Remove `.env("TERM_SESSION_ACTIVE", "1")` from:
- `attach_inside_nested_env_aborts_without_allow_nested`
- `attach_inside_nested_env_proceeds_with_allow_nested`
- `attach_cross_gateway_proceeds_without_allow_nested`
