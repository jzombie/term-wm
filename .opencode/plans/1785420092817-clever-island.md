# Surgical Fix: Two State Bugs, Zero Architecture Changes

## Principle
Keep the existing architecture (Void nodes, `active_keys` sync, `register_managed_layout` pipeline, debug logs) completely untouched. Fix only the two state-transition bugs in isolated functions.

---

## Bug 1: Maximize → minimize → restore → focus other → window vanishes

### Root Cause
`toggle_maximize` replaces the tiled window's Leaf with a Void in the layout tree, storing a `void_id`. If the window is minimized between maximize and unmaximize, `detach_from_tiling_layout` destroys the Void and clears `void_id`. When `toggle_maximize` later tries to unmaximize, it finds `void_id == None` and silently skips restoration — window falls out of both the tree and the floating pass.

### Fix: Don't mutate the tree on maximize
Maximize for a tiled window just sets `floating_rect = Some(full_area)` and `is_maximized = true`. The window stays in the tree as a Leaf. `bifurcate_draw_order` puts floating windows last, so it renders on top at full area naturally. Unmaximize just clears `floating_rect` and `is_maximized`. No Void, no `void_id`, nothing to go stale.

**File:** `crates/term-wm-core/src/window/window_manager/chrome.rs`

In `toggle_maximize`, change the "Was tiled" branch (lines 58–67):
```rust
// OLD:
} else {
    // Was tiled: replace Leaf with Void in-place, preserving tree
    if let Some(ref mut layout) = self.managed_layout
        && let Some(void_id) = layout.replace_leaf_with_void(key)
        && let Some(w) = self.windows.get_mut(key)
    {
        w.set_void_id(Some(void_id));
    }
    self.set_prev_floating_rect(key, None);
}

// NEW:
} else {
    // Was tiled: window stays in tree. Render override handles full-area.
    // Save None as prev_floating_rect to signal "was tiled" on unmaximize.
    self.set_prev_floating_rect(key, None);
}
```

And in the unmaximize path (lines 28–37), remove the Void restoration — just clear floating_rect:
```rust
// OLD:
} else {
    // Was tiled: restore Void → Leaf in layout tree
    self.clear_floating_rect(key);
    let void_id = self.window(key).and_then(|w| w.void_id());
    if let Some(vid) = void_id
        && let Some(ref mut layout) = self.managed_layout
    {
        layout.replace_void_by_id(vid, LayoutNode::leaf(key));
    }
}

// NEW:
} else {
    // Was tiled: clear floating rect — window renders at tiled position
    self.clear_floating_rect(key);
}
```

Also remove `use crate::layout::LayoutNode;` from the imports in chrome.rs if it's no longer needed.

## Bug 2: Minimize last tiled window → restore → half-screen Void

### Root Cause
`detach_from_tiling_layout` calls `remove_leaf(key)` on a single-Leaf root, which returns `false` (can't remove the root). Then `clear_leaf(key)` replaces `Leaf(key)` → `Void(new_id)`. On restore, `reattach_to_tiling_layout` sees a non-empty tree (Void root), calls `split_root`, which splits the Void with the new Leaf into a 50/50 split.

### Fix: Set `managed_layout = None` when last tiled window is removed
After `remove_leaf` fails, the tree was a single Leaf root holding the last tiled window. Instead of replacing it with Void, set the whole layout to `None`. On restore, `reattach_to_tiling_layout` sees `managed_layout.is_none()` and creates a fresh `TilingLayout::new(leaf(key))`.

**File:** `crates/term-wm-core/src/window/window_manager/layout.rs`

In `detach_from_tiling_layout`, change the non-void branch (lines 811–817):
```rust
// OLD:
} else {
    let _ = layout.root_mut().remove_leaf(key);
    layout.root_mut().cleanup_after_removal();
    // If the tree was a single leaf matching key, remove_leaf
    // cannot remove it.  Clear it explicitly to prevent stale
    // leaves from persisting in the tree.
    layout.root_mut().clear_leaf(key);
}

// NEW:
} else if layout.root_mut().remove_leaf(key) {
    layout.root_mut().cleanup_after_removal();
} else {
    // Single-Leaf root: last tiled window being minimized.
    // Tree becomes empty — managed_layout set to None.
    // On restore, reattaches as a fresh Leaf root.
    self.managed_layout = None;
}
```
