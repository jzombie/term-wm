# Fix: Tiled Window Minimize/Maximize Bugs (Tests-First)

## Existing Test Coverage Gap

The existing test `tiled_maximize_then_minimize_and_restore` (mod.rs:3739-3780) checks `is_maximized` after restore but does NOT trigger auto-unmaximize (focus another window), so it doesn't catch the disappearance bug.

## Step 1: Write Failing Tests

### Bug 1 Test — `tiled_maximize_minimize_restore_focus_other_stays_in_layout`

**File:** `crates/term-wm-core/src/window/window_manager/mod.rs` (in the `mod tests` block)

Test scenario:
1. Two tiled windows in horizontal split (50/50)
2. Focus keys[0], maximize keys[0] → void placed in tree
3. Minimize keys[0] → void removed from tree, void_id cleared
4. Restore keys[0] → window comes back maximized (floating rect + is_maximized)
5. Focus keys[1] → triggers auto-unmaximize in `focus_window_key`
6. **Assert**: keys[0] is NOT maximized, is NOT floating, IS in the layout tree, has `void_id == None`, has a region in `managed_area`

This test will **fail** on current code because:
- Auto-unmaximize calls `toggle_maximize(keys[0])` which enters unmaximize path
- `prev_floating_rect` is None (was tiled)
- `void_id` is None (cleared by `detach_from_tiling_layout`)
- Neither branch executes → `clear_floating_rect` makes it non-floating but not in tree
- `register_managed_layout` removes it from `z_order` → **window disappears**

### Bug 2 Test — `minimize_restore_single_tiled_window_takes_full_area`

**File:** `crates/term-wm-core/src/window/window_manager/mod.rs`

Test scenario:
1. Single tiled window in `Leaf(key)` layout
2. Minimize (Iconic) → `detach_from_tiling_layout` → `clear_leaf` replaces Leaf with Void
3. Restore (Mapped) → `reattach_to_tiling_layout`
4. **Assert**: window is NOT floating, IS in the layout tree at a Leaf root (not 50/50 split with a Void)

This test will **fail** on current code because:
- `clear_leaf` replaces `Leaf(key)` with `Void(new_id)`, `managed_layout` stays `Some(Void(...))`
- `reattach_to_tiling_layout` sees `managed_layout.is_some()` and calls `split_root`
- `split_root` detects Void root, creates 50/50 split: `Void(new_id) | Leaf(key)`
- Window takes half the screen with empty void space

### Bug 1b Test — `tiled_maximize_minimize_restore_focus_other_proper_region`

**File:** `crates/term-wm-core/src/window/window_manager/mod.rs`

Same as Bug 1 test but adds `register_managed_layout` after all operations and checks that the window appears in `regions` with a proper rect.

## Step 2: Implement Fixes

### Fix A: `toggle_maximize` unmaximize — handle missing void_id

**File:** `crates/term-wm-core/src/window/window_manager/chrome.rs:22-44`

Current unmaximize path:
```rust
if is_maxed {
    let prev_float = self.take_prev_floating_rect(key);
    if let Some(prev_spec) = prev_float {
        // Was floating: restore pre-maximize floating rect
        self.set_floating_rect(key, Some(prev_spec));
    } else {
        // Was tiled: restore Void → Leaf in layout tree
        self.clear_floating_rect(key);
        let void_id = self.window(key).and_then(|w| w.void_id());
        if let Some(vid) = void_id
            && let Some(ref mut layout) = self.managed_layout
        {
            layout.replace_void_by_id(vid, LayoutNode::leaf(key));
        }
        // BUG: else branch is silently skipped!
    }
    ...
}
```

Change to:
```rust
if is_maxed {
    let prev_float = self.take_prev_floating_rect(key);
    if let Some(prev_spec) = prev_float {
        // Was floating: restore pre-maximize floating rect
        self.set_floating_rect(key, Some(prev_spec));
    } else {
        // Was tiled: restore Void → Leaf in layout tree
        self.clear_floating_rect(key);
        let void_id = self.window(key).and_then(|w| w.void_id());
        if let Some(vid) = void_id
            && let Some(ref mut layout) = self.managed_layout
        {
            layout.replace_void_by_id(vid, LayoutNode::leaf(key));
        } else {
            // void_id was lost (e.g., minimize+restore cleared it).
            // Re-attach as a regular tiled window.
            self.tile_window_key(key);
        }
    }
    ...
}
```

### Fix B: `detach_from_tiling_layout` — clear managed_layout when tree becomes empty

**File:** `crates/term-wm-core/src/window/window_manager/layout.rs:802-820`

Current code:
```rust
} else {
    let _ = layout.root_mut().remove_leaf(key);
    layout.root_mut().cleanup_after_removal();
    layout.root_mut().clear_leaf(key);
}
```

Change to:
```rust
} else {
    if layout.root_mut().remove_leaf(key) {
        layout.root_mut().cleanup_after_removal();
    }
    // If the tree is now empty (was a single Leaf root), clear it
    if layout.is_empty() {
        self.managed_layout = None;
    }
}
```

Note: `LayoutNode::Void(_) => true` in `is_empty()`, so this correctly detects both:
- A Void root (left by the old `clear_leaf` path — kept for backwards compat)
- An empty tree where remove_leaf consumed the last child

### Fix C: `detach_from_tiling_layout` void path — cleanup after removal

Same file, void path. After `remove_void_by_id(vid)`, add cleanup:
```rust
if let Some(vid) = void_id {
    layout.remove_void_by_id(vid);
    layout.root_mut().cleanup_after_removal();  // collapse split if void was only child
    if let Some(w) = self.windows.get_mut(key) {
        w.clear_void_id();
    }
    if layout.is_empty() {
        self.managed_layout = None;
    }
}
```
