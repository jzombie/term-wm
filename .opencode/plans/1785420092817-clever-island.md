# Fix: Tiled Window Minimize/Maximize Bugs

## Bug 1: Windows Disappear After Minimize/Maximize Cycle

### Root Cause
In `crates/term-wm-core/src/window/window_manager/layout.rs:802-820` (`detach_from_tiling_layout`), when a maximized window is minimized, the `Void` placeholder is removed from the layout tree and `void_id` is cleared on the window — but `floating_rect` (set to full `managed_area` during maximize) and `is_maximized` are **not** cleared.

This creates a stale maximize state: the window still reports `is_window_floating() == true` (via `floating_rect`) and `is_maximized == true`, but the `void_id` linkage to the tree is gone.

### Disappearance Sequence
1. **Tiled → Maximize**: `Leaf(A)` → `Void(vid)`, `void_id=Some(vid)`, `floating_rect=Some(full_area)`, `is_maximized=true`
2. **Maximized → Minimize**: `detach_from_tiling_layout` removes the void and clears `void_id` but **leaves `floating_rect` and `is_maximized`**
3. **Minimized → Restore**: `transition_window(Iconic→Mapped)` checks `is_window_floating(key)` → returns **true** (floating_rect still set). Neither reattachment branch runs. Window is added to `z_order`/`managed_draw_order` but NOT the layout tree.
4. **Focus another window**: `focus_window_key` auto-unmaximizes previous focus. `toggle_maximize` unmaximize path: `prev_floating_rect` is `None` (set in step 1), tries to get `void_id` → **None** (cleared in step 2). Layout tree is never updated.
5. **Next frame**: `register_managed_layout` won't find the window in tree or floating state → removed from `z_order`, `managed_draw_order` → **invisible**.

### Fix (layout.rs line 808-809)
When `detach_from_tiling_layout` removes a void placeholder, also clear the maximize state since the tree linkage is severed:
```rust
// After w.clear_void_id()
w.set_maximized(false);
w.clear_floating_rect();
```
This ensures on restore, `is_window_floating()` returns false, so the window routes to `reattach_to_tiling_layout()` correctly.

## Bug 2: Half-Screen Void on Restore (Minimized Single Tiled Window)

### Root Cause
In `detach_from_tiling_layout` (layout.rs:817), when a single-leaf root tree has its last window minimized, `clear_leaf` replaces `Leaf(A)` with `Void(new_id)`. But `managed_layout` stays `Some(...)` — the empty Void-rooted tree is **not set to None**.

Contrast with `tile_window_key` (drag.rs:444-447) which **does** check `layout.is_empty()` and clears `managed_layout`.

On restore, `reattach_to_tiling_layout` (layout.rs:832) sees `managed_layout.is_some()` (Void root) and calls `split_root` (tiling.rs:975). `split_root` detects a Void root and creates a 50/50 split between the Void and the new leaf. Result: window takes half the screen, the other half is a dead Void space.

### Fix (layout.rs after line 817)
Follow the same pattern as `tile_window_key`:
```rust
layout.root_mut().clear_leaf(key);
if layout.is_empty() {
    self.managed_layout = None;
}
```
