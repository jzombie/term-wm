# Fix: Monocle Mode Border Visibility from Floating State

## Bug

When entering monocle mode from "all floating" mode, window borders still show. Doesn't happen when entering from tiled.

## Root Cause

`window_mode()` in `layout.rs:216-226` checks `is_floating()` **before** `is_monocle()`. Even though `ModeChromeConfig.monocle` in `entry.rs` already correctly defines `show_borders: false`, this setting is never reached for floating windows because `window_mode()` short-circuits at `is_floating()`.

## Fix

**File: `crates/term-wm-core/src/window/window_manager/layout.rs`, line 216-226**

Swap the precedence in `window_mode()` so `is_monocle()` is checked **before** `is_floating()`:

```rust
pub fn window_mode(&self, w: &Window) -> WindowMode {
    if w.is_maximized() {
        WindowMode::Maximized
    } else if self.is_monocle() {
        WindowMode::Monocle         // ← checked before Floating
    } else if w.is_floating() {
        WindowMode::Floating
    } else {
        WindowMode::Tiled
    }
}
```

This makes the `ModeChromeConfig.monocle` setting in `entry.rs` actually take effect for floating windows when monocle is active.

Update the doc comment at lines 206-215 to reflect the new precedence (monocle before floating).
