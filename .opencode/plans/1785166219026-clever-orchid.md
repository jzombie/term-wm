# Fix Bouncy Scrollbar (Drag-to-Bottom) Regression

## Root Cause

The `view` parameter passed to `ScrollbarDrag::handle_mouse()` in `ScrollViewComponent::on_mouse()` uses `sa.height`/`sa.width` (the full screen area), but the scrollbar track area uses `va.height`/`va.width` (the viewport area after layout adjustments). When both a horizontal and vertical scrollbar are active (common in Debug Log with long unwrapped lines), `va.height` can be `sa.height - 1`, creating a mismatch:

- Rendered scrollbar height = `inner_area.height` (= `va.height`)
- Drag handler track height = `va.height` (via `sb_area`)
- But drag handler's `view` = `sa.height` (= `va.height + 1`)

This causes `thumb_size` to be computed ~1 cell too large, making `available_track` ~1 cell too small, shifting the offset-to-position mapping so the bottommost offset is unreachable by drag.

## Changes

### 1. Fix `view` parameter in `on_mouse` (`crates/term-wm-ui-components/src/scroll_view.rs`)

**Vertical scrollbar** (lines ~316-323): Change `sa.height` to `va.height` in the `handle_mouse` call:
```
sa.height as usize → va.height as usize
```

**Horizontal scrollbar** (lines ~338-345): Change `sa.width` to `va.width` in the `handle_mouse` call:
```
sa.width as usize → va.width as usize
```

### 2. Fix scrollbar-need guard in `on_mouse` — DO NOT CHANGE

The guard conditions must stay as `content_h > sa.height / content_w > sa.width`. The `sa` (screen area from `ctx.screen_area()`) is the authoritative area for determining whether scrollbar is needed at all. Using `va.height` here (from `compute_layout`) creates a correctness issue because `compute_layout` can return a smaller height when a horizontal scrollbar is also needed, making the guard inconsistent with the render-time check which also uses the screen-area-level check.

The render function independently determines `needs_vertical` using `inner_area` (which equals `va`), so the scrollbar will be rendered correctly regardless. The `on_mouse` guard just needs to be a coarse check to avoid processing events when no scrollbar could possibly be active.

### 3. Add test: drag-to-bottom boundary

Add a test that verifies dragging the vertical scrollbar to the very bottom cell of the track produces `max_offset` (= `total - view`). Also test with both scrollbars active to cover the `va.height != sa.height` scenario.
