# Fix Bouncy Scrollbar (Drag-to-Bottom) Regression

## Root Cause

Two related bugs in `ScrollViewComponent::on_mouse()` in `crates/term-wm-ui-components/src/scroll_view.rs`:

### Bug A: `view` parameter mismatch

The `view` parameter passed to `ScrollbarDrag::handle_mouse()` uses `sa.height`/`sa.width` (the full screen area), but:
- The scrollbar track area is `va.height`/`va.width` (the viewport area after `compute_layout`)
- The render-time scrollbar visibility check uses `inner_area.height` (= `va.height`)

When both horizontal and vertical scrollbars are active, `va.height = sa.height - 1` and `va.width = sa.width - 1`. The drag handler receives `view = sa.height` while `track_len = va.height`, creating a coordinate-space mismatch. This distorts the thumb size ratio and can prevent the scroll offset from reaching `content_h - va.height` when dragging.

### Bug B: Guard/visibility desync (SEV-1)

The `on_mouse` guard uses `content_h > sa.height`, but the render function uses `content_h > inner_area.height` (= `content_h > va.height`) to decide whether to render the scrollbar. When `content_h == sa.height` and a horizontal scrollbar is present:
- `va.height = sa.height - 1`
- Render: `content_h > va.height` → true → scrollbar is rendered
- Mouse guard: `content_h > sa.height` → false → clicks DROPPED

This creates a dead-zone where the scrollbar is visible but completely unclickable.

## Changes

### 1. Fix `view` parameter + guard in `on_mouse`

Both the guard condition and the `view` parameter must use `va.height`/`va.width` (the output of `compute_layout(sa)`) instead of `sa.height`/`sa.width`. This aligns mouse event handling with the render-time visibility check.

**Vertical scrollbar guard + view param:**
```
content_h > sa.height as usize  →  content_h > va.height as usize
sa.height as usize              →  va.height as usize         (in handle_mouse call)
```

**Horizontal scrollbar guard + view param:**
```
content_w > sa.width as usize  →  content_w > va.width as usize
sa.width as usize              →  va.width as usize           (in handle_mouse call)
```

### 2. Add dead-zone unit test

Add a test for the edge case: `content_h == sa.height` with a horizontal scrollbar consuming 1 row. Verify that:
- `handle_mouse` is called (guard passes)
- Dragging to the bottom cell of the track yields `max_offset = content_h - va.height`
