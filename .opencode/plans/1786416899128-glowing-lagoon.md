# Fix flaky `session_osc52_in_output` (timing-dependent OSC 52 delivery)

## Root cause

`crates/term-session-mock/src/main.rs` `osc52` writes the OSC 52 sequence then
exits after a **500 ms sleep**. The tests subscribe to output *after* `Spawn`. If
the `SubscribeOutput` RPC is delayed past mock-exit + poll-detection (CI load,
slow IPC), the server's output-polling task sees **empty subscribers** and, on
exit, runs `sync_screen()` (which deliberately does **not** drain `pending`) then
`check_exited()` → true → `guard.session = None`
(`crates/term-session-server/src/session_server.rs:472-480`). Dropping the
session drops the `Pty`, which drops its in-memory `pending` buffer — the OSC 52
bytes are destroyed. The late subscriber receives only the initial screen
snapshot (the reset-sequence byte stream in the panic output) and an instant EOF.
The 500 ms window is the only thing keeping the test green.

Secondary hazard: `wait_for_output` breaks as soon as `52;` appears, so a payload
split across broadcast chunks (Windows ConPTY) could also break early.

## Changes

### 1. Mock: add a staying-alive `osc52_alive` subcommand
`crates/term-session-mock/src/main.rs`

- Add `"osc52_alive" => { ... }` arm mirroring the `echo` arm's keep-alive pattern:
  `#[cfg(windows)] win_console::enable_raw_vt()` then
  `#[cfg(windows)] win_console::disable_stdout_vt_processing()` (stdin raw + echo
  off, stdout raw so ConPTY doesn't eat the `ESC`), `disable_stdin_echo()`, write
  `\x1b]52;` + `OSC52_TEST_PAYLOAD` + `\x07`, flush, then loop `stdin.read` until
  EOF (process is killed via `ShutdownGateway`).
- Update the usage string (line ~108) and the `osc52` doc comment (lines 13-15) to
  list the new subcommand.
- Keep `osc52` (write + 500 ms sleep + exit) unchanged — still used by the mock
  unit test and the new server regression test below.

### 2. Server: retain unconsumed PTY output across session teardown
`crates/term-session-server/src/session_server.rs`

- `ChannelState`: add `output_cache: Vec<u8>`, init `Vec::new()` in `new()`
  (~line 166-184), and `self.output_cache.clear()` in `set_session()` (~line 188)
  so a respawned session never replays stale output.
- Empty-subscribers exit branch (lines 472-480): between `check_exited()` true and
  `guard.session = None`, add `guard.output_cache.extend(session.read_output());`
  so a late subscriber can still receive the session's final output.
- `SubscribeOutput` handler (lines 990-1012):
  - Prepend retained bytes: `let mut all = std::mem::take(&mut guard.output_cache);`
    then `all.extend_from_slice(&session.read_output())` when a live session
    exists; `early = None` if `all.is_empty()` else `Some(all)`.
  - Deliver `snapshot`/`early`/EOF **while still holding the channel guard**
    (move the three `respond` calls before `drop(guard)`). This closes the race
    where the poll task's "no live session" branch (lines 483-491) sends an EOF
    to the just-registered subscriber ahead of this subscriber's retained data.
    `respond()` is synchronous/non-blocking and is already called under the guard
    elsewhere in the poll task (lines 485-489, 504-506), so holding the lock is
    safe and deterministic.

### 3. Tests
`tests/integration_session.rs`

- `session_osc52_in_output` (line 313): spawn `mock osc52_alive` instead of
  `osc52`; change the wait pattern from `b"52;"` to
  `common::mock::EXPECTED_OSC52_PAYLOAD` so a cross-chunk split can't break early.
  Keep `#[serial]`.
- `session_osc52_via_osc52extractor` (line 347): spawn `mock osc52_alive`. No
  other change needed (it accumulates chunks until extraction succeeds).
- New regression test `session_osc52_late_subscribe_gets_retained_output`
  (`#[tokio::test] #[serial]`, unique channel `test/osc52_retained`): spawn
  `mock osc52` (write + 500 ms + exit), `sleep(1200ms)` past exit + detection,
  subscribe, `wait_for_output(EXPECTED_OSC52_PAYLOAD, 3s)`, assert
  `find_osc52_payload == Some(EXPECTED_OSC52_PAYLOAD)`. Deterministic either way:
  subscribe-before-exit → live early-drain delivers; subscribe-after-exit →
  retained cache delivers.

## Verification

```bash
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test -p term-session-mock                 # osc52_alive + existing osc52 unit tests
cargo test -p term-session-server
cargo test --test integration_session -- --nocapture
# Repeat the OSC 52 tests to confirm stability:
for i in $(seq 1 20); do
  cargo test -p term-wm --test integration_session session_osc52 -- --nocapture || break
done
```

## Notes / residual risk

- The 500 ms-sleep mock makes the retention path deterministic (payload is read
  into `pending` microseconds after spawn, long before exit). A theoretical
  micro-race remains where `check_exited()` (try_wait) fires before the reader
  thread appends the final chunk — not reachable with the test mocks, acceptable.
- `finalize_subscribers` (kill paths) is left unchanged: its call sites always run
  with a live session and are unaffected by `output_cache`.
