# Fix flaky `session_osc52_in_output` (timing-dependent OSC 52 delivery)

## Root cause

`crates/term-session-mock/src/main.rs` `osc52` writes the OSC 52 sequence then
exits after a **500 ms sleep**. The tests subscribe to output *after* `Spawn`. If
the `SubscribeOutput` RPC is delayed past mock-exit + poll-detection (CI load,
slow IPC), the server's output-polling task sees **empty subscribers** and, on
exit, runs `sync_screen()` (which deliberately does **not** drain `pending`) then
`check_exited()` → true → `guard.session = None`
(`crates/term-session-server/src/session_server.rs:472-480`). Dropping the
session drops the `Pty`, which drops its in-memory `pending` buffer — the OSC 52
bytes are destroyed. The late subscriber receives only the initial screen
snapshot (the reset-sequence byte stream in the panic output) and an instant EOF.
The 500 ms window is the only thing keeping the test green.

Secondary hazard: `wait_for_output` breaks as soon as `52;` appears, so a payload
split across broadcast chunks (Windows ConPTY) could also break early.

## Changes

### 1. Mock: add a staying-alive `osc52_alive` subcommand
`crates/term-session-mock/src/main.rs`

- Add `"osc52_alive" => { ... }` arm mirroring the `echo` arm's keep-alive pattern:
  `#[cfg(windows)] win_console::enable_raw_vt()` then
  `#[cfg(windows)] win_console::disable_stdout_vt_processing()` (stdin raw + echo
  off, stdout raw so ConPTY doesn't eat the `ESC`), `disable_stdin_echo()`, write
  `\x1b]52;` + `OSC52_TEST_PAYLOAD` + `\x07`, flush, then loop `stdin.read` until
  EOF (process is killed via `ShutdownGateway`).
- Update the usage string (line ~108) and the `osc52` doc comment (lines 13-15) to
  list the new subcommand.
- Keep `osc52` (write + 500 ms sleep + exit) unchanged — still used by the mock
  unit test and the new server regression test below.

### 2. Server: retain unconsumed PTY output across session teardown (bounded)
`crates/term-session-server/src/session_server.rs`

New constants:
- `MAX_RETAINED_OUTPUT_BYTES: usize = 65_536` — hard cap on the retained cache.
- `READER_DRAIN_GRACE: Duration = Duration::from_millis(50)` — bounded wait for
  the PTY reader thread to reach EOF before the final drain.

`ChannelState`:
- Add `output_cache: Vec<u8>`; init `Vec::new()` in `new()` (~line 166-184);
  clear in `set_session()` (~line 188) so a respawned session never replays stale
  output.
- Add helper `fn retain_final_output(&mut self, bytes: &[u8])` that appends with
  **tail retention**: if the buffer would exceed `MAX_RETAINED_OUTPUT_BYTES`,
  drop the oldest bytes so at most the last 64 KB is ever retained. Memory is
  bounded per dead channel regardless of how much output the session produced.

Exit-with-empty-subscribers branch (lines 472-480):
```rust
if session.check_exited() {
    let final_out = session.read_final_output(READER_DRAIN_GRACE);
    guard.retain_final_output(&final_out);
    guard.session = None;
    guard.kill_pending = false;
}
```

`SubscribeOutput` handler (lines 990-1012):
- Prepend the retained tail **by clone, not `take`** (`guard.output_cache.clone()`)
  so a subscriber that connects and drops does not consume the bytes for later
  subscribers; the cache persists until channel reap or `set_session`.
  When a live session exists, also drain its `pending` (`read_output()`) into the
  same chunk. `early = None` if the combined bytes are empty.
- Deliver `snapshot`/`early`/EOF **while still holding the channel guard**
  (move the three `respond` calls before `drop(guard)`). This closes the race
  where the poll task's "no live session" branch (lines 483-491) sends an EOF to
  the just-registered subscriber ahead of this subscriber's retained data.
  `respond()` is synchronous/non-blocking and is already called under the guard
  elsewhere in the poll task (lines 485-489, 504-506), so holding the lock is
  safe and deterministic.

### 3. PTY: synchronize reader completion before the final drain
`crates/term-wm-pty-engine/src/pty.rs` + `crates/term-session-server/src/session.rs`

The OS exit signal (`child.try_wait()`) can precede the reader thread's final
kernel-buffer read, so draining immediately at `check_exited()` may truncate
trailing bytes. Fix by making the drain wait (bounded) for the reader thread to
finish its EOF processing:

- `Pty::drain_final_output(&mut self, grace: Duration) -> Vec<u8>`:
  call `self.screen()`, then — while the stored reader `JoinHandle` is not
  finished and the grace deadline has not passed — sleep a few ms (`JoinHandle
  ::is_finished()`, stable since Rust 1.61); finally `drain_pending()`. On Unix
  the reader EOFs within microseconds of process exit, so the wait is effectively
  free; on Windows ConPTY (where EOF can be swallowed and `has_exited()` relies
  on the `try_wait` fallback) the grace bounds the wait and we drain best-effort.
- `Session::read_final_output(&mut self, grace: Duration) -> Vec<u8>`: thin
  wrapper over `pty.drain_final_output(grace)` that also syncs the title
  (`take_pending_title`), mirroring `read_output()`.

This satisfies "do not drop the session until the reader task signals stream
completion": the drain happens only after EOF processing is observed finished
(or the bounded grace expires).

### 4. Tests
`tests/integration_session.rs`

- `session_osc52_in_output` (line 313): spawn `mock osc52_alive` instead of
  `osc52`; change the wait pattern from `b"52;"` to
  `common::mock::EXPECTED_OSC52_PAYLOAD` so a cross-chunk split can't break early.
  Keep `#[serial]`.
- `session_osc52_via_osc52extractor` (line 347): spawn `mock osc52_alive`. No
  other change needed (it accumulates chunks until extraction succeeds).
- New regression test `session_osc52_late_subscribe_gets_retained_output`
  (`#[tokio::test] #[serial]`, unique channel `test/osc52_retained`): spawn
  `mock osc52` (write + 500 ms + exit), `sleep(1200ms)` past exit + detection,
  subscribe, `wait_for_output(EXPECTED_OSC52_PAYLOAD, 3s)`, assert
  `find_osc52_payload == Some(EXPECTED_OSC52_PAYLOAD)`. Deterministic either way:
  subscribe-before-exit → live early-drain delivers; subscribe-after-exit →
  retained cache delivers.

## Notes / residual risk

- Retained output is capped at 64 KB per dead channel (tail retention), and is
  cleared on respawn and dropped on channel reap — no unbounded accumulation.
- The reader-synchronized drain waits at most `READER_DRAIN_GRACE` (50 ms) and
  only in the exit-with-empty-subscribers path, so it does not add latency to
  live broadcast.
- `finalize_subscribers` (kill paths) is left unchanged: its call sites always run
  with a live session and are unaffected by `output_cache`.
