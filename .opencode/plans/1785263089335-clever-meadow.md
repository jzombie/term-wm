# Key Monitor Applet for System Panel

## Goal
Add an applet to the system panel that displays the last detected key press (including modifiers) — updated regardless of which window has focus.

## Architecture
The system panel (`WmSystemPanelComponent`) is a window that only receives events when focused. To show keys pressed *anywhere*, we use shared state (`Rc<RefCell<Option<String>>>`) owned by `TermWmApp` and injected into both the event handler and the panel.

## Changes

### 1. `crates/term-wm-sys-ui-components/src/wm_system_panel.rs`

- **Add `KeyMonitorComponent`** — a leaf component similar to `SpacerComponent`:
  - Stores `state: Rc<RefCell<Option<KeyEvent>>>` (raw event, not formatted string)
  - `desired_height()` returns 1
  - `render()` reads raw `KeyEvent` from `state`, formats on the fly, renders as styled text
  - `handle_events()` returns `EventResult::Ignored`
- **Add `KeyMonitor(KeyMonitorComponent)` variant** to `PanelChild` enum
- **Update `impl_component_delegate!`** to include `KeyMonitor`
- **Add `WmSystemPanelComponent::with_key_monitor()` builder method** (does NOT modify `new()`):
  ```rust
  pub fn with_key_monitor(mut self, state: Rc<RefCell<Option<KeyEvent>>>) -> Self {
      self.children.push(PanelChild::KeyMonitor(
          KeyMonitorComponent::new(state),
      ));
      self
  }
  ```
  Where `children` is a new `Vec<PanelChild>` field on `WmSystemPanelComponent` built during `new()` and consumed by the scroll view.
  
  **Design note**: `WmSystemPanelComponent` currently stores `scroll_view`. To support builder methods, extract the child list into a `Vec<PanelChild>` built in `new()`, then consumed at the end of construction. This avoids breaking the existing constructor signature.
- Add `fn format_key_event(key: &KeyEvent) -> String` helper for use in `render()`

### 2. `src/term_wm_app.rs`

- **Add field** `last_key: Rc<RefCell<Option<KeyEvent>>>` to `TermWmApp<C>` struct
- **Initialize** `last_key` in:
  - `from_wm()` constructor
  - All constructors that go through `from_wm()`
- **In `init_system_windows()`**: chain `.with_key_monitor(self.last_key.clone())` after `WmSystemPanelComponent::new()`
- **Override `handle_app_event()`**: on `Event::Key`, clone and store the raw `KeyEvent`, return `false` (don't consume)
- **Import** needed types: `Rc`, `RefCell`, `Event`, `KeyEvent`, `KeyCode`

## Formatting Logic (for display string)

Uses the project's own `KeyModifiers` (bool fields: `shift`, `control`, `alt`) and `KeyCode` (enum with `Char`, `Enter`, `Tab`, etc.) from `crates/term-wm-core/src/events.rs`.

- Ctrl/Alt modifiers always shown as prefixes
- Shift modifier shown for non-char keys (for `Char` keys, case already reflects shift state)
- Names for special keys: `Enter`, `Tab`, `Esc`, `Backspace`, `Left`, etc.

Examples: `Ctrl+A`, `Alt+Tab`, `Ctrl+Shift+Tab`, `Enter`, `F1`, `Ctrl+C`

### 3. `crates/term-wm-core/src/runner.rs` (BUG FIX)

Move `handle_app_event` to the **very top of the event handler** (before all layer checks) so it captures EVERY key press — including those consumed by overlays, command palette, or keybindings.

**New insertion point** (after synthetic event swap & FramePacer arm, before Layer 1 overlays):
```
FramePacer arm
PRE-LAYER: app.handle_app_event(&evt)  ← NEW: captures all key events
Layer 1: Overlays (exit confirm, help, command palette)
Layer 2a: Command palette toggle
Layer 2b: Direct mode check
Layer 3: Pass-through to focused component
```

The override in `TermWmApp` returns `false` (don't consume), so overlay/keybinding processing is unaffected.

### 4. `src/main.rs` (CRITICAL BUG FIX)

The event loop calls `WindowManagerHost::handle_app_event` on the **`App`** wrapper struct, not directly on `TermWmApp`. `App` delegates `wm()` and `render()` to `self.inner`, but has no `handle_app_event` override → default no-op runs.

- **Add `handle_app_event` override** inside the `impl WindowManagerHost for App` block (line 183), delegating to `self.inner`:
  ```rust
  fn handle_app_event(&mut self, event: &Event) -> bool {
      self.inner.handle_app_event(event)
  }
  ```
- **Add import** for `Event` in `main.rs`.
